`NinoSerializer` and `NinoDeserializer` (namespace `Nino.Core`) are the whole runtime API. Both are static and **thread safe**: call them from any number of threads without locking. Per-call state (the <Term id="scratch-buffer">scratch buffer</Term> Nino serializes into, reference tables) is kept per thread, and no hot path writes shared memory.

This page covers the calls you use every day. [High-Performance Serialization](/en/docs/v4/advanced/high-performance) takes the same calls down to no allocation at all.

The examples on this page serialize an `Order` like this one:

```csharp title="Order.cs"
using System.Collections.Generic;
using Nino.Core;

[NinoType]
public sealed class Order
{
    public long Id;
    public string Customer;
    public List<OrderLine> Lines;
}

[NinoType]
public struct OrderLine
{
    public int ProductId;
    public int Quantity;
}
```

## Serializing

```csharp nocheck
// Into a new byte array
byte[] NinoSerializer.Serialize<T>(in T value);

// Into any IBufferWriter<byte>
void NinoSerializer.Serialize<T>(in T value, IBufferWriter<byte> bufferWriter);

// With an existing Writer (several values in one buffer, custom formatters)
void NinoSerializer.Serialize<T>(in T value, ref Writer writer);

// To a Stream: the same bytes, no framing (see Streams and Compression)
void NinoSerializer.Serialize<T>(in T value, Stream stream);
ValueTask NinoSerializer.SerializeAsync<T>(T value, Stream stream, CancellationToken cancellationToken = default);

// Boxed values, only for a type known only at run time as a Type (see Runtime Types)
byte[] NinoSerializer.SerializeBoxed(object value, Type type);
void NinoSerializer.SerializeBoxed(object value, IBufferWriter<byte> bufferWriter, Type type);
void NinoSerializer.SerializeBoxed(object value, ref Writer writer, Type type);
void NinoSerializer.SerializeBoxed(object value, Stream stream, Type type);
ValueTask NinoSerializer.SerializeBoxedAsync(object value, Stream stream, Type type, CancellationToken cancellationToken = default);
```

`T` can be any [supported type](/en/docs/v4/types): a `[NinoType]`, a primitive, a string, a collection, and so on.

```csharp
byte[] bytes = NinoSerializer.Serialize(order);
```

### Reusing a Buffer

`Serialize<T>(value)` allocates one `byte[]` for the result. For a <Term id="fixed-size">fixed-size type</Term>, and for an array or list whose elements are written as one block (unmanaged values, raw structs), that array is allocated at its final size and written in place ([Fixed-Size Types](/en/docs/v4/performance#fixed-size-types) says how); other values are written into a per-thread scratch buffer and copied out. To allocate nothing, serialize into a buffer you keep.

`NinoArrayBufferWriter` is Nino's own `IBufferWriter<byte>`, backed by `ArrayPool<byte>.Shared` (or a pool you pass in), and Nino writes into it **in place**. Any other `IBufferWriter<byte>` (.NET's `ArrayBufferWriter<byte>`, a `PipeWriter`, a writer that wraps a `Stream`) costs one extra copy at the end.

```csharp
var buffer = new NinoArrayBufferWriter();      // or new NinoArrayBufferWriter(initialCapacity)

NinoSerializer.Serialize(order, buffer);
ReadOnlySpan<byte> bytes = buffer.WrittenSpan; // also WrittenMemory, WrittenCount, ToArray()
// ... send or store the bytes ...

buffer.ResetWrittenCount();                    // reuse the same array // [!code highlight]
NinoSerializer.Serialize(order, buffer);       // no allocation this time
```

The buffer grows by renting a larger array from the pool. If you know roughly how large your messages are, size it up front with `new NinoArrayBufferWriter(initialCapacity)` or `EnsureCapacity(sizeHint)`; `Capacity` and `FreeCapacity` report the array's size and the room left.

<Callout type="warn">

A `NinoArrayBufferWriter` is **not** thread safe: use one per thread, per connection or per operation. When you no longer need it, call `Dispose()` to return its array to the pool.

</Callout>

Serializing into arrays you manage (a pool of your own), exact-size arrays and every other lever are in [High-Performance Serialization](/en/docs/v4/advanced/high-performance#levers).

### Several Values in One Buffer

`Writer` is a `ref struct` that writes into a `NinoArrayBufferWriter`. Use it to write several values back to back, or inside a [custom formatter](/en/docs/v4/custom-formatters):

```csharp
var buffer = new NinoArrayBufferWriter();
var writer = new Writer(buffer);
NinoSerializer.Serialize(header, ref writer);
NinoSerializer.Serialize(body, ref writer);
writer.Flush();             // commits the bytes to buffer.WrittenCount (Dispose() does the same)
writer.ReleaseReferences(); // ends reference tracking, see below
```

<Callout type="info">

When you pass a value and get bytes back (or pass a buffer writer), [reference tracking](/en/docs/v4/reference-tracking) covers that one call. When you create a `Writer` (or `Reader`) yourself, tracking spans everything written through it until you call `ReleaseReferences()`. Call it at the end of each logical message; it costs nothing if no tracked type was written.

</Callout>

## Deserializing

```csharp nocheck
// A new value
T NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data);

// Into an existing value, reusing its instances
void NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data, ref T value);

// With an existing Reader
T NinoDeserializer.Deserialize<T>(ref Reader reader);
void NinoDeserializer.Deserialize<T>(ref Reader reader, ref T value);

// A ReadOnlySequence<byte> from a PipeReader (see Streams and Compression)
T NinoDeserializer.Deserialize<T>(in ReadOnlySequence<byte> data);
void NinoDeserializer.Deserialize<T>(in ReadOnlySequence<byte> data, ref T value);

// A Stream, read to its end (see Streams and Compression)
T NinoDeserializer.Deserialize<T>(Stream stream);
void NinoDeserializer.Deserialize<T>(Stream stream, ref T value);
ValueTask<T> NinoDeserializer.DeserializeAsync<T>(Stream stream, CancellationToken cancellationToken = default);

// Boxed values, only for a type known only at run time as a Type (see Runtime Types)
object NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, Type type);
void NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, ref object value, Type type);
void NinoDeserializer.DeserializeBoxed(ref Reader reader, ref object value, Type type);
object NinoDeserializer.DeserializeBoxed(Stream stream, Type type);
void NinoDeserializer.DeserializeBoxed(Stream stream, ref object value, Type type);
ValueTask<object> NinoDeserializer.DeserializeBoxedAsync(Stream stream, Type type, CancellationToken cancellationToken = default);
```

The data is a `ReadOnlySpan<byte>`: pass a `byte[]`, an `ArraySegment<byte>`, a `Span<byte>`, `Memory<byte>.Span` or a slice of any buffer you already have, without copying it. A `ReadOnlySequence<byte>` (from `System.IO.Pipelines`) has overloads of its own, which copy only data that spans several segments: [Multi-Segment Input](/en/docs/v4/advanced/streams#readonlysequence-input). A `Stream` holding one value is read with `Deserialize<T>(stream)` or `await DeserializeAsync<T>(stream)`: [Streams](/en/docs/v4/advanced/streams#streams).

```csharp
Order order = NinoDeserializer.Deserialize<Order>(bytes);
Order fromSlice = NinoDeserializer.Deserialize<Order>(rented.AsSpan(0, received));
```

Recursive types (trees, linked lists) can nest to any depth: neither side overflows the stack. An object referenced twice is written twice, and a cycle throws while serializing; [Reference Tracking](/en/docs/v4/reference-tracking) keeps shared objects and cycles, and explains deep graphs.

### Into an Existing Value

Pass an existing value by `ref` and Nino fills it in place (<Term id="reuse-deserialization">reuse deserialization</Term>), reusing the instance and its nested objects, lists, arrays and dictionaries where it can. Pass `null` (or `default`) and a new value is created. Strings are compared with what the value already holds: a string with the same text is kept, and only a string whose text changed (or that was `null`) is read into a new instance. A `[NinoUtf8]` string is kept this way when its text is ASCII; non-ASCII UTF-8 text is always decoded into a new string.

```csharp
Order order = null;
foreach (var message in messages)
{
    NinoDeserializer.Deserialize(message, ref order); // the first call creates order, later calls reuse it
    Handle(order);
}
```

Instances that are dropped along the way (the data holds `null`, a list shrinks, a dictionary key disappears, the polymorphic type changes) can go back to an object pool. There is no `out` overload: use the return value for a new instance, or `ref` to reuse one. See [Reuse and Pooling](/en/docs/v4/pooling).

### Several Values from One Buffer

Read values written back to back with a `Reader`, in the same order:

```csharp
var reader = new Reader(buffer.WrittenSpan);
var header = NinoDeserializer.Deserialize<Header>(ref reader);
var body = NinoDeserializer.Deserialize<Body>(ref reader);
reader.ReleaseReferences();
```

## Runtime Types

Code that handles many types at once (RPC or message dispatch, a plugin system, editor tooling) rarely needs runtime types. Give the types a common `[NinoType]` base class or interface and serialize through it: `Serialize<TBase>` writes a type id, and `Deserialize<TBase>` reads it and creates the right type in generated code. This is the fastest way to handle many types, and it works with [reuse deserialization and pooling](/en/docs/v4/pooling), so a receive loop allocates nothing but the strings in the data:

```csharp
[NinoType]
public abstract class Message { }

public sealed class Ping : Message { public long SentAt; } // inherits [NinoType]
public sealed class Chat : Message { public string Text; }

var buffer = new NinoArrayBufferWriter();                  // one per connection, reused
NinoSerializer.Serialize<Message>(new Ping { SentAt = 1 }, buffer); // declared as the base: a type id is written

Message message = null;
NinoDeserializer.Deserialize(buffer.WrittenSpan, ref message); // a Ping, reused by later calls while the type matches
```

See [Polymorphism](/en/docs/v4/polymorphism#dispatching-through-a-common-base).

### The Boxed API [#the-boxed-api]

Use the boxed API **only** when the type is known only at run time, as a `Type`, and the types share no common `[NinoType]` base: reflection-driven tooling over arbitrary types, such as an inspector that saves whatever field it is pointed at. Serialize and deserialize with the **same** type:

```csharp
Type type = field.FieldType;                                   // known only at run time
byte[] bytes = NinoSerializer.SerializeBoxed(field.GetValue(target), type);
object copy = NinoDeserializer.DeserializeBoxed(bytes, type);

// into an existing instance, reused when it is an instance of type
object current = field.GetValue(target);
NinoDeserializer.DeserializeBoxed(bytes, ref current, type);
field.SetValue(target, current);
```

`SerializeBoxed(value, type)` writes exactly what `Serialize<T>(value)` with `T` = `type` would, `null` included for a type that can be null, so the generic and boxed calls read each other's data. The boxed API finds the formatter by `Type` (through reflection on first use, a dictionary lookup afterward) and boxes value types. `NinoSerializer.IsSupported(type)` tells whether Nino can serialize and deserialize a type at all (a `[NinoType]`, a built-in type or a type with a registered formatter), for code that has only a `Type` and must decide whether to handle it, such as the [ASP.NET Core formatters](/en/docs/v4/advanced/aspnetcore#mvc).

<Callout type="warn" title="Don't use object as T">

`NinoSerializer.Serialize(value)` with a variable declared as `object` calls `Serialize<object>`, not the boxed API. It accepts only `[NinoType]` values, writes a <Term id="type-id">type id</Term> and dispatches through the global registry of every `[NinoType]`, which costs more than the generated dispatch of a common base. Declare the variable as the common base type instead, or call `SerializeBoxed` with the `Type`.

</Callout>

## Invalid Data

Nino is built to read data you do not trust (a network peer, a user's file, a request body): whatever the bytes, a read never crashes the process, reads past the input or allocates out of proportion to it. Invalid data (truncated, an impossible length, an unknown type id, bytes Nino never writes) throws one exception, [`NinoDataException`](/en/docs/v4/security#ninodataexception) (namespace `Nino.Core`), whose message starts with `Nino:`. Catch it where the data comes in and drop the input. Data someone could craft also needs `NinoSettings.Untrusted` and a size cap of your own: read [Untrusted Data](/en/docs/v4/security) before you ship.

Words these docs use with a specific meaning (top-level call, formatter, raw, slot and more) are in the [Glossary](/en/docs/v4/glossary).
