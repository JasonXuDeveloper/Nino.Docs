`NinoSerializer` and `NinoDeserializer` (namespace `Nino.Core`) are the whole runtime API. Both are static and **thread safe**: call them from any number of threads without locking. Per-call state (scratch buffers, reference tables) is kept per thread, and no hot path writes shared memory.

## Serializing

```csharp
// Into a new byte array
byte[] NinoSerializer.Serialize<T>(T value);

// Into any IBufferWriter<byte>
void NinoSerializer.Serialize<T>(T value, IBufferWriter<byte> bufferWriter);

// With an existing Writer (several values in one buffer, custom formatters)
void NinoSerializer.Serialize<T>(T value, ref Writer writer);

// Boxed values, when the type is only known at run time
byte[] NinoSerializer.Serialize(object value);    // as value.GetType(); value must not be null
void NinoSerializer.SerializeBoxed(object value, IBufferWriter<byte> bufferWriter, Type type);
void NinoSerializer.SerializeBoxed(object value, ref Writer writer, Type type);
```

`T` can be any [supported type](/en/docs/v4/types): a `[NinoType]`, a primitive, a string, a collection, and so on.

```csharp
byte[] bytes = NinoSerializer.Serialize(player);
```

### Reusing a Buffer

`Serialize<T>(value)` allocates one `byte[]` for the result. For a [fixed-size type](/en/docs/v4/performance#fixed-size-types) that array is allocated at its final size and written in place; other values are written into a per-thread scratch buffer and copied out. To allocate nothing, serialize into a buffer you keep.

`NinoArrayBufferWriter` is Nino's own `IBufferWriter<byte>`, backed by `ArrayPool<byte>.Shared`. Nino writes into it **in place**. Any other `IBufferWriter<byte>` (.NET's `ArrayBufferWriter<byte>`, a `PipeWriter`, a writer wrapping a `Stream`) receives the bytes with one extra copy at the end.

```csharp
var buffer = new NinoArrayBufferWriter();      // or new NinoArrayBufferWriter(initialCapacity)

NinoSerializer.Serialize(player, buffer);
ReadOnlySpan<byte> bytes = buffer.WrittenSpan; // also WrittenMemory, WrittenCount, ToArray()
// ... send or store the bytes ...

buffer.ResetWrittenCount();                    // reuse the same array
NinoSerializer.Serialize(player, buffer);      // no allocation this time
```

<Callout type="warn">

A `NinoArrayBufferWriter` is **not** thread safe: use one per thread, per connection or per operation. Call `Dispose()` when you no longer need it, to return its array to the pool.

</Callout>

### Several Values in One Buffer

`Writer` is a `ref struct` that writes into a `NinoArrayBufferWriter`. Use it to write several values back to back, or inside a [custom formatter](/en/docs/v4/custom-formatters):

```csharp
var buffer = new NinoArrayBufferWriter();
var writer = new Writer(buffer);
NinoSerializer.Serialize(header, ref writer);
NinoSerializer.Serialize(body, ref writer);
writer.Flush();             // commits the bytes to buffer.WrittenCount (Dispose() does the same)
writer.ReleaseReferences(); // ends reference tracking, see below
```

<Callout type="info">

The top-level overloads scope [reference tracking](/en/docs/v4/reference-tracking) to one call. When you create a `Writer` (or `Reader`) yourself, objects are tracked across everything written through it until you call `ReleaseReferences()`. Call it when the logical message ends; it costs nothing when no tracked type was written.

</Callout>

## Deserializing

```csharp
// A new value
T NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data);

// Into an existing value, reusing its instances
void NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data, ref T value);

// With an existing Reader
T NinoDeserializer.Deserialize<T>(ref Reader reader);
void NinoDeserializer.Deserialize<T>(ref T value, ref Reader reader);

// Boxed values, when the type is only known at run time
object NinoDeserializer.Deserialize(ReadOnlySpan<byte> data, Type type);
void NinoDeserializer.Deserialize(ReadOnlySpan<byte> data, Type type, ref object value);
void NinoDeserializer.DeserializeBoxed(ref object value, ref Reader reader, Type type);
```

The data is a `ReadOnlySpan<byte>`: pass a `byte[]`, an `ArraySegment<byte>`, a `Span<byte>`, `Memory<byte>.Span` or a slice of any buffer you already have, without copying it.

```csharp
Player player = NinoDeserializer.Deserialize<Player>(bytes);
Player fromSlice = NinoDeserializer.Deserialize<Player>(rented.AsSpan(0, received));
```

### Into an Existing Value

Pass an existing value by `ref` and Nino fills it in place, reusing the instance and its nested objects, lists, arrays and dictionaries where it can. Pass `null` (or `default`) and a new value is created.

```csharp
Player player = null;
foreach (var message in messages)
{
    NinoDeserializer.Deserialize(message, ref player); // the first call creates player, later calls reuse it
    Handle(player);
}
```

Instances dropped along the way (the data holds `null`, a list shrinks, a dictionary key disappears, the polymorphic type changes) can be returned to an object pool. There is no `out` overload: use the return value for a new instance, or `ref` to reuse one. See [Reuse Deserialization and Pooling](/en/docs/v4/pooling).

### Several Values from One Buffer

Read values written back to back with a `Reader`, in the same order:

```csharp
var reader = new Reader(buffer.WrittenSpan);
var header = NinoDeserializer.Deserialize<Header>(ref reader);
var body = NinoDeserializer.Deserialize<Body>(ref reader);
reader.ReleaseReferences();
```

### Multi-Segment Data

There is no `ReadOnlySequence<byte>` overload. A sequence from `System.IO.Pipelines` is usually a single segment, which you pass directly; otherwise copy it into one contiguous block first:

```csharp
static Player Read(ReadOnlySequence<byte> data)
{
    if (data.IsSingleSegment)
        return NinoDeserializer.Deserialize<Player>(data.First.Span);

    int length = (int)data.Length;
    byte[] rented = ArrayPool<byte>.Shared.Rent(length);
    try
    {
        data.CopyTo(rented);
        return NinoDeserializer.Deserialize<Player>(rented.AsSpan(0, length));
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(rented);
    }
}
```

## Runtime Types

When the type is only known at run time (a plugin system, an editor tool, a message table keyed by `Type`), use the boxed overloads. Serialize and deserialize with the **same** type:

```csharp
object value = GetComponentData();
byte[] bytes = NinoSerializer.Serialize(value);                    // written as value.GetType()
object copy = NinoDeserializer.Deserialize(bytes, value.GetType());

// a value declared as a base type: write and read it as that type, so the subtype is preserved
NinoSerializer.SerializeBoxed(shape, buffer, typeof(Shape));
object read = NinoDeserializer.Deserialize(buffer.WrittenSpan, typeof(Shape));
```

The boxed overloads resolve the formatter by `Type` (cached after the first call) and box value types. Prefer the generic overloads when the type is known at compile time.

## Deep Object Graphs

Recursive types (a linked list, a tree, a node that holds another node) can be any depth. Nino writes the first 128 nested objects in place; an object nested deeper is written later, from a shallow point, and read back the same way. Writing and reading take a bounded amount of stack however deep the graph is: a 100,000-node linked list round-trips on a 512 KB thread stack, and data cannot be crafted to overflow the reader's stack, so recursive types are safe in messages from untrusted sources. Data less than 128 objects deep is written exactly as before.

```csharp
[NinoType]
public class TreeNode
{
    public int Value;
    public List<TreeNode> Children;
}

// As deep as you like: no StackOverflowException on either side.
byte[] bytes = NinoSerializer.Serialize(deepTree);
var copy = NinoDeserializer.Deserialize<TreeNode>(bytes);
```

A deferred object is created and put in its slot as soon as its slot is read, and its members are read later in the same call, so reuse deserialization and `[NinoPooled]` still reuse every instance. Two kinds of classes cannot wait like that, and are always nested in place:

- classes created by their **constructor** (positional records, init-only or read-only members), since there is no instance until their members are read;
- classes **compared by value** (records, classes that override `GetHashCode` or implement `IComparable`), since a `HashSet<T>`, dictionary key or sorted collection could hold one before its members are read.

A graph of those fails with an `InvalidOperationException` once 512 objects are nested. Give a deeply recursive type a parameterless constructor and settable members.

An object graph with a **cycle** (`a.Next = b; b.Next = a;`) would be written forever. Writing it throws an `InvalidOperationException` that names the type; mark the types on the cycle [`trackReferences: true`](/en/docs/v4/reference-tracking) to write each object once and keep the cycle.

## Invalid Data

Every length read from a payload is checked against the bytes left before anything is allocated, so malformed or hostile input cannot trigger huge allocations. Invalid data throws an `InvalidOperationException` whose message starts with `Nino:`: truncated data ("unexpected end of data"), an impossible length, an unknown type id, a type id that is not a subtype of the declared type, or a `[NinoUtf8]` string whose bytes are not valid UTF-8 or do not match its char and byte counts. Nothing reads past the end of the span.

Deeply nested data cannot overflow the stack either: see [Deep Object Graphs](#deep-object-graphs).

Nino does not detect data written for a **different** type with a compatible layout: the bytes carry no schema. Version your payloads yourself (see [Evolving Your Data](/en/docs/v4/evolving-data) and the [save file header](/en/docs/v4/advanced/persistence#add-a-file-header) pattern).
