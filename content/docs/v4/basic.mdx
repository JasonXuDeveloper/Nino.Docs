`NinoSerializer` and `NinoDeserializer` (namespace `Nino.Core`) are the whole runtime API. Both are static and **thread safe**: call them from any number of threads without locking. Per-call state (the [scratch buffer](#terms) Nino serializes into, reference tables) is kept per thread, and no hot path writes shared memory.

## Serializing

```csharp
// Into a new byte array
byte[] NinoSerializer.Serialize<T>(in T value);

// Into any IBufferWriter<byte>
void NinoSerializer.Serialize<T>(in T value, IBufferWriter<byte> bufferWriter);

// With an existing Writer (several values in one buffer, custom formatters)
void NinoSerializer.Serialize<T>(in T value, ref Writer writer);

// Boxed values, only for a type known only at run time as a Type (see Runtime Types)
byte[] NinoSerializer.SerializeBoxed(object value, Type type);
void NinoSerializer.SerializeBoxed(object value, IBufferWriter<byte> bufferWriter, Type type);
void NinoSerializer.SerializeBoxed(object value, ref Writer writer, Type type);
```

`T` can be any [supported type](/en/docs/v4/types): a `[NinoType]`, a primitive, a string, a collection, and so on.

```csharp
byte[] bytes = NinoSerializer.Serialize(order);
```

### Reusing a Buffer

`Serialize<T>(value)` allocates one `byte[]` for the result. For a [fixed-size type](/en/docs/v4/performance#fixed-size-types), and for an array or list of fixed-size elements, that array is allocated at its final size and written in place; other values are written into a per-thread scratch buffer and copied out. To allocate nothing, serialize into a buffer you keep.

`NinoArrayBufferWriter` is Nino's own `IBufferWriter<byte>`, backed by `ArrayPool<byte>.Shared` (or a pool you pass in), and Nino writes into it **in place**. Any other `IBufferWriter<byte>` (.NET's `ArrayBufferWriter<byte>`, a `PipeWriter`, a writer that wraps a `Stream`) costs one extra copy at the end.

```csharp
var buffer = new NinoArrayBufferWriter();      // or new NinoArrayBufferWriter(initialCapacity)

NinoSerializer.Serialize(order, buffer);
ReadOnlySpan<byte> bytes = buffer.WrittenSpan; // also WrittenMemory, WrittenCount, ToArray()
// ... send or store the bytes ...

buffer.ResetWrittenCount();                    // reuse the same array // [!code highlight]
NinoSerializer.Serialize(order, buffer);       // no allocation this time
```

The buffer grows by renting a larger array from the pool. If you know roughly how large your messages are, size it up front with `new NinoArrayBufferWriter(initialCapacity)` or `EnsureCapacity(sizeHint)`; `Capacity` and `FreeCapacity` report the array's size and the room left.

To serialize straight into buffers you manage, pass your own `ArrayPool<byte>`: `new NinoArrayBufferWriter(initialCapacity, pool)` rents every array from that pool and returns them to it as it grows and on `Dispose()`. A server that allocates its socket buffers on the pinned object heap, for example, can then serialize messages directly into them, with no extra copy. Growing returns the previous array to the pool, so take `WrittenMemory` after the last write and use it only until the next write or `ResetWrittenCount()`.

```csharp
// pinnedPool: an ArrayPool<byte> of your own, e.g. of GC.AllocateUninitializedArray<byte>(n, pinned: true) arrays
var buffer = new NinoArrayBufferWriter(4096, pinnedPool);
```

<Callout type="warn">

A `NinoArrayBufferWriter` is **not** thread safe: use one per thread, per connection or per operation. When you no longer need it, call `Dispose()` to return its array to the pool.

</Callout>

### Several Values in One Buffer

`Writer` is a `ref struct` that writes into a `NinoArrayBufferWriter`. Use it to write several values back to back, or inside a [custom formatter](/en/docs/v4/custom-formatters):

```csharp
var buffer = new NinoArrayBufferWriter();
var writer = new Writer(buffer);
NinoSerializer.Serialize(header, ref writer);
NinoSerializer.Serialize(body, ref writer);
writer.Flush();             // commits the bytes to buffer.WrittenCount (Dispose() does the same)
writer.ReleaseReferences(); // ends reference tracking, see below
```

<Callout type="info">

When you pass a value and get bytes back (or pass a buffer writer), [reference tracking](/en/docs/v4/reference-tracking) covers that one call. When you create a `Writer` (or `Reader`) yourself, tracking spans everything written through it until you call `ReleaseReferences()`. Call it at the end of each logical message; it costs nothing if no tracked type was written.

</Callout>

## Deserializing

```csharp
// A new value
T NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data);

// Into an existing value, reusing its instances
void NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data, ref T value);

// With an existing Reader
T NinoDeserializer.Deserialize<T>(ref Reader reader);
void NinoDeserializer.Deserialize<T>(ref T value, ref Reader reader);

// Boxed values, only for a type known only at run time as a Type (see Runtime Types)
object NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, Type type);
void NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, ref object value, Type type);
void NinoDeserializer.DeserializeBoxed(ref object value, ref Reader reader, Type type);
```

The data is a `ReadOnlySpan<byte>`: pass a `byte[]`, an `ArraySegment<byte>`, a `Span<byte>`, `Memory<byte>.Span` or a slice of any buffer you already have, without copying it.

```csharp
Order order = NinoDeserializer.Deserialize<Order>(bytes);
Order fromSlice = NinoDeserializer.Deserialize<Order>(rented.AsSpan(0, received));
```

### Into an Existing Value

Pass an existing value by `ref` and Nino fills it in place, reusing the instance and its nested objects, lists, arrays and dictionaries where it can. Pass `null` (or `default`) and a new value is created. Strings are compared with what the value already holds: a string with the same text is kept, and only a string whose text changed (or that was `null`) is read into a new instance. A `[NinoUtf8]` string is kept this way when its text is ASCII; non-ASCII UTF-8 text is always decoded into a new string.

```csharp
Order order = null;
foreach (var message in messages)
{
    NinoDeserializer.Deserialize(message, ref order); // the first call creates order, later calls reuse it
    Handle(order);
}
```

Instances that are dropped along the way (the data holds `null`, a list shrinks, a dictionary key disappears, the polymorphic type changes) can go back to an object pool. There is no `out` overload: use the return value for a new instance, or `ref` to reuse one. See [Reuse Deserialization and Pooling](/en/docs/v4/pooling).

### Several Values from One Buffer

Read values written back to back with a `Reader`, in the same order:

```csharp
var reader = new Reader(buffer.WrittenSpan);
var header = NinoDeserializer.Deserialize<Header>(ref reader);
var body = NinoDeserializer.Deserialize<Body>(ref reader);
reader.ReleaseReferences();
```

### Multi-Segment Data

There is no `ReadOnlySequence<byte>` overload. A sequence from `System.IO.Pipelines` is usually a single segment, which you can pass directly; otherwise, copy it into one contiguous block first:

```csharp
static Order Read(ReadOnlySequence<byte> data)
{
    if (data.IsSingleSegment)
        return NinoDeserializer.Deserialize<Order>(data.First.Span);

    int length = (int)data.Length;
    byte[] rented = ArrayPool<byte>.Shared.Rent(length);
    try
    {
        data.CopyTo(rented);
        return NinoDeserializer.Deserialize<Order>(rented.AsSpan(0, length));
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(rented);
    }
}
```

## Runtime Types

Code that handles many types at once (RPC or message dispatch, a plugin system, editor tooling) rarely needs runtime types. Give the types a common `[NinoType]` base class or interface and serialize through it: `Serialize<TBase>` writes a type id, and `Deserialize<TBase>` reads it and creates the right type in generated code. This is the fastest way to handle many types, and it works with [reuse deserialization and pooling](/en/docs/v4/pooling), so a receive loop allocates nothing but the strings in the data:

```csharp
[NinoType]
public abstract class Message { }

public sealed class Ping : Message { public long SentAt; } // inherits [NinoType]
public sealed class Chat : Message { public string Text; }

var buffer = new NinoArrayBufferWriter();                  // one per connection, reused
NinoSerializer.Serialize<Message>(new Ping { SentAt = 1 }, buffer); // declared as the base: a type id is written

Message message = null;
NinoDeserializer.Deserialize(buffer.WrittenSpan, ref message); // a Ping, reused by later calls while the type matches
```

See [Polymorphism](/en/docs/v4/polymorphism#dispatching-through-a-common-base).

### The Boxed API [#the-boxed-api]

Use the boxed API **only** when the type is known only at run time, as a `Type`, and the types share no common `[NinoType]` base: reflection-driven tooling over arbitrary types, such as an inspector that saves whatever field it is pointed at. Serialize and deserialize with the **same** type:

```csharp
Type type = field.FieldType;                                   // known only at run time
byte[] bytes = NinoSerializer.SerializeBoxed(field.GetValue(target), type);
object copy = NinoDeserializer.DeserializeBoxed(bytes, type);

// into an existing instance, reused when it is an instance of type
object current = field.GetValue(target);
NinoDeserializer.DeserializeBoxed(bytes, ref current, type);
field.SetValue(target, current);
```

`SerializeBoxed(value, type)` writes exactly what `Serialize<T>(value)` with `T` = `type` would, `null` included for a type that can be null, so the generic and boxed calls read each other's data. The boxed API finds the formatter by `Type` (through reflection on first use, a dictionary lookup afterward) and boxes value types. `NinoSerializer.IsSupported(type)` tells whether Nino can serialize and deserialize a type at all (a `[NinoType]`, a built-in type or a type with a registered formatter), for code that has only a `Type` and must decide whether to handle it, such as the [ASP.NET Core formatters](/en/docs/v4/advanced/aspnetcore#mvc).

<Callout type="warn" title="Don't use object as T">

`NinoSerializer.Serialize(value)` with a variable declared as `object` calls `Serialize<object>`, not the boxed API. It accepts only `[NinoType]` values, writes a type id and dispatches through the global registry of every `[NinoType]`, which costs more than the generated dispatch of a common base. Declare the variable as the common base type instead, or call `SerializeBoxed` with the `Type`.

</Callout>

## Deep Object Graphs

Recursive types (a linked list, a tree, a node that holds another node) can nest to any depth. Nino writes the first 128 levels of nested objects in place; an object nested deeper is **deferred**: written later from a shallower level, and read back the same way. As a result:

- Writing and reading use a bounded amount of stack, however deep the graph is: a 100,000-node linked list round-trips on a 512 KB thread stack.
- Data cannot be crafted to overflow the reader's stack, so recursive types are safe in messages from untrusted sources.
- Data nested less than 128 levels deep is not affected: its bytes do not change.

```csharp
[NinoType]
public class TreeNode
{
    public int Value;
    public List<TreeNode> Children;
}

// As deep as you like: no StackOverflowException on either side.
byte[] bytes = NinoSerializer.Serialize(deepTree);
var copy = NinoDeserializer.Deserialize<TreeNode>(bytes);
```

A recursive type like `TreeNode` needs no `trackReferences` as long as the data is a tree, where each node is referenced once. If a node appears twice or the graph has a cycle, mark the type [`trackReferences: true`](/en/docs/v4/reference-tracking). Without it, a shared node is written as separate copies, and a cycle (`a.Next = b; b.Next = a;`) is detected while writing and throws an `InvalidOperationException` that names the type and points to `trackReferences`, so it never loops forever.

A deferred object is created and stored in its member or collection element as soon as Nino reaches that member, and its members are read later in the same call, so reuse deserialization and `[NinoPooled]` still reuse every instance. Two kinds of classes cannot be deferred like that and are always nested in place:

- classes created by their **constructor** (positional records, init-only or read-only members), since there is no instance until their members are read;
- classes **compared by value** (records, classes that override `GetHashCode` or implement `IComparable`), since a `HashSet<T>`, dictionary key or sorted collection could hold one before its members are read.

A graph of such classes nested deeper than [`NinoSettings.MaxDepth`](/en/docs/v4/security#limits) (512 levels by default) throws, counting the open bodies of structs that hold themselves around them too, on both sides: an `InvalidOperationException` when it is serialized, a `NinoDataException` when such data is read. Give a deeply recursive type a parameterless constructor and settable members.

## Invalid Data

Nino is built to read data from sources you do not trust: a network peer, a file a user hands you, a request body. Data crafted against a reader cannot crash the process, read past the end of the input, allocate out of proportion to its size, or make Nino create a type you did not declare:

- **Lengths are checked before anything is allocated.** Every count is checked against the bytes left, at the fewest bytes an element takes, and a collection allocates ahead of its elements at most 16 times the bytes left in the input (16 KB at least): a count beyond that is grown into as elements are actually read. Data that claims a billion elements in a few bytes is rejected.
- **The stack stays bounded.** Objects nested more than 128 levels deep are read later, from a shallow level, and what cannot wait (types built by their constructor or compared by value, structs and collections that hold themselves) is limited to [`NinoSettings.MaxDepth`](/en/docs/v4/security#limits) (512 by default), with the stack checked on the way: deeper data throws instead of overflowing the stack. See [Deep Object Graphs](#deep-object-graphs).
- **Only the types you declared.** The data holds type ids, never type names: a polymorphic value can only be one of the declared type's registered subtypes, and a back reference must point to an object already read, of the slot's type. `System.Type` is not serializable, on purpose.
- **A failed read leaves no stale memory.** Reading into an existing value never leaves an array of uninitialized memory in it when the data turns out short.

Invalid data throws a `NinoDataException` (namespace `Nino.Core`, derived from `InvalidOperationException`) whose message starts with `Nino:`, and nothing else: a value its own type rejects (a malformed `Uri`, an unknown culture or time zone, a `DateTimeOffset` out of range, a null dictionary key) is reported the same way, with the original exception as `InnerException`. For example:

- truncated data ("unexpected end of data");
- an impossible length;
- an unknown type id, or one that is not a subtype of the declared type;
- data nested deeper than the limits above;
- a `[NinoUtf8]` string whose bytes are not valid UTF-8 or do not match its char and byte counts;
- bytes Nino never writes: a `bool` or null flag other than 0 or 1, a string header longer than it needs to be or with a first byte of `0x82` or above, a keyed member whose entry holds more bytes than its value, a section of deferred bodies that does not match its region;
- a key repeated in a dictionary or set, or keys built to collide in a hash table ([hash flooding](/en/docs/v4/security#hash-flooding)).

The limits can be tightened in `NinoSettings`, and `NinoSettings.Untrusted` adds checks that cost time on every read; see [Untrusted Data](/en/docs/v4/security).

Catch it where the data comes in and treat the input as bad. What Nino cannot check is up to your code, as with a save file a user has edited:

- **Values.** A value read in full is whatever the data says: a negative health, an enum value with no name, and, unless [`NinoSettings.Untrusted`](/en/docs/v4/security#untrusted-mode) is set, a `bool` of an unmanaged struct copied as a block whose byte is neither 0 nor 1. Constructors and setters run with those values. Validate what your logic depends on.
- **The type.** The bytes carry no schema, so data written for a **different** type with a compatible layout reads without error. Version your payloads yourself (see [Evolving Your Data](/en/docs/v4/evolving-data) and the [file header](/en/docs/v4/advanced/persistence#add-a-file-header) pattern); `Deserialize<object>` accepts any registered type.
- **The size of a message.** Allocation is bounded relative to the input, so bound the input: cap the size of a frame or request before you buffer it (see [Frame the Stream](/en/docs/v4/advanced/networking#frame-the-stream)). Elements that really are in the data cost their size in memory: a large version-tolerant struct whose members are all left out takes 4 bytes on the wire.

## Terms [#terms]

Words these docs use with a specific meaning:

- **Top-level call**: a `NinoSerializer.Serialize(...)` or `NinoDeserializer.Deserialize(...)` call that takes your value and a `byte[]`, span or buffer writer, as opposed to a call that passes a `Writer` or `Reader` you created yourself, and to the values Nino reads and writes inside a call. Each top-level call is self-contained: it starts and ends its own [reference tracking](/en/docs/v4/reference-tracking).
- **Boxed API**: `SerializeBoxed` and `DeserializeBoxed`, the overloads that take an `object` and a `Type`, for a type known only at run time that shares no common `[NinoType]` base with the others; see [The Boxed API](#the-boxed-api).
- **Formatter**: the code that writes and reads one type: generated for each `[NinoType]`, built into Nino for the BCL types, or [written by you](/en/docs/v4/custom-formatters). The **formatter cache** is `NinoFormatterCache<T>`, the static field through which a call finds the formatter of `T`.
- **Intercepted call**: on the .NET 8 SDK and later, the generator redirects each call whose type is known at compile time straight to that type's formatter, skipping the formatter cache; see [Interceptors](/en/docs/v4/performance#interceptors).
- **Scratch buffer**: a `NinoArrayBufferWriter` that Nino keeps per thread. A call that returns a `byte[]`, or writes into a buffer writer other than `NinoArrayBufferWriter`, serializes into it first and then copies the bytes out.
- **Raw** (raw value, raw struct): an unmanaged value that Nino writes as its memory, in one copy, with padding bytes zeroed: primitives, enums, `DateTime`, `Guid`, and unmanaged structs that qualify (see [Structs](/en/docs/v4/defining-types#structs)). Arrays and lists of raw values are one block copy.
- **Fixed-size type**: a struct or sealed class whose values always take the same number of bytes, returned by `NinoSerializer.GetFixedSize<T>()`; see [Fixed-Size Types](/en/docs/v4/performance#fixed-size-types).
- **Positional**: the default format of a `[NinoType]`: members in declaration order, with no names or lengths. Smallest and fastest, but any change to the members changes the format; see [Evolving Your Data](/en/docs/v4/evolving-data#positional).
- **Version-tolerant** and **keyed**: the two other formats (`NinoFormat.VersionTolerant` and `NinoFormat.Keyed`). A version-tolerant object writes its length in bytes first, so members can be appended later; a keyed object writes each member with a key (a hash of its name) and a length, so members can be added, removed, reordered or renamed. See [Evolving Your Data](/en/docs/v4/evolving-data).
- **Slot**: a place that holds a value: a member, a collection element, a dictionary value, or the variable you pass by `ref`. What Nino writes for a value depends on the slot's declared type.
- **Header**: the bytes Nino writes before a class value: a 1-byte null flag for a sealed class, a 4-byte type id for a type that can have subtypes; a struct has none. See [How a Polymorphic Value Is Written](/en/docs/v4/polymorphism#how-a-polymorphic-value-is-written).
- **Reuse deserialization**: `Deserialize(data, ref value)`, which fills the value you pass, and the objects, lists and dictionaries it holds, in place instead of creating new ones; see [Into an Existing Value](#into-an-existing-value).
- **Pooled class**: a `[NinoType]` class marked `[NinoPooled]`: Nino takes new instances of it from a built-in pool and returns dropped ones to it; see [`[NinoPooled]`](/en/docs/v4/pooling#ninopooled).
- **Recycler**: what receives an instance that [reuse deserialization](/en/docs/v4/pooling) drops from a slot: a handler registered with `NinoSettings.SetRecycler<T>`, otherwise the instance's own pool (`ReturnToPool()`), otherwise nobody. See [Where Dropped Instances Go](/en/docs/v4/pooling#where-dropped-instances-go).
- **Registry**: the code the generator emits into each assembly to list its `[NinoType]`s, their formatters and their type ids. Nino loads it the first time it meets a type of that assembly, or a type id it does not know, so no initialization call is needed; `NinoRegistry.EnsureInitialized(assembly)` loads it ahead of time. The **global registry** is the table of every `[NinoType]` through which values declared as `object` are dispatched; see [Dispatch](/en/docs/v4/polymorphism#dispatch).
- **Deferred object**: an object nested more than 128 levels deep, written and read later from a shallower level so that the stack stays bounded; see [Deep Object Graphs](#deep-object-graphs).
