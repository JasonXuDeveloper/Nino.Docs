Nino 就是为读取不可信来源的数据而设计的：网络对端发来的消息、用户交给你的文件、请求体。本页列出每次读取都会做的检查、可以在 `NinoSettings` 中收紧的限制、`NinoSettings.Untrusted` 额外的检查，以及仍需你的代码负责的部分。

## 保证 [#guarantees]

无论字节是什么，一次读取都：

- **不会读到输入之外**，也不会读出它所在的区域或键控条目；
- **按输入的大小分配内存**：每个长度在分配任何内存之前，先按元素最少占用的字节数与剩余字节数比较；集合在读到元素之前最多预先分配剩余字节数的 16 倍（至少 16 KB），更大的数量随着元素真正读入再增长；
- **栈深度有界**：嵌套超过 128 层的对象会延迟到较浅的层级再读；其他会嵌套的内容（由构造函数创建或按值比较的类型、包含自身的结构体和集合）在 [`NinoSettings.MaxDepth`](#limits) 处停止，途中还会检查线程栈（见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)）；
- **只创建你声明过的类型**：数据中只有类型 ID，没有类型名；多态值只能是声明类型已注册的子类型之一，回引用只能指向已读过、且类型与槽位相符的对象；
- **限制它填充的字典和集合中每个键的工作量**（[哈希洪泛](#hash-flooding)）；
- **只抛出一种异常**：以上所有情况都抛出 [`NinoDataException`](#ninodataexception)。

## NinoDataException [#ninodataexception]

每一项拒绝数据的检查都抛出 `NinoDataException`（命名空间 `Nino.Core`），消息以 `Nino:` 开头。值在创建时被其自身类型拒绝（格式错误的 `Uri`、未知的区域性或时区、超出范围的 `DateTimeOffset`、为 null 的字典键）时也同样报告，原始异常放在 `InnerException` 中。在数据进入的地方捕获它：

```csharp title="Receive.cs"
try
{
    var message = NinoDeserializer.Deserialize<Message>(payload);
    Handle(message);
}
catch (NinoDataException e)
{
    // 这段数据不是 Message 的有效 Nino 数据：丢弃、记录日志或关闭连接。
    log.Warn($"Bad message from {peer}: {e.Message}");
}
```

`NinoDataException` 派生自 `InvalidOperationException`，即 Nino 在 4.0.0-rc.7 及之前对无效数据抛出的类型，所以 `catch (InvalidOperationException)` 仍然能捕获它。调用方的错误保留各自的异常类型：参数为 null、类型没有格式化器、反序列化到只读集合、[过晚修改设置](#limits)。**序列化**时的失败也是如此（对象图有未跟踪的循环，或嵌套超过 `MaxDepth`），抛出 `InvalidOperationException`：那是你的对象，不是无效数据。[Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore) 对无效请求体返回 400。

## 会被拒绝的数据 [#what-is-rejected]

在任何模式下，以下情况都抛出 `NinoDataException`：

- 数据提前结束；长度或数量为负（null 用的 `-1` 除外），或剩余字节放不下；
- 集合长度超过 [`MaxCollectionLength`](#limits)；
- 未知的类型 ID、不是声明类型子类型的 ID，以及无效的回引用；
- 嵌套深度超过 [`MaxDepth`](#limits)；
- 读取从空开始填充的字典、`HashSet<T>` 或查找表时出现重复键，以及某个键在其哈希桶中遇到超过 [`MaxHashCollisions`](#hash-flooding) 个键；
- 值不是 `0` 或 `1` 的 `bool`、null 标记或 has-value 字节（Nino 只写这两个值）；
- 条目中的字节多于其值的键控成员，以及超出其区域末尾的成员；
- 延迟主体段（其偏移或条目）与所在区域不符的版本容错或键控区域；
- 字节不是有效 UTF-8、或与字符数和字节数不符的 `[NinoUtf8]` 字符串。

原始结构体中的 `bool` 字段随结构体的字节一起复制，不做检查，除非开启了 [`Untrusted`](#untrusted-mode)。值元组和 `KeyValuePair` 中的 `bool` 项在任何模式下都会检查，按块读取的数组和列表也一样。

## 限制 [#limits]

`NinoSettings`（命名空间 `Nino.Core`）中的这些静态成员限制一次读取能占用的资源：

<TypeTable
  type={{
    MaxDepth: {
      description: '读写数据时对象最多可以嵌套多深：类主体，加上可能包含自身的结构体和集合。Nino 能在读取成员之前创建的类，超过 128 层的主体会被延迟，不需要限制；这个值限制其余的一切。至少 128。读取时过深抛出 NinoDataException，写入时抛出 InvalidOperationException。',
      type: 'int',
      default: '512',
    },
    MaxCollectionLength: {
      description: '数据中一个集合或数组最多可以声称有多少个元素（或键值对）；更长的在分配任何内存之前就抛出 NinoDataException。多维数组按元素总数计算。每个长度本来就会与剩余字节数比较，所以只在需要限制有效但很大的数据所占内存时才调低它。',
      type: 'int',
      default: 'int.MaxValue',
    },
    MaxHashCollisions: {
      description: 'Nino 把从数据中读到的键加入它所填充的哈希表时，这个键在其哈希桶中最多可以遇到多少个键；更多则抛出 NinoDataException。至少 1。见“哈希洪泛”。',
      type: 'int',
      default: '100',
    },
    Untrusted: {
      description: '加上每次读取都要花时间的检查：常见键类型的带种子哈希、按原始字节复制的值的范围检查，以及拒绝值之后的字节。见“不可信模式”。',
      type: 'bool',
      default: 'false',
    },
  }}
/>

<Callout type="warn" title="在首次使用前设置">

读写路径把这四个值当作常量：Nino 第一次用到其中任何一个时它们就被冻结，之后再设置会抛出 `InvalidOperationException`。请在启动时、任何线程第一次序列化或反序列化之前设置。超出范围的值（`MaxDepth` 小于 128、`MaxCollectionLength` 为负、`MaxHashCollisions` 小于 1）抛出 `ArgumentOutOfRangeException`。

</Callout>

```csharp title="Program.cs"
// 启动时，在任何 Nino 调用之前。
NinoSettings.Untrusted = true;              // 数据来自客户端
NinoSettings.MaxCollectionLength = 100_000; // 我们的消息都不会更多
```

`NinoSettings` 中对象池和回收器的设置见[对象池](/zh/docs/v4/pooling#settings)。

## 哈希洪泛 [#hash-flooding]

精心构造、全部落在同一个哈希桶中的键，会让每次插入都扫描它之前的所有键，于是填充这样一个字典所需的时间与其大小的平方成正比。在任何模式下，从数据中读到的键如果在其哈希桶中遇到超过 `MaxHashCollisions`（默认 100）个键，就抛出 `NinoDataException`。这适用于 `Dictionary<TKey, TValue>`、`HashSet<T>`、查找表（`ILookup`）、`ConcurrentDictionary<TKey, TValue>`，以及 Nino.Immutable 中的 `ImmutableDictionary<TKey, TValue>` 和 `ImmutableHashSet<T>`（在这两者中，指超过这么多个键有相同的哈希码）。

- Nino 自己填充新表时，计数没有额外开销，因为它本来就要遍历哈希桶来查找重复键；由表自己添加键时（读入已有集合），Nino 在添加之后遍历新键所在的桶。
- 哈希码合理的键，每个桶大约只有一个键。哈希码较差的键（例如没有自己的 `GetHashCode` 的结构体键）可以调高这个限制。
- 字符串键交给那些在 100 次冲突后会自行改用随机化比较器的表处理（.NET 的 `Dictionary`、`HashSet` 和 `ConcurrentDictionary`，以及 .NET Framework 的 `Dictionary` 和 `ConcurrentDictionary`）。
- `ConcurrentDictionary<TKey, TValue>` 不公开自己的桶：Nino 通过为每个运行时（.NET、.NET Framework、Mono 和 Unity）声明、并在启动时检查的布局找到它们，在构建新字典时为每个键所在的桶计数，读入已有字典时则在每次添加之后遍历该桶。没有匹配的布局时，由字典的构造函数填充，不计数。

## 不可信模式 [#untrusted-mode]

`NinoSettings.Untrusted = true` 加上每次读取都要花时间、可信数据不需要的检查。关闭时（默认）它们没有任何开销：读取路径把它当作常量判断。开启后：

- **带种子的哈希。** Nino 创建的字典和哈希集合（包括 `IDictionary`、`ISet` 和查找表）对整数、`char`、`Guid` 和 `string` 键使用以每个进程随机生成的密钥为种子的比较器（SipHash-1-3），使键根本无法被选成相互冲突。它们的 `Comparer` 不是默认比较器，但相等性相同。你传入的集合保留自己的比较器；其他键类型，以及 `ImmutableDictionary` 和 `ImmutableHashSet`，依靠 `MaxHashCollisions`。
- **按字节复制的值也会检查**，与其自身构造函数的检查一致，原始结构体和元组内部也一样：不是 0 或 1 的 `bool`、超过 `DateTime.MaxValue` 的 `DateTime`、标志位中除符号和小数位数之外还有其他位、或小数位数超过 28 的 `decimal`、超出范围的 `DateOnly` 或 `TimeOnly`。枚举不检查：底层类型的任何值都是有效的枚举值（标志可以组合，新版本也可能增加成员）。`TimeSpan`、`Guid`、`char` 和数字没有无效值。
- **值之后的字节**对接收整段数据（span 或数组）的 API（`NinoDeserializer.Deserialize` 和生成的重载）而言是无效数据。从你自己创建的 `Reader` 读取时，其余字节交给你处理，所以仍然可以从一个缓冲区中读取多个值。

## 仍需你负责的部分 [#what-stays-your-job]

Nino 检查数据的结构，而不是数据的含义，就像对待用户编辑过的存档文件一样：

- **值。** 完整读取的值就是数据所写的值：负的生命值、没有名字的枚举值。构造函数和 setter 会以这些值运行。请校验你的逻辑所依赖的值。
- **类型。** 字节中不带模式信息，所以为**另一个**布局兼容的类型写出的数据也能无错读取。请自己为数据加上版本（见[数据演进](/zh/docs/v4/evolving-data)和[文件头](/zh/docs/v4/advanced/persistence#add-a-file-header)模式）；`Deserialize<object>` 接受任何已注册的类型。
- **消息大小。** 内存分配与输入大小成比例，所以要限制输入：在缓冲之前限制帧或请求的大小（见[为流分帧](/zh/docs/v4/advanced/networking#frame-the-stream)）。数据中真实存在的元素会按其大小占用内存：一个成员全部省略的大型版本容错结构体在线上只占 4 个字节。

## 其他语言 [#other-languages]

[TypeScript、Go 和 Rust 的读取器](/zh/docs/v4/advanced/codegen#untrusted-data)做同样的检查：在分配之前检查边界和长度，按 .NET 的方式计算深度，类型 ID 仅限槽位允许的类型，并严格检查字节。它们各自只抛出或返回一种错误类型。Go 和 Rust 还会拒绝一些 .NET 在不可信模式之外接受的字节，例如超出范围的日期和 decimal。所有读取器遵循的规则见[二进制格式](/zh/docs/v4/wire-format#validation)。
