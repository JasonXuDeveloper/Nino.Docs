大家问得最多的 Nino 问题，每个回答都链接到详细页面。最后几个讲的是最常碰到的报错和意外。

## Nino 是什么？ [#what-is-nino]

Nino 是一个通用的高性能 C# / .NET 二进制序列化库。给类型加上 `[NinoType]`，Roslyn 源生成器就会在编译期写好它的序列化代码；运行时调用 `NinoSerializer.Serialize` 和 `NinoDeserializer.Deserialize` 就行。不用反射，不在运行时生成代码，没有 schema 文件，也不用注册。Nino 以 MIT 协议开源：[github.com/JasonXuDeveloper/Nino](https://github.com/JasonXuDeveloper/Nino)。参见[介绍](/zh/docs/v4)。

## 怎么安装 Nino？ [#how-do-i-install-nino]

.NET 或 Godot 项目里运行 `dotnet add package Nino --prerelease`（v4 还是预发行版：不加这个参数，NuGet 装的是稳定版 3.9.x，那是试验 v4 功能的过渡版本，和 v4 不兼容）；`Nino` 包会带上运行时（`Nino.Serialization`）和源生成器（`Nino.Generator`）。Unity 里从 OpenUPM 安装 `com.jasonxudeveloper.nino`（`openupm add com.jasonxudeveloper.nino`），源生成器已经包含在内。另有几个可选包：不可变集合（`Nino.Immutable`）、ASP.NET Core 请求体与响应（`Nino.AspNetCore`）、生成 TypeScript、Go 或 Rust 代码（`Nino.Codegen`）。参见[快速开始](/zh/docs/v4/start)。

## Nino 支持哪些平台和 .NET 版本？ [#which-platforms-and-net-versions-does-nino-support]

运行时的目标框架是 `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0`。.NET 服务端和桌面程序、Unity 2022.3 及以上版本（Mono 与 IL2CPP，所有 Player 平台）、Godot 4 .NET 项目和 HybridCLR 热更新都能用，跨平台、跨运行时字节一致。源生成器要求 Roslyn 4.3 或更高版本，项目要用 C# 9 或更高版本。参见[平台](/zh/docs/v4/platforms)。

## Nino 用反射吗？能在 IL2CPP 和 NativeAOT 下用吗？ [#does-nino-use-reflection-does-it-work-with-il2cpp-and-nativeaot]

不用反射：源生成器在编译期给每个类型生成一个格式化器，所以 IL2CPP、NativeAOT 和 HybridCLR 这些不能在运行时生成代码的环境里，Nino 照样能用。参见[性能原理](/zh/docs/v4/performance)。

Nino.Core 的 net8.0 和 net10.0 版本还带了裁剪和 Native AOT 标注：用 `PublishTrimmed` 或 `PublishAot` 发布，Nino 不报任何警告。Native AOT 下，Nino 只用生成器写好的格式化器，所以要序列化的每个类型，都得出现在生成器看得到的代码里（当成员类型，或者当 `NinoSerializer`/`NinoDeserializer` 调用的类型实参或 `typeof` 参数）。只在运行时才出现的类型会报错，错误里写明是哪个类型，绝不会读写出错的数据。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。

## Nino 和 MemoryPack 相比有多快？ [#how-fast-is-nino-compared-with-memorypack]

在同一次基准测试里，Nino v4 序列化最多比 MemoryPack 快 <BenchValue k="serialize.max" />，反序列化类和多态对象图最多快 <BenchValue k="deserialize.max" />；原始结构体数组上两者至少持平。序列化到复用的缓冲区不分配内存。参见[.NET 基准测试](/zh/docs/v4/benchmarks)和 [Nino 与 MemoryPack 对比](/zh/docs/v4/vs-memorypack)。

## Nino 和 MessagePack、protobuf-net 比怎么样？ [#how-does-nino-compare-with-messagepack-and-protobuf-net]

它们写出的格式，其他语言的程序不用你的 C# 类型也能读：MessagePack 给每个值打类型标记，Protocol Buffers 给每个字段编号。Nino 的字节由你的 C# 类型决定，在 .NET 里读，也能通过生成的代码与 Go、Rust 和 TypeScript 互通。换来的好处是：Nino 默认模式就能读不可信数据，成员上不用写键或字段号，多态不用列子类型，还能追踪共享引用，这些它们都做不到。发布时的基准测试会用同样的数据测它们和 Nino。参见 [Nino 与 MessagePack 对比](/zh/docs/v4/vs-messagepack)和 [Nino 与 protobuf-net 对比](/zh/docs/v4/vs-protobuf-net)。

## Nino 适合用在哪里？ [#what-can-i-use-nino-for]

凡是要把 .NET 对象变成紧凑的字节、再还原回来的地方都行：服务之间的网络协议与 RPC、消息队列与事件流、缓存、文件等持久化存储、进程间通信、数据管道。同一份代码在 .NET 服务器、桌面应用、Unity 和 Godot 上都能跑。参见[进阶指南](/zh/docs/v4/advanced)。

## 数据写出后还能修改类型吗？ [#can-i-change-my-types-after-data-has-been-written]

可以，前提是事先选对格式。普通的 `[NinoType]` 按位置写，最快；`[NinoType(format: NinoFormat.VersionTolerant)]` 可以在末尾追加成员；`[NinoType(format: NinoFormat.Keyed)]` 可以增删成员、调整顺序。参见[数据演进](/zh/docs/v4/evolving-data)。

## Nino 支持多态和共享引用吗？ [#does-nino-support-polymorphism-and-shared-references]

支持。声明为基类或接口的值，读回来还是它的运行时类型，不用维护 Union 标签。引用追踪按类型开启，能保留共享引用和循环引用。参见[多态](/zh/docs/v4/polymorphism)和[引用追踪](/zh/docs/v4/reference-tracking)。

## 怎么序列化多种消息类型，或者运行时才知道的类型？ [#how-do-i-serialize-many-message-types-or-a-type-known-only-at-run-time]

给这些类型一个共同的 `[NinoType]` 基类或接口，再调用 `Serialize<TBase>` / `Deserialize<TBase>`：类型 ID 由生成的代码写入和分派，这是最快的做法，还能配合复用反序列化和对象池，每条消息除了内容变了的字符串，什么都不分配。RPC 和消息分派、插件系统、编辑器工具都适合这么做。只有手里只有一个 `Type`、这些类型又没有共同基类时（比如靠反射处理任意类型的工具），才用 `SerializeBoxed(value, type)` 和 `DeserializeBoxed(data, type)`。别把 `object` 当类型实参：它只接受 `[NinoType]` 的值，而且要经过全局注册表分派，开销更大。参见[运行时类型](/zh/docs/v4/basic#runtime-types)。

## Nino 是线程安全的吗？ [#is-nino-thread-safe]

是。`NinoSerializer` 和 `NinoDeserializer` 都是静态的，多少个线程同时调用都不用加锁。你自己创建的 `NinoArrayBufferWriter` 不是线程安全的：每个线程或每个连接用一个。参见[序列化与反序列化](/zh/docs/v4/basic)。

## Nino v4 能读取 Nino v3 写出的数据吗？ [#can-nino-v4-read-data-written-by-nino-v3]

不能。v4 用的是新的二进制格式，读不了 v3、也读不了 v4 测试版和预览版写的数据，存下来的 v3 数据要转换一次。见[从 v3 迁移](/zh/docs/v4/migration)。v4 候选版本之间升级，见[从更早的候选版本升级](/zh/docs/v4/migration#upgrading-from-an-earlier-release-candidate)。

## JavaScript 或 TypeScript 里能用 Nino 吗？ [#can-i-use-nino-from-javascript-or-typescript]

可以。[Nino.Codegen](/zh/docs/v4/advanced/typescript) 每次构建后为你的 `[NinoType]` 生成 TypeScript 类、枚举和编解码器，再配上 `nino.ts` 运行时，浏览器和 Node 不用 .NET 运行时就能与 .NET 互通，字节完全一致。泛型类型、引用追踪和少数内置类型不在其列（[TypeScript 不支持的内容](/zh/docs/v4/advanced/typescript#not-supported)）。要用这些，就在浏览器里直接跑 C# 类型：做一个引用 Nino 的 .NET `browser-wasm` 应用，通过 `[JSExport]` 从 JavaScript 调用，代价是浏览器要下载 .NET 运行时。参见[浏览器客户端](/zh/docs/v4/advanced/browser)。

## ASP.NET Core 能读写 Nino 请求体和响应吗？ [#can-aspnet-core-read-and-write-nino-bodies]

可以，用 [Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore)（4.0.0-rc.6 及以上）：`AddNinoFormatters()` 为 `application/x-nino` 添加 MVC 输入和输出格式化器；Minimal API 用 `NinoBody<T>` 参数接收、用 `NinoResults.Ok(value)` 返回。请求体直接从请求管道读，响应直接写进响应管道，自身不分配内存。

## 什么时候不该用 Nino？ [#when-should-i-not-use-nino]

数据要给人看或手改时（用 JSON、YAML 或 TOML）；或者要让 C#、TypeScript、JavaScript、Go、Rust 以外的语言读时：格式由你的 C# 类型决定，没有 schema 文件，也没有面向那些语言的生成器，这时用 Protocol Buffers、FlatBuffers 或 MessagePack（[Nino 与 MessagePack 对比](/zh/docs/v4/vs-messagepack)、[Nino 与 protobuf-net 对比](/zh/docs/v4/vs-protobuf-net)）。JavaScript、TypeScript、Go 和 Rust 程序通过[生成的代码](/zh/docs/v4/advanced/codegen)使用 Nino，浏览器还能在 [.NET WebAssembly](/zh/docs/v4/advanced/browser) 上直接跑 C# 类型。参见[局限性](/zh/docs/v4/limit)。

## 为什么 Nino 提示某个类型没有格式化器？ [#no-formatter]

`Nino: no formatter for T` 表示 Nino 不知道怎么写 `T`。给它加上 `[NinoType]`，或者用 [`[assembly: NinoFormatter]`](/zh/docs/v4/custom-formatters#for-a-type-assembly-ninoformatter) 为它声明格式化器（也可以在成员上用 [`[NinoMemberFormatter]`](/zh/docs/v4/custom-formatters#for-one-member)）。如果是成员，你写代码时分析器就会报出来（NINO007）。另外，声明这个类型的项目里也得运行源生成器：在那个项目里安装 `Nino` 包；Unity 里让它所在的程序集引用 `Nino.Core`。

Native AOT 下，错误信息会说运行时没法现场构建格式化器：只有源生成器见过的封闭类型才有格式化器。在某个 `[NinoType]` 成员或某次 `Serialize`/`Deserialize` 调用里写出这个确切的类型。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。

## 为什么读取时报错说某个类型 ID 不是已注册的子类型？ [#unknown-type-id]

数据里写的类型，读取方在声明类型下面找不到。常见原因：子类型所在的程序集还没加载（先加载就行，不用注册）；类型改名或挪了位置，却没加 [`[NinoFormerName]`](/zh/docs/v4/evolving-data#former-name)；或者数据是按另一个声明类型写的。进程只读不写的封闭泛型子类型，要在启动时调用 `NinoPolymorphic.TryRegister<T>()`。如果是*写入*时报错说某个类型不是已注册的子类型，说明这个运行时类型不是 `[NinoType]`：它的基类设了 `inheritedBySubtypes: false`（NINO003），或者它所在的程序集没跑源生成器。参见[其他程序集中的子类型](/zh/docs/v4/polymorphism#subtypes-in-other-assemblies)。

## 为什么序列化时报错说对象图中有环？ [#cycle]

某个对象经由成员又引用回自己，又没有类型追踪引用，就会一直写下去。把环上的类型标成 [`trackReferences: true`](/zh/docs/v4/reference-tracking)。报错说某个类型嵌套超过 512 层时也这样处理；另外，靠构造函数创建或按值比较的类没法推迟，所以深度递归的类型要有无参构造函数和可赋值的成员。参见[深层对象图](/zh/docs/v4/reference-tracking#deep-object-graphs)。

## 为什么旧数据读不出来了，或者读出的值不对？ [#old-data]

只写 `[NinoType]` 就是按位置格式：增删成员、调整顺序都会改变字节，这时读旧数据会抛异常（`unexpected end of data`、`invalid length`），更糟的是读出错的值，因为字节里不带 schema。要存下来的数据，写第一份之前就选好 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`；版本容错的继承体系里，只往没有子类的类追加成员。想在 CI 里发现改动，就比较每次构建的[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。参见[数据演进](/zh/docs/v4/evolving-data)。

## 为什么拦截器没接管我的调用？ [#not-intercepted]

拦截器要求 Roslyn 4.8 或更高版本（.NET 8 SDK 及以上）；Unity 用的是 Roslyn 4.3 版本，从不拦截。泛型代码里的调用、针对别的程序集声明的 `[NinoType]` 的调用，以及针对原始值的调用，都是有意走常规路径。如果项目自己设置了 `InterceptorsNamespaces`，在原值后面追加，别整个替换。拦不拦截，字节都一样。参见[拦截器](/zh/docs/v4/performance#interceptors)。

## 为什么我的热路径还在分配内存？ [#still-allocates]

按顺序检查：是不是序列化到复用的 `NinoArrayBufferWriter`（或其他 `IBufferWriter<byte>`），而不是调用返回新 `byte[]` 的 `Serialize(value)`；是不是用 `ref` 读入已有的值；自己创建的 `Writer` 或 `Reader` 最后有没有调用 `ReleaseReferences()`；数组长度是不是不变（数量会变就用 `List<T>`）；Nino 要新建的类有没有标 `[NinoPooled]`；是不是预热之后才测。内容变了的文本，总要产生新字符串。参见[哪些调用会分配内存](/zh/docs/v4/advanced/zero-allocation#what-allocates)和[检查清单](/zh/docs/v4/advanced/zero-allocation#checklist)。
