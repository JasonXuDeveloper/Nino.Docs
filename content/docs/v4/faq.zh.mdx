关于 Nino 最常被问到的问题，每个回答都附有详细页面的链接。最后几个问题讲的是最常遇到的错误和意外情况。

## Nino 是什么？ [#what-is-nino]

Nino 是通用的高性能 C# / .NET 二进制序列化库。给类型加上 `[NinoType]`，Roslyn 源生成器就会在编译期生成它的序列化代码；运行时调用 `NinoSerializer.Serialize` 和 `NinoDeserializer.Deserialize` 即可。没有反射，没有运行时代码生成，没有 schema 文件，也不需要注册。Nino 以 MIT 协议开源：[github.com/JasonXuDeveloper/Nino](https://github.com/JasonXuDeveloper/Nino)。参见[介绍](/zh/docs/v4)。

## 如何安装 Nino？ [#how-do-i-install-nino]

在 .NET 或 Godot 项目中运行 `dotnet add package Nino --prerelease`（v4 仍是预发行版：不加这个参数时 NuGet 会安装稳定版 3.9.x，它是测试 v4 功能的过渡版本，与 v4 不兼容）；`Nino` 包会引入运行时（`Nino.Serialization`）和源生成器（`Nino.Generator`）。在 Unity 中，从 OpenUPM 安装 `com.jasonxudeveloper.nino`（`openupm add com.jasonxudeveloper.nino`），其中已包含源生成器。可选包分别提供不可变集合（`Nino.Immutable`）、ASP.NET Core 请求体与响应（`Nino.AspNetCore`）和生成的 TypeScript、Go 或 Rust 代码（`Nino.Codegen`）。参见[快速开始](/zh/docs/v4/start)。

## Nino 支持哪些平台和 .NET 版本？ [#which-platforms-and-net-versions-does-nino-support]

运行时面向 `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0`。Nino 可用于 .NET 服务端和桌面程序、Unity 2022.3 及以上版本（Mono 与 IL2CPP，所有 Player 平台）、Godot 4 .NET 项目以及 HybridCLR 热更新，并且所有目标写出的字节完全相同。源生成器需要 Roslyn 4.3 或更高版本，项目需使用 C# 9 或更高版本。参见[平台与二进制格式](/zh/docs/v4/platforms)。

## Nino 使用反射吗？能在 IL2CPP 和 NativeAOT 下使用吗？ [#does-nino-use-reflection-does-it-work-with-il2cpp-and-nativeaot]

不使用反射：源生成器在编译期为每个类型生成一个格式化器，因此 Nino 可以在不支持运行时代码生成的 IL2CPP、NativeAOT 和 HybridCLR 环境中使用。参见[性能指南](/zh/docs/v4/performance)。

Nino.Core 的 net8.0 和 net10.0 版本还带有裁剪和 Native AOT 标注：用 `PublishTrimmed` 或 `PublishAot` 发布时，Nino 不会产生任何警告。在 Native AOT 下，Nino 只使用生成器写好的格式化器，所以要序列化的每个类型都必须出现在生成器看得到的代码里（作为成员类型，或作为 `Serialize`、`Deserialize` 调用的类型参数）。只在运行时才出现的类型会抛出一个指明该类型的错误，不会读写出错误的数据。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。

## Nino 和 MemoryPack 相比有多快？ [#how-fast-is-nino-compared-with-memorypack]

在同一次基准测试中，Nino v4 的序列化最高比 MemoryPack 快 <BenchValue k="serialize.max" />，类与多态对象图的反序列化最高快 <BenchValue k="deserialize.max" />；原始结构体数组上两者至少持平。序列化到复用的缓冲区时零分配。参见[基准测试](/zh/docs/v4/benchmarks)和 [Nino 与 MemoryPack 对比](/zh/docs/v4/vs-memorypack)。

## Nino 适合用在哪里？ [#what-can-i-use-nino-for]

凡是需要把 .NET 对象转成紧凑字节、再还原回来的地方：服务之间的网络协议与 RPC、消息队列与事件流、缓存、文件等持久化存储、进程间通信以及数据管道。同样的代码可以运行在 .NET 服务器、桌面应用、Unity 和 Godot 上。参见[进阶指南](/zh/docs/v4/advanced)。

## 数据写出后还能修改类型吗？ [#can-i-change-my-types-after-data-has-been-written]

可以，只要事先选好格式。普通的 `[NinoType]` 按位置写入，速度最快；`[NinoType(format: NinoFormat.VersionTolerant)]` 允许在末尾追加成员；`[NinoType(format: NinoFormat.Keyed)]` 允许添加、删除和重新排序成员。参见[数据演进](/zh/docs/v4/evolving-data)。

## Nino 支持多态和共享引用吗？ [#does-nino-support-polymorphism-and-shared-references]

支持。声明为基类或接口的值读回时仍是它的运行时类型，无需维护 Union 标签。按类型开启的引用追踪可以保留共享引用和循环引用。参见[多态](/zh/docs/v4/polymorphism)和[引用追踪](/zh/docs/v4/reference-tracking)。

## 如何序列化多种消息类型，或者运行时才知道的类型？ [#how-do-i-serialize-many-message-types-or-a-type-known-only-at-run-time]

给这些类型一个共同的 `[NinoType]` 基类或接口，然后调用 `Serialize<TBase>` / `Deserialize<TBase>`：类型 ID 的写入和分派都由生成代码完成，速度最快，还能配合复用反序列化和对象池，每条消息除了内容变化的字符串之外不分配内存。RPC 和消息分派、插件系统、编辑器工具都适用这种做法。只有当类型只能以 `Type` 的形式得知、并且这些类型没有共同的基类型时（例如基于反射、面向任意类型的工具），才使用 `SerializeBoxed(value, type)` 和 `DeserializeBoxed(data, type)`。不要把 `object` 当作类型参数：它只接受 `[NinoType]` 的值，并通过开销更大的全局注册表分派。参见[运行时类型](/zh/docs/v4/basic#runtime-types)。

## Nino 是线程安全的吗？ [#is-nino-thread-safe]

是的。`NinoSerializer` 和 `NinoDeserializer` 都是静态的，可以在任意多个线程中调用，无需加锁。你自己创建的 `NinoArrayBufferWriter` 不是线程安全的：每个线程或每个连接使用一个。参见[序列化与反序列化](/zh/docs/v4/basic)。

## Nino v4 能读取 Nino v3 写出的数据吗？ [#can-nino-v4-read-data-written-by-nino-v3]

不能。v4 使用新的二进制格式，无法读取 v3 以及 v4 测试版和预览版写出的数据，已存储的 v3 数据需要转换一次。参见[从 v3 迁移](/zh/docs/v4/migration)。在 v4 各候选版本之间升级，参见[从更早的候选版本升级](/zh/docs/v4/migration#upgrading-from-an-earlier-release-candidate)。

## 能在 JavaScript 或 TypeScript 中使用 Nino 吗？ [#can-i-use-nino-from-javascript-or-typescript]

可以。[Nino.Codegen](/zh/docs/v4/advanced/codegen#typescript) 在每次构建后为你的 `[NinoType]` 生成 TypeScript 类、枚举和编解码器，并附带 `nino.ts` 运行时，浏览器和 Node 读写的字节与 .NET 写出的完全相同，无需 .NET 运行时。它不支持泛型类型、引用跟踪和少数内置类型（[TypeScript 不支持的内容](/zh/docs/v4/advanced/codegen#not-supported)）。需要这些功能时，可以在浏览器中直接运行 C# 类型：构建一个引用 Nino 的 .NET `browser-wasm` 应用，通过 `[JSExport]` 从 JavaScript 调用，代价是浏览器要下载 .NET 运行时。参见[浏览器与 JavaScript 客户端](/zh/docs/v4/advanced/browser)。

## ASP.NET Core 能读写 Nino 请求体和响应吗？ [#can-aspnet-core-read-and-write-nino-bodies]

可以，使用 [Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore)（4.0.0-rc.6 及以上）：`AddNinoFormatters()` 为 `application/x-nino` 添加 MVC 输入和输出格式化器，Minimal API 用 `NinoBody<T>` 参数接收、用 `NinoResults.Ok(value)` 返回。请求体从请求管道读取、响应写入响应管道，自身不做任何分配。

## 什么时候不该用 Nino？ [#when-should-i-not-use-nino]

当数据需要人来阅读或编辑时（请用 JSON、YAML 或 TOML），或者需要由 C#、TypeScript、JavaScript、Go、Rust 以外语言的程序读取时：格式由你的 C# 类型定义，没有 schema 文件，也没有面向这些语言的生成器，这种情况请使用 Protocol Buffers、FlatBuffers 或 MessagePack。JavaScript、TypeScript、Go 和 Rust 程序可以通过[生成的代码](/zh/docs/v4/advanced/codegen)使用 Nino，浏览器还可以在 [.NET WebAssembly](/zh/docs/v4/advanced/browser) 上运行 C# 类型。参见[局限性](/zh/docs/v4/limit)。

## 为什么 Nino 提示某个类型没有格式化器？ [#no-formatter]

`Nino: no formatter for T` 表示 Nino 不知道如何写入 `T`。给它加上 `[NinoType]`，或者用 [`[assembly: NinoFormatter]`](/zh/docs/v4/custom-formatters#for-a-type-assembly-ninoformatter) 为它声明格式化器（也可以在成员上用 [`[NinoMemberFormatter]`](/zh/docs/v4/custom-formatters#for-one-member)）。如果是成员的类型，分析器在你写代码时就会报告（NINO007）。此外，声明该类型的项目里也必须运行源生成器：在那个项目中安装 `Nino` 包；在 Unity 中让它所在的程序集引用 `Nino.Core`。

在 Native AOT 下，错误信息会说明运行时无法在运行时构建格式化器：只有源生成器见过的封闭类型才有格式化器。请在某个 `[NinoType]` 成员或某次 `Serialize`/`Deserialize` 调用中写出这个确切的类型。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。

## 为什么读取时报错说某个类型 ID 不是已注册的子类型？ [#unknown-type-id]

数据里记录的类型，读取方在声明类型之下找不到。常见原因：子类型所在的程序集还没有加载（先加载它即可，不需要注册）；类型改名或移动了命名空间却没有加 [`[NinoFormerName]`](/zh/docs/v4/defining-types#former-name)；或者数据是按另一个声明类型写入的。进程只读取、从不写出的封闭泛型子类型，需要在启动时调用 `NinoPolymorphic.Register<T>()`。如果是*写入*时报错说某个类型不是已注册的子类型，说明这个运行时类型不是 `[NinoType]`：它的基类设置了 `allowInheritance: false`（NINO003），或者它所在的程序集没有运行源生成器。参见[其他程序集中的子类型](/zh/docs/v4/polymorphism#subtypes-in-other-assemblies)。

## 为什么序列化时报错说对象图中有环？ [#cycle]

某个对象通过成员又引用回了自己，而没有任何类型追踪引用，写入就会无休止地进行下去。把环上的类型标记为 [`trackReferences: true`](/zh/docs/v4/reference-tracking)。报错说某个类型嵌套超过 512 层时也一样处理；此外，通过构造函数创建或按值比较的类无法延迟写入，所以深度递归的类型要提供无参构造函数和可赋值的成员。参见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)。

## 为什么旧数据读不出来了，或者读出的值不对？ [#old-data]

只写 `[NinoType]` 时是按位置格式：增加、删除或调整成员顺序都会改变字节，此时读取旧数据会抛出异常（`unexpected end of data`、`invalid length`），更糟的是读出错误的值，因为字节里不带 schema。需要保存的数据，在写入之前就选用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`；在版本容错的继承层次中，只往没有子类的类末尾追加成员。要在 CI 中发现格式变化，可以比较每次构建的[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。参见[数据演进](/zh/docs/v4/evolving-data)。

## 为什么我的调用没有被拦截？ [#not-intercepted]

拦截器需要 Roslyn 4.8 或更高版本（.NET 8 SDK 及以上）；Unity 使用 Roslyn 4.3 版本，从不拦截。泛型代码中的调用、针对其他程序集中声明的 `[NinoType]` 的调用，以及针对原始值的调用，都有意走常规路径。如果项目自己设置了 `InterceptorsNamespaces`，请在原值后追加，而不是替换它。无论是否拦截，写出的字节都相同。参见[拦截器](/zh/docs/v4/performance#interceptors)。

## 为什么我的热路径还在分配内存？ [#still-allocates]

依次检查：序列化到复用的 `NinoArrayBufferWriter`（或其他 `IBufferWriter<byte>`），而不是调用会返回新 `byte[]` 的 `Serialize(value)`；用 `ref` 反序列化到已有的值；自己创建的 `Writer` 或 `Reader` 最后调用了 `ReleaseReferences()`；数组长度保持不变（数量会变化时用 `List<T>`）；Nino 需要新建的类标记了 `[NinoPooled]`；并且是在预热之后才测量。内容变化的文本总会产生新字符串。参见[哪些调用会分配内存](/zh/docs/v4/advanced/zero-allocation#what-allocates)和[检查清单](/zh/docs/v4/advanced/zero-allocation#checklist)。
