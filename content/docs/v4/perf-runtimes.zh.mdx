Nino 在 Go、Rust 和 TypeScript 中读写的字节与 .NET 完全相同，所用的代码由 [Nino.Codegen](/zh/docs/v4/advanced/codegen) 根据你的 C# 类型生成。这几个运行时在 Nino 的仓库中各有一个基准测试，用各自语言的标准工具测量，对比 Protocol Buffers、MessagePack 以及该语言常用的序列化库。.NET 的基准测试（对比 MemoryPack、MessagePack、protobuf-net 和 v3）参见[基准测试](/zh/docs/v4/perf)。

## 对比对象 [#what-is-compared]

| 语言 | 计时工具 | Nino | Protocol Buffers | MessagePack | 其他 |
| --- | --- | --- | --- | --- | --- |
| Go | `testing.B`，由 benchstat 汇总 | 与 nino-gen 生成代码形式相同的编解码器，以及[结构体标签](/zh/docs/v4/advanced/codegen#struct-tags) | google.golang.org/protobuf | vmihailenco/msgpack | `encoding/json`、`encoding/gob` |
| Rust | criterion | 与 nino-gen 生成代码形式相同的编解码器 | prost | rmp-serde | bincode、postcard、serde_json |
| TypeScript | tinybench，在 Node 中运行 | nino-gen 生成的代码 | protobuf-es | msgpackr | `JSON` |

每个用例中各序列化库拿到的数据都相同：protobuf 消息与类型逐字段对应；计时之前，每个序列化库都要先验证能读回自己写出的内容。

## 测量方法 [#setup]

每次发布都会用该版本自己的源码，在 GitHub 托管的 `ubuntu-26.04` 运行器上运行这三个基准测试，每种语言一台运行器，并为每种语言在发布说明中添加一节。本站显示包含这些小节的最新 v4 版本的结果。

- 每张表中，每个用例和操作占一行，每个序列化库占一列，Nino 在最前。请只在同一张表内比较序列化库：每种语言只在自己的运行器上运行了一次，所以不同语言、不同版本之间的耗时不可比较。
- 时间后的 “· 2.00×” 表示在该用例中，Nino 生成的代码比这个序列化库快多少倍。相差 5% 以内为持平；低于 1 ns 的时间对比可测的时间时，记为更快（快到测不出），与 [.NET 页面](/zh/docs/v4/perf#setup)的规则相同。只有时间表示 Nino 在该用例中没有领先。
- 大小是该用例的值编码后的字节数。

### Go [#go]

[`runtimes/go/bench`](https://github.com/JasonXuDeveloper/Nino/tree/main/runtimes/go/bench) 是一个独立的模块，因此运行时自己的模块没有任何依赖。每个基准测试的名称是 `Benchmark{Serialize,Deserialize}/<case>/<serializer>`，使用 `b.Loop`、`ReportAllocs`，并把编码后的大小作为一项指标；发布时每个基准测试运行六次，由 benchstat 给出中位数 ± 其 95% 置信区间，以及每次操作的分配次数。

- **用例：** .NET 基准测试中的 `SimpleClass`（`simple-class`）、100 个它组成的列表（`simple-class-100`），以及两个[字符串用例](#strings)。
- **序列化库：** `Nino`，与 nino-gen 生成代码形式相同的编解码器（不用反射）；`Nino (tags)`，用 `nino` 结构体标签映射的同一组 Go 类型，每个类型只构建一次读写计划；Protocol Buffers（`MarshalAppend` 写入复用的缓冲区）；MessagePack（复用同一个编码器）；`encoding/json`；以及 `gob`，与一次性序列化一样，每个值都新建编码器和解码器。

### Rust [#rust]

[`runtimes/rust/bench`](https://github.com/JasonXuDeveloper/Nino/tree/main/runtimes/rust/bench) 使用 criterion：每个用例一组，吞吐量为值的个数，每个输入和输出都经过 `black_box`。时间是 criterion 的均值估计 ± 其 95% 置信区间的一半。

- **用例：** 一条记录（`record`）、1,000 条记录（`records-1000`）、10,000 个 `i32`（`i32-10000`）、10,000 个 `f64`（`f64-10000`），以及两个[字符串用例](#strings)。
- **序列化库：** Nino，与模板生成代码形式相同的编解码器；Protocol Buffers（prost，消息在基准测试中派生，不需要 protoc）；MessagePack（rmp-serde）；bincode；postcard；serde_json。

### TypeScript [#typescript]

[`runtimes/typescript/bench`](https://github.com/JasonXuDeveloper/Nino/tree/main/runtimes/typescript/bench) 测量 nino-gen 根据基准测试的 C# 类型生成的 TypeScript，在 Node 中由 [tinybench](https://github.com/tinylibs/tinybench) 计时：先预热，再在设定的时间内采样。时间是均值 ± 其相对误差。

- **数据：** 每个场景的值都由 .NET 中的 Nino 写出。计时之前，每个值都要在 TypeScript 中读出再写回，必须与 .NET 写出的字节完全相同；每条 protobuf 消息也必须读回相同的值。一个任务是对场景中所有值的一次遍历。
- **场景：** 玩家、通过类型 id 区分的动物园动物、订单簿、长文本文章、由向量和整数组成的网格、数字样本、由两个短字符串映射组成的查找表、带 64 位整数的事件，以及两个[字符串用例](#strings)。
- **序列化库：** Nino；Protocol Buffers（protobuf-es，代码由基准测试的 `.proto` 生成）；MessagePack（msgpackr，使用标准映射，不用 msgpackr 的 records），它拿到的是 Nino 读出的原样的值（`bigint` 作为 64 位整数，读回仍是 `bigint`）；以及 `JSON`，它拿到的是普通 JSON 数据（64 位整数为字符串，映射为对象），读出后也不转换回 `bigint` 或 `Map`，所以它做的工作比生成的读取代码少。MessagePack 和 JSON 都不携带多态值的类型，而 Nino 和 protobuf（`oneof`）会携带。

## 字符串 [#strings]

三种语言的字符串用例相同：

- **ASCII：** 1,000 个短 ASCII 字符串，从 `"string 0"` 到 `"string 999"`。
- **混合：** 1,000 个字符串，三种轮流出现：ASCII（`"string i"`）、Latin-1（`"crème brûlée i"`），以及含 BMP 以外字符的其他文字（`"строка 字符串 🎉 i"`）。

Nino 的[线格式](/zh/docs/v4/wire-format)按 .NET 保存字符串的方式写出字符串：所有字符都不超过 U+00FF 时写成 Latin-1，每个字符一个字节，否则写成 UTF-16。.NET 的字符串是 UTF-16，所以写入只是一次收窄的复制，读取只是一次展宽的复制，两者都用 SIMD；长度就是字符数，读取方可以先分配字符串，再解码内容。

Go 和 Rust 的字符串是 UTF-8。Nino 的运行时写入字符串时，要检查是否有非 ASCII 字节，再转码为 Latin-1 或 UTF-16；读取时再转码回 UTF-8。而 Protocol Buffers、MessagePack、JSON、bincode 和 postcard 都直接写入和读取原样的 UTF-8 字节。ASCII 在 UTF-8 和 Latin-1 中是相同的字节，所以 ASCII 用例展示的是几乎不需要转码时各格式的表现；混合用例展示的是转码的开销。大小也不同：`è` 在 Latin-1 中占一个字节，在 UTF-8 中占两个；UTF-16 字符串的每个字符都占两个字节，而 UTF-8 中 ASCII 占一个、西里尔字母占两个、汉字占三个。JavaScript 的字符串是 UTF-16（V8 把单字节字符串按 Latin-1 保存），所以在 TypeScript 中，需要编码成 UTF-8 并从 UTF-8 解码的是 Protocol Buffers 和 MessagePack。

标记了 `[NinoUtf8]` 的成员改为按 UTF-8 写出（参见[字符串编码](/zh/docs/v4/defining-types#string-encoding)），Go 和 Rust 读写它时不需要转码；这些基准测试使用的是默认编码。

## 复现 [#reproducing]

克隆 [Nino 仓库](https://github.com/JasonXuDeveloper/Nino)后：

```shell
# Go: six runs, summarized by benchstat
cd runtimes/go/bench
go test -run='^$' -bench=. -benchmem -count=6 . | tee bench.txt
go run golang.org/x/perf/cmd/benchstat@latest bench.txt

# Rust (from runtimes/rust)
cargo bench -p nino-bench

# TypeScript: needs the .NET 10 SDK and Node 22.18+
runtimes/typescript/bench/run.sh
```

`runtimes/typescript/bench/run.sh` 先在 Node 中、再在无头 Chromium 中运行 TypeScript 基准测试，后者需要安装 Playwright 和 Chromium；发布说明中的是 Node 的结果。各项选项和发布流程见 [benchmarks README](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks#runtimes-outside-net)。在自己机器上测得的数据，只适合在同一台机器上前后对比改动。
