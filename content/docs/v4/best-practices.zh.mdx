数据上线前，对照这份清单过一遍。Nino 用默认设置就能工作，下面大多是可选的：有些决定一旦写出数据就很难再改，有些习惯能让调用既正确又快。每条都链接到讲透它的页面。

## 设计类型 [#designing-types]

- **在保存或发送任何数据之前，先为每个类型选定格式。** 由同一版本写入和读取的数据保持按位置格式（只写 `[NinoType]`）；只会追加成员的数据用 `NinoFormat.VersionTolerant`；要经过许多版本编辑的文档和配置用 `NinoFormat.Keyed`。之后再改变类型的格式，已有的数据就读不出来了。参见[数据演进](/zh/docs/v4/evolving-data#choosing)。
- **在版本容错的继承层次中，只往没有子类的类追加成员。** 往基类追加的成员会让所有子类的成员错位。参见[向基类追加成员](/zh/docs/v4/evolving-data#appending-to-a-base-class)。
- **没有子类型的类声明为 `sealed`。** 密封类只需一个存在字节；未密封的类要写 4 字节的类型 ID，还要做一次类型检查。参见[多态](/zh/docs/v4/polymorphism#how-a-polymorphic-value-is-written)。
- **给多态类型一个共同的 `[NinoType]` 基类或接口**，成员和调用都声明为这个基类，而不是 `object`。参见[通过共同基类分派](/zh/docs/v4/polymorphism#dispatching-through-a-common-base)。
- **只给被共享或构成环的类型开启引用追踪。** 树形数据不需要追踪。参见[引用追踪](/zh/docs/v4/reference-tracking#when-to-use-it)。
- **热路径上的结构体保持非托管，并在保存之前定好它的布局。** 原始结构体按内存拷贝，所以字段顺序、`Pack` 和 `Size` 都是格式的一部分。参见[结构体](/zh/docs/v4/defining-types#structs)和[结构体布局](/zh/docs/v4/performance#struct-layout)。
- **热路径上读取的类型，提供无参构造函数和可赋值的成员。** 通过构造函数创建的类型（位置记录、`init` 或只读成员）每次读取都会重新创建，无法池化，也无法追踪引用。参见[重新创建的类型](/zh/docs/v4/constructors#re-created-types)。
- **不是数据的东西不要写。** 缓存和派生状态用 `[NinoIgnore]` 排除；要记录类型时存你自己的 ID，而不是 `System.Type`，Nino 有意不序列化它。参见[不支持的类型](/zh/docs/v4/types#not-supported)。

## 调用 Nino [#calling-nino]

- **用写入时的类型来读取。** 多态值按基类序列化（`Serialize<TBase>`），再用 `Deserialize<TBase>` 读取；[装箱 API](/zh/docs/v4/basic#the-boxed-api) 只用于运行时才以 `Type` 形式得知的类型。
- **在热路径上复用缓冲区和实例**：缓冲区写入器一直复用，反序列化时读入手上已有的实例。所有手段见高性能序列化的[一览表](/zh/docs/v4/advanced/high-performance#levers)。
- **自己创建的 `Writer` 或 `Reader` 要收尾**：每条逻辑消息结束时调用 `Flush()` 和 `ReleaseReferences()`（`Reader` 调用 `ReleaseReferences()`）。参见[一个缓冲区写多个值](/zh/docs/v4/basic#several-values-in-one-buffer)。
- **在启动时配置 `NinoSettings`**，赶在任何线程第一次调用之前：读取这些值时不加同步。参见[设置](/zh/docs/v4/settings#startup)。

## 保存与交换的数据 [#stored-data]

- **在保存的数据前面加上你自己的文件头**：一个魔数和一个格式版本号，让以后的版本知道自己读的是什么。参见[添加文件头](/zh/docs/v4/advanced/persistence#add-a-file-header)。
- **改名时使用 `[NinoFormerName]`。** 用在类型上，它保留已有数据使用的类型 ID；用在键控类型的成员上，它继续读取旧名称。参见[重命名](/zh/docs/v4/evolving-data#renaming)。
- **维护一份布局基线。** 类型要存盘或发出去的项目，提交一个 [`NinoLayouts.cs`](/zh/docs/v4/evolving-data#layout-baseline)：改出会破坏已有数据的改动时，分析器在写代码时就会指出来，`nino-gen layouts --check` 在 CI 里做同样的检查。测试里也留几份旧数据（[测试旧文件](/zh/docs/v4/advanced/persistence#test-old-files)），哪份读不了，就用 [`nino-gen inspect`](/zh/docs/v4/advanced/codegen#inspect) 看看。
- **谨慎修改字符串编码和集合的声明。** 增加或去掉 `[NinoUtf8]`，或者把可空元素的列表在数组、`List<T?>` 与接口之间改来改去，都会改变字节。参见[字符串编码](/zh/docs/v4/defining-types#string-encoding)和[集合类型](/zh/docs/v4/types#collection-types)。
- **两端分别升级时，只用容错的格式。** 客户端和服务器分开发布时，消息要用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`。参见[网络](/zh/docs/v4/advanced/networking)。

## 不可信的输入 [#untrusted-input]

- **读外部来的数据，打开 `NinoSettings.Untrusted = true`**：在启动时、第一次调用 Nino 之前设置；在数据进来的地方捕获 `NinoDataException`。参见[不可信模式](/zh/docs/v4/security#untrusted-mode)。
- **合法消息用不到那么大的限制，就调低**，比如 `NinoSettings.MaxCollectionLength`。参见[限制](/zh/docs/v4/security#limits)。
- **帧或请求先限制大小再缓冲**，逻辑依赖的值自己校验：Nino 只检查数据的结构，不管它的含义。参见[为数据流分帧](/zh/docs/v4/advanced/networking#frame-the-stream)。

## 项目配置 [#project-setup]

- **每个声明了 `[NinoType]` 的项目都要安装 `Nino`**，源生成器才会在这个项目里运行。在 Unity 中，每个声明了这些类型的程序集定义都要引用 `Nino.Core`。参见[快速开始](/zh/docs/v4/start)。
- **用 .NET 8 SDK 或更高版本构建**，才能用上[拦截器](/zh/docs/v4/performance#interceptors)。项目自己设置了 `InterceptorsNamespaces` 的话，在原值后面追加。
- **不要忽略分析器的警告。** NINO006 和 NINO007 表示某个成员的值会丢掉或跳过；NINO034 和 NINO035 表示某个改动会破坏已存的数据，或者让它悄悄丢失。参见[分析器](/zh/docs/v4/analyzers)。
