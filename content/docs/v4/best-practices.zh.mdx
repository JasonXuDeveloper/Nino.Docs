Nino 用默认设置就能工作，下面的大多数建议都是可选的。第一节是热路径上最重要的做法：处理消息时不分配内存。其余几节是数据写出之后就很难再改的决定，以及让调用保持快速的习惯。每一条都链接到详细说明它的页面。

## 处理消息时不分配内存 [#zero-gc-messages]

高频收发消息的循环（网络数据包、游戏 tick、队列消费者）在预热之后，每条消息都不应再分配内存，这样垃圾回收就不会因它而触发。Nino 的序列化和反序列化都能做到 0 B，做法分三部分。

### 写入 [#writing-messages]

- **每个线程或连接持有一个 `NinoArrayBufferWriter`**，每条消息之前调用 `ResetWrittenCount()`，并在下一次重置之前把 `WrittenSpan` 发送出去。Nino 直接写入其中，数组增长到最大消息的大小之后，序列化就不再分配内存。缓冲区不是线程安全的，不要在线程之间共享。参见[每个归属方复用一个缓冲区](/zh/docs/v4/advanced/zero-allocation#reuse-one-buffer)。
- **或者序列化到调用方提供的 `IBufferWriter<byte>`**（`PipeWriter`、Kestrel 的响应体）：向它的内存拷贝一次，0 B。参见[序列化到任意 IBufferWriter](/zh/docs/v4/advanced/high-performance#serialize-into-any-ibufferwriter)。
- **只在某个 API 需要 `byte[]` 时才调用 `Serialize(value)`。** 它每次都会分配这个数组（大小正好等于数据）。

### 读取 [#reading-messages]

- **直接从字节到达时所在的内存反序列化**：用接收缓冲区的切片，而不是先拷贝到新的 `byte[]`。
- **如果每条消息在下一条到达之前就处理完，用 `ref` 反序列化到上一次的实例中。** Nino 原地填充同一个对象、它的嵌套对象和列表。参见[复用反序列化的结果](/zh/docs/v4/advanced/zero-allocation#reuse-what-you-deserialize)。
- **如果要保留消息，或把它交给另一个线程，就把消息类标记为 `[NinoPooled]`。** 这样 `Deserialize<T>` 会从该类型的池中取出每个实例。用完消息的代码对它调用一次 `ReturnToPool()`，而且要在没有别处使用它之后。消息内部由 Nino 高频创建的类（不断变长的列表中的元素）也值得池化。参见[内置对象池](/zh/docs/v4/pooling#ninopooled)。

### 类型 [#message-types]

- **热数据放在非托管结构体中**，单个或放在数组和 `List<T>` 里：它们按原始内存拷贝，一个列表就是一次块拷贝。调整字段顺序或设置 `Pack`，让它们没有填充字节。参见[结构体布局](/zh/docs/v4/performance#struct-layout)。
- **让字符串保持不变。** 读入已有实例时，文本没变的字符串会被保留，只有变化了的文本才分配新字符串。每条消息都会变的值用数字、枚举或 ID 表示，而不是文本。非 ASCII 的 `[NinoUtf8]` 字符串每次都会解码成新字符串。
- **数量会变化时用 `List<T>`。** 列表复用时保留容量；数组只有长度不变时才会被复用。
- **消息中不要用 `object` 和装箱 API。** `object` 成员会把值类型装箱，并通过全局注册表分派；`SerializeBoxed` 和 `DeserializeBoxed` 要按 `Type` 查找格式化器。成员声明为它们自己的类型或共同的 `[NinoType]` 基类，没有子类型的类声明为 `sealed`。

### 示例 [#zero-gc-example]

一个游戏服务器通过已连接的 UDP 套接字向每个客户端发送状态。每条消息是一个 `StateUpdate`，其中每个实体都是非托管结构体：

```csharp title="StateUpdate.cs"
using System.Collections.Generic;
using System.Linq;
using Nino.Core;

[NinoType]
public struct EntityState                // 非托管：按原始内存拷贝
{
    public int Id;
    public float X, Y, Z;
    public uint Flags;
}

[NinoType, NinoPooled]
public sealed partial class StateUpdate
{
    public long Tick;
    public string Zone;                  // 文本不变时，复用会保留它
    public List<EntityState> Entities;   // 一次块拷贝；复用时保留容量

    private static partial IEnumerable<StateUpdate> OnNinoPoolWarmup() =>
        Enumerable.Range(0, 32).Select(_ => new StateUpdate { Entities = new List<EntityState>(256) });

    private partial void OnNinoPoolReturn() { }
}
```

每个客户端一个 `Connection`，持有一个发送缓冲区和一个接收缓冲区。发送时序列化到复用的缓冲区；接收时把每个数据报读入上一条消息，或者为另一个线程上的消费者读入从池中取出的实例：

```csharp title="Connection.cs"
using System;
using System.Collections.Concurrent;
using System.Net.Sockets;
using Nino.Core;

public sealed class Connection : IDisposable
{
    private readonly Socket _socket;                                // 已连接的 UDP 套接字
    private readonly NinoArrayBufferWriter _send = new(16 * 1024);  // 每个连接一个
    private readonly byte[] _receive = new byte[64 * 1024];         // 每个连接一个
    private StateUpdate _latest;                                    // 每个数据报都原地填充它

    public Connection(Socket socket) => _socket = socket;

    // 发送：缓冲区增长到最大消息之后为 0 B。
    public void Send(StateUpdate update)
    {
        _send.ResetWrittenCount();
        NinoSerializer.Serialize(update, _send); // [!code highlight]
        _socket.Send(_send.WrittenSpan);
    }

    // 接收后立即处理：每次都是同一个 StateUpdate。
    public void ReceiveAndApply(Action<StateUpdate> apply)
    {
        int received = _socket.Receive(_receive);
        NinoDeserializer.Deserialize(_receive.AsSpan(0, received), ref _latest); // [!code highlight]
        apply(_latest);
    }

    // 接收后交给另一个线程：每条消息是独立的实例，从池中取出。
    // 消费者用完后调用 update.ReturnToPool()。
    public void ReceiveInto(ConcurrentQueue<StateUpdate> inbox)
    {
        int received = _socket.Receive(_receive);
        inbox.Enqueue(NinoDeserializer.Deserialize<StateUpdate>(_receive.AsSpan(0, received))); // [!code highlight]
    }

    public void Dispose() => _send.Dispose();   // 把发送缓冲区的数组还给它的池
}
```

预热之后，Nino 在 `Send`、`ReceiveAndApply` 和 `ReceiveInto` 中都不分配内存：实体列表连同容量一起被复用，区域名在不变时被保留，池化的 `StateUpdate` 回来时列表仍然挂在上面。用[分配测试](/zh/docs/v4/advanced/zero-allocation#verify-it)把它固定下来；批量写入、分帧的流和自有内存参见[零分配模式](/zh/docs/v4/advanced/zero-allocation)，复用的确切规则参见[复用反序列化与对象池](/zh/docs/v4/pooling)。

## 设计类型 [#designing-types]

- **在保存或发送任何数据之前，先为每个类型选定格式。** 由同一版本写入和读取的数据保持按位置格式（只写 `[NinoType]`）；只会追加成员的数据用 `NinoFormat.VersionTolerant`；要经过许多版本编辑的文档和配置用 `NinoFormat.Keyed`。之后再改变类型的格式，已有的数据就读不出来了。参见[数据演进](/zh/docs/v4/evolving-data#choosing)。
- **在版本容错的继承层次中，只往没有子类的类追加成员。** 往基类追加的成员会让所有子类的成员错位。参见[向基类追加成员](/zh/docs/v4/evolving-data#appending-to-a-base-class)。
- **没有子类型的类声明为 `sealed`。** 密封类只需一个存在字节；未密封的类要写 4 字节的类型 ID，还要做一次类型检查。参见[多态](/zh/docs/v4/polymorphism#how-a-polymorphic-value-is-written)。
- **给多态类型一个共同的 `[NinoType]` 基类或接口**，成员和调用都声明为这个基类，而不是 `object`。参见[通过共同基类分派](/zh/docs/v4/polymorphism#dispatching-through-a-common-base)。
- **只给被共享或构成环的类型开启引用追踪。** 树形数据不需要追踪。参见[引用追踪](/zh/docs/v4/reference-tracking#when-to-use-it)。
- **热路径上的结构体保持非托管，并在保存之前定好它的布局。** 原始结构体按内存拷贝，所以字段顺序、`Pack` 和 `Size` 都是格式的一部分。参见[结构体](/zh/docs/v4/defining-types#structs)和[结构体布局](/zh/docs/v4/performance#struct-layout)。
- **热路径上读取的类型，提供无参构造函数和可赋值的成员。** 通过构造函数创建的类型（位置记录、`init` 或只读成员）每次读取都会重新创建，无法池化，也无法追踪引用。参见[重新创建的类型](/zh/docs/v4/constructors#re-created-types)。
- **不是数据的东西不要写。** 缓存和派生状态用 `[NinoIgnore]` 排除；要记录类型时存你自己的 ID，而不是 `System.Type`，Nino 有意不序列化它。参见[不支持的类型](/zh/docs/v4/types#not-supported)。

## 调用 Nino [#calling-nino]

- **用写入时的类型来读取。** 多态值按基类序列化（`Serialize<TBase>`），再用 `Deserialize<TBase>` 读取；[装箱 API](/zh/docs/v4/basic#the-boxed-api) 只用于运行时才以 `Type` 形式得知的类型。
- **在热路径上复用缓冲区和实例**，做法见[处理消息时不分配内存](#zero-gc-messages)。
- **自己创建的 `Writer` 或 `Reader` 要收尾**：每条逻辑消息结束时调用 `Flush()` 和 `ReleaseReferences()`（`Reader` 调用 `ReleaseReferences()`）。参见[一个缓冲区中的多个值](/zh/docs/v4/basic#several-values-in-one-buffer)。
- **在启动时配置 `NinoSettings`**，早于任何线程上的第一次调用：它的值在读取时不做同步。参见[设置](/zh/docs/v4/pooling#settings)。

这些选择在速度上的影响，参见[高性能序列化](/zh/docs/v4/advanced/high-performance)。

## 保存与交换的数据 [#stored-data]

- **在保存的数据前面加上你自己的文件头**：一个魔数和一个格式版本号，让以后的版本知道自己读的是什么。参见[添加文件头](/zh/docs/v4/advanced/persistence#add-a-file-header)。
- **改名时使用 `[NinoFormerName]`。** 用在类型上，它保留已有数据使用的类型 ID；用在键控类型的成员上，它继续读取旧名称。参见[曾用名](/zh/docs/v4/defining-types#former-name)。
- **在版本之间检查布局。** 在 CI 中把每次构建的[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)与上一个版本比较，并在测试中保留旧的数据（[测试旧文件](/zh/docs/v4/advanced/persistence#test-old-files)）。
- **谨慎修改字符串编码和集合的声明。** 增加或去掉 `[NinoUtf8]`，或者把可空元素的列表在数组、`List<T?>` 与接口之间改来改去，都会改变字节。参见[字符串编码](/zh/docs/v4/defining-types#string-encoding)和[集合类型](/zh/docs/v4/types#collection-types)。
- **两端分别升级时，只用容错的格式。** 客户端和服务器分开发布时，消息要用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`。参见[网络层](/zh/docs/v4/advanced/networking)。

## 不可信的输入 [#untrusted-input]

- Nino 本来就是为读取不可信数据而设计的：分配内存之前会检查每个长度是否超出剩余字节（一个集合在读到元素之前最多预先分配剩余字节数的 16 倍），无论数据嵌套多深栈的用量都有上限，只会创建派生自声明类型的类型。所有无效输入都会抛出消息以 `Nino:` 开头的 `NinoDataException`（一种 `InvalidOperationException`）：在边界处捕获它，把输入当作坏数据处理。参见[不可信数据](/zh/docs/v4/security)。
- 读取外部数据时，在启动时、第一次调用 Nino 之前设置 `NinoSettings.Untrusted = true`：它用每个进程的密钥对常见键类型做哈希，检查原始结构体中的值，并拒绝值之后的字节。如果有效消息不会包含那么多元素，就调低 `NinoSettings.MaxCollectionLength`。参见[限制](/zh/docs/v4/security#limits)。
- 在缓冲之前限制帧或请求的大小（参见[为数据流分帧](/zh/docs/v4/advanced/networking#frame-the-stream)）：一次读取的分配量相对于输入是有界的。
- 校验你的逻辑依赖的值，就像对待被用户改过的存档：Nino 检查的是数据的结构，而不是它的含义。
- 字节里不带 schema，所以 Nino 分辨不出按另一个布局兼容的类型写出的数据。请自己为数据加上版本。

## 项目配置 [#project-setup]

- **每个声明了 `[NinoType]` 的项目都要安装 `Nino`**，源生成器才会在那里运行。在 Unity 中，每个声明了这些类型的程序集定义都要引用 `Nino.Core`。参见[快速开始](/zh/docs/v4/start)。
- **用 .NET 8 SDK 或更高版本构建**，以启用[拦截器](/zh/docs/v4/performance#interceptors)。如果项目自己设置了 `InterceptorsNamespaces`，请在原值后追加。
- **不要忽略分析器的警告。** NINO006 和 NINO007 意味着某个成员的值被丢弃或跳过。参见[分析器诊断](/zh/docs/v4/analyzers)。
