[MemoryPack](https://github.com/Cysharp/MemoryPack) 是一个出色的序列化库，也是我们用来衡量 Nino 的对象。本页将 Nino v4 与 MemoryPack **1.21.4** 进行比较：MemoryPack 的功能以其自己的 README 为准，Nino 的功能以 Nino 源码为准。任何一方无法核实的功能都没有列出。

### 反序列化到已有对象 [#deserialize-into-existing-objects]

两个库都可以填充你已有的对象，而不是分配新对象。Nino 通过 `ref` 反序列化到已有对象图，新实例取自 [`[NinoPooled]`](/zh/docs/v4/pooling) 对象池；MemoryPack 覆盖已有实例。在池化路径上，Nino 最高**快 <BenchValue k="reuse.max" />**，且分配 **0 B**，而 MemoryPack 每次调用都要分配。

反序列化 `Vector4[10000]` 可能是 MemoryPack 更快。每次调用都会在大对象堆上分配一个 160 KB 的数组，因此该用例主要测量的是第 2 代垃圾回收，结果随运行波动。拷贝本身在两个库中都是一次 `memcpy`。

## MemoryPack 仍然领先的地方 [#where-memorypack-is-ahead]

坦白地说，以下是 MemoryPack 能做而 Nino v4 不能做的：

- **更多内置类型。** MemoryPack 可以序列化 `BigInteger`、`Uri`、`Version`、`StringBuilder`、`Type`、`BitArray`、`CultureInfo`、`TimeZoneInfo`、`Lazy<T>`、`Memory<T>`、`ReadOnlyMemory<T>`、`ReadOnlySequence<T>`、`ReadOnlyCollection<T>`、`ReadOnlyObservableCollection<T>`、`ILookup<,>`、`IGrouping<,>`、`BlockingCollection<T>` 以及所有不可变集合。Nino 都不支持（它通过 `Nino.Immutable` 支持 `ImmutableArray<T>` 和 `ImmutableList<T>`）。*变通方法：*编写[自定义格式化器](/zh/docs/v4/custom-formatters)，或使用可序列化的成员进行转换（`Uri` 用 `string`，`BigInteger` 用 `byte[]`）。
- **Unity 类类型。** `MemoryPack.Unity` 可以序列化 `AnimationCurve`、`Gradient` 和 `RectOffset`。Nino 支持 Unity 的非托管结构体（`Vector3`、`Quaternion`、`Color32`……），但不支持 Unity 的类。*变通方法：*自定义格式化器。
- **Stream 与异步。** MemoryPack 提供 `Stream` 重载、`SerializeAsync`/`DeserializeAsync`，以及用于 `IAsyncEnumerable<T>` 的 `MemoryPack.Streaming`。Nino 只处理缓冲区。*变通方法：*序列化到 `NinoArrayBufferWriter` 后把其 `WrittenMemory` 写入流；从流读取到池化缓冲区后反序列化 Span。
- **`ReadOnlySequence<byte>` 输入。** MemoryPack 可以直接反序列化多段序列。*变通方法：*`IsSingleSegment` 时反序列化 `sequence.First.Span`，否则拷贝到栈或池化缓冲区（[示例](/zh/docs/v4/advanced/networking#reading-frames)）。
- **序列化回调。** MemoryPack 会调用 `[MemoryPackOnSerializing]`、`[MemoryPackOnSerialized]`、`[MemoryPackOnDeserializing]` 和 `[MemoryPackOnDeserialized]` 方法。Nino 没有回调。*变通方法：*在调用 `Serialize`/`Deserialize` 前后执行逻辑，使用属性 setter，或使用 `[NinoConstructor]` / `[NinoRefDeserialization]` 工厂方法。
- **内置压缩。** MemoryPack 提供 Brotli 辅助工具和 Brotli 成员格式化器。*变通方法：*用 `System.IO.Compression`（`BrotliEncoder`、`BrotliStream`）或 LZ4 等库压缩 Nino 的输出。
- **TypeScript 与 ASP.NET Core。** MemoryPack 可以生成 TypeScript 读写代码，并提供 MVC 输入/输出格式化器。Nino 两者都没有。
- **更小的多态头部。** MemoryPack 的 Union 标签为 1 字节（超过 249 时 3 字节）；Nino 写入 4 字节类型 ID。Nino 的 ID 无需维护标签，但每个多态值多花 3 字节。
- **依赖注入与选项。** MemoryPack 在每次调用中传递 `MemoryPackSerializerOptions`（字符串编码、`IServiceProvider`）。Nino 没有按调用的选项；它的设置是进程级的（`NinoSettings`）和按类型的特性。

## Nino 领先的地方 [#where-nino-is-ahead]

- **速度**：类和多态对象图的序列化最高快 <BenchValue k="serialize.max" />、反序列化最高快 <BenchValue k="deserialize.max" />，数据如上。
- **零分配复用**：引用反序列化会复用嵌套对象、列表和字典，`[NinoPooled]` 对象池，以及为每个被丢弃实例准备的回收器。
- **可演进的数据**：键控成员可以重新排序、删除和插入；版本兼容类型允许向基类追加成员；旧代码可以读取新数据。
- **无需维护的多态**：没有标签，任何非密封类都可以，其他程序集和热更新 DLL 中的子类型会被自动发现。
- **可移植、确定性的字节**：在 CoreCLR、Mono 和 IL2CPP、64 位和 32 位上完全相同，填充清零。
- **更广的覆盖**：`netstandard2.0`、Unity 的 OpenUPM 包、无需初始化调用的 HybridCLR。
- **构建时间**：每个类型一个生成文件，真正增量的生成器。

## 如何选择 [#when-to-choose-which]

<Cards>
  <Card title="选择 Nino，如果">
    你在 Unity 或 .NET 上高频序列化游戏状态、网络消息或存档；你需要无需标签表的多态、可演进的数据、共享引用，或通过池化实现零 GC；或者你需要 Unity、IL2CPP 与服务器之间字节完全一致。
  </Card>
  <Card title="选择 MemoryPack，如果">
    你需要 Stream 或异步 API、`ReadOnlySequence` 输入、TypeScript 客户端或 ASP.NET Core 格式化器、序列化回调、内置 Brotli，或者开箱即用地支持上面列出的 BCL 与 Unity 类类型。
  </Card>
</Cards>

<Callout type="idea">

两者都采用 MIT 许可证、基于源生成、对 AOT 安全。如果不确定，请用你自己的类型做基准测试：[基准测试项目](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.Benchmark)会同时运行 Nino 与 MemoryPack。

</Callout>
