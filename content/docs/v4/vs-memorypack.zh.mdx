[MemoryPack](https://github.com/Cysharp/MemoryPack) 是一个出色的序列化库，也是我们衡量 Nino 的标杆。本页对比 Nino v4 和 MemoryPack **1.21.4**：MemoryPack 的功能以它自己的 README 为准，Nino 的功能以 Nino 源码为准。无法核实的功能，两边都不列出。

### 反序列化到已有对象 [#deserialize-into-existing-objects]

两个库都能填充已有的对象，而不分配新对象。Nino 通过 `ref` 反序列化到已有的对象图中，需要新实例时从 [`[NinoPooled]`](/zh/docs/v4/pooling) 对象池中取；MemoryPack 则覆盖已有实例。Nino 最高**快 <BenchValue k="reuse.max" />**，池化路径上分配 **0 B**，而 MemoryPack 每次调用都要分配。

反序列化 `Vector4[10000]` 时，MemoryPack 可能更快。每次调用都要在大对象堆上分配一个 160 KB 的数组，所以这一项测到的主要是第 2 代垃圾回收，结果每次运行都有波动。拷贝本身在两个库中都只是一次 `memcpy`。

## MemoryPack 仍然领先的地方 [#where-memorypack-is-ahead]

坦白说，以下功能 MemoryPack 支持，Nino v4 不支持：

- **更多内置类型。** MemoryPack 可以序列化 `BigInteger`、`Uri`、`Version`、`StringBuilder`、`Type`、`BitArray`、`CultureInfo`、`TimeZoneInfo`、`Lazy<T>`、`Memory<T>`、`ReadOnlyMemory<T>`、`ReadOnlySequence<T>`、`ReadOnlyCollection<T>`、`ReadOnlyObservableCollection<T>`、`ILookup<,>`、`IGrouping<,>`、`BlockingCollection<T>` 以及所有不可变集合。Nino 都不支持（不可变集合中只通过 `Nino.Immutable` 支持 `ImmutableArray<T>` 和 `ImmutableList<T>`）。*变通方法：*编写[自定义格式化器](/zh/docs/v4/custom-formatters)，或者用一个可序列化的成员做转换（`Uri` 存成 `string`，`BigInteger` 存成 `byte[]`）。
- **Unity 的类。** `MemoryPack.Unity` 可以序列化 `AnimationCurve`、`Gradient` 和 `RectOffset`。Nino 支持 Unity 的非托管结构体（`Vector3`、`Quaternion`、`Color32`……），但不支持 Unity 的类。*变通方法：*自定义格式化器。
- **TypeScript 与 ASP.NET Core。** MemoryPack 可以生成 TypeScript 读写代码，并提供 MVC 输入/输出格式化器。Nino 两者都没有。
- **依赖注入与选项。** MemoryPack 的每次调用都可以传入 `MemoryPackSerializerOptions`（字符串编码、`IServiceProvider`）。Nino 没有按调用设置的选项，只有进程级的 `NinoSettings` 和按类型标注的特性。

流、异步 I/O、`ReadOnlySequence<byte>` 输入、序列化回调和压缩不在这个列表里：它们都只需在 Nino 的 `IBufferWriter<byte>` 和 `ReadOnlySpan<byte>` API 外面写几行代码。可以直接复制的写法参见[流、异步、回调与压缩](/zh/docs/v4/advanced/streams)。

## 类型 ID 与 Union 标签 [#type-ids-and-union-tags]

MemoryPack 写入 1 字节的 Union 标签（超过 249 时 3 字节），Nino 写入 4 字节的类型 ID。这是有意的取舍：

- Nino 的 ID 由类型本身决定（类型名的 FNV-1a 哈希），子类型不需要标签。子类型可以放在任何程序集中（插件、HybridCLR 热更新、继承你的基类的库），增删子类型时 ID 也不会重新编号。
- MemoryPack 要在基类上用 `[MemoryPackUnion(tag, type)]` 列出所有子类型，或者通过 Union 格式化器手动注册，标签还要靠人工保持稳定。

代价是每个多态值多 3 字节。参见[多态](/zh/docs/v4/polymorphism)。

## Nino 领先的地方 [#where-nino-is-ahead]

- **速度**：序列化最高快 <BenchValue k="serialize.max" />，反序列化类和多态对象图最高快 <BenchValue k="deserialize.max" />，数据见上文。
- **零分配复用**：复用反序列化复用嵌套的对象、列表和字典；`[NinoPooled]` 对象池；被丢弃的每个实例都能交给回收器。
- **数据可以演进**：键控成员可以调整顺序、删除和插入；版本兼容类型允许在基类中追加成员；旧代码能读新数据。
- **多态无需维护**：没有标签，任何非密封类都可以作为基类，其他程序集和热更新 DLL 中的子类型会自动找到。
- **可移植、确定的字节**：CoreCLR、Mono、IL2CPP 以及 64 位和 32 位平台上完全相同，填充字节清零。
- **适用范围更广**：支持 `netstandard2.0`，Unity 有 OpenUPM 包，HybridCLR 无需初始化调用。
- **构建时间**：每个类型一个生成文件，源生成器真正增量。

## 如何选择 [#when-to-choose-which]

<Cards>
  <Card title="适合选 Nino 的情况">
    在 Unity 或 .NET 上高频序列化游戏状态、网络消息或存档；需要不用标签表的多态、可演进的数据、共享引用，或借助池化做到零 GC；或者需要 Unity、IL2CPP 与服务器之间字节完全一致。
  </Card>
  <Card title="适合选 MemoryPack 的情况">
    需要 TypeScript 客户端、ASP.NET Core MVC 格式化器、按调用设置的选项，或者需要开箱即用地支持上面列出的 BCL 类型和 Unity 类。
  </Card>
</Cards>

<Callout type="idea">

两者都采用 MIT 许可证，都基于源生成，都能安全用于 AOT。如果拿不定主意，就用你自己的类型测一测：[基准测试项目](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.Benchmark)会把 Nino 和 MemoryPack 放在一起运行。

</Callout>
