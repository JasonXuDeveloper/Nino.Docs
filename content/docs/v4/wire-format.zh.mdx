Nino 仓库的 [docs/spec/wire-format.md](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/spec/wire-format.md) 逐字节规定了 Nino 的二进制格式。其他语言的读写实现都以它为契约：[TypeScript](/zh/docs/v4/advanced/typescript)、[Go](/zh/docs/v4/advanced/go) 和 [Rust](/zh/docs/v4/advanced/rust) 运行时都依据它构建，并用 .NET Nino 写出的同一份一致性语料测试。本页只是概览；确切规则、十六进制转储形式的完整示例和布局元数据的语法，都在规范里。

在 C# 里用 Nino 不需要了解这些：生成器会替你读写这些字节。

## 动手看看 [#try-it]

选一个例子，看 Nino 为它写出的字节，每一段都标了含义。这些字节来自规范中实际运行的输出。想看你自己类型的消息是怎么拆开的，运行 [`nino-gen inspect`](/zh/docs/v4/advanced/codegen#inspect)。

## 约定 [#conventions]

- **小端序，不对齐。** 所有多字节值都是小端序，每个值紧接在上一个值之后。字节里只有两处填充，都写零：原始结构体内部，以及原始数组的可空元素内部。.NET 实现拒绝在大端主机上运行。
- **没有信封。** 一段数据就是按声明类型写出的顶层值，后面跟着推迟的主体（如果有）。没有魔数、版本、长度或类型描述：这些字节怎么读，只由声明类型决定。值后面的字节默认忽略，在[不可信模式](/zh/docs/v4/security#untrusted-mode)下拒绝。`Serialize(value, stream)` 也不额外加任何东西，所以多条消息共用一个流时要[分帧](/zh/docs/v4/advanced/streams#frames)。
- **定长整数。** 长度和数量是 `int32`，`-1` 表示 null；密封类和可空值带一个存在字节（`0` 或 `1`）。唯一的变长整数是[字符串头](#strings)，由第一个字节决定它的大小。
- **版本。** 格式版本跟着 Nino 的主版本走：v4 不读 v3 的数据。v4 之内对字节的改动，会写在[更新日志](/zh/docs/v4/changelog)的“二进制格式”一节。给类型加成员靠的是各类型自己的[版本容错和键控格式](/zh/docs/v4/evolving-data)，而不是格式版本。

## 值 [#values]

- **基元类型**（`bool`、整数、`float`、`double`、`Half`、`char`、枚举）就是它们的字节。`nint` 和 `nuint` 在所有平台上都是 8 字节。`Int128` 和 `UInt128` 先写低 64 位，再写高 64 位。
- **BCL 值**：`decimal`、`Guid`、`DateTime`、`TimeSpan`、`DateOnly`、`TimeOnly` 等大小固定；`DateTimeOffset` 是 UTC 刻度加偏移分钟数（10 字节）。`BigInteger`、`Version`、`BitArray`、`Uri` 和其他变长值有各自的编码。
- **字符串**有两种编码，按成员选择，都以一个 1、3 或 5 字节的头开始；参见[字符串](#strings)。

## 字符串 [#strings]

字符串有两种编码，按成员选择：默认编码，或者标了 [`[NinoUtf8]`](/zh/docs/v4/defining-types#string-encoding) 的成员使用的 UTF-8。两者都以一个**头**开始。头是小于 2³² 的无符号值，第一个字节决定它占几个字节，和 MessagePack 的字符串标记一样：

| 第一个字节 | 大小 | 值 |
| --- | --- | --- |
| `00` 到 `7F` | 1 字节 | 这个字节本身（0 到 127） |
| `80` | 3 字节 | 后面两个字节，小端序 `uint16`（128 到 65,535） |
| `81` | 5 字节 | 后面四个字节，小端序 `uint32`（65,536 及以上） |
| `82` 到 `FF` | | 无效 |

头必须最短：每个值都用放得下它的最短形式写出。读取方拒绝三种头：不是最短形式的、越过数据末尾的、第一个字节在 `82` 及以上的。

- **默认编码。** null 的头为 `0`；所有字符都不超过 U+00FF 时，头为 `2n + 1`，后面是 `n` 个 Latin-1 字节（`1` 即空字符串）；否则头为 `2n`，后面是 `n` 个 UTF-16 码元。`n` 个字符的字符串，无论哪种形式，头的大小都一样：63 个字符以内 1 字节，32,767 个以内 3 字节，再长 5 字节。不成对的代理项原样写出，用 UTF-16 形式。`StringBuilder` 总是写成 UTF-16 形式，只有空的时候写 `01`（`0` 表示 null）；读取方两种形式都接受。`Uri`、`CultureInfo` 和 `TimeZoneInfo`（时区的 ID）的文本也按这种编码写出。
- **`[NinoUtf8]`。** 头是字符数（UTF-16 码元个数）加一：`0` 为 null，`1` 为空字符串，两者之后都不再有内容。非空字符串接着用第二个头写字节数，然后是 UTF-8 字节。不成对的代理项写成 U+FFFD，所以字符数就是读回的字符串的长度。

| 值 | 默认编码 | `[NinoUtf8]` |
| --- | --- | --- |
| `null` | `00` | `00` |
| `""` | `01` | `01` |
| `"abc"` | `07 61 62 63` | `04 03 61 62 63` |
| `"é"` | `03 E9` | `02 02 C3 A9` |
| `"a中"` | `04 61 00 2D 4E` | `03 04 61 E4 B8 AD` |
| `"é😀"` | `06 E9 00 3D D8 00 DE` | `04 06 C3 A9 F0 9F 98 80` |
| 64 × `"a"` | `80 81 00 61 … 61` | `41 40 61 … 61` |

## 原始值 [#raw-values]

非托管值（基元类型、枚举、不是 `[NinoType]` 的非托管结构体，或符合条件的 `[NinoType]` 结构体）按**规范布局**整块写出。规范布局就是 64 位 CoreCLR 给它的布局：每个字段按自然对齐（`decimal` 对齐到 8，`Int128` 对齐到 16），填充写零。所有运行时写出的字节都一样：自身布局不同时（32 位平台、Mono 和 IL2CPP、.NET Framework 上的部分结构体），Nino 逐字段转换。`Nullable<T>`、`ValueTuple`、`KeyValuePair` 和 `DateTimeOffset` 单独出现时从不按原始值写，而是逐项写。放在非托管结构体里时，它们属于结构体的那一整块，同样用规范布局：值元组的各项放在 64 位 CoreCLR 放的位置（较大的基元项在前，所以 `(int, long)` 先 `long` 后 `int`）；`KeyValuePair` 先键后值；`DateTimeOffset` 按 .NET 10 的存法（先是 `int` 型的偏移分钟数，UTC 时间从第 8 字节开始）；`nint`/`nuint` 占 8 字节。SIMD 向量（`Vector64<T>` 到 `Vector512<T>`）按 x64 的方式对齐；`Vector<T>` 的宽度由 CPU 决定（16、32 或 64 字节），[不能序列化](/zh/docs/v4/struct-layouts#vector-t)。各运行时的差异见[结构体布局](/zh/docs/v4/struct-layouts)。

<Callout type="warn" title="原始字节按原样复制">

读原始结构体就是复制它的整块字节：默认模式下，里面的 `bool` 字段和 `Nullable` 存在字节都不检查，那里出现不是 0 或 1 的字节，对 .NET JIT 是未定义行为（这个值可能和自己都不相等）。来源不可信的数据，要设 `NinoSettings.Untrusted = true` 再读（见[会被拒绝的数据](/zh/docs/v4/security#what-is-rejected)）。

</Callout>

## 集合 [#collections]

- **序列**（数组、列表、Set、队列、栈、`Memory<T>`、不可变序列，以及你自己写的集合）是一个 `int32` 数量（`-1` 为 null），然后是各元素。原始元素是一整块 `数量 × 大小` 字节。栈从底到顶写出。
- **映射**是一个数量，然后是每个键和值。有序映射按键的顺序写出；哈希映射按枚举顺序写出，读取器不能依赖这个顺序。
- **原始 `T` 的 `T?[]` 和 `List<T?>`** 使用固定步长：一个存在字节，填充到 `T` 的对齐，然后是 `T`（为 null 时全为零）。声明为接口的成员（`IList<int?>`）则把每个元素作为单独的 `T?` 写出。
- **元组和键值对**按顺序写出各项；`Tuple<...>`、`T?` 和 `Lazy<T>` 前面有一个存在字节。多维数组先写每一维的长度，再按行优先顺序写元素。

## 对象 [#objects]

`[NinoType]` 值先写**头**（由声明类型决定），再写**主体**：

| 声明类型 | 头 |
| --- | --- |
| 结构体 | 无 |
| 密封类 | 存在字节（[布局](/zh/docs/v4/evolving-data#layout-metadata)中为 `header=Presence`）：`0` 为 null，`1` 为有值 |
| 其他类、接口、`object` | 运行时类型的 `int32` 类型 ID，`0` 为 null |

- **类型 ID** 是类型全名（或其 [`[NinoFormerName]`](/zh/docs/v4/evolving-data#former-name)）按 UTF-16 码元计算的 32 位 FNV-1a 哈希，所以数据里从不出现类型名；读取器也只接受它在这个槽位上认识的子类型。参见[多态](/zh/docs/v4/polymorphism)。
- **按位置**的主体就是整个继承层次的成员，从根类开始依次写出，不带长度，也不带名字。
- **版本容错**的主体是一个 `int32` 长度，然后是各成员：旧版本的读取器跳过不认识的成员，新版本给缺少的成员赋默认值。
- **键控**的主体是一个 `int32` 长度，然后每个成员一个 `(int32 键, int32 长度, 值)` 条目，键是成员名的 FNV-1a 哈希。条目顺序不限，不认识的键直接跳过。
- **引用追踪**（`trackReferences: true`）把头换成一个 `int32`：`0` 为 null，`-1` 为新对象，`n > 0` 为指向第 `n` 个已读对象的回引用。参见[引用追踪](/zh/docs/v4/reference-tracking)。

## 深层嵌套 [#deep-nesting]

每个读取器都必须实现推迟，否则读不了超过 128 个节点的链表。已经有 128 个类主体打开、又要再打开一个时，**可推迟**的类型只写头，不写主体：对象进入队列，主体稍后在较浅的位置写出，即顶层值之后；在版本容错或键控区域内，则写在最外层区域末尾的一个段里。Nino 能在读成员之前就创建出来的类型是可推迟的，布局元数据会标明这一点（`deferrable=true|false`）。嵌套不到 128 层的数据，字节里不会多出任何内容。参见[深层对象图](/zh/docs/v4/reference-tracking#deep-object-graphs)。

## 布局元数据 [#layout-metadata]

生成器为每个 `[NinoType]` 发布一条 `[assembly: NinoTypeLayout(...)]`，说明它怎么写：格式、头、类型 ID、是否为原始值、是否追踪引用、是否可推迟，以及每个成员的名字、类型和编码（`raw(4)`、`string`、`seq(...)`、`map(K,V)`、`type(T)` ……）。规范给出了它的语法。其他语言的代码生成器（例如 [nino-gen](/zh/docs/v4/advanced/codegen)）只读取这份元数据；`nino-gen inspect` 和[布局基线](/zh/docs/v4/evolving-data#layout-baseline)也是：布局基线拿它和你保存的布局比对，报告会弄坏旧数据的改动。参见[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。

## 校验 [#validation]

规范列出了读取不可信数据时必须做的检查，以及 .NET 读取器对每一项怎么做：边界；分配之前把长度与剩余字节比较；`bool` 和存在字节只能是 0 或 1；字符串头最短、UTF-8 严格；区域和键控条目恰好填满；类型 ID 仅限声明类型的子类型；回引用；重复键与哈希洪泛；深度；值的范围；尾随数据。.NET 的做法和相关设置见[不可信数据](/zh/docs/v4/security)。
