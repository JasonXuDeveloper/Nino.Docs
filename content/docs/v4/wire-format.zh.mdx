Nino 的二进制格式在 Nino 仓库的 [docs/spec/wire-format.md](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/spec/wire-format.md) 中逐字节规定。它是其他语言读取器和写入器的契约：[TypeScript](/zh/docs/v4/advanced/codegen#typescript)、[Go](/zh/docs/v4/advanced/codegen#go) 和 [Rust](/zh/docs/v4/advanced/codegen#rust) 运行时都依据它构建，并用 .NET Nino 写出的同一份一致性语料测试。本页是概览；确切的规则、以十六进制转储给出的完整示例，以及布局元数据的语法都在规范中。

在 C# 中使用 Nino 不需要了解这些：生成器会替你写出并读取这些字节。

## 约定 [#conventions]

- **小端序，不对齐。** 所有多字节值都是小端序，每个值紧接在上一个值之后。线上唯一的填充位于原始结构体内部和原始数组的可空元素内部，写为零。.NET 实现拒绝在大端主机上运行。
- **没有信封。** 一段数据就是顶层值按其声明类型的编码，后面跟着可能有的推迟的主体。没有魔数、版本、长度或类型描述：如何读取字节只由声明类型决定。值之后的字节默认被忽略，在[不可信模式](/zh/docs/v4/security#untrusted-mode)下被拒绝。
- **定长整数。** 长度和数量是 `int32`，`-1` 表示 null；密封类和可空值带一个存在字节（`0` 或 `1`）。唯一的变长整数是[字符串头](#strings)，由第一个字节决定它的大小。
- **版本。** 格式随 Nino 的主版本变化：v4 不读取 v3 的数据。v4 之内对字节的改动会在[更新日志](/zh/docs/v4/changelog)的“二进制格式”中说明。给类型添加成员由各类型的[版本容错和键控格式](/zh/docs/v4/evolving-data)处理，不靠格式版本。

## 值 [#values]

- **基元类型**（`bool`、整数、`float`、`double`、`Half`、`char`、枚举）就是它们的字节。`nint` 和 `nuint` 在所有平台上都是 8 字节。`Int128` 和 `UInt128` 先写低 64 位，再写高 64 位。
- **BCL 值**：`decimal`、`Guid`、`DateTime`、`TimeSpan`、`DateOnly`、`TimeOnly` 等大小固定；`DateTimeOffset` 是 UTC 刻度加偏移分钟数（10 字节）。`BigInteger`、`Version`、`BitArray`、`Uri` 和其他变长值有各自的编码。
- **字符串**有两种编码，按成员选择，都以一个 1、3 或 5 字节的头开始；参见[字符串](#strings)。

## 字符串 [#strings]

字符串有两种编码，按成员选择：默认编码，或者标了 [`[NinoUtf8]`](/zh/docs/v4/defining-types#string-encoding) 的成员使用的 UTF-8。两者都以一个**头**开始：一个小于 2³² 的无符号值，由第一个字节决定它的大小，与 MessagePack 的字符串标记相同：

| 第一个字节 | 大小 | 值 |
| --- | --- | --- |
| `00` 到 `7F` | 1 字节 | 这个字节本身（0 到 127） |
| `80` | 3 字节 | 后面两个字节，小端序 `uint16`（128 到 65,535） |
| `81` | 5 字节 | 后面四个字节，小端序 `uint32`（65,536 及以上） |
| `82` 到 `FF` | | 无效 |

头必须是最短形式：一个值总是用能容纳它的最短形式写出。读取方会拒绝不是最短形式的头、超出数据末尾的头，以及第一个字节为 `82` 或以上的头。

- **默认编码。** null 的头为 `0`；所有字符都不超过 U+00FF 时，头为 `2n + 1`，后面是 `n` 个 Latin-1 字节（`1` 即空字符串）；否则头为 `2n`，后面是 `n` 个 UTF-16 码元。同一个 `n` 个字符的字符串，两种形式的头大小相同：63 个字符以内 1 字节，32,767 个以内 3 字节，更长 5 字节。不成对的代理项按原样以 UTF-16 形式写出。`StringBuilder` 总是以 UTF-16 形式写出，只有为空时写 `01`，因为 `0` 是 null；读取方两种形式都接受。`Uri`、`CultureInfo` 和 `TimeZoneInfo`（时区的 ID）的文本也按这种编码写出。
- **`[NinoUtf8]`。** 头是字符数（UTF-16 码元个数）加一：`0` 为 null，`1` 为空字符串，两者之后都不再有内容。非空字符串接着以第二个头写入字节数，然后是 UTF-8 字节。不成对的代理项写成 U+FFFD，所以字符数就是读回的字符串的长度。

| 值 | 默认编码 | `[NinoUtf8]` |
| --- | --- | --- |
| `null` | `00` | `00` |
| `""` | `01` | `01` |
| `"abc"` | `07 61 62 63` | `04 03 61 62 63` |
| `"é"` | `03 E9` | `02 02 C3 A9` |
| `"a中"` | `04 61 00 2D 4E` | `03 04 61 E4 B8 AD` |
| `"é😀"` | `06 E9 00 3D D8 00 DE` | `04 06 C3 A9 F0 9F 98 80` |
| 64 × `"a"` | `80 81 00 61 … 61` | `41 40 61 … 61` |

这是规范的 4.1 版，从 4.0.0-rc.8 起写出；更早的 4.0 预发布版本写的是 4 字节的 `int32` 头，4.0.0-rc.8 无法读取。参见[更新日志](/zh/docs/v4/changelog#wire-format-3)。

## 原始值 [#raw-values]

非托管值（基元类型、枚举、不是 `[NinoType]` 的非托管结构体，或符合条件的 `[NinoType]` 结构体）按**规范布局**作为一整块写出：即 64 位 CoreCLR 给它的布局，每个字段按自然对齐（`decimal` 对齐到 8，`Int128` 对齐到 16），填充写为零。每个运行时写出的字节都相同：自身布局不同时（32 位平台，Mono 和 IL2CPP 上的部分结构体），Nino 逐字段转换。`Nullable<T>`、`ValueTuple`、`KeyValuePair` 和 `DateTimeOffset` 从不按原始值写出，而是逐项写出。参见[可移植的设计](/zh/docs/v4/platforms#portable-by-design)。

## 集合 [#collections]

- **序列**（数组、列表、集合、队列、栈、`Memory<T>`、不可变序列，以及你自己写的集合）是一个 `int32` 数量（`-1` 为 null），然后是各元素。原始元素是一整块 `数量 × 大小` 字节。栈从底到顶写出。
- **映射**是一个数量，然后是每个键和值。有序映射按键的顺序写出；哈希映射按枚举顺序写出，读取器不能依赖这个顺序。
- **原始 `T` 的 `T?[]` 和 `List<T?>`** 使用固定步长：一个 存在字节，填充到 `T` 的对齐，然后是 `T`（为 null 时全为零）。声明为接口的成员（`IList<int?>`）则把每个元素作为单独的 `T?` 写出。
- **元组和键值对**按顺序写出各项；`Tuple<...>`、`T?` 和 `Lazy<T>` 前面有一个存在字节。多维数组先写每一维的长度，再按行优先顺序写元素。

## 对象 [#objects]

`[NinoType]` 值由其声明类型决定的**头**加上它的**主体**组成：

| 声明类型 | 头 |
| --- | --- |
| 结构体 | 无 |
| 密封类 | 存在字节（[布局](/zh/docs/v4/evolving-data#layout-metadata)中为 `header=NullFlag`）：`0` 为 null，`1` 为有值 |
| 其他类、接口、`object` | 运行时类型的 `int32` 类型 ID，`0` 为 null |

- **类型 ID** 是类型全名（或其 [`[NinoFormerName]`](/zh/docs/v4/defining-types#former-name)）按 UTF-16 码元计算的 32 位 FNV-1a 哈希，所以数据中从不包含类型名，读取器也只接受它在该槽位已知的子类型。参见[多态](/zh/docs/v4/polymorphism)。
- **按位置**的主体是整个继承层次的成员，按顺序、从根类开始，不带长度和名字。
- **版本容错**的主体是一个 `int32` 长度，然后是各成员：旧版本的读取器跳过不认识的成员，新版本给缺少的成员赋默认值。
- **键控**的主体是一个 `int32` 长度，然后每个成员一个 `(int32 键, int32 长度, 值)` 条目，键是成员名的 FNV-1a 哈希。条目可以任意顺序，未知的键被跳过。
- **引用追踪**（`trackReferences: true`）把头换成一个 `int32`：`0` 为 null，`-1` 为新对象，`n > 0` 为指向第 `n` 个已读对象的回引用。参见[引用追踪](/zh/docs/v4/reference-tracking)。

## 深层嵌套 [#deep-nesting]

每个读取器都必须实现推迟，否则读不了超过 128 个节点的链表。当已有 128 个类主体打开、又要打开一个类主体时，**可推迟**的类型只写出头而不写主体：对象进入队列，主体稍后从较浅的位置写出，位于顶层值之后；如果在版本容错或键控区域内，则写在最外层区域末尾的一个段中。Nino 能在读取成员之前创建的类型是可推迟的；布局元数据会发布这一点（`deferrable=true|false`）。浅于 128 层的数据在线上没有任何额外内容。参见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)。

## 布局元数据 [#layout-metadata]

对每个 `[NinoType]`，生成器都以 `[assembly: NinoTypeLayout(...)]` 发布它的写法：格式、头、类型 ID、是否为原始值、是否追踪引用、是否可推迟，以及每个成员的名字、类型和编码（`raw(4)`、`string`、`seq(...)`、`map(K,V)`、`type(T)` ……）。规范给出了它的语法。其他语言的代码生成器（例如 [nino-gen](/zh/docs/v4/advanced/codegen)）只读取这份元数据。参见[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。

## 校验 [#validation]

规范列出了读取不可信数据的读取器必须做的检查，以及 .NET 读取器对每一项的处理：边界；分配之前把长度与剩余字节比较；`bool` 和存在字节为 0 或 1；最短形式的字符串头和严格的 UTF-8；区域和键控条目被恰好填满；类型 ID 仅限声明类型的子类型；回引用；重复键与哈希洪泛；深度；值的范围；尾随数据。.NET 的做法和相关设置见[不可信数据](/zh/docs/v4/security)。
