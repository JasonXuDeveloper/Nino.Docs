Nino 在每个平台上写出的字节都相同。在有向量指令的平台上，各个运行时把它们用在收益最大的工作上：搬运字节与内存布局不同的值（元组、带填充的结构体）、大块拷贝，以及在[线格式](/zh/docs/v4/wire-format#values)的字符串编码与语言自身的编码之间转换。每条向量路径都在运行时（或为目标平台编译代码时）选定，并且都有写出相同字节的可移植回退路径；测试会比较两者。

下面按平台列出 Nino 源码中现有的向量路径，以及衡量每条路径的基准测试。

## .NET [#dotnet]

`Nino.Core` 的 `net8.0` 和 `net10.0` 版本使用 .NET 的硬件内联函数（hardware intrinsics）。JIT 只编译 CPU 支持的那条路径（`IsSupported` 检查对它来说是常量），其余路径没有任何开销。每种指令集具体做什么，完整列表见[各平台的 SIMD（平台页）](/zh/docs/v4/platforms#simd)。

| 硬件 | 向量路径 | 基准测试 |
| --- | --- | --- |
| 支持 AVX-512 的 x64 | 对齐存储的 64 字节块拷贝；字节置换（AVX-512 VBMI，或仅需 AVX-512F 的 4 字节字置换），每次 64 字节读写带填充的元组和 `KeyValuePair`；512 位掩码拷贝，清零原始结构体的填充 | [基准测试](/zh/docs/v4/benchmarks)，x64 |
| 支持 AVX2 的 x64 | 32 字节块拷贝；带填充的元组和键值对按一组 32 字节向量搬运（`vpshufb`、`vperm2i128`）；字符串每次 32 字节收窄为 Latin-1 或扩展回来 | [基准测试](/zh/docs/v4/benchmarks)，x64 |
| 支持 SSSE3 的 x64 | 带填充的元组和键值对按一组 16 字节向量搬运（`pshufb`）；字符串每次 16 字节收窄和扩展 | [基准测试](/zh/docs/v4/benchmarks) |
| Arm64（AdvSimd） | 用查表指令（`TBL`）按一组 16 字节向量搬运带填充的元组和键值对；用成对加载和存储（`LDP`/`STP`）拷贝块；字符串每次 16 字节收窄和扩展 | [基准测试](/zh/docs/v4/benchmarks)，Arm64 标签页 |
| 支持 SIMD 的 WebAssembly（.NET 10） | 带填充的元组和键值对每个 16 字节向量两次 swizzle（`i8x16.swizzle`） | — |
| Arm32，或关闭了硬件内联函数（`DOTNET_EnableHWIntrinsic=0`） | 无：值逐个搬运，超过 64 字节的块用 `memmove`；字节相同 | — |

.NET Framework 和 .NET Core 3.0 到 .NET 7 加载 netstandard 版本，其中没有硬件内联函数；JIT 加速 `Vector<T>` 时，它们用它收窄和扩展较长的 Latin-1 字符串（Mono 和 Unity 上从不使用）。

## Unity [#unity]

Unity 加载 `Nino.Core` 的 netstandard 版本。安装 `com.unity.burst` 1.8 或更高版本后，Unity 包会在启动时通过 `NinoKernels` 注册 [Burst 编译的内核](/zh/docs/v4/advanced/unity#burst-kernels)。`NinoKernels` 是一张原生函数指针表，只有 netstandard 版本会调用它（每个指针存进静态字段，与阈值比较一次后直接调用）（每个版本都声明了它，所以注册内核的库在 .NET 8 及更高版本上也能加载，那里仍使用自己的路径）。Burst 为其 AOT 设置中的每个 CPU 目标编译内核，启动时选出 CPU 能运行的版本，注册时各自检查指令集。

| 硬件 | 向量路径 | 基准测试 |
| --- | --- | --- |
| 支持 AVX2 的 x64，Burst AVX2 目标 | 256 个值及以上、每个值最多 16 字节的块的 `Permute`：每个 32 字节向量放两个或更多值，一个 `vpshufb` 掩码，各通道用 `vpermd` 拼接或分成两个 16 字节存储；其余部分、更宽的值和字符串走下面的 SSSE3 路径 | [Unity 基准测试](/zh/docs/v4/perf-unity) |
| 支持 SSSE3 的 x86 和 x64（x64 播放器中需要 SSE4 目标） | `Permute`：2 个及以上的元组、键值对和按块读写的 `[NinoType]` 结构体组成的数组和列表，每 16 字节一次字节重排（`pshufb`）读写，16 个及以上带填充的原始结构体在拷贝时清零填充；`Narrow` 和 `Widen`：16 个字符及以上的 Latin-1 字符串，每次 16 个字符；`NarrowAscii` 和 `WidenAscii`：16 个字符及以上的 `[NinoUtf8]` 字符串中直到第一个非 ASCII 字符为止的 ASCII 文本，其余部分交给 .NET 的 UTF-8 编码器和严格解码器 | [Unity 基准测试](/zh/docs/v4/perf-unity) |
| Arm64（Neon） | 同样的内核，用 `tbl`，字符串用 `uzp1`/`zip` | — |
| 用 WebAssembly SIMD 构建的 WebGL（Unity 6 的 Target WebAssembly 2023，或 2022.3 上的 `-msimd128`） | 那里没有 Burst：同样的内核用 C 写成（`Nino.WebGL`），使用 `i8x16.swizzle` 和向量收窄、扩展，处理 16 个字符及以上的 Latin-1 字符串和 `[NinoUtf8]` 字符串中的 ASCII 文本，其余的从 32 个值起。参见 [WebGL](/zh/docs/v4/advanced/unity#webgl-kernels) | — |
| Armv7、没有 SIMD 的 WebGL、不支持 SSSE3（或没有包含它的目标）的 x86 和 x64、没有 Burst 的 IL2CPP 和 Mono 播放器（安装 Burst 即可使用内核） | 无：Nino 的 netstandard 标量路径；字节相同 | [Unity 基准测试](/zh/docs/v4/perf-unity)，“不用 Burst”一列 |

## Go [#go]

Go 运行时的向量代码是处理字符串的汇编，每个指令集一套内核，在运行时选用处理器支持的最好一档（`CPUID`，以及用 `XGETBV` 确认系统会保存向量寄存器；在 macOS 上，与 golang.org/x/sys/cpu 一样通过 `sysctl` 检测 AVX-512，从 macOS 12.2 起）。写入器一遍完成 WTF-8 校验，并以 Latin-1 或 UTF-16 写出；`WriteStrings` 一次调用写出整个列表，其中 64 字节及以上的字符串走单个字符串的内核：它先预留文本可能需要的最长的头，头较短时再把文本前移。

| 硬件 | 向量路径 | 基准测试 |
| --- | --- | --- |
| 支持 AVX-512（F、BW、VL、VBMI2）的 amd64 | 写入器每次 32 字节，使用掩码加载和压缩指令，不需要查找表；同时支持 VBMI 时，读取器用 AVX-512 把 Latin-1 和 UTF-16 转换为 UTF-8 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#go)，字符串用例 |
| 支持 AVX2（和 POPCNT）的 amd64 | 写入器每次 32 字节；读取器使用 SSSE3 内核 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#go) |
| 支持 SSSE3 的 amd64 | 写入器和读取器每次 16 字节，使用 `PSHUFB` 和 `PALIGNR` | — |
| arm64（NEON） | 写入器和读取器每次 16 字节；写入器把不需要向量的部分（块的 ASCII 判断、movemask）放在标量寄存器中做 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#go)，Arm64 |
| 不支持 SSSE3 的 amd64、其他所有平台，或用 `-tags purego` 构建 | 无：按 8 字节字循环的 Go 代码（长串 ASCII 用 SSE2 或 NEON 每次 16 字节拷贝或扩展）；字节相同 | — |

## Rust [#rust]

Rust crate 的向量代码在 `src/simd.rs` 及其子模块 `simd/x86.rs`、`simd/neon.rs` 中，这是它唯一允许 `unsafe` 的代码，在 Miri 下针对 x86_64（仅 SSE2、SSSE3、SSE4.1、AVX2、AVX-512）、Arm64 和大端的 s390x 测试。写入字符串时一遍把 UTF-8 直接转码为 Latin-1 或 UTF-16 写进缓冲区；读取时把 Latin-1 或 UTF-16 直接解码进 `String`。每个指令集有自己的内核，x86_64 上在运行时检测一次并缓存，只在它针对的 CPU 上实测更快时才保留。

| 硬件 | 向量路径 | 基准测试 |
| --- | --- | --- |
| 支持 AVX-512（F、BW、VL、VBMI2；crate 用 Rust 1.89 或更高版本构建）的 x86_64 | 写入每步 64 字节，用掩码加载和存储，由 `vpcompressb`/`vpcompressw` 打包；读取 32 字节及以上的 Latin-1 和 24 个代码单元及以上的 UTF-16 时用 AVX-512 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#rust)，字符串用例 |
| 支持 AVX2（以及 BMI1、BMI2、LZCNT）的 x86_64 | 写入用 32 字节窗口 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#rust) |
| 支持 SSE4.1 的 x86_64 | 写入用 16 字节窗口；读取 24 个代码单元及以上的 UTF-16（Latin-1 用 SSSE3） | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#rust) |
| 只有 SSSE3 或 SSE2 的 x86_64 | 64 字节以内的文本逐字符处理，更长的文本每块 16 字节（48 字节及以上文本中的双字节字符用 SSSE3） | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#rust) |
| 小端 Arm64（NEON） | 写入 64 字节以上的文本用 32 字节窗口，连续的三字节字符（中日韩文字）每步 48 字节（`ld3`），更短的文本逐字符处理；读取 32 字节及以上的 Latin-1 和 24 个代码单元及以上的 UTF-16 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#rust) |
| 32 位目标、WebAssembly、大端平台 | 无：每块两个 8 字节字；字节相同 | — |

## TypeScript [#typescript]

TypeScript 运行时用 `DataView` 和类型化数组读写。它的向量代码用于浏览器和 Deno 中的字符串：嵌入 `nino.ts` 的一个小型 [WebAssembly 模块](/zh/docs/v4/advanced/codegen#text-in-browsers)，在第一次需要时检测和编译。

| 引擎 | 向量路径 | 基准测试 |
| --- | --- | --- |
| 支持 WebAssembly SIMD、GC 和 JS String Builtins 的浏览器和 Deno | 读取较长的 UTF-16 和 Latin-1 文本、写入超过 64 个字符的文本，在 SIMD 寄存器中每次 8 或 16 个字符（`useWasm(false)` 可关闭） | — |
| Node、Bun、带 Node `Buffer` 的 Deno | 不用 Nino 自己的：`Buffer` 原生的 Latin-1 和 UTF-16 方法 | [其他语言的基准测试](/zh/docs/v4/perf-runtimes#typescript) |
| 不支持它们的引擎，或阻止编译 WebAssembly 的内容安全策略 | 无：JavaScript 路径和引擎内置的解码器；字节相同 | — |
