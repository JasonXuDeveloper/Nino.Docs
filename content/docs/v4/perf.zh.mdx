## 对比对象 [#what-is-compared]

| 对比对象 | 原因 | 测量内容 |
| --- | --- | --- |
| [MemoryPack](https://github.com/Cysharp/MemoryPack) **1.21.4** | .NET 上使用广泛、速度最快的二进制序列化库，和 Nino 一样基于源生成器 | 运行时性能，同一次 BenchmarkDotNet 运行：[序列化](#serialize-to-a-reused-buffer-writer)、[反序列化](#deserialize-new-instances)、[多态对象图](#polymorphism)、[复用实例](#pooling)、[引用追踪、版本容错和固定大小的类型](#more-cases) |
| Nino v3 **3.3.13** | v3 API 的最后一个版本，也就是你升级之前所用的版本 | 运行时性能，与 v4 在同一台机器上背靠背测量（运行时表格中的 **v4 对比 v3** 列），以及[构建时间](#build-time-and-generated-code) |
| [MessagePack for C#](https://github.com/MessagePack-CSharp/MessagePack-CSharp) | .NET 中最常用的二进制格式 | 运行时性能，仅 `SimpleTest` 和 `PolymorphicTest`，只在本地运行 Nino 的 `benchmarks/run.sh` 时测量：发布的报告不包含它 |

绝对耗时取决于机器，请比较倍数。功能而非速度方面的对比，参见 [Nino 与 MemoryPack 对比](/zh/docs/v4/vs-memorypack)和 [v3 与 v4 对比](/zh/docs/v4/v3-vs-v4)。

## 测量方法 [#setup]

| | |
| --- | --- |
| 机器 | 运行时：发布时基准测试所用的 GitHub 托管 `ubuntu-26.04` 运行器，具体 CPU 见[全部测量结果](#results)。构建时间：Intel Xeon 2.10 GHz，4 核，AVX-512 |
| 运行时 | .NET 10.0.13（SDK 10.0.402），服务器 GC |
| 测试框架 | BenchmarkDotNet 0.15.8，每个用例在 3 个进程中各做 5 次预热、15 次测量，取三者的平均（只用一个进程时，一个 12 ns 的用例最多会偏差 13%）；各基准测试类在每种架构的五台运行器上并行运行，同一个用例的 Nino 和 MemoryPack 总在同一台运行器上 |
| 项目 | [`src/Nino.Benchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.Benchmark)（运行时），[`src/Nino.GeneratorBenchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.GeneratorBenchmark)（构建时间） |

- **序列化**测试写入一个只创建一次、每次调用前重置的缓冲区写入器（Nino 用 `NinoArrayBufferWriter`，其他库用 `ArrayBufferWriter<byte>`），因此测的是序列化本身，而不是数组分配。每个库用的都是它能原地写入的写入器：写入其他 `IBufferWriter<byte>` 时，Nino 先写入池化的缓冲区再整体复制过去，比这些表格多一次复制。
- **反序列化**测试读取各个库在启动时写好的字节，每次调用都创建新对象。
- **先验证**：基准测试运行前，`--verify`（[`Verify.cs`](https://github.com/JasonXuDeveloper/Nino/blob/main/src/Nino.Benchmark/Verify.cs)）会跑一遍每个用例，检查每个序列化用例写出的字节数与载荷一致，并逐层比较各个库读回的值是否相同。测试数据使用固定种子，每次运行序列化的都是同样的值。
- **1 ns 以下**（约三个时钟周期）的耗时无法区分：读取一个 40 字节的结构体，在扣除 BenchmarkDotNet 的空方法开销后，两个库测出来都在 0.05 到 0.8 ns 之间。两边都低于 1 ns 记为持平；Nino 低于 1 ns 而另一方可测时，记为更快（快到测不出），不给倍数。相差 5% 以内同样记为持平。
- **复用**测试反序列化到已经存在的对象中：Nino 通过 `ref` 和 `[NinoPooled]` 对象池，MemoryPack 用它的覆盖模式。
- **v3** 运行的是同一个 `SimpleTest`，但编译时引用的是 NuGet 上的 Nino 3.3.13，在同一台运行器上、紧接在 v4 的 `SimpleTest` 之前运行一次。两次运行都包含 MemoryPack，它前后两次耗时的差别就是机器本身的波动。每张 v3 图表下方都注明了数据来自哪次运行。
- **Arm64**：发布时的基准测试还会以相同设置在 GitHub 的 Arm64 运行器（`ubuntu-24.04-arm`）上运行同样的基准测试类。等某个版本的发布报告包含这些结果后，Nino 对比 MemoryPack 的运行时表格和图表会在 **x64** 旁边多出一个 **Arm64** 标签页，你选择的标签页会同时切换全站所有基准测试表格和图表。两种运行器不同，请在同一架构内比较 Nino 与 MemoryPack，不要跨架构比较耗时。与 v3 的对比只有 x64。

每个基准测试的代码见[基准测试代码](#benchmark-code)。

### 引用追踪、版本容错、固定大小的类型和泛型基类型 [#more-cases]

另有四个基准测试类，比较的是会改变类型写入方式的功能，各自对照 MemoryPack 中最接近的模式：

- **引用追踪**（[`ReferenceTest`](#referencetest)）：一张 200 个节点的对象图，带共享对象和环。Nino 使用 `[NinoType(trackReferences: true)]`，MemoryPack 使用 `GenerateType.CircularReference`。
- **版本容错**（[`VersionTolerantTest`](#versiontoleranttest)）：把 `SimpleClass` 的成员放进一个以后还能添加成员的类型，单个对象和 100 个的数组各测一次。Nino 使用 `format: NinoFormat.VersionTolerant`（每个对象一个长度），MemoryPack 使用 `GenerateType.VersionTolerant`（每个成员一个长度）。
- **固定大小的类型**（[`FixedSizeTest`](#fixedsizetest)）：一个 40 字节的结构体、成员相同的密封类，以及这种类的 100 个元素的数组，都通过两个库返回 `byte[]` 的 API 测量，所以每次调用都包含分配结果数组的开销。反序列化这个结构体只是一次 40 字节的拷贝，两个库都只要一个时钟周期左右。
- **泛型基类型**（[`GenericPolymorphicTest`](#genericpolymorphictest)，从 v4.0.0-rc.7 起测量）：8 种子类型、随机顺序的 1,000 个元素，分别经非泛型基类型和泛型基类型的封闭实例读写：`Box<int>`、`Box<(int, long)>`、`Box<(int, string)>`，以及包含密封类和有子类型的类的元组。MemoryPack 的 Union 特性不能用在泛型类型上，所以为每个封闭基类型注册一个 `DynamicUnionFormatter`。发布的报告包含这些用例后，表中才会出现对应各行。

### 常用类型、集合与 BCL 类型 [#common-types-and-collections]

自 v4.0.0-rc.5 起又测量了三个测试类，结果在[全部测量结果](#results)中：

- **常用类型**（[`CommonTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/src/Nino.Benchmark/CommonTypesTest.cs)）：形态接近常见应用的数据，`List<Player>`（100 个）、`List<Order>`（100 个）、`List<Shape>`（1,000 个，声明为抽象基类）、一棵 `TreeNode` 树（1,365 个节点）、`InventoryItem[1000]`（带填充的结构体）和 `Dictionary<string, string>`（1,000 项）。
- **集合**（[`CollectionsTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/src/Nino.Benchmark/CollectionsTest.cs)）：基础类库中的集合，各 1,000 个元素：`List<(int, long)>`、`KeyValuePair<int, int>[]`、`HashSet<int>`、`Queue<int>`、`LinkedList<int>`、`SortedList<int, int>` 和 `ConcurrentDictionary<int, int>`。
- **BCL 类型**（[`BclTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/src/Nino.Benchmark/BclTypesTest.cs)）：两个库都有格式化器的其他基础类库类型：`BigInteger`（3^1000）、`Uri`、`Version`、`StringBuilder`（1,000 个字符）、`BitArray`（1,000 位）、`CultureInfo`、`TimeZoneInfo`、`Lazy<string>`，以及各 1,000 个元素的 `Memory<int>`、`ReadOnlySequence<int>`、`ReadOnlyCollection<int>`、`ILookup<int, int>`、`BlockingCollection<int>` 和 `Nino.Immutable` 中的不可变集合（`ImmutableHashSet`、`ImmutableSortedSet`、`ImmutableQueue`、`ImmutableStack`、`ImmutableDictionary`、`ImmutableSortedDictionary`）。`TimeZoneInfo` 这一项测的更多是设计差异而不是速度：Nino 按 id 写入系统时区，读取时取系统缓存的时区；MemoryPack 每次都写入并解析时区完整的序列化字符串。`BigInteger` 和 `BitArray` 只测 Nino：MemoryPack 1.21.4 无法正确往返它们（参见[基准测试中发现的 MemoryPack 问题](/zh/docs/v4/vs-memorypack#memorypack-bugs-found-while-benchmarking)）。

三者都序列化到复用的缓冲区写入器，并反序列化为新实例。

## 构建时间与生成代码 [#build-time-and-generated-code]

测试项目是一个合成的程序集：`N` 个抽象根类，每个根类下有 8 层派生类、一个密封叶子类和一个结构体（共 `N × 11` 个类型），成员包括基元类型、字符串、`List<T>`、`Dictionary<int, string>`、对其他 `[NinoType]` 的引用以及私有字段。测试工具对这份编译运行源生成器（进程内的 Roslyn 4.3），输出程序集，修改之后再重新运行生成器。每项耗时取五次运行中后三次的中位数；只有 v3 在 1,100 个类型时取三次运行的中位数，每次耗时 7.6 到 7.8 分钟。基线是 v3 3.3.13，在同一台机器上运行。

// In RefGraph: count nodes sharing 16 tags; each node's peer is an earlier node
// (a back reference, so the nesting stays shallow), and every node refers back to the graph.
public static RefGraph Create(int count)
{

## 复现 [#reproducing]

克隆 [Nino 仓库](https://github.com/JasonXuDeveloper/Nino)，准备好 .NET 10 SDK 和 Python 3：

```shell
# runtime, as published: v3 3.3.13, then the full v4 suite (about three and a half hours)
benchmarks/run.sh

# runtime, v4 only, a subset
dotnet run -c Release --project src/Nino.Benchmark -- --filter '*SimpleTest*' --launchCount 3 --warmupCount 5 --iterationCount 15

# reference tracking, version tolerance and fixed-size types
dotnet run -c Release --project src/Nino.Benchmark -- --filter '*ReferenceTest*' '*VersionTolerantTest*' '*FixedSizeTest*'

# build time and generated code (N = 30, 8 derived classes per root)
dotnet run -c Release --project src/Nino.GeneratorBenchmark -- 30 8
```

- `benchmarks/run.sh` 会构建 `benchmarks/v3`（引用 NuGet 上 Nino 3.3.13 的同一个 `SimpleTest`），在 v4 之前紧接着运行一次，然后逐个用例输出 **v4 对比 v3**。
- 每次发布时，CI 都按同样的流程运行，各基准测试类分布在每种架构的五台运行器上（v3 在 `SimpleTest` 所在的运行器上、紧接在它之前运行），并把结果写进发布说明：Performance Report，以及 **v3 3.3.13 vs v4 (same machine)** 一节。本站的运行时数据取自包含这些数据的最新 v4 版本。
- `benchmarks/members` 把 `SimpleClass` 按成员逐个拆开，分别对比 v3 和 v4，用来找出某个用例的时间花在哪个成员上。参见 [benchmarks README](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks)。
