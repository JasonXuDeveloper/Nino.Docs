What to know before choosing Nino v4: what it needs, what it does not do, and where to go instead.

## Current Limitations
- **Source generator required.** Nino needs its source generator (Roslyn 4.3 or later) and C# 9 or later in the project that declares `[NinoType]`s.
- **Not compatible with v3 data.** v4 cannot read data written by v3 or by the v4 betas and previews. See [Migrating from v3](/en/docs/v4/migration#converting-v3-data).
- **Positional by default.** A bare `[NinoType]` is the fastest format but does not survive member changes. For data you store or exchange across versions, choose `NinoFormat.VersionTolerant` or `NinoFormat.Keyed` before writing any: see [Evolving Your Data](/en/docs/v4/evolving-data).
- **The bytes describe nothing.** They carry no type tags or member names: only your C# types, or the code [nino-gen](/en/docs/v4/advanced/codegen) generates from them, can read them. For a format any language reads without your types, see [Nino vs MessagePack](/en/docs/v4/vs-messagepack) and [Nino vs protobuf-net](/en/docs/v4/vs-protobuf-net); to look into a payload while debugging, [`nino-gen inspect`](/en/docs/v4/advanced/codegen#inspect) decodes it with your assembly's layouts.
- **Settings are process-wide.** There are no per-call options: the members of [`NinoSettings`](/en/docs/v4/settings) apply to every call, and the limits are frozen at first use; attributes configure each type.
- **Some types have no built-in formatter.** `System.Type` is left out on purpose (data that names the types to create is a deserialization attack), as are delegates, non-generic collections and engine classes other than Unity's `AnimationCurve`, `Gradient` and `RectOffset`. See [Supported Types](/en/docs/v4/types#not-supported); a [custom formatter](/en/docs/v4/custom-formatters) can add any of them.
- **No built-in compression, and one value per stream call.** Compress the output with `System.IO.Compression` ([Compression](/en/docs/v4/advanced/streams#compression)). `NinoDeserializer.Deserialize<T>(stream)` reads to the end of the stream, so several messages on one stream go as [frames](/en/docs/v4/advanced/streams#frames) your code writes.
- **Generated TypeScript, Go and Rust cover most types, not all.** [Nino.Codegen](/en/docs/v4/advanced/codegen#not-generated) leaves out, with a build warning, each type a language cannot express and the types that hold it: in every language, closed generic types in slots that nothing names; in TypeScript, members such as multi-dimensional arrays, `DateTimeOffset` or custom formatters; in Rust, maps and sets keyed by floats. Each language's list: [TypeScript](/en/docs/v4/advanced/typescript#not-supported), [Go](/en/docs/v4/advanced/go#not-supported), [Rust](/en/docs/v4/advanced/rust#not-supported). A browser client that needs them can run the C# types in a [.NET WebAssembly module](/en/docs/v4/advanced/browser#jsexport).

## Platform Notes

Nino defines its bytes instead of copying memory, so data is portable between CoreCLR, Mono and IL2CPP, 64-bit and 32-bit. How `Nullable<T>`, `ValueTuple`, `decimal`, `DateTimeOffset`, 32-bit alignment and padding are handled is described in [Platforms](/en/docs/v4/platforms#portable-by-design). Bytes are little-endian; on a big-endian host, which no current .NET or Unity platform is, Nino throws instead of writing them.
