## 对比对象 [#what-is-compared]

| 对比对象 | 原因 | 测量内容 |
| --- | --- | --- |
| [MemoryPack](https://github.com/Cysharp/MemoryPack) **1.21.4** | .NET 上用得最广的二进制序列化库里最快的一个，和 Nino 一样基于源生成器 | 运行时性能，在同一次 BenchmarkDotNet 运行里测：[序列化](#serialize-to-a-reused-buffer-writer)、[反序列化](#deserialize-new-instances)、[多态对象图](#polymorphism)、[复用实例](#pooling)、[引用追踪、版本容错和固定大小的类型](#more-cases) |
| Nino v3 **3.3.13** | v3 API 的最后一个版本，也就是你要从它升级的版本 | 运行时性能，和 v4 在同一台机器上前后紧挨着测（运行时表格里的 **v4 对比 v3** 列），以及[构建时间](#build-time-and-generated-code) |
| [MessagePack for C#](https://github.com/MessagePack-CSharp/MessagePack-CSharp) **3.1.12** 和 [protobuf-net](https://github.com/protobuf-net/protobuf-net) **3.4.40** | .NET 里最常用的二进制格式，和 .NET 里最常用的 Protocol Buffers 库 | 运行时性能，在同一次 BenchmarkDotNet 运行里测，格式能写出相同数据的用例都测：运行时表格里各占一列，[全部测量结果](#results)里各有若干行（见 [MessagePack 与 protobuf-net](#messagepack-and-protobuf-net)）。它们加入之前的发布报告里没有这些行，表格就只显示 Nino 和 MemoryPack |

绝对耗时因机器而异，看倍数。Go、Rust 和 TypeScript 里的 Nino 对比 Protocol Buffers、MessagePack 和各语言常用序列化库的结果，见[其他语言的基准测试](/zh/docs/v4/benchmarks-runtimes)。比功能而不是比速度，见 [Nino 与 MemoryPack 对比](/zh/docs/v4/vs-memorypack)和 [v3 与 v4 对比](/zh/docs/v4/whats-new#features)。

## 测量方法 [#setup]

| | |
| --- | --- |
| 机器 | 运行时：发布时跑基准测试的 GitHub 托管 `ubuntu-26.04` runner，具体 CPU 见[全部测量结果](#results)。构建时间：Intel Xeon 2.10 GHz，4 核，AVX-512 |
| 运行时 | .NET 10.0.13（SDK 10.0.402），服务器 GC |
| 测试框架 | BenchmarkDotNet 0.15.8，每个用例跑 3 个进程，每个进程预热 5 次、测量 15 次，取三个进程的平均（只跑一个进程时，一个 12 ns 的用例最多偏差 13%）；各基准测试类在每种架构的十台 runner 上并行跑，同一个用例的所有序列化库都在同一台 runner 上 |
| 项目 | [`benchmarks/Nino.Benchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks/Nino.Benchmark)（运行时），[`benchmarks/Nino.GeneratorBenchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks/Nino.GeneratorBenchmark)（构建时间） |

- **序列化**测试写进一个缓冲区写入器，它只创建一次，每次调用前重置（Nino 用 `NinoArrayBufferWriter`，其他库用 `ArrayBufferWriter<byte>`），所以测的是序列化本身，不是数组分配。每个库用的都是它能直接写入的写入器：换成其他 `IBufferWriter<byte>`，Nino 会先写进池化的缓冲区再整体复制过去，比这些表格多一次复制。
- **反序列化**测试读的是各个库启动时写好的字节，每次调用都创建新对象。
- **先验证**：跑基准测试之前，`--verify`（[`Verify.cs`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/Verify.cs)）把每个用例跑一遍，检查每个序列化用例写出的正是载荷的字节，各个库读回的值也逐层比较、完全相同。测试数据用固定种子，每次跑序列化的都是同样的值。
- **1 ns 以下**（大约三个时钟周期）的耗时分不出快慢：读一个 40 字节的结构体，扣掉 BenchmarkDotNet 的空方法开销后，两个库测出来都在 0.05 到 0.8 ns 之间晃。两边都低于 1 ns 记为持平；Nino 低于 1 ns、对方测得出时，记为更快（快到测不出），不给倍数。相差 5% 以内也记为持平。
- **复用**测试读入已有的对象：Nino 用 `ref` 和 `[NinoPooled]` 对象池，MemoryPack 用它的覆盖模式。
- **MessagePack 与 protobuf-net** 用同样的类型，读写和 Nino、MemoryPack 一样的值，各自用文档推荐的最快 API；见 [MessagePack 与 protobuf-net](#messagepack-and-protobuf-net)。
- **v3** 跑的是同一个 `SimpleTest`，只是编译时引用 NuGet 上的 Nino 3.3.13，在同一台 runner 上、紧挨着 v4 的 `SimpleTest` 之前跑一次。两次都带 MemoryPack，它前后两次的耗时差就是机器本身的波动。每张 v3 图表下面都注明了数据出自哪次运行。
- **Arm64**：发布时的基准测试还会用同样的设置，在 GitHub 的 Arm64 runner（`ubuntu-24.04-arm`）上跑同样的基准测试类。某个版本的发布报告有了这些结果后，Nino 对比 MemoryPack 的运行时表格和图表会在 **x64** 旁边多一个 **Arm64** 标签页，选哪个标签页，全站的基准测试表格和图表都跟着切换。两种 runner 不一样，只在同一架构内比较 Nino 和 MemoryPack，别跨架构比耗时。和 v3 的对比只有 x64。

每个基准测试的代码见[基准测试代码](#benchmark-code)。

### 引用追踪、版本容错、固定大小的类型和泛型基类型 [#more-cases]

另外四个基准测试类比的是改变类型写法的功能，各自对照 MemoryPack 最接近的模式；MessagePack 和 protobuf-net 能写出相同数据时，也和它们比（这两个都不支持引用追踪）：

- **引用追踪**（[`ReferenceTest`](#referencetest)）：一张 200 个节点的对象图，有共享对象，也有环。Nino 用 `[NinoType(trackReferences: true)]`，MemoryPack 用 `GenerateType.CircularReference`。
- **版本容错**（[`VersionTolerantTest`](#versiontoleranttest)）：把 `SimpleClass` 的成员放进一个以后还能加成员的类型，单个对象和 100 个的数组各测一次。Nino 用 `format: NinoFormat.VersionTolerant`（每个对象一个长度），MemoryPack 用 `GenerateType.VersionTolerant`（每个成员一个长度）。
- **固定大小的类型**（[`FixedSizeTest`](#fixedsizetest)）：一个 40 字节的结构体、成员相同的密封类，以及 100 个这种类组成的数组，都用两个库返回 `byte[]` 的 API 测，所以每次调用都算上了分配结果数组的开销。反序列化这个结构体只是一次 40 字节的拷贝，两个库都只要一个时钟周期左右。
- **泛型基类型**（[`GenericPolymorphicTest`](#genericpolymorphictest)，从 v4.0.0-rc.7 起测量）：8 种类型的 1,000 个子类型实例，顺序随机，分别经非泛型基类型和泛型基类型的封闭实例读写：`Box<int>`、`Box<(int, long)>`、`Box<(int, string)>`，以及装着一个密封类和一个有子类型的类的元组。MemoryPack 的 Union 特性不能加在泛型类型上，所以给每个封闭基类型注册一个 `DynamicUnionFormatter`。发布报告里有了这些用例，表里才会出现对应的行。

### 常用类型、集合与 BCL 类型 [#common-types-and-collections]

从 v4.0.0-rc.5 起又加测了三个测试类，结果在[全部测量结果](#results)里：

- **常用类型**（[`CommonTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/CommonTypesTest.cs)）：贴近常见应用的数据，`List<Player>`（100 个）、`List<Order>`（100 个）、`List<Shape>`（1,000 个，声明为抽象基类）、一棵 `TreeNode` 树（1,365 个节点）、`InventoryItem[1000]`（带填充的结构体）和 `Dictionary<string, string>`（1,000 项）。
- **集合**（[`CollectionsTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/CollectionsTest.cs)）：基础类库里的集合，各 1,000 个元素：`List<(int, long)>`、`KeyValuePair<int, int>[]`、`HashSet<int>`、`Queue<int>`、`LinkedList<int>`、`SortedList<int, int>` 和 `ConcurrentDictionary<int, int>`。
- **BCL 类型**（[`BclTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/BclTypesTest.cs)）：两个库都有格式化器的其余基础类库类型：`BigInteger`（3^1000）、`Uri`、`Version`、`StringBuilder`（1,000 个字符）、`BitArray`（1,000 位）、`CultureInfo`、`TimeZoneInfo`、`Lazy<string>`，以及各 1,000 个元素的 `Memory<int>`、`ReadOnlySequence<int>`、`ReadOnlyCollection<int>`、`ILookup<int, int>`、`BlockingCollection<int>` 和 `Nino.Immutable` 里的不可变集合（`ImmutableHashSet`、`ImmutableSortedSet`、`ImmutableQueue`、`ImmutableStack`、`ImmutableDictionary`、`ImmutableSortedDictionary`）。`TimeZoneInfo` 这一项测的主要是设计差异，不是速度：Nino 按 ID 写系统时区，读的时候直接取系统缓存的时区；MemoryPack 每次都写出并解析时区完整的序列化字符串。`BigInteger` 和 `BitArray` 只测 Nino：MemoryPack 1.21.4 写出去再读回来就不对了（见[基准测试中发现的 MemoryPack 问题](/zh/docs/v4/vs-memorypack#memorypack-bugs-found-while-benchmarking)）。

这三个类都序列化到复用的缓冲区写入器，反序列化成新实例。

**不可信读取**（[`UntrustedTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/UntrustedTest.cs)，从 v4.0.0-rc.8 起测，只测反序列化）打开 [`NinoSettings.Untrusted`](/zh/docs/v4/security#untrusted-mode)，读一个由 1,000 个原始结构体组成的列表，结构体里有一个 `DateTime` 和一个 `bool`，每个值的这两个字段都要检查；对照的 MemoryPack 不检查，直接复制。结果在[全部测量结果](#results)里。

`InventoryItem` 和 `(int, long)` 在内存里有填充，MemoryPack 原样拷贝，Nino 则写成零或干脆不写：这对耗时、大小和字节本身有什么影响，见[带填充的结构体和元组](/zh/docs/v4/vs-memorypack#padded-values)。

### MessagePack 与 protobuf-net [#messagepack-and-protobuf-net]

MessagePack 3（MessagePack-CSharp）和 protobuf-net 3 用同样的类型，读写和 Nino、MemoryPack 一样的值：`[MessagePackObject]` 配合整数 `[Key]`，子类型用 `[Union]`；`[ProtoContract]` 配合 `[ProtoMember]` 和 `[ProtoInclude]`。速度以外的区别见 [Nino 与 MessagePack 对比](/zh/docs/v4/vs-messagepack)和 [Nino 与 protobuf-net 对比](/zh/docs/v4/vs-protobuf-net)。

- **MessagePack** 用 `MessagePackSerializer.Serialize(IBufferWriter<byte>, value)` 序列化到复用的 `ArrayBufferWriter<byte>`，用 `Deserialize<T>(ReadOnlyMemory<byte>)` 反序列化，用默认选项；默认的解析器会用上 MessagePack 源生成器在编译时为基准测试类型生成的格式化器。不可变集合交给 `ImmutableCollectionResolver`（MessagePack.ImmutableCollection 包）处理。
- **protobuf-net** 用 `Serializer.Serialize(Stream, value)` 序列化到复用的 `MemoryStream`，用 `Serializer.Deserialize<T>(ReadOnlySpan<byte>)` 反序列化，用默认的运行时模型：某个类型第一次用到时，才为它编译序列化器。写流是 protobuf-net 最快的写法：它的 `IBufferWriter<byte>` 写入器在写每条嵌套消息之前，都要先算一遍消息的大小。`FixedSizeTest` 测的是返回 `byte[]` 的 API：protobuf-net 没有这种 API，所以先写进复用的流，再把字节复制到新数组。

某个库没法用相同数据表达的用例，就不给它写测试方法，绝不换成别的数据来测；表格里它的单元格是 “—”：

| 测试类 | 没有 MessagePack | 没有 protobuf-net |
| --- | --- | --- |
| `ReferenceTest` | 不支持引用追踪：写不出共享对象和环 | 同上（protobuf-net 3 没有实现 `AsReference`） |
| `PooledTest`、`PooledGraphTest` | 覆盖和池化用例：它只能读出新实例 | 同上：读入已有实例时是合并（往它的列表里追加），不是覆盖 |
| `GenericPolymorphicTest` | 五个泛型基类型：它的 Union 是基类型上的特性，没法按类型实参指定不同的子类型 | — |
| `CommonTypesTest` | — | `Tree`：protobuf 分不清空列表和没有列表，叶子节点的空子列表读回来是 null |
| `BclTypesTest` | `CultureInfo`、`TimeZoneInfo`、`BlockingCollection<T>`：遇到就抛异常 | 除 `Uri` 和不可变集合以外全部没有：其他类型 protobuf-net 没有序列化器 |

各种格式写的内容不一样，载荷大小就看得出来：MessagePack 把 `Guid` 写成 36 个字符的字符串，把 `DateTime` 写成 UTC 时间戳；protobuf-net 给类层次的每一层套一条消息，`DateTime` 也单独写成一条消息。

## 构建时间与生成代码 [#build-time-and-generated-code]

测试项目是一个人工合成的程序集：`N` 个抽象根类，每个根类下面一条 8 层的派生链、一个密封叶子类和一个结构体（共 `N × 11` 个类型），成员有基元类型、字符串、`List<T>`、`Dictionary<int, string>`、对其他 `[NinoType]` 的引用和私有字段。测试工具对这次编译运行源生成器（进程内的 Roslyn 4.3），输出程序集，改一处代码后再跑一遍生成器。每项耗时取五次运行里后三次的中位数；只有 v3 在 1,100 个类型时取三次运行的中位数，每次要 7.6 到 7.8 分钟。基线是 v3 3.3.13，在同一台机器上跑。

### ReferenceTest [#referencetest]

一张 200 个节点的对象图，有共享的标签、共享的对等节点，还有经过根对象的环，写进复用的缓冲区写入器再读回来。Nino 用 `trackReferences` 追踪引用，MemoryPack 用 `GenerateType.CircularReference`（要求每个成员都有 `[MemoryPackOrder]`）；两者都只把每个对象写一次，读回时共享引用和环仍然指向同一个实例。对应上文[结果表格](#more-cases)里的“对象图”各行。

```csharp title="ReferenceTest.cs" excerpt tab="类型" tab-group="bench-code"

    [MemoryPackOrder(1)] public string Name;
}

[NinoType(trackReferences: true)]
[MemoryPackable(GenerateType.CircularReference)]
public sealed partial class RefGraph
{
    [MemoryPackOrder(0)] public int Version;
    [MemoryPackOrder(1)] public List<RefNode> Nodes;
    [MemoryPackOrder(2)] public List<RefTag> Tags;
```

```csharp title="ReferenceTest.cs" nocheck tab="数据" tab-group="bench-code"
// RefGraph 中：count 个节点共享 16 个标签；每个节点的 peer 是更早的一个节点
// （向后引用，嵌套因此保持很浅），并且每个节点都引用回图本身。
public static RefGraph Create(int count)
{
    var r = new Random(3);
    var graph = new RefGraph { Version = 1, Nodes = new List<RefNode>(count) };
    graph.Tags = Enumerable.Range(0, 16).Select(i => new RefTag { Id = i, Name = "tag" + i }).ToList();
    for (int i = 0; i < count; i++)
    {
        graph.Nodes.Add(new RefNode
        {
            Id = i, Weight = r.NextDouble(), Graph = graph, Tag = graph.Tags[r.Next(graph.Tags.Count)],
            Peer = i == 0 ? null : graph.Nodes[r.Next(i)]
        });
    }

    return graph;
}
```

值总是占同样字节数的类型（[固定大小的类型](/zh/docs/v4/performance#fixed-size-types)）：`Serialize(value)` 按这个大小分配一个新 `byte[]` 返回，把值直接写进去，不经过暂存缓冲区和写入器，也不拷贝。用两个序列化库返回 `byte[]` 的 API 测，所以每次序列化都算上了分配结果数组的开销；另外还测了 100 个这种类组成的数组，它的长度不固定，走常规路径。对应上文[结果表格](#more-cases)里的 `FixedStruct` 和 `FixedClass` 各行。

```csharp title="FixedSizeTest.cs" excerpt tab="类型" tab-group="bench-code"
// 只有非托管成员（40 字节，没有填充）：每个值序列化后的字节数都相同。
[NinoType]
[MemoryPackable]
public partial struct FixedStruct
{
    public int Id;
    public Vector3 Position;
    public long Ticks;
    public Guid Guid;
}

// 同样的成员放在密封类中：大小也固定（一个存在字节加 40 字节）。
[NinoType]
[MemoryPackable]
public sealed partial class FixedClass
{
    public int Id;
    public Vector3 Position;
    public long Ticks;
    public Guid Guid;
}
```

```csharp title="FixedSizeTest.cs" nocheck tab="数据" tab-group="bench-code"
// FixedStruct 中（FixedClass 的 Create 相同）：
public static FixedStruct Create(Random r) => new()
{
    Id = r.Next(),
    Position = new Vector3(r.NextSingle(), r.NextSingle(), r.NextSingle()),
    Ticks = DateTime.Now.AddSeconds(r.Next()).Ticks,
    Guid = Guid.NewGuid(),
};

// FixedSizeTest 中：
private static readonly FixedStruct FixedStruct = FixedStruct.Create(new Random(4));
private static readonly FixedClass FixedClass = FixedClass.Create(new Random(5));
private static readonly FixedClass[] FixedClasses =
    Enumerable.Range(0, 100).Select(i => FixedClass.Create(new Random(6 + i))).ToArray();

static FixedSizeTest()
{
    // 这些用例测的是固定大小的路径：任一类型不再走这条路径，就直接报错。
    if (NinoSerializer.GetFixedSize<FixedStruct>() < 0 || NinoSerializer.GetFixedSize<FixedClass>() < 0)
        throw new InvalidOperationException("FixedStruct and FixedClass must be of fixed size");
}
```

```csharp title="FixedSizeTest.cs" excerpt tab="方法" tab-group="bench-code"
[Benchmark(Baseline = true), BenchmarkCategory("FixedClassSerialize")]
public byte[] NinoSerializeFixedClass() => NinoSerializer.Serialize(FixedClass);

[Benchmark, BenchmarkCategory("FixedClassSerialize")]
public byte[] MemoryPackSerializeFixedClass() => MemoryPackSerializer.Serialize(FixedClass);

[Benchmark(Baseline = true), BenchmarkCategory("FixedClassDeserialize")]
public FixedClass NinoDeserializeFixedClass() => NinoDeserializer.Deserialize<FixedClass>(NinoFixedClass);

[Benchmark, BenchmarkCategory("FixedClassDeserialize")]
public FixedClass MemoryPackDeserializeFixedClass() =>
    MemoryPackSerializer.Deserialize<FixedClass>(MemoryPackFixedClass);

// FixedStruct 和 FixedClasses（100 个元素的数组）的方法相同。
```

### GenericPolymorphicTest [#genericpolymorphictest]

数组里是 8 种类型的 1,000 个子类型实例，顺序随机，分别经非泛型基类型和泛型基类型的封闭实例读写。MemoryPack 的 `[MemoryPackUnion]` 不能加在泛型类型上（会报 MEMPACK013 或 MEMPACK014），所以基准测试给每个封闭基类型注册一个 `DynamicUnionFormatter`；Nino 只要 `[NinoType]`。对应[上文结果](#more-cases)里的泛型基类型各行。

```csharp title="GenericPolymorphicTest.cs" nocheck
[NinoType, MemoryPackable]
[MemoryPackUnion(0, typeof(ProbeA))] // ... ProbeH
public abstract partial class ProbeBase { public int V; }
[NinoType, MemoryPackable] public sealed partial class ProbeA : ProbeBase { } // ... ProbeH

[NinoType] public abstract class ProbeBox<T> { public T V; }
[NinoType, MemoryPackable] public sealed partial class ProbeBoxA : ProbeBox<int> { }                  // ... H
[NinoType, MemoryPackable] public sealed partial class ProbeTupA : ProbeBox<(int, long)> { }          // ... H
[NinoType, MemoryPackable] public sealed partial class ProbeStrA : ProbeBox<(int, string)> { }        // ... H
[NinoType, MemoryPackable] public sealed partial class ProbeScA : ProbeBox<(ProbeSealedItem, int)> { } // ... H
[NinoType, MemoryPackable] public sealed partial class ProbeOcA : ProbeBox<(ProbeOpenItem, int)> { }   // ... H

// 只有 MemoryPack 需要：每个封闭泛型基类型一个 Union 格式化器，并指定标签。
MemoryPackFormatterProvider.Register(new DynamicUnionFormatter<ProbeBox<int>>(
    (0, typeof(ProbeBoxA)), (1, typeof(ProbeBoxB)), /* ... */ (7, typeof(ProbeBoxH))));

[Benchmark(Baseline = true), BenchmarkCategory("GenericIntBaseSerialize")]
public int NinoSerializeGenericIntBase()
{
    _buffer.ResetWrittenCount();
    NinoSerializer.Serialize(GenericIntBase, _buffer);
    return _buffer.WrittenCount;
}

[Benchmark(Baseline = true), BenchmarkCategory("GenericIntBaseDeserialize")]
public ProbeBox<int>[] NinoDeserializeGenericIntBase() =>
    NinoDeserializer.Deserialize<ProbeBox<int>[]>(NinoGenericIntBaseBytes);
// MemoryPack 的方法和其他用例相同。
```

## 复现 [#reproducing]

克隆 [Nino 仓库](https://github.com/JasonXuDeveloper/Nino)，装好 .NET 10 SDK 和 Python 3，然后：

```shell
# 运行时，与发布的数据相同：先 v3 3.3.13，再完整的 v4 套件（约六小时）
benchmarks/run.sh

# 运行时，只测 v4 的一部分
dotnet run -c Release --project benchmarks/Nino.Benchmark -- --filter '*SimpleTest*' --launchCount 3 --warmupCount 5 --iterationCount 15

# 引用追踪、版本容错和固定大小的类型
dotnet run -c Release --project benchmarks/Nino.Benchmark -- --filter '*ReferenceTest*' '*VersionTolerantTest*' '*FixedSizeTest*'

# 构建时间和生成的代码（N = 30，每个根类型 8 个派生类）
dotnet run -c Release --project benchmarks/Nino.GeneratorBenchmark -- 30 8
```

- `benchmarks/run.sh` 会构建 `benchmarks/v3`（同一个 `SimpleTest`，引用 NuGet 上的 Nino 3.3.13），紧挨着 v4 之前跑一次，再逐个用例输出 **v4 对比 v3**。
- 每次发布，CI 都按同样的流程跑，各基准测试类分到每种架构的十台 runner 上（v3 在 `SimpleTest` 那台 runner 上、紧挨着它之前跑），结果写进发布说明：Performance Report，以及 **v3 3.3.13 vs v4 (same machine)** 一节。本站的运行时数据取自带这些数据的最新 v4 版本。
- Go、Rust 和 TypeScript 的基准测试也在这个发布流程里跑；怎么跑见[其他语言的基准测试](/zh/docs/v4/benchmarks-runtimes#reproducing)。
- `benchmarks/members` 把 `SimpleClass` 按成员一个个拆开，分别对比 v3 和 v4，找出某个用例的时间花在哪个成员上。见 [benchmarks README](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks)。
