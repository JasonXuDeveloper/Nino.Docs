This page has every benchmark number the documentation quotes, the code that produces them, and how to run it yourself. Other pages summarize these results and link here. Go, Rust and TypeScript have [Benchmarks in Other Languages](/en/docs/v4/perf-runtimes), and Unity's Burst kernels the [Unity Benchmark](/en/docs/v4/perf-unity); [SIMD on Every Platform](/en/docs/v4/simd) says which vector paths each of them measures.

## What Is Compared [#what-is-compared]

| Against | Why | What is measured |
| --- | --- | --- |
| [MemoryPack](https://github.com/Cysharp/MemoryPack) **1.21.4** | The fastest widely used binary serializer for .NET, and source-generated like Nino | Runtime, in the same BenchmarkDotNet run: [serialize](#serialize-to-a-reused-buffer-writer), [deserialize](#deserialize-new-instances), [polymorphic graphs](#polymorphism), [reusing instances](#pooling), [reference tracking, version tolerance and fixed-size types](#more-cases) |
| Nino v3 **3.3.13** | The last release of the v3 API, the version you would upgrade from | Runtime, back to back with v4 on the same machine (the **v4 vs v3** column of the runtime tables), and [build time](#build-time-and-generated-code) |
| [MessagePack for C#](https://github.com/MessagePack-CSharp/MessagePack-CSharp) **3.1.12** and [protobuf-net](https://github.com/protobuf-net/protobuf-net) **3.4.30** | The most common binary format in .NET, and the most common Protocol Buffers library for .NET | Runtime, in the same BenchmarkDotNet run, in every case where the format can write the same data: a column each in the runtime tables, a row each in [All Measurements](#results) (see [MessagePack and protobuf-net](#messagepack-and-protobuf-net)). Release reports before they joined the benchmark have no rows for them, and the tables then show Nino and MemoryPack only |

Absolute times depend on the machine; compare the ratios. For Nino in Go, Rust and TypeScript against Protocol Buffers, MessagePack and each language's usual serializers, see [Benchmarks in Other Languages](/en/docs/v4/perf-runtimes). For features rather than speed, see [Nino vs MemoryPack](/en/docs/v4/vs-memorypack) and [v3 vs v4](/en/docs/v4/v3-vs-v4).

## How It Is Measured [#setup]

| | |
| --- | --- |
| Machine | Runtime: the GitHub-hosted `ubuntu-26.04` runners of the release's benchmark run; the exact CPU is listed under [All Measurements](#results). Build time: Intel Xeon 2.10 GHz, 4 cores, AVX-512 |
| Runtime | .NET 10.0.13 (SDK 10.0.402), server GC |
| Harness | BenchmarkDotNet 0.15.8, each case in 3 processes of 5 warm-up and 15 measured iterations (the mean of the three: one process alone moved a 12 ns case by up to 13%); the benchmark classes run in parallel on ten runners per architecture, with every serializer's run of a case on the same runner |
| Projects | [`benchmarks/Nino.Benchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks/Nino.Benchmark) (runtime), [`benchmarks/Nino.GeneratorBenchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks/Nino.GeneratorBenchmark) (build time) |

- **Serialize** benchmarks write into a buffer writer that is created once and reset before each call (`NinoArrayBufferWriter` for Nino, `ArrayBufferWriter<byte>` for the others), so they measure the serializer, not array allocation. Each library gets the writer it writes in place: into any other `IBufferWriter<byte>`, Nino writes a pooled buffer and then copies it over, one copy more than these tables measure.
- **Deserialize** benchmarks read bytes that each serializer wrote at startup, and create new objects on every call.
- **Verified first**: before the benchmarks run, `--verify` ([`Verify.cs`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/Verify.cs)) runs every case and checks that each serialize case writes its payload's bytes and that every library reads back the same value, deep-compared. The test data is seeded, so every run serializes the same values.
- **Under 1 ns** (about three clock cycles), times cannot be told apart: reading a 40-byte struct measures anywhere from 0.05 to 0.8 ns in both libraries once BenchmarkDotNet subtracts its empty-method overhead. Two times under 1 ns are on par; Nino under it against a measurable time is faster, too fast to measure, with no ratio. Within 5% is on par too.
- **Reuse** benchmarks deserialize into objects that already exist: Nino by `ref` and from `[NinoPooled]` pools, MemoryPack with its overwrite mode.
- **MessagePack and protobuf-net** read and write the same values as Nino and MemoryPack, through the same types, each with the API its documentation recommends for speed; see [MessagePack and protobuf-net](#messagepack-and-protobuf-net).
- **v3** runs the same `SimpleTest` built against Nino 3.3.13 from NuGet, directly before the v4 `SimpleTest` run on the same runner. MemoryPack runs in both, so the difference between its two times shows how much the machine itself varied. The note under each v3 chart names the run its numbers come from.
- **Arm64**: the release benchmark run also runs the same benchmark classes, with the same settings, on GitHub's Arm64 runners (`ubuntu-24.04-arm`). Once a release's report includes them, the runtime tables and charts of Nino against MemoryPack get an **Arm64** tab next to **x64**, and the tab you pick switches every benchmark table and chart on the site. The runners differ, so compare Nino with MemoryPack within one architecture, not times across the two. Comparisons with v3 are x64 only.

The code of every benchmark is in [Benchmark Code](#benchmark-code).

### Reference Tracking, Version Tolerance, Fixed-Size Types and Generic Bases [#more-cases]

Four more benchmark classes compare features that change how a type is written, each against the closest MemoryPack mode, and against MessagePack and protobuf-net where they can write the same data (neither tracks references):

- **Reference tracking** ([`ReferenceTest`](#referencetest)): a graph of 200 nodes with shared objects and cycles. Nino uses `[NinoType(trackReferences: true)]`, MemoryPack `GenerateType.CircularReference`.
- **Version tolerance** ([`VersionTolerantTest`](#versiontoleranttest)): `SimpleClass`'s members in a type that can gain members later, alone and as an array of 100. Nino uses `format: NinoFormat.VersionTolerant` (one length per object), MemoryPack `GenerateType.VersionTolerant` (a length per member).
- **Fixed-size types** ([`FixedSizeTest`](#fixedsizetest)): a 40-byte struct, the same members in a sealed class, and an array of 100 of the classes, through the `byte[]` APIs of both libraries, so allocating the result is part of every call. Deserializing the struct is a single 40-byte copy, about a clock cycle in both.
- **Generic bases** ([`GenericPolymorphicTest`](#genericpolymorphictest), measured from v4.0.0-rc.7): 1,000 subtypes of eight types in random order, through a non-generic base and through closed instances of a generic base: `Box<int>`, `Box<(int, long)>`, `Box<(int, string)>`, and tuples holding a sealed class and a class with subtypes. MemoryPack's union attribute cannot be put on a generic type, so it gets a `DynamicUnionFormatter` registered for each closed base. Their rows appear once a release's report includes them.

### Common Types, Collections and BCL Types [#common-types-and-collections]

Three more classes, measured since v4.0.0-rc.5; their rows are in [All Measurements](#results):

- **Common types** ([`CommonTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/CommonTypesTest.cs)): data shaped like that of common applications, `List<Player>` (100), `List<Order>` (100), `List<Shape>` (1,000 through an abstract base), a `TreeNode` tree (1,365 nodes), `InventoryItem[1000]` (a padded struct) and `Dictionary<string, string>` (1,000).
- **Collections** ([`CollectionsTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/CollectionsTest.cs)): collections of the base class library, 1,000 elements each: `List<(int, long)>`, `KeyValuePair<int, int>[]`, `HashSet<int>`, `Queue<int>`, `LinkedList<int>`, `SortedList<int, int>` and `ConcurrentDictionary<int, int>`.
- **BCL types** ([`BclTypesTest`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/BclTypesTest.cs)): the other base class library types both libraries have formatters for: `BigInteger` (3^1000), `Uri`, `Version`, `StringBuilder` (1,000 chars), `BitArray` (1,000 bits), `CultureInfo`, `TimeZoneInfo`, `Lazy<string>`, and with 1,000 elements `Memory<int>`, `ReadOnlySequence<int>`, `ReadOnlyCollection<int>`, `ILookup<int, int>`, `BlockingCollection<int>` and the immutable collections of `Nino.Immutable` (`ImmutableHashSet`, `ImmutableSortedSet`, `ImmutableQueue`, `ImmutableStack`, `ImmutableDictionary`, `ImmutableSortedDictionary`). The `TimeZoneInfo` case measures a design difference more than speed: Nino writes a system time zone by its id and reads it back from the system's cached zones, MemoryPack writes and parses the zone's whole serialized string on every call. `BigInteger` and `BitArray` are timed for Nino only: MemoryPack 1.21.4 does not round-trip them (see [MemoryPack Bugs Found While Benchmarking](/en/docs/v4/vs-memorypack#memorypack-bugs-found-while-benchmarking)).

All three serialize to a reused buffer writer and deserialize into new instances.

### MessagePack and protobuf-net [#messagepack-and-protobuf-net]

MessagePack 3 (MessagePack-CSharp) and protobuf-net 3 read and write the same values as Nino and MemoryPack, through the same types: `[MessagePackObject]` with integer `[Key]`s and `[Union]` for subtypes, `[ProtoContract]` with `[ProtoMember]` and `[ProtoInclude]`.

- **MessagePack** serializes with `MessagePackSerializer.Serialize(IBufferWriter<byte>, value)` into a reused `ArrayBufferWriter<byte>` and deserializes with `Deserialize<T>(ReadOnlyMemory<byte>)`, with the default options, whose resolver takes the formatters MessagePack's source generator writes for the benchmark types at compile time. The immutable collections go through `ImmutableCollectionResolver` (the MessagePack.ImmutableCollection package).
- **protobuf-net** serializes with `Serializer.Serialize(Stream, value)` into a reused `MemoryStream` and deserializes with `Serializer.Deserialize<T>(ReadOnlySpan<byte>)`, on the default runtime model, which compiles a serializer for each type on first use. Its stream writer is its fastest: its `IBufferWriter<byte>` writer measures each nested message before writing it. `FixedSizeTest` measures `byte[]` APIs: protobuf-net has none, so it writes to a reused stream and copies the bytes into a new array.

A case a library cannot express with the same data has no method for it, never one with other data, and its cell in the tables is “—”:

| Class | No MessagePack | No protobuf-net |
| --- | --- | --- |
| `ReferenceTest` | no reference tracking: shared objects and cycles cannot be written | the same (protobuf-net 3 does not implement `AsReference`) |
| `PooledTest`, `PooledGraphTest` | the overwrite and pooled cases: it reads new instances only | the same: deserializing into an instance merges (appends to its lists) instead of overwriting it |
| `GenericPolymorphicTest` | the five generic bases: its unions are attributes on the base, which cannot name other subtypes for each type argument | — |
| `CommonTypesTest` | — | `Tree`: protobuf cannot tell an empty list from none, and the leaves' empty child lists read back as null |
| `BclTypesTest` | `CultureInfo`, `TimeZoneInfo`, `BlockingCollection<T>`: it throws on them | everything but `Uri` and the immutable collections: protobuf-net has no serializer for the others |

The formats differ in what they write, and the payload sizes show it: MessagePack writes a `Guid` as a 36-character string and a `DateTime` as a UTC timestamp, protobuf-net nests one message per level of a class hierarchy and writes a `DateTime` as a message of its own.

## Build Time and Generated Code [#build-time-and-generated-code]

The test project is a synthetic assembly of `N` abstract root classes, each with a chain of 8 derived classes, a sealed leaf and a struct (`N × 11` types), with primitives, strings, `List<T>`, `Dictionary<int, string>`, references to other `[NinoType]`s and private fields. The harness runs the generator on the compilation (Roslyn 4.3 in-process), emits the assembly, and re-runs the generator after an edit. Each time is the median of the last three of five runs, except v3 at 1,100 types: the median of three runs, which took 7.6 to 7.8 minutes each. The baseline is v3 3.3.13, run on the same machine.

```csharp title="PolymorphicTest.cs"
// Polymorphic class: one PolymorphicClass. Create() fills Numbers (100 ints),
// Map1 (12 Foos: FooA to FooD, three times), Foo (a FooD) and Set (100 ints);
// then 1,000 Foos are added to Numbers2, cycling through the 20 subtypes.
PolymorphicInstance = PolymorphicClass.Create();
var polyClass = (PolymorphicClass)PolymorphicInstance;
```

```csharp title="ReferenceTest.cs"
// In RefGraph: count nodes sharing 16 tags; each node's peer is an earlier node
// (a back reference, so the nesting stays shallow), and every node refers back to the graph.
public static RefGraph Create(int count)
{
    var r = new Random(3);
    var graph = new RefGraph { Version = 1, Nodes = new List<RefNode>(count) };
    graph.Tags = Enumerable.Range(0, 16).Select(i => new RefTag { Id = i, Name = "tag" + i }).ToList();

            Peer = i == 0 ? null : graph.Nodes[r.Next(i)]
        });
    }

    return graph;
}
```

## Reproducing [#reproducing]

From a clone of the [Nino repository](https://github.com/JasonXuDeveloper/Nino), with the .NET 10 SDK and Python 3:

```shell
# runtime, as published: v3 3.3.13, then the full v4 suite (about six hours)
benchmarks/run.sh

# runtime, v4 only, a subset
dotnet run -c Release --project benchmarks/Nino.Benchmark -- --filter '*SimpleTest*' --launchCount 3 --warmupCount 5 --iterationCount 15

# reference tracking, version tolerance and fixed-size types
dotnet run -c Release --project benchmarks/Nino.Benchmark -- --filter '*ReferenceTest*' '*VersionTolerantTest*' '*FixedSizeTest*'

# build time and generated code (N = 30, 8 derived classes per root)
dotnet run -c Release --project benchmarks/Nino.GeneratorBenchmark -- 30 8
```

- `benchmarks/run.sh` builds `benchmarks/v3` (the same `SimpleTest` against Nino 3.3.13 from NuGet) and runs it directly before v4. It prints **v4 vs v3** for each case.
- Every release runs the same protocol in CI, with the benchmark classes split over ten runners per architecture (v3 runs directly before `SimpleTest` on its runner), and publishes the result in the release notes: the Performance Report, and a **v3 3.3.13 vs v4 (same machine)** section. This site takes its runtime numbers from the newest v4 release that has them.
- The Go, Rust and TypeScript benchmarks run in the same release workflow; how to run them is in [Benchmarks in Other Languages](/en/docs/v4/perf-runtimes#reproducing).
- `benchmarks/members` takes `SimpleClass` apart member by member, against v3 and v4, to find which member a case spends its time on. See the [benchmarks README](https://github.com/JasonXuDeveloper/Nino/tree/main/benchmarks).
