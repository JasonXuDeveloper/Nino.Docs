Build-time and runtime measurements of Nino v4 against Nino v3 **3.3.13** (the last v3 release) and [MemoryPack](https://github.com/Cysharp/MemoryPack) **1.21.4**. Absolute times vary between machines; the ratios are what to look at. For a feature comparison, see [Nino vs MemoryPack](/en/docs/v4/vs-memorypack).

## Setup

| | |
| --- | --- |
| CPU | Runtime: Intel Xeon 2.10 GHz, 4 cores, AVX-512; build time: Intel Xeon 2.80 GHz, 4 cores |
| OS | Ubuntu 24.04 |
| Runtime | .NET 10.0.13 (SDK 10.0.402), server GC |
| Harness | BenchmarkDotNet 0.15.2, 5 warm-up and 15 measured iterations, all four benchmark classes in one run |
| Projects | [`src/Nino.Benchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.Benchmark) (runtime), [`src/Nino.GeneratorBenchmark`](https://github.com/JasonXuDeveloper/Nino/tree/main/src/Nino.GeneratorBenchmark) (build time) |

## Build Time and Generated Code

Workload: `N` abstract root classes, each with a chain of 8 derived classes, a sealed leaf and a struct (`N × 11` types), with primitives, strings, `List<T>`, `Dictionary<int, string>`, references to other `[NinoType]`s and private fields. The harness runs the generator on the compilation (Roslyn 4.3 in-process), emits the assembly, and re-runs the generator after an edit. Times are the median of the last three of five runs.

### 330 Types (N = 30)

| | v3 (3.3.13) | v4 | v4 vs v3 |
| --- | ---: | ---: | ---: |
| Generated source | 18.7 MB (363,233 lines) | 1.15 MB (21,679 lines) | **16× smaller** |
| Compiling the generated code (emit) | 56.0 s | 1.27 s | **44× faster** |
| Running the generator | 1.11 s | 0.14 s | **7.9× faster** |
| Re-generating after editing a member | 1.31 s | 0.19 s | **6.9× faster** |
| Re-generating after editing a comment | 1.11 s | 0.19 s | **5.8× faster** |
| IL of the generated code | 2.2 MB | 0.37 MB | **6.0× smaller** |

### 1,100 Types (N = 100)

| | v3 (3.3.13) | v4 | v4 vs v3 |
|---|---:|---:|---:|
| Generated source | 62.0 MB (1,204,143 lines) | 3.9 MB (72,429 lines) | **16× smaller** |
| Compiling the generated code (emit) | 636 s | 2.2 s | **289× faster** |
| Running the generator | 5.5 s | 0.68 s | **8.1× faster** |
| Re-generating after editing a member | 4.1 s | 0.57 s | **7.2× faster** |
| Re-generating after editing a comment | 4.1 s | 0.45 s | **9.0× faster** |
| IL of the generated code | 7.3 MB | 1.3 MB | **5.6× smaller** |

v3's compile time grows much faster than the number of types: 3.3× the types took 11× the compile time (56 s → 636 s). v4 grows linearly: about 3.5 KB of source and 2 ms of compile time per type.

`SimpleStruct` (`int` + `DateTime`) is declared with `[StructLayout(LayoutKind.Sequential, Pack = 4)]`, so it is 12 bytes with no padding and every serializer copies it as one block. Without `Pack` it would be 16 bytes with 4 bytes of padding, which Nino zeroes on write; see [Struct Layout](/en/docs/v4/performance#struct-layout).

The `Nino.Benchmark` project also compares Nino with [MessagePack for C#](https://github.com/MessagePack-CSharp/MessagePack-CSharp), on the data structures below.

[NinoType]
[MemoryPackable]
[MessagePackObject]
[MemoryPackUnion(0, typeof(SimpleClass))]
[Union(0, typeof(SimpleClass))]
public abstract partial class SimpleClassBase
{
    [Key(0)] public int Id;
    [Key(1)] public bool Tag;
    [Key(2)] public Guid Guid;
    [Key(3)] public DateTime CreateTime;

[NinoType]
[MemoryPackable]
[MessagePackObject]
public sealed partial class SimpleClass : SimpleClassBase
{
    [Key(4)] public string Name { get; set; }
    [Key(5)] [NinoUtf8] public string Desc;
    [Key(6)] public int[] Numbers { get; set; }
    [Key(7)] public List<DateTime> Dates { get; set; }
    [Key(8)] public Dictionary<int, string> Map1;
    [Key(9)] public Dictionary<int, int> Map2 { get; set; }
}

### Data Generation

#### Generation Function

<Tabs items={["Simple Class", "Simple Struct"]}>

<Tab value="Simple Class">

```csharp
public static SimpleClass Create()
{
    Random random = new Random();
    return new SimpleClass
    {
        Id = random.Next(),
        Tag = random.Next() % 2 == 0,
        Guid = Guid.NewGuid(),
        CreateTime = DateTime.Now,
        Name = Guid.NewGuid().ToString(),
        Desc = Enumerable.Range(0, 10).Select(_ => Guid.NewGuid().ToString()).Aggregate((a, b) => a + b),
        Numbers = Enumerable.Range(0, 100).Select(_ => random.Next()).ToArray(),
        Dates = Enumerable.Range(0, 10).Select(_ => DateTime.Now.AddSeconds(random.Next())).ToList(),
        Map1 = Enumerable.Range(0, 10).ToDictionary(n => n, n => n.ToString()),
        Map2 = Enumerable.Range(0, 10).ToDictionary(n => n, n => n * 2)
    };
}
```

</Tab>
<Tab value="Simple Struct">

```csharp
public static SimpleStruct Create()
{
    Random random = new Random();
    return new SimpleStruct
    {
        Id = random.Next(),
        CreateTime = DateTime.Now.AddSeconds(random.Next())
    };
}
```

</Tab>
</Tabs>

#### Benchmark Data

```csharp
SimpleClass = SimpleClass.Create();
SimpleClasses = Enumerable.Range(0, 100).Select(_ => SimpleClass.Create()).ToArray();
SimpleStruct = SimpleStruct.Create();
SimpleStructs = Enumerable.Range(0, 100).Select(_ => SimpleStruct.Create()).ToArray();
var r = Random.Shared;
Vectors = Enumerable.Range(0, 10000)
    .Select(_ => new Vector4(r.NextSingle(), r.NextSingle(),
        r.NextSingle(), r.NextSingle())).ToArray();
```

Serialization writes into a reused buffer writer (`NinoArrayBufferWriter` for Nino, `ArrayBufferWriter<byte>` for the others), so no serializer allocates on the serialize paths.
