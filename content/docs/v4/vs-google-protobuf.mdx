[Google.Protobuf](https://github.com/protocolbuffers/protobuf/tree/main/csharp) is Google's own C# runtime for [Protocol Buffers](https://protobuf.dev). It is schema-first: you write messages in a `.proto` file, `protoc` generates a C# class for each, and programs in any language with a protobuf implementation read the same bytes from the same schema. Nino starts from your C# types instead. This page compares Nino v4 with Google.Protobuf **3.36.2**, the version Nino's benchmark runs, using the Protocol Buffers documentation at [protobuf.dev](https://protobuf.dev) for its features and Nino's source for Nino's. Where we could not verify a feature, it is left out. protobuf-net writes the same format from attributes on C# classes: see [Nino vs protobuf-net](/en/docs/v4/vs-protobuf-net). How all of them compare is on [Choosing a Serializer](/en/docs/v4/compare).

## Two Formats [#formats]

Protocol Buffers writes each field with its number and wire type, so a reader skips fields it does not know; the schema is the `.proto` file. Nino's bytes carry no field numbers: your C# types say how to read them, in .NET and in the Go, Rust and TypeScript code [nino-gen](/en/docs/v4/advanced/codegen) generates from them. The rows the two protobuf libraries share (objects, integers, null and empty) are in [protobuf-net's table](/en/docs/v4/vs-protobuf-net#formats); what Google.Protobuf does its own way:

| | Nino v4 | Google.Protobuf |
| --- | --- | --- |
| The schema | your C# types | a `.proto` file; `protoc` generates the C# classes |
| A subtype | a 4-byte type id, a hash of the type's name, before the subtype's members | no inheritance: a `oneof` field holds one of several messages |
| A missing value | a presence byte for a nullable value or reference | proto3 scalars have no null: a field is present (`optional`) or a wrapper message (`Int32Value`, read as `int?`) |
| Time | `DateTime`, `DateTimeOffset`, `TimeSpan` as they are | the well-known messages `Timestamp` and `Duration` |

## Performance [#performance]

Measured with BenchmarkDotNet in the same run as Nino, on the same values. Google.Protobuf runs on its own messages, which `protoc` generates from the benchmark's [`workloads.proto`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/Workloads/workloads.proto) and `cases.proto`; they write the same protobuf messages as protobuf-net. It writes with `WriteTo` into a reused `ArrayBufferWriter<byte>` and reads with `Parser.ParseFrom(ReadOnlySpan<byte>)` ([setup](/en/docs/v4/benchmarks#workloads)). <IfWorkloads>On the [real workloads](/en/docs/v4/benchmarks#workloads) where Nino leads, it serializes <BenchValue k="workloads.googleprotobuf.serialize" /> faster and deserializes <BenchValue k="workloads.googleprotobuf.deserialize" /> faster.</IfWorkloads> Google.Protobuf runs the workloads and the basic, polymorphism and nullable groups.

Payload sizes differ by format, not by effort: protobuf writes small integers as one-byte varints, Nino writes integers at their full width.

## Untrusted Input [#untrusted-input]

Google.Protobuf has no separate mode for untrusted data. A message cannot name a type to create: there is no inheritance, and an `Any` is unpacked only into a type the caller names (`Any.Unpack<T>`). Nesting is bounded by the recursion limit of `CodedInputStream`; the size of a message is bounded only when you create the stream with `CodedInputStream.CreateWithLimits` or bound the input at the host.

Nino reads untrusted data in its default mode; [`NinoSettings.Untrusted`](/en/docs/v4/security#untrusted-mode) adds the checks that cost time on every read.

## Where Google.Protobuf Is Ahead [#where-google-protobuf-is-ahead]

Google.Protobuf does these things and Nino v4 does not:

- **One schema for every language.** The `.proto` file is the contract, and Google's implementations for C++, Java, Python, Go and other languages generate their code from it. Nino's data is read through your C# types, or through the Go, Rust and TypeScript code generated from them.
- **gRPC.** gRPC for .NET (`Grpc.AspNetCore`, `Grpc.Net.Client`) is built on Google.Protobuf messages, and gRPC peers in other languages talk to it.
- **Every message tolerates change**, by field numbers, with rules the Protocol Buffers documentation sets out (never reuse a number; `reserved` keeps removed ones from coming back). In Nino this is a choice per type ([`NinoFormat.Keyed`](/en/docs/v4/evolving-data#keyed-members)); the default positional format breaks when members change.
- **A JSON form built in.** `JsonFormatter` and `JsonParser` read and write the Protocol Buffers JSON mapping of the same messages.
- **Descriptors.** Each message carries its schema at run time (`Descriptor`), for tools that work on any message.
- **Smaller integers.** Varints take one byte for small numbers.

The workaround for what Nino leaves out is on [Limitations](/en/docs/v4/compare#limitations). Which to choose for which job: [Which to Choose](/en/docs/v4/compare#which-to-choose).

## Switching from Google.Protobuf [#switching-from-google-protobuf]

With Nino the C# types are the schema, so each message becomes a type of your own:

| Google.Protobuf | Nino |
| --- | --- |
| `message Order { ... }` in a `.proto` file, compiled by `protoc` | a C# class, struct or record with `[NinoType]` ([Defining Types](/en/docs/v4/defining-types)) |
| field numbers (`int32 id = 1;`) | declaration order; or `[NinoType(false)]` with `[NinoMember(n)]` on the members to write ([Choosing Members Explicitly](/en/docs/v4/defining-types#choosing-members-explicitly)) |
| removing fields and `reserved` numbers | `[NinoType(format: NinoFormat.Keyed)]`: members by name, removed freely, renamed with `[NinoFormerName]` ([Evolving Your Data](/en/docs/v4/evolving-data)) |
| `oneof` | a base class or interface with `[NinoType]` and a subtype per case ([Polymorphism](/en/docs/v4/polymorphism)) |
| `repeated T`, `map<K, V>` | `List<T>` or `T[]`, `Dictionary<K, V>` |
| `optional` scalars, wrappers (`Int32Value`) | `int?` and other nullable types |
| `google.protobuf.Timestamp`, `Duration` | `DateTime` or `DateTimeOffset`, `TimeSpan` |
| `bytes` | `byte[]` |
| `message.WriteTo(bufferWriter)`, `message.ToByteArray()` | `NinoSerializer.Serialize(value, bufferWriter)`, `NinoSerializer.Serialize(value)` |
| `Order.Parser.ParseFrom(span)` | `NinoDeserializer.Deserialize<Order>(span)` |
| `MergeFrom` | `NinoDeserializer.Deserialize(bytes, ref value)`, which replaces the contents instead of appending ([Reuse and Pooling](/en/docs/v4/pooling)) |
| `WriteDelimitedTo`, `ParseDelimitedFrom` | [frames](/en/docs/v4/advanced/streams#frames) on the stream |

The two write different bytes, so stored data has to be converted: read each value with Google.Protobuf, copy it into the Nino type and write it with Nino ([Switching to Nino](/en/docs/v4/compare#switching) has the steps). Messages that programs in other languages read from the `.proto` file stay Protocol Buffers, or move to code generated by [nino-gen](/en/docs/v4/advanced/codegen) if those programs are TypeScript, Go or Rust. gRPC itself is not tied to protobuf: a `Marshaller<T>` made with `Marshallers.Create` from `NinoSerializer.Serialize` and `NinoDeserializer.Deserialize` carries Nino types, but only between peers that both use Nino.
