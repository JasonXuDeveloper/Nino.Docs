本页对比 Nino v3 与 Nino v4 的功能、构建时间与生成代码，以及运行时性能。如需升级，请参阅[从 v3 迁移](/zh/docs/v4/migration)。

## 功能

| | v3 | v4 |
| --- | --- | --- |
| API | 每个程序集生成的 `Serializer` / `Deserializer`，以及扩展方法 | `Nino.Core` 中的 `NinoSerializer` / `NinoDeserializer` |
| 二进制格式 | 按位置 | 默认按位置，所有目标框架产出相同字节；填充字节清零（输出确定） |
| 版本兼容 | 整个项目使用 `WEAK_VERSION_TOLERANCE`，只能在末尾追加 | 每个类型单独设置 `versionTolerant`；可在该类型或任意基类中追加，任意嵌套深度 |
| 键控成员（重新排序 / 删除 / 插入） | 不支持 | `[NinoType(keyed: true)]` |
| 共享引用与循环引用 | 不支持 | `[NinoType(trackReferences: true)]` |
| 反序列化到已有实例 | 不支持 | `Deserialize(data, ref value)`，并回收被丢弃的实例 |
| 对象池 | 不支持 | `[NinoPooled]`、`[NinoRefDeserialization]` 工厂方法、`NinoSettings.SetRecycler<T>` |
| `[NinoType]` 的子类型 | 需要各自标记 `[NinoType]` | 自动继承 |
| 用户集合（`List<T>`、`Dictionary<,>` 等的子类） | 字典子类需要公共索引器 | 无需特性即可支持 |
| `PriorityQueue<,>`、不可变集合 | 不支持 | 支持（.NET 6+；`Nino.Immutable`） |
| 自定义格式化器 | 不支持 | 每个成员 `[NinoCustomFormatter]`，每个类型 `[assembly: NinoFormatter]` |
| 装箱 / 运行时类型 API | 不支持 | `Serialize(object)`、`Deserialize(data, Type)` |
| 诊断 | 生成代码中的编译错误 | 包含 22 条诊断的分析器，许多提供代码修复 |
| 增量生成器 | 否：扫描整个编译，每次修改都重新生成所有类型 | 每个类型一个文件，只重新生成被修改的类型 |
| 拦截器 | 不支持 | Roslyn 4.8+（.NET 8 SDK 及更高版本）上始终开启 |
| 热更新（HybridCLR） | 支持 | 支持，无需初始化调用 |
| Unity | 2022.3+，需手动安装 `Microsoft.CodeAnalysis` | 2022.3+，生成器随包附带 |
| 线程安全 | 内联缓存在高并发下可能出现竞争 | 无锁、写时复制的注册表 |

## 构建时间与生成代码 [#build-time-and-generated-code]

v4 与 v3 的最后一个版本 **3.3.13** 对比。测试使用一个合成程序集：`N` 个抽象根类，每个根类下有 8 层派生类链、一个密封叶子类和一个结构体（共 `N × 11` 个类型），成员包括基元类型、字符串、`List<T>`、`Dictionary<int, string>`、对其他 `[NinoType]` 的引用以及私有字段。Intel Xeon 2.80 GHz，4 核，Ubuntu 24.04，.NET SDK 10.0.402；重点看比例。

<BenchmarkChart chart="compile" lang="zh" table={false} />

<Tabs items={["330 个类型（N = 30）", "1,100 个类型（N = 100）"]}>

<Tab value="330 个类型（N = 30）">

| | v3（3.3.13） | v4 | v4 对比 v3 |
|---|---:|---:|---:|
| 生成的源码 | 18.7 MB（363,233 行） | 1.15 MB（21,679 行） | **小 16 倍** |
| 编译生成的代码（emit） | 56.0 s | 1.27 s | **快 44 倍** |
| 运行生成器 | 1.11 s | 0.14 s | **快 7.9 倍** |
| 修改一个成员后重新生成 | 1.31 s | 0.19 s | **快 6.9 倍** |
| 修改一处注释后重新生成 | 1.11 s | 0.19 s | **快 5.8 倍** |
| 生成代码的 IL | 2.2 MB | 0.37 MB | **小 6.0 倍** |

</Tab>
<Tab value="1,100 个类型（N = 100）">

| | v3（3.3.13） | v4 | v4 对比 v3 |
|---|---:|---:|---:|
| 生成源码 | 62.0 MB（1,204,143 行） | 3.9 MB（72,429 行） | **小 16 倍** |
| 编译生成代码（emit） | 636 秒 | 2.2 秒 | **快 289 倍** |
| 运行生成器 | 5.5 秒 | 0.68 秒 | **快 8.1 倍** |
| 修改成员后重新生成 | 4.1 秒 | 0.57 秒 | **快 7.2 倍** |
| 修改注释后重新生成 | 4.1 秒 | 0.45 秒 | **快 9.0 倍** |
| 生成代码的 IL | 7.3 MB | 1.3 MB | **小 5.6 倍** |

v3 的编译耗时增长远快于类型数量：类型多 3.3 倍，编译耗时多 11 倍（56 秒 → 636 秒）。v4 随类型数量线性增长：每个类型约 3.5 KB 源码和 2 ms 编译时间。

</Tab>
</Tabs>

v3 会把每个子类型的主体内联到每个多态基类中，并在每次修改时重新生成所有类型。v4 每个主体只生成一次，并随类型数量线性增长：每个类型约 3.5 KB 源码和 2 ms 编译时间。在 IDE 中修改一个类型只会重新生成该类型。

## 运行时 [#runtime]

BenchmarkDotNet 0.15.2，.NET 10.0.13。每个比例是把 v4 / MemoryPack 1.21.4 与同一台机器上另一次运行得到的 v3 3.3.13 / MemoryPack 相比；v3 的基准测试没有多态用例。绝对耗时参见[基准测试](/zh/docs/v4/perf)。

<BenchmarkChart chart={['v3-serialize', 'v3-deserialize']} lang="zh" table={false} />

### 序列化 [#serialize]

| 用例 | v4 对比 v3 |
|---|---:|
| `SimpleClass` | **快 1.73 倍** |
| `SimpleClass[100]` | **快 1.29 倍** |
| `SimpleStruct`（`int` + `DateTime`） | **快 1.35 倍** |
| `SimpleStruct[100]` | 持平 |
| `Vector4[10000]` | 持平 |

### 反序列化 [#deserialize]

{/* V3_DESERIALIZE */}

| 用例 | v4 对比 v3 |
|---|---:|
| `SimpleClass` | **快 1.19 倍** |
| `SimpleClass[100]` | **快 1.22 倍** |
| `SimpleStruct[100]` | 持平 |
| `Vector4[10000]` | 0.90 倍（主要耗时在每次调用分配 160 KB 数组） |

{/* /V3_DESERIALIZE */}

类的反序列化主要耗时在分配结果对象上。v4 增加了 v3 做不到的能力：反序列化到已有实例和池化实例，每次调用分配 **0 B**。参见 [v4 新特性](/zh/docs/v4/whats-new)。
