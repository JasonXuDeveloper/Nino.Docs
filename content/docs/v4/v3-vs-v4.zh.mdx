本页从功能、构建时间与生成代码、运行时性能三方面对比 Nino v3 和 v4。升级步骤参见[从 v3 迁移](/zh/docs/v4/migration)。

## 功能 [#features]

| | v3 | v4 |
| --- | --- | --- |
| API | 每个程序集各自生成 `Serializer` / `Deserializer`，外加扩展方法 | `Nino.Core` 中的 `NinoSerializer` / `NinoDeserializer` |
| 二进制格式 | 按位置 | 默认按位置，所有目标框架写出的字节相同；填充字节清零（输出是确定的） |
| 版本容错 | 用 `WEAK_VERSION_TOLERANCE` 对整个项目统一开启，只能在末尾追加 | 每个类型单独设置 `versionTolerant`；可以向最末端的派生类型追加，嵌套多深都可以；旧代码会跳过新成员 |
| 键控成员（调整顺序 / 删除 / 插入） | 不支持 | `[NinoType(keyed: true)]` |
| 共享引用与循环引用 | 不支持 | `[NinoType(trackReferences: true)]` |
| 反序列化到已有实例 | 不支持 | `Deserialize(data, ref value)`，并回收被丢弃的实例 |
| 对象池 | 不支持 | `[NinoPooled]`、`[NinoFactory]` 工厂方法、`NinoSettings.SetRecycler<T>` |
| `[NinoType]` 的子类型 | 需要各自标记 `[NinoType]` | 自动继承 |
| 自定义集合（`List<T>`、`Dictionary<,>` 等的子类） | 字典子类需要公共索引器 | 直接支持，无需特性 |
| `PriorityQueue<,>`、不可变集合 | 不支持 | .NET 6+ 支持 `PriorityQueue<,>`；安装 `Nino.Immutable` 后支持 `ImmutableArray<T>` 和 `ImmutableList<T>` |
| 自定义格式化器 | 不支持 | 针对成员用 `[NinoCustomFormatter]`，针对类型用 `[assembly: NinoFormatter]` |
| 装箱 / 运行时类型 API | 不支持 | `Serialize(object)`、`Deserialize(data, Type)` |
| 诊断 | 生成代码中的编译错误 | 24 条分析器诊断（NINO001–NINO024），许多带代码修复 |
| 增量生成 | 否：每次都扫描整个 Compilation，任何修改都会重新生成全部类型 | 每个类型一个文件，只重新生成改动过的类型 |
| 拦截器 | 不支持 | Roslyn 4.8+（.NET 8 SDK 及以上）下始终开启 |
| 热更新（HybridCLR） | 支持 | 支持，无需初始化调用 |
| Unity | 2022.3+，需手动安装 `Microsoft.CodeAnalysis` | 2022.3+，生成器随包附带 |
| 线程安全 | 内联缓存在高并发下可能出现竞争 | 注册表无锁，采用写时复制 |

## 构建时间与生成代码 [#build-time-and-generated-code]

对比基准是 v3 的最后一个版本 **3.3.13**。测试项目是一个合成程序集：`N` 个抽象根类，每个根类下有 8 层派生类链、一个密封叶子类和一个结构体（共 `N × 11` 个类型），成员包括基元类型、字符串、`List<T>`、`Dictionary<int, string>`、对其他 `[NinoType]` 的引用以及私有字段。Intel Xeon 2.80 GHz，4 核，Ubuntu 24.04，.NET SDK 10.0.402。请看比例，而不是绝对耗时。

<Tab value="330 个类型（N = 30）">

| | v3（3.3.13） | v4 | v4 对比 v3 |
|---|---:|---:|---:|
| 生成源码 | 18.7 MB（363,233 行） | 1.15 MB（21,679 行） | **仅 1/16** |
| 编译生成代码（emit） | 56.0 秒 | 1.27 秒 | **快 44 倍** |
| 运行生成器 | 1.11 秒 | 0.14 秒 | **快 7.9 倍** |
| 修改成员后重新生成 | 1.31 秒 | 0.19 秒 | **快 6.9 倍** |
| 修改注释后重新生成 | 1.11 秒 | 0.19 秒 | **快 5.8 倍** |
| 生成代码的 IL | 2.2 MB | 0.37 MB | **约 1/6** |

</Tab>
<Tab value="1,100 个类型（N = 100）">

| | v3（3.3.13） | v4 | v4 对比 v3 |
|---|---:|---:|---:|
| 生成源码 | 62.0 MB（1,204,143 行） | 3.9 MB（72,429 行） | **仅 1/16** |
| 编译生成代码（emit） | 636 秒 | 2.2 秒 | **快 289 倍** |
| 运行生成器 | 5.5 秒 | 0.68 秒 | **快 8.1 倍** |
| 修改成员后重新生成 | 4.1 秒 | 0.57 秒 | **快 7.2 倍** |
| 修改注释后重新生成 | 4.1 秒 | 0.45 秒 | **快 9.0 倍** |
| 生成代码的 IL | 7.3 MB | 1.3 MB | **约 1/5.6** |

v3 的编译耗时增长远快于类型数量：类型数变为 3.3 倍，编译耗时变为 11 倍（56 秒 → 636 秒）。

</Tab>
</Tabs>

v3 会把每个子类型的代码内联到它的每个多态基类中，每次修改都要重新生成全部类型。v4 每段代码只生成一次，规模随类型数线性增长：每个类型约 3.5 KB 源码、2 毫秒编译时间。在 IDE 中修改一个类型，只会重新生成这个类型。

## 运行时 [#runtime]

Nino v4 与 NuGet 上的 v3 3.3.13 在同一台机器上先后运行。绝对耗时以及与 MemoryPack 的对比参见[基准测试](/zh/docs/v4/perf)。

<BenchmarkChart chart={['v3-serialize', 'v3-deserialize']} lang="zh" />

类的序列化明显更快。反序列化与 v3 持平。反序列化的耗时主要花在分配结果对象上，而 v4 在此之外还要处理引用追踪、复用反序列化和数据校验。带填充字节的结构体数组序列化时慢几纳秒，因为 v4 会把填充字节清零，保证输出是确定的；没有填充的结构体（参见[结构体布局](/zh/docs/v4/performance#struct-layout)）与 v3 一样快。v4 还能做到 v3 做不到的事：反序列化到已有实例或池化实例，每次调用分配 **0 B**。参见 [v4 新特性](/zh/docs/v4/whats-new)。
