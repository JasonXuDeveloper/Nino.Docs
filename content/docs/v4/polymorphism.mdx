Nino serializes the runtime type of a value, so a value declared as a base class or interface is read back as the type it really is. This is what you need for the event history of an event-sourced order, the shapes of a drawing, or the messages of a network protocol: one declared type, many concrete ones.

```csharp title="OrderEvents.cs"
[NinoType] // [!code highlight]
public abstract class OrderEvent
{
    public long OrderId;
    public DateTime At;
}

public sealed class OrderPlaced : OrderEvent   // inherits [NinoType]
{
    public decimal Total;
}

public sealed class OrderShipped : OrderEvent
{
    public string Carrier;
}

public sealed class OrderCancelled : OrderEvent { }
```

```csharp
var history = new List<OrderEvent>
{
    new OrderPlaced { OrderId = 7, Total = 40m },
    new OrderCancelled { OrderId = 7 },
};
byte[] bytes = NinoSerializer.Serialize(history);
List<OrderEvent> events = NinoDeserializer.Deserialize<List<OrderEvent>>(bytes);
// events[0] is an OrderPlaced, events[1] is an OrderCancelled
```

<Callout type="info">

In v4, subtypes **inherit** `[NinoType]` (including its options) from their nearest `[NinoType]` base class or interface, unless the base sets `allowInheritance: false`. You can still put `[NinoType]` on a subtype to give it its own options.

</Callout>

## Interfaces and Abstract Classes

Interfaces and abstract classes work the same way. Mark the interface or abstract class with `[NinoType]`; implementing classes and structs inherit it:

<Tabs items={["Interface example", "Abstract class example"]}>

<Tab value="Interface example">

```csharp
[NinoType] // [!code highlight]
public interface IBase
{
    int A { get; set; }
}

public class Impl : IBase
{
    public int A { get; set; }
}

public struct ImplStruct : IBase
{
    public int A { get; set; }
}
```

</Tab>

<Tab value="Abstract class example">

```csharp
[NinoType] // [!code highlight]
public abstract class Base
{
    public int A { get; set; }
}

public class Derived : Base
{
    public int B { get; set; }
}
```

</Tab>
</Tabs>

A `[NinoType]` interface serializes its own members through the implementing type's members of the same name. A struct read through a member declared as an interface or `object` is boxed.

## How a Polymorphic Value Is Written

The header (the null flag or type id before the value) depends on the **declared** type of the slot (a member, a collection element, or the type argument of your `Serialize<T>`/`Deserialize<T>` call):

| Declared type | Header | Polymorphic |
| --- | --- | :---: |
| `struct` | none | no |
| `sealed class` | 1 byte null flag | no |
| non-sealed class, abstract class, interface | 4-byte type id (`0` = null) | yes |
| `object` | 4-byte type id | yes, any `[NinoType]` |

The type id is the FNV-1a hash of the runtime type's full name, computed by the generator, so there are no tags to assign and nothing to keep in sync between assemblies. Rename or move a type with [`[NinoFormerName]`](/en/docs/v4/defining-types#former-name).

<Callout type="idea">

Seal classes that have no subtypes. A sealed class costs 1 byte and no dispatch; a non-sealed one costs 4 bytes and a type check, even when no subtype exists.

</Callout>

### Inspecting Type Ids

`NinoTypeId` computes the same ids at run time, for logging, protocol checks or a handshake that compares message sets between peers:

```csharp
int id = NinoTypeId.Of(typeof(OrderShipped));               // the id OrderShipped is written with ([NinoFormerName] honored)
string name = NinoTypeId.GetName(typeof(OrderShipped));     // its runtime-form name, e.g. "MyApp.Events.OrderShipped"
string hashed = NinoTypeId.GetIdName(typeof(OrderShipped)); // the name the id is computed from: its [NinoFormerName], if any
int same = NinoTypeId.Compute(hashed);                      // == id: the hash of a runtime-form name
```

Ids are never `0`, which encodes `null`.

## Dispatch

Nino uses hybrid dispatch:

- **Generated dispatch** for subtypes declared in the same assembly as their base: writing is a chain of exact type checks and reading is a `switch` on the type id, and both call the subtype's formatter directly.
- **A lock-free registry** for everything else: subtypes in other assemblies, closed generic types, tracked types, and writes in hierarchies with more than 64 subtypes (reading still uses the generated `switch`).

When reading, Nino checks that the type in the data really derives from the declared type; data that names an unrelated type throws instead of being stored.

## Dispatching Through a Common Base [#dispatching-through-a-common-base]

For RPC or message dispatch, plugin systems and editor tooling, give the types a common `[NinoType]` base class or interface, and serialize and deserialize through it with `Serialize<TBase>` / `Deserialize<TBase>`. The type id is written and dispatched on by generated code, which is faster than the alternatives below, and it works with [reuse deserialization](#reuse-deserialization) and `[NinoPooled]`, so a receive loop allocates nothing but strings whose text changed. For a complete example, see [Network Layer](/en/docs/v4/advanced/networking).

```csharp
[NinoType]
public interface ICommand { }

public sealed class CreateUser : ICommand { public string Name; }   // implementations inherit [NinoType]
public sealed class DeleteUser : ICommand { public int UserId; }

public sealed class CommandChannel
{
    private readonly Socket _socket;
    private readonly NinoArrayBufferWriter _buffer = new(); // reused for every message

    public CommandChannel(Socket socket) => _socket = socket;

    public void Send(ICommand command)
    {
        _buffer.ResetWrittenCount();
        NinoSerializer.Serialize<ICommand>(command, _buffer); // the type id, then the command
        _socket.Send(_buffer.WrittenSpan);
    }

    // Fills `command` in place when the data holds the same type, else replaces (and recycles) it
    public void Receive(ReadOnlySpan<byte> message, ref ICommand command) =>
        NinoDeserializer.Deserialize(message, ref command); // [!code highlight]
}
```

Two alternatives exist, and both are slower:

- **`object` as the declared type** (a member, element or `Serialize<object>` call): only `[NinoType]` values are accepted, a type id is written, and reading dispatches through the global registry of every `[NinoType]` instead of the generated dispatch of one base. Prefer the common base.
- **The [boxed API](/en/docs/v4/basic#the-boxed-api)** (`SerializeBoxed` / `DeserializeBoxed` with a `Type`): finds the formatter by `Type` and boxes value types. Use it only when the type is known only at run time, as a `Type`, and the types share no common `[NinoType]` base, as in reflection-driven tooling over arbitrary types.

## Subtypes in Other Assemblies

Subtypes are found automatically wherever they are declared, including assemblies loaded later (plugins, HybridCLR hot-update DLLs): when a type id is unknown, Nino looks in the registries of newly loaded assemblies before it fails. There is no registration call. For example, a plugin or hot-update DLL adds `public sealed class OrderRefunded : OrderEvent`. Once the DLL is loaded, the code in the main (AOT) assembly reads a `List<OrderEvent>` that contains an `OrderRefunded`, with no change to that code. The generator must run in the subtype's assembly too (install the `Nino` package in that project; in Unity, its assembly must reference `Nino.Core`); an id whose type is in no loaded assembly throws `InvalidOperationException`.

The one exception is a closed generic subtype (`Box<int>`) that the process only **reads**, and never names in code or writes. Register it at startup:

```csharp
NinoPolymorphic.Register<Box<int>>();
```

`NinoPolymorphic.Register(Type)` does the same for a type you only have as a `Type` (one built with `MakeGenericType`, for example). Both return `false` for a type that cannot be written polymorphically: an abstract or open generic type, or a type that is not a `[NinoType]`.

## Opting Out

`[NinoType(allowInheritance: false)]` stops subtypes from inheriting the attribute: they are not serializable through the base unless they declare `[NinoType]` themselves (NINO003, with a code fix).

## Reuse Deserialization

When you deserialize into an existing value whose runtime type differs from the type in the data, the old instance is dropped (and recycled, see [pooling](/en/docs/v4/pooling)) and a new one of the right type is created. When the types match, the instance is filled in place.
