安装 Nino，给类型加上 `[NinoType]`，然后序列化。不需要注册，也不需要初始化。

## 安装 [#installation]

<AnchorRedirect map={{ 'installation-details': '/zh/docs/v4/start#installation' }} />

<Tabs groupId="platform" persist items={['.NET', 'Unity', 'Godot']}>
<Tab value=".NET" id="net-project" forceMount>

环境要求：

- **运行时**：能引用 .NET Standard 2.0 库的项目都能用。`Nino.Core` 的目标框架是 `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0`，各目标框架字节一致。
- **编译器**：源生成器需要 Roslyn 4.3 及以上（Visual Studio 2022 17.3+、Rider，或 .NET 6.0.400 及以上的 SDK）。
- **语言版本**：C# 9 及以上（生成的代码用到了 C# 9）。较老的 .NET Framework 项目默认是 C# 7.3，需要设置 `<LangVersion>9</LangVersion>` 或更高。

<Steps>
<Step>

**添加包。** 在 Visual Studio 或 Rider 的 NuGet 包管理器中勾选**包括预发行版**，搜索 `Nino` 并安装。也可以：

```shell tab="dotnet 命令行"
dotnet add package Nino --prerelease
```

```xml tab=".csproj"
<ItemGroup>
  <PackageReference Include="Nino" Version="%NINO_VERSION%" />
</ItemGroup>
```

<Callout type="info">

Nino v4 目前仍是预发行版，所以必须加 `--prerelease`（或勾选**包括预发行版**）。不加的话，NuGet 会装上最新的稳定版 3.9.x：那是试验 v4 功能的过渡版本，读写不了 v4 的数据。

</Callout>

</Step>
<Step>

**构建。** `Nino` 会带上运行时库（`Nino.Serialization`，即 `Nino.Core.dll`）和源生成器（`Nino.Generator`，含分析器和代码修复），两个都不能少。用 .NET 8 SDK 及以上版本编译时，编译期能确定类型的调用会直接走生成的代码（[拦截器](/zh/docs/v4/performance#interceptors)），字节不变。

</Step>
<Step>

**序列化一个类型**：见下文[第一次序列化](#first-serialization)。

</Step>
</Steps>

<Accordions>
<Accordion title="可选包" id="optional-packages" value="optional-packages">

安装方式相同，同样要加 `--prerelease`：

| 包 | 作用 |
|---|---|
| `Nino.Immutable` | `System.Collections.Immutable` 的格式化器，从 `ImmutableArray<T>` 到 `ImmutableSortedDictionary<TKey, TValue>`（[不可变集合](/zh/docs/v4/types#immutable-collections)） |
| `Nino.AspNetCore` | 在 ASP.NET Core 中读写请求体和响应体：`application/x-nino` 的 MVC 格式化器与 Minimal API 请求体（[ASP.NET Core](/zh/docs/v4/advanced/aspnetcore)） |
| `Nino.Codegen` | 每次构建后，把你的类型及其编解码器写成 TypeScript、Go 或 Rust（[在其他语言中使用](/zh/docs/v4/advanced/codegen)） |

</Accordion>
</Accordions>

<Tab value="Unity" id="unity-project" forceMount>

环境要求：Unity 2022.3 及以上，所有 Player 平台（Mono 和 IL2CPP）都支持。

<Steps>
<Step>

**从 [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/#modal-manualinstallation) 添加包**：用 openupm 命令行，或者把它的作用域注册表和包名合并进 `Packages/manifest.json`：

```shell tab="openupm 命令行"
# 在 Unity 项目文件夹中运行（先安装 openupm-cli：npm install -g openupm-cli）
openupm add com.jasonxudeveloper.nino
```

```json tab="Packages/manifest.json"
{
  "scopedRegistries": [
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["com.jasonxudeveloper.nino"]
    }
  ],
  "dependencies": {
    "com.jasonxudeveloper.nino": "%NINO_OPENUPM_VERSION%"
  }
}
```

%NINO_VERSION% 在 Unity 里对应 %NINO_OPENUPM_VERSION%（见下方 [OpenUPM 版本号](#openupm-versions)）。

</Step>
<Step>

**等 Unity 导入完成。** 包里自带 `Nino.Core.dll`、源生成器（`Nino.Generator.dll`，已标记为 `RoslynAnalyzer`）和 `Nino.UnityTypes.dll`（[Unity 的 `AnimationCurve`、`Gradient` 和 `RectOffset`](/zh/docs/v4/advanced/unity#unity-classes) 的格式化器），不用再装别的。这里的源生成器是 Roslyn 4.3 版本，对应 Unity 支持的最低编译器版本，所以 Unity 中的调用不会被[拦截](/zh/docs/v4/performance#interceptors)，而是走常规路径，字节一致。

</Step>
<Step>

**序列化一个类型**：见下文[第一次序列化](#first-serialization)。Unity 基于 .NET Standard 编译，没有 `[UnsafeAccessor]`，所以序列化非公开成员（或使用 `[NinoPooled]`）的类型必须声明为 `partial`，外层的每个类型也一样。分析器会报 NINO002，在 Rider 或 Visual Studio 中用它的代码修复就能加上 `partial`。

</Step>
</Steps>

<Accordions type="multiple">
<Accordion title="OpenUPM 版本号" id="openupm-versions" value="openupm-versions">

OpenUPM 无法给预发行版标签排序，所以每个候选版本在 OpenUPM 上发布为 `4.0.0-preview.(200 + N)`：NuGet 和本文档里的 rc.N，在 Unity Package Manager 里就是 preview.(200 + N)。比如 rc.10 就是 preview.210。

OpenUPM 上低于 preview.200 的 alpha 和 beta 预览版是更早的 v4 测试版本，请使用 rc。

</Accordion>
<Accordion title="程序集定义（asmdef）" id="asmdef" value="asmdef">

用了 `asmdef` 的话，请确认勾选了 `Auto Referenced`；如果开启了 `Override References`，要手动添加对 `Nino.Core.dll` 的引用。

</Accordion>
<Accordion title="热更新代码（HybridCLR）" id="hot-update-code" value="hot-update-code">

- Nino 支持 **HybridCLR**。生成的注册表要等到其中某个类型第一次用到时才加载，所以用 `Assembly.Load` 加载的热更新程序集**不需要任何初始化调用**。详见 [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity#hybridclr-hot-update)。
- 热更新代码可以放在 Unity 的 `asmdef` 里，也可以放在从 NuGet 安装 Nino 的独立 C# 项目中（见 [.NET](#net-project)），编译出的 DLL 照常交给 HybridCLR 即可。

</Accordion>
<Accordion title="示例项目与排查问题" id="unity-sample" value="unity-sample">

GitHub 上的 `Nino.Unity` 示例项目演示了 Nino 在 Unity 中的用法，还附带能在 Test Runner 中运行的单元测试。遇到问题时，先确认这个示例项目能正常运行；问题依旧的话，请到 GitHub 提交 issue。

</Accordion>
</Accordions>

<Tab value="Godot" id="godot-project" forceMount>

环境要求：Godot 4 的 .NET 版（支持 C# 的版本）。它的 C# 项目就是普通的 .NET 项目，用 `Godot.NET.Sdk` 构建（Godot 4.4 起目标框架为 .NET 8，4.0–4.3 为 .NET 6），所以 Nino 的安装方式和其他 NuGet 包相同。

<Steps>
<Step>

**添加包**，和 [.NET](#net-project) 一样要加 `--prerelease`：

```shell
# 在 Godot 项目 .csproj 所在的文件夹中
dotnet add package Nino --prerelease
```

</Step>
<Step>

**构建项目**：用 Godot 的 **Build** 按钮、IDE 或 `dotnet build` 都行。源生成器和分析器与在其他 .NET 项目中一样生效，用 .NET 8 及以上的 SDK 构建时[拦截器](/zh/docs/v4/performance#interceptors)也会生效。

</Step>
<Step>

**序列化一个类型**：见下文[第一次序列化](#first-serialization)。Godot 的数学结构体按原始内存拷贝，`Node`、`Resource` 等引擎对象则不序列化。哪些类型需要声明 `partial`、双精度构建要注意什么，以及存档和联网，参见 [Godot](/zh/docs/v4/advanced/godot)。

</Step>
</Steps>

## 第一次序列化 [#first-serialization]

源生成器会在编译期为每个 `[NinoType]` 生成**格式化器**，也就是读写这个类型的代码。你只需要调用 `NinoSerializer` 和 `NinoDeserializer`（命名空间 `Nino.Core`）：

<Steps>
<Step>

### 给类型加上 `[NinoType]` [#mark-a-type-with-ninotype]

```csharp title="UserProfile.cs"
using System;
using Nino.Core;

[NinoType]
public class UserProfile
{
    public long Id;
    public string Name;
    public DateTime LastLogin;
}
```

把类型放在单独的文件里。如果想写在控制台程序的 `Program.cs` 里，就放在顶级语句之后：C# 要求类型声明出现在顶级语句后面（否则报 CS8803）。

</Step>
<Step>

### 序列化 [#serialize-it]

```csharp title="Program.cs"
using System;
using Nino.Core;

var data = new UserProfile { Id = 42, Name = "Ada", LastLogin = DateTime.UtcNow };
byte[] bytes = NinoSerializer.Serialize(data);
```

这会分配返回的数组。热路径上请序列化到一个长期保留的缓冲区，这样完全不分配内存，参见[复用缓冲区](/zh/docs/v4/basic#reusing-a-buffer)。

</Step>
<Step>

### 反序列化 [#deserialize-it]

```csharp
UserProfile restored = NinoDeserializer.Deserialize<UserProfile>(bytes);
Console.WriteLine($"{restored.Id} {restored.Name}"); // 42 Ada
```

参数是 `ReadOnlySpan<byte>`，所以池化数组或网络缓冲区的切片也能直接传进去，不用拷贝。

</Step>
<Step>

### 或者反序列化到已有对象 [#or-deserialize-into-an-object-you-already-have]

用 `ref` 传入已有实例，Nino 把数据读入这个实例，并复用其中的嵌套对象和集合；传入 `null` 则创建新实例：

```csharp
byte[] newBytes = NinoSerializer.Serialize(new UserProfile { Id = 42, Name = "Ada Lovelace" });

UserProfile current = null;
NinoDeserializer.Deserialize(bytes, ref current);    // 创建实例
NinoDeserializer.Deserialize(newBytes, ref current); // 填充同一个实例
```

</Step>
</Steps>

<Callout type="info">

后面各页的例子默认已经有 `using Nino.Core;`（也可以在项目里写一次 `global using Nino.Core;`），并且省略了可空注解。新建的 .NET 项目默认开启可空引用类型，照抄会看到 CS8618、CS8600 之类的警告：想消除警告，写成 `string? Name`、`UserProfile? current = null` 即可。两种写法下 Nino 的字节一致。

</Callout>

## 启动时 [#at-startup]

Nino 不需要任何初始化调用：生成的代码会自行注册，之后加载的程序集，第一次用到时 Nino 也会自己找到。下面三项调用都是可选的：

- `NinoSettings`（池大小、回收器、[不可信数据的限制](/zh/docs/v4/security#limits)），在第一次序列化调用之前设置。全部设置见[设置](/zh/docs/v4/settings)。
- `NinoPolymorphic.TryRegister<T>()`：某个封闭泛型 `[NinoType]` 只会通过基类型读取、代码里从没写出过它的名字时，用它来注册。
- `NinoRegistry.EnsureInitialized(assembly)`：立即加载某个插件的注册表，而不是等到第一次用到时。

自定义格式化器也不需要调用任何方法：它们用特性声明（参见[自定义格式化器](/zh/docs/v4/custom-formatters)）。Unity 和 HybridCLR 项目请参见[启动检查清单](/zh/docs/v4/advanced/unity#startup-checklist)。
