安装 Nino，给类型加上 `[NinoType]`，然后序列化。不需要注册，也不需要初始化。

<Callout type="idea">

第一次接触 v4，或者正从 v3 升级？请先看 [v4 新特性](/zh/docs/v4/whats-new)和[迁移指南](/zh/docs/v4/migration)。v4 的二进制格式与 v3 以及更早的 v4 beta 版本**不兼容**。

</Callout>

## 安装 [#installation]

<Tabs groupId="platform" persist items={['.NET', 'Unity', 'Godot']}>
<Tab value=".NET">

```shell
dotnet add package Nino
```

详见 [.NET 项目](#net-project)。

</Tab>
<Tab value="Unity">

```shell
openupm add com.jasonxudeveloper.nino
```

详见 [Unity 项目](#unity-project)。

</Tab>
<Tab value="Godot">

```shell
# in the folder with your Godot project's .csproj
dotnet add package Nino
```

详见 [Godot 项目](#godot-project)。

</Tab>
</Tabs>

### .NET 项目 [#net-project]

<Callout type="info">

运行时（`Nino.Core`）的目标框架是 `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0`，凡是能引用 .NET Standard 2.0 库的项目都能用。所有目标框架写出的字节完全相同。

源生成器需要 Roslyn 4.3 及以上的编译器（Visual Studio 2022 17.3+、Rider，或 .NET 6.0.400 及以上的 SDK）。生成的代码用到了 C# 9 特性，所以项目的 `LangVersion` 至少要是 9。较老的 .NET Framework 项目默认是 C# 7.3，需要设置 `<LangVersion>9</LangVersion>` 或更高。

</Callout>

- 在 Visual Studio 或 Rider 的 NuGet 包管理器中搜索 `Nino` 并安装；
- 或者使用 `dotnet` 命令行：
    ```shell
    dotnet add package Nino
    # Optional: ImmutableArray<T> / ImmutableList<T> support
    dotnet add package Nino.Immutable
    ```

<Callout type="info">

`Nino` 包会引入以下两个包，缺一不可：
- `Nino.Serialization`：运行时库（`Nino.Core.dll`）
- `Nino.Generator`：源生成器、分析器和代码修复

`Nino.Immutable` 是可选包，为 `ImmutableArray<T>` 和 `ImmutableList<T>` 提供格式化器。

</Callout>

<Callout type="idea">

使用 .NET 8 SDK 及以上版本编译时，类型已知的 `NinoSerializer`/`NinoDeserializer` 调用会在编译期直接改为调用生成的格式化器（拦截器）。这是自动完成的，参见[拦截器](/zh/docs/v4/performance#interceptors)。

</Callout>

### Unity 项目 [#unity-project]

<Callout type="info">

Nino 支持 Unity 2022.3 及以上版本，支持所有 Player 平台（Mono 和 IL2CPP）。

GitHub 上的 `Nino.Unity` 示例项目演示了 Nino 在 Unity 中的用法，并附带一套可在 `TestRunner` 中运行的单元测试。

</Callout>

用 Unity Package Manager 从 [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/#modal-manualinstallation) 安装，例如：

```shell
openupm add com.jasonxudeveloper.nino
```

包里同时带有 `Nino.Core.dll` 和源生成器（`Nino.Generator.dll`，已标记为 `RoslynAnalyzer`），不需要再装别的东西。这是源生成器的 Roslyn 4.3 版本，对应 Unity 支持的最低编译器版本，所以 Unity 中的调用不会被[拦截](/zh/docs/v4/performance#interceptors)，而是走常规路径，写出的字节完全相同。

<Callout type="warn">

如果用了 `asmdef`，请确认勾选了 `Auto Referenced`；如果开启了 `Override References`，则要手动添加对 `Nino.Core.dll` 的引用。

</Callout>

<Callout type="info">

Unity 基于 .NET Standard 编译，没有 `[UnsafeAccessor]`。因此，序列化非公开成员（或使用 `[NinoPooled]`）的类型必须声明为 `partial`，包含它的外层类型也一样。分析器会报告 NINO002 并提供修复。

</Callout>

<Callout type="idea">

遇到问题时，先确认 `Nino.Unity` 示例项目能正常运行。如果问题依旧，请到 GitHub 提交 issue。

</Callout>

#### 热更新代码 [#hot-update-code]
- Nino 支持 **HybridCLR**。生成的注册表会在其中某个类型第一次用到时才加载，所以用 `Assembly.Load` 加载的热更新程序集**不需要任何初始化调用**。详见 [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity#hybridclr-hot-update)。
- 热更新代码可以放在 Unity 的 `asmdef` 里，也可以放在通过 NuGet 安装 Nino 的独立 C# 项目中（[见上文](#net-project)），编译出的 DLL 照常交给 HybridCLR 使用即可。

### Godot 项目 [#godot-project]

Godot 4 的 C# 项目（Godot 的 .NET 版）就是普通的 .NET 项目，用 `Godot.NET.Sdk` 构建，目标框架是 .NET 8，所以像其他 NuGet 包一样安装即可：

```shell
# in the folder with your Godot project's .csproj
dotnet add package Nino
```

然后构建项目（Godot 的 **Build** 按钮、IDE 或 `dotnet build` 均可）。

- 项目由 .NET 8+ SDK 编译，源生成器、分析器和[拦截器](/zh/docs/v4/performance#interceptors)都会生效。
- .NET 8 有 `[UnsafeAccessor]`，所以序列化私有成员时类型不必声明为 `partial`（泛型类型除外）。
- Godot 的数学结构体（`Vector2`、`Vector3`、`Quaternion`、`Transform3D`、`Color` 等）都是非托管类型，和其他非托管结构体一样按原始内存拷贝。
- 要序列化的是你自己的数据类和结构体。`Node`、`Resource` 等 Godot 对象是引擎对象而不是数据，Nino 不会序列化它们。

详见[平台](/zh/docs/v4/platforms#godot)。

## 第一次序列化 [#first-serialization]

源生成器会在编译期为每个 `[NinoType]` 生成格式化器，你只需要调用 `NinoSerializer` 和 `NinoDeserializer`（命名空间 `Nino.Core`）：

<Steps>
<Step>

### 给类型加上 `[NinoType]` [#mark-a-type-with-ninotype]

```csharp
using Nino.Core;

[NinoType]
public class UserProfile
{
    public long Id;
    public string Name;
    public DateTime LastLogin;
}
```

</Step>
<Step>

### 序列化 [#serialize-it]

```csharp
var data = new UserProfile { Id = 42, Name = "Ada", LastLogin = DateTime.UtcNow };
byte[] bytes = NinoSerializer.Serialize(data);
```

</Step>
<Step>

### 反序列化 [#deserialize-it]

```csharp
UserProfile restored = NinoDeserializer.Deserialize<UserProfile>(bytes);
```

</Step>
<Step>

### 或者反序列化到已有对象 [#or-deserialize-into-an-object-you-already-have]

用 `ref` 传入已有实例，Nino 会原地填充它，并复用其中的嵌套对象和集合；传入 `null` 则创建新实例：

```csharp
UserProfile current = null;
NinoDeserializer.Deserialize(bytes, ref current);    // creates the instance
NinoDeserializer.Deserialize(newBytes, ref current); // fills the same instance
```

</Step>
</Steps>

## 启动时 [#at-startup]

Nino 不需要任何初始化调用：生成的代码会自行注册，之后加载的程序集在第一次用到时也会被找到。以下四项调用是可选的：

- `NinoSettings`（池大小、回收器），在第一次序列化调用之前设置。
- `NinoPolymorphic.Register<T>()`：用于这样的封闭泛型 `[NinoType]`：进程只通过基类型读取它，代码里从来没写过它的名字。
- `NinoRegistry.EnsureInitialized(assembly)`：立即加载某个插件的注册表，而不是等到第一次用到时。
- `NinoFormatterCache<T>.Register<TFormatter>()`：注册运行时选定的格式化器。必须在 `T` 第一次序列化或反序列化之前调用，之后再注册会抛出异常。参见[运行时注册](/zh/docs/v4/custom-formatters#registering-at-run-time)。

Unity 和 HybridCLR 项目请参见[启动检查清单](/zh/docs/v4/advanced/unity#startup-checklist)。
