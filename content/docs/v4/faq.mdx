Short answers to the questions people ask most about Nino, each with a link to the full page.

## What is Nino?

Nino is a high-performance binary serializer for C# and .NET. You mark a type with `[NinoType]`, and a Roslyn source generator writes its serialization code at compile time; at run time you call `NinoSerializer.Serialize` and `NinoDeserializer.Deserialize`. There is no reflection, no runtime code generation, no schema file and no registration step. Nino is open source under the MIT license: [github.com/JasonXuDeveloper/Nino](https://github.com/JasonXuDeveloper/Nino). See [Introduction](/en/docs/v4).

## How do I install Nino?

In a .NET or Godot project, run `dotnet add package Nino`; the `Nino` package brings in the runtime (`Nino.Serialization`) and the source generator (`Nino.Generator`). In Unity, install `com.jasonxudeveloper.nino` from OpenUPM (`openupm add com.jasonxudeveloper.nino`), which includes the generator. See [Quick Start](/en/docs/v4/start).

## Which platforms and .NET versions does Nino support?

The runtime targets `netstandard2.0`, `netstandard2.1`, `net8.0` and `net10.0`. Nino runs on .NET servers and desktop apps, Unity 2022.3 and later (Mono and IL2CPP, every player platform), Godot 4 .NET projects and HybridCLR hot update, and every target writes identical bytes. The generator needs Roslyn 4.3 or later and the project must use C# 9 or later. See [Platforms and Binary Format](/en/docs/v4/platforms).

## Does Nino use reflection? Does it work with IL2CPP and NativeAOT?

No reflection: the generator writes one formatter per type at compile time, so Nino works under IL2CPP, NativeAOT and HybridCLR, where runtime code generation is unavailable. See [Performance Guide](/en/docs/v4/performance).

## How fast is Nino compared with MemoryPack?

In the same benchmark run, Nino v4 serializes up to <BenchValue k="serialize.max" /> faster than MemoryPack and deserializes classes and polymorphic graphs up to <BenchValue k="deserialize.max" /> faster; on raw struct arrays the two are close. Serializing into a reused buffer allocates nothing. See [Benchmarks](/en/docs/v4/perf) and [Nino vs MemoryPack](/en/docs/v4/vs-memorypack).

## What can I use Nino for?

Anything that turns .NET objects into compact bytes and back: network protocols and RPC between services, message queues and event streams, caches, files and other persistent storage, inter-process communication, and data pipelines. The same code runs on .NET servers, desktop apps, Unity and Godot. See [Advanced Guides](/en/docs/v4/advanced).

## Can I change my types after data has been written?

Yes, if you choose a format for it. A plain `[NinoType]` is positional and the fastest. `[NinoType(format: NinoFormat.VersionTolerant)]` lets you append members, and `[NinoType(format: NinoFormat.Keyed)]` lets you add, remove and reorder members. See [Evolving Your Data](/en/docs/v4/evolving-data).

## Does Nino support polymorphism and shared references?

Yes. A value declared as a base class or interface is read back as its runtime type, with no union tags to maintain. Reference tracking, enabled per type, preserves shared references and cycles. See [Polymorphism](/en/docs/v4/polymorphism) and [Reference Tracking](/en/docs/v4/reference-tracking).

## How do I serialize many message types, or a type known only at run time?

Give the types a common `[NinoType]` base class or interface and call `Serialize<TBase>` / `Deserialize<TBase>`: generated code writes the type id and dispatches on it, it is the fastest option, and it works with reuse deserialization and pooling for 0 B per message. This covers RPC and message dispatch, plugin systems and editor tooling. Only when the type is known only as a `Type` and the types share no common base (reflection-driven tooling over arbitrary types), use `SerializeBoxed(value, type)` and `DeserializeBoxed(data, type)`. Avoid `object` as the type argument: it accepts only `[NinoType]` values and dispatches through a slower global registry. See [Runtime Types](/en/docs/v4/basic#runtime-types).

## Is Nino thread safe?

Yes. `NinoSerializer` and `NinoDeserializer` are static and can be called from any number of threads without locking. A `NinoArrayBufferWriter` that you create yourself is not thread safe: use one per thread or per connection. See [Serialize and Deserialize](/en/docs/v4/basic).

## Can Nino v4 read data written by Nino v3?

No. v4 has a new binary format and cannot read data written by v3 or by the v4 betas and previews, so stored v3 data has to be converted once. See [Migrating from v3](/en/docs/v4/migration).

## When should I not use Nino?

When people need to read or edit the data (use JSON, YAML or TOML), or when a program in another language must read it: the format is defined by your C# types, with no schema file and no generator for other languages, so use Protocol Buffers, FlatBuffers or MessagePack for that. See [Limitations](/en/docs/v4/limit).
