[System.Text.Json](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/overview) is the JSON serializer built into .NET. JSON is text and describes itself: people read and edit it, browsers and every language parse it without your types, and ASP.NET Core speaks it by default. Nino writes binary that only your C# types, or the TypeScript, Go and Rust [nino-gen](/en/docs/v4/advanced/codegen) generates from them, can read, in exchange for speed, size and features JSON has no form for. This page compares Nino v4 with System.Text.Json on .NET 10, using Microsoft's documentation for its features and Nino's source for Nino's. Where we could not verify a feature, it is left out. How all the libraries compare is on [Choosing a Serializer](/en/docs/v4/compare).

## Two Formats [#formats]

| | Nino v4 | System.Text.Json |
| --- | --- | --- |
| A value | its bytes only | text: a number, a string, `true`, `false`, `null`, an array or an object |
| An object | its members one after another; with [`NinoFormat.Keyed`](/en/docs/v4/evolving-data#keyed-members), a key and a length per member (8 bytes) | `{ "name": value, ... }`, every property under its name |
| A subtype | a 4-byte type id, a hash of the type's name | a `$type` property holding the discriminator you gave the subtype |
| Integers and floats | at their full width (an `int` is 4 bytes) | decimal digits |
| Strings | one byte a char when every char is at most U+00FF, else UTF-16; UTF-8 with [`[NinoUtf8]`](/en/docs/v4/defining-types#string-encoding) | UTF-8 text in quotes; the default encoder escapes non-ASCII chars as `\uXXXX` |
| `byte[]` | a length and the bytes | a Base64 string |
| `Guid`, `DateTime` | 16 bytes; ticks and kind | a 36-character string; an ISO 8601 string |

## Performance [#performance]

Measured with BenchmarkDotNet in the same run as Nino, on the same values and the same types. System.Text.Json runs with its source generator (a `JsonSerializerContext`), writing UTF-8 through a reused `Utf8JsonWriter` into an `ArrayBufferWriter<byte>` and reading from the UTF-8 bytes ([setup](/en/docs/v4/benchmarks#workloads)). <IfWorkloads>On the [real workloads](/en/docs/v4/benchmarks#workloads) where Nino leads, it serializes <BenchValue k="workloads.json.serialize" /> faster and deserializes <BenchValue k="workloads.json.deserialize" /> faster.</IfWorkloads> System.Text.Json runs the workloads and the basic, polymorphism and nullable groups.

## Untrusted Input [#untrusted-input]

System.Text.Json has no separate mode for untrusted data. Its polymorphism reads only the derived types declared on the base, so a payload cannot name a type to create, it refuses `System.Type`, and `JsonSerializerOptions.MaxDepth` bounds nesting (64 by default). Bound the size of a request at the host, such as Kestrel's `MaxRequestBodySize`.

Nino reads untrusted data in its default mode; [`NinoSettings.Untrusted`](/en/docs/v4/security#untrusted-mode) adds the checks that cost time on every read.

## Where System.Text.Json Is Ahead [#where-system-text-json-is-ahead]

System.Text.Json does these things and Nino v4 does not:

- **People read and edit the data.** Configuration, logs, test fixtures and API responses you look at in a browser stay readable without a tool.
- **Every language reads it**, without generated code: browsers, scripts and services that have never seen your types parse JSON.
- **Built into .NET**, with no package to add on .NET Core 3.0 and later, and the default format of ASP.NET Core and `HttpClient`'s JSON extensions.
- **Reading without types.** `JsonDocument` reads a document as a read-only tree and `JsonNode` as one you can change, so code can pick out one value without a type for the whole payload.
- **Options per call**, with `JsonSerializerOptions`, and naming policies such as camelCase.
- **A schema for other tools.** .NET 9 and later export a JSON schema of a type with `JsonSchemaExporter`.

The workaround for what Nino leaves out is on [Limitations](/en/docs/v4/compare#limitations). Which to choose for which job: [Which to Choose](/en/docs/v4/compare#which-to-choose).

## Switching from System.Text.Json [#switching-from-system-text-json]

The two often live side by side: keep JSON where people or other languages read the data, and use Nino between your own .NET programs, Unity clients and the languages nino-gen covers. In ASP.NET Core, [Nino.AspNetCore](/en/docs/v4/advanced/aspnetcore) adds `application/x-nino` next to JSON, so a client chooses with its `Content-Type` and `Accept` headers.

| System.Text.Json | Nino |
| --- | --- |
| `[JsonSerializable(typeof(T))]` on a `JsonSerializerContext` | `[NinoType]` on `T`: the generator finds the types, with no context to list them in |
| public properties by name | public fields and properties in declaration order ([Defining Types](/en/docs/v4/defining-types)); `[NinoType(format: NinoFormat.Keyed)]` for members by name ([Keyed Members](/en/docs/v4/evolving-data#keyed-members)) |
| `[JsonPropertyName("old")]` to keep a name after a rename | `[NinoFormerName("old")]` on a keyed member; a positional member renames freely |
| `[JsonIgnore]` | `[NinoIgnore]` |
| `[JsonInclude]` on a non-public member | `[NinoType(includeNonPublicMembers: true)]`, or `[NinoType(false, true)]` with `[NinoMember(index)]` on each member to write |
| `[JsonConstructor]` | `[NinoConstructor]` ([Constructors](/en/docs/v4/constructors)) |
| `[JsonPolymorphic]` and a `[JsonDerivedType]` per subtype | `[NinoType]` on the base: subtypes inherit it, with nothing listed ([Polymorphism](/en/docs/v4/polymorphism)) |
| `ReferenceHandler.Preserve` | `[NinoType(trackReferences: true)]` ([Reference Tracking](/en/docs/v4/reference-tracking)) |
| `JsonObjectCreationHandling.Populate` | `NinoDeserializer.Deserialize(bytes, ref value)`, which fills the whole graph in place ([Reuse and Pooling](/en/docs/v4/pooling)) |
| `IJsonOnSerializing`, `IJsonOnSerialized`, `IJsonOnDeserializing`, `IJsonOnDeserialized` | `[NinoOnSerializing]`, `[NinoOnSerialized]`, `[NinoOnDeserializing]`, `[NinoOnDeserialized]` on methods, with no interface ([Callbacks](/en/docs/v4/defining-types#callbacks)) |
| `JsonConverter<T>` | [Custom Formatters](/en/docs/v4/custom-formatters) |
| `JsonSerializer.SerializeToUtf8Bytes(value)` | `NinoSerializer.Serialize(value)` |
| `JsonSerializer.Deserialize<T>(utf8Bytes)` | `NinoDeserializer.Deserialize<T>(bytes)` |
| `JsonSerializer.SerializeAsync(stream, value)`, `DeserializeAsync<T>(stream)` | `NinoSerializer.SerializeAsync(value, stream)`, `NinoDeserializer.DeserializeAsync<T>(stream)`: the value comes first ([Streams](/en/docs/v4/advanced/streams#streams)) |
| `DeserializeAsyncEnumerable` | [frames](/en/docs/v4/advanced/streams#frames) on the stream |
| `JsonSerializerOptions.MaxDepth` | `NinoSettings.MaxDepth` ([Limits](/en/docs/v4/security#limits)) |

Both can sit on the same types while you convert: keep the JSON attributes, add `[NinoType]`, read each stored document with System.Text.Json and write it again with Nino ([Switching to Nino](/en/docs/v4/compare#switching) has the steps). System.Text.Json writes public properties only by default: a type made of public fields, as most `[NinoType]`s are, needs `IncludeFields` to keep its JSON.
