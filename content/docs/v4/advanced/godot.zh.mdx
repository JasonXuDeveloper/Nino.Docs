Nino 是普通的 NuGet 包，Godot 4 的 .NET 项目直接就能用。本指南讲安装、和普通 .NET 项目一样的地方、Godot 的结构体和类、存档、联网、在编辑器里重新构建，以及导出。

## 配置 [#setup]

<Steps>
<Step>

### 安装包 [#install-the-package]

Godot 4 的 C# 项目就是用 `Godot.NET.Sdk` 构建的普通 .NET 项目（Godot 4.4 起目标框架为 .NET 8，4.0–4.3 为 .NET 6）。把 Nino 加进它的 `.csproj`：

```shell
# 在 Godot 项目 .csproj 所在的文件夹中
dotnet add package Nino --prerelease
```

然后构建项目（Godot 的 **Build** 按钮、IDE 或 `dotnet build` 都行）。`Nino` 包自带运行时和源生成器。

</Step>
<Step>

### 标记类型 [#mark-your-types]

```csharp title="PlayerState.cs"
using Godot;
using Nino.Core;

[NinoType]
public sealed class PlayerState
{
    public string Name;
    public Vector3 Position;      // Godot 的结构体是非托管类型：按原始内存写入
    public Quaternion Rotation;
    public Color[] Palette;       // 一次整块拷贝
}
```

</Step>
</Steps>

## 和普通 .NET 项目一样的地方 [#what-works]

- **源生成器和分析器**每次构建都会运行，不管构建是 Godot 还是 IDE 发起的；分析器的代码修复在 IDE 里照常可用。
- 用 .NET 8 或更高版本的 SDK 构建时（Godot 4.4 起必须如此），**拦截器**生效：调用处能确定类型的调用，直接进入生成的格式化器。参见[拦截器](/zh/docs/v4/performance#interceptors)。
- **`partial`**：目标为 .NET 8 的项目通过 `[UnsafeAccessor]` 访问私有成员，只有泛型类型才需要 `partial`。目标为 .NET 6 时（Godot 4.0–4.3），凡是序列化非公共成员的类型都必须是 `partial`（NINO002）。`[NinoPooled]` 类则一律要 `partial`。
- **不需要初始化调用。** 生成的注册表会自行注册，第一次使用时自动找到。
- **文档里的其他内容同样适用**：[格式](/zh/docs/v4/evolving-data)、[多态](/zh/docs/v4/polymorphism)、[复用与对象池](/zh/docs/v4/pooling)、[零分配模式](/zh/docs/v4/advanced/zero-allocation)。写出的字节和 .NET 服务器、Unity 客户端上的完全一致。

## Godot 的结构体 [#godot-structs]

Godot 的数学结构体（`Vector2`、`Vector3`、`Vector2I`、`Vector3I`、`Quaternion`、`Basis`、`Transform2D`、`Transform3D`、`Color`、`Rect2`、`Aabb` 等）都是非托管类型，Nino 不用格式化器，直接按原始内存拷贝：单个值拷贝一次，它们的数组或 `List<T>` 整块拷贝一次。你用它们组成的结构体同样按原始内存拷贝，而且是[固定大小](/zh/docs/v4/performance#fixed-size-types)的。

<Callout type="warn">

在双精度版本的 Godot 中（`real_t` 为 `double`），这些结构体的字段是 `double`（`Color` 除外，始终是 `float`），布局和默认的单精度版本不同。含有这些结构体的数据，一个版本写的，另一个版本读不了。要在两种版本之间共享的数据，请改用自己的结构体或基元字段。

</Callout>

## 节点与资源 [#nodes-and-resources]

Godot 的类（`Node` 及其所有派生类、`Resource`、`StringName`、`NodePath` 等）是引擎对象，不是数据：Nino 不序列化它们，遇到这类类型的成员直接跳过，并报 NINO007 警告。类型里的集合请用 .NET 集合（`T[]`、`List<T>`、`Dictionary<TKey, TValue>`），不要用 `Godot.Collections` 里的类型；也不要保存对象本身，而是保存重建它所需的信息：

- 节点：你自己的 ID 和关键的值（位置、生命值），再加上用来实例化它的场景；
- 资源：它的路径（`ResourcePath`），之后用 `GD.Load<T>` 重新加载；
- `StringName` 或 `NodePath`：存成 `string`。

```csharp title="Enemy.cs"
using Godot;
using Nino.Core;

[NinoType(format: NinoFormat.VersionTolerant)]
public sealed class EnemySave
{
    public int Id;            // 你自己的 ID，每次会话都相同
    public string Scene;      // 用来重新实例化的场景，例如 "res://enemies/goblin.tscn"
    public Vector3 Position;
    public int Health;
}

public partial class Enemy : CharacterBody3D
{
    public int Id;
    public int Health;

    public EnemySave Save() => new EnemySave
    {
        Id = Id,
        Scene = SceneFilePath,
        Position = GlobalPosition,
        Health = Health,
    };

    public static Enemy Load(EnemySave save, Node parent)
    {
        var enemy = GD.Load<PackedScene>(save.Scene).Instantiate<Enemy>();
        enemy.Id = save.Id;
        enemy.Health = save.Health;
        parent.AddChild(enemy);
        enemy.GlobalPosition = save.Position;
        return enemy;
    }
}
```

要序列化改不了的类（比如某个库里的类），就写一个[自定义格式化器](/zh/docs/v4/custom-formatters)。

## 存档 [#save-games]

存档比写出它的版本活得更久，所以存档里的每个类型都要用经得起改动的格式：只在末尾追加成员，用 `NinoFormat.VersionTolerant`；还要调整顺序或删除成员，用 `NinoFormat.Keyed`（参见[数据演进](/zh/docs/v4/evolving-data#choosing)）。用 Godot 的 `FileAccess` 把存档写到 `user://` 下，也就是 Godot 给每个用户的数据目录：

```csharp title="SaveFile.cs"
using System.Collections.Generic;
using System.IO;
using Godot;
using Nino.Core;
using FileAccess = Godot.FileAccess;

[NinoType(format: NinoFormat.VersionTolerant)]
public sealed class SaveGame
{
    public int Level;
    public List<EnemySave> Enemies;
}

public static class SaveFile
{
    private const string SavePath = "user://save.dat";

    public static void Write(SaveGame save)
    {
        byte[] bytes = NinoSerializer.Serialize(save);
        using var file = FileAccess.Open(SavePath, FileAccess.ModeFlags.Write)
            ?? throw new IOException($"Cannot write {SavePath}: {FileAccess.GetOpenError()}");
        file.StoreBuffer(bytes);
    }

    public static SaveGame Read() =>
        FileAccess.FileExists(SavePath)
            ? NinoDeserializer.Deserialize<SaveGame>(FileAccess.GetFileAsBytes(SavePath))
            : null;
}
```

也可以用 `System.IO`，配合这个目录的实际路径，这样 Nino 直接写进文件，连数组都不用：`using var file = File.Create(ProjectSettings.GlobalizePath(SavePath));`，再 `NinoSerializer.Serialize(save, file);`；读的时候用 `NinoDeserializer.Deserialize<SaveGame>(file)`（[流](/zh/docs/v4/advanced/streams#streams)）。下面持久化指南里的两个辅助类就是这么写的。不管用哪种：

- 在数据前加一个文件头，写上魔数和格式版本号，以后的版本才知道自己读的是什么：参见[添加文件头](/zh/docs/v4/advanced/persistence#add-a-file-header)。
- 先写到临时文件，写完整了再替换存档，保存途中崩溃也不会毁掉上一份存档：参见[安全写入](/zh/docs/v4/advanced/persistence#write-safely)。
- 给存档类型提交一份[布局基线](/zh/docs/v4/evolving-data#layout-baseline)：如果某个改动会让已有存档读不出来，分析器在你敲代码时就会在改动的成员上报出来。
- 不随版本变化的数据（比如从你的工具导出的关卡数据）可以继续用按位置格式，更小也更快。

## 联网 [#networking]

Godot 的多人联机 API 接受 `byte[]` 参数。用 `NinoSerializer.Serialize(value)` 序列化消息，返回的数组大小正好等于数据大小；另一端用 `ref` 把它读入上一条消息：

```csharp title="StateSync.cs"
using System.Collections.Generic;
using Godot;
using Nino.Core;

[NinoType]
public struct EntityState         // 非托管：按原始内存拷贝
{
    public int Id;
    public Vector3 Position;
    public Quaternion Rotation;
}

[NinoType]
public sealed class WorldState
{
    public long Tick;
    public List<EntityState> Entities;   // 一次整块拷贝
}

public partial class StateSync : Node
{
    private WorldState _latest;          // 每个数据包都读入这个对象

    // 服务器端：把状态发给每个对端。
    public void Broadcast(WorldState state) =>
        Rpc(MethodName.ReceiveState, NinoSerializer.Serialize(state)); // [!code highlight]

    // 客户端：数据包以 byte[] 的形式收到。
    [Rpc(MultiplayerApi.RpcMode.Authority, TransferMode = MultiplayerPeer.TransferModeEnum.UnreliableOrdered)]
    private void ReceiveState(byte[] data)
    {
        NinoDeserializer.Deserialize(data, ref _latest); // [!code highlight]
        Apply(_latest);
    }

    private void Apply(WorldState state) { /* 移动节点 */ }
}
```

`NinoSerializer.Serialize(state)` 每次广播都会分配一个数组。想省掉它，就改用更底层的 API：`SceneMultiplayer.SendBytes` 和 `PacketPeer.PutPacket` 都有接收 `ReadOnlySpan<byte>` 的重载（GodotSharp 4.7 里两者都有），序列化进一个长期持有的缓冲区再发出去：

```csharp title="StateBroadcast.cs"
using Godot;
using Nino.Core;

public partial class StateBroadcast : Node
{
    private readonly NinoArrayBufferWriter _send = new(4096); // 每次广播都复用
    private WorldState _latest;

    public override void _Ready() =>
        ((SceneMultiplayer)Multiplayer).PeerPacket += OnPeerPacket;

    private void OnPeerPacket(long id, byte[] packet) // 这个 byte[] 由 Godot 分配
    {
        try
        {
            NinoDeserializer.Deserialize(packet, ref _latest);
        }
        catch (NinoDataException)
        {
            _latest = null; // 任何对端都能发包：读失败时状态可能只填了一半，整个丢掉，接着收
        }
    }

    public void Broadcast(WorldState state)
    {
        _send.ResetWrittenCount();
        NinoSerializer.Serialize(state, _send);
        ((SceneMultiplayer)Multiplayer).SendBytes(_send.WrittenSpan, 0, // [!code highlight]
            MultiplayerPeer.TransferModeEnum.UnreliableOrdered, 0);
    }
}
```

- 收到的数据包仍是 `byte[]`（`PeerPacket` 信号、`PacketPeer.GetPacket`），由 Godot 分配。`StreamPeer`（TCP）是字节流，所以每条消息前要加上长度：参见[分帧](/zh/docs/v4/advanced/networking#frame-the-stream)。
- 读入 `_latest` 时，每个数据包都复用同一个 `WorldState` 和它的列表，预热之后 Nino 不再分配内存；参见[完整的消息循环](/zh/docs/v4/advanced/zero-allocation#message-loop)。
- 客户端和服务器分开更新时，消息要用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`：参见[滚动升级](/zh/docs/v4/advanced/networking#rolling-upgrades)。各端运行同一版本时，消息可以继续用按位置格式。
- 多态的消息类型按基类发送（`Serialize<Message>(...)`），也按基类读取：参见[多态](/zh/docs/v4/polymorphism)。

## 在编辑器中重新构建 [#editor-reload]

编辑器开着时重新构建，Godot 会卸载项目的程序集，再加载新构建的程序集。某个库如果还持有指向旧程序集的引用，就可能让旧程序集卸载不掉。Nino 不会（[#199](https://github.com/JasonXuDeveloper/Nino/issues/199)）：

- **Godot 4.4 及以上（.NET 8）：** 项目用的是 Nino.Core 的 `net8.0` 版本。程序集里有 Nino 生成的代码时，它的加载上下文一开始卸载，Nino 就清掉为它缓存的一切：它的注册表，它的类型的格式化器、类型 ID 和原始内存布局，它的多态子类型，以及它的 `[assembly: NinoFormatter]` 注册。你什么都不用做。
- **Godot 4.0–4.3（.NET 6）：** 项目用的是 `netstandard2.1` 版本，看不到 `AssemblyLoadContext`。`NinoRegistry.Remove(assembly)` 做同样的清理，在上下文卸载时调用它：

```csharp title="UnloadCleanup.cs"
using System.Runtime.Loader;
using Nino.Core;

public static class UnloadCleanup
{
    /// <summary>启动时调用一次：本程序集的加载上下文卸载时，把它从 Nino 中移除。</summary>
    public static void Register()
    {
        var assembly = typeof(UnloadCleanup).Assembly;
        var context = AssemblyLoadContext.GetLoadContext(assembly);
        if (context is { IsCollectible: true })
            context.Unloading += _ => NinoRegistry.Remove(assembly);
    }
}
```

项目为**其他**程序集的类型声明的格式化器（为某个库的类型写的 `[assembly: NinoFormatter]`），Nino 用过一次之后就一直保持注册；这种格式化器请放进那个库里。详见[卸载程序集](/zh/docs/v4/platforms#unloading-assemblies)。

## 导出 [#exports]

- 导出的游戏和编辑器里跑的是同一套 Nino 代码，Nino 在任何运行时、CPU 和指针宽度上写出的字节都一致：存档和消息可以在游戏的桌面版与移动版之间互通，也能发给 .NET 服务器。参见[平台](/zh/docs/v4/platforms)。
- 如果导出时做了裁剪或用 Native AOT 编译，你序列化的每个类型都必须出现在生成器看得到的代码里：作为成员类型，或者作为 `NinoSerializer`/`NinoDeserializer` 调用的类型参数或 `typeof` 参数。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。
- 双精度版本写出的 Godot 结构体和单精度版本不一样：参见 [Godot 的结构体](#godot-structs)。

## 降低帧耗时的技巧 [#frame-time-tips]

- **网络或回放数据不再引起 GC 尖峰：** 用 `ref` 把每个 tick 读入上一个 tick 的对象，大批创建的类（投射物、事件）标上 `[NinoPooled]`。参见[零分配模式](/zh/docs/v4/advanced/zero-allocation)。
- 字节写往 span（文件、你自己管理的 socket）时，**每个发送方复用一个 `NinoArrayBufferWriter`**，不要每帧分配一个 `byte[]`。Godot 自己的 API 要的是 `byte[]`：这时 `Serialize(value)` 分配一个大小正好等于数据的数组。
- **批量数据保持非托管：** `Vector3`、`Color` 或你自己的非托管 `[NinoType]` 结构体组成的数组，只需一次内存拷贝。

## 故障排查 [#troubleshooting]

<Accordions type="single">
<Accordion title="error NINO002: Type must be partial">

这个类型序列化了私有成员，而项目的目标是 .NET 6（Godot 4.0–4.3）；或者它是泛型类型或 `[NinoPooled]` 类。把它和包含它的每个类型都声明为 `partial`（Rider 和 Visual Studio 里的代码修复会帮你改）。

</Accordion>
<Accordion title="Node 或 Resource 成员报 NINO007 警告">

Nino 不序列化 Godot 的类。改存 ID、路径或你需要的值（见[节点与资源](#nodes-and-resources)），或者给这个成员加上 `[NinoIgnore]`。

</Accordion>
<Accordion title="旧版本的数据读不出来">

Nino 默认用按位置格式：改了类型的成员，旧数据就读不出来。存档等需要保存的数据请用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`，再配一份[布局基线](/zh/docs/v4/evolving-data#layout-baseline)；旧存档从哪里开始对不上，[`nino-gen inspect`](/zh/docs/v4/advanced/codegen#inspect) 能看出来。参见[数据演进](/zh/docs/v4/evolving-data)。数据里如果有 Godot 的结构体，双精度版本写的数据单精度版本读不了。

</Accordion>
</Accordions>
