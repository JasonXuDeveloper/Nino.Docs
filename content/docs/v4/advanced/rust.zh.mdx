Rust 运行时（crate `nino-serialization`，库名 `nino`）读写 Nino 的[二进制格式](/zh/docs/v4/wire-format)。边界检查全是安全代码；只有两处允许 `unsafe`（其余部分都是 `#![deny(unsafe_code)]`）：一处是读写时转码字符串的模块，在小端和大端目标上用 Miri 测过；另一处是[引用追踪](#reference-tracking)里 `Shared::get` 的一个代码块，同样用 Miri 测过。它没有必需的依赖，随 Nino 每次发布以相同的版本号发布到 crates.io。

## 安装 [#install]

```shell
# 与你的 Nino 包版本相同
cargo add nino-serialization@=%NINO_VERSION% --features indexmap
cargo add indexmap
```

nino-gen 生成的代码需要 `indexmap` 功能和 `indexmap` 本身：映射和 Set 用 `IndexMap` 和 `IndexSet`，保留字节中的顺序。用 [`Maps="std"`](/zh/docs/v4/advanced/codegen#options) 时，它们是 `std::collections::HashMap` 和 `HashSet`，这两样都不需要；这时按 `HashMap` 的迭代顺序写出，字节和 .NET 写的不同，但 .NET 读出的值相同。用 `Serde="true"` 时，给你的 crate 加一个 `serde` 功能，由它打开 `serde` 和 `nino-serialization/serde`。

要生成代码，声明一个 `<NinoCodegen Include="rust" Out="../client/src" />` 项（[在构建中生成](/zh/docs/v4/advanced/codegen#setup)）；它的选项是 `Serde`、`SerdeNames`、`Strings` 和 `Maps`（[选项](/zh/docs/v4/advanced/codegen#options)）。生成的代码需要 Rust 1.88 或更高版本。

## 读写 [#functions]

把生成的文件作为模块引入（生成的代码，关掉 rustfmt），再调用 crate 的函数。下面读的是 [TypeScript 例子](/zh/docs/v4/advanced/typescript#example)里由 .NET 写出的 `Order`：

```rust title="main.rs"
#[rustfmt::skip]
#[path = "nino_types.rs"]
mod protocol;

use protocol::OrderRef;

fn main() -> nino::Result<()> {
    let bytes = std::fs::read("order.bin").expect("order.bin"); // NinoSerializer.Serialize(order) 写出的字节
    let order: Option<OrderRef> = nino::deserialize(&bytes)?;   // Order 不是密封类：按类型 ID 读取
    assert_eq!(nino::serialize(&order)?, bytes);                // 再次得到相同的字节
    Ok(())
}
```

结构体读出来就是它本身，密封类读成 `Option<Order>`，非密封类（比如 `Order`）读成 `Option<OrderRef>`：一个枚举，列出这个槽位允许的类型。

| 函数 | |
| --- | --- |
| `serialize`、`serialize_into` | 按声明类型写出一个值，和 `NinoSerializer.Serialize<T>` 一样。`serialize_into` 追加到一个 `Vec` 末尾，出错时截回原来的长度。 |
| `deserialize`、`deserialize_exact` | 读取一个值。`deserialize_exact` 还会拒绝值后面多出的字节。 |
| `deserialize_into` | 读入已有的值，和 `NinoDeserializer.Deserialize(data, ref value)` 一样：成员原地读取，复用 `Vec` 的缓冲区和元素，映射和 Set 先清空再填充，多态值只在类型相同时复用。 |

## 生成的代码 [#generated-code]

编解码器是完整写出来的（每个类型实现 `NinoRead`、`NinoWrite`、`NinoReadBody` 和 `NinoWriteBody`），不用 `#[derive]` 属性，所以既不需要 derive crate，也不用编译它的过程宏；旧键按布局里带的哈希检查。每个类型都有 `NINO_TYPE_ID`、`NINO_TYPE_NAME` 和 `NINO_LAYOUT` 常量（`Cat::NINO_TYPE_ID`），用 `nino::type_consts!(id, name, layout)` 声明，文档只在 crate 里写一次（泛型类型没有 `NINO_TYPE_ID`）；它的 `NinoReadBody` 和 `NinoWriteBody` impl 把各自的 `TYPE_ID` 设成同一个 ID，和 derive 一样。原始结构体的 `NinoRead` 和 `NinoWrite` impl 就是 `nino::raw_read!()` 和 `nino::raw_write!()`。能放多种类型的槽位是枚举 `<Base>Ref`，每个允许的类型对应一个装箱变体；`object` 槽位是 `AnyObject`。枚举是整数，另有一个单元结构体把各个具名取值作为常量。`with_nino_type(name, visitor)` 找到某个 .NET 名字对应的类型，用它调用 `NinoVisit` 访问者。引入生成的文件时要关掉 rustfmt，见[读写](#functions)。

## 类型 [#types]

| C# | Rust |
| --- | --- |
| `sbyte` … `ulong`、`Int128`、`UInt128`、`float`、`double`、`bool` | `i8` … `u64`、`i128`、`u128`、`f32`、`f64`、`bool` |
| `char` | `u16`，即一个 UTF-16 码元（Rust 的 `char` 对应 `Rune`） |
| `string` | `Option<String>`、`Option<WideString>`；`[NinoUtf8]` 是 `Option<Utf8>` |
| `T?`（结构体）、类 | `Option<T>`；递归的类是 `Option<Box<T>>` |
| `T[]`、`List<T>`、`Queue<T>`…… | `Option<Vec<T>>`、`VecDeque<T>` |
| `HashSet<T>`、`SortedSet<T>` | `HashSet<T>`、`BTreeSet<T>`、`IndexSet<T>` |
| `Dictionary<K, V>`、`SortedDictionary<K, V>` | `HashMap<K, V>`、`BTreeMap<K, V>`、`IndexMap<K, V>` |
| `ValueTuple<…>`（1 到 7 项） | 元组 |
| `T[,]` 等多维数组 | `Grid<T, R>` |
| 原始结构体的 `T?[]`（按原始内存写入） | `RawNullables<T>` |
| 原始结构体里的 `nint`；`nuint`、指针和函数指针 | `i64`；`u64` |
| 原始结构体里的 `DateTimeOffset` | 结构体 `{ date_time, offset_minutes }` |
| `decimal`、`Guid`、`DateTime`、`DateTimeOffset`、`TimeSpan`、`DateOnly`、`TimeOnly`、`Half`、`Rune`、`Version`、`BigInteger`、`BitArray` | 同名类型；`DateTimeKind` 表示 `DateTime` 的 Kind |

`String` 会把未配对的代理项（.NET 字符串里可能有）换成 U+FFFD；`WideString` 保留原始的 UTF-16 码元，这样的值能逐字节写回（生成代码时用 `Strings="wide"`）。`HashSet<string>` 的元素也是 `Option`（`IndexSet<Option<String>>`），因为 .NET 的 Set 里可以有一个 null；字典的键是非 null 字符串（`IndexMap<String, V>`），因为 .NET 从不写出 null 键。

## .NET 值 [#values]

用各类型的构造函数创建（会检查 .NET 接受的范围，返回 `nino::Result`），或者从文本解析。打开 `chrono`、`uuid`、`rust_decimal` 和 `num-bigint` 这几个[功能](#features)，还能用 `TryFrom` 和 `From` 从这些 crate 的类型转换过来：

```rust
use nino::{DateOnly, DateTime, DateTimeKind, DateTimeOffset, Decimal, Guid, TimeSpan};

let price: Decimal = "19.99".parse()?;                       // decimal 文本，保留小数位数
let price = Decimal::new(1999, 2, false)?;                   // 系数、小数位数、是否为负
let id: Guid = "6f9619ff-8b86-d011-b42d-00c04fc964ff".parse()?;
let id = Guid::from_u128(0x6f9619ff_8b86_d011_b42d_00c04fc964ff);
let epoch = DateTime::new(nino::UNIX_EPOCH_TICKS, DateTimeKind::Utc)?; // 自 0001-01-01 起的 tick 数
let timeout = TimeSpan(90 * 10_000_000);                     // 以 100 ns 为单位的 tick 数
let day = DateOnly::new(739_919)?;                           // 自 0001-01-01 起的天数

// 开启 chrono 功能时
let now = DateTime::try_from(chrono::Utc::now())?;          // Kind 为 Utc
let sent = DateTimeOffset::try_from(chrono::Local::now().fixed_offset())?;
let wait = TimeSpan::try_from(chrono::TimeDelta::seconds(90))?;
let date: chrono::NaiveDate = day.try_into()?;
```

`Half` 直接存它的 16 位（`Half(0x3E00)` 是 1.5），`BigInteger` 用 `from_i128` 或从文本创建，`Version` 是字段公开的结构体。所有类型和转换见运行时的 [README](https://github.com/JasonXuDeveloper/Nino/tree/main/runtimes/rust)。

夏令时切换时有一小时会重复，.NET 为这一小时里的本地时间写出的 `DateTime`（最高两位是 kind 3）能读出来并原样写回：`kind()` 和 .NET 的 `DateTime.Kind` 一样返回 `Local`，用 `is_ambiguous_local()` 可以把它区分出来。

## Derive [#derive]

自己写的类型用 `#[derive(NinoRead, NinoWrite)]`（功能 `derive`），生成同样的代码，并在编译时和类型发布的布局核对：

```rust
use nino::{NinoRead, NinoWrite};

#[derive(Debug, Default, Clone, PartialEq, NinoRead, NinoWrite)]
#[nino(format = "keyed")]                 // [NinoType(NinoFormat.Keyed)] 密封类
pub struct Player {
    #[nino(key = "Name", utf8)]           // [NinoUtf8]
    pub name: Option<String>,
    #[nino(former = "Health")]            // 键是 "Hp"，也认 "Health"
    pub hp: i32,
    #[nino(skip)]                         // 不写入数据，读取时为 Default
    pub cached: u64,
}

#[derive(Debug, Default, Clone, Copy, PartialEq, NinoRead, NinoWrite)]
#[nino(kind = "raw")]                     // 非托管结构体，用规范布局
pub struct Vec2 { pub x: f32, pub y: f32 }
```

| 类型属性 | 含义 |
| --- | --- |
| `format = "positional" \| "version_tolerant" \| "keyed"` | `NinoFormat.Positional`（默认）、`VersionTolerant` 或 `Keyed`。 |
| `kind = "class" \| "open" \| "struct" \| "raw"` | 密封类（默认，前面带存在字节）、非密封类（前面带类型 ID）、结构体，或按内存原样写出的非托管结构体（可配 `pack` 和 `size`）。 |
| `id = "Full.Name"` 或 `id = 0x…` | 类型 ID：编译时对 .NET 全名求哈希，或直接给数字。 |
| `deferrable = false` | .NET 从不推迟的类型（记录、通过构造函数创建的类型）。不写时从 `layout` 取。 |
| `layout = "…"` | 类型发布的[布局](/zh/docs/v4/evolving-data#layout-metadata)，编译时核对：成员名和顺序、键、旧键、`[NinoUtf8]`、原始值的大小和偏移。格式、种类、类型 ID 和可推迟性不写时从它取。 |

字段属性有 `index`、`name`（.NET 里的名字，默认是字段名的 PascalCase 形式）、`key`、`former`、`utf8` 和 `skip`。枚举表示多态的声明类型，每个具体类型一个变体；其他类型 ID 一律拒绝。二进制格式表达不了的东西（`usize`、Rust 的 `char`、引用、冲突的键、对不上的 `layout`）都是编译错误，错误信息指明是哪个字段。

## 手写 impl [#hand-written]

优先用 derive。想手写类型的 impl（不编译过程宏）时，用 crate 里的宏：它们写出的方法和生成代码、derive 写的一样，读写的字节也一致：

| 宏 | 写出 | 放在 |
| --- | --- | --- |
| `nino::raw_read!()`、`nino::raw_write!()` | 原始结构体的读和写，基于它的 `nino::Raw` impl（`SIZE`、`ALIGN`、`decode_raw`、`encode_raw`）：每个值一个块，填充清零 | `impl NinoRead`、`impl NinoWrite` |
| `nino::sealed_read!()`、`nino::sealed_write!()` | 密封类的读和写（先存在字节，再是它的 `NinoReadBody` / `NinoWriteBody`） | `impl NinoRead`、`impl NinoWrite` |
| `nino::type_consts!(id, name, layout)` | 常量 `NINO_TYPE_ID`、`NINO_TYPE_NAME` 和 `NINO_LAYOUT`；泛型类型没有自己的 ID，写 `type_consts!(name, layout)` | 类型自己的 `impl` |

```rust
use nino::{NinoRead, NinoWrite, Raw};

/// C#：`struct Cell { int Row; int Column; }`，8 字节。
#[derive(Debug, Default, Clone, Copy, PartialEq)]
pub struct Cell { pub row: i32, pub column: i32 }

impl Raw for Cell {
    const SIZE: usize = 8;
    const ALIGN: usize = 4;

    fn decode_raw(b: &[u8]) -> nino::Result<Self> {
        Ok(Self { row: i32::decode_raw(b)?, column: i32::decode_raw(b.get(4..).unwrap_or_default())? })
    }

    fn encode_raw(&self, out: &mut [u8]) {
        self.row.encode_raw(out);
        if let Some(o) = out.get_mut(4..) {
            self.column.encode_raw(o);
        }
    }
}

impl NinoRead for Cell { nino::raw_read!(); }   // 每个值读一个 8 字节块，先查边界
impl NinoWrite for Cell { nino::raw_write!(); } // 写一个先清零的块，填充保持为 0
```

`NinoWrite::PREFETCH_BYTES`（默认 0）估算写一个值时要顺着它的指针读多少字节，写长列表时据此提前预取。手写的 impl 不对照任何布局检查：想在编译时发现不一致，就用带 `layout = "…"` 的 [derive](#derive)。

## 泛型类型 [#generics]

泛型 `[NinoType]` 生成泛型类型，编解码器由类型实参的编解码器组合而成。各语言支持哪些泛型，以及下面的 `Box<T>`、`Shelf<T>` 和 `Animal`，见[泛型类型](/zh/docs/v4/advanced/codegen#generics)。在 Rust 中：

| | Rust |
| --- | --- |
| `Box<T>` | `struct BoxType<T>`（`Box` 这个名字已有他用） |
| 它的编解码器 | 只要 `T` 实现了 `NinoRead` 和 `NinoWrite`，`BoxType<T>` 也就实现了 |
| 作为成员的 `Box<int>` | `Option<Box<BoxType<i32>>>` |
| 成员 `Shelf<int>` ([按类型 ID 写出](/zh/docs/v4/advanced/codegen#generic-types-behind-a-type-id)) | `Option<ShelfInt32Ref>`，每个允许的类型一个装箱变体的枚举 |
| 泛型 `OpenHolder<T>` 中的 `Open<T>` | 在自身的类型参数后面多一个类型参数（`OpenHolder<T, S0>`），用法是 `OpenHolder<i64, OpenInt64Ref>`；只有槽位用到的类型参数放在 `_params: PhantomData` 字段里 |
| `Animal` 槽位中的 `Box<int>` ([槽位中的封闭泛型类型](/zh/docs/v4/advanced/codegen#closed-generic-types-in-slots)) | 变体 `AnimalRef::BoxInt32(Box<BoxType<i32>>)`，`AnyObject` 里也有一个 |

Rust 在编译时实例化泛型，所以用别的类型实参包含自己的泛型类型（`Nest<T>` 里有 `Nest<List<T>>`）直接跳过，包含它的类型也一起跳过，并报警告 NINOGEN002。

## 引用追踪 [#reference-tracking]

声明了 [`[NinoType(trackReferences: true)]`](/zh/docs/v4/reference-tracking) 的类（比如 `Node`）是 `Option<nino::Shared<Node>>`：一个对象，可以有任意多处持有（克隆得到的还是同一个对象），按标识判断相等；用 `Shared::empty` 和 `fill` 构建循环。引用头和相关检查各语言都一样（[引用追踪](/zh/docs/v4/advanced/codegen#reference-tracking)）。

在 Rust 中，一次读取创建的对象（包括循环）都归这次读取所有，并像 .NET 的垃圾回收器那样一起释放：时机是最后一个持有它们的 `Shared`（返回的值、它的任何克隆、存在所有追踪对象之外的 `Shared`）drop 掉时，或者读取失败时。丢掉读到的值后还想留下图的一部分，就克隆要留下的 `Shared`。手工构建的图（`Shared::new`、`Shared::empty` 和 `fill`）像 `Rc` 一样做引用计数，这样构建的循环不会释放。手写多态的追踪槽位的读取代码时，对槽位允许的每个类型，用 `r.shared_from::<T>(&r.back_ref(header)?)` 取回回引用。

## 不可信数据 [#untrusted-data]

生成的读取代码、derive 和 crate 自带的读取代码都把输入当作不可信数据，做[每种语言都做的检查](/zh/docs/v4/advanced/codegen#untrusted-data)。在 Rust 中：

- 从不 panic：要么返回完整的值，要么返回 `Error`（`ErrorKind` 说明哪项检查没过；超过 512 层是 `ErrorKind::TooDeep`）。
- 推迟的主体放进堆上的工作列表。集合预先分配的内存从每次读取的一份额度里扣（每个输入字节 16 字节，另加 4 KiB）。
- 比 .NET 更严格（有的是相对没开[不可信模式](/zh/docs/v4/security#untrusted-mode)的 .NET，有的是任何模式下都更严）：还会拒绝超出范围的日期和时间、无效的 `decimal`、原始结构体里非零的填充、`BitArray` 里非零的未用位，以及不是最简形式的 `BigInteger`。

这边读不了 .NET 写的字节，或者 .NET 不认这边写的字节时，把字节交给 [`nino-gen inspect`](/zh/docs/v4/advanced/codegen#inspect)：它会列出每个字节属于哪个成员，以及出错的偏移和没通过的检查。

## Rust 不支持的内容 [#not-supported]

由 Nino.Core 以外的格式化器写出的成员（自定义格式化器、`Nino.Immutable`、Unity 的类）在每种语言里都会跳过，Rust 也一样（[不会生成的内容](/zh/docs/v4/advanced/codegen#not-generated)）。除了[所有语言都不会生成的内容](/zh/docs/v4/advanced/codegen#not-generated)，Rust 还会跳过下面这些类型以及包含它们的类型，并报警告 NINOGEN002：

- 用别的类型实参包含自己的泛型类型（[泛型类型](#generics)）；
- 键或元素在 Rust 里无法求哈希的映射和 Set（`f32`、`f64` 以及包含它们的类型）；
- 带填充的原始元组。

## 功能 [#features]

| 功能 | 增加 |
| --- | --- |
| `derive` | `#[derive(NinoRead, NinoWrite)]`（crate `nino-serialization-derive`） |
| `indexmap` | `IndexMap` 和 `IndexSet`，保留字节中的顺序，所以映射读回来再写出去逐字节相同。生成的代码需要它，除非用 `Maps="std"`。 |
| `serde` | 为运行时的值类型实现 serde，带 Nino 编解码器的类型也就能派生 serde（`Serde="true"`）；同时打开了 `indexmap` 和 `uuid` 功能时，也为它们打开 serde |
| `uuid`、`rust_decimal`、`chrono`、`num-bigint` | Nino 的 `Guid`、`decimal`、日期时间类型和 `BigInteger` 与这些 crate 类型之间的转换 |

完整的 API 和各值类型的 serde 形式见运行时的 [README](https://github.com/JasonXuDeveloper/Nino/tree/main/runtimes/rust)。
