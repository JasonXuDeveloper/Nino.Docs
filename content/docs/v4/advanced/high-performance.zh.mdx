`NinoSerializer.Serialize(value)` 和 `NinoDeserializer.Deserialize<T>(bytes)` 本身已经很快，但每次调用都要为结果分配内存。在热路径上（服务器的一次 tick、渲染的一帧、消息循环），下面这些做法可以让序列化和反序列化都降到**每次调用 0 B**。

## 序列化到复用的缓冲区 [#serialize-into-a-reused-buffer]

`NinoArrayBufferWriter` 是 Nino 自带的 `IBufferWriter<byte>`，底层数组租自 `ArrayPool<byte>.Shared`。Nino 直接写入其中；最初几次调用后，它会增长到你需要的大小，之后序列化就不再分配内存。

```csharp title="FrameEncoder.cs"
using Nino.Core;

public sealed class FrameEncoder : IDisposable
{
    private readonly NinoArrayBufferWriter _buffer = new(64 * 1024);

    public ReadOnlySpan<byte> Encode(WorldState state)
    {
        _buffer.ResetWrittenCount();          // reuse the same array
        NinoSerializer.Serialize(state, _buffer);
        return _buffer.WrittenSpan;           // valid until the next Encode
    }

    public void Dispose() => _buffer.Dispose(); // returns the array to the pool
}
```

缓冲区不是线程安全的，每个线程（或每个连接、每个编码器）各用一个。如果代码没有明确的归属对象，可以用线程静态的缓冲区：

```csharp
static class ScratchBuffer
{
    [ThreadStatic] private static NinoArrayBufferWriter t_buffer;

    public static NinoArrayBufferWriter Get()
    {
        var buffer = t_buffer ??= new NinoArrayBufferWriter();
        buffer.ResetWrittenCount();
        return buffer;
    }
}
```

<Callout type="warn">

在缓冲区被再次使用之前，先拷贝或发送 `WrittenSpan`；也不要把线程静态缓冲区交给可能在用完之前再次调用 `Get()` 的代码（重入问题）。

</Callout>

### 连续写入多个值 [#several-values-back-to-back]

`Writer` 写入 `NinoArrayBufferWriter`，可以把多个值放进同一个缓冲区，或者预留空间稍后回填：

```csharp
var buffer = new NinoArrayBufferWriter();
var writer = new Writer(buffer);
NinoSerializer.Serialize(header, ref writer);
NinoSerializer.Serialize(body, ref writer);
writer.Flush();              // commit to buffer.WrittenCount
writer.ReleaseReferences();  // only needed when trackReferences types were written

// reading them back in the same order
var reader = new Reader(buffer.WrittenSpan);
var h = NinoDeserializer.Deserialize<Header>(ref reader);
var b = NinoDeserializer.Deserialize<Body>(ref reader);
reader.ReleaseReferences();
```

## 序列化到任意 IBufferWriter [#serialize-into-any-ibufferwriter]

任何 `IBufferWriter<byte>` 都可以作为写入目标：`PipeWriter`、Kestrel 的响应体写入器、`ArrayBufferWriter<byte>`。Nino 先写入线程本地的暂存缓冲区，再一次性拷贝到目标写入器，因此每次调用都不分配内存：

```csharp
NinoSerializer.Serialize(message, pipeWriter); // one copy into the pipe's memory
await pipeWriter.FlushAsync();
```

只有 `NinoArrayBufferWriter` 是直接写入的。需要在写完之后回填字节时（例如长度前缀，参见[分帧](/zh/docs/v4/advanced/networking#frame-the-stream)），请使用它。

## 直接从已有内存反序列化 [#deserialize-from-the-memory-you-have]

`NinoDeserializer` 读取的是 `ReadOnlySpan<byte>`，字节在哪个缓冲区里，就直接传那块缓冲区的切片，不必再拷贝到新的 `byte[]`：

```csharp
// a received datagram in a pooled array
byte[] rented = ArrayPool<byte>.Shared.Rent(65536);
int received = socket.Receive(rented);
var message = NinoDeserializer.Deserialize<Message>(rented.AsSpan(0, received));
ArrayPool<byte>.Shared.Return(rented);
```

`ReadOnlySequence<byte>`（来自 `System.IO.Pipelines`）的处理方式见[网络层](/zh/docs/v4/advanced/networking#reading-frames)。

## 反序列化到已有对象 [#deserialize-into-existing-objects]

用 `ref` 传入上一次的结果，Nino 会原地填充：同一个对象，同样的嵌套对象、列表、数组和字典。这样，结构相同的消息源源不断地到来时，也不会分配内存。

```csharp
WorldState state = null;                 // created on the first call
while (TryReceive(out ReadOnlySpan<byte> frame))
{
    NinoDeserializer.Deserialize(frame, ref state);
    Render(state);
}
```

- 列表和数组逐个元素复用；字典按键合并。
- 无法原地填充的类型（位置记录、`init` 或只读成员）会被重新创建。
- 已有实例被**丢弃**时（数据中为 `null`、列表变短、某个键消失、多态类型改变），它会恰好一次交给该槽位的回收器，而不是被悄悄覆盖。正因如此，复用反序列化才能安全地与对象池配合使用；参见 [复用反序列化与对象池](/zh/docs/v4/pooling#deserializing-into-existing-instances)。

## 池化新建的对象 [#pool-what-you-create]

复用反序列化复用的是你手里已有的对象，其余的交给 `[NinoPooled]`：每当 Nino 需要**新建**该类型的实例（顶层、成员、变长列表中的新元素），都会先从池中取，被丢弃的实例也会自动回到池中。

<Steps>
<Step>

### 标记类 [#mark-the-class]

```csharp
[NinoType, NinoPooled] // [!code highlight]
public sealed partial class Bullet
{
    public int Id;
    public Vector3 Position;
    public Vector3 Velocity;
    public List<int> HitTargets;

    // Called once, before Nino first deserializes the type: pre-fill the pool.
    private static partial IEnumerable<Bullet> OnNinoPoolWarmup() =>
        Enumerable.Range(0, 256).Select(_ => new Bullet { HitTargets = new List<int>(8) });

    // Called by ReturnToPool(): release state Nino does not deserialize.
    private partial void OnNinoPoolReturn() { }
}
```

该类必须是 `sealed`、`partial`，并且可以原地填充（NINO018、NINO002）。分析器提供一键添加两个钩子方法的修复（NINO019）。

</Step>
<Step>

### 照常反序列化 [#deserialize-as-usual]

```csharp
[NinoType]
public sealed class Snapshot
{
    public long Tick;
    public List<Bullet> Bullets;
}

Snapshot snapshot = null;
NinoDeserializer.Deserialize(frame1, ref snapshot); // bullets come from the pool
NinoDeserializer.Deserialize(frame2, ref snapshot); // bullets that disappeared go back to it
```

</Step>
<Step>

### 归还你持有的实例 [#return-what-you-own]

顶层反序列化得到的实例用完之后，把它还回去：

```csharp
var bullet = NinoDeserializer.Deserialize<Bullet>(data);
Simulate(bullet);
bullet.ReturnToPool(); // its List<int> stays attached and is reused next time
```

同一个实例归还两次会抛出 `InvalidOperationException`。从未归还的实例只是被垃圾回收而已。

</Step>
</Steps>

如果默认容量（共享栈 256 个，另外每个线程最多 64 个）不合适，可以在启动时调整：

```csharp
NinoSettings.SetPoolMaxRetained<Bullet>(4096);
```

<Callout type="idea">

已经有自己的对象池了？给一个公共静态工厂方法加上 `[NinoFactory]`，Nino 就会通过它创建实例；再用 `NinoSettings.SetRecycler<T>(...)` 注册处理函数，接收 Nino 丢弃的实例。参见 [复用反序列化与对象池](/zh/docs/v4/pooling#creating-instances-with-ninofactory)。

</Callout>

## 批量数据保持原始内存格式 [#keep-bulk-data-raw]

非托管数据会按原始内存整块拷贝：

```csharp
[NinoType]
public struct Particle          // unmanaged, sequential: written as raw memory
{
    public Vector3 Position;
    public Vector3 Velocity;
    public float Life;
}

[NinoType]
public sealed class ParticleSystemState
{
    public int Seed;
    public Particle[] Particles; // one block copy for the whole array
}
```

- 非托管元素的数组和 `List<T>` 只需一次拷贝。
- 含有 `string` 或数组的结构体不能按原始内存写入；如果这个结构体处在热路径上，把这些字段挪到单独的类里。
- `versionTolerant`、`keyed` 和自定义成员格式化器都会关闭该结构体的原始内存拷贝。

### 确定性的字节 [#deterministic-bytes]

Nino 会把填充字节清零，所以相等的值总是产生相同的字节，即使结构体是在未初始化的内存中构造的（`stackalloc`、`SkipLocalsInit`）。因此可以直接对数据做哈希或比较，例如跳过发送没有变化的状态：

```csharp
NinoSerializer.Serialize(state, buffer);
ulong hash = XxHash64.HashToUInt64(buffer.WrittenSpan); // System.IO.Hashing
if (hash != lastHash) { Send(buffer.WrittenSpan); lastHash = hash; }
```

## 检查清单 [#checklist]

- [ ] 序列化到复用的 `NinoArrayBufferWriter`，每个线程或每个持有者一个。
- [ ] 直接从已有内存的 span 反序列化。
- [ ] 高频消息用 `ref` 反序列化到已有实例。
- [ ] 给频繁创建和丢弃的类加上 `[NinoPooled]`。
- [ ] 批量数据放在非托管结构体的数组或列表中。
- [ ] 没有子类型的类声明为 `sealed`（1 字节头部，无需分派）。
- [ ] 用 .NET 8 SDK 或更高版本编译，以启用[拦截器](/zh/docs/v4/performance#interceptors)。
