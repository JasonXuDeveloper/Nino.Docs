Stored data is read by builds that did not exist when it was written: a game save, a desktop app's document, a local cache, a snapshot, an event log. This guide shows how to lay out persistent data so that next year's release still loads this year's files, using a game save as the running example, and then covers [key-value stores](#key-value-stores), [append-only logs](#append-only-logs) and [snapshots](#snapshots-and-checkpoints).

## Pick a Format per Type

| Data | Format | Why |
| --- | --- | --- |
| The save root and long-lived records | `keyed: true` | Fields can be added, removed and reordered in any update. |
| Records that only ever grow | `versionTolerant: true` | Append fields to classes without subclasses; 4 bytes per object instead of 8 per member. |
| Small value structs (`Vector3`, your `GridPos`) | positional (bare `[NinoType]`) | Raw, compact, and unlikely to change. Freeze them. |

```csharp title="SaveData.cs"
using Nino.Core;

[NinoType(keyed: true)]
public sealed class SaveGame
{
    public int Version;              // your own content version, see below
    public DateTime SavedAt;
    public Player Player;
    public List<Quest> Quests;
    public Dictionary<string, int> Flags;
}

[NinoType(keyed: true)]
public sealed class Player
{
    public string Name;
    public int Level;
    public GridPos Position;
    public List<Item> Inventory;
}

[NinoType(versionTolerant: true)]
public class Item
{
    public int DefinitionId;
    public int Count;
}

[NinoType]
public struct GridPos            // positional raw struct: never reorder its fields
{
    public int X, Y, Layer;
}
```

A field added in a later update is missing from older saves. When they load, it keeps the value the constructor gives it, so give new fields a sensible initializer: with `public int Difficulty = 1;` added to `SaveGame`, every old save loads on normal difficulty instead of `0`.

<Callout type="warn">

Keyed members are identified by the hash of their **name**. When you rename a field, keep its old name with `[NinoFormerName]` (see [Rename a Field](#rename-a-field)); otherwise the rename reads as "removed one, added another" and the old value is not loaded. Rename *types* with [`[NinoFormerName]`](/en/docs/v4/defining-types#former-name) on the type.

</Callout>

## Rename a Field

In a keyed save type, rename the field and list its old name. Saves written before the rename load into the new field, and new saves are written under the new name:

```csharp
[NinoType(keyed: true)]
public sealed class Player
{
    [NinoFormerName("Lvl")] // [!code highlight]
    public int Level;       // was: public int Lvl;
}
```

Keep the attribute for as long as old saves may still be loaded. A build that predates the rename cannot read the new name, so do not let players downgrade after it.

## Object Graphs

By default every reference is written as its own copy. If several parts of a save point to the same object (a party member who is also in a guild, a quest that references an NPC that references the quest), mark the shared types `trackReferences: true`:

```csharp
[NinoType(keyed: true, trackReferences: true)] // [!code highlight]
public class Character
{
    public string Name;
    public Character Mentor;         // may point to another saved character, or back to this one
    public List<Character> Party;
}
```

Each object is written once; later references are written as a 4-byte index, and cycles are restored. Tracking covers `[NinoType]` classes, not collections, and cannot be used with types re-created from constructor arguments such as positional records (NINO016). See [Reference Tracking](/en/docs/v4/reference-tracking).

## Add a File Header

Nino writes no magic number or format version of its own. Put a small header in front of the save so you can recognize the file and decide how to migrate it:

```csharp title="SaveFile.cs"
using System.IO;
using Nino.Core;

public static class SaveFile
{
    private const int Magic = 0x5641534E;   // any constant you like
    private const int FormatVersion = 3;    // bump when you change the save layout by hand

    public static byte[] Encode(SaveGame save)
    {
        using var buffer = new NinoArrayBufferWriter();
        var writer = new Writer(buffer);
        writer.Write(Magic);
        writer.Write(FormatVersion);
        NinoSerializer.Serialize(save, ref writer);
        writer.Flush();
        writer.ReleaseReferences();         // the save uses trackReferences
        return buffer.ToArray();
    }

    public static SaveGame Decode(ReadOnlySpan<byte> data)
    {
        var reader = new Reader(data);
        if (reader.Read<int>() != Magic)
            throw new InvalidDataException("Not a save file");
        int version = reader.Read<int>();
        if (version > FormatVersion)
            throw new InvalidDataException("Save from a newer game version");

        var save = NinoDeserializer.Deserialize<SaveGame>(ref reader);
        reader.ReleaseReferences();
        return Migrate(save, version);      // fix up content between versions
    }
}
```

## Write Safely

A crash or power loss in the middle of a write must not destroy the previous save. Write to a temporary file, then swap it in:

```csharp
public static void Save(string path, SaveGame save)
{
    byte[] bytes = SaveFile.Encode(save);
    string temp = path + ".tmp";
    File.WriteAllBytes(temp, bytes);
    if (File.Exists(path))
        File.Replace(temp, path, path + ".bak");   // keeps the previous save as a backup
    else
        File.Move(temp, path);
}

public static SaveGame Load(string path) =>
    SaveFile.Decode(File.ReadAllBytes(path));
```

<Callout type="info">

On Unity, write under `Application.persistentDataPath`.

</Callout>

## Key-Value Stores [#key-value-stores]

Embedded stores (RocksDB, LMDB, FASTER, LiteDB's file storage, SQLite `BLOB` columns) and local caches take bytes in and give bytes out. Nino fits both sides: serialize the key and the value into reused buffers, pass the spans, and deserialize what comes back. The store interface below stands in for your store's API:

```csharp title="TypedStore.cs"
using Nino.Core;

public interface IKeyValueStore            // stands in for your store's API
{
    void Put(ReadOnlySpan<byte> key, ReadOnlySpan<byte> value);
    byte[] Get(ReadOnlySpan<byte> key);
}

public sealed class TypedStore<TKey, TValue> where TKey : unmanaged
{
    private readonly IKeyValueStore _store;
    private readonly NinoArrayBufferWriter _key = new(64);
    private readonly NinoArrayBufferWriter _value = new(1024);

    public TypedStore(IKeyValueStore store) => _store = store;

    public void Put(TKey key, TValue value)
    {
        _key.ResetWrittenCount();
        NinoSerializer.Serialize(key, _key);
        _value.ResetWrittenCount();
        NinoSerializer.Serialize(value, _value);
        _store.Put(_key.WrittenSpan, _value.WrittenSpan);
    }

    public bool TryGet(TKey key, out TValue value)
    {
        _key.ResetWrittenCount();
        NinoSerializer.Serialize(key, _key);
        byte[] bytes = _store.Get(_key.WrittenSpan);
        value = bytes == null ? default : NinoDeserializer.Deserialize<TValue>(bytes);
        return bytes != null;
    }
}
```

- An unmanaged key (an `int`, a `Guid`, a struct of ids) is written as its raw little-endian bytes. Stores that sort keys bytewise do **not** sort little-endian integers numerically; if you need range scans in numeric order, write such keys yourself with `BinaryPrimitives.WriteInt64BigEndian`.
- The instance holds two buffers, so use one per thread or guard it with a lock.
- Stored values outlive the code that wrote them: make value types `keyed` or `versionTolerant`, as for save files.

## Append-Only Logs [#append-only-logs]

An append-only log (an event store, a write-ahead log, a journal of changes) appends records and never rewrites them. Frame each record with a length prefix, so a reader can find the record boundaries and detect a record that a crash cut short:

```csharp title="EventLog.cs"
using System.Buffers.Binary;
using Nino.Core;

[NinoType(versionTolerant: true)]
public abstract class AccountEvent
{
    public long Sequence;
}

public sealed class Deposited : AccountEvent { public decimal Amount; }
public sealed class Withdrawn : AccountEvent { public decimal Amount; }

/// <summary>An append-only file of [int32 length][payload] records.</summary>
public sealed class EventLog : IDisposable
{
    private readonly FileStream _file;
    private readonly NinoArrayBufferWriter _buffer = new(1024);

    public EventLog(string path) =>
        _file = new FileStream(path, FileMode.Append, FileAccess.Write, FileShare.Read);

    public void Append(AccountEvent evt)
    {
        _buffer.ResetWrittenCount();
        var writer = new Writer(_buffer);
        int slot = writer.ReserveInt32();
        NinoSerializer.Serialize(evt, ref writer);
        writer.PatchLength(slot);                 // bytes written after the slot
        writer.Flush();
        _file.Write(_buffer.WrittenSpan);
        _file.Flush(flushToDisk: true);           // durable before the caller is told it is stored
    }

    public void Dispose()
    {
        _file.Dispose();
        _buffer.Dispose();
    }

    /// <summary>Replays every complete record; a torn record at the end (a crash mid-write) is ignored.</summary>
    public static IEnumerable<AccountEvent> Replay(string path)
    {
        byte[] data = File.ReadAllBytes(path);
        int offset = 0;
        while (data.Length - offset >= 4)
        {
            int length = BinaryPrimitives.ReadInt32LittleEndian(data.AsSpan(offset));
            if (length < 0 || length > data.Length - offset - 4)
                yield break;                      // incomplete tail
            yield return NinoDeserializer.Deserialize<AccountEvent>(data.AsSpan(offset + 4, length));
            offset += 4 + length;
        }
    }
}
```

- `Flush(flushToDisk: true)` per record is the safe default and the slowest. To trade durability for throughput, append several records and flush once (group commit).
- The length prefix finds a torn **tail**. To detect corruption in the middle of a file, add a checksum per record (for example `System.IO.Hashing.Crc32`) after the length.
- Events are read back by builds that did not exist when they were written: the [message queue rules](/en/docs/v4/advanced/message-queues#topics-that-outlive-a-deployment) apply unchanged.
- `Replay` reads the whole file for brevity. For large logs, read it in chunks with the [`Stream` frame helpers](/en/docs/v4/advanced/streams#streams), which use the same format.

## Snapshots and Checkpoints [#snapshots-and-checkpoints]

Replaying a long log on every start is slow. Store a snapshot of the state together with the position it covers, and replay only what came after it:

```csharp title="Snapshots.cs"
using Nino.Core;

[NinoType(keyed: true)]
public sealed class AccountSnapshot
{
    public long LastSequence;   // the last event the snapshot includes
    public decimal Balance;
}

public static class Snapshots
{
    public static void Write(string path, AccountSnapshot snapshot)
    {
        string temp = path + ".tmp";
        File.WriteAllBytes(temp, NinoSerializer.Serialize(snapshot));
        File.Move(temp, path, overwrite: true);   // never leaves a half-written snapshot
    }

    public static AccountSnapshot Load(string snapshotPath, string logPath)
    {
        var state = File.Exists(snapshotPath)
            ? NinoDeserializer.Deserialize<AccountSnapshot>(File.ReadAllBytes(snapshotPath))
            : new AccountSnapshot();
        foreach (var evt in EventLog.Replay(logPath))
        {
            if (evt.Sequence <= state.LastSequence)
                continue;                         // already in the snapshot
            state.Balance += evt switch
            {
                Deposited d => d.Amount,
                Withdrawn w => -w.Amount,
                _ => 0m,
            };
            state.LastSequence = evt.Sequence;
        }
        return state;
    }
}
```

The same pattern checkpoints any long-running computation (a simulation, a stream processor, a training job): serialize its state and the input position it has reached, write it [safely](#write-safely), and resume from it after a restart. Object graphs with shared references need [`trackReferences`](#object-graphs) in the snapshot types.

## Test Old Saves

The rules above keep old data readable, but only a test proves it. Keep a few saves from every released version in your repository and load them in a unit test on each build:

```csharp
[TestMethod]
public void LoadsEveryShippedSave()
{
    foreach (var file in Directory.GetFiles("TestData/Saves", "*.sav"))
    {
        var save = SaveFile.Decode(File.ReadAllBytes(file));
        Assert.IsNotNull(save.Player);
    }
}
```

## Checklist

- [ ] Root and long-lived records are `keyed` (or `versionTolerant` if they only grow).
- [ ] Small raw structs are frozen: never reorder or retype their fields.
- [ ] Shared or cyclic objects are `trackReferences`.
- [ ] Renamed types and renamed keyed members carry `[NinoFormerName]`.
- [ ] The file starts with your own magic number and version.
- [ ] Saves are written to a temporary file and swapped in.
- [ ] Saves from every shipped version are loaded in a test.
