**Nino.TypeScript** 是一个构建包。每次编译之后，它从构建出的程序集的[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)中读取每个 `[NinoType]` 的写法，生成两个文件：`<程序集名>.ts`，为每个类型生成一个类、为每个枚举生成一个 `as const` 对象、为每个类型生成一个编解码器；以及 `nino.ts`，即读写 Nino 格式的运行时。浏览器或 Node 客户端由此与 .NET 代码交换完全相同的字节，不需要下载 .NET 运行时。

<Callout type="info">

Nino.TypeScript 需要 Nino **4.0.0-rc.6** 或更高版本：它读取的是生成器自该版本起在布局元数据中发布的字节编码。生成的代码需要 TypeScript 5.7 或更高版本（它返回的类型化数组标明了 `ArrayBuffer` 类型），可在浏览器、Node 等 ES2020 环境中运行。

</Callout>

## 工作原理 [#how-it-works]

- **基于构建出的程序集。** 一个 MSBuild 目标在 `CoreCompile` 之后运行，在独立进程中启动 `nino-ts` 工具。工具读取该程序集及其引用的每个程序集上的 `[assembly: NinoTypeLayout]` 特性，不加载这些程序集，因此与项目的目标框架无关。
- **与格式化器同一份布局。** 生成器用生成类型格式化器的同一个模型写出布局，因此 TypeScript 读写成员的顺序、编码和格式与 .NET 代码一致。Nino 的测试先在 .NET 中序列化一个包含所有受支持成员种类的样例，再在 Node 中读取并写回、逐字节比较，检查 .NET 能读取 TypeScript 创建的值，并用 `tsc --strict` 编译生成的代码。
- **构建未变时不打扰。** 每个文件只在文本变化时才写入，监视器和增量 TypeScript 构建不会看到变化；只有程序集、它的引用、工具或选项变化时，工具才会重新运行。IDE 的设计时构建不会运行它。以前写出、现在不再写出的文件（比如程序集改名后）会被删除。
- **一个版本一份运行时。** 包版本一旦改变 `nino.ts`，就会重写它，并在 `ninoVersion` 中记下版本号。

## 配置 [#setup]

<Steps>
<Step>

### 添加包 [#add-the-package]

把它添加到声明 `[NinoType]` 的项目，或引用它们的项目（如服务端项目）中：生成的文件包含该程序集及其引用的程序集中的类型。

```shell
dotnet add Shop.Contracts package Nino --prerelease
dotnet add Shop.Contracts package Nino.TypeScript --prerelease
```

Nino.TypeScript 是开发依赖：`dotnet add package` 会把它标为 `PrivateAssets="all"`，它不会向构建输出添加任何内容，引用你项目的项目也不会继承它。

```xml title="Shop.Contracts.csproj"
<PackageReference Include="Nino.TypeScript" Version="..." PrivateAssets="all" />
```

</Step>
<Step>

### 构建 [#build]

```shell
dotnet build Shop.Contracts
# nino-ts: Shop.Contracts.ts and nino.ts -> .../Shop.Contracts/ts/
```

文件写到项目文件旁的 `ts/` 中。把 [`NinoTypeScriptOutput`](#options) 指向前端的源码目录，即可直接写到那里。如果前端构建前不会先运行 `dotnet build`，就把这两个文件提交到仓库。

</Step>
<Step>

### 导入 [#import-them]

```ts
import { deserialize, serialize } from './ts/nino';
import { Order, OrderCodec } from './ts/Shop.Contracts';
```

生成的代码是普通的 TypeScript：类、`const` 对象和函数，没有装饰器，也没有依赖。目标版本需要支持 `BigInt`（ES2020 或更高）。

</Step>
</Steps>

### 选项 [#options]

在项目文件中设置这些 MSBuild 属性：

| 属性 | 默认值 | |
| --- | --- | --- |
| `NinoTypeScriptOutput` | 项目文件旁的 `ts/` | 两个文件的输出目录。 |
| `NinoTypeScriptImportExtension` | 空 | 生成的文件导入 `nino.ts` 时用的扩展名：空适用于打包工具（Vite、webpack、esbuild），`.js` 适用于用 `tsc` 编译的 Node ESM，`.ts` 适用于 Deno 和 Node 的类型剥离，也可以是 `.mjs`、`.mts`。 |
| `NinoTypeScriptNames` | `camel` | `camel` 把成员名写成 camelCase（`UnitPrice` → `unitPrice`，`URL` → `url`）；`keep` 保留 C# 中的名字。 |
| `NinoTypeScriptTargetFramework` | 第一个 | 有多个目标框架时，由哪个目标框架的构建写出文件。 |
| `NinoTypeScriptEnabled` | `true` | 设为 `false` 即关闭。 |

```xml title="Shop.Contracts.csproj"
<PropertyGroup>
  <NinoTypeScriptOutput>$(MSBuildProjectDirectory)/../web/src/nino/</NinoTypeScriptOutput>
  <NinoTypeScriptImportExtension>.js</NinoTypeScriptImportExtension>
</PropertyGroup>
```

## 示例 [#example]

类型只在 C# 中声明一次：

```csharp title="Shop.Contracts/Order.cs"
using System;
using System.Collections.Generic;
using Nino.Core;

namespace Shop.Contracts;

public enum OrderStatus { Pending, Paid, Shipped }

[NinoType(format: NinoFormat.VersionTolerant)]
public class Order
{
    public long Id;
    public string Customer;
    public OrderStatus Status;
    public DateTime PlacedAt;
    public decimal Total;
    public List<OrderLine> Lines;
}

[NinoType]
public struct OrderLine
{
    public int ProductId;
    public int Quantity;
    public double UnitPrice;
}
```

构建写入 `ts/Shop.Contracts.ts` 的内容（节选，省略了函数）：

```ts title="ts/Shop.Contracts.ts"
export const OrderStatus = {
  Pending: 0,
  Paid: 1,
  Shipped: 2,
} as const;
export type OrderStatus = (typeof OrderStatus)[keyof typeof OrderStatus];

/** `Shop.Contracts.OrderLine`, copied as raw memory (16 bytes). */
export class OrderLine {
  productId: number = 0;
  quantity: number = 0;
  unitPrice: number = 0;
}

/** `Shop.Contracts.Order`. */
export class Order {
  id: bigint = 0n;
  customer: string | null = null;
  status: OrderStatus = 0 as OrderStatus;
  placedAt: Date = new Date(-62135596800000);
  total: string = "0";
  lines: OrderLine[] | null = null;
}

export const OrderCodec: NinoCodec<Order | null> = types.codec<Order>([1504254414]);
export const OrderLineCodec: NinoCodec<OrderLine> = { read: readOrderLine, write: writeOrderLine };
```

每个成员的初始值就是 .NET 中的默认值（`0`、`null`、`DateTime.MinValue`）。`Order` 是版本容错类型，所以它的读取函数和 .NET 中一样：读到旧版本写出的成员末尾就停止，并跳过新版本多出的成员。

使用方式：

```ts
import { deserialize, serialize } from './ts/nino';
import { Order, OrderCodec, OrderLine, OrderStatus } from './ts/Shop.Contracts';

const order = new Order();
order.id = 42n;
order.customer = 'Ada';
order.status = OrderStatus.Paid;
order.placedAt = new Date(Date.UTC(2026, 9, 18, 12, 0, 0));
order.total = '39.00';
const line = new OrderLine();
line.productId = 7;
line.quantity = 2;
line.unitPrice = 9.5;
order.lines = [line];

const bytes = serialize(OrderCodec, order);  // 与 .NET 中 NinoSerializer.Serialize(order) 写出的相同 // [!code highlight]
const copy = deserialize(OrderCodec, bytes); // 又是一个 Order
```

### 配合 ASP.NET Core 服务端 [#with-aspnet-core]

服务端使用 [Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore) 时，请求和响应各一行调用：

```csharp title="Program.cs (ASP.NET Core)"
app.MapPost("/orders", (NinoBody<Order> order) =>
{
    // ... 保存 order.Value ...
    return NinoResults.Ok(order.Value);
});
```

```ts title="orders.ts"
import { deserialize, serialize } from './ts/nino';
import { type Order, OrderCodec } from './ts/Shop.Contracts';

export async function placeOrder(order: Order): Promise<Order | null> {
  const response = await fetch('/orders', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-nino', Accept: 'application/x-nino' },
    body: serialize(OrderCodec, order),
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return deserialize(OrderCodec, new Uint8Array(await response.arrayBuffer()));
}
```

WebSocket 的用法相同：发送 `serialize` 的结果，设置 `binaryType = 'arraybuffer'`，再 `deserialize(codec, new Uint8Array(event.data))`。每条消息就是一个值，不需要分帧。

## API [#api]

- **`serialize(codec, value)`** 返回一个 `Uint8Array`，内容与 .NET 中 `NinoSerializer.Serialize<T>` 写出的相同。字节先写进一个在调用之间复用的缓冲区，再复制出来，因此每次调用只分配返回的数组。较小的结果是一个共享的池化 `ArrayBuffer` 上的视图（和 Node 的 `Buffer` 一样）：直接把这个 `Uint8Array` 交给 `fetch`、`WebSocket.send`、`Blob` 或流，它们会按 `byteOffset` 和 `length` 读取；不要使用它的 `.buffer`。需要独占缓冲区的数组时，调用 `bytes.slice()`。
- **`deserialize(codec, bytes)`** 从一个 `Uint8Array`（Node 的 `Buffer` 也可以）中读取一个值。
- 每个类型 `X` 都有 **`XCodec`**：按 .NET 为其声明类型写出的头读写这个值。结构体没有头（`NinoCodec<X>`），密封类有空标记（`NinoCodec<X | null>`），非密封类和接口有类型 ID，所以 `AnimalCodec` 能读写 `Animal` 的任何生成子类型，与 `Serialize<Animal>` 一样。
- **`NinoWriter` 和 `NinoReader`** 把多个值写进一个缓冲区并按顺序读回，相当于 .NET 中的 `Writer` 和 `Reader`：先 `codec.write(writer, value)`，再 `writer.toBytes()`；读取时 `codec.read(new NinoReader(bytes))`。
- 数据不是所读类型的有效值时（数据被截断、长度超出末尾、未知的类型 ID），以及值无法写出时，抛出 **`NinoError`**。

<Callout type="warn" title="多态的值要用 new 创建">

按类型 ID 写出的值（声明为非密封类、接口或 `object` 的成员）是按它的构造函数查找类型的，所以必须是生成类的实例：要用 `new Cat()`，而不是形状相同的对象字面量。对象字面量会抛出 `NinoError`（`Object is not a type that can be written here`）。

</Callout>

## 类型映射 [#type-mapping]

| C# | TypeScript | 说明 |
| --- | --- | --- |
| `bool` | `boolean` | |
| `byte`、`sbyte`、`short`、`ushort`、`int`、`uint`、`float`、`double` | `number` | |
| `long`、`ulong`、`nint`、`nuint` | `bigint` | |
| `char` | `string` | 一个 UTF-16 码元 |
| `decimal` | `string` | 精确的十进制文本，如 `"-12.345"` |
| `Guid` | `string` | 读出为 `xxxxxxxx-xxxx-…`；写入时接受 `D`、`N` 和 `B` 格式 |
| `DateTime` | `Date` | 精确到毫秒；读取时不保留 Kind，`Date` 按 UTC 写入 |
| `TimeSpan` | `bigint` | 以 100 ns 为单位的 tick 数 |
| `string`（包括 `[NinoUtf8]`） | `string \| null` | |
| `byte[]` | `Uint8Array \| null` | 字节的副本 |
| 数组、`List<T>` 和其他序列 | `T[] \| null` | |
| `HashSet<T>` 和其他集合 | `Set<T> \| null` | |
| `Dictionary<TKey, TValue>` 和其他字典 | `Map<K, V> \| null` | |
| `ValueTuple`、`KeyValuePair` | `[A, B, ...]` | TypeScript 元组，最多 7 项 |
| `Tuple<...>` | `[A, ...] \| null` | |
| `T?`、`Lazy<T>` | `T \| null` | |
| 枚举 | `as const` 对象，以及由其取值组成的类型 | `[Flags]` 枚举是 `number`（64 位的是 `bigint`）；64 位枚举的取值是 `bigint` |
| `[NinoType]` 类 | 类 | `extends` 生成的基类，`implements` 生成的接口；抽象类仍是抽象类 |
| `[NinoType]` 接口 | 接口 | |
| 结构体（`[NinoType]` 或按原始内存复制的） | 类 | 原始结构体按各字段的偏移逐个读写，填充字节置零 |
| `object` | `unknown` | 任何生成的 `[NinoType]`，按类型 ID |
| 键控与版本容错类型 | 同上 | 按其[格式](/zh/docs/v4/evolving-data)读写，包括旧键 |

## 不支持的情况 [#not-supported]

无法用 TypeScript 写出的类型会被跳过，并给出构建警告；包含这种类型的类型也会被跳过：

```text
nino-ts : warning NINOTS002: Samples.Node is not written to TypeScript: reference tracking (trackReferences) is not supported.
```

- 泛型 `[NinoType]`；
- 带 [`trackReferences: true`](/zh/docs/v4/reference-tracking) 的类型；
- 本身是集合的 `[NinoType]`；
- 编码暂时没有 TypeScript 形式的成员：多维数组、`DateTimeOffset`、`BigInteger`、`Version`、`BitArray`、`TimeZoneInfo`、`Uri`、`CultureInfo`、`StringBuilder`、`Memory<T>`、`ILookup` 和 `IGrouping`、超过 7 项的元组，以及由[自定义格式化器](/zh/docs/v4/custom-formatters)写出的成员。

参数无效或工具无法读取程序集时，构建以 `NINOTS001` 失败。

## 与 MemoryPack 的 TypeScript 对比 [#compared-with-memorypack]

[MemoryPack](https://github.com/Cysharp/MemoryPack) 也能为标记了 `[GenerateTypeScript]` 的类生成 TypeScript。它在 Roslyn 源生成器内部完成这件事，在编译 C# 的同时把 `.ts` 文件写到磁盘。两者的差异都源于这一选择：

| | Nino.TypeScript | MemoryPack `[GenerateTypeScript]` |
| --- | --- | --- |
| 何时运行 | 每次构建之后，在独立进程中，基于构建出的程序集 | 在源生成器内部，每次编译都运行，包括 IDE 中的编译 |
| 读取什么 | 发布的[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)，即生成格式化器所依据的布局 | C# 源码，配合它自己的 TypeScript 读写代码 |
| 配置 | 一个包引用；可选的 MSBuild 属性 | 需要用 `CompilerVisibleProperty` 项让编译器看到 MSBuild 属性，每个类型还要加特性 |
| 运行时文件 | 版本变化导致内容变化时就重写 | 只在文件不存在时写入，升级 MemoryPack 不会更新已经写出的副本 |
| 类型改名 | 旧文件会被删除 | 过时的 `.ts` 文件会留下（[#315](https://github.com/Cysharp/MemoryPack/issues/315)，以不计划修复关闭） |
| 结构体 | ✅ | ❌ 只支持类 |
| `char`、`decimal`、64 位枚举 | ✅ | ❌ |
| 版本容错 | ✅ 版本容错和键控 | ❌ |
| 泛型、引用跟踪 | ❌（跳过并给出警告） | ❌ |
| 导入扩展名 | 空、`.js`、`.ts`、`.mjs` 或 `.mts` | 默认 `.js`（[#170](https://github.com/Cysharp/MemoryPack/issues/170)） |

Roslyn 不支持源生成器输出 C# 以外的文件（[dotnet/roslyn#49935](https://github.com/dotnet/roslyn/issues/49935)），分析器规则 RS1035 也禁止在生成器中读写文件；MemoryPack 没有启用包含这条规则的扩展分析器规则。它的 TypeScript 读写代码与 C# 格式化器分开编写，两者可能不一致：在 [#309](https://github.com/Cysharp/MemoryPack/issues/309) 中，TypeScript 写 `float?` 或 `double?` 的有值标记时宽度不对，C# 读出的是 `null`；在 [#166](https://github.com/Cysharp/MemoryPack/issues/166) 中，空字符串曾被写错。用户还报告过生成的代码无法通过严格的 `tsconfig`（[#426](https://github.com/Cysharp/MemoryPack/issues/426)）、导入了没有 `.ts` 文件的基类型（[#174](https://github.com/Cysharp/MemoryPack/issues/174)），以及换行符混用（[#311](https://github.com/Cysharp/MemoryPack/issues/311)）。

Nino.TypeScript 在构建之后运行，依据的正是 C# 格式化器所依据的布局，测试中还在 .NET 与 Node 之间逐字节往返并运行 `tsc --strict`，从而避开了这些问题。其他方案（Protocol Buffers、MessagePack）见[什么时候不适合](/zh/docs/v4#when-not-to-use-it)。
