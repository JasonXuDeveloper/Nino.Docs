The feature pages explain what each option does. These guides put them together for the systems you actually build, with complete patterns you can copy. Every snippet uses only Nino's public API and standard .NET types; where a third-party client appears (Redis, Kafka, gRPC), it is shown minimally, as an illustration.

## Which Guide Do I Need? [#which-guide-do-i-need]

| You are building | Start with |
| --- | --- |
| A service protocol, a real-time server (trading, collaboration, games), a WebSocket or UDP link | [Networking](/en/docs/v4/advanced/networking) |
| gRPC services without `.proto` files, between .NET peers | [gRPC](/en/docs/v4/advanced/networking#grpc) |
| An ASP.NET Core API (MVC or Minimal APIs) that takes and returns Nino bodies | [ASP.NET Core](/en/docs/v4/advanced/aspnetcore) |
| A web or Node front end (JavaScript or TypeScript) that talks to a Nino server | [TypeScript](/en/docs/v4/advanced/typescript) (the recommended way; [Blazor](/en/docs/v4/advanced/browser#blazor) uses Nino as any .NET app) |
| A Go or Rust service that exchanges data with .NET | [Go](/en/docs/v4/advanced/go) or [Rust](/en/docs/v4/advanced/rust) |
| Code in several languages from one set of types, or the generator in a build or CI step | [Use in Other Languages](/en/docs/v4/advanced/codegen) (`<NinoCodegen>` items, the `nino-gen` tool) |
| Bytes that will not read: from another language, a packet capture, a log or a save | [`nino-gen inspect`](/en/docs/v4/advanced/codegen#inspect) |
| Producers and consumers on Kafka, RabbitMQ or another broker | [Message Queues](/en/docs/v4/advanced/message-queues) |
| Telemetry, metrics or market-data feeds | [Telemetry and Tick Streams](/en/docs/v4/advanced/message-queues#telemetry-and-tick-streams) |
| An HTTP body, a file or a blob read from or written to a `Stream`, sync or async | [Streams](/en/docs/v4/advanced/streams#streams) |
| A Redis or `IDistributedCache` layer, or an in-process cache of blobs | [Caching](/en/docs/v4/advanced/caching) |
| Files, documents, save data, local key-value stores | [Persistence](/en/docs/v4/advanced/persistence) |
| Saved data or deployed clients that a change must not break | [Layout Baseline](/en/docs/v4/evolving-data#layout-baseline), then [Persistence](/en/docs/v4/advanced/persistence) or [Rolling Upgrades](/en/docs/v4/advanced/networking#rolling-upgrades) |
| An event store, a journal, snapshots or checkpoints | [Append-Only Logs](/en/docs/v4/advanced/persistence#append-only-logs) |
| IPC over named pipes or sockets | [Framed Streams](/en/docs/v4/advanced/zero-allocation#framed-streams) |
| Records in shared or memory-mapped files | [Fixed-Size Records](/en/docs/v4/advanced/zero-allocation#fixed-size-records) |
| A Unity or HybridCLR project | [Unity and HybridCLR](/en/docs/v4/advanced/unity) |
| A Godot 4 .NET project | [Godot](/en/docs/v4/advanced/godot) |

## Other Languages [#other-languages]

Clients and services in TypeScript, Go and Rust read and write the same bytes as .NET, with code nino-gen writes from the [layout metadata](/en/docs/v4/evolving-data#layout-metadata) of your built assembly. The format they share is described in [Wire Format](/en/docs/v4/wire-format).

## Which Feature Do I Need? [#which-feature-do-i-need]

| You want to | Use |
| --- | --- |
| Add members to a saved type later | [`format: NinoFormat.VersionTolerant`](/en/docs/v4/evolving-data#version-tolerance) |
| Reorder, remove or insert members later | [`format: NinoFormat.Keyed`](/en/docs/v4/evolving-data#keyed-members) |
| Rename a type or move it to another namespace | [`[NinoFormerName]`](/en/docs/v4/evolving-data#former-name) |
| Keep shared references or cycles | [`trackReferences: true`](/en/docs/v4/reference-tracking) |
| Stop allocating on every deserialization | [reuse deserialization and `[NinoPooled]`](/en/docs/v4/pooling) |
| Serialize a type Nino does not know | [`[assembly: NinoFormatter]`](/en/docs/v4/custom-formatters) |
| Encode one member differently | [`[NinoMemberFormatter]`](/en/docs/v4/custom-formatters#for-one-member) |
| Read a value as the type it really is | [Polymorphism](/en/docs/v4/polymorphism) |
| Serialize a type known only at run time | [Runtime types](/en/docs/v4/basic#runtime-types) |
| Write several values into one buffer | [`Writer` and `Reader`](/en/docs/v4/basic#several-values-in-one-buffer) |
| Read from or write to a `Stream`, async | [Streams](/en/docs/v4/advanced/streams#streams) and [Async](/en/docs/v4/advanced/streams#async) |
| Read the `ReadOnlySequence<byte>` of a `PipeReader`, gRPC or `HybridCache` | [`Deserialize<T>(sequence)`](/en/docs/v4/advanced/streams#readonlysequence-input) |
| Several messages on one stream | [Frames](/en/docs/v4/advanced/streams#frames) |
| Run code before serializing or after deserializing | [Callbacks](/en/docs/v4/defining-types#callbacks) |
| Compress the output | [Compression](/en/docs/v4/advanced/streams#compression) |
| Be told, as you type, about a change that breaks old data | [Layout baseline](/en/docs/v4/evolving-data#layout-baseline) (NINO034 to NINO037, `nino-gen layouts`) |
| Read how a type is written, in a tool of your own | [Layout metadata](/en/docs/v4/evolving-data#layout-metadata) |
| See what each byte of a message is | [`nino-gen inspect`](/en/docs/v4/advanced/codegen#inspect) |
| Write arrays and lists of nullable values as one block | [`NinoNullable<T>`](/en/docs/v4/nullable-values#nino-nullable) |
| Rent serialization buffers from your own `ArrayPool<byte>` | [`NinoArrayBufferWriter`](/en/docs/v4/basic#reusing-a-buffer) |
| Hot-reload logic in a collectible `AssemblyLoadContext` | [Unloading assemblies](/en/docs/v4/platforms#unloading-assemblies) |
| Publish trimmed or with Native AOT | [Trimming and Native AOT](/en/docs/v4/platforms#trimming-and-native-aot) |
