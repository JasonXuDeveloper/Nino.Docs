Nino 支持 Unity 2022.3 及以上版本的 Mono 和 IL2CPP、所有 Player 平台，以及 HybridCLR 热更新程序集，且无需任何初始化调用。本指南介绍安装、程序集定义、可选的 Burst 内核、Nino 支持的 Unity 类、IL2CPP 构建、热更新，以及如何让每一帧都不产生 GC。

## 配置 [#setup]

<Steps>
<Step>

### 安装包 [#install-the-package]

从 [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/) 安装：

```shell
openupm add com.jasonxudeveloper.nino
```

包中含有 `Nino.Core.dll`、源生成器 `Nino.Generator.dll`（已标记为 `RoslynAnalyzer`，Unity 会在编译脚本时运行它）、它的代码修复 `Nino.Generator.CodeFixes.dll`（供 Rider 和 Visual Studio 使用）、`Nino.UnityTypes.dll`（下文 [Unity 的类](#unity-classes)的格式化器），以及 Nino.Core 依赖的 `System.Buffers`、`System.Memory` 和 `System.Runtime.CompilerServices.Unsafe` 程序集。

</Step>
<Step>

### 在程序集定义中引用 [#reference-it-from-your-assembly-definitions]

使用 `.asmdef` 的程序集，在勾选 **Auto Referenced** 时能直接看到 `Nino.Core.dll`。如果程序集启用了 **Override References**，需要把 `Nino.Core.dll` 手动加进列表。源生成器会在每个引用了 `Nino.Core` 的程序集上运行。

</Step>
<Step>

### 标记类型 [#mark-your-types]

```csharp
using Nino.Core;
using UnityEngine;

[NinoType]
public class PlayerState
{
    public string Name;
    public Vector3 Position;      // Unity structs are unmanaged: written as raw memory
    public Quaternion Rotation;
    public Color32[] Palette;     // one block copy
}
```

</Step>
</Steps>

## 与 .NET 的区别 [#what-differs-from-net]

- **私有成员需要 `partial`。** Unity 基于 .NET Standard 编译，没有 `[UnsafeAccessor]`，所以序列化非公开成员（或标记了 `[NinoPooled]`）的类型必须声明为 `partial`，包含它的外层类型也一样。分析器会报告 NINO002。自动加上 `partial` 的代码修复在 Rider 和 Visual Studio 中同样可用；其他编辑器中需要手动添加。
- **没有拦截器。** Unity 包附带的是源生成器的 Roslyn 4.3 版本（Unity 支持的最低编译器版本），所以调用走常规路径。写出的字节完全相同，每次调用只差几纳秒。
- **字节与 .NET 一致。** .NET 服务器写出的数据，Unity 客户端可以直接读取，反过来也一样，32 位的 IL2CPP Player 和旧版 Mono 运行时也不例外。参见[平台与二进制格式](/zh/docs/v4/platforms)。

## Burst 加速内核 [#burst-kernels]

Unity 运行的是 `Nino.Core` 的 netstandard 构建，其中没有硬件内联函数（hardware intrinsics）：单靠它自己，元组、带填充的结构体和 Latin-1 文本只能一个字段或一个字（word）地搬运，`[NinoUtf8]` 字符串用 .NET 的 UTF-8 编码器转码。没有 Burst 的 IL2CPP 和 Mono 播放器只走这些标量路径，所以**想要速度，请安装 Burst**：之后 Nino 会改用 SIMD 搬运它们，你的代码无需任何改动：

1. 打开 **Window > Package Manager**，选择 **Unity Registry**，安装 **Burst**（`com.unity.burst`）1.8 或更高版本。用到 Entities 或 Collections 的项目已经有它了，因为两者都依赖 Burst。
2. 就这样。只要项目中有 Burst，Nino 包里的 `Nino.Burst` 程序集就会参与编译（没有 Burst 时跳过），并在启动时（第一个场景加载之前）以及编辑器中每次域重载（domain reload）后注册它的内核。

| 内核 | 加速的内容 | 起始长度 |
| --- | --- | --- |
| Permute | 读写值元组、`KeyValuePair` 以及字节与内存布局不同（有填充、含元组或键值对成员）的 `[NinoType]` 结构体的数组和列表，以及复制带填充的原始结构体数组（顺带清零填充）；每个值最多 64 字节。在支持 AVX2 的 x64 CPU 上，最多 16 字节的值每个 32 字节向量放两个或更多 | 2 个值（带填充的原始结构体：16 个；AVX2：256 个） |
| Narrow、Widen | 读写单字节（Latin-1）形式的字符串（包括 ASCII）：一次 16 个字符 | 16 个字符 |
| NarrowAscii、WidenAscii | 读写 [`[NinoUtf8]` 字符串](/zh/docs/v4/defining-types#string-encoding)：其中直到第一个非 ASCII 字符为止的 ASCII 文本，一次 16 个字符；其余部分交给编码器（或严格的解码器），因此无效的 UTF-8 被拒绝的方式与没有 Burst 时完全相同 | 16 个字符 |

更短的数组和字符串继续走标量路径，因为调用内核的开销会超过它省下的时间：这些阈值就是内核在 Unity 2022.3 和 6000.3 的 IL2CPP 播放器中开始变快的地方。`Nino.Core` 把每个内核的 Burst 函数指针存进静态字段并直接调用，这是调用 Burst 代码最便宜的方式：先把长度和阈值比较一次，然后直接调用，中间没有对象，也没有虚调用（运行时无法调用 Burst 函数指针时，不注册任何内核）。没有填充的原始结构体数组（`Vector3[]`、`Color32[]`、你自己的非托管结构体）无论有没有 Burst 都是一次内存复制。

<UnityHighlights lang="zh" />

**指令集。** 内核在 x86 和 x64 上使用 AVX2（`vpshufb`）和 SSSE3（`pshufb`），在 Arm64 上使用 Neon（`tbl`），适用于编辑器、Mono 和 IL2CPP 播放器，以及通过 AOT 的 `Nino.Core` 调用它们的 HybridCLR 热更新代码。在内核无法运行的地方，Nino 不注册任何内核，继续使用标量路径：Armv7（32 位 Android）、WebGL（它有自己的内核，见[下文](#webgl-kernels)）、不支持 SSSE3 的 x86 和 x64 CPU、Burst 不运行的播放器，以及关闭了 Burst 编译的编辑器（**Jobs > Burst > Enable Compilation**）。

**x64 播放器：启用 SSE4 和 AVX2。** Burst 为 **Edit > Project Settings > Burst AOT Settings** 中的每个 x64 CPU 目标各编译一次播放器代码，启动时选出 CPU 能运行的版本。AVX2 目标让支持 AVX2 的 CPU 使用 32 字节置换；SSE4 目标让支持 SSSE3 但不支持 AVX2 的 CPU 使用 16 字节内核。SSE2 版本没有字节重排，所以没有 SSE4 目标时，这类 CPU 完全用不上内核。默认的目标列表因 Burst 版本而异（1.8.29 的是 SSE2 和 AVX2），所以请确认其中包含 SSE4 和 AVX2，Nino 自己的测试工程就是这样设置的（SSE2、SSE4 和 AVX2）。

**字节相同。** 每个内核写出的字节与它替代的标量路径完全相同，因此有 Burst 和没有 Burst 的播放器、.NET 服务器以及 [Go、Rust 和 TypeScript 运行时](/zh/docs/v4/advanced/codegen)都能互相读取对方的数据。Nino 的 CI 在编辑器和 IL2CPP 播放器中、在 Unity 2022.3 和 6000.3 上逐字节比较每个内核与它的标量参考实现。[Unity 基准测试](/zh/docs/v4/perf-unity)在每个版本中对 IL2CPP 播放器分别在使用和不用内核时计时。

要在运行时检查或切换内核，使用 `Nino.Burst.NinoBurst` 类（你自己的程序集定义中的代码需要引用 `Nino.Burst` 程序集定义才能调用它）：

```csharp nocheck
using Nino.Burst;

Debug.Log($"Nino Burst kernels: {NinoBurst.Registered}, {NinoBurst.IsaName}"); // Isa：3 AVX2，1 SSSE3，2 Neon，0 无
NinoBurst.Unregister(); // 回到标量路径，例如用来对比帧耗时
NinoBurst.Register();   // Burst 关闭或 CPU 不支持其中任何指令集时返回 false
NinoBurst.Register(NinoBurst.Ssse3); // 让支持 AVX2 的 CPU 只用 16 字节内核（字节相同）
```

### WebGL [#webgl-kernels]

Burst 不能为 WebGL 编译，因此 Unity 包为它提供了用 C 和 WebAssembly SIMD 写成的同样的内核（`Nino.WebGL`，由 Unity 编译进播放器，无需安装任何东西）。播放器用 WebAssembly SIMD 构建时，它们在启动时注册；没有 SIMD 的播放器继续走标量路径：

- **Unity 6**：开启 **Player Settings > Publishing Settings > Target WebAssembly 2023**（`PlayerSettings.WebGL.wasm2023`），整个播放器就会带 SIMD 构建。
- **Unity 2022.3** 没有这个设置。在 **Player Settings > Other Settings > Additional IL2CPP Arguments** 中加上 `--compiler-flags=-msimd128`。这样的播放器需要浏览器支持 WebAssembly SIMD：Chrome 91、Firefox 89、Safari 16.4 或更高版本，而 Unity 2022.3 本身支持 Safari 15，所以如果你的玩家还在用更旧的 Safari，请不要开启。

它们处理 16 个字符及以上的 Latin-1 字符串和 `[NinoUtf8]` 字符串中的 ASCII 文本，以及 32 个值及以上的带填充原始结构体数组；元组数组在那里测不出收益，同样从 32 个起。写出的字节与不用它们时相同，CI 在两个 Unity 版本上都会在 Chrome 中把它们与标量路径逐一比对。`Nino.WebGL.NinoWasm` 可以查询它们是否启用（`Simd`、`Registered`），并提供 `Register` 和 `Unregister`。这些 C 内核只用于 WebGL：其他平台上的内核都来自 Burst。

## Unity 的类 [#unity-classes]

Unity 的结构体（`Vector3`、`Quaternion`、`Color32`、`Bounds` 等）是非托管类型，Nino 不需要格式化器，直接按内存写入。有三个 Unity 类的格式化器位于 `Nino.UnityTypes.dll` 中，它和 `Nino.Core.dll` 一起随 Unity 包提供，因此这些类可以作为成员、列表元素或顶层值使用：

| 类 | 写入内容 |
| --- | --- |
| `AnimationCurve` | 它的关键帧（每个关键帧的时间、值、切线、权重和权重模式），然后是前后循环模式 |
| `Gradient` | 它的颜色关键帧、透明度关键帧，然后是模式 |
| `RectOffset` | 它的 left、right、top 和 bottom |

支持 `null`；用 `ref` 反序列化到已有实例时会就地重新填充。如果程序集启用了 **Override References**，也要把 `Nino.UnityTypes.dll` 加进列表。其他 Unity 类（`Texture2D`、`Material`、`ScriptableObject` 等）是资源而不是数据：序列化你需要的那些值，或者编写[自定义格式化器](/zh/docs/v4/custom-formatters)。

## IL2CPP [#il2cpp]

- 生成的代码是普通 C#：序列化时不使用反射，也不使用 `System.Reflection.Emit`。
- 每个生成的注册表都标记了 `[RuntimeInitializeOnLoadMethod]`（编辑器中还有 `[InitializeOnLoadMethod]`），因此注册表会在启动时运行，也不会被 IL2CPP 链接器裁剪掉。即使没有这一步，注册也会在第一次用到时按需完成。
- 代码中**写出名字**的泛型 `[NinoType]` 实例化和内置泛型集合（成员类型、`NinoSerializer.Serialize<List<MyStruct>>` 调用）都会由生成器注册，因此 IL2CPP 会提前编译它们。
- 只通过反射创建、并且只会多态**读取**的实例化，需要在启动时加一行：`NinoPolymorphic.Register<Box<MyStruct>>()`。

## HybridCLR 热更新 [#hybridclr-hot-update]

在热更新代码中，Nino **不需要任何初始化调用**。生成的注册表是按需查找的：Nino 第一次遇到新加载程序集中的类型，或者遇到还不认识的类型 ID 时，就会找到该程序集的注册表。所以：

```csharp
Assembly hotUpdate = Assembly.Load(dllBytes); // HybridCLR
// nothing else to do: types in hotUpdate serialize, including subtypes of AOT base classes
```

常见的划分方式是：AOT 主包（启动器、网络层）声明 `Message` 基类，所有帧都按 `Message` 读取；热更新 DLL 声明玩法消息和配置类型。某次更新新增了 `public sealed class EnterDungeon : Message` 之后，只要加载了新的 DLL，主包中的网络代码就能读到它，既不需要注册调用，也不需要重新打主包。

- 把热更新类型放在引用了 `Nino.Core` 的程序集定义中，或者放在通过 NuGet 安装 Nino 的独立 C# 项目中编译，然后照常加载 DLL。
- 遵循 HybridCLR 自己的 AOT 泛型规则：热更新代码用到了哪些 AOT 程序集中的泛型，就为这些程序集加载补充元数据。
- 热更新代码运行在 HybridCLR 的解释器中，解释器不会内联调用。正因如此，Nino 生成的代码直接调用 `Nino.Core`，不经过任何包装层。
- 注册是按需完成的，所以热更新类型第一次序列化时要承担加载注册表的开销。如果想把这部分开销放到加载界面中，可以在加载程序集后调用 `NinoRegistry.EnsureInitialized(hotUpdate)`（或用 `NinoRegistry.EnsureAllInitialized()` 处理所有已加载的程序集）。两者都是可选的。

## 启动检查清单 [#startup-checklist]

大多数项目一步都不需要。需要的步骤，在第一次序列化调用之前执行一次即可：

| 步骤 | 什么时候需要 | 什么时候不需要 |
| --- | --- | --- |
| `NinoSettings`（`PoolMaxRetained`、`SetPoolMaxRetained<T>`、`SetRecycler<T>`） | 想改变默认的池大小（共享栈 256、每个线程 64），或者想让自己的对象池接收被丢弃的实例。请**最先**设置：这些值的读取不做同步。 | 默认值够用。 |
| HybridCLR 补充元数据 | 热更新代码用到了 AOT 程序集中定义的泛型。按 HybridCLR 的规则处理即可，Nino 没有额外要求。 | 没有热更新。 |
| 用 `Assembly.Load` 加载热更新 DLL | 在读取包含其中类型的数据之前。 | |
| `NinoRegistry.EnsureInitialized(assembly)` 或 `EnsureAllInitialized()` | 想把一次性的注册表加载放到加载界面，而不是第一次用到该程序集的调用。 | 始终是可选的：注册表在首次使用时自动加载。 |
| `NinoPolymorphic.Register<T>()` | 某个封闭泛型 `[NinoType]`（如 `Box<MyStruct>`）在本进程中只会通过基类型**读取**，代码里从未写出它的名字，也从未写入过它。 | 普通子类型，无论在哪个程序集（包括热更新程序集），都会自动找到。 |

```csharp
public static class NinoStartup
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    private static void Init()
    {
        NinoSettings.SetPoolMaxRetained<Bullet>(1024); // only if the defaults do not fit
        NinoPolymorphic.Register<Box<MyStruct>>();     // only for read-only closed generics
    }
}

// after HybridCLR has loaded its supplementary metadata:
Assembly hotUpdate = Assembly.Load(dllBytes);
NinoRegistry.EnsureInitialized(hotUpdate);             // optional: pay the registry load now
```

## 配置表 [#config-tables]

在表格或编辑器中编辑的游戏数据（道具、关卡、掉落表）很适合用 Nino：导出一次 `.bytes` 文件，运行时直接加载，不需要任何解析。把表的类型设为 `format: NinoFormat.Keyed`，这样新增或调整列不会让之前导出的文件失效：

```csharp title="ItemTable.cs"
[NinoType(format: NinoFormat.Keyed)]
public sealed class ItemTable
{
    public List<ItemRow> Rows;
}

[NinoType(format: NinoFormat.Keyed)]
public sealed class ItemRow
{
    public int Id;
    public string Name;
    public int Price;
}

// Editor: export after the table is edited (a menu item, or an import step for your spreadsheets)
File.WriteAllBytes("Assets/Config/items.bytes", NinoSerializer.Serialize(table));

// Player: .bytes files import as TextAsset
var asset = Resources.Load<TextAsset>("Config/items");
ItemTable items = NinoDeserializer.Deserialize<ItemTable>(asset.bytes);
```

## 降低帧耗时的技巧 [#frame-time-tips]

- **网络或回放数据不引起 GC 峰值：** 每个 tick 都用 `ref` 反序列化到上一个 tick 的对象中，并给批量创建的类（子弹、事件）加上 `[NinoPooled]`。参见[零分配模式](/zh/docs/v4/advanced/zero-allocation)。
- **每个发送方复用一个 `NinoArrayBufferWriter`** 来写出数据，而不是每帧调用 `Serialize(value)` 分配一个 `byte[]`。
- **批量数据保持非托管：** `Vector3`、`Color32` 或你自己的非托管 `[NinoType]` 结构体组成的数组，只需一次内存拷贝。

<Callout type="warn">

启用 **Enter Play Mode Options** 并关闭域重载后，静态状态会在多次运行之间保留，包括 `[NinoPooled]` 对象池和 `NinoSettings`。如果残留的实例会带来问题，请在进入运行模式时清空用到的池：`NinoPool<Bullet>.Shared.Clear()`。

</Callout>

## 常见问题 [#troubleshooting]

<Accordions type="single">
<Accordion title="类型没有被序列化 / 源生成器没有运行">

确认程序集引用了 `Nino.Core.dll`（勾选了 Auto Referenced，或在 Override References 中列出），并且 `Nino.Generator.dll` 在导入设置中仍标记为 `RoslynAnalyzer`。然后试试 GitHub 仓库中的 `Nino.Unity` 示例项目，它附带一套可以用 Test Runner 运行的测试。

</Accordion>
<Accordion title="error NINO002：类型必须是 partial">

该类型序列化了私有成员，或者标记了 `[NinoPooled]`，而 Unity 没有 `[UnsafeAccessor]`。把该类型及其所有外层类型声明为 `partial`（在 Rider 和 Visual Studio 中可用代码修复完成）。

</Accordion>
<Accordion title="读取不了旧版本的数据">

Nino 默认按位置写入：修改类型的成员会破坏旧数据。需要保存的数据请使用 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`，参见[数据演进](/zh/docs/v4/evolving-data)。Nino v3 写出的数据 v4 完全无法读取，参见[从 v3 迁移](/zh/docs/v4/migration)。

</Accordion>
</Accordions>
