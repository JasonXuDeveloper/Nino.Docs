Service-to-service messaging, real-time servers (games, trading, collaboration) and device links all need a message format. This guide builds the serialization half of a TCP protocol: a message hierarchy, length-prefixed frames written to a `PipeWriter`, frames read from a `PipeReader` without copying, and messages reused per connection. The transport (sockets, Kestrel connections, your engine's networking) is up to you; anything that gives you a `PipeReader`/`PipeWriter`, a `Stream` or raw buffers works the same way.

## Define the Messages

Derive all messages from one `[NinoType]` base class. Every message is written with a 4-byte **type id** (a stable hash of its full name), so the receiver gets back the right subtype without a hand-maintained opcode table.

```csharp title="Messages.cs"
using Nino.Core;

[NinoType(format: NinoFormat.VersionTolerant)] // subtypes inherit [NinoType] and its options
public abstract class Message
{
    public int RequestId;
}

public sealed class Login : Message
{
    public string User;
    public byte[] Token;
}

public sealed class PriceUpdate : Message
{
    public int InstrumentId;
    public long Timestamp;
    public double Bid, Ask;
}

public sealed class Chat : Message
{
    [NinoUtf8] public string Text; // UTF-8: smaller for mostly-ASCII text
}
```

- Declare the messages in the same assembly as `Message`: Nino then dispatches on them with generated code (a type check chain when writing, a `switch` on the id when reading) instead of a registry lookup. Seal them, so that a member declared as `PriceUpdate` costs a 1-byte header instead of a 4-byte id.
- Type ids come from names, so renaming or moving a message class breaks old peers. Use [`[NinoFormerName]`](/en/docs/v4/defining-types#former-name) when you rename one.
- `NinoFormat.VersionTolerant` lets you add fields to each message later (not to `Message` itself); see [Rolling Upgrades](#rolling-upgrades). Subtypes inherit it with `[NinoType]`; if you give a message its own `[NinoType]`, repeat `format: NinoFormat.VersionTolerant` there.

Dispatch with ordinary pattern matching:

```csharp
void Handle(Message message)
{
    switch (message)
    {
        case Login login:       OnLogin(login); break;
        case PriceUpdate price: OnPrice(price); break;
        case Chat chat:         OnChat(chat);   break;
    }
}
```

## Frame the Stream

TCP is a byte stream, so each message needs a frame. A 4-byte little-endian length prefix is the simplest. Nino's `Writer` can reserve the 4 bytes, serialize the message after them, and then patch in the length, all in one reused buffer, which is then copied into the `PipeWriter` once. Once the buffer has grown to the largest message, writing a frame allocates nothing:

```csharp title="FrameWriter.cs"
using System.IO.Pipelines;
using Nino.Core;

public sealed class FrameWriter
{
    private readonly NinoArrayBufferWriter _buffer = new(4096); // one per connection

    public void Write(PipeWriter output, Message message)
    {
        _buffer.ResetWrittenCount();
        var writer = new Writer(_buffer);
        int lengthPosition = writer.ReserveInt32();   // 4 bytes for the length
        NinoSerializer.Serialize(message, ref writer); // [!code highlight]
        writer.PatchLength(lengthPosition);           // bytes written after the slot
        writer.Flush();
        writer.ReleaseReferences();                   // end the call, as NinoSerializer does

        output.Write(_buffer.WrittenSpan);            // PipeWriter is an IBufferWriter<byte>
    }
}

// sending: one FrameWriter per connection; update is a PriceUpdate you fill in and reuse
frameWriter.Write(pipe.Output, update);
await pipe.Output.FlushAsync();
```

<Callout type="info">

To write frames into buffers you manage (pinned arrays for socket I/O, for example), create the buffer with your pool: `new NinoArrayBufferWriter(4096, pool)`; see [Reusing a Buffer](/en/docs/v4/basic#reusing-a-buffer).

If your transport already frames messages (WebSocket messages, UDP datagrams, a message queue), skip the prefix and serialize into a reused `NinoArrayBufferWriter`, or straight into the transport's `IBufferWriter<byte>` (`NinoSerializer.Serialize(message, pipeWriter)`, which writes into a per-thread scratch buffer and copies the result in once); see [WebSocket and UDP](#websocket-and-udp) and [Message Queues and Event Streams](/en/docs/v4/advanced/message-queues).

</Callout>

## Reading Frames

Read frames out of the `ReadOnlySequence<byte>` the pipe gives you. A frame that lies in one segment (the common case) is deserialized from the pipe's own memory; one that spans two segments is copied once, to the stack or to a pooled array. A read may end in the middle of a frame or hold several frames: the loop takes every complete frame and leaves the rest in the pipe for the next read.

```csharp title="FrameReader.cs"
using System.Buffers;
using System.IO.Pipelines;
using Nino.Core;

public static class FrameReader
{
    public const int MaxFrameSize = 1 << 20; // reject absurd lengths before buffering them

    public static async Task ReadLoopAsync(PipeReader input, Action<Message> handle)
    {
        while (true)
        {
            ReadResult result = await input.ReadAsync();
            ReadOnlySequence<byte> buffer = result.Buffer;

            while (TryReadFrame(ref buffer, out ReadOnlySequence<byte> frame))
                handle(Decode<Message>(frame));

            input.AdvanceTo(buffer.Start, buffer.End);
            if (result.IsCompleted) break;
        }
        await input.CompleteAsync();
    }

    private static bool TryReadFrame(ref ReadOnlySequence<byte> buffer, out ReadOnlySequence<byte> frame)
    {
        var reader = new SequenceReader<byte>(buffer);
        frame = default;
        if (!reader.TryReadLittleEndian(out int length))
            return false;
        if ((uint)length > MaxFrameSize)
            throw new InvalidDataException($"Frame of {length} bytes");
        if (reader.Remaining < length)
            return false;

        frame = buffer.Slice(4, length);
        buffer = buffer.Slice(4 + length);
        return true;
    }

    public static T Decode<T>(in ReadOnlySequence<byte> frame)
    {
        if (frame.IsSingleSegment)                       // the common case: no copy
            return NinoDeserializer.Deserialize<T>(frame.First.Span); // [!code highlight]

        int length = checked((int)frame.Length);         // spans segments: copy once
        if (length <= 512)
        {
            Span<byte> stack = stackalloc byte[length];
            frame.CopyTo(stack);
            return NinoDeserializer.Deserialize<T>(stack);
        }
        byte[] rented = ArrayPool<byte>.Shared.Rent(length);
        try
        {
            frame.CopyTo(rented);
            return NinoDeserializer.Deserialize<T>(rented.AsSpan(0, length));
        }
        finally { ArrayPool<byte>.Shared.Return(rented); }
    }
}
```

<Callout type="info">

Nino validates every length inside the payload against the bytes left before allocating, so a malicious frame cannot make it allocate a huge array, and truncated data throws instead of reading past the end. Still cap the frame size yourself, as above, so a peer cannot make the pipe buffer gigabytes. Deeply nested payloads cannot overflow the server's stack either: objects nested more than 128 levels deep are deferred and read from a shallower level. See [Invalid Data](/en/docs/v4/basic#invalid-data) and [Deep Object Graphs](/en/docs/v4/basic#deep-object-graphs).

</Callout>

## WebSocket and UDP [#websocket-and-udp]

Transports that deliver whole messages need no length prefix: one Nino payload is one WebSocket message or one datagram. Serialize into a reused buffer and send its memory; receive into a reused buffer and deserialize from it:

```csharp title="MessageTransports.cs"
using System.Net;
using System.Net.Sockets;
using System.Net.WebSockets;
using Nino.Core;

public static class MessageTransports
{
    public const int MaxMessageSize = 1 << 20;

    // WebSocket: one Nino payload per WebSocket message.
    // Returns the socket's task: do not reuse buffer until it has completed.
    public static ValueTask SendAsync<T>(WebSocket socket, T message, NinoArrayBufferWriter buffer,
        CancellationToken ct)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(message, buffer);
        return socket.SendAsync(buffer.WrittenMemory, WebSocketMessageType.Binary, endOfMessage: true, ct);
    }

    public static async ValueTask<T> ReceiveAsync<T>(WebSocket socket, NinoArrayBufferWriter buffer,
        CancellationToken ct)
    {
        buffer.ResetWrittenCount();
        ValueWebSocketReceiveResult result;
        do                                                  // a message may arrive in several parts
        {
            if (buffer.WrittenCount >= MaxMessageSize)
                throw new InvalidDataException("WebSocket message too large");
            Memory<byte> free = buffer.GetMemory(4096);
            result = await socket.ReceiveAsync(free, ct);
            if (result.MessageType == WebSocketMessageType.Close)
                throw new WebSocketException(WebSocketError.ConnectionClosedPrematurely);
            buffer.Advance(result.Count);
        } while (!result.EndOfMessage);

        return NinoDeserializer.Deserialize<T>(buffer.WrittenSpan);
    }

    // UDP: one Nino payload per datagram
    public static void SendDatagram<T>(Socket socket, SocketAddress remote, T message, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(message, buffer);
        socket.SendTo(buffer.WrittenSpan, SocketFlags.None, remote);
    }

    public static void ReceiveLoop<T>(Socket socket, Action<T> handle) where T : class
    {
        byte[] datagram = new byte[65_527];  // the largest UDP payload, allocated once
        T message = null;                    // reused for every datagram
        while (true)
        {
            int received = socket.Receive(datagram);
            NinoDeserializer.Deserialize(datagram.AsSpan(0, received), ref message);
            handle(message);
        }
    }
}
```

- A WebSocket message can arrive in several `ReceiveAsync` parts; the loop collects them into the buffer, which grows as needed and is then reused. `MaxMessageSize` stops an untrusted peer from making it grow without bound.
- Neither method allocates a task when the socket completes synchronously: both return a `ValueTask`, and `SendAsync` is not `async` at all.
- A UDP datagram carries at most 65,507 bytes of payload over IPv4 (65,527 over IPv6). Keep messages well below the path MTU (about 1,200 bytes is a common budget) to avoid IP fragmentation, and add your own sequence numbers if order or loss matters.
- Pass the destination as a `SocketAddress`, made once with `remoteEndPoint.Serialize()`: `SendTo` with an `EndPoint` converts it into a new `SocketAddress` on every call. The `SocketAddress` overload needs .NET 8 or later.
- In the UDP loop, the receive array and the message instance are reused: after the first datagram, a stream of messages of the same type allocates nothing but the strings whose text changed and the arrays they contain.

## Reuse Messages per Connection

A busy connection deserializes the same few message types over and over. There are two ways to stop allocating them:

<Tabs items={["Pooled messages", "One instance per type"]}>
<Tab value="Pooled messages">

Make the hot messages `[NinoPooled]`. Nino takes an instance from the pool whenever it creates one, including when it reads a `PriceUpdate` through the `Message` base type. Return it once it has been handled; decoding, handling and returning a pooled message then allocates nothing:

```csharp
[NinoPooled] // [NinoType] and its format are inherited from Message
public sealed partial class PriceUpdate : Message
{
    public int InstrumentId;
    public long Timestamp;
    public double Bid, Ask;

    private static partial IEnumerable<PriceUpdate> OnNinoPoolWarmup() => null; // start empty
    private partial void OnNinoPoolReturn() { }
}

// in the read loop
Message message = FrameReader.Decode<Message>(frame);
Handle(message);
if (message is INinoPooled pooled)
    pooled.ReturnToPool();
```

Pools are thread safe and keep a stack per thread, so connections on different threads do not contend.

</Tab>
<Tab value="One instance per type">

If messages are handled synchronously and never kept, deserialize into the last instance by `ref`. When the next message is the same type it is filled in place; when it is a different type, the old instance is dropped (and recycled, if it is pooled):

```csharp
private Message _last; // per connection, used by one thread at a time

void OnFrame(ReadOnlySpan<byte> frame)
{
    NinoDeserializer.Deserialize(frame, ref _last);
    Handle(_last);
}
```

</Tab>
</Tabs>

## gRPC [#grpc]

gRPC for .NET does not require Protocol Buffers: a method is described by a `Method<TRequest, TResponse>` with a marshaller per message type. A Nino marshaller writes into the buffer writer gRPC provides (through Nino's scratch buffer, one copy) and reads the payload sequence it receives with `FrameReader.Decode` from [Reading Frames](#reading-frames), with no per-message `byte[]` on either side:

```csharp title="NinoMarshaller.cs"
using Grpc.Core;
using Nino.Core;

public static class NinoMarshaller
{
    public static Marshaller<T> Create<T>() => Marshallers.Create<T>(
        serializer: (value, context) =>
        {
            NinoSerializer.Serialize(value, context.GetBufferWriter());
            context.Complete();
        },
        // the payload as it arrived: one segment is read in place, several are copied once
        deserializer: context => FrameReader.Decode<T>(context.PayloadAsReadOnlySequence()));
}

[NinoType] public sealed class GetPriceRequest { public int InstrumentId; }
[NinoType] public sealed class GetPriceReply { public double Bid, Ask; }

public static class PricingMethods
{
    public static readonly Method<GetPriceRequest, GetPriceReply> GetPrice = new(
        MethodType.Unary, "pricing.Pricing", "GetPrice",
        NinoMarshaller.Create<GetPriceRequest>(), NinoMarshaller.Create<GetPriceReply>());
}
```

Use these `Method` definitions with a `CallInvoker` on the client and `ServerServiceDefinition.CreateBuilder().AddMethod(...)` on the server, or with a code-first library that accepts custom marshallers. Both ends must be .NET with the same message types, which is the trade-off against `.proto` contracts; see [When Not to Use It](/en/docs/v4#when-not-to-use-it).

## Threads

- `NinoSerializer` and `NinoDeserializer` are safe to call from any number of threads at once, with no locks.
- Your buffers and reused messages are not: keep one `FrameWriter` per connection (or per sending thread), and never let two threads deserialize into the same instance.
- A message you hand to another thread (a processing loop, a job queue) must not be reused or returned to its pool until that thread is done with it.

## Rolling Upgrades

When clients and servers are not always on the same build, choose the format with the upgrade in mind:

| Change | Positional | `NinoFormat.VersionTolerant` | `NinoFormat.Keyed` |
| --- | :---: | :---: | :---: |
| New field at the end of a message | ✗ | ✓ | ✓ |
| New field in the `Message` base class | ✗ | ✗ shifts every message's fields | ✓ |
| Remove or reorder fields | ✗ | ✗ | ✓ |
| New message type | old peers cannot read it | old peers cannot read it | old peers cannot read it |

- With `NinoFormat.VersionTolerant` on the base class (inherited by every message), an old peer skips the fields it does not know, and on a new peer a missing field keeps the value the message's constructor gave it (a field initializer such as `public int Priority = 1;` works as the default for old senders).
- Add fields to the sealed message classes only: `Message`'s members are written before each message's own, so a field appended to `Message` makes old and new peers read each other's fields in the wrong places ([Appending to a Base Class](/en/docs/v4/evolving-data#appending-to-a-base-class)). To add a field every message carries, make the hierarchy `NinoFormat.Keyed`, or add it to each message.
- A reused or pooled message is filled in place, so there a missing field keeps the value of the **previous** message: reset such fields in `OnNinoPoolReturn`, or do not reuse instances while old peers are connected.
- A peer that receives a **message type it does not know** cannot deserialize it: the call throws an `InvalidOperationException` (unknown type id). Negotiate a protocol version in your handshake and only send new message types to peers that announced support; `NinoTypeId.Of(typeof(T))` gives the id of each message type if you want to exchange the list.
- If both sides always ship together (two services deployed as one unit, a game client and its dedicated server), stay positional: it is the smallest and fastest format.
- To see every change to what your messages write before it ships, record the [layout metadata](/en/docs/v4/evolving-data#layout-metadata) of each message type and of every type it contains in CI, compare it with the last release's, and check each difference against the table above.

See [Evolving Your Data](/en/docs/v4/evolving-data) for the exact rules.
