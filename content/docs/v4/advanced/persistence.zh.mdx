存下来的数据，将来读它的版本在写入时还不存在：桌面应用的文档、用户设置、本地缓存、游戏存档、快照、事件日志都是这样。这篇以一个文档文件为例，讲怎样安排持久化数据，让明年的版本还能打开今年的文件；后半部分讲[键值存储](#key-value-stores)、[追加日志](#append-only-logs)和[快照](#snapshots-and-checkpoints)。

## 按类型选择格式 [#pick-a-format-per-type]

| 数据 | 格式 | 原因 |
| --- | --- | --- |
| 文件的根对象和长期保留的记录 | `format: NinoFormat.Keyed` | 每次更新都能增删字段、调整顺序。 |
| 只会加字段的记录 | `format: NinoFormat.VersionTolerant` | 只往没有子类的类追加字段；每个对象多 4 字节，而不是每个成员 8 字节。 |
| 小的值结构体（`Point`、`Rgba`） | 按位置（不带参数的 `[NinoType]`） | 按原始字节写，紧凑，也很少改。定下来就别再动。 |

```csharp title="Document.cs"
using System;
using System.Collections.Generic;
using Nino.Core;

[NinoType(format: NinoFormat.Keyed)]
public sealed class Document
{
    public int Version;              // 你自己的内容版本，见下文
    public DateTime SavedAt;
    public Profile Owner;
    public List<Layer> Layers;
    public Dictionary<string, string> Settings;
}

[NinoType(format: NinoFormat.Keyed)]
public sealed class Profile
{
    public string DisplayName;
    public string Email;
}

[NinoType(format: NinoFormat.VersionTolerant)]
public sealed class Layer
{
    public string Name;
    public bool Visible;
    public Rgba Color;
    public List<Point> Path;
}

[NinoType]
public struct Point              // 按位置的原始结构体：永远不要调整字段顺序
{
    public float X, Y;
}

[NinoType]
public struct Rgba
{
    public byte R, G, B, A;
}
```

后来加的字段，旧文件里没有。读旧文件时，这个字段保留构造函数给的值，所以新字段要给一个合理的初始值：给 `Document` 加上 `public float Zoom = 1f;`，旧文件打开时就都是 100% 缩放，而不是 `0`。

游戏存档也是这个结构：键控的 `SaveGame` 根对象和 `Player`，版本容错的背包物品，坐标用按位置的结构体。本页的规则原样适用。

<Callout type="warn">

键控成员靠**成员名**的哈希识别。字段改名时，用 `[NinoFormerName]` 留下旧名称（见[字段改名](#rename-a-field)）；不然改名就等于“删一个、加一个”，旧值读不进来。*类型*改名，在类型上加 [`[NinoFormerName]`](/zh/docs/v4/defining-types#former-name)。

</Callout>

## 字段改名 [#rename-a-field]

键控类型的字段改名时，把旧名称标上。改名前写的文件会读进新字段，新文件按新名称写：

```csharp
[NinoType(format: NinoFormat.Keyed)]
public sealed class Profile
{
    [NinoFormerName("Name")]  // [!code highlight]
    public string DisplayName; // 原来是：public string Name;
    public string Email;
}
```

只要还可能打开旧文件，这个特性就一直留着。改名之前的版本不认识新名称：打开新文件时读不到这个值（再保存一次还会把它丢掉），所以改名之后别让用户降级。

## 修改字段类型 [#change-a-fields-type]

成员改类型，哪种格式都容不下：`int` 的字节和 `long` 的不一样。在键控类型里，用新名字加一个成员，旧成员留着读旧文件，加载后按[文件头](#add-a-file-header)里的版本把值搬过去：

```csharp
[NinoType(format: NinoFormat.Keyed)]
public sealed class PlayerStats
{
    public long TotalScore; // 文件版本 4 新增
    public int Score;       // 版本 3 及以前写的 int：只留着读旧文件
}

static void Upgrade(PlayerStats stats, int fileVersion)
{
    if (fileVersion < 4)
        stats.TotalScore = stats.Score;
    stats.Score = 0;        // 新文件里它是 0；版本 3 的文件都没了就删掉它
}
```

整个类的结构都变了的话，把旧类改个名字留下来（`DocumentV3`），按文件头里的版本挑对应的类来读，再在代码里转换。`Document` 这样的密封根类型写入时不带类型 ID，所以旧类改名不影响它能读的数据。

## 对象图 [#object-graphs]

默认每个引用各写一份副本。如果文件里有好几处指向同一个对象（被好几个任务依赖的任务、指回上一层的父节点），就给这些共享的类型加上 `trackReferences: true`：

```csharp
[NinoType(format: NinoFormat.Keyed, trackReferences: true)] // [!code highlight]
public class TaskItem
{
    public string Title;
    public TaskItem Parent;            // 可能指向文件中的另一个任务
    public List<TaskItem> DependsOn;   // 同一个任务可能出现在多个列表里，也可能指回这里
}
```

每个对象只写一次，之后的引用写成 4 字节的索引，循环引用也能还原。引用追踪只管 `[NinoType]` 类，不管集合；靠构造函数参数重建的类型（例如位置记录）用不了它（NINO016）。见[引用追踪](/zh/docs/v4/reference-tracking)。

## 添加文件头 [#add-a-file-header]

Nino 自己不写魔数，也不写格式版本。在数据前面加一个小文件头，用来认出文件、决定怎么迁移。编码到调用方传进来的缓冲区，这样每次保存都能用同一个复用的缓冲区：

```csharp title="DocumentFile.cs"
using System;
using System.IO;
using Nino.Core;

public static class DocumentFile
{
    private const int Magic = 0x434F444E;   // 随便选一个常量（"NDOC"）
    private const int FormatVersion = 3;    // 手动修改布局时递增

    public static void Encode(Document document, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        var writer = new Writer(buffer);
        writer.Write(Magic);
        writer.Write(FormatVersion);
        NinoSerializer.Serialize(document, ref writer);
        writer.Flush();
        writer.ReleaseReferences();         // 把引用表（trackReferences 类型用到的）还给它的池
    }

    public static Document Decode(ReadOnlySpan<byte> data)
    {
        var reader = new Reader(data);
        if (reader.Read<int>() != Magic)
            throw new InvalidDataException("Not a document file");
        int version = reader.Read<int>();
        if (version > FormatVersion)
            throw new InvalidDataException("File from a newer version of the app");

        var document = NinoDeserializer.Deserialize<Document>(ref reader); // [!code highlight]
        reader.ReleaseReferences();
        return Migrate(document, version);
    }

    // 修正旧布局（FormatVersion < 3）写出的内容
    private static Document Migrate(Document document, int fromVersion) => document;
}
```

## 安全写入 [#write-safely]

写到一半崩溃或断电，不能把上一份文件也毁了。先写临时文件，刷到磁盘，再换掉正式文件。读的时候也读进复用的缓冲区，这样加载也不用单独分配 `byte[]`：

```csharp title="SafeFile.cs"
using System;
using System.IO;
using Nino.Core;

public static class SafeFile
{
    /// <summary>替换 path 处的文件；崩溃时留下的要么是旧文件，要么是新文件，绝不会新旧混杂。</summary>
    public static void Write(string path, ReadOnlySpan<byte> bytes)
    {
        string temp = path + ".tmp";
        using (var file = new FileStream(temp, FileMode.Create, FileAccess.Write, FileShare.None, bufferSize: 1))
        {
            file.Write(bytes);
            file.Flush(flushToDisk: true);              // 替换旧文件之前先落盘
        }
        if (File.Exists(path))
            File.Replace(temp, path, path + ".bak");    // 把之前的文件保留为备份
        else
            File.Move(temp, path);
    }

    /// <summary>把整个文件读入 buffer，buffer 在多次调用之间复用。</summary>
    public static ReadOnlySpan<byte> Read(string path, NinoArrayBufferWriter buffer)
    {
        using var file = new FileStream(path, FileMode.Open, FileAccess.Read, FileShare.Read, bufferSize: 1);
        int length = checked((int)file.Length);
        buffer.ResetWrittenCount();
        file.ReadExactly(buffer.GetSpan(length).Slice(0, length));
        buffer.Advance(length);
        return buffer.WrittenSpan;
    }
}
```

```csharp
using var buffer = new NinoArrayBufferWriter(64 * 1024); // 或者每个线程保留一个并复用

DocumentFile.Encode(document, buffer);
SafeFile.Write(path, buffer.WrittenSpan);

Document loaded = DocumentFile.Decode(SafeFile.Read(path, buffer));
```

<Callout type="info">

`bufferSize: 1` 关掉 `FileStream` 自带的缓冲区：一次读写一整块时，它只会多一次拷贝。`Stream.ReadExactly` 要求 .NET 7 或更高版本；其他平台（包括 Unity）循环调用 `Read`，直到读满 `length` 字节。在 Unity 里，文件写到 `Application.persistentDataPath` 下。

</Callout>

## 键值存储 [#key-value-stores]

嵌入式存储（RocksDB、LMDB、FASTER、LiteDB 的文件存储、SQLite 的 `BLOB` 列）和本地缓存都是字节进、字节出。Nino 两头都接得上：把键和值分别序列化到复用的缓冲区，传 span 进去，取回的字节再读入复用的实例。下面的存储接口代替你实际用的存储 API：

```csharp title="TypedStore.cs"
using System;
using System.Buffers;
using Nino.Core;

public interface IKeyValueStore            // 代替你实际用的存储 API
{
    void Put(ReadOnlySpan<byte> key, ReadOnlySpan<byte> value);
    bool TryGet(ReadOnlySpan<byte> key, IBufferWriter<byte> value);  // 把值复制到 writer 中
}

public sealed class TypedStore<TKey, TValue> where TKey : unmanaged
{
    private readonly IKeyValueStore _store;
    private readonly NinoArrayBufferWriter _key = new(64);
    private readonly NinoArrayBufferWriter _value = new(1024);

    public TypedStore(IKeyValueStore store) => _store = store;

    public void Put(TKey key, TValue value)
    {
        _key.ResetWrittenCount();
        NinoSerializer.Serialize(key, _key);
        _value.ResetWrittenCount();
        NinoSerializer.Serialize(value, _value);
        _store.Put(_key.WrittenSpan, _value.WrittenSpan);
    }

    public bool TryGet(TKey key, ref TValue value)
    {
        _key.ResetWrittenCount();
        NinoSerializer.Serialize(key, _key);
        _value.ResetWrittenCount();
        if (!_store.TryGet(_key.WrittenSpan, _value))
            return false;
        NinoDeserializer.Deserialize(_value.WrittenSpan, ref value);   // [!code highlight]
        return true;
    }
}
```

- `Put` 和 `TryGet` 复用两个缓冲区；传进来的 `value` 不为 null 时，`TryGet` 直接填充它。只要存储把值拷进你给的缓冲区，连续调用时，除了值里变了的字符串和数组，什么都不分配。如果存储返回的是 `byte[]` 或 span，就直接从它反序列化。
- 非托管类型的键（`int`、`Guid`、几个 ID 组成的结构体）按原始的小端字节写入。按字节给键排序的存储，**不会**让小端整数按数值大小排好；要按数值顺序做范围扫描，就自己用 `BinaryPrimitives.WriteInt64BigEndian` 写这类键。
- 每个实例持有两个缓冲区，所以每个线程用一个，或者加锁。
- 存下来的值比写它的代码活得久：和文档文件一样，值的类型用 `NinoFormat.Keyed` 或 `NinoFormat.VersionTolerant`。

## 追加日志 [#append-only-logs]

追加日志（事件存储、预写日志、变更记录）只往后追加，从不改写。每条记录前加一个长度前缀，读的一方就能找到记录的边界，也能发现崩溃时只写了一半的记录：

```csharp title="EventLog.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using Nino.Core;

[NinoType(format: NinoFormat.VersionTolerant)]
public abstract class AccountEvent
{
    public long Sequence;
}

public sealed class Deposited : AccountEvent { public decimal Amount; }
public sealed class Withdrawn : AccountEvent { public decimal Amount; }

/// <summary>只追加的文件，记录格式为 [int32 长度][负载]。</summary>
public sealed class EventLog : IDisposable
{
    public const int MaxRecordSize = 1 << 20;

    private readonly FileStream _file;
    private readonly NinoArrayBufferWriter _buffer = new(1024);

    public EventLog(string path) =>
        _file = new FileStream(path, FileMode.Append, FileAccess.Write, FileShare.Read);

    public void Append(AccountEvent evt)
    {
        _buffer.ResetWrittenCount();
        var writer = new Writer(_buffer);
        int slot = writer.ReserveInt32();
        NinoSerializer.Serialize(evt, ref writer);
        writer.PatchLength(slot);                 // 槽位之后写入的字节数
        writer.Flush();
        writer.ReleaseReferences();               // 结束这次调用，和 NinoSerializer 一样
        _file.Write(_buffer.WrittenSpan);
        _file.Flush(flushToDisk: true);           // 落盘之后才告诉调用方已存好
    }

    public void Dispose()
    {
        _file.Dispose();
        _buffer.Dispose();
    }

    /// <summary>
    /// 按顺序把每条完整的记录交给 apply；末尾残缺的记录（写到一半时崩溃）直接忽略。
    /// apply 收到的是复用的实例：不要保留它。
    /// </summary>
    public static void Replay(string path, Action<AccountEvent> apply)
    {
        using var file = new FileStream(path, FileMode.Open, FileAccess.Read, FileShare.ReadWrite);
        byte[] record = ArrayPool<byte>.Shared.Rent(4096);
        AccountEvent evt = null;                  // 下一条记录类型相同时原地填充
        try
        {
            while (file.ReadAtLeast(record.AsSpan(0, 4), 4, throwOnEndOfStream: false) == 4)
            {
                int length = BinaryPrimitives.ReadInt32LittleEndian(record);
                if ((uint)length > MaxRecordSize)
                    throw new InvalidDataException($"Record of {length} bytes");
                if (length > record.Length)
                {
                    byte[] larger = ArrayPool<byte>.Shared.Rent(length);
                    ArrayPool<byte>.Shared.Return(record);
                    record = larger;              // finally 归还当前所用的数组
                }
                if (file.ReadAtLeast(record.AsSpan(0, length), length, throwOnEndOfStream: false) < length)
                    break;                        // 末尾不完整
                NinoDeserializer.Deserialize(record.AsSpan(0, length), ref evt); // [!code highlight]
                apply(evt);
            }
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(record);
        }
    }
}
```

- `Append` 用复用的缓冲区写每条记录，不分配内存。`Replay` 用一个池化数组读文件，并读入同一个复用的事件实例，所以只有事件类型和上一条不同时，这条记录才要分配（另外就是事件里的数组和变了的字符串）。`ReadAtLeast` 要求 .NET 7 或更高版本；其他平台循环调用 `Read`。
- 每条记录都 `Flush(flushToDisk: true)` 是最安全的默认做法，也最慢。愿意拿持久性换吞吐量的话，追加几条记录再刷一次（组提交）。
- 长度前缀只能发现被截断的**末尾**。要发现文件中间的损坏，在每条记录的长度之后加一个校验和（例如 `System.IO.Hashing.Crc32`）。
- 读回事件的版本，在写入时可能还不存在：[消息队列的规则](/zh/docs/v4/advanced/message-queues#topics-that-outlive-a-deployment)原样适用。
- 这些记录的帧格式 `[int32 长度][负载]` 和 [`Stream` 辅助类](/zh/docs/v4/advanced/streams#streams)、[网络层指南](/zh/docs/v4/advanced/networking#frame-the-stream)一样，所以也能用它们读写这份日志。

## 快照与检查点 [#snapshots-and-checkpoints]

每次启动都重放一份长日志很慢。把状态的快照和它覆盖到的位置一起存下来，之后只应用快照以后的事件（或者每次打快照时截断日志，让重放一直很短）：

```csharp title="Snapshots.cs"
using System.IO;
using Nino.Core;

[NinoType(format: NinoFormat.Keyed)]
public sealed class AccountSnapshot
{
    public long LastSequence;   // 快照包含的最后一个事件
    public decimal Balance;

    public void Apply(AccountEvent evt)
    {
        if (evt.Sequence <= LastSequence)
            return;                               // 已经在快照中
        Balance += evt switch
        {
            Deposited d => d.Amount,
            Withdrawn w => -w.Amount,
            _ => 0m,
        };
        LastSequence = evt.Sequence;
    }
}

public static class Snapshots
{
    public static void Write(string path, AccountSnapshot snapshot, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(snapshot, buffer);
        SafeFile.Write(path, buffer.WrittenSpan); // 绝不会留下写了一半的快照
    }

    public static AccountSnapshot Load(string snapshotPath, string logPath, NinoArrayBufferWriter buffer)
    {
        var state = File.Exists(snapshotPath)
            ? NinoDeserializer.Deserialize<AccountSnapshot>(SafeFile.Read(snapshotPath, buffer))
            : new AccountSnapshot();
        if (File.Exists(logPath))
            EventLog.Replay(logPath, state.Apply);   // 读取整个日志；Apply 跳过快照已经包含的部分
        return state;
    }
}
```

`SafeFile` 就是[安全写入](#write-safely)里的辅助类。任何长时间运行的计算（模拟、流处理、训练任务）都能这样打检查点：把状态和已经处理到的输入位置一起序列化，安全地写盘，重启后从那里接着跑。对象图里有共享引用的话，快照类型要开 [`trackReferences`](#object-graphs)。

## 测试旧文件 [#test-old-files]

上面的规则能让旧数据一直可读，但要靠测试来证明。每个发布过的版本都留几份文件放进仓库，每次构建都用单元测试加载一遍：

```csharp
[TestMethod]
public void OpensEveryShippedDocument()
{
    foreach (var file in Directory.GetFiles("TestData/Documents", "*.ndoc"))
    {
        var document = DocumentFile.Decode(File.ReadAllBytes(file));
        Assert.IsNotNull(document.Owner);
    }
}
```

## 检查清单 [#checklist]

- [ ] 根对象和长期保留的记录用 `NinoFormat.Keyed`（只会加字段的用 `NinoFormat.VersionTolerant`）。
- [ ] 小的原始结构体已经定型：不再调整字段的顺序或类型。
- [ ] 共享或循环引用的对象开了 `trackReferences`。
- [ ] 改过名的类型和键控成员都带 `[NinoFormerName]`。
- [ ] 文件开头是你自己的魔数和版本。
- [ ] 文件先写临时文件、刷到磁盘，再替换。
- [ ] 测试会加载每个发布过的版本的文件。
