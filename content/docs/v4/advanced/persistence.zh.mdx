存档会被写入它时还不存在的版本读取。本指南介绍如何组织持久化数据，让明年的更新依然能加载今年的存档。

## 按类型选择格式 [#pick-a-format-per-type]

| 数据 | 格式 | 原因 |
| --- | --- | --- |
| 存档根对象与长期存在的记录 | `keyed: true` | 任何更新中都可以添加、删除和重排字段。 |
| 只会增长的记录 | `versionTolerant: true` | 只追加字段；每个继承层级 4 字节，而不是每个成员 8 字节。 |
| 小型值结构体（`Vector3`、你的 `GridPos`） | 按位置（不带参数的 `[NinoType]`） | 原始、紧凑，且不太会变化。将它们冻结。 |

```csharp title="SaveData.cs"
using Nino.Core;

[NinoType(keyed: true)]
public sealed class SaveGame
{
    public int Version;              // 你自己的内容版本，见下文
    public DateTime SavedAt;
    public Player Player;
    public List<Quest> Quests;
    public Dictionary<string, int> Flags;
}

[NinoType(keyed: true)]
public sealed class Player
{
    public string Name;
    public int Level;
    public GridPos Position;
    public List<Item> Inventory;
}

[NinoType(versionTolerant: true)]
public class Item
{
    public int DefinitionId;
    public int Count;
}

[NinoType]
public struct GridPos            // 按位置的原始结构体：永远不要重排它的字段
{
    public int X, Y, Layer;
}
```

<Callout type="warn">

键控成员由其**名称**的哈希识别：重命名字段会被视为“删除了一个、新增了另一个”，旧值不会被加载。*类型*可以用 [`[NinoFormerName]`](/zh/docs/v4/defining-types#former-name) 自由重命名，但字段名请保持稳定，否则需要自己迁移该值。

</Callout>

## 对象图 [#object-graphs]

默认情况下，每个引用都会写成独立的副本。如果存档中有多处指向同一个对象（既在队伍中又在公会中的成员、引用了某个 NPC 而该 NPC 又引用了它的任务），请把这些共享类型标记为 `trackReferences: true`：

```csharp
[NinoType(keyed: true, trackReferences: true)] // [!code highlight]
public class Character
{
    public string Name;
    public Character Mentor;         // 可能指向另一个已保存的角色，或指回自己
    public List<Character> Party;
}
```

每个对象只写入一次；之后的引用写为 4 字节索引，循环引用也能解析。追踪只覆盖 `[NinoType]` 类，不覆盖集合，并且不能用于通过构造函数参数重新创建的类型，例如位置记录（NINO016）。参见[引用追踪](/zh/docs/v4/reference-tracking)。

## 添加文件头 [#add-a-file-header]

Nino 自身不写入魔数或格式版本。在存档前面加一个小文件头，以便识别文件并决定如何迁移：

```csharp title="SaveFile.cs"
using System.IO;
using Nino.Core;

public static class SaveFile
{
    private const int Magic = 0x5641534E;   // 任意你喜欢的常量
    private const int FormatVersion = 3;    // 手动修改存档布局时递增

    public static byte[] Encode(SaveGame save)
    {
        using var buffer = new NinoArrayBufferWriter();
        var writer = new Writer(buffer);
        writer.Write(Magic);
        writer.Write(FormatVersion);
        NinoSerializer.Serialize(save, ref writer);
        writer.Flush();
        writer.ReleaseReferences();         // 存档使用了 trackReferences
        return buffer.ToArray();
    }

    public static SaveGame Decode(ReadOnlySpan<byte> data)
    {
        var reader = new Reader(data);
        if (reader.Read<int>() != Magic)
            throw new InvalidDataException("Not a save file");
        int version = reader.Read<int>();
        if (version > FormatVersion)
            throw new InvalidDataException("Save from a newer game version");

        var save = NinoDeserializer.Deserialize<SaveGame>(ref reader);
        reader.ReleaseReferences();
        return Migrate(save, version);      // 在版本之间修正内容
    }
}
```

## 安全写入 [#write-safely]

写入过程中崩溃或断电，不能毁掉之前的存档。先写入临时文件，再替换：

```csharp
public static void Save(string path, SaveGame save)
{
    byte[] bytes = SaveFile.Encode(save);
    string temp = path + ".tmp";
    File.WriteAllBytes(temp, bytes);
    if (File.Exists(path))
        File.Replace(temp, path, path + ".bak");   // 保留上一份存档作为备份
    else
        File.Move(temp, path);
}

public static SaveGame Load(string path) =>
    SaveFile.Decode(File.ReadAllBytes(path));
```

<Callout type="info">

在 Unity 中，请写入 `Application.persistentDataPath` 之下。

</Callout>

## 测试旧存档 [#test-old-saves]

以上规则能让旧数据保持可读，但只有测试才能证明这一点。在仓库中保留每个已发布版本的几份存档，并在每次构建时用单元测试加载它们：

```csharp
[TestMethod]
public void LoadsEveryShippedSave()
{
    foreach (var file in Directory.GetFiles("TestData/Saves", "*.sav"))
    {
        var save = SaveFile.Decode(File.ReadAllBytes(file));
        Assert.IsNotNull(save.Player);
    }
}
```

## 检查清单 [#checklist]

- [ ] 根对象和长期记录使用 `keyed`（只会增长的使用 `versionTolerant`）。
- [ ] 小型原始结构体已冻结：永不重排或修改其字段类型。
- [ ] 共享或循环的对象使用 `trackReferences`。
- [ ] 重命名的类型带有 `[NinoFormerName]`。
- [ ] 文件以你自己的魔数和版本开头。
- [ ] 存档先写入临时文件再替换。
- [ ] 每个已发布版本的存档都在测试中被加载。
