服务间通信、实时服务器（游戏、交易、协作）以及设备之间的连接，都需要一种消息格式。本指南实现一个 TCP 协议中与序列化相关的部分：消息继承体系、写入 `PipeWriter` 的长度前缀帧、从 `PipeReader` 无拷贝地读取帧，以及按连接复用消息对象；然后把同一套消息用在 WebSocket、UDP 和 gRPC 上，最后讲旧版对端还连着时怎么改消息。传输层（socket、Kestrel 连接、引擎自带的网络模块）由你决定；只要能提供 `PipeReader`/`PipeWriter`、`Stream` 或原始缓冲区，做法都一样。

## 定义消息 [#define-the-messages]

让所有消息继承同一个 `[NinoType]` 基类。每条消息写入时都带有 4 字节的**类型 ID**（类型全名的稳定哈希），接收方无需手工维护操作码表，就能还原出正确的子类型。

```csharp title="Messages.cs"
using Nino.Core;

[NinoType(format: NinoFormat.VersionTolerant)] // 子类型继承 [NinoType] 及其选项
public abstract class Message
{
    public int RequestId;
}

public sealed class Login : Message
{
    public string User;
    public byte[] Token;
}

public sealed class PriceUpdate : Message
{
    public int InstrumentId;
    public long Timestamp;
    public double Bid, Ask;
}

public sealed class Chat : Message
{
    [NinoUtf8] public string Text; // UTF-8：文本大多是 ASCII、夹带 emoji 或其他 U+00FF 以上的字符时更小
}
```

- 把消息和 `Message` 声明在同一个程序集中：这样 Nino 会用生成的代码分派（写入时是一串类型判断，读取时是对 ID 的 `switch`），而不是查注册表。把它们声明为 `sealed`，这样声明为 `PriceUpdate` 的成员只需 1 字节头部，而不是 4 字节 ID。
- 这个程序集要让两端都编译进去：放在服务端和 .NET 客户端都引用的类库里；Unity 客户端见[与 .NET 服务端共享类型](/zh/docs/v4/advanced/unity#shared-types)。
- 类型 ID 来自类型名，所以给消息类改名或换命名空间会导致旧版本的对端无法识别。改名时请使用 [`[NinoFormerName]`](/zh/docs/v4/evolving-data#former-name)。
- `NinoFormat.VersionTolerant` 让你以后可以给各个消息添加字段（不能加到 `Message` 本身），参见[滚动升级](#rolling-upgrades)。子类型会随 `[NinoType]` 一起继承它；如果给某个消息单独加了 `[NinoType]`，记得在那里也写上 `format: NinoFormat.VersionTolerant`。

用普通的模式匹配分发消息：

```csharp
void Handle(Message message)
{
    switch (message)
    {
        case Login login:       OnLogin(login); break;
        case PriceUpdate price: OnPrice(price); break;
        case Chat chat:         OnChat(chat);   break;
    }
}
```

## 分帧 [#frame-the-stream]

TCP 是字节流，每条消息都需要分帧。最简单的做法是加 4 字节小端序的长度前缀。Nino 的 `Writer` 可以先预留 4 字节，接着序列化消息，最后回填长度，全部在同一个复用的缓冲区里完成，然后整帧一次性拷贝进 `PipeWriter`。缓冲区增长到最大消息的大小之后，写一帧不再分配内存：

```csharp title="FrameWriter.cs"
using System;
using System.Buffers;
using System.IO.Pipelines;
using Nino.Core;

public sealed class FrameWriter : IDisposable
{
    private readonly NinoArrayBufferWriter _buffer = new(4096); // 每个连接一个；从 ArrayPool<byte>.Shared 租用

    public void Write(PipeWriter output, Message message)
    {
        _buffer.ResetWrittenCount();
        var writer = new Writer(_buffer);
        int lengthPosition = writer.ReserveInt32();   // 为长度预留 4 字节
        NinoSerializer.Serialize(message, ref writer); // [!code highlight]
        writer.PatchLength(lengthPosition);           // 槽位之后写入的字节数
        writer.Flush();
        writer.ReleaseReferences();                   // 结束这次调用，和 NinoSerializer 一样

        output.Write(_buffer.WrittenSpan);            // PipeWriter 就是 IBufferWriter<byte>
    }

    public void Dispose() => _buffer.Dispose();       // 缓冲区回到池中
}
```

```csharp
// 发送：每个连接一个 FrameWriter；update 是一个你填好数据、反复复用的 PriceUpdate
frameWriter.Write(pipe.Output, update);
await pipe.Output.FlushAsync();
```

<Callout type="info">

如果帧要写进你自己管理的缓冲区（比如 socket I/O 用的 pinned 数组），创建缓冲区时传入你的池即可：`new NinoArrayBufferWriter(4096, pool)`，参见[复用缓冲区](/zh/docs/v4/basic#reusing-a-buffer)。

如果传输层本身已经分帧（WebSocket 消息、UDP 数据报、消息队列），就不需要长度前缀，序列化到复用的 `NinoArrayBufferWriter`，或直接序列化到传输层的 `IBufferWriter<byte>`（`NinoSerializer.Serialize(message, pipeWriter)`，它先写入线程自己的暂存缓冲区，再一次性拷贝过去）即可；参见 [WebSocket 与 UDP](#websocket-and-udp) 和[消息队列](/zh/docs/v4/advanced/message-queues)。只传一条消息就结束的流（HTTP 请求体、文件）也不用分帧：`await NinoDeserializer.DeserializeAsync<Message>(body)` 一直读到流结束（[流](/zh/docs/v4/advanced/streams#streams)）。

</Callout>

## 读取帧 [#reading-frames]

管道到了多少字节就给多少，而 `NinoDeserializer.Deserialize<T>(sequence)` 只读一个值，所以下面的循环先从 `ReadOnlySequence<byte>` 里切出每一帧，再交给 Nino。整帧落在一个分段里（最常见）时，直接在管道自己的内存上反序列化；跨两个分段的帧拷贝一次，拷到栈上或池化数组里。一次读取可能停在某帧的中间，也可能包含好几帧：循环取出所有完整的帧，剩下的留在管道里等下一次读取。

```csharp title="FrameReader.cs"
using System;
using System.Buffers;
using System.IO;
using System.IO.Pipelines;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static class FrameReader
{
    public const int MaxFrameSize = 1 << 20; // 在缓冲之前拒绝离谱的长度

    // handler 写入 replies 的回复，每次读取只 flush 一次
    public static async Task ReadLoopAsync(PipeReader input, Action<Message> handle,
        PipeWriter replies = null, CancellationToken cancel = default)
    {
        try
        {
            while (true)
            {
                ReadResult result = await input.ReadAsync(cancel);
                ReadOnlySequence<byte> buffer = result.Buffer;

                while (TryReadFrame(ref buffer, out ReadOnlySequence<byte> frame))
                    handle(NinoDeserializer.Deserialize<Message>(frame)); // [!code highlight]

                input.AdvanceTo(buffer.Start, buffer.End);
                if (replies != null)
                    await replies.FlushAsync(cancel);        // 这次读取的所有回复，一次发出
                if (result.IsCompleted)
                {
                    if (!buffer.IsEmpty)
                        throw new EndOfStreamException("Connection closed mid-frame");
                    break;
                }
            }
        }
        finally
        {
            await input.CompleteAsync();
        }
    }

    private static bool TryReadFrame(ref ReadOnlySequence<byte> buffer, out ReadOnlySequence<byte> frame)
    {
        var reader = new SequenceReader<byte>(buffer);
        frame = default;
        if (!reader.TryReadLittleEndian(out int length))
            return false;
        if ((uint)length > MaxFrameSize)
            throw new InvalidDataException($"Frame of {length} bytes");
        if (reader.Remaining < length)
            return false;

        frame = buffer.Slice(4, length);
        buffer = buffer.Slice(4 + length);
        return true;
    }
}
```

- **恶意的帧。** Nino 分配内存之前会把帧里的每个长度和剩余字节数比对，数据截断或格式不对时抛 `NinoDataException`，不会越界读取，嵌套深度也有上限（`NinoSettings.MaxDepth`）；全部检查见[不可信数据](/zh/docs/v4/security)。帧长度要你自己检查：有了 `MaxFrameSize`，对端就没法让管道缓冲几个 GB 的数据。
- **某一帧读不出来。** 把它的字节交给 [`nino-gen inspect`](/zh/docs/v4/advanced/codegen#inspect)：它会列出每个字节属于哪个成员；数据有问题时，还会给出出错的偏移和没通过的检查。十六进制转储用 `--hex` 传进去，长度前缀用 `--offset 4` 跳过。

<Callout title="rc.9 及更早的版本">

`NinoDeserializer` 从 rc.10 起才能读 `ReadOnlySequence<byte>`。更早的版本里，本页调用 `NinoDeserializer.Deserialize(frame)` 的地方，换成 [rc.9 及更早版本用的序列辅助方法](/zh/docs/v4/advanced/streams#sequence-helpers-rc9)。

</Callout>

## 接到 Socket 上 [#connect-to-a-socket]

`FrameWriter` 和 `FrameReader` 工作在 `PipeWriter` 和 `PipeReader` 上。用普通 socket 时，用 `PipeWriter.Create` 和 `PipeReader.Create` 从它的 `NetworkStream` 创建这两个对象（Kestrel 的连接处理器直接给你 pipe）。下面是一个完整的程序：通过本机回环 TCP 发送两条消息，打印服务端读到的内容：

```csharp title="Program.cs"
using System;
using System.IO.Pipelines;
using System.Net;
using System.Net.Sockets;
using System.Threading.Tasks;

var listener = new TcpListener(IPAddress.Loopback, 0);
listener.Start();
int port = ((IPEndPoint)listener.LocalEndpoint).Port;

Task server = Task.Run(async () =>
{
    using TcpClient connection = await listener.AcceptTcpClientAsync();
    PipeReader input = PipeReader.Create(connection.GetStream());
    await FrameReader.ReadLoopAsync(input, message => Console.WriteLine(message.GetType().Name));
});

using (var client = new TcpClient())
{
    await client.ConnectAsync(IPAddress.Loopback, port);
    PipeWriter output = PipeWriter.Create(client.GetStream());
    var frameWriter = new FrameWriter();                          // 每个连接一个
    frameWriter.Write(output, new Login { RequestId = 1, User = "ada" });
    frameWriter.Write(output, new Chat { RequestId = 2, Text = "hello 👋" });
    await output.FlushAsync();                                    // 发出两帧
    await output.CompleteAsync();                                 // 关闭流：服务端的循环随之结束
}

await server;
listener.Stop();
```

它会打印 `Login` 和 `Chat`。

### 服务多个连接 [#accept-loop]

服务端在循环里接受连接，每个连接在自己的任务里处理，并使用自己的 `FrameWriter`。下面的 `MessageServer` 就是这样做的：它把 handler 返回的回复发回去，令牌取消时停止：

```csharp title="MessageServer.cs"
using System;
using System.Collections.Concurrent;
using System.IO;
using System.IO.Pipelines;
using System.Net.Sockets;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static class MessageServer
{
    // 接受连接，直到 cancel 触发，再等仍打开的连接关闭
    public static async Task RunAsync(TcpListener listener, Func<Message, Message> handle, CancellationToken cancel)
    {
        var open = new ConcurrentDictionary<Task, bool>();
        try
        {
            while (true)
            {
                Socket socket = await listener.AcceptSocketAsync(cancel);
                Task connection = ServeAsync(socket, handle, cancel); // 每个连接一个任务
                open.TryAdd(connection, true);
                // 出错的连接留在集合里，RunAsync 停止时重新抛出它的异常
                _ = connection.ContinueWith(done => open.TryRemove(done, out _),
                    TaskContinuationOptions.OnlyOnRanToCompletion);
            }
        }
        catch (OperationCanceledException) when (cancel.IsCancellationRequested) { }
        await Task.WhenAll(open.Keys);
    }

    private static async Task ServeAsync(Socket socket, Func<Message, Message> handle, CancellationToken cancel)
    {
        await Task.Yield();                                   // 立即回到 accept 循环
        using var stream = new NetworkStream(socket, ownsSocket: true);
        using var frames = new FrameWriter();                 // 这个连接的缓冲区，来自对象池
        PipeReader input = PipeReader.Create(stream);
        PipeWriter output = PipeWriter.Create(stream);
        try
        {
            await FrameReader.ReadLoopAsync(input, message =>
            {
                Message reply = handle(message);
                if (reply != null)
                    frames.Write(output, reply);              // 和这次读取的其他回复一起发出
            }, output, cancel);
        }
        catch (OperationCanceledException) when (cancel.IsCancellationRequested) { } // 正在停止
        catch (IOException) { }                               // 对端重置了连接
        catch (InvalidDataException) { }                      // 帧超过 MaxFrameSize
        catch (NinoDataException) { }                         // 不是合法的 Message
        await output.CompleteAsync();
    }
}
```

```csharp title="Program.cs"
using System;
using System.Net;
using System.Net.Sockets;
using System.Threading;

var listener = new TcpListener(IPAddress.Any, 5000);
listener.Start();
using var stop = new CancellationTokenSource();
Console.CancelKeyPress += (_, e) => { e.Cancel = true; stop.Cancel(); }; // Ctrl+C：停止并关闭所有连接

await MessageServer.RunAsync(listener, message => message switch
{
    Login login => new Chat { RequestId = login.RequestId, Text = $"welcome, {login.User}" },
    _ => null,                                                // 不回复
}, stop.Token);
listener.Stop();
```

- **每个连接一个任务。** `ServeAsync` 一开始先让出线程，accept 循环立即去接下一个连接。同一个连接的消息在它自己的任务上按顺序处理；不同连接并行处理，这是[安全的](#threads)，因为每个连接有自己的 `FrameWriter`。
- **池化的缓冲区。** 每个连接的 `FrameWriter` 从 `ArrayPool<byte>.Shared` 租用缓冲区，连接结束时（`Dispose`）还回去，所以连接来来去去，也不会把缓冲区留给垃圾回收器。帧直接从管道自己的池化分段中读取，只有跨两个分段的帧才拷贝一次（见[读取帧](#reading-frames)）。
- **每次读取只发送一次。** handler 的回复生成后立即写进管道，`ReadLoopAsync` 每次读取之后 flush 一次：客户端在一个包里发了十个请求，十个回复也在一次发送里回去。
- **取消。** 取消令牌会结束 `AcceptSocketAsync` 和每个连接上等待中的读取；仍打开的连接都关闭之后，`RunAsync` 返回。
- **恶意或出错的对端。** 连接如果发来超过 `MaxFrameSize` 的帧，或者发来的字节不是合法的 `Message`，就关掉这个连接，其他连接照常运行。数据来自客户端时，还要打开[不可信模式](/zh/docs/v4/security#untrusted-mode)。handler 抛出的异常不会被捕获：它结束那个连接，`RunAsync` 停止时会重新抛出。

客户端像上面的程序那样连接，用 `FrameReader.ReadLoopAsync` 在 `PipeReader.Create(client.GetStream())` 上读取回复。

## WebSocket 与 UDP [#websocket-and-udp]

以完整消息为单位传输的协议不需要长度前缀：一个 Nino 负载就是一条 WebSocket 消息或一个数据报。序列化到复用的缓冲区并发送它的内存；接收到复用的缓冲区，再从中反序列化：

```csharp title="MessageTransports.cs"
using System;
using System.IO;
using System.Net;
using System.Net.Sockets;
using System.Net.WebSockets;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static class MessageTransports
{
    public const int MaxMessageSize = 1 << 20;

    // WebSocket：每条 WebSocket 消息一个 Nino 负载。
    // 返回 socket 的任务：它完成之前不要复用 buffer。
    public static ValueTask SendAsync<T>(WebSocket socket, T message, NinoArrayBufferWriter buffer,
        CancellationToken ct)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(message, buffer);
        return socket.SendAsync(buffer.WrittenMemory, WebSocketMessageType.Binary, endOfMessage: true, ct);
    }

    public static async ValueTask ReceiveAsync(WebSocket socket, NinoArrayBufferWriter buffer,
        CancellationToken ct)
    {
        buffer.ResetWrittenCount();
        ValueWebSocketReceiveResult result;
        do                                                  // 一条消息可能分几部分到达
        {
            if (buffer.WrittenCount >= MaxMessageSize)
                throw new InvalidDataException("WebSocket message too large");
            Memory<byte> free = buffer.GetMemory(4096);
            result = await socket.ReceiveAsync(free, ct);
            if (result.MessageType == WebSocketMessageType.Close)
                throw new WebSocketException(WebSocketError.ConnectionClosedPrematurely);
            buffer.Advance(result.Count);
        } while (!result.EndOfMessage);

    }

    public static async Task ReceiveLoopAsync<T>(WebSocket socket, NinoArrayBufferWriter buffer, Action<T> handle,
        CancellationToken ct) where T : class
    {
        T message = null;                                   // 每条消息都读进同一个实例
        while (true)
        {
            await ReceiveAsync(socket, buffer, ct);         // 只收字节，不反序列化
            NinoDeserializer.Deserialize(buffer.WrittenSpan, ref message);
            handle(message);
        }
    }

    // UDP：每个数据报一个 Nino 负载
    public static void SendDatagram<T>(Socket socket, SocketAddress remote, T message, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(message, buffer);
        socket.SendTo(buffer.WrittenSpan, SocketFlags.None, remote);
    }

    public static void ReceiveLoop<T>(Socket socket, Action<T> handle) where T : class
    {
        byte[] datagram = new byte[65_527];  // UDP 负载的最大值，只分配一次
        T message = null;                    // 每个数据报都复用它
        while (true)
        {
            int received = socket.Receive(datagram);
            try
            {
                NinoDeserializer.Deserialize(datagram.AsSpan(0, received), ref message);
            }
            catch (NinoDataException)
            {
                message = null; // 任何人都能发数据报：丢掉格式不对的那个，接着收
                continue;
            }
            handle(message);
        }
    }
}
```

- 一条 WebSocket 消息可能分几次 `ReceiveAsync` 才收完；循环把它们收集到缓冲区里，缓冲区按需增长，之后一直复用。`MaxMessageSize` 防止不可信的对端让缓冲区无限增长。
- 套接字同步完成时，`SendAsync` 和 `ReceiveAsync` 都不会分配任务对象：它们都返回 `ValueTask`，而 `SendAsync` 本身根本不是 `async` 方法。`ReceiveAsync` 只负责收字节，反序列化留在 `ReceiveLoopAsync` 里同步进行，这样每条消息都能用 `ref` 读进同一个实例（`async` 方法不能带 `ref` 参数）。
- 一个 UDP 数据报的负载在 IPv4 上最多 65,507 字节（IPv6 上 65,527 字节）。消息要远小于路径 MTU（常见的预算是 1,200 字节左右），以免 IP 分片；如果在意顺序或丢包，请自己加序号。
- 用 `SocketAddress` 指定目标地址，用 `remoteEndPoint.Serialize()` 生成一次即可：传 `EndPoint` 的 `SendTo` 每次调用都会把它转换成一个新的 `SocketAddress`。`SocketAddress` 重载需要 .NET 8 或更高版本。
- UDP 循环复用了接收数组和消息实例：收到第一个数据报之后，持续接收同一类型的消息，只会为文本变了的字符串和消息里的数组分配内存。

## 按连接复用消息 [#reuse-messages-per-connection]

繁忙的连接会反复反序列化同样几种消息。有两种办法避免为它们分配内存：

<Tabs items={["池化消息", "每种类型一个实例"]}>
<Tab value="池化消息">

给高频消息加上 `[NinoPooled]`。Nino 每次创建实例时都会先从池中取，通过 `Message` 基类型读取 `PriceUpdate` 时也一样。处理完之后把它还回去；这样解码、处理、归还一条池化消息都不会分配内存：

```csharp
[NinoPooled] // [NinoType] 及其格式继承自 Message
public sealed partial class PriceUpdate : Message
{
    public int InstrumentId;
    public long Timestamp;
    public double Bid, Ask;

    private static partial IEnumerable<PriceUpdate> OnNinoPoolWarmup() => null; // 一开始为空
    private partial void OnNinoPoolReturn() { }
}

// 在读取循环中
Message message = NinoDeserializer.Deserialize<Message>(frame);
Handle(message);
if (message is INinoPooled pooled)
    pooled.ReturnToPool();
```

对象池是线程安全的，并且每个线程有自己的栈，所以不同线程上的连接之间不会争用。

</Tab>
<Tab value="每种类型一个实例">

如果消息是同步处理的、处理完不会保留，就用 `ref` 反序列化到上一个实例。下一条消息类型相同时，直接填进这个实例；类型不同时，丢掉旧实例（池化类型会回收到池里）：

```csharp
private Message _last; // 每个连接一个，同一时间只由一个线程使用

void OnFrame(in ReadOnlySequence<byte> frame) // TryReadFrame 取出的每一帧
{
    NinoDeserializer.Deserialize(frame, ref _last);
    Handle(_last);
}
```

</Tab>
</Tabs>

## gRPC [#grpc]

.NET 的 gRPC 并不要求使用 Protocol Buffers：一个方法由 `Method<TRequest, TResponse>` 描述，每种消息类型配一个编组器（marshaller）。Nino 编组器写入 gRPC 提供的缓冲区写入器（经由 Nino 的暂存缓冲区，拷贝一次），收到的负载序列直接交给[序列重载](/zh/docs/v4/advanced/streams#readonlysequence-input)读取，两端都不会为每条消息分配 `byte[]`：

```csharp title="NinoMarshaller.cs"
using Grpc.Core;
using Nino.Core;

public static class NinoMarshaller
{
    public static Marshaller<T> Create<T>() => Marshallers.Create<T>(
        serializer: (value, context) =>
        {
            NinoSerializer.Serialize(value, context.GetBufferWriter());
            context.Complete();
        },
        // 负载保持到达时的样子：只有一个段就原地读取，多个段则复制一次
        deserializer: context => NinoDeserializer.Deserialize<T>(context.PayloadAsReadOnlySequence()));
}

[NinoType] public sealed class GetPriceRequest { public int InstrumentId; }
[NinoType] public sealed class GetPriceReply { public double Bid, Ask; }

public static class PricingMethods
{
    public static readonly Method<GetPriceRequest, GetPriceReply> GetPrice = new(
        MethodType.Unary, "pricing.Pricing", "GetPrice",
        NinoMarshaller.Create<GetPriceRequest>(), NinoMarshaller.Create<GetPriceReply>());
}
```

客户端用 `CallInvoker` 调用这些 `Method` 定义，服务端用 `ServerServiceDefinition.CreateBuilder().AddMethod(...)` 注册；也可以交给支持自定义编组器的 code-first 库。两端都必须是使用相同消息类型的 .NET 程序，这是相对于 `.proto` 契约的取舍；参见[什么时候不适合](/zh/docs/v4#when-not-to-use-it)。

## 线程 [#threads]

- `NinoSerializer` 和 `NinoDeserializer` 可以在任意多个线程上同时调用，无需加锁。
- 但你的缓冲区和复用的消息对象不行：每个连接（或每个发送线程）用一个 `FrameWriter`，并且绝不能让两个线程反序列化到同一个实例。
- 交给其他线程（处理循环、任务队列）的消息，在那个线程用完之前，不能复用，也不能归还到池中。

## 滚动升级 [#rolling-upgrades]

客户端和服务器不总是同一个构建版本时，选格式就要把升级考虑进去：

| 改动 | 按位置 | `NinoFormat.VersionTolerant` | `NinoFormat.Keyed` |
| --- | :---: | :---: | :---: |
| 在消息末尾新增字段 | ✗ | ✓ | ✓ |
| 在 `Message` 基类中新增字段 | ✗ | ✗ 所有消息的字段都会错位 | ✓ |
| 删除或重排字段 | ✗ | ✗ | ✓ |
| 新增消息类型 | 旧对端无法读取 | 旧对端无法读取 | 旧对端无法读取 |

- 在基类上设置 `NinoFormat.VersionTolerant`（所有消息都会继承），旧对端会跳过它不认识的字段，新对端上缺失的字段则保留消息构造函数赋予的值（可以用 `public int Priority = 1;` 这样的字段初始化器为旧版发送方指定默认值）。
- 只向密封的消息类添加字段：`Message` 的成员写在每个消息自己的成员之前，向 `Message` 追加字段会让新旧对端在错误的位置读取彼此的字段（参见[向基类追加成员](/zh/docs/v4/evolving-data#appending-to-a-base-class)）。如果要添加每条消息都带的字段，就把整个继承体系改为 `NinoFormat.Keyed`，或者分别加到每个消息类中。
- 复用或池化的消息是原地填充的，所以缺失的字段保留的是**上一条**消息的值：请在 `OnNinoPoolReturn` 中重置这些字段，或者在还有旧版对端连接时不要复用实例。
- 对端收到**它不认识的消息类型**时无法反序列化，调用会抛出 `NinoDataException`（未知的类型 ID）。请在握手时协商协议版本，只向声明支持的对端发送新的消息类型；如果想交换消息类型列表，`NinoTypeId.Of(typeof(T))` 可以给出每种消息的 ID。
- 如果两端总是一起发布（作为一个整体部署的两个服务、游戏客户端和它的专用服务器），就保持按位置格式：它最小也最快。
- 给消息所在的程序集提交一份[布局基线](/zh/docs/v4/evolving-data#layout-baseline)：改出旧对端读不了的改动时，分析器在你敲代码时就会在改动的成员上报出来（NINO034、NINO035），CI 里 `nino-gen layouts --check` 也会失败。

具体规则参见[数据演进](/zh/docs/v4/evolving-data)。
