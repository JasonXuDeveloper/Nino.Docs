浏览器读写 Nino 字节有两种形式：一是**生成的 TypeScript**，所有 TypeScript 或 JavaScript 前端都推荐用它；二是直接在 WebAssembly 上跑 **.NET**，适合本身就是 .NET 的应用（Blazor WebAssembly），以及少数需要 TypeScript 不支持的成员的前端。本页讲的是跑 .NET 的这两种场景，先对照下表选好路线。

## 选哪条路 [#which-way]

| 浏览器端代码 | 用法 | 代价 |
| --- | --- | --- |
| TypeScript 或 JavaScript（React、Vue、Angular、普通页面），或 Node | **生成的 TypeScript**（推荐）：见 [TypeScript](/zh/docs/v4/advanced/typescript) | 不需要 .NET 运行时，只有普通的 TypeScript 类、编解码器和一个运行时文件 |
| Blazor WebAssembly 应用，或其他已经跑在浏览器里的 .NET 代码 | **和普通 .NET 项目一样用 Nino**：见 [Blazor WebAssembly](#blazor) | 只多一个 Nino.Core 程序集，.NET 本来就已经加载 |
| 需要 TypeScript 不支持的成员（`DateTimeOffset`、多维数组、自定义格式化器，见 [TypeScript 不支持的内容](/zh/docs/v4/advanced/typescript#not-supported)）的 TypeScript 或 JavaScript 前端 | **通过 `[JSExport]` 调用的 .NET 模块**：见[给 JavaScript 用的 .NET 模块](#jsexport) | 浏览器要下载 .NET 运行时（见[权衡](#trade-offs)） |

数据要给人看，或者是给 .NET 以外团队用的公开 API，JSON 可能更合适，见[什么时候不适合](/zh/docs/v4#when-not-to-use-it)。

## 把类型放进共享项目 [#put-the-types-in-a-shared-project]

两种 .NET 用法都从这一步开始。

类型只在一个类库里声明一次（这里是 `net10.0`），服务端和浏览器应用都引用它，类库里装上 Nino（如果是给 Unity 客户端用，目标框架改成 `netstandard2.1`，见[与 .NET 服务端共享类型](/zh/docs/v4/advanced/unity#shared-types)）：

```shell
dotnet new classlib -n Shop.Contracts -f net10.0
dotnet add Shop.Contracts package Nino --prerelease
```

```csharp title="Shop.Contracts/Order.cs"
using System.Collections.Generic;
using Nino.Core;

namespace Shop.Contracts;

[NinoType(format: NinoFormat.VersionTolerant)] // 浏览器和服务器可能在不同时间更新
public class Order
{
    public long Id;
    public string Customer;
    public List<OrderLine> Lines;
}

[NinoType]
public struct OrderLine
{
    public int ProductId;
    public int Quantity;
    public double UnitPrice;
}
```

已经打开的页面在刷新之前会一直跑旧代码（模块或 Blazor 应用），所以和服务端交换的数据要选能容忍变化的格式，参见[数据演进](/zh/docs/v4/evolving-data)。

<Callout type="info">

Nino 的[拦截器](/zh/docs/v4/performance#interceptors)在浏览器里照样工作，规则和平时一样：`[NinoType]` 声明在其他程序集里（比如这里的 `Shop.Contracts`）时，对它们的调用不走拦截器，而是和服务端一样经过格式化器缓存。想让这些调用也走拦截器，就把类型声明在浏览器项目里（或把同一个源文件链接进来）。

</Callout>

## Blazor WebAssembly [#blazor]

Blazor WebAssembly 应用本身就是 .NET，Nino 在里面的用法和服务端一样：Blazor 项目引用共享项目，直接调用 `NinoSerializer` 和 `NinoDeserializer`。不需要 `[JSExport]`，也不需要生成 TypeScript。

```shell
dotnet add Shop.Client reference Shop.Contracts/Shop.Contracts.csproj
```

和服务端不同的地方：

| | Blazor WebAssembly 中 |
| --- | --- |
| HTTP | `HttpClient` 底层走浏览器的 `fetch`；请求体和响应体的读写和其他 .NET 客户端一样（见[客户端](/zh/docs/v4/advanced/aspnetcore#clients)）。Nino.AspNetCore 依赖 ASP.NET Core，只能留在服务端。 |
| SIMD | Nino.Core 的 net10.0 版本在运行时支持时使用 WebAssembly SIMD（见 [SIMD](/zh/docs/v4/simd#dotnet)），各条路径写出的字节都一样 |
| 发布 | 和 Blazor 平时一样裁剪发布：Nino 不会带来裁剪警告，`_framework` 里只多一个程序集（见[权衡](#trade-offs)） |

## 给 JavaScript 用的 .NET 模块 [#jsexport]

TypeScript 或 JavaScript 前端需要生成的 TypeScript 不支持的内容时，可以直接跑 C# 类型：做一个小型 .NET `browser-wasm` 应用，引用 Nino 和共享项目，用 `[JSExport]` 导出几个函数，再从前端调用。浏览器跑的就是服务端那套类型和生成的格式化器，所有成员类型都能用，字节也完全一样；JavaScript 这边只看到 `Uint8Array`、数字、字符串和数组。代价是要下载并启动 .NET 运行时（见[权衡](#trade-offs)）。

下面的代码都来自一个用 .NET 10 SDK 构建、在无头 Chromium 中实际跑过的项目。在这个项目里，浏览器序列化出的订单和 .NET 10 控制台程序序列化的同一订单逐字节相同，浏览器也能解码控制台程序和 ASP.NET Core 接口发来的字节。

<Step>

### 创建浏览器项目 [#create-the-browser-project]

`browser-wasm` 应用就是一个使用 `Microsoft.NET.Sdk.WebAssembly` SDK 的普通项目：

```xml title="Shop.Browser/Shop.Browser.csproj"
<Project Sdk="Microsoft.NET.Sdk.WebAssembly">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <OutputType>Exe</OutputType>
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks> <!-- [!code highlight] -->
    <InvariantGlobalization>true</InvariantGlobalization>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="../Shop.Contracts/Shop.Contracts.csproj" />
  </ItemGroup>
</Project>
```

```csharp title="Shop.Browser/Program.cs"
// 运行时由 JavaScript 启动，Main 什么都不用做。
return;
```

- `AllowUnsafeBlocks` 是 `[JSExport]` 生成器的要求（缺少时报 SYSLIB1075 错误），与 Nino 无关。
- 不需要安装任何 workload：项目用普通的 .NET SDK 即可构建和发布。只有 AOT 编译或原生重链接才需要 `wasm-tools` workload。
- `InvariantGlobalization` 是可选的，用来去掉编解码用不到的区域性数据。

</Step>
<Step>

### 用 `[JSExport]` 导出函数 [#export-functions-with-jsexport]

写一个 `static partial class`，里面的方法给 JavaScript 调用。粒度要粗：每条消息调一次，具体的活交给 C# 干。

```csharp title="Shop.Browser/OrderCodec.cs"
using System.Collections.Generic;
using System.Runtime.InteropServices.JavaScript;
using System.Runtime.Versioning;
using Nino.Core;
using Shop.Contracts;

namespace Shop.Browser;

[SupportedOSPlatform("browser")] // 消除互操作特性上的 CA1416 警告
public static partial class OrderCodec
{
    // 传入 JavaScript 值，返回 Nino 字节
    [JSExport]
    public static byte[] EncodeOrder(
        [JSMarshalAs<JSType.Number>] long id,
        string customer,
        int[] productIds,
        int[] quantities,
        double[] unitPrices)
    {
        var order = new Order { Id = id, Customer = customer, Lines = new List<OrderLine>(productIds.Length) };
        for (int i = 0; i < productIds.Length; i++)
            order.Lines.Add(new OrderLine { ProductId = productIds[i], Quantity = quantities[i], UnitPrice = unitPrices[i] });
        return NinoSerializer.Serialize(order); // [!code highlight]
    }

    // 传入 Nino 字节，返回界面需要的数据
    // WebAssembly 只有一个线程：所有导出函数共用一个 Order 和它的列表，每次调用都原地重新填充
    private static Order _order = new();

    [JSExport]
    public static string GetCustomer(byte[] data)
    {
        NinoDeserializer.Deserialize(data, ref _order); // [!code highlight]
        return _order.Customer;
    }

    [JSExport]
    [return: JSMarshalAs<JSType.Number>]
    public static long GetId(byte[] data)
    {
        NinoDeserializer.Deserialize(data, ref _order);
        return _order.Id;
    }

    [JSExport]
    public static double GetTotal(byte[] data)
    {
        NinoDeserializer.Deserialize(data, ref _order);
        double total = 0;
        foreach (OrderLine line in _order.Lines) total += line.Quantity * line.UnitPrice;
        return total;
    }

    [JSExport]
    public static int CountLines(byte[] data)
    {
        NinoDeserializer.Deserialize(data, ref _order);
        return _order.Lines.Count;
    }
}
```

本例中 `[JSExport]` 的类型映射：

| C# | JavaScript |
| --- | --- |
| `byte[]` | `Uint8Array`（每个方向跨边界时都会复制） |
| `int[]`、`double[]` | 数字数组 |
| `string`、`int`、`double` | `string`、`number` |
| 带 `[JSMarshalAs<JSType.Number>]` 的 `long` | `number`（2^53 以内精确） |
| 带 `[JSMarshalAs<JSType.BigInt>]` 的 `long` | `bigint` |

`long` 必须写明映射成这两种里的哪一种。标了 `[JSMarshalAs<JSType.MemoryView>]` 的 `Span<byte>` 参数收不了 JavaScript 传来的 `Uint8Array`（调用失败，报 `Expected MemoryViewType.Byte`），所以参数用 `byte[]`。

</Step>

### 在 JavaScript 中加载模块 [#load-the-module-from-javascript]

在项目的 `wwwroot` 文件夹中添加一个页面和一个模块脚本：

```html title="Shop.Browser/wwwroot/index.html"
<!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <script type="module" src="./main.js"></script>
  </head>
  <body></body>
</html>
```

```js title="Shop.Browser/wwwroot/main.js"
import { dotnet } from './_framework/dotnet.js';

const runtime = await dotnet.create();
const exports = await runtime.getAssemblyExports('Shop.Browser.dll');
const codec = exports.Shop.Browser.OrderCodec; // 先命名空间，再类名 // [!code highlight]

const bytes = codec.EncodeOrder(42, 'Ada', [7, 9], [2, 1], [9.5, 20]); // 一个 Uint8Array
codec.GetTotal(bytes); // 39
```

导出函数按命名空间和类名访问：上例中是 `Shop.Browser.OrderCodec`。

发布后，用任意静态 Web 服务器托管输出目录：

```shell
dotnet publish Shop.Browser -c Release
# 托管 Shop.Browser/bin/Release/net10.0/publish/wwwroot 目录
```

</Step>

### 在 TypeScript 中为导出函数声明类型 [#type-the-exports-in-typescript]

`getAssemblyExports` 返回 `any`。导出函数是你自己写的，请手写它们的类型声明，放在 `OrderCodec.cs` 旁边，C# 签名变化时同步更新：

```ts title="order-codec.d.ts"
export interface OrderCodec {
  EncodeOrder(id: number, customer: string, productIds: number[], quantities: number[], unitPrices: number[]): Uint8Array;
  GetCustomer(data: Uint8Array): string;
  GetId(data: Uint8Array): number;
  GetTotal(data: Uint8Array): number;
  CountLines(data: Uint8Array): number;
}
```

```ts title="main.ts"
import { dotnet } from './_framework/dotnet.js';
import type { OrderCodec } from './order-codec';

const runtime = await dotnet.create();
const exports = await runtime.getAssemblyExports('Shop.Browser.dll');
const codec: OrderCodec = exports.Shop.Browser.OrderCodec;
```

这里描述的只是几个函数，而不是数据模型：类型本身仍然只在 C# 中定义。

</Step>

### 发送与接收 [#sending-and-receiving]

字节就是普通的 `Uint8Array`，任何能传二进制数据的浏览器 API 都能用。

使用 `fetch` 时，把字节作为请求体发送，并以 `ArrayBuffer` 读取响应：

```js
const reply = await fetch('/orders', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-nino' },
  body: codec.EncodeOrder(42, 'Ada', [7, 9], [2, 1], [9.5, 20]),
});
const replyBytes = new Uint8Array(await reply.arrayBuffer());
codec.GetCustomer(replyBytes);
```

服务端用同一个 `Order` 类型反序列化并应答。使用 [Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore) 时，接口以 `NinoBody<Order>` 接收请求体，返回 `NinoResults.Ok`，两者都是 `application/x-nino`：

```csharp title="Program.cs (ASP.NET Core)"
app.MapPost("/orders", (NinoBody<Order> order) =>
{
    // ... 处理 order.Value ...
    return NinoResults.Ok(order.Value);
});
```

使用 WebSocket 时，把 `binaryType` 设为 `'arraybuffer'`；每条 WebSocket 消息就是一个 Nino 负载，无需分帧：

```js
const socket = new WebSocket(`wss://${location.host}/ws`);
socket.binaryType = 'arraybuffer';
socket.onopen = () => socket.send(codec.EncodeOrder(7, 'Grace', [1], [3], [2.5]));
socket.onmessage = (e) => {
  const data = new Uint8Array(e.data);
  console.log(codec.GetTotal(data)); // 每条消息只调一次、只解码一次
};
```

服务端读写 WebSocket 消息的方法见 [WebSocket 与 UDP](/zh/docs/v4/advanced/networking#websocket-and-udp)。

## 权衡 [#trade-offs]

**下载体积。** 浏览器除了你的代码，还要下载 .NET 运行时；Blazor 应用本来就要付这笔，Nino 只多出 `Nino.Core` 这一行。上面的模块用 .NET 10.0.404 SDK（运行时 10.0.15）以 Release 模式裁剪发布后：

| `_framework` 中的文件 | 未压缩 | Brotli | Gzip |
| --- | --- | --- | --- |
| 全部（运行时、CoreLib、Nino、应用） | 5.18 MB | 1.72 MB | 2.09 MB |
| `Nino.Core` | 352 KB | 179 KB | |
| `dotnet.native.wasm`（运行时） | 3.00 MB | 0.98 MB | |

`dotnet publish` 会在每个文件旁边生成 `.br` 和 `.gz` 副本；请配置服务器直接提供它们，并对 `_framework` 设置长期缓存（文件名中带有内容哈希）。

**启动时间。** 运行时下载并启动完成之前，无法编码或解码任何数据。在测试中（无头 Chromium，从 localhost 加载），页面从开始导航到得到第一批解码结果用时 0.4 到 0.7 秒；在真实网络中，下载时间占大头。运行时要在页面加载时就启动，别等到第一条消息才启动。

**跨越边界**（仅限模块）。每次调用都会在 JavaScript 内存和 WebAssembly 内存之间复制 `byte[]` 参数和返回值。导出少量粗粒度的函数（编码一条消息、解码视图需要的字段），而不是为每个成员导出一个 getter。

**裁剪。** Nino.Core 标记为可裁剪、兼容 AOT，生成的代码也带有裁剪器需要的标注，因此裁剪发布时 Nino 不会产生警告。上线前仍请用 Release 发布验证你自己的类型。
