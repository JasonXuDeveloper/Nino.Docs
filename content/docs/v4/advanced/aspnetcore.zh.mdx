**Nino.AspNetCore** 让 ASP.NET Core 用 Nino 读取请求体、写出响应，媒体类型为 `application/x-nino`：为 MVC 控制器提供输入和输出格式化器，为 Minimal API 提供一个参数类型和一组结果类型。请求体直接在请求管道里反序列化，不用复制；响应直接序列化进响应管道。所以读请求体、写响应时，除了值本身，不再分配任何内存。

<Callout type="info">

Nino.AspNetCore 的目标框架是 `net8.0` 和 `net10.0`。

</Callout>

## 安装 [#install]

```shell
dotnet add package Nino --prerelease             # 声明 [NinoType] 的项目
dotnet add package Nino.AspNetCore --prerelease  # Web 项目
```

用到的类型就是你已经在序列化的类型：任何 `[NinoType]`、内置类型，或有[自定义格式化器](/zh/docs/v4/custom-formatters)的类型。客户端和服务端不同时更新时，需要[能容忍变化的格式](/zh/docs/v4/evolving-data)。

本页的例子使用下面这些类型。把它们声明在服务端和 .NET 客户端都引用的类库里，并在类库中安装 `Nino`（[把类型放进共享项目](/zh/docs/v4/advanced/browser#put-the-types-in-a-shared-project)）：

```csharp title="Shop.Contracts/Order.cs"
using Nino.Core;

[NinoType]
public class Order
{
    public int Id;
    public string Customer;
}

[NinoType]
public abstract class Shape { }

public sealed class Circle : Shape { public double Radius; }

public sealed class Square : Shape { public double Side; }
```

## MVC 控制器 [#mvc]

在 `AddControllers()`、`AddMvc()` 或 `AddMvcCore()` 之后调用 `AddNinoFormatters()`，把格式化器加入 MVC：

```csharp title="Program.cs"
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.DependencyInjection;
using Nino.AspNetCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers().AddNinoFormatters(); // [!code highlight]

var app = builder.Build();
app.MapControllers();
app.Run();
```

```csharp title="OrdersController.cs"
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("orders")]
public class OrdersController : ControllerBase
{
    [HttpPost]
    public Order Create([FromBody] Order order) => Save(order);  // 读取 application/x-nino

    [HttpGet("{id}.{format?}")]
    [FormatFilter]                                               // /orders/42.nino 或 ?format=nino
    public Order Get(int id) => Load(id);

    [HttpGet("shape")]
    public ActionResult<Shape> GetShape() => new Circle { Radius = 2.5 };
}
```

- **内容协商。** 格式化器添加在已有格式化器之后，所以对接受任意格式的客户端，默认仍是 JSON。`Content-Type: application/x-nino` 的请求用 Nino 读取；发送 `Accept: application/x-nino` 的客户端，或在 `[FormatFilter]` 下把 `format` 设为 `nino` 的 URL，会得到 Nino 响应。JSON 客户端拿到的是 `System.Text.Json` 的输出，它默认只写公共属性：只有公共字段的类型（这份文档里的大多数 `[NinoType]` 都是这样）会输出 `{}`。如果 JSON 客户端也读这些类型，打开 `IncludeFields`：MVC 用 `AddControllers().AddJsonOptions(o => o.JsonSerializerOptions.IncludeFields = true)`，Minimal API 用 `builder.Services.ConfigureHttpJsonOptions(o => o.SerializerOptions.IncludeFields = true)`。
- **只处理 Nino 支持的类型。** 只有 `NinoSerializer.IsSupported(type)` 为 true 时（true 按类型缓存；false 只在 Native AOT 下缓存，之后才注册的格式化器照样认得出），格式化器才会接手这个类型，其他类型都留给别的格式化器。
- **格式化器类。** `AddNinoFormatters()` 添加的是 `NinoInputFormatter` 和 `NinoOutputFormatter`，并把格式名 `nino` 映射到 `application/x-nino`。想让接受任意格式的客户端默认拿到 Nino，就不调用 `AddNinoFormatters()`，自己把这两个格式化器插到 `MvcOptions.InputFormatters` 和 `MvcOptions.OutputFormatters` 的最前面（`options.OutputFormatters.Insert(0, new NinoOutputFormatter())`）；用到 `[FormatFilter]` 时，再用 `options.FormatterMappings.SetMediaTypeMappingForFormat(NinoMediaTypes.Format, NinoMediaTypes.Application)` 映射格式名。
- **按声明的类型写出。** 结果按 action 声明的类型序列化，与用这个类型作 `T` 调用 `Serialize<T>` 相同：`ActionResult<Shape>` 返回一个 `Circle` 时，写出的是 `Circle` 的类型 ID，按 `Shape` 读取的客户端拿回的仍是 `Circle`。参见[多态](/zh/docs/v4/polymorphism)。
- **无效数据返回 400。** Nino 读不了的请求体（截断了、损坏了，或者是按别的类型写的）记为模型状态错误，`[ApiController]` 返回 400。只有无效数据（`NinoDataException`）这样处理：服务端读取时自己出的错（比如 `[NinoFactory]` 返回了 null）照常作为服务器错误抛出。

## Minimal API [#minimal-apis]

参数用 `NinoBody<T>`，返回 `NinoResults.Ok(value)` 或 `NinoResults.Status(statusCode, value)`：

```csharp title="Program.cs"
using Microsoft.AspNetCore.Builder;
using Nino.AspNetCore;

app.MapPost("/orders", (NinoBody<Order> order) => NinoResults.Ok(Save(order.Value)));
app.MapPost("/orders/new", (NinoBody<Order> order) => NinoResults.Status(201, Save(order.Value)));
app.MapGet("/shape", () => NinoResults.Ok<Shape>(new Square { Side = 3 })); // 按 Shape 写出，带 Square 的类型 ID
```

- **`NinoBody<T>`** 绑定请求体，值在 `order.Value` 中。其他内容类型的请求得到 415，不是有效 `T` 的请求体得到 400。
- **`NinoResults.Ok` 和 `NinoResults.Status`** 返回 `NinoResult<T>`，它按 `T` 写出值，内容类型为 `application/x-nino`。要把子类型按基类写出，显式指定 `T`。
- **OpenAPI** 能看到两者：`NinoBody<T>` 声明这个接口接受 `application/x-nino` 格式的 `T`，`NinoResult<T>` 声明它返回 `application/x-nino` 格式的 `T`。

## 手动读写 [#by-hand]

在任何处理程序或中间件中，`HttpRequest.ReadFromNinoAsync<T>()` 把整个请求体读成一个 `T`，`HttpResponse.WriteAsNinoAsync(value)` 写出一个值：

```csharp title="Program.cs"
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Nino.AspNetCore;

app.MapPost("/orders/bump", async (HttpContext context) =>
{
    Order order = await context.Request.ReadFromNinoAsync<Order>(context.RequestAborted);
    order.Id++;
    await context.Response.WriteAsNinoAsync(order, context.RequestAborted);
});
```

请求的内容类型不是 `application/x-nino` 时，`ReadFromNinoAsync` 抛出 `InvalidOperationException`（可以先用 `request.HasNinoContentType()` 检查）；请求体不是有效的 `T` 时，抛出状态码为 400 的 `BadHttpRequestException`。`WriteAsNinoAsync` 会设置响应的内容类型。媒体类型和格式名都是常量：`NinoMediaTypes.Application`（`application/x-nino`）和 `NinoMediaTypes.Format`（`nino`）。

## 客户端 [#clients]

.NET 客户端用 `NinoSerializer` 和 `NinoDeserializer` 发送和读取字节。客户端只需要 `Nino` 包和共享的类型，不需要 Nino.AspNetCore：它依赖 ASP.NET Core，装不进 MAUI、Blazor WebAssembly 或 Unity 客户端（Unity 项目怎么拿到共享类型，见[与 .NET 服务端共享类型](/zh/docs/v4/advanced/unity#shared-types)）：

```csharp title="Client.cs"
using System;
using System.Net.Http;
using System.Net.Http.Headers;
using Nino.Core;

const string NinoMediaType = "application/x-nino"; // 即服务端的 NinoMediaTypes.Application
using var http = new HttpClient { BaseAddress = new Uri("https://localhost:5001") };

var order = new Order { Customer = "Ada" };
using var content = new ByteArrayContent(NinoSerializer.Serialize(order));
content.Headers.ContentType = new MediaTypeHeaderValue(NinoMediaType);
using var request = new HttpRequestMessage(HttpMethod.Post, "/orders") { Content = content };
request.Headers.Accept.Add(new MediaTypeWithQualityHeaderValue(NinoMediaType));

using HttpResponseMessage response = await http.SendAsync(request);
response.EnsureSuccessStatusCode(); // 错误响应是 problem+json，不是 Nino
Order saved = await NinoDeserializer.DeserializeAsync<Order>(await response.Content.ReadAsStreamAsync());
```

`DeserializeAsync` 从响应内容的流里读，读进从 `ArrayPool<byte>.Shared` 租来的数组，客户端不用为响应体分配 `byte[]`（[异步](/zh/docs/v4/advanced/streams#async)）。

<Callout title="rc.9 及更早的版本">

`Stream` 重载是 rc.10 新增的：先用 `ReadAsByteArrayAsync()` 读出响应体，再把数组交给 `NinoDeserializer.Deserialize<Order>`。

</Callout>

浏览器或 Node 客户端可以使用 [Nino.Codegen](/zh/docs/v4/advanced/typescript#with-aspnet-core) 从同一组类型生成的编解码器，Blazor WebAssembly 客户端则和其他 .NET 客户端一样使用 Nino（[浏览器中的 .NET](/zh/docs/v4/advanced/browser#which-way)）。

## 请求体和响应怎么读写 [#performance]

- **请求**从请求的 `PipeReader` 读取。有 `Content-Length` 时，读取方一次等到整个请求体到齐，而不是每来一个分段就唤醒一次。整个落在一个分段里的请求体，直接在这个分段上反序列化；只有跨多个分段的请求体才会复制一次，复制到从 `ArrayPool<byte>.Shared` 租来的缓冲区，读完即归还。
- **响应**直接序列化进响应的 `PipeWriter`，没有中间的 `byte[]`。
- **自身不做分配。** 内容类型直接在请求头的字符上检查，不解析成对象；已经到达管道的请求体（最常见：小请求体和请求头一起到达）不经过 async 方法，直接读取；还没完整到达的，才由 async 方法等待，这个方法的状态机来自对象池；立即完成的刷新返回缓存的 Task。Nino 的测试测得：在值本身反序列化不分配的情况下，读取请求体和写出响应分配的字节数都是零。
- **请求体先完整缓冲再读取。** Nino 反序列化的是完整的值，请求体会一直留在管道里，直到全部到达；它和其他请求体一样，受 ASP.NET Core 请求体大小上限（Kestrel 的 `MaxRequestBodySize`）的限制。
