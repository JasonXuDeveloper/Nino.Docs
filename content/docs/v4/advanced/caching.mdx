A cache stores values as bytes: Redis strings, `IDistributedCache` entries, memcached items, or `byte[]` in a dictionary of your own. Nino turns a value into those bytes and back with no reflection and no per-call allocations of its own, and the payload is compact, so more entries fit in the same memory and less data crosses the network.

The examples below use a profile type:

```csharp title="UserProfile.cs"
using System;
using System.Collections.Generic;
using Nino.Core;

[NinoType(format: NinoFormat.VersionTolerant)] // cached data outlives a deployment, see below
public sealed class UserProfile
{
    public long Id;
    public string DisplayName;
    public string Email;
    public DateTime UpdatedAt;
    public List<string> Roles;
}
```

## Redis [#redis]

Any Redis client takes and returns values as bytes. With [StackExchange.Redis](https://stackexchange.github.io/StackExchange.Redis/), serialize into a reused buffer and pass its memory directly, and read with `StringGetLease`, which hands you pooled bytes instead of a new `byte[]`:

```csharp title="RedisProfileCache.cs"
using System;
using Nino.Core;
using StackExchange.Redis;

public sealed class RedisProfileCache
{
    private readonly IDatabase _db;
    [ThreadStatic] private static NinoArrayBufferWriter t_buffer;

    public RedisProfileCache(IConnectionMultiplexer redis) => _db = redis.GetDatabase();

    private static RedisKey Key(long id) => $"profile:v1:{id}"; // the key carries a schema version

    public void Set(UserProfile profile, TimeSpan ttl)
    {
        var buffer = t_buffer ??= new NinoArrayBufferWriter(1024);
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(profile, buffer); // [!code highlight]
        try
        {
            _db.StringSet(Key(profile.Id), buffer.WrittenMemory, ttl); // synchronous: done before the buffer is reused
        }
        catch
        {
            t_buffer = null; // a command that timed out may still be sent later: never reuse its buffer
            throw;
        }
    }

    public UserProfile Get(long id)
    {
        using Lease<byte> lease = _db.StringGetLease(Key(id));      // pooled bytes, no byte[] per read
        if (lease == null)
            return null;
        return NinoDeserializer.Deserialize<UserProfile>(lease.Span);
    }
}
```

The Redis calls are an illustration; the Nino part is the same with any client. If you use the async API (`StringSetAsync`), await it before the buffer is reset, or serialize with `NinoSerializer.Serialize(profile)` and pass the `byte[]`.

## IDistributedCache [#idistributedcache]

`IDistributedCache` (Redis, SQL Server, and other ASP.NET Core cache providers) stores `byte[]`. Two extension methods are enough:

```csharp title="DistributedCacheExtensions.cs"
using System.Threading;
using System.Threading.Tasks;
using Microsoft.Extensions.Caching.Distributed;
using Nino.Core;

public static class DistributedCacheExtensions
{
    public static Task SetNinoAsync<T>(this IDistributedCache cache, string key, T value,
        DistributedCacheEntryOptions options, CancellationToken ct = default) =>
        cache.SetAsync(key, NinoSerializer.Serialize(value), options, ct);

    public static async Task<T> GetNinoAsync<T>(this IDistributedCache cache, string key,
        CancellationToken ct = default)
    {
        byte[] bytes = await cache.GetAsync(key, ct);
        return bytes == null ? default : NinoDeserializer.Deserialize<T>(bytes);
    }
}
```

The interface takes and returns arrays, so each call allocates one `byte[]`: that is the cache API's cost, not Nino's. Providers that also implement `IBufferDistributedCache` (Microsoft.Extensions.Caching.StackExchangeRedis 10 does) read and write through buffers instead; `HybridCache`, below, uses that interface when the provider has it, so for a hot cache use `HybridCache` rather than these two methods.

A store that hands you a `Stream` instead (a blob container, an S3 object, a file cache) needs no buffer of yours: `await NinoSerializer.SerializeAsync(profile, upload, ct)` writes the profile, and `await NinoDeserializer.DeserializeAsync<UserProfile>(download, ct)` reads it back ([Async](/en/docs/v4/advanced/streams#async)).

## HybridCache [#hybridcache]

`HybridCache` (the `Microsoft.Extensions.Caching.Hybrid` package) hands a serializer an `IBufferWriter<byte>` to write into and a `ReadOnlySequence<byte>` to read from, which matches Nino's API directly:

```csharp title="NinoHybridSerializer.cs"
using System.Buffers;
using Microsoft.Extensions.Caching.Hybrid;
using Nino.Core;

public sealed class NinoHybridSerializer<T> : IHybridCacheSerializer<T>
{
    public void Serialize(T value, IBufferWriter<byte> target) => NinoSerializer.Serialize(value, target);

    public T Deserialize(ReadOnlySequence<byte> source) => NinoDeserializer.Deserialize<T>(source); // [!code highlight]
}
```

`Deserialize` reads the sequence where it lies when it is one segment, and copies it once into a pooled buffer when it is several ([Multi-Segment Input](/en/docs/v4/advanced/streams#readonlysequence-input)).

- Register one serializer per cached type, with `AddSerializer` (see [Register Them](#registration)).
- `HybridCache`'s buffer writer is not a `NinoArrayBufferWriter`, so Nino serializes into its per-thread scratch buffer and copies the result in once. Nothing is allocated per call.
- Calls inside the generic serializer are not [intercepted](/en/docs/v4/performance#interceptors), because `T` is a type parameter there; they take the regular path, a few nanoseconds more per call.

<Callout title="On rc.9 and earlier">

`NinoDeserializer` reads a `ReadOnlySequence<byte>` since rc.10. On earlier releases, return the [sequence helper for rc.9 and earlier](/en/docs/v4/advanced/streams#sequence-helpers-rc9) from `Deserialize` instead.

</Callout>

## Register Them [#registration]

The three adapters above need their clients registered in the host. With the packages

```shell
dotnet add package Nino --prerelease
dotnet add package StackExchange.Redis
dotnet add package Microsoft.Extensions.Caching.StackExchangeRedis
dotnet add package Microsoft.Extensions.Caching.Hybrid
```

an ASP.NET Core host that uses all three looks like this (keep the ones you use):

```csharp title="Program.cs"
using System.Threading;
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.Caching.Distributed;
using Microsoft.Extensions.Caching.Hybrid;
using Microsoft.Extensions.DependencyInjection;
using StackExchange.Redis;

var builder = WebApplication.CreateBuilder(args);
const string redis = "localhost:6379";

// StackExchange.Redis directly: one multiplexer for the process
builder.Services.AddSingleton<IConnectionMultiplexer>(_ => ConnectionMultiplexer.Connect(redis));
builder.Services.AddSingleton<RedisProfileCache>();

// IDistributedCache on Redis
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = redis;
    options.InstanceName = "dc:"; // a key space of its own: RedisProfileCache writes profile:v1:* in the same Redis
});

// HybridCache: memory in front of that IDistributedCache, with Nino for the profiles
builder.Services.AddHybridCache()
    .AddSerializer<UserProfile, NinoHybridSerializer<UserProfile>>(); // [!code highlight]

var app = builder.Build();
app.MapGet("/profiles/{id}", (long id, HybridCache cache, CancellationToken ct) =>
    cache.GetOrCreateAsync($"profile:v1:{id}", id, static (profileId, token) => LoadProfileAsync(profileId, token), // the state overload: no closure per request
        cancellationToken: ct));
// HybridCache stores its own envelope under its key in the same IDistributedCache: read raw entries under keys SetNinoAsync writes
app.MapGet("/profiles/{id}/stored", (long id, IDistributedCache cache, CancellationToken ct) =>
    cache.GetNinoAsync<UserProfile>($"profile-blob:v1:{id}", ct));
app.Run();
```

<Callout type="info" title="What this code was tested against">

The C# on this page is compiled against StackExchange.Redis 3, Microsoft.Extensions.Caching.StackExchangeRedis 10 and Microsoft.Extensions.Caching.Hybrid 10 on every change to this site. `DistributedCacheExtensions`, `NinoHybridSerializer` and `BlobCache` were run in a test, with an in-memory `IDistributedCache` standing in for Redis behind two `HybridCache` instances; `RedisProfileCache` and the Redis connection were not run, so check those settings against the Redis documentation.

</Callout>

## In-Process Blob Caches [#in-process-blob-caches]

An in-process cache usually holds live objects. Holding the serialized bytes instead has three effects:

- **Isolation.** Every read deserializes a fresh copy, so a caller that modifies its value cannot corrupt the cached one or race with another thread.
- **Footprint.** A `byte[]` is one object for the garbage collector to track, instead of a graph of objects, lists and strings.
- **Reuse.** A caller that keeps an instance can deserialize into it with `ref`, allocating nothing but the strings whose text changed.

```csharp title="BlobCache.cs"
using System.Collections.Concurrent;
using Nino.Core;

/// <summary>Holds values as bytes: compact, and every reader gets its own copy.</summary>
public sealed class BlobCache<TKey, TValue>
{
    private readonly ConcurrentDictionary<TKey, byte[]> _entries = new();

    // the entry is the array: Serialize(value) allocates it at its exact size
    public void Set(TKey key, TValue value) => _entries[key] = NinoSerializer.Serialize(value);

    public bool TryGet(TKey key, out TValue value)
    {
        if (_entries.TryGetValue(key, out byte[] bytes))
        {
            value = NinoDeserializer.Deserialize<TValue>(bytes);
            return true;
        }
        value = default;
        return false;
    }

    /// <summary>Reads into an instance the caller keeps: once it has the right shape, only changed strings allocate.</summary>
    public bool TryGetInto(TKey key, ref TValue value)
    {
        if (!_entries.TryGetValue(key, out byte[] bytes))
            return false;
        NinoDeserializer.Deserialize(bytes, ref value);
        return true;
    }
}
```

The trade-off is a deserialization per read. For values read far more often than they change and never modified by readers, caching the objects themselves is cheaper.

## Schema Changes Across Deployments [#schema-changes]

A shared cache outlives the process that wrote it: during a rolling deployment, old and new instances read each other's entries. Pick one of the first two approaches for every cached type, and add the third:

| Approach | How | When |
| --- | --- | --- |
| Tolerant types | [`format: NinoFormat.VersionTolerant`](/en/docs/v4/evolving-data#version-tolerance) (append members) or [`format: NinoFormat.Keyed`](/en/docs/v4/evolving-data#keyed-members) (any change) | Entries should survive the deployment. |
| Versioned keys | Put a schema version in the key (`profile:v2:42`) and bump it when the type changes | The type changes in ways the options above do not cover, or the cache is cheap to refill. |
| Treat failures as misses | Catch the `NinoDataException` that invalid data throws, delete the entry and load from the source | Always, as a safety net on top of either approach. |

The safety net does not replace the other two: bytes written for a different type with a compatible layout can deserialize without an error. With tolerant types, commit a [layout baseline](/en/docs/v4/evolving-data#layout-baseline) for the cached types' assembly: a change that entries written by the running deployment cannot survive is then reported on the member you changed, as you type (NINO034, NINO035).

A [positional](/en/docs/v4/evolving-data#positional) type (bare `[NinoType]`) is the smallest and fastest, but any change to its members makes old entries unreadable. Use it for cached values only together with versioned keys.

Nino checks every length and bound while reading, so a truncated or corrupt entry throws instead of reading out of range. The bytes carry no schema, though: see [Invalid Data](/en/docs/v4/basic#invalid-data).

## Checklist [#checklist]

- [ ] Every cached type is `NinoFormat.VersionTolerant` or `NinoFormat.Keyed`, or its keys carry a schema version.
- [ ] Writes reuse a buffer per thread; async writes await before the buffer is reset.
- [ ] Reads deserialize from the client's pooled memory (`Lease<byte>`, a `ReadOnlySequence<byte>`) where the client offers it.
- [ ] Deserialization failures are treated as cache misses.
