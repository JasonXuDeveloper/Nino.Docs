Nino 序列化到 `IBufferWriter<byte>`，从 `ReadOnlySpan<byte>` 反序列化。流、异步 I/O、多段输入、序列化回调和压缩，在这两个调用之上多写几行就能实现。本页为每一种都给出了可以直接复制的写法。

## 流 [#streams]

流没有消息边界，所以每个值都写成一帧：先是 4 字节小端序的长度，再是数据。`Writer` 先预留长度的位置，接着序列化值，最后回填长度，全部在同一个缓冲区里完成：

```csharp title="NinoStream.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static class NinoStream
{
    public const int MaxFrameSize = 16 << 20; // reject absurd lengths before renting a buffer

    // [int32 length][payload], built in buffer
    public static void Frame<T>(T value, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        var writer = new Writer(buffer);
        int slot = writer.ReserveInt32();
        NinoSerializer.Serialize(value, ref writer);
        writer.PatchLength(slot);   // bytes written after the slot
        writer.Flush();
    }

    public static void Write<T>(Stream stream, T value, NinoArrayBufferWriter buffer)
    {
        Frame(value, buffer);
        stream.Write(buffer.WrittenSpan);
    }

    public static T Read<T>(Stream stream)
    {
        byte[] prefix = new byte[4];
        Fill(stream, prefix, 4);
        int length = ReadLength(prefix);

        byte[] payload = ArrayPool<byte>.Shared.Rent(length);
        try
        {
            Fill(stream, payload, length);
            return NinoDeserializer.Deserialize<T>(payload.AsSpan(0, length));
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(payload);
        }
    }

    // Stream.ReadExactly does the same on .NET 7+; this loop runs everywhere, including Unity
    private static void Fill(Stream stream, byte[] buffer, int count)
    {
        for (int read = 0; read < count; )
        {
            int n = stream.Read(buffer, read, count - read);
            if (n == 0) throw new EndOfStreamException();
            read += n;
        }
    }

    private static int ReadLength(ReadOnlySpan<byte> prefix)
    {
        int length = BinaryPrimitives.ReadInt32LittleEndian(prefix);
        if ((uint)length > MaxFrameSize)
            throw new InvalidDataException($"Frame of {length} bytes");
        return length;
    }
}
```

```csharp
using var buffer = new NinoArrayBufferWriter(); // one per thread or connection
using (var file = File.Create(path))
    NinoStream.Write(file, save, buffer);

using (var file = File.OpenRead(path))
    save = NinoStream.Read<SaveGame>(file);
```

一串值（其他库用 `IAsyncEnumerable<T>` 流式传输的那种）就是连续的帧：每个元素写一帧，读到流结束为止。帧格式与[网络层指南](/zh/docs/v4/advanced/networking#frame-the-stream)相同，两边可以混用。

## 异步 [#async]

`Writer` 是 `ref struct`，不能用在 `async` 方法里，所以先用 `Frame` 同步构建帧，再 await I/O。把下面几个方法加到 `NinoStream` 中：

```csharp
public static async ValueTask WriteAsync<T>(Stream stream, T value, NinoArrayBufferWriter buffer,
    CancellationToken ct = default)
{
    Frame(value, buffer);
    await stream.WriteAsync(buffer.WrittenMemory, ct);
}

public static async ValueTask<T> ReadAsync<T>(Stream stream, CancellationToken ct = default)
{
    byte[] prefix = new byte[4];
    await FillAsync(stream, prefix, 4, ct);
    int length = ReadLength(prefix);

    byte[] payload = ArrayPool<byte>.Shared.Rent(length);
    try
    {
        await FillAsync(stream, payload, length, ct);
        return NinoDeserializer.Deserialize<T>(payload.AsSpan(0, length));
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(payload);
    }
}

private static async ValueTask FillAsync(Stream stream, byte[] buffer, int count, CancellationToken ct)
{
    for (int read = 0; read < count; )
    {
        int n = await stream.ReadAsync(buffer, read, count - read, ct);
        if (n == 0) throw new EndOfStreamException();
        read += n;
    }
}
```

`Fill` 和 `FillAsync` 在所有目标上都能用；在 .NET 7 及以上，也可以换成 `Stream.ReadExactly` / `ReadExactlyAsync`。`stream.Write(span)` 和 `WriteAsync(memory)` 需要 .NET Standard 2.1（Unity 2022.3 满足）；只面向 .NET Standard 2.0 时，用 `MemoryMarshal.TryGetArray(buffer.WrittenMemory, out var segment)` 取出数组，再调用 `Write(segment.Array, segment.Offset, segment.Count)`。

使用 `System.IO.Pipelines` 时，直接序列化到 `PipeWriter`（它就是 `IBufferWriter<byte>`），再从 `PipeReader` 中读取帧。完整的读取循环参见[读取帧](/zh/docs/v4/advanced/networking#reading-frames)，它解码每一帧的方式与下面的工具方法相同。

## 多段输入（`ReadOnlySequence`） [#readonlysequence-input]

`PipeReader` 或 `SequenceReader` 给出的是 `ReadOnlySequence<byte>`。只有一段时直接原地反序列化；有多段时，先拷贝一次到池化的缓冲区：

```csharp
public static T Deserialize<T>(in ReadOnlySequence<byte> data)
{
    if (data.IsSingleSegment)
        return NinoDeserializer.Deserialize<T>(data.First.Span); // data.FirstSpan on .NET 5+

    int length = checked((int)data.Length);
    byte[] rented = ArrayPool<byte>.Shared.Rent(length);
    try
    {
        data.CopyTo(rented);
        return NinoDeserializer.Deserialize<T>(rented.AsSpan(0, length));
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(rented);
    }
}
```

管道每次读取通常只返回一段，所以大多数帧走第一个分支，不需要任何拷贝。

## 回调 [#callbacks]

Nino 自己不调用任何钩子。把前后要执行的逻辑放进一个接口，再写一个小工具方法，在调用 Nino 的前后调用它们：

```csharp
public interface ISerializationCallbacks
{
    void OnBeforeSerialize();
    void OnAfterDeserialize();
}

public static class CallbackSerializer
{
    public static void Serialize<T>(T value, IBufferWriter<byte> output) where T : ISerializationCallbacks
    {
        value.OnBeforeSerialize();
        NinoSerializer.Serialize(value, output);
    }

    public static T Deserialize<T>(ReadOnlySpan<byte> data) where T : ISerializationCallbacks
    {
        T value = NinoDeserializer.Deserialize<T>(data);
        value.OnAfterDeserialize();
        return value;
    }
}
```

- 泛型工具方法里的调用不会被[拦截](/zh/docs/v4/performance#interceptors)，因为那里的 `T` 是类型参数。这些调用走常规路径，每次慢几纳秒。
- 嵌套对象的钩子也由你的工具方法负责：在根对象的 `OnAfterDeserialize` 中调用它们。
- 属于构造过程的逻辑，可以放在 [`[NinoConstructor]`](/zh/docs/v4/constructors) 或属性 setter 里，它们在反序列化过程中就会执行。

## 压缩 [#compression]

压缩 Nino 写出的字节；读取前先解压到池化的缓冲区。使用 span 时，先写入未压缩的长度，这样读取方才知道要租多大的缓冲区：

```csharp title="NinoBrotli.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using System.IO.Compression;
using Nino.Core;

public static class NinoBrotli
{
    public const int MaxSize = 64 << 20;

    public static byte[] Compress<T>(T value, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        NinoSerializer.Serialize(value, buffer);

        int length = buffer.WrittenCount;
        var output = new byte[4 + BrotliEncoder.GetMaxCompressedLength(length)];
        BinaryPrimitives.WriteInt32LittleEndian(output, length);
        if (!BrotliEncoder.TryCompress(buffer.WrittenSpan, output.AsSpan(4), out int written))
            throw new InvalidOperationException("Compression failed");
        Array.Resize(ref output, 4 + written);
        return output;
    }

    public static T Decompress<T>(ReadOnlySpan<byte> data)
    {
        int length = BinaryPrimitives.ReadInt32LittleEndian(data);
        if ((uint)length > MaxSize)
            throw new InvalidDataException($"{length} bytes");

        byte[] rented = ArrayPool<byte>.Shared.Rent(length);
        try
        {
            if (!BrotliDecoder.TryDecompress(data.Slice(4), rented.AsSpan(0, length), out int written)
                || written != length)
                throw new InvalidDataException("Corrupt data");
            return NinoDeserializer.Deserialize<T>(rented.AsSpan(0, length));
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(rented);
        }
    }
}
```

使用流时，把流包装一层，再复用上面的帧工具方法。`GZipStream` 在所有平台上都可用，包括 .NET Standard 2.0 和 Unity：

```csharp
using (var gzip = new GZipStream(File.Create(path), CompressionLevel.Fastest))
    NinoStream.Write(gzip, save, buffer);

using (var gzip = new GZipStream(File.OpenRead(path), CompressionMode.Decompress))
    save = NinoStream.Read<SaveGame>(gzip);
```

`BrotliEncoder`、`BrotliDecoder` 和 `BrotliStream` 需要 .NET Core 2.1 及以上，.NET Standard 中没有。如果想要更快、可以接受压缩率低一些，可以用 LZ4 库，它们提供和 `BrotliEncoder.TryCompress` 一样的 span 输入、span 输出接口。
