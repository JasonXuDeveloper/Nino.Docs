`NinoSerializer` and `NinoDeserializer` write a value to a `Stream` and read it back, synchronously or with `await`, and read the `ReadOnlySequence<byte>` a pipe hands you. Each call handles one value. Several messages on one stream need frames, and smaller bytes need compression: Nino has neither built in, so this page shows the code to add for each.

| You have | Use |
| --- | --- |
| One value per stream: a file, an HTTP body, a blob | [`Serialize(value, stream)`, `Deserialize<T>(stream)`](#streams) |
| The same, with async I/O | [`SerializeAsync`, `DeserializeAsync`](#async) |
| A `ReadOnlySequence<byte>` from a `PipeReader`, gRPC or `HybridCache` | [`Deserialize<T>(sequence)`](#readonlysequence-input) |
| Many values on one stream: a socket, a log of records | [frames](#frames) |
| Fewer bytes on disk or on the wire | [compression](#compression) |

## Streams

`NinoSerializer.Serialize(value, stream)` writes one value; `NinoDeserializer.Deserialize<T>(stream)` reads it back, to the end of the stream:

```csharp
using (var file = File.Create(path))
    NinoSerializer.Serialize(checkpoint, file); // [!code highlight]

using (var file = File.OpenRead(path))
    checkpoint = NinoDeserializer.Deserialize<Checkpoint>(file); // [!code highlight]

using (var file = File.OpenRead(path))
    NinoDeserializer.Deserialize(file, ref checkpoint); // fills the instance you keep
```

- **The bytes.** The stream gets exactly what `NinoSerializer.Serialize(checkpoint)` returns: no length, no header. Nino serializes into its pooled <Term id="scratch-buffer">scratch buffer</Term> and hands it to the stream in one `Write`, so a call allocates no array.
- **Reading.** From the stream's position to its end, into an array rented from `ArrayPool<byte>.Shared` and returned after the read. A `MemoryStream` whose buffer is exposed (`TryGetBuffer` succeeds: one you wrote into with `new MemoryStream()`, or one made with `publiclyVisible: true`) is read in place, with no copy, and left at its end; `new MemoryStream(bytes)` hides its buffer, so its bytes are copied into the rented array. When you already hold the array, pass it to `Deserialize<T>(bytes)` instead of wrapping it in a stream. The bytes are then read as a span is, with every check: [untrusted mode](/en/docs/v4/security#untrusted-mode) applies, bytes after the value included, and a stream that ends early throws `NinoDataException`.
- **Growth.** A stream that cannot seek starts with 4 KiB and doubles the array only when it is full. A seekable stream's `Length` sizes the first array up to 1 MiB, since a length is only a claim. Nino never holds much more than twice what the stream delivered.
- **Calls.** With a type known at compile time, both calls are [intercepted](/en/docs/v4/performance#interceptors) like the span calls and go straight to the generated formatter. For a type known only as a `Type`, the [boxed calls](/en/docs/v4/basic#the-boxed-api) take a stream too: `SerializeBoxed(value, stream, type)`, `DeserializeBoxed(stream, type)` and `DeserializeBoxed(stream, ref value, type)`.

<Callout type="warn" title="Bound a stream from a peer">

Nino reads until the stream ends, so a stream someone else controls (an upload, a socket) can make it hold as much as they send. Cap it before you read: reject a request whose length is over your limit (ASP.NET Core's request size limit does), or send [frames](#frames) with a maximum size. See [What Stays Your Job](/en/docs/v4/security#what-stays-your-job).

</Callout>

## Async

```csharp
await NinoSerializer.SerializeAsync(checkpoint, stream, ct);
Checkpoint read = await NinoDeserializer.DeserializeAsync<Checkpoint>(stream, ct);
```

- Both return a `ValueTask` and write and read the same bytes as the synchronous calls; `SerializeBoxedAsync` and `DeserializeBoxedAsync` take a `Type`.
- `SerializeAsync` serializes the value before it returns, so you may change the value while the write is pending. A write that completes at once (a `MemoryStream`, a buffered `FileStream`) allocates nothing; a pending one keeps Nino's buffer until it completes, and the next call on the thread gets another.
- `DeserializeAsync` from a `MemoryStream` allocates nothing but the value.
- There is no async form that reads into an existing instance (an `async` method takes no `ref`): call the synchronous `Deserialize(stream, ref value)`, or read the bytes yourself and call `Deserialize(span, ref value)`.
- The async calls need .NET Standard 2.1 or later: .NET 8 and 10, and every Unity version Nino supports. .NET Framework uses the .NET Standard 2.0 build, which has only the synchronous calls.

## Multi-Segment Input (`ReadOnlySequence`) [#readonlysequence-input]

A `PipeReader`, a gRPC payload or `HybridCache` hands you a `ReadOnlySequence<byte>`. Pass it to `NinoDeserializer` as it is: a single segment is deserialized in place, a multi-segment sequence is copied once (to the stack up to 512 bytes, else into a pooled array), and the `ref` overload fills an instance you keep.

```csharp
Checkpoint read = NinoDeserializer.Deserialize<Checkpoint>(sequence); // [!code highlight]
NinoDeserializer.Deserialize(sequence, ref checkpoint); // fills the same instance
```

Pipes usually return one segment per read, so most reads copy nothing. The sequence must hold exactly one value: to cut frames out of a pipe's buffer, see [Reading Frames](/en/docs/v4/advanced/networking#reading-frames).

<Callout title="On rc.9 and earlier">

The sequence overloads are new in rc.10; earlier releases read spans only. Deserialize `sequence.First.Span` when `sequence.IsSingleSegment`, and copy the sequence into a pooled array otherwise.

<Accordions>
<Accordion title="Sequence helpers for rc.9 and earlier" id="sequence-helpers-rc9" value="sequence-helpers-rc9">

```csharp
public static T Deserialize<T>(in ReadOnlySequence<byte> data)
{
    T value = default;
    Deserialize(data, ref value);
    return value;
}

public static void Deserialize<T>(in ReadOnlySequence<byte> data, ref T value)
{
    if (data.IsSingleSegment)
    {
        NinoDeserializer.Deserialize(data.First.Span, ref value); // data.FirstSpan on .NET 5+
        return;
    }

    int length = checked((int)data.Length);
    byte[] rented = ArrayPool<byte>.Shared.Rent(length);
    try
    {
        data.CopyTo(rented);
        NinoDeserializer.Deserialize(rented.AsSpan(0, length), ref value);
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(rented);
    }
}
```

## Several Messages on One Stream [#frames]

Nino has no frame format of its own: `Deserialize<T>(stream)` reads one value up to the end of the stream, and where each message ends on a socket or in a file of records is your protocol's choice. A common one is a frame per value: a 4-byte little-endian length, then the payload. `Writer` reserves the length slot, serializes the value after it and then patches in the length, all in one buffer:

```csharp title="StreamFrames.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static partial class StreamFrames
{
    public const int MaxFrameSize = 16 << 20; // the most one frame (and so one peer) can make the reader rent

    // [int32 length][payload], built in buffer
    public static void Frame<T>(T value, NinoArrayBufferWriter buffer)
    {
        buffer.ResetWrittenCount();
        var writer = new Writer(buffer);
        int slot = writer.ReserveInt32();
        NinoSerializer.Serialize(value, ref writer); // [!code highlight]
        writer.PatchLength(slot);   // bytes written after the slot
        writer.Flush();
        writer.ReleaseReferences(); // end the call, as NinoSerializer does
    }

    public static void Write<T>(Stream stream, T value, NinoArrayBufferWriter buffer)
    {
        Frame(value, buffer);
        stream.Write(buffer.WrittenSpan);
    }
}
```

Reading is the mirror image: read the 4-byte prefix, check the length, read exactly that many bytes, then deserialize. A stream may return fewer bytes than asked, so `Fill` loops until it has them all:

```csharp title="StreamFrames.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using Nino.Core;

public static partial class StreamFrames
{
    /// <summary>Reads the next frame into value (default: a new one). False at the end of the stream.</summary>
    public static bool TryRead<T>(Stream stream, ref T value)
    {
        byte[] buffer = ArrayPool<byte>.Shared.Rent(4096); // the prefix, then the payload
        try
        {
            if (!Fill(stream, buffer, 4, endAllowed: true))
                return false;                              // clean end between frames
            int length = ReadLength(buffer);
            if (length > buffer.Length)
                Grow(ref buffer, length);
            Fill(stream, buffer, length, endAllowed: false);
            NinoDeserializer.Deserialize(buffer.AsSpan(0, length), ref value); // [!code highlight]
            return true;
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }

    public static T Read<T>(Stream stream)
    {
        T value = default;
        if (!TryRead(stream, ref value))
            throw new EndOfStreamException();
        return value;
    }

    // Stream.ReadAtLeast does the same on .NET 7+; this loop runs everywhere, including Unity
    private static bool Fill(Stream stream, byte[] buffer, int count, bool endAllowed)
    {
        for (int read = 0; read < count; )
        {
            int n = stream.Read(buffer, read, count - read);
            if (n == 0)
            {
                if (read == 0 && endAllowed)
                    return false;
                throw new EndOfStreamException();
            }
            read += n;
        }
        return true;
    }

    private static void Grow(ref byte[] buffer, int length)
    {
        byte[] larger = ArrayPool<byte>.Shared.Rent(length);
        ArrayPool<byte>.Shared.Return(buffer);
        buffer = larger;
    }

    private static int ReadLength(ReadOnlySpan<byte> prefix)
    {
        int length = BinaryPrimitives.ReadInt32LittleEndian(prefix);
        if ((uint)length > MaxFrameSize)
            throw new InvalidDataException($"Frame of {length} bytes");
        return length;
    }
}
```

A sequence of values (what `IAsyncEnumerable<T>` streaming gives you elsewhere) is just consecutive frames: write one frame per element, and read until the stream ends, into one instance:

```csharp
using var buffer = new NinoArrayBufferWriter(); // one per thread or connection
foreach (AuditEvent e in events)
    StreamFrames.Write(stream, e, buffer);
```

```csharp
AuditEvent auditEvent = null;                   // filled in place by every frame
while (StreamFrames.TryRead(stream, ref auditEvent))
    Index(auditEvent);
```

`TryRead` rents one pooled array per frame for the prefix and the payload, and deserializes into `value` in place: once `value` has the right shape, writing and reading a frame allocates nothing but the strings whose text changed. `Read` returns a new value each time. The frame format is the same as in the [network guide](/en/docs/v4/advanced/networking#frame-the-stream), so both ends can mix the two.

### Async Frames [#async-frames]

Build the frame synchronously with `Frame` (a `Writer` is a `ref struct` and cannot live in an `async` method), then await the I/O. `WriteAsync` needs no `async` of its own: it returns the stream's task, so do not reuse the buffer until that has completed. Add these to `StreamFrames`:

```csharp title="StreamFrames.cs"
using System;
using System.Buffers;
using System.IO;
using System.Threading;
using System.Threading.Tasks;
using Nino.Core;

public static partial class StreamFrames
{
    /// <summary>Do not reuse buffer until the returned task has completed.</summary>
    public static ValueTask WriteAsync<T>(Stream stream, T value, NinoArrayBufferWriter buffer,
        CancellationToken ct = default)
    {
        Frame(value, buffer);
        return stream.WriteAsync(buffer.WrittenMemory, ct);
    }

    public static async ValueTask<T> ReadAsync<T>(Stream stream, CancellationToken ct = default)
    {
        byte[] buffer = ArrayPool<byte>.Shared.Rent(4096);
        try
        {
            await FillAsync(stream, buffer, 4, ct);
            int length = ReadLength(buffer);
            if (length > buffer.Length)
                Grow(ref buffer, length);
            await FillAsync(stream, buffer, length, ct);
            return NinoDeserializer.Deserialize<T>(buffer.AsSpan(0, length));
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }

    private static async ValueTask FillAsync(Stream stream, byte[] buffer, int count, CancellationToken ct)
    {
        for (int read = 0; read < count; )
        {
            int n = await stream.ReadAsync(buffer.AsMemory(read, count - read), ct);
            if (n == 0) throw new EndOfStreamException();
            read += n;
        }
    }
}
```

An `async` method allocates its state machine only when it actually waits for I/O, and `ReadAsync` returns a new value per frame; for a loop that must not allocate, use the synchronous `TryRead` or a [`PipeReader`](/en/docs/v4/advanced/networking#reading-frames).

`Fill` and `FillAsync` run on every target; on .NET 7 and later, `Stream.ReadAtLeast` and `ReadExactlyAsync` do the same. `stream.Write(span)`, `WriteAsync(memory)` and `ReadAsync(memory)` need .NET Standard 2.1, which every Unity version Nino supports (2022.3 and later) has; on .NET Standard 2.0 only, use the `byte[]` overloads, getting the written array with `MemoryMarshal.TryGetArray(buffer.WrittenMemory, out var segment)`.

With `System.IO.Pipelines`, serialize straight into the `PipeWriter` (it is an `IBufferWriter<byte>`) and read frames from the `PipeReader`; see [Reading Frames](/en/docs/v4/advanced/networking#reading-frames) for the complete loop, which reads each frame with the [sequence overload](#readonlysequence-input).

## Compression

Nino does not compress: it writes and reads the bytes, and a compression library makes them smaller. With a stream, wrap it and call Nino's stream overloads on the wrapper. `GZipStream` is available everywhere, including .NET Standard 2.0 and Unity:

```csharp
using (var gzip = new GZipStream(File.Create(path), CompressionLevel.Fastest))
    NinoSerializer.Serialize(checkpoint, gzip);

using (var gzip = new GZipStream(File.OpenRead(path), CompressionMode.Decompress))
    checkpoint = NinoDeserializer.Deserialize<Checkpoint>(gzip);
```

For several values in one compressed stream, write [frames](#frames) into the wrapper with `StreamFrames`. A decompressing stream delivers as many bytes as the data expands to, whatever the file's size, so read data from others as the compressed frames below, whose `MaxSize` bounds the uncompressed length.

### Compressed Frames [#compressed-frames]

With spans, compress the bytes Nino writes and decompress into a pooled buffer before reading. Each frame starts with two lengths: the compressed length, which tells the reader where the frame ends (so frames can follow one another in a buffer), and the uncompressed length, which tells it how much to rent. `Compress` writes into any `IBufferWriter<byte>` (a second `NinoArrayBufferWriter` you keep, a `PipeWriter`), and `Decompress` fills an instance you keep, so neither allocates once the buffers have grown:

```csharp title="BrotliPayload.cs"
using System;
using System.Buffers;
using System.Buffers.Binary;
using System.IO;
using System.IO.Compression;
using Nino.Core;

public static class BrotliPayload
{
    public const int MaxSize = 16 << 20; // the most one frame can make a reader rent

    /// <summary>Writes [int32 compressed length][int32 uncompressed length][Brotli data] to output. scratch holds the uncompressed bytes.</summary>
    public static void Compress<T>(T value, NinoArrayBufferWriter scratch, IBufferWriter<byte> output)
    {
        scratch.ResetWrittenCount();
        NinoSerializer.Serialize(value, scratch);

        int length = scratch.WrittenCount;
        Span<byte> target = output.GetSpan(8 + BrotliEncoder.GetMaxCompressedLength(length));
        // quality 1 of 0-11: fast, still compact; window 22 is the default
        if (!BrotliEncoder.TryCompress(scratch.WrittenSpan, target.Slice(8), out int written, 1, 22))
            throw new InvalidOperationException("Compression failed");
        BinaryPrimitives.WriteInt32LittleEndian(target, written);
        BinaryPrimitives.WriteInt32LittleEndian(target.Slice(4), length);
        output.Advance(8 + written);
    }

    /// <summary>Reads one frame into value and returns its size, so the next frame starts there.</summary>
    public static int Decompress<T>(ReadOnlySpan<byte> data, ref T value)
    {
        if (data.Length < 8)
            throw new InvalidDataException("Truncated frame");
        int compressed = BinaryPrimitives.ReadInt32LittleEndian(data);
        int length = BinaryPrimitives.ReadInt32LittleEndian(data.Slice(4));
        if ((uint)compressed > (uint)(data.Length - 8) || (uint)length > MaxSize)
            throw new InvalidDataException("Bad frame header");

        // MaxSize is the most one frame can make the reader rent: keep it small for untrusted senders
        byte[] rented = ArrayPool<byte>.Shared.Rent(length);
        try
        {
            // one-shot, with no decoder instance: nothing is allocated
            if (!BrotliDecoder.TryDecompress(data.Slice(8, compressed), rented.AsSpan(0, length), out int written)
                || written != length)
                throw new InvalidDataException("Corrupt data");
            NinoDeserializer.Deserialize(rented.AsSpan(0, length), ref value);
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(rented);
        }
        return 8 + compressed;
    }
}
```

`BrotliEncoder`, `BrotliDecoder` and `BrotliStream` need .NET Core 2.1 or later, and are not in .NET Standard. If you want more speed and can accept less compression, LZ4 libraries offer the same span-in, span-out shape as `BrotliEncoder.TryCompress`.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| Several values written to one stream with `Serialize(value, stream)` | `Deserialize<T>(stream)` reads to the end and returns the first value: the bytes after it are ignored, and with [`NinoSettings.Untrusted`](/en/docs/v4/security#untrusted-mode) the call throws `NinoDataException` (bytes after the value) | nothing: write [frames](#frames) |
| Reading a stream someone else controls without a size limit | Nino holds as much as they send | nothing: cap the stream or the frame ([above](#streams)) |
| Reusing the buffer of `StreamFrames.WriteAsync` before its task completes | The pending write sends the next frame's bytes | nothing: await the task first |
| `SerializeAsync` or `DeserializeAsync` in a .NET Framework or .NET Standard 2.0 project | It does not compile: that build has only the synchronous calls | the compiler |
