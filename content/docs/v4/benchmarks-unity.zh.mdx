Unity 跑的是 `Nino.Core` 的 netstandard 构建，本身不带硬件内部函数（hardware intrinsics）。装了 `com.unity.burst` 后，Nino 的 Unity 包会为最能受益于 SIMD 的工作注册 [Burst 编译的内核](/zh/docs/v4/advanced/unity#burst-kernels)。这个基准测试测的就是它们在真实播放器里带来的变化。.NET 运行时的结果见[.NET 基准测试](/zh/docs/v4/benchmarks)；Go、Rust 和 TypeScript 的结果见[其他语言的基准测试](/zh/docs/v4/benchmarks-runtimes)。

## 测量内容 [#setup]

- **在哪测：** 每次发布时，发布流程在 GitHub 托管的 Linux x64 运行器上运行一个 IL2CPP 播放器，每个 Unity 版本一张表。表格下方一行列出 Unity 版本、播放器配置、CPU、Burst 版本，以及内核编译时针对的指令集，都取自发布报告。
- **测什么：** 每个用例在同一个播放器里计时两次：**不用 Burst**，走 Nino 的 netstandard 标量路径；**用 Burst**，注册了内核。两者写出的字节一致。用例是 `Test.Runtime.Burst.BurstBenchmark`，用 Unity Performance Testing 包测量（`Measure.Method`：先预热，再测 9 次，每次约 100 ms，取单次调用的平均时间）；表中每个时间是这 9 次的中位数。
- **加速比：** 不用 Burst 的时间除以用 Burst 的时间，由本站根据这两个时间算出。相差 5% 以内算持平；一边低于 1 ns、另一边可测时，算更快（快到测不出），规则和 [.NET 页面](/zh/docs/v4/benchmarks#setup)相同。

内核只处理至少 2 个值（带填充的原始结构体至少 16 个）的数组和列表，以及至少 16 个字符的字符串；更短的数据在两列里都走标量路径，所以低于这些阈值的用例，两列时间应该差不多。在支持 AVX2 的 CPU 上，256 个值及以上（每个值最多 16 字节）的块走 32 字节的 AVX2 置换，其余走 16 字节的 SSSE3 内核；表格下方一行列出每个播放器注册了哪些内核，以及构建时用的 Burst x64 目标。请只在同一张表内比较时间：每个 Unity 版本跑在各自的播放器里，运行器的 CPU 在不同发布之间也可能不同。

## 复现 [#reproducing]

Unity 工程在 [Nino 仓库](https://github.com/JasonXuDeveloper/Nino)的 `src/Nino.Unity`。用 Unity 2022.3 或更高版本打开，并安装 `com.unity.burst`；Test Runner 里的 `BurstKernelTests` 逐字节比较每个内核和它的标量参考实现（在支持 AVX2 的 CPU 上，AVX2 和 SSSE3 两档各比一次），`BurstBenchmark` 就是上面的基准测试，`NinoBurst.Unregister()` 和 `NinoBurst.Register()` 可以在运行时关闭、打开内核。自己机器上测出的数字，只适合在同一台机器上前后对比改动。
