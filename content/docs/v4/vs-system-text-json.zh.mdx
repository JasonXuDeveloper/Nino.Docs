[System.Text.Json](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/overview) 是 .NET 内置的 JSON 序列化库。JSON 是文本，自己描述自己：人能看能改，浏览器和任何语言不需要你的类型就能解析，ASP.NET Core 默认用的也是它。Nino 写的是二进制，只有你的 C# 类型，或者 [nino-gen](/zh/docs/v4/advanced/codegen) 从这些类型生成的 TypeScript、Go 和 Rust 才读得懂，换来的是速度、体积，以及 JSON 表达不了的功能。本页对比 Nino v4 和 .NET 10 上的 System.Text.Json：System.Text.Json 的功能以微软文档为准，Nino 的功能以 Nino 源码为准。无法核实的功能，一律不列出。所有库放在一起比，见[序列化库选型](/zh/docs/v4/compare)。

## 两种格式 [#formats]

| | Nino v4 | System.Text.Json |
| --- | --- | --- |
| 一个值 | 只有它的字节 | 文本：数字、字符串、`true`、`false`、`null`、数组或对象 |
| 一个对象 | 成员依次排列；用 [`NinoFormat.Keyed`](/zh/docs/v4/evolving-data#keyed-members) 时每个成员多一个键和一个长度（8 字节） | `{ "name": value, ... }`，每个属性都带着名字 |
| 一个子类型 | 4 字节类型 ID，即类型名的哈希 | 一个 `$type` 属性，值是你给这个子类型定的标识 |
| 整数和浮点数 | 按完整宽度写（`int` 占 4 字节） | 十进制数字 |
| 字符串 | 所有字符都不超过 U+00FF 时每字符一个字节，否则 UTF-16；加 [`[NinoUtf8]`](/zh/docs/v4/defining-types#string-encoding) 用 UTF-8 | 带引号的 UTF-8 文本；默认编码器把非 ASCII 字符转义成 `\uXXXX` |
| `byte[]` | 长度加字节 | Base64 字符串 |
| `Guid`、`DateTime` | 16 字节；tick 和 kind | 36 个字符的字符串；ISO 8601 字符串 |

## 性能 [#performance]

用 BenchmarkDotNet 测量，与 Nino 在同一轮测试中运行，数据和类型都相同。System.Text.Json 用的是源生成（一个 `JsonSerializerContext`），通过复用的 `Utf8JsonWriter` 把 UTF-8 写进 `ArrayBufferWriter<byte>`，从 UTF-8 字节读取（[测试设置](/zh/docs/v4/benchmarks#workloads)）。<IfWorkloads>在 Nino 领先的[真实负载](/zh/docs/v4/benchmarks#workloads)上，序列化快 <BenchValue k="workloads.json.serialize" />，反序列化快 <BenchValue k="workloads.json.deserialize" />。</IfWorkloads>System.Text.Json 跑了真实负载以及基础、多态、可空值三组用例。

文本的载荷更大：每个对象都要写一遍所有属性名，数字也写成一串数字字符。

## 不可信输入 [#untrusted-input]

System.Text.Json 没有专门读不可信数据的模式。它的多态只认基类上声明过的派生类型，所以数据没法指定要创建的类型；它拒绝 `System.Type`；`JsonSerializerOptions.MaxDepth` 限制嵌套深度（默认 64）。请求大小要在宿主上限制，比如 Kestrel 的 `MaxRequestBodySize`。

Nino 的默认模式就能读不可信数据；[`NinoSettings.Untrusted`](/zh/docs/v4/security#untrusted-mode) 再加上那些每次读取都要多花时间的检查。

## System.Text.Json 领先的地方 [#where-system-text-json-is-ahead]

下面这些 System.Text.Json 能做，Nino v4 不做：

- **人能看能改。** 配置、日志、测试数据，还有在浏览器里查看的 API 响应，不用工具就能读。
- **任何语言都能读**，不需要生成代码：从没见过你的类型的浏览器、脚本和服务都能解析 JSON。
- **内置于 .NET**：.NET Core 3.0 及以后不用另装包，也是 ASP.NET Core 和 `HttpClient` 的 JSON 扩展方法默认的格式。
- **不靠类型读取。** `JsonDocument` 把文档读成只读的树，`JsonNode` 读成可修改的树，代码可以只取出一个值，不必为整个载荷定义类型。
- **按调用传选项**：`JsonSerializerOptions`，还有 camelCase 之类的命名策略。
- **给其他工具用的 schema。** .NET 9 及以后可以用 `JsonSchemaExporter` 导出一个类型的 JSON schema。

Nino 不做的事有什么替代做法，见[局限](/zh/docs/v4/compare#limitations)。什么场景选哪个：[怎么选](/zh/docs/v4/compare#which-to-choose)。

## 从 System.Text.Json 迁移 [#switching-from-system-text-json]

两者常常并存：人或其他语言要读的数据继续用 JSON，你自己的 .NET 程序、Unity 客户端以及 nino-gen 覆盖的语言之间用 Nino。在 ASP.NET Core 里，[Nino.AspNetCore](/zh/docs/v4/advanced/aspnetcore) 在 JSON 旁边加上 `application/x-nino`，客户端用 `Content-Type` 和 `Accept` 头来选。

| System.Text.Json | Nino |
| --- | --- |
| `JsonSerializerContext` 上的 `[JsonSerializable(typeof(T))]` | `T` 上的 `[NinoType]`：生成器自己找到类型，不用在 context 里列出 |
| 按名字写公共属性 | 按声明顺序写公共字段和属性（[定义类型](/zh/docs/v4/defining-types)）；要按名字写，用 `[NinoType(format: NinoFormat.Keyed)]`（[键控成员](/zh/docs/v4/evolving-data#keyed-members)） |
| 改名后用 `[JsonPropertyName("old")]` 保留旧名字 | 键控成员上的 `[NinoFormerName("old")]`；按位置的成员随便改名 |
| `[JsonIgnore]` | `[NinoIgnore]` |
| 非公共成员上的 `[JsonInclude]` | `[NinoType(includeNonPublicMembers: true)]`；或者用 `[NinoType(false, true)]`，在每个要写的成员上加 `[NinoMember(index)]` |
| `[JsonConstructor]` | `[NinoConstructor]`（[构造函数](/zh/docs/v4/constructors)） |
| `[JsonPolymorphic]` 加上每个子类型一个 `[JsonDerivedType]` | 基类型上的 `[NinoType]`：子类型自动继承，什么都不用列（[多态](/zh/docs/v4/polymorphism)） |
| `ReferenceHandler.Preserve` | `[NinoType(trackReferences: true)]`（[引用追踪](/zh/docs/v4/reference-tracking)） |
| `JsonObjectCreationHandling.Populate` | `NinoDeserializer.Deserialize(bytes, ref value)`，原地填充整个对象图（[复用与对象池](/zh/docs/v4/pooling)） |
| `IJsonOnSerializing`、`IJsonOnSerialized`、`IJsonOnDeserializing`、`IJsonOnDeserialized` | 方法上的 `[NinoOnSerializing]`、`[NinoOnSerialized]`、`[NinoOnDeserializing]`、`[NinoOnDeserialized]`，不用实现接口（[回调](/zh/docs/v4/defining-types#callbacks)） |
| `JsonConverter<T>` | [自定义格式化器](/zh/docs/v4/custom-formatters) |
| `JsonSerializer.SerializeToUtf8Bytes(value)` | `NinoSerializer.Serialize(value)` |
| `JsonSerializer.Deserialize<T>(utf8Bytes)` | `NinoDeserializer.Deserialize<T>(bytes)` |
| `JsonSerializer.SerializeAsync(stream, value)`、`DeserializeAsync<T>(stream)` | `NinoSerializer.SerializeAsync(value, stream)`、`NinoDeserializer.DeserializeAsync<T>(stream)`：值在前（[流](/zh/docs/v4/advanced/streams#streams)） |
| `DeserializeAsyncEnumerable` | 在流上读写[帧](/zh/docs/v4/advanced/streams#frames) |
| `JsonSerializerOptions.MaxDepth` | `NinoSettings.MaxDepth`（[限制](/zh/docs/v4/security#limits)） |

转换期间两者可以标在同一批类型上：JSON 的特性留着，加上 `[NinoType]`，用 System.Text.Json 读出每份存下的文档，再用 Nino 写回去（步骤见[换成 Nino](/zh/docs/v4/compare#switching)）。System.Text.Json 默认只写公共属性：由公共字段组成的类型（大多数 `[NinoType]` 都是这样）要开 `IncludeFields`，JSON 才不会变成空的。
