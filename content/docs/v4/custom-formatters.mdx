Nino has formatters for the [built-in types](/en/docs/v4/types) and generates one for every `[NinoType]`. Write your own to encode one member differently (a varint, a fixed-point number) or to serialize a type Nino does not know (a third-party collection, a type from another library).

A formatter is a **struct** implementing `INinoFormatter<T>`:

```csharp nocheck
public interface INinoFormatter<T>
{
    void Serialize(T value, ref Writer writer);
    void Deserialize(ref Reader reader, ref T value);
}
```

`Deserialize` takes the reader first, as every read API does, and receives the current value by `ref`: `default` means "create a new value", and an existing instance may be reused. Formatters are called as `default(TFormatter)`, so they have no instance state; keep any state in static fields.

## For One Member

Use `[NinoMemberFormatter]` to serialize a single member with your own formatter. The formatter must implement `INinoFormatter<T>` for **exactly** the member type (NINO008).

A typical case is a ledger or a metrics stream that records how much each value changed. The deltas are usually tiny, yet a `long` always takes 8 bytes. A zig-zag varint writes values from -64 to 63 in 1 byte, and values up to ±8191 in 2:

```csharp
/// Writes a long as a zig-zag varint.
public struct ZigZagLongFormatter : INinoFormatter<long>
{
    public void Serialize(long value, ref Writer writer)
    {
        ulong v = (ulong)((value << 1) ^ (value >> 63));
        while (v >= 0x80)
        {
            writer.Write((byte)(v | 0x80));
            v >>= 7;
        }
        writer.Write((byte)v);
    }

    public void Deserialize(ref Reader reader, ref long value)
    {
        ulong v = 0;
        int shift = 0;
        byte b;
        do
        {
            reader.Read(out b);
            v |= (ulong)(b & 0x7F) << shift;
            shift += 7;
        } while ((b & 0x80) != 0 && shift < 70); // at most 10 bytes: a 64-bit value
        value = (long)(v >> 1) ^ -(long)(v & 1);
    }
}

[NinoType]
public sealed class BalanceChange
{
    public int AccountId;
    [NinoMemberFormatter(typeof(ZigZagLongFormatter))] // [!code highlight]
    public long DeltaCents;
}
```

The attribute applies to one field or property, wherever the containing type is serialized. A member with a custom formatter is never copied as part of a block of [raw memory](/en/docs/v4/defining-types#structs). The analyzer reports a formatter that is not a struct, or is for another type (NINO008).

## For a Type: `[assembly: NinoFormatter]`

To teach Nino a type it does not know (your own or a third-party one), register a formatter on your assembly. Type arguments and element formatters are inferred: a type parameter constrained to `INinoFormatter<E>` receives the formatter Nino resolves for `E`, so element (de)serialization is inlined. Generated code calls the formatter directly, and the runtime uses the same registration.

```csharp
[assembly: NinoFormatter(typeof(RingFormatter<,>))]

// From a library you cannot annotate: a fixed-capacity buffer whose struct enumerator keeps foreach free of allocations
//   public sealed class Ring<T> : IEnumerable<T>
//   {
//       public Ring(int capacity); public int Count { get; } public int Capacity { get; }
//       public void Push(T item); public void Clear(); public Enumerator GetEnumerator();
//   }

public struct RingFormatter<T, TFormatter> : INinoFormatter<Ring<T>>
    where TFormatter : struct, INinoFormatter<T>
{
    public void Serialize(Ring<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.WriteNullLength();          // -1
            return;
        }

        writer.WriteLength(value.Count);
        writer.Write(value.Capacity);
        foreach (var item in value)            // Ring's struct enumerator: no allocation
            default(TFormatter).Serialize(item, ref writer); // inlined element formatter
    }

    public void Deserialize(ref Reader reader, ref Ring<T> value)
    {
        int count = reader.ReadLength();       // validated against the bytes left
        if (count < 0)
        {
            NinoRecycler.Discard(ref value);   // the data holds null: recycle the old ring
            return;
        }

        reader.Read(out int capacity);
        if (value != null && value.Capacity == capacity)
            value.Clear();                     // reuse the existing ring // [!code highlight]
        else
            NinoRecycler.Replace(ref value, new Ring<T>(capacity)); // recycles the old one, if any
        for (int i = 0; i < count; i++)
        {
            T item = default;
            default(TFormatter).Deserialize(ref reader, ref item);
            value.Push(item);
        }
    }
}

[NinoType]
public sealed class RingHolder
{
    public Ring<int> Ints;          // uses RingFormatter<int, ...>
    public List<Ring<string>> Nested;
}
```

- The formatter is a struct, not nested in a generic type, that implements `INinoFormatter<P>` exactly once. Register a generic formatter as an open definition (`typeof(F<,>)`) and a non-generic one as itself (`typeof(F)`). Every type parameter must be inferable from `P`, from a type constraint (`where TList : List<T>`), or from an `INinoFormatter<E>` constraint. An unusable registration is ignored and reported as NINO020.
- When `Deserialize` drops an instance (the data holds `null`, or the old instance cannot be reused), hand it to `NinoRecycler` rather than overwriting it, so [recycler handlers and pools](/en/docs/v4/pooling) see it: `Discard(ref value)` when the data holds `null`, `Replace(ref value, replacement)` for a new instance, `Reuse<TDeclared, TConcrete>(ref value)` to take the old instance for a formatter of a more derived type (it returns the instance, or recycles it and returns `null`), and `NinoRecycler<T>.Recycle(element)` for each element a collection drops, skipped when `NinoRecycler<T>.MayRecycle` is false.
- To target a bare type parameter (`INinoFormatter<TCollection>`), list the target type definitions: `[assembly: NinoFormatter(typeof(F<,,>), typeof(IList<>))]`. Without targets it applies to every type its constraints admit.
- Lookup order: formatters registered for the type's own definition (and for arrays), then raw unmanaged values, then `[NinoType]`s, then formatters of a bare type parameter. When several registrations match, the higher `Priority` wins (for example `Priority = 10`); on a tie, the full name that sorts first ordinally wins.

<Callout type="info" title="Declarative, no startup code">

`[assembly: NinoFormatter]` is an attribute, not a call: there is no module initializer and nothing to run at startup. The runtime reads an assembly's registrations when it first meets one of its types (or, when a lookup misses, from every loaded assembly). Formatters declared in a HybridCLR hot-update assembly are therefore picked up as soon as the assembly is loaded, and Nino declares its own BCL formatters the same way.

There is no call that registers or replaces a formatter at run time: every formatter is declared with `[assembly: NinoFormatter]` or, for one member, `[NinoMemberFormatter]`. A type's formatter therefore never changes while the process runs, and generated code and the runtime always agree on it.

</Callout>

The bytes a formatter of your own writes are known only to its code: the [layout metadata](/en/docs/v4/evolving-data#layout-metadata) shows a member it writes as `formatter(F)`, and [generated TypeScript](/en/docs/v4/advanced/typescript#not-supported) leaves out the types that hold one.

### Example: A Generic Type From Another Library [#example-grid]

`Grid<T>` below stands for a type from a library you cannot add `[NinoType]` to. This formatter handles a `Grid<T>` of any raw element type: it writes the width and the cells as one block, and reads into the current grid when its size matches, so [reuse deserialization](/en/docs/v4/pooling) allocates nothing:

```csharp title="GridFormatter.cs"
using System;
using System.Numerics;
using System.Runtime.CompilerServices;
using Nino.Core;

// From a library you cannot annotate:
//   public sealed class Grid<T> { public Grid(int width, int height); public int Width { get; } public T[] Cells { get; } }

[assembly: NinoFormatter(typeof(GridFormatter<>))]

/// Grid<T> of raw cells: the width (-1 for null), then the cells as a T[] (a length, then one block).
public struct GridFormatter<[NinoRaw] T> : INinoFormatter<Grid<T>>
    where T : unmanaged
{
    public void Serialize(Grid<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.Write(-1);
            return;
        }

        writer.Write(value.Width);
        writer.Write<T>(value.Cells.AsSpan());                     // length, then one block copy
    }

    public void Deserialize(ref Reader reader, ref Grid<T> value)
    {
        int width = reader.Read<int>();
        if (width < 0)
        {
            value = null;
            return;
        }

        int length = reader.ReadLength(Unsafe.SizeOf<T>());     // checked against the bytes left
        if (width == 0 ? length != 0 : length % width != 0)
            throw new InvalidOperationException("Not a grid.");
        if (value == null || value.Cells.Length != length || value.Width != width)
            value = new Grid<T>(width, width == 0 ? 0 : length / width); // reuse the grid when its size matches
        reader.ReadUnmanagedRaw(value.Cells.AsSpan());          // one block copy // [!code highlight]
    }
}

[NinoType]
public sealed class Level
{
    public string Name;
    public Grid<byte> Tiles;        // uses GridFormatter<byte>
    public Grid<Vector2> Flow;      // uses GridFormatter<Vector2>
}
```

- `[NinoRaw]` binds `T` only to types Nino copies as raw bytes: `Grid<byte>` and `Grid<Vector2>` use this formatter, while a `Grid<string>` member has no formatter (NINO007). The runtime applies the same rule to types it meets only at run time, in Unity's IL2CPP players too: IL2CPP keeps no attributes on type parameters, so your assembly's generated registry registers `[NinoRaw]`, `[NinoCreated]` and `unmanaged` for the formatters it registers.
- `Writer.Write<T>(ReadOnlySpan<T>)` and `Reader.ReadUnmanagedRaw<T>(Span<T>)` copy the elements as one block, and convert them field by field on a runtime whose layout differs from the canonical one.
- `ReadLength` throws when the bytes left cannot hold that many cells, so corrupt data cannot make the formatter allocate a huge grid.

## Built-in Formatters [#built-in-formatters]

Nino's own formatters are public structs in `Nino.Core`, generic over their element formatters like the ones above. Pass them as type arguments to build a formatter from parts: a list whose elements are zig-zag varints, a dictionary whose values Nino writes as it always does. Each is a struct, so the composed formatter is still direct calls the JIT can inline, with no allocation.

```csharp
[NinoType]
public sealed class PriceHistory
{
    public string Symbol;

    // Every delta as a zig-zag varint (ZigZagLongFormatter, above): 1 or 2 bytes instead of 8
    [NinoMemberFormatter(typeof(ListFormatter<List<long>, long, ZigZagLongFormatter>))] // [!code highlight]
    public List<long> DeltaCents;

    // Keys as zig-zag varints, values exactly as Nino writes a Trade
    [NinoMemberFormatter(typeof(DictionaryFormatter<long, Trade, ZigZagLongFormatter, CachedFormatter<Trade>>))] // [!code highlight]
    public Dictionary<long, Trade> TradesByTime;
}

[NinoType]
public sealed class Trade
{
    public int Quantity;
    public long PriceCents;
}
```

The element formatter is the last type arguments, after the types: `ListFormatter<TList, T, TFormatter>` takes the list type (`List<T>` or a class derived from it), the element type, then the element's formatter. For an element that has no formatter of yours, pass the one Nino would use:

| Element | Formatter to pass |
| --- | --- |
| an unmanaged value (`int`, `long`, an enum, `Vector3`, a raw struct) | `UnmanagedFormatter<T>`: its raw bytes |
| `string` | `StringFormatter`: one byte a char or UTF-16, as a member is written. For UTF-8, mark the member `[NinoUtf8]` instead (`Utf8StringFormatter` is for generated code; NINO031) |
| anything else (a `[NinoType]`, a collection, a type of a registered formatter) | `CachedFormatter<T>`: whatever Nino uses for `T`, so it writes what `NinoSerializer.Serialize(value, ref writer)` writes, headers and polymorphism included |

`CachedFormatter<T>` reads the formatter from a static field. Where `T` is a concrete type, the JIT calls it directly and can inline it; in shared generic code (a `T` that is a class) and on AOT runtimes (IL2CPP, Native AOT) each value costs one virtual call. In a generic formatter you register with `[assembly: NinoFormatter]`, take the element formatter as a type parameter (`where TFormatter : struct, INinoFormatter<T>`, as `RingFormatter` does) instead: Nino binds the exact formatter there.

Every built-in formatter, by what it formats (`TF`, `TKF` and `TVF` are element, key and value formatters; `-1` is the length of `null`):

The type parameters marked `[NinoCreated]` (`TList`, `TSet`, `TDictionary`, ...) are created with `NinoActivator<T>.Create()` when the slot is `null`; reading into an existing collection reuses or refills it, as [reuse deserialization](/en/docs/v4/pooling) does everywhere. A built-in formatter with an element formatter of yours writes bytes only your code knows: give the reading side the same composition.

## Writer and Reader

A formatter writes with `Writer` and reads with `Reader`, both `ref struct`s. The methods you need most:

| Writer | Reader | Data |
| --- | --- | --- |
| `Write<T>(in T value)` | `Read(out T value)`, `Read<T>()` | an unmanaged value (`int`, `float`, an unmanaged struct...) as raw bytes |
| `Write<T>(T? value)` | `Read(out T? value)` | a nullable unmanaged value |
| `Write<T>(T[] values)`, `Write<T>(ReadOnlySpan<T>)` | `Read(out T[] values)` | an unmanaged array: length, then one block |
| `WriteUnmanagedRaw<T>(ReadOnlySpan<T>)` | `ReadUnmanagedRaw<T>(Span<T>)` | unmanaged values as one block with no length, read into memory you already have |
| `Write(string)`, `WriteUtf8(string)` | `Read(out string)`, `ReadUtf8(out string)` | a string: one byte a char or UTF-16, chosen per string, or UTF-8 |
| | `ReadString(string current)`, `ReadUtf8(string current)` | a string, returning `current` itself when the data holds the same text, as generated code does when it reads into an existing instance |
| `WriteLength(int)`, `WriteNullLength()` | `ReadLength(minElementSize = 1)` | a collection length, `-1` for null; `ReadLength` throws if the bytes left cannot hold that many elements of at least `minElementSize` bytes |
| `ReserveInt32()`, `PatchInt32(...)`, `PatchLength(...)` | | 4 bytes to fill in later, such as a byte length |
| `WriteRaw(ReadOnlySpan<byte>)` | `ReadRaw(int)`, `Advance(int)` | raw bytes, or skipping them |
| `Reserve(int)` | `ReadBlock(int)` | a fixed number of bytes you encode yourself, through a `ref byte` ([Raw Bytes](#raw-bytes)) |
| `Position` | `Position`, `Remaining`, `Eof` | where you are: `Position` is an absolute offset, `Remaining` the bytes left |

`Write(string)` writes a header of 1, 3 or 5 bytes and the chars: `0` for `null`; `2 × length + 1` and one byte a char when every char is at most U+00FF (`1` for empty, with nothing after it); otherwise `2 × length` and the UTF-16 code units. `WriteUtf8` writes the length in chars plus one as a header (`0` for `null`, `1` for empty), then the byte count as a second header and exactly that many UTF-8 bytes: `"é😀"` is `04` `06` `C3 A9 F0 9F 98 80`. An unpaired surrogate is written as U+FFFD. See [Strings](/en/docs/v4/wire-format#strings).

### Raw Bytes [#raw-bytes]

For an encoding of a fixed size that the table's methods do not cover, take the bytes directly: `Writer.Reserve(size)` and `Reader.ReadBlock(size)` return a `ref byte` to the first of `size` bytes and move past them. Nino's bytes are little-endian, and `Writer` and `Reader` refuse to run on a big-endian host, so encode explicitly little-endian, as `BinaryPrimitives` does:

```csharp
/// Unix milliseconds in 6 bytes, little-endian (until the year 10889).
public struct UnixMillis48Formatter : INinoFormatter<long>
{
    public void Serialize(long value, ref Writer writer)
    {
        if ((ulong)value >= 1UL << 48)
            throw new ArgumentOutOfRangeException(nameof(value));
        Span<byte> bytes = MemoryMarshal.CreateSpan(ref writer.Reserve(6), 6); // [!code highlight]
        BinaryPrimitives.WriteUInt32LittleEndian(bytes, (uint)value);
        BinaryPrimitives.WriteUInt16LittleEndian(bytes.Slice(4), (ushort)(value >> 32));
    }

    public void Deserialize(ref Reader reader, ref long value)
    {
        // NinoDataException when fewer than 6 bytes are left
        ReadOnlySpan<byte> bytes = MemoryMarshal.CreateReadOnlySpan(ref reader.ReadBlock(6), 6); // [!code highlight]
        value = BinaryPrimitives.ReadUInt32LittleEndian(bytes) | (long)BinaryPrimitives.ReadUInt16LittleEndian(bytes.Slice(4)) << 32;
    }
}

[NinoType]
public sealed class AuditEntry
{
    [NinoMemberFormatter(typeof(UnixMillis48Formatter))]
    public long AtUnixMs;
    public string Action;
}
```

`MemoryMarshal.CreateSpan` exists on .NET Core 2.1 and later, .NET 5 and later and Unity; on .NET Framework, read and write through the `ref byte` with `Unsafe.ReadUnaligned` and `Unsafe.WriteUnaligned`, which use the host's byte order: little-endian wherever `Writer` and `Reader` run.

| Method | Does | When the size is wrong |
| --- | --- | --- |
| `Writer.Reserve(int size)` | Adds `size` bytes to the output, growing the buffer, and returns a `ref` to the first. The bytes are **not cleared**: they hold whatever the pooled buffer held, so write every one | A negative size throws `OverflowException` |
| `Writer.ReserveInt32()` | Adds 4 bytes and returns their position, for `PatchInt32(position, value)` or `PatchLength(position)` once you know the value | |
| `Reader.ReadBlock(int size)` | Consumes `size` bytes and returns a `ref` to the first | Negative, or more than `Remaining`: `NinoDataException` ("unexpected end of data"), nothing consumed |
| `Reader.ReadRaw(int length)` | The same, as a `ReadOnlySpan<byte>` | the same |
| `Reader.Advance(int count)` | Skips `count` bytes (`ReadBlock` without the `ref`) | the same |

<Callout type="warn" title="These references are unchecked">

- The `ref` from `Reserve` is valid only until the next write to the writer: any write may move the output to a larger buffer and return the old one to the pool, and writing through an old `ref` then corrupts memory something else uses. Fill the bytes right away.
- The `ref` from `ReadBlock` points into the data you are deserializing. It is not read-only: never write through it, and read only the `size` bytes you asked for. With a size of `0`, it may point past the end of the data.
- `PatchInt32` writes at the position you pass without checking it: pass only a position `ReserveInt32` returned for this writer.

</Callout>

### Positions in a Slice [#positions-in-a-slice]

`Reader.ReadSlice()` reads an `int32` byte length and returns a reader over the block that follows (the kind of block `ReserveInt32()` and `PatchLength(...)` write). Its `Position` does **not** restart at `0`: like the parent's, it is an offset from the start of the whole input. `Remaining` and `Eof` stop at the end of the slice. To count the bytes read inside a slice, record the position first and subtract:

```csharp
static void ReadBlock(ref Reader reader)
{
    Reader slice = reader.ReadSlice();     // the parent skips the whole block
    int start = slice.Position;            // an offset in the whole input, not 0
    slice.Read(out int kind);
    // ...
    int consumed = slice.Position - start; // bytes read inside the slice
    bool complete = slice.Eof;             // Remaining == 0: the slice is used up
    reader.EndSlice(in slice);             // objects read in the slice stay visible to back references
}
```

`Writer.Position` is likewise the absolute position in the `NinoArrayBufferWriter`.

To write a value that has its own formatter (a `[NinoType]`, a `List<T>`), call the regular API with the writer or reader, so its references and polymorphism are handled as usual:

```csharp
// in a formatter for Contract, whose Owner field is a [NinoType]
public void Serialize(Contract value, ref Writer writer)
{
    writer.Write(value.Id);
    NinoSerializer.Serialize(value.Owner, ref writer); // [!code highlight]
}

public void Deserialize(ref Reader reader, ref Contract value)
{
    value ??= new Contract();
    reader.Read(out value.Id);
    NinoDeserializer.Deserialize(ref reader, ref value.Owner); // [!code highlight]
}
```

Always read exactly what you wrote, in the same order: the bytes carry no schema.
