任何标记了 `[NinoType]` 的 `class`、`struct`、`record`、`record struct` 或 `interface` 都可以序列化。源生成器在编译期写好它的格式化器，无需注册。本页介绍哪些成员会被写入、写入顺序，以及改变格式的各个选项。

```csharp
using Nino.Core;

[NinoType]
public class Player
{
    public int Id;                       // public fields
    public string Name { get; set; }     // public properties with a getter and a setter
    public List<Item> Inventory { get; init; } // init setters work too
    public Vector3? LastCheckpoint;      // Nullable<T> of any serializable T
}
```

<Callout type="info">

`[NinoType]` 类型及其所有外层类型必须是 `public` 或 `internal`（`protected internal` 也可以），并且不能是 `static` 类或 `ref struct`（NINO001，提供代码修复）。

</Callout>

## `[NinoType]` 选项 [#ninotype-options]

```csharp
public NinoTypeAttribute(
    bool autoCollect = true,
    bool containNonPublicMembers = false,
    bool allowInheritance = true,
    bool versionTolerant = false,
    bool keyed = false,
    bool trackReferences = false)
```

建议使用命名参数，便于阅读：`[NinoType(versionTolerant: true)]`。不带参数的 `[NinoType]` 是最快、最紧凑的格式：按位置写入，每个成员没有额外开销。

## 哪些成员会被序列化 [#which-members-are-serialized]

在默认的 `autoCollect: true` 下，Nino 会收集：

- 所有**公共字段**，以及所有**同时具有 getter 和 setter 的公共属性**（`set` 或 `init` 均可）；
- 先收集 `[NinoType]` 基类的成员，再按声明顺序收集类型自身的成员；
- 记录类型的主构造函数参数（它们本身就是公共属性）。

以下成员会被跳过：

- **只有 getter 的自动属性**（`public int Id { get; }`），除非某个构造函数有同名参数（不区分大小写）接收它，因为没有别的办法能还原它的值。参见[构造函数](/zh/docs/v4/constructors)；
- **显式接口实现**（`int IHasId.Id { get; set; }`），生成代码无法通过名称访问它。`[NinoType]` 接口的成员会通过实现类型中同名的成员来序列化；
- 类型无法序列化的成员（委托、`Task`、指针等），会报告警告 NINO007。

`override` 成员与它重写的成员视为同一个，只收集一次。用 `new` 隐藏基类成员时，两者是不同的成员，都会被序列化，基类的在前。如果被隐藏的基类成员不是公共的，生成代码只能通过 `[UnsafeAccessor]` 访问它（.NET 8+，且限于非泛型类型）；否则会跳过该成员并报告警告 NINO022。

### 忽略成员 [#ignoring-a-member]

```csharp
[NinoType]
public class Session
{
    public int UserId;
    [NinoIgnore] public DateTime CachedAt; // [!code highlight]
}
```

### 显式指定成员 [#choosing-members-explicitly]

使用 `[NinoType(false)]`（即 `autoCollect: false`）时，只有标记了 `[NinoMember(index)]` 的成员会被序列化，按 `index` 升序写入：

<Tabs items={["类", "记录"]}>
<Tab value="类">

```csharp
[NinoType(false)] // [!code highlight]
public class SampleClass
{
    public int Id;                       // not serialized
    [NinoMember(1)] public string Name { get; set; } // [!code highlight]
    [NinoMember(0)] public int Level;    // written first
}
```

</Tab>
<Tab value="记录">

```csharp
[NinoType(false)] // [!code highlight]
public record SampleRecord(
    [property: NinoMember(2)] int Id, // [!code highlight]
    [property: NinoMember(1)] string Name); // [!code highlight]
```

</Tab>
</Tabs>

<Callout type="info">

分析器会检查这些标记是否一致：`autoCollect: true` 时 `[NinoMember]` 是多余的（NINO010），`autoCollect: false` 时 `[NinoIgnore]` 是多余的（NINO011），同一成员不能同时标记两者（NINO012），索引不能重复（NINO013）。这些诊断都附带代码修复。

</Callout>

### 私有成员 [#private-members]

设置 `containNonPublicMembers` 后，非公开成员也会被序列化：

```csharp
[NinoType(containNonPublicMembers: true)] // [!code highlight]
public partial class Account
{
    private long _balance;
    protected string Owner;
    public int Id;
}
```

- 在 .NET 8 及以上版本，生成代码通过 `[UnsafeAccessor]` 访问私有成员（泛型类型除外）。
- 在 .NET 8 之前（包括 .NET Standard 和 Unity）以及泛型类型中，生成代码会在类型**内部**生成访问器，所以该类型及其所有外层类型都必须声明为 `partial`（NINO002，提供代码修复）。
- 没有设置 `containNonPublicMembers` 却给非公开成员标记 `[NinoMember]`，会报错（NINO009）。
- 基类的私有成员永远不属于子类型。

编译器看不到生成的访问器，因此 Nino 会屏蔽它所序列化的私有成员上“字段从未使用 / 从未赋值”之类的警告。

## 成员顺序 [#member-order]

不使用 `keyed: true` 时，成员顺序**就是**数据格式。默认先写基类成员，再按声明顺序写入，除非用以下方式改变：

- `[NinoType(false)]` 配合 `[NinoMember(index)]`：按索引升序。
- 在类、结构体或接口上使用 `[NinoExplicitOrder(...)]`：先按给定顺序写入列出的成员（按名称），其余成员随后按声明顺序写入。

```csharp
[NinoType]
[NinoExplicitOrder(nameof(Name), nameof(Id))] // [!code highlight]
public class Ordered
{
    public int Id;
    public string Name;
    public bool Flag;   // written after Name and Id
}
```

<Callout type="warn">

调整顺序、插入或删除成员（或修改索引）都会让之前写出的数据无法读取。如果数据需要长期保存，请提前规划[版本兼容或键控成员](/zh/docs/v4/evolving-data)。

</Callout>

## 字符串编码 [#string-encoding]

字符串默认以 UTF-16 写入：一个长度加一次整块拷贝，速度最快。给 `string` 字段或属性加上 `[NinoUtf8]` 则改为 UTF-8，以 ASCII 为主的文本体积可减半，代价是需要转码（运行时已做向量化）。该特性对其他类型的成员无效，并且读写双方必须一致：UTF-8 写入的成员不能按 UTF-16 读取。

```csharp
[NinoType]
public class ChatMessage
{
    public int SenderId;
    [NinoUtf8] public string Text; // [!code highlight]
}
```

## 曾用名 [#former-name]

非密封类、抽象类和接口在写入时都带有一个**类型 ID**，即类型全名的 32 位哈希，这样多态值才能还原成正确的类型。类型改名或换命名空间后，ID 也会变。用 `[NinoFormerName]` 可以继续读取旧数据：

```csharp
[NinoType]
[NinoFormerName("Old.Namespace.Outer+Item")] // [!code highlight]
public class ItemRenamed
{
    public int Id;
}
```

曾用名使用全名的**运行时形式**：`Namespace.Type`，嵌套类型与外层类型之间用 `+` 连接（`Namespace.Outer+Inner`），不带 `global::`。类型 ID 由曾用名计算，所以改名后的类型仍写出旧读取方认识的 ID，而读取方用新旧两个名字都能找到它。`NinoTypeId.Of(typeof(T))` 可以查看某个类型写出的 ID。

在 `keyed` 类型的字段或属性上，`[NinoFormerName("OldName")]`（可重复使用）可以继续读取以成员旧名称写出的数据，参见[重命名键控成员](/zh/docs/v4/evolving-data#renaming-keyed-members)。按位置和版本兼容的类型不写成员名，重命名成员时什么都不用做。

## 结构体 [#structs]

`[NinoType]` 结构体没有任何头部。当它是非托管类型、未启用 `versionTolerant` 或 `keyed`、使用默认的顺序布局、没有自定义成员格式化器，并且每个实例字段都参与序列化时，会按**原始内存**写入：单个值一次拷贝，它的数组和列表也是整块拷贝。否则逐个成员写入。

```csharp
[NinoType]
public struct Hit          // raw: one 16-byte copy (padding zeroed)
{
    public int TargetId;
    public float Damage;
    public long Tick;
}
```

如果一个结构体最终没有任何成员参与序列化（所有字段都被忽略），会报错（NINO023）：它会被写成 0 字节，由它组成的集合将无法读回。请至少序列化一个成员，或者把它标记为 `versionTolerant` 或 `keyed`。

<Callout type="warn">

原始内存结构体按规范的字段顺序写入：调整字段顺序或修改 `StructLayout` 都会破坏已有数据。如果想避免按原始内存拷贝，可以把它标记为 `versionTolerant`（或用 `[NinoIgnore]` 忽略某个字段）。参见[平台与二进制格式](/zh/docs/v4/platforms)。

</Callout>

## 记录 [#records]

位置记录（positional record）通过主构造函数创建，其参数就是参与序列化的属性。带有成员体的记录与普通类相同。

```csharp
[NinoType]
public record Point(int X, int Y);

[NinoType]
public record struct Range(int Start, int Length);
```

由于这些属性是 `init` 只读的，位置记录每次反序列化都会重新创建，即使是反序列化到已有实例也一样，因此不能使用 [`trackReferences`](/zh/docs/v4/reference-tracking) 或 [`[NinoPooled]`](/zh/docs/v4/pooling)。需要这些功能时，请使用属性可写的记录。实例的创建方式参见[构造函数](/zh/docs/v4/constructors)。

## 泛型类型 [#generic-types]

```csharp
[NinoType]
public class Box<T>
{
    public T Value;
}

[NinoType]
public record struct Pair<TKey, TValue>(TKey Key, TValue Value);
```

每个泛型 `[NinoType]` 定义只生成一个格式化器，而不是每个封闭类型各一个。类型参数必须是可序列化的类型（`Box<int>`、`Box<List<string>>`、`Box<Player>`）。生成器会注册编译中出现过的所有封闭类型（成员类型、基类型、`NinoSerializer`/`NinoDeserializer` 调用的类型参数），确保 AOT 平台具备所需的实例化；其余的由运行时在首次使用时构造。

<Callout type="warn">

如果某个封闭泛型类型在进程中只会被多态地**读取**（按类型 ID），代码中既不出现它的名字，也从不写入它，就需要在启动时注册：`NinoPolymorphic.Register<Box<int>>()`。这种情况只出现在通过反射或在其他程序集中构造的实例化上。

</Callout>

## 继承 [#inheritance]

子类型会从最近的 `[NinoType]` 基类或接口继承 `[NinoType]` 及其选项；如果想给子类型单独设置选项，在子类型上再加一个 `[NinoType]` 即可。子类型自己的 `[NinoType]` 会完全取代继承来的选项，所以需要保留的选项要重新写上：例如版本兼容基类的子类型应写成 `[NinoType(versionTolerant: true)]`。参见[多态](/zh/docs/v4/polymorphism)。
