`class`、`struct`、`record`、`record struct` 或 `interface` 标上 `[NinoType]` 就能序列化。源生成器在编译期写好它的格式化器，不用注册。本页讲哪些成员会写、按什么顺序写，以及哪些选项会改变格式。

```csharp
using Nino.Core;

[NinoType]
public class Order
{
    public long Id;                              // 公共字段
    public string CustomerName { get; set; }     // 有 getter 和 setter 的公共属性
    public List<OrderLine> Lines { get; init; }  // init 访问器也可以
    public DateTime? ShippedAt;                  // 任意可序列化 T 的 Nullable<T>
}
```

```csharp tab="类"
[NinoType]
public class Customer
{
    public int Id;
    public string Email { get; set; }
}
```

```csharp tab="结构体"
[NinoType]
public struct Money
{
    public long MinorUnits;
    public string Currency { get; set; }
}
```

```csharp tab="记录"
[NinoType]
public record Address(string Street, string City, string PostalCode);
```

```csharp tab="记录结构体"
[NinoType]
public record struct GeoPoint(double Latitude, double Longitude);
```

```csharp tab="接口"
[NinoType]
public interface IEvent
{
    long Timestamp { get; set; }
}

public class OrderShipped : IEvent // 继承 [NinoType]
{
    public long Timestamp { get; set; }
    public long OrderId;
}
```

<Callout type="info">

`[NinoType]` 类型和它的所有外层类型都必须是 `public` 或 `internal`（`protected internal` 也行），并且不能是 `static` 类或 `ref struct`（NINO001，带代码修复）。

</Callout>

## `[NinoType]` 选项 [#ninotype-options]

```csharp nocheck
public NinoTypeAttribute(
    bool autoCollect = true,
    bool includeNonPublicMembers = false,
    bool inheritedBySubtypes = true,
    NinoFormat format = NinoFormat.Positional,
    bool trackReferences = false)
```

      default: 'true',

    includeNonPublicMembers: {

    },
    trackReferences: {

`NinoFormat` 是 `Nino.Core` 里的枚举，有三个值：`Positional`、`VersionTolerant` 和 `Keyed`。建议用命名参数，读起来清楚：`[NinoType(format: NinoFormat.VersionTolerant)]`。不带参数的 `[NinoType]` 就是最快、最紧凑的格式：[按位置](/zh/docs/v4/evolving-data#positional)写（成员按声明顺序排，不带名字和长度），每个成员没有额外开销。

## 哪些成员参与序列化 [#which-members-are-serialized]

默认 `autoCollect: true` 时，Nino 收集：

- 所有**公共字段**，以及所有**同时有 getter 和 setter 的公共属性**（`set` 或 `init` 都行）；
- 先收集 `[NinoType]` 基类的成员（从最顶层的基类开始），再按声明顺序收集类型自己的成员；`[NinoType]` 接口的成员，排在继承链上第一个实现它的类的成员前面；
- 记录类型的主构造函数参数（它们本身就是公共属性）。

跳过的成员：

- **只有 getter 的自动属性**（`public int Id { get; }`），除非某个构造函数有同名参数（不区分大小写），因为没有别的办法还原它的值。参见[构造函数](/zh/docs/v4/constructors)；
- 非 `[NinoType]` 接口的**显式接口实现**（`int IHasId.Id { get; set; }`）；如果接口是 `[NinoType]`，改为写出接口的这个成员（见[接口](/zh/docs/v4/polymorphism#interfaces-and-abstract-classes)）；
- 类型无法序列化的成员（委托、`Task`、指针等），同时报警告 NINO007。

`override` 成员和它重写的成员算同一个，只收集一次。用 `new` 隐藏基类成员时，两者是不同的成员，都会序列化，基类的在前。被隐藏的基类成员不是公共的时，生成代码只能通过 `[UnsafeAccessor]` 访问它（.NET 8+；泛型类型要 .NET 9+，见下文）；做不到就跳过这个成员，并报警告 NINO022。

### 忽略成员 [#ignoring-a-member]

```csharp
[NinoType]
public class Session
{
    public int UserId;
    [NinoIgnore] public DateTime CachedAt; // [!code highlight]
}
```

### 显式指定成员 [#choosing-members-explicitly]

用 `[NinoType(false)]`（即 `autoCollect: false`）时，只序列化标了 `[NinoMember(index)]` 的成员，按 `index` 从小到大写：

```csharp tab="类"
[NinoType(false)] // [!code highlight]
public class Invoice
{
    public decimal CachedTotal;                         // 不序列化
    [NinoMember(1)] public string Number { get; set; } // [!code highlight]
    [NinoMember(0)] public long CustomerId;            // 最先写出
}
```

```csharp tab="记录"
[NinoType(false)] // [!code highlight]
public record Shipment(
    [property: NinoMember(2)] string Carrier,         // [!code highlight]
    [property: NinoMember(1)] string TrackingNumber); // [!code highlight]
```

<Callout type="info">

分析器会检查这些标记是否自洽：`autoCollect: true` 时 `[NinoMember]` 是多余的（NINO010），`autoCollect: false` 时 `[NinoIgnore]` 是多余的（NINO011），同一成员不能两个都标（NINO012），索引不能重复（NINO013）。这些诊断都带代码修复。

</Callout>

### 私有成员 [#private-members]

设置 `includeNonPublicMembers` 后，非公开成员也参与序列化：

```csharp
[NinoType(includeNonPublicMembers: true)] // [!code highlight]
public partial class Account
{
    private long _balance;
    protected string Owner;
    public int Id;
}
```

- 在 .NET 8 及以上版本，生成代码通过 `[UnsafeAccessor]` 访问私有成员；泛型类型需要 .NET 9 及以上（编译定义了 `NET9_0_OR_GREATER`）。
- 更早的平台（.NET Standard、.NET Framework 和 Unity；以及 .NET 8 上的泛型类型）上，生成代码在类型**内部**生成访问器，所以这个类型和它的所有外层类型都必须是 `partial`（NINO002，带代码修复）。在 .NET 9+ 上，泛型类型要序列化泛型基类的非公开成员，而基类的类型实参又不是它自己按顺序排列的前几个类型参数时，也需要 `partial`：`class D<T> : Base<List<T>>` 或 `Base<int>` 需要，`class D<T, U> : Base<T>` 不需要。
- 没设置 `includeNonPublicMembers` 却给非公开成员标 `[NinoMember]`，报错（NINO009）。
- 基类的私有成员永远不属于子类型。

编译器看不到生成的访问器，所以 Nino 会屏蔽它要序列化的私有成员上“字段从未使用 / 从未赋值”之类的编译器警告。

## 成员顺序 [#member-order]

不用 `format: NinoFormat.Keyed` 时，成员顺序**就是**数据格式。默认先写基类成员，再按声明顺序写类型自己的成员。想换个顺序，就用 `[NinoType(false)]`，给每个成员加上 `[NinoMember(index)]`：成员按索引从小到大写，示例见[显式指定成员](#choosing-members-explicitly)。

<Callout type="warn">

调整顺序、插入或删除成员（或者改索引），之前写出的数据就读不了了。请提前用[版本容错或键控成员](/zh/docs/v4/evolving-data)为以后的改动做准备。

</Callout>

## 字符串编码 [#string-encoding]

默认情况下，Nino 为每个字符串单独选写法：所有字符都不超过 U+00FF（ASCII 和 Latin-1：英文、标识符、键名、西欧文字）时每个字符一个字节，否则用 UTF-16。两种写法都只是把字符收窄、展宽或拷贝一遍，在 .NET 8 及以上做了向量化。给成员加上 `[NinoUtf8]` 就改写 UTF-8。以 ASCII 为主、夹着少量 U+00FF 以上字符（弯引号、emoji、其他文字的名字）的文本，默认编码会整串写成 UTF-16，这时 `[NinoUtf8]` 才划算；代价是要转码，还要多写一个字节数（UTF-8 不超过 127 字节时占 1 字节）。典型场景：要发给大量客户端的聊天内容和用户名，或者存盘的大型文本表。以中日韩文字为主的文本请保持默认编码：这类字符在 UTF-8 下每个占 3 字节，在 UTF-16 下只占 2 字节。

| n 个字符的文本（不计头） | 默认 | `[NinoUtf8]` |
| --- | --- | --- |
| ASCII（英文、标识符、键名） | n 字节 | n 字节，外加字节数 |
| U+007F 以上的 Latin-1（é、ü） | n 字节 | 这样的字符每个 2 字节 |
| 以 ASCII 为主，夹杂少量 U+00FF 以上的字符（“弯引号”、emoji） | 2n 字节：整个字符串写成 UTF-16 | 约 n 字节 |
| 以中日韩文字为主 | 2n 字节 | 约 3n 字节 |

```csharp
[NinoType]
public class ChatMessage
{
    public int SenderId;
    [NinoUtf8] public string Text;                       // [!code highlight]
    [NinoUtf8] public Dictionary<string, string> Tags;   // 键和值也按 UTF-8 写
}
```

`[NinoUtf8]` 作用于这个成员的格式化器直接写出的每个字符串：成员本身，以及集合或元组成员里的 `string` 元素、键、值和元组项（`List<string>`、`string[]`、`Dictionary<string, int>`、`(string, int)`）。嵌套的 `[NinoType]` 里的字符串，仍按那个类型自己的设置编码。它不起作用时（成员不含字符串、由 `[NinoMemberFormatter]` 写出，或者根本不序列化），分析器报警告 [NINO030](/zh/docs/v4/analyzers#nino030)；标在接口成员上时报 [NINO033](/zh/docs/v4/analyzers#nino033)，应该标在实现成员上。要 UTF-8 就用 `[NinoUtf8]`，这是唯一的写法；手写的 `[NinoMemberFormatter(typeof(Utf8StringFormatter))]` 会被当作它处理（NINO031）。

读写双方必须一致：按 UTF-8 写的数据，成员没标 `[NinoUtf8]` 的类型读不了。UTF-8 字符串同时写了字符数和字节数，所以读的时候能按最终长度分配字符串，再一遍把这些字节转码进去（参见[字符串](/zh/docs/v4/wire-format#strings)）。

## 旧名称 [#former-name]

成员、元素或变量的声明类型是非密封类、抽象类、接口或 `object` 时，值会连同它运行时类型的**类型 ID** 一起写出。类型 ID 是类型全名的 32 位哈希，读取时靠它还原成正确的类型。类型改名或换命名空间，ID 就变了，密封的子类型也一样（比如通过 `Message` 基类发送的各个消息类）。

典型场景：你把协议类从 `MyApp.Net` 挪到了 `MyApp.Protocol`，而上个版本存下的文件或客户端用的还是旧 ID。加上 `[NinoFormerName]` 就能继续读旧数据：

```csharp
namespace MyApp.Protocol
{
    [NinoType]
    [NinoFormerName("MyApp.Net.OrderPlaced")] // [!code highlight]
    public class OrderPlaced
    {
        public long OrderId;
    }
}
```

旧名称用全名的**运行时形式**：`Namespace.Type`，嵌套类型和外层类型之间用 `+` 连接（`Namespace.Outer+Inner`），不带 `global::`。类型 ID 由旧名称算出，所以改名后的类型读写的仍是已有数据和旧版读取方用的那个 ID。`NinoTypeId.Of(typeof(T))` 返回某个类型写出的 ID。一个类型只能有一个 `[NinoFormerName]`，因为 ID 只能由一个名称算出；再加一个就报错 NINO026。

在 `NinoFormat.Keyed` 类型的字段或属性上，`[NinoFormerName("OldName")]`（可以写多个）让按成员旧名称写出的数据仍能读取，参见[重命名键控成员](/zh/docs/v4/evolving-data#renaming-keyed-members)。按位置和版本容错的类型不写成员名，重命名成员时什么都不用做。

## 结构体 [#structs]

`[NinoType]` 结构体不带任何头部。满足下面的条件时，它按**原始内存**写（单个值拷贝一次，数组和列表整块拷贝）：

- 是非托管类型，并使用顺序布局（默认就是顺序布局，设不设 `Pack` 和 `Size` 都行；`LayoutKind.Explicit` 和 `LayoutKind.Auto` 的结构体不按原始内存写）；
- 格式不是 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`，也没有自定义成员格式化器；
- 每个实例字段都参与序列化，而且字段本身也按原始字节写（不是 `Nullable<T>`、元组、`nint`、`DateTimeOffset`，也不是不按原始内存写的 `[NinoType]` 结构体）。

否则逐个成员写。不管哪种，只要它是按位置格式（既不是版本容错也不是键控），并且所有成员都是原始值或这样的结构体，它就是[固定大小](/zh/docs/v4/performance#fixed-size-types)的：`NinoSerializer.Serialize(value)` 直接把它写进大小正好的 `byte[]`。

```csharp
[NinoType]
public struct SensorReading // 原始值：一次拷贝 16 字节，没有填充
{
    public int SensorId;
    public float Value;
    public long Timestamp;
}
```

结构体如果最终一个成员都不参与序列化（字段全被忽略），就报错（NINO023）：它会写成 0 字节，由它组成的集合也读不回来。请至少序列化一个成员，或者给这个结构体设置 `format: NinoFormat.VersionTolerant` 或 `format: NinoFormat.Keyed`。

<Callout type="warn">

原始结构体按规范的字段顺序写：调整字段顺序或改 `StructLayout` 都会破坏已有数据。不想按原始内存拷贝，就给它设置 `format: NinoFormat.VersionTolerant`（或者用 `[NinoIgnore]` 忽略某个字段）。它的布局在所有运行时上都一样，参见[结构体布局](/zh/docs/v4/struct-layouts)。

</Callout>

## 记录 [#records]

位置记录（positional record）通过主构造函数创建，构造函数的参数就是参与序列化的属性。带类体的记录和普通类一样处理。

```csharp
[NinoType]
public record Price(decimal Amount, string Currency);

[NinoType]
public record struct DateRange(DateTime Start, DateTime End);
```

这些属性只有 `init` 访问器，所以位置记录每次反序列化都会重新创建，读入已有实例时也一样，因此不能用 [`trackReferences`](/zh/docs/v4/reference-tracking) 或 [`[NinoPooled]`](/zh/docs/v4/pooling)。需要这些功能时，请用属性可写的记录。实例怎么创建见[构造函数](/zh/docs/v4/constructors)。

## 泛型类型 [#generic-types]

```csharp
[NinoType]
public class Box<T>
{
    public T Value;
}

[NinoType]
public record struct Pair<TKey, TValue>(TKey Key, TValue Value);
```

每个泛型 `[NinoType]` 定义只生成一个格式化器，不是每个封闭类型各一个。类型实参必须可序列化（`Box<int>`、`Box<List<string>>`、`Box<Order>`）。生成器会注册当前编译里出现的所有封闭类型（成员类型、基类型、`NinoSerializer`/`NinoDeserializer` 调用的类型参数、装箱调用和 `IsSupported` 的 `typeof` 参数），保证 AOT 平台有所需的实例化；其余的由运行时在第一次用到时构造，而 Native AOT 做不到这一点（参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)）。

封闭的泛型 `[NinoType]` 结构体不管出现在哪里（成员、元素、类型实参或顶层），都由它的定义的格式化器写出。只要有字段的类型是类型参数，不管实参是什么，它都逐成员写，所以上面的 `Pair<int, int>` 逐成员写，永远不按原始内存拷贝。

<Callout type="warn">

如果进程只会按多态方式**读取**某个封闭泛型类型（按类型 ID），代码里既不出现它的名字，也从不写它，就要在启动时注册：`NinoPolymorphic.TryRegister<Box<int>>()`。只有通过反射或在其他程序集里构造的实例化，才会遇到这种情况。

</Callout>

## 继承 [#inheritance]

子类型从最近的 `[NinoType]` 基类或接口继承 `[NinoType]` 和它的选项；想给子类型单独设选项，在子类型上再加一个 `[NinoType]` 就行。子类型自己的 `[NinoType]` 会替换继承来的选项，所以要保留的选项得重新写上：比如版本容错基类的子类型要写 `[NinoType(format: NinoFormat.VersionTolerant)]`。唯一的例外是 `trackReferences`：只要类本身或任何一个 `[NinoType]` 基类、接口要求追踪，这个类就追踪引用，不管它自己的特性怎么写，所以开了追踪的继承体系始终保持追踪。参见[多态](/zh/docs/v4/polymorphism)。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 由谁发现 |
| --- | --- | --- |
| 按位置格式的类型，数据已经存下或发出后，又调整成员顺序、插入或删除成员 | 旧数据读进错误的成员，或者抛出 `NinoDataException` | 编译时发现不了：改用[版本容错或键控成员](/zh/docs/v4/evolving-data)，并在 CI 中检查[布局元数据](/zh/docs/v4/evolving-data#layout-metadata) |
| 重命名或移动一个连同类型 ID 写出的类型 | 旧数据的类型 ID 认不出来：`NinoDataException` | 无：加上 [`[NinoFormerName]`](#former-name) |
| 只读属性没有对应的构造函数参数 | 不参与序列化 | [NINO006](/zh/docs/v4/analyzers#nino006) |
| 成员的类型 Nino 无法序列化（委托、`Task`） | 跳过这个成员 | [NINO007](/zh/docs/v4/analyzers#nino007) |
| 在 .NET Standard、.NET Framework 或 Unity 上，类型有非公开成员却不是 `partial` | 生成的代码无法编译 | [NINO002](/zh/docs/v4/analyzers#nino002)，带代码修复 |
| `[NinoUtf8]` 加在不含字符串、由 `[NinoMemberFormatter]` 写出或从不序列化的成员上 | 不起作用 | [NINO030](/zh/docs/v4/analyzers#nino030) |
| `[NinoUtf8]` 加在接口成员上 | 不起作用：只认实现成员上的特性 | [NINO033](/zh/docs/v4/analyzers#nino033)，代码修复会把它移过去 |
| 数据已经存下或发出后，给成员加上或去掉 `[NinoUtf8]` | 按另一种编码写出的数据读不回来 | 无：这会改变格式，和换掉成员类型一样 |
| 结构体的字段全被忽略 | 它会写成 0 字节 | [NINO023](/zh/docs/v4/analyzers#nino023) |
