任何标记了 `[NinoType]` 的 `class`、`struct`、`record`、`record struct` 或 `interface` 都可以序列化。源生成器在编译期生成它的格式化器，无需注册。本页介绍哪些成员会写入、按什么顺序写入，以及哪些选项会改变格式。

```csharp
using Nino.Core;

[NinoType]
public class Order
{
    public long Id;                              // public fields
    public string CustomerName { get; set; }     // public properties with a getter and a setter
    public List<OrderLine> Lines { get; init; }  // init setters work too
    public DateTime? ShippedAt;                  // Nullable<T> of any serializable T
}
```

<Callout type="info">

`[NinoType]` 类型及其所有外层类型必须是 `public` 或 `internal`（`protected internal` 也可以），并且不能是 `static` 类或 `ref struct`（NINO001，提供代码修复）。

</Callout>

## `[NinoType]` 选项 [#ninotype-options]

```csharp
public NinoTypeAttribute(
    bool autoCollect = true,
    bool containNonPublicMembers = false,
    bool allowInheritance = true,
    NinoFormat format = NinoFormat.Positional,
    bool trackReferences = false)
```

<TypeTable
  type={{
    autoCollect: {
      description: <><code>true</code>：序列化所有公共字段和属性。<code>false</code>：只序列化标记了 <code>[NinoMember]</code> 的成员。</>,
      type: 'bool',
      default: 'true',
    },
    containNonPublicMembers: {
      description: <>同时序列化 <code>private</code>、<code>protected</code> 和 <code>internal</code> 成员（配合 <code>autoCollect</code> 时收集全部，否则只收集标记了 <code>[NinoMember]</code> 的）。</>,
      type: 'bool',
      default: 'false',
    },
    allowInheritance: {
      description: <>子类型继承此特性，可以通过此类型序列化。设为 <code>false</code> 时，子类型必须自己声明 <code>[NinoType]</code>（NINO003）。</>,
      type: 'bool',
      default: 'true',
    },
    format: {
      description: <>成员的写入方式。<code>Positional</code>：成员依次写入，体积最小、速度最快。<code>VersionTolerant</code>：以后可以向最末端的派生类型追加成员（参见<a href="/zh/docs/v4/evolving-data#version-tolerance">版本容错</a>）。<code>Keyed</code>：每个成员带键写入，之后可以调整顺序、删除和插入成员（参见<a href="/zh/docs/v4/evolving-data#keyed-members">键控成员</a>）。</>,
      type: 'NinoFormat',
      default: 'NinoFormat.Positional',
    },
    trackReferences: {
      description: <>仅适用于类。共享引用和循环引用在序列化往返后保持不变。参见<a href="/zh/docs/v4/reference-tracking">引用追踪</a>。</>,

      default: 'false',
    },

/>

`NinoFormat` 是 `Nino.Core` 中的枚举，有三个值：`Positional`、`VersionTolerant` 和 `Keyed`。建议使用命名参数，方便阅读：`[NinoType(format: NinoFormat.VersionTolerant)]`。不带参数的 `[NinoType]` 是最快、最紧凑的格式：[按位置](/zh/docs/v4/evolving-data#positional)写入（成员按声明顺序排列，不带名称和长度），每个成员没有额外开销。

## 哪些成员会被序列化 [#which-members-are-serialized]

在默认的 `autoCollect: true` 下，Nino 会收集：

- 所有**公共字段**，以及所有**同时具有 getter 和 setter 的公共属性**（`set` 或 `init` 均可）；
- 先收集 `[NinoType]` 基类的成员（从最上层的基类开始），再按声明顺序收集类型自身的成员；`[NinoType]` 接口的成员排在继承链中第一个实现它的类的成员之前；
- 记录类型的主构造函数参数（它们本身就是公共属性）。

以下成员会被跳过：

- **只有 getter 的自动属性**（`public int Id { get; }`），除非某个构造函数有同名参数（不区分大小写），因为没有别的办法能还原它的值。参见[构造函数](/zh/docs/v4/constructors)；
- **显式接口实现**（`int IHasId.Id { get; set; }`），因为生成代码无法通过名称访问它。`[NinoType]` 接口的成员会通过实现类型中同名的成员来序列化；
- 类型无法序列化的成员（委托、`Task`、指针等），并报告警告 NINO007。

`override` 成员和它重写的成员算作同一个，只收集一次。用 `new` 隐藏基类成员时，两者是不同的成员，都会序列化，基类的在前。如果被隐藏的基类成员不是公共的，生成代码只能通过 `[UnsafeAccessor]` 访问它（.NET 8+；泛型类型需 .NET 9+，见下文）；否则会跳过该成员并报告警告 NINO022。

### 忽略成员 [#ignoring-a-member]

```csharp
[NinoType]
public class Session
{
    public int UserId;
    [NinoIgnore] public DateTime CachedAt; // [!code highlight]
}
```

### 显式指定成员 [#choosing-members-explicitly]

使用 `[NinoType(false)]`（即 `autoCollect: false`）时，只有标记了 `[NinoMember(index)]` 的成员会被序列化，按 `index` 升序写入：

<Tabs items={["类", "记录"]}>
<Tab value="类">

```csharp
[NinoType(false)] // [!code highlight]
public class Invoice
{
    public decimal CachedTotal;                         // not serialized
    [NinoMember(1)] public string Number { get; set; } // [!code highlight]
    [NinoMember(0)] public long CustomerId;            // written first
}
```

</Tab>
<Tab value="记录">

```csharp
[NinoType(false)] // [!code highlight]
public record Shipment(
    [property: NinoMember(2)] string Carrier,         // [!code highlight]
    [property: NinoMember(1)] string TrackingNumber); // [!code highlight]
```

</Tab>
</Tabs>

<Callout type="info">

分析器会检查这些标记是否一致：`autoCollect: true` 时 `[NinoMember]` 是多余的（NINO010），`autoCollect: false` 时 `[NinoIgnore]` 是多余的（NINO011），同一成员不能同时标记两者（NINO012），索引不能重复（NINO013）。这些诊断都附带代码修复。

</Callout>

### 私有成员 [#private-members]

设置 `containNonPublicMembers` 后，非公开成员也会被序列化：

```csharp
[NinoType(containNonPublicMembers: true)] // [!code highlight]
public partial class Account
{
    private long _balance;
    protected string Owner;
    public int Id;
}
```

- 在 .NET 8 及以上版本，生成代码通过 `[UnsafeAccessor]` 访问私有成员；泛型类型需要 .NET 9 及以上（编译定义了 `NET9_0_OR_GREATER`）。
- 在此之前（.NET Standard、.NET Framework 和 Unity；.NET 8 上的泛型类型），生成代码会在类型**内部**生成访问器，所以该类型及其所有外层类型都必须声明为 `partial`（NINO002，提供代码修复）。在 .NET 9+ 上，如果泛型类型要序列化泛型基类的非公开成员，而基类的类型参数不是它自己按顺序排列的前几个类型参数，也需要 `partial`：`class D<T> : Base<List<T>>` 或 `Base<int>` 需要，`class D<T, U> : Base<T>` 不需要。
- 没有设置 `containNonPublicMembers` 却给非公开成员标记 `[NinoMember]`，会报错（NINO009）。
- 基类的私有成员永远不属于子类型。

编译器看不到生成的访问器，所以在 Nino 要序列化的私有成员上，Nino 会屏蔽“字段从未使用 / 从未赋值”之类的编译器警告。

## 成员顺序 [#member-order]

不使用 `format: NinoFormat.Keyed` 时，成员顺序**就是**数据格式。默认先写基类成员，再按声明顺序写类型自身的成员。如果想换一种顺序，就使用 `[NinoType(false)]`，并给每个成员加上 `[NinoMember(index)]`：成员按索引升序写入，示例见[显式指定成员](#choosing-members-explicitly)。

<Callout type="warn">

调整顺序、插入或删除成员（或修改索引）都会让之前写出的数据无法读取。请提前用[版本容错或键控成员](/zh/docs/v4/evolving-data)为将来的改动做好准备。

</Callout>

## 字符串编码 [#string-encoding]

默认情况下，Nino 为每个字符串单独选择写法：所有字符都不超过 U+00FF（ASCII 和 Latin-1：英文、标识符、键名、西欧文字）时每个字符一个字节，否则用 UTF-16。两种写法都只需一遍收窄、扩宽或复制字符，在 .NET 8 及以上做了向量化。给成员加上 `[NinoUtf8]` 则改为 UTF-8。它适合以 ASCII 为主、但夹杂少量 U+00FF 以上字符（弯引号、emoji、其他文字的名字）的文本，默认编码会把这样的文本整个写成 UTF-16；代价是需要转码，还要多写字节数（UTF-8 不超过 127 字节时占 1 字节）。适合字节比 CPU 更贵的场景：要广播给大量客户端的聊天内容和用户名，或者落盘的大型文本表。以中日韩文字为主的文本请保持默认编码：这类字符在 UTF-8 下每个占 3 字节，在 UTF-16 下只占 2 字节。

```csharp
[NinoType]
public class ChatMessage
{
    public int SenderId;
    [NinoUtf8] public string Text;                       // [!code highlight]
    [NinoUtf8] public Dictionary<string, string> Tags;   // keys and values are UTF-8 too
}
```

该特性作用于这个成员的格式化器直接写出的所有字符串：成员本身，以及集合或元组成员中的 `string` 元素、键、值和元组项（`List<string>`、`string[]`、`Dictionary<string, int>`、`(string, int)`）。嵌套的 `[NinoType]` 里的字符串仍按那个类型自己的设置编码；成员中不含字符串时，该特性不起作用。

读写双方必须一致：以 UTF-8 写出的数据，不能由一个没有给该成员标 `[NinoUtf8]` 的类型读取。UTF-8 字符串会同时写入字符数和字节数，所以读取时可以按最终长度分配字符串，再一次性把这些字节转码进去（参见[二进制格式](/zh/docs/v4/platforms#binary-format)）。

## 旧名称 [#former-name]

如果成员、元素或变量的声明类型是非密封类、抽象类、接口或 `object`，值会连同它运行时类型的**类型 ID** 一起写入。类型 ID 是类型全名的 32 位哈希，读取时靠它还原成正确的类型。类型改名或换命名空间后，ID 也会变，密封的子类型也一样（例如通过 `Message` 基类发送的各个消息类）。

典型场景：你把协议类从 `MyApp.Net` 挪到了 `MyApp.Protocol`，而上个版本存下的文件或客户端用的还是旧 ID。用 `[NinoFormerName]` 可以继续读取旧数据：

```csharp
namespace MyApp.Protocol
{
    [NinoType]
    [NinoFormerName("MyApp.Net.OrderPlaced")] // [!code highlight]
    public class OrderPlaced
    {
        public long OrderId;
    }
}
```

旧名称使用全名的**运行时形式**：`Namespace.Type`，嵌套类型与外层类型之间用 `+` 连接（`Namespace.Outer+Inner`），不带 `global::`。类型 ID 由旧名称计算，所以改名后的类型写出和读取的仍是已有数据和旧版读取方使用的那个 ID。`NinoTypeId.Of(typeof(T))` 可以查看某个类型写出的 ID。一个类型只能有一个 `[NinoFormerName]`，因为它的 ID 只由一个名称计算；再加一个会报错 NINO026。

在 `NinoFormat.Keyed` 类型的字段或属性上，`[NinoFormerName("OldName")]`（可重复使用）可以继续读取以成员旧名称写出的数据，参见[重命名键控成员](/zh/docs/v4/evolving-data#renaming-keyed-members)。按位置和版本容错的类型不写成员名，重命名成员时什么都不用做。

## 结构体 [#structs]

`[NinoType]` 结构体没有任何头部。满足以下条件时，它按**原始内存**写入（单个值一次拷贝，数组和列表整块拷贝）：

- 是非托管类型，并使用顺序布局（默认就是顺序布局，设不设 `Pack` 和 `Size` 都可以；`LayoutKind.Explicit` 和 `LayoutKind.Auto` 的结构体不按原始内存写入）；
- 格式不是 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`，也没有自定义成员格式化器；
- 每个实例字段都参与序列化，而且这些字段本身也按原始字节写入（不是 `Nullable<T>`、元组、`nint`、`DateTimeOffset`，也不是非原始内存的 `[NinoType]` 结构体）。

否则逐个成员写入。无论哪种情况，只要它是按位置格式（既不是版本容错也不是键控），并且所有成员都是原始值或这样的结构体，它就是[固定大小的](/zh/docs/v4/performance#fixed-size-types)：`NinoSerializer.Serialize(value)` 会把它直接写进大小正好的 `byte[]`。

```csharp
[NinoType]
public struct SensorReading // raw: one 16-byte copy, no padding
{
    public int SensorId;
    public float Value;
    public long Timestamp;
}
```

如果一个结构体最终没有任何成员参与序列化（所有字段都被忽略），会报错（NINO023）：它会被写成 0 字节，由它组成的集合也无法读回。请至少序列化一个成员，或者给这个结构体设置 `format: NinoFormat.VersionTolerant` 或 `format: NinoFormat.Keyed`。

<Callout type="warn">

原始结构体按规范的字段顺序写入：调整字段顺序或修改 `StructLayout` 都会破坏已有数据。如果想避免按原始内存拷贝，可以给它设置 `format: NinoFormat.VersionTolerant`（或用 `[NinoIgnore]` 忽略某个字段）。参见[平台与二进制格式](/zh/docs/v4/platforms)。

</Callout>

## 记录 [#records]

位置记录（positional record）通过主构造函数创建，构造函数的参数就是参与序列化的属性。带类体的记录和普通类一样。

```csharp
[NinoType]
public record Price(decimal Amount, string Currency);

[NinoType]
public record struct DateRange(DateTime Start, DateTime End);
```

由于这些属性只有 `init` 访问器，位置记录每次反序列化都会重新创建，即使是反序列化到已有实例也一样，因此不能使用 [`trackReferences`](/zh/docs/v4/reference-tracking) 或 [`[NinoPooled]`](/zh/docs/v4/pooling)。需要这些功能时，请使用属性可写的记录。实例的创建方式参见[构造函数](/zh/docs/v4/constructors)。

## 泛型类型 [#generic-types]

```csharp
[NinoType]
public class Box<T>
{
    public T Value;
}

[NinoType]
public record struct Pair<TKey, TValue>(TKey Key, TValue Value);
```

每个泛型 `[NinoType]` 定义只生成一个格式化器，而不是每个封闭类型各一个。类型参数必须是可序列化的类型（`Box<int>`、`Box<List<string>>`、`Box<Order>`）。生成器会注册当前编译中用到的所有封闭类型（成员类型、基类型、`NinoSerializer`/`NinoDeserializer` 调用的类型参数），确保 AOT 平台有需要的实例化；其余的由运行时在第一次用到时构造。

封闭的泛型 `[NinoType]` 结构体无论出现在哪里（成员、元素、类型实参或顶层），都由其定义的格式化器写出。只要有类型参数类型的字段，不论实参是什么，它都逐成员写出，所以上面的 `Pair<int, int>` 逐成员写出，永远不会按原始内存复制。

<Callout type="warn">

如果进程只会多态地**读取**某个封闭泛型类型（按类型 ID），代码中既不出现它的名字，也从不写入它，就需要在启动时注册：`NinoPolymorphic.Register<Box<int>>()`。只有通过反射或在其他程序集中构造的实例化，才会遇到这种情况。

</Callout>

## 继承 [#inheritance]

子类型会从最近的 `[NinoType]` 基类或接口继承 `[NinoType]` 及其选项；如果想给子类型单独设置选项，在子类型上再加一个 `[NinoType]` 即可。子类型自己的 `[NinoType]` 会取代继承来的选项，所以需要保留的选项要重新写上：例如版本容错基类的子类型应写成 `[NinoType(format: NinoFormat.VersionTolerant)]`。唯一的例外是 `trackReferences`：只要类本身或任意一个 `[NinoType]` 基类、接口要求追踪，这个类就会被追踪，与它自己的特性怎么写无关，因此开启了追踪的继承体系会一直保持追踪。参见[多态](/zh/docs/v4/polymorphism)。
