<AnchorRedirect map={{ 'example-memory': '/zh/docs/v4/types#collection-types' }} />

Nino 自带[内置类型](/zh/docs/v4/types)的格式化器，并为每个 `[NinoType]` 生成一个。想换种方式编码某个成员（变长整数、定点数），或者要序列化 Nino 不认识的类型（第三方集合、别的库里的类型），就自己写一个格式化器。

<Callout type="idea" title="适合">

单个成员换一种编码（[`[NinoMemberFormatter]`](#for-one-member)），以及没法标 `[NinoType]`、Nino 又不支持的类型（[`[assembly: NinoFormatter]`](#for-a-type-assembly-ninoformatter)）。

</Callout>

<Callout type="warn" title="不适合">

自己的类型（标 `[NinoType]` 就行）、Nino 已经支持的类型（见[支持的类型](/zh/docs/v4/types)；运行时可以用 `NinoSerializer.IsSupported(type)` 判断）、UTF-8 字符串（用 `[NinoUtf8]`），以及应该保持[原始内存拷贝](/zh/docs/v4/advanced/type-design#keep-bulk-data-raw)的热点结构体。格式化器写出什么字节，只有它自己的代码知道：[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)把它负责的成员显示为 `formatter(F)`，[生成的 TypeScript](/zh/docs/v4/advanced/typescript#not-supported) 也会跳过含有这类成员的类型。

</Callout>

格式化器是实现了 `INinoFormatter<T>` 的**结构体**：

```csharp nocheck
public interface INinoFormatter<T>
{
    void Serialize(T value, ref Writer writer);
    void Deserialize(ref Reader reader, ref T value);
}
```

`Deserialize` 和所有读取 API 一样，第一个参数是 reader，再通过 `ref` 拿到当前值：`default` 表示要创建新值，已有实例则可以复用。格式化器总是以 `default(TFormatter)` 调用，没有实例状态；要保存状态，请放进静态字段。

## 用于单个成员 [#for-one-member]

用 `[NinoMemberFormatter]` 让某个成员改用你自己的格式化器。格式化器实现的 `INinoFormatter<T>` 里，`T` 必须**正好**是成员类型（NINO008）。

典型的例子是账本或指标流：每条记录存的是各个数值的变化量。变化量通常很小，`long` 却总要占 8 字节。改用 zig-zag 变长整数后，-64 到 63 的值只占 1 字节，±8191 以内只占 2 字节：

```csharp
/// 把 long 写成 zig-zag varint。
public struct ZigZagLongFormatter : INinoFormatter<long>
{
    public void Serialize(long value, ref Writer writer)
    {
        ulong v = (ulong)((value << 1) ^ (value >> 63));
        while (v >= 0x80)
        {
            writer.Write((byte)(v | 0x80));
            v >>= 7;
        }
        writer.Write((byte)v);
    }

    public void Deserialize(ref Reader reader, ref long value)
    {
        ulong v = 0;
        int shift = 0;
        byte b;
        do
        {
            reader.Read(out b);
            v |= (ulong)(b & 0x7F) << shift;
            shift += 7;
        } while ((b & 0x80) != 0 && shift < 70); // 最多 10 字节：一个 64 位值
        if ((b & 0x80) != 0 || (shift == 70 && b > 1))
            throw new NinoDataException("Nino: invalid varint."); // 超过 10 字节，或第 10 字节溢出 64 位
        value = (long)(v >> 1) ^ -(long)(v & 1);
    }
}

[NinoType]
public sealed class BalanceChange
{
    public int AccountId;
    [NinoMemberFormatter(typeof(ZigZagLongFormatter))] // [!code highlight]
    public long DeltaCents;
}
```

这个特性作用于单个字段或属性，外层类型不管在哪里序列化都生效。用了自定义格式化器的成员，不会跟着[原始内存](/zh/docs/v4/defining-types#structs)整块拷贝。格式化器不是结构体，或者针对的类型不对，分析器报 NINO008。

## 用于整个类型：`[assembly: NinoFormatter]` [#for-a-type-assembly-ninoformatter]

要让 Nino 支持它不认识的类型（你自己的或第三方的），就在程序集上注册一个格式化器。类型参数和元素格式化器都自动推断：约束为 `INinoFormatter<E>` 的类型参数，拿到的是 Nino 为 `E` 解析出的格式化器，所以元素的读写都能内联。生成代码直接调用这个格式化器，运行时用的也是同一份注册信息。

```csharp
[assembly: NinoFormatter(typeof(RingFormatter<,>))]

// 来自一个你没法加特性的库：容量固定的缓冲区，结构体枚举器让 foreach 不分配内存
//   public sealed class Ring<T> : IEnumerable<T>
//   {
//       public Ring(int capacity); public int Count { get; } public int Capacity { get; }
//       public void Push(T item); public void Clear(); public Enumerator GetEnumerator();
//   }

public struct RingFormatter<T, TFormatter> : INinoFormatter<Ring<T>>
    where TFormatter : struct, INinoFormatter<T>
{
    private const int MaxCapacity = 1 << 20; // 一个环最多容纳的元素数

    public void Serialize(Ring<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.WriteNullLength();          // -1
            return;
        }

        writer.WriteLength(value.Count);
        writer.Write(value.Capacity);
        foreach (var item in value)            // Ring 的结构体枚举器：不分配内存
            default(TFormatter).Serialize(item, ref writer); // 内联的元素格式化器
    }

    public void Deserialize(ref Reader reader, ref Ring<T> value)
    {
        int count = reader.ReadLength();       // 对照剩余字节校验
        if (count < 0)
        {
            NinoRecycler.Discard(ref value);   // 数据中是 null：回收旧的 ring
            return;
        }

        reader.Read(out int capacity);
        // 容量不对应数据里的字节：分配之前先限定它
        if ((uint)capacity < (uint)count || capacity > MaxCapacity)
            throw new NinoDataException("Nino: invalid ring capacity.");
        if (value != null && value.Capacity == capacity)
            value.Clear();                     // 复用已有的 ring // [!code highlight]
        else
            NinoRecycler.Replace(ref value, new Ring<T>(capacity)); // 如果有旧的，就回收它
        for (int i = 0; i < count; i++)
        {
            T item = default;
            default(TFormatter).Deserialize(ref reader, ref item);
            value.Push(item);
        }
    }
}

[NinoType]
public sealed class RingHolder
{
    public Ring<int> Ints;          // 使用 RingFormatter<int, ...>
    public List<Ring<string>> Nested;
}
```

- 格式化器必须是结构体，不能嵌套在泛型类型里，并且只实现一次 `INinoFormatter<P>`。泛型格式化器按开放定义注册（`typeof(F<,>)`），非泛型格式化器直接注册（`typeof(F)`）。每个类型参数都必须推断得出：要么出现在 `P` 里，要么出现在类型约束里（`where TList : List<T>`），要么受 `INinoFormatter<E>` 约束。用不了的注册直接忽略，并报 NINO020。
- `Deserialize` 要丢弃实例时（数据是 `null`，或者旧实例没法复用），请交给 `NinoRecycler`，不要直接覆盖，[回收处理器和对象池](/zh/docs/v4/pooling)才能拿到它：数据是 `null` 时用 `Discard(ref value)`；换成新实例时用 `Replace(ref value, replacement)`；要把旧实例交给更具体类型的格式化器时用 `Reuse<TDeclared, TConcrete>(ref value)`（返回这个实例，或者回收它并返回 `null`）；集合丢掉的每个元素用 `NinoRecycler<T>.Recycle(element)`，`NinoRecycler<T>.MayRecycle` 为 false 时可以跳过。
- 格式化的目标是裸类型参数（`INinoFormatter<TCollection>`）时，可以列出适用的类型定义：`[assembly: NinoFormatter(typeof(F<,,>), typeof(IList<>))]`。不列时，约束允许的所有类型都适用。
- 查找顺序：先找为类型自身的定义（以及数组）注册的格式化器，再是原始非托管值，再是 `[NinoType]`，最后是裸类型参数的格式化器。多个注册同时匹配时，`Priority` 高的胜出（例如 `Priority = 10`）；优先级相同时，取完整名称按序数排在前面的那个。

<Callout type="info" title="声明式注册，无需启动代码">

`[assembly: NinoFormatter]` 是特性，不是方法调用：没有模块初始化器，启动时什么都不用执行。运行时第一次遇到某个程序集里的类型，就读取这个程序集的注册信息（查找落空时，读取所有已加载的程序集）。所以 HybridCLR 热更新程序集里声明的格式化器，程序集一加载就能用。Nino 自带的 BCL 格式化器也是这样声明的。

没有在运行时注册或替换格式化器的 API：格式化器一律用 `[assembly: NinoFormatter]` 声明，单个成员则用 `[NinoMemberFormatter]`。所以进程运行期间，一个类型的格式化器不会变，生成代码和运行时用的始终是同一个。

</Callout>

### 示例：别的库里的泛型类型 [#example-grid]

下面的 `Grid<T>` 代表别的库里的类型，你没法给它加 `[NinoType]`。这个格式化器支持元素为任意原始类型的 `Grid<T>`：先写宽度，再把所有格子整块写出；读取时如果大小没变，就直接读进现有的网格，所以[复用反序列化](/zh/docs/v4/pooling)不分配内存：

```csharp title="GridFormatter.cs"
using System;
using System.Numerics;
using System.Runtime.CompilerServices;
using Nino.Core;

// 来自一个你没法加特性的库：
//   public sealed class Grid<T> { public Grid(int width, int height); public int Width { get; } public T[] Cells { get; } }

[assembly: NinoFormatter(typeof(GridFormatter<>))]

/// 单元格为原始值的 Grid<T>：先写宽度（null 写 -1），再把单元格写成 T[]（一个长度，然后一整块）。
public struct GridFormatter<[NinoRaw] T> : INinoFormatter<Grid<T>>
    where T : unmanaged
{
    public void Serialize(Grid<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.Write(-1);
            return;
        }

        writer.Write(value.Width);
        writer.Write<T>(value.Cells.AsSpan());                     // 先写长度，再整块复制
    }

    public void Deserialize(ref Reader reader, ref Grid<T> value)
    {
        int width = reader.Read<int>();
        if (width < 0)
        {
            NinoRecycler.Discard(ref value);
            return;
        }

        int length = reader.ReadLength(Unsafe.SizeOf<T>());     // 对照剩余字节检查
        if (width == 0 ? length != 0 : length % width != 0)
            throw new NinoDataException("Nino: not a grid.");
        if (value == null || value.Cells.Length != length || value.Width != width)
            NinoRecycler.Replace(ref value, new Grid<T>(width, width == 0 ? 0 : length / width)); // 大小相同时复用 grid
        reader.ReadUnmanagedRaw(value.Cells.AsSpan());          // 一次整块复制 // [!code highlight]
    }
}

[NinoType]
public sealed class Level
{
    public string Name;
    public Grid<byte> Tiles;        // 使用 GridFormatter<byte>
    public Grid<Vector2> Flow;      // 使用 GridFormatter<Vector2>
}
```

- `[NinoRaw]` 只把 `T` 绑定到 Nino 按原始字节拷贝的类型：`Grid<byte>`、`Grid<Vector2>` 用这个格式化器，`Grid<string>` 成员则没有格式化器（NINO007）。运行时才遇到的类型按同样的规则绑定，Unity 的 IL2CPP Player 里也一样：IL2CPP 不保留类型参数上的特性，所以你的程序集生成的注册表，会为它注册的格式化器记下 `[NinoRaw]`、`[NinoCreated]` 和 `unmanaged`。
- `Writer.Write<T>(ReadOnlySpan<T>)` 和 `Reader.ReadUnmanagedRaw<T>(Span<T>)` 把元素整块拷贝；运行时的内存布局和规范布局不同时，逐字段转换。这里的整块拷贝是 Nino 自己的实现，CPU 有向量指令就用向量指令（原始结构体的填充也用它清零；读 `bool` 时先用它检查每个字节只是 0 或 1，再整块拷贝），格式化器里不用再自己写 SIMD，详见 [SIMD](/zh/docs/v4/simd#dotnet)。
- 剩下的字节装不下这么多格子时，`ReadLength` 抛出异常，损坏的数据就没法让格式化器分配一个巨大的网格。

## 内置格式化器 [#built-in-formatters]

Nino 自己的格式化器都是 `Nino.Core` 里的公共结构体，和上面的例子一样，元素格式化器是它们的泛型参数。把它们当类型参数传进去，就能拼出新的格式化器：元素按 zig-zag 变长整数写的列表，值按 Nino 默认方式写的字典。它们都是结构体，拼出来的格式化器仍然是 JIT 能内联的直接调用，不分配内存。

```csharp
[NinoType]
public sealed class PriceHistory
{
    public string Symbol;

    // 每个变化量写成 zig-zag 变长整数（上面的 ZigZagLongFormatter）：1 到 2 字节，而不是 8 字节
    [NinoMemberFormatter(typeof(ListFormatter<List<long>, long, ZigZagLongFormatter>))] // [!code highlight]
    public List<long> DeltaCents;

    // 键写成 zig-zag 变长整数，值和 Nino 默认写 Trade 的方式一模一样
    [NinoMemberFormatter(typeof(DictionaryFormatter<long, Trade, ZigZagLongFormatter, CachedFormatter<Trade>>))] // [!code highlight]
    public Dictionary<long, Trade> TradesByTime;
}

[NinoType]
public sealed class Trade
{
    public int Quantity;
    public long PriceCents;
}
```

元素格式化器排在类型之后，是最后几个类型参数：`ListFormatter<TList, T, TFormatter>` 依次是列表类型（`List<T>` 或它的派生类）、元素类型、元素的格式化器。元素没有你自己的格式化器时，传 Nino 本来会用的那个：

| 元素 | 传入的格式化器 |
| --- | --- |
| 非托管值（`int`、`long`、枚举、`Vector3`、原始结构体） | `UnmanagedFormatter<T>`：按原始字节写 |
| `string` | `StringFormatter`：每字符一个字节或 UTF-16，和成员的写法一样。要 UTF-8，请给成员加 `[NinoUtf8]`（`Utf8StringFormatter` 是给生成代码用的；NINO031） |
| 其他类型（`[NinoType]`、集合、有注册格式化器的类型） | `CachedFormatter<T>`：Nino 给 `T` 用什么就用什么，所以写出的内容和 `NinoSerializer.Serialize(value, ref writer)` 一样，头部和多态都包括在内 |

`CachedFormatter<T>` 从静态字段取格式化器。`T` 是具体类型时，JIT 直接调用它，还能内联；在共享泛型代码里（`T` 是类）和 AOT 运行时（IL2CPP、Native AOT）上，每个值多一次虚调用。用 `[assembly: NinoFormatter]` 注册的泛型格式化器，请像 `RingFormatter` 那样把元素格式化器声明成类型参数（`where TFormatter : struct, INinoFormatter<T>`）：Nino 会在那里绑定确切的格式化器。

按格式化的类型排列（`TF`、`TKF`、`TVF` 分别是元素、键、值的格式化器；`-1` 是 `null` 的长度）：

| 格式化器 | 格式化的类型 | 写法 |
| --- | --- | --- |
| `UnmanagedFormatter<T>` | 非托管的 `T` | 原始字节 |
| `NullableFormatter<T, TF>` | `T?` | 存在字节，然后是值 |
| `StringFormatter`、`Utf8StringFormatter` | `string` | Nino 默认的字符串编码，或 UTF-8 |
| `IntPtrFormatter`、`UIntPtrFormatter` | `nint`、`nuint` | 在所有平台上都是 8 字节 |
| `DateTimeOffsetFormatter` | `DateTimeOffset` | UTC 刻度（`long`），然后是以分钟计的偏移（`short`） |
| `ObjectFormatter` | 装着 `[NinoType]` 的 `object` | 类型 ID，然后是主体 |
| `ArrayFormatter<T, TF>`、`UnmanagedArrayFormatter<T>` | `T[]` | 长度（`null` 写 `-1`），然后是元素；非托管版整块写 |
| `NullableArrayFormatter<T>`、`NullableListFormatter<TList, T>` | 原始 `T` 的 `T?[]`、`List<T?>` | 每个元素占固定步长（和 `ArrayFormatter` 配 `NullableFormatter` 写出的字节不同） |
| `ArraySegmentFormatter<T, TF>` | `ArraySegment<T>` | 和数组一样；读成新数组 |
| `Array2DFormatter<T, TF>`、`Array3DFormatter<T, TF>`、`Array4DFormatter<T, TF>` | `T[,]`、`T[,,]`、`T[,,,]` | 各维长度（第一个为 `-1` 表示 `null`），然后按行优先顺序写元素 |
| `ListFormatter<TList, T, TF>`、`UnmanagedListFormatter<TList, T>` | `List<T>` 或它的派生类 | 个数（`null` 写 `-1`），然后是元素；非托管版整块写 |
| `HashSetFormatter<TSet, T, TF>` | `HashSet<T>` 或它的派生类 | 个数，然后是元素 |
| `QueueFormatter<T, TF>`、`QueueFormatter<TQueue, T, TF>` | `Queue<T>` 或它的派生类 | 个数，然后从队头到队尾 |
| `StackFormatter<T, TF>`、`StackFormatter<TStack, T, TF>` | `Stack<T>` 或它的派生类 | 个数，然后从栈底到栈顶 |
| `CollectionFormatter<TCollection, T, TF>` | Nino 能创建的任意 `ICollection<T>` 类（`SortedSet<T>`、`LinkedList<T>`、你自己的集合） | 个数，然后按枚举顺序写元素 |
| `ProducerConsumerFormatter<TCollection, T, TF>` | `ConcurrentQueue<T>`、`ConcurrentBag<T>` 等 `IProducerConsumerCollection<T>` | 个数，然后按加回去的顺序写元素 |
| `ConcurrentStackFormatter<T, TF>` | `ConcurrentStack<T>` | 和 `ProducerConsumerFormatter` 一样（字节相同），往已有的栈里填充时直接调用 |
| `BlockingCollectionFormatter<T, TF>` | `BlockingCollection<T>` | 个数，然后是一份快照；读成基于 `ConcurrentQueue<T>` 的集合 |
| `InterfaceListFormatter<TInterface, T, TF>`、`InterfaceSetFormatter<TInterface, T, TF>` | `IEnumerable<T>`、`IList<T>`、`IReadOnlyList<T>` 等；`ISet<T>`、`IReadOnlySet<T>` | 个数，然后是元素；读成 `List<T>` 或 `HashSet<T>` |
| `DictionaryFormatter<TKey, TValue, TKF, TVF>`、`DictionaryFormatter<TDictionary, TKey, TValue, TKF, TVF>` | `Dictionary<TKey, TValue>` 或它的派生类 | 个数，然后是一对对键和值 |
| `DictionaryLikeFormatter<TDictionary, TKey, TValue, TKF, TVF>` | Nino 能创建的任意 `IDictionary<TKey, TValue>` 类（`SortedDictionary`、`SortedList`、`ConcurrentDictionary`、你自己的字典） | 个数，然后是键值对 |
| `InterfaceDictionaryFormatter<TInterface, TKey, TValue, TKF, TVF>` | `IDictionary<TKey, TValue>`、`IReadOnlyDictionary<TKey, TValue>`、`ReadOnlyDictionary<TKey, TValue>` | 个数，然后是键值对；读成 `Dictionary<TKey, TValue>` |
| `KeyValuePairFormatter<TKey, TValue, TKF, TVF>` | `KeyValuePair<TKey, TValue>` | 键，然后是值 |
| `ValueTupleFormatter<T1, ..., TF1, ...>`、`TupleFormatter<T1, ..., TF1, ...>` | 值元组（8 项及以上通过 `TRest`）、1 到 7 项的 `Tuple` | 按顺序写各项；`Tuple` 前面多一个存在字节 |
| `PriorityQueueFormatter<TElement, TPriority, TEF, TPF>` | `PriorityQueue<TElement, TPriority>`（只在 `net8.0` 和 `net10.0` 版本里） | 个数，然后按堆的顺序写元素和优先级 |
| `LazyFormatter<T, TF>` | `Lazy<T>` | 存在字节，然后是值（还没创建的会先创建） |
| `MemoryFormatter<T, TF>`、`ReadOnlyMemoryFormatter<T, TF>`、`ReadOnlySequenceFormatter<T, TF>` | `Memory<T>`、`ReadOnlyMemory<T>`、`ReadOnlySequence<T>` | 和由这些元素组成的 `T[]` 字节相同 |
| `GroupingFormatter<TKey, TElement, TKF, TEF>`、`LookupFormatter<TKey, TElement, TKF, TEF>` | `IGrouping<TKey, TElement>`、`ILookup<TKey, TElement>` | 分组：个数、键、元素；查找表：个数，然后是各个分组 |
| `BigIntegerFormatter`、`UriFormatter`、`VersionFormatter`、`StringBuilderFormatter`、`BitArrayFormatter`、`CultureInfoFormatter`、`TimeZoneInfoFormatter` | 对应的类型 | 见[支持的类型](/zh/docs/v4/types) |
| `CachedFormatter<T>` | Nino 支持的任意 `T` | Nino 给 `T` 用的格式化器（见上文） |

</Accordion>
</Accordions>

标了 `[NinoCreated]` 的类型参数（`TList`、`TSet`、`TDictionary` 等）在槽位为 `null` 时用 `NinoActivator<T>.Create()` 创建；读入已有集合时会复用或重新填充它，和[复用反序列化](/zh/docs/v4/pooling)在别处的做法一样。内置格式化器配上你自己的元素格式化器后，写出的字节只有你的代码认识：读的一端要用同样的组合。

## Writer 与 Reader [#writer-and-reader]

格式化器用 `Writer` 写、用 `Reader` 读，两者都是 `ref struct`。最常用的方法：

| Writer | Reader | 数据 |
| --- | --- | --- |
| `Write<T>(in T value)` | `Read(out T value)`、`Read<T>()` | 非托管值（`int`、`float`、非托管结构体等），按原始字节 |
| `Write<T>(T? value)` | `Read(out T? value)` | 可空的非托管值 |
| `Write<T>(T[] values)`、`Write<T>(ReadOnlySpan<T>)` | `Read(out T[] values)` | 非托管数组：长度加一整块数据 |
| `WriteUnmanagedRaw<T>(ReadOnlySpan<T>)` | `ReadUnmanagedRaw<T>(Span<T>)` | 不带长度的一整块非托管值，可以读进你已有的内存 |
| `Write(string)`、`WriteUtf8(string)` | `Read(out string)`、`ReadUtf8(out string)` | 字符串：每个字符串自动选每字符一个字节或 UTF-16；或者 UTF-8 |
| | `ReadString(string current)`、`ReadUtf8(string current)` | 字符串；数据里的文本和 `current` 相同时直接返回 `current`，生成代码读入已有实例时就是这么做的 |
| `WriteLength(int)`、`WriteNullLength()` | `ReadLength(minElementSize = 1)` | 集合长度，`-1` 表示 null；剩下的字节装不下这么多个至少 `minElementSize` 字节的元素时，`ReadLength` 抛出异常 |
| `ReserveInt32()`、`PatchInt32(...)`、`PatchLength(...)` | | 先占 4 字节，稍后回填，例如字节长度 |
| `WriteRaw(ReadOnlySpan<byte>)` | `ReadRaw(int)`、`Advance(int)` | 原始字节，或跳过若干字节 |
| `Reserve(int)` | `ReadBlock(int)` | 固定数量的字节，通过 `ref byte` 自己编码（[原始字节](#raw-bytes)） |
| `Position` | `Position`、`Remaining`、`Eof` | 当前位置：`Position` 是绝对偏移，`Remaining` 是剩余字节数 |

`Write(string)` 先写一个 1、3 或 5 字节的头，再写字符：`null` 的头是 `0`；所有字符都不超过 U+00FF 时，头是 `2 × 长度 + 1`，后面每个字符一个字节（空串的头是 `1`，后面没有内容）；否则头是 `2 × 长度`，后面是 UTF-16 码元。`WriteUtf8` 的第一个头是字符数加一（`null` 为 `0`，空串为 `1`），第二个头是字节数，后面正好是这么多 UTF-8 字节：`"é😀"` 写成 `04` `06` `C3 A9 F0 9F 98 80`。未配对的代理项写成 U+FFFD。参见[字符串](/zh/docs/v4/wire-format#strings)。

### 自带格式化器的值 [#nested-values]

要写的值有自己的格式化器时（`[NinoType]`、`List<T>` 等），就把 writer 或 reader 传给常规 API，引用和多态都会照常处理：

```csharp
// Contract 的格式化器里，它的 Owner 字段是 [NinoType]
public void Serialize(Contract value, ref Writer writer)
{
    writer.Write(value.Id);
    NinoSerializer.Serialize(value.Owner, ref writer); // [!code highlight]
}

public void Deserialize(ref Reader reader, ref Contract value)
{
    value ??= new Contract();
    reader.Read(out value.Id);
    NinoDeserializer.Deserialize(ref reader, ref value.Owner); // [!code highlight]
}
```

读的时候必须按写的顺序、一项不差地读回来：字节里不带 schema。

### 原始字节 [#raw-bytes]

表里的方法覆盖不到的定长编码，可以直接操作字节：`Writer.Reserve(size)` 和 `Reader.ReadBlock(size)` 返回指向 `size` 个字节中第一个字节的 `ref byte`，并越过这些字节。Nino 的字节是小端序，`Writer` 和 `Reader` 在大端主机上直接拒绝运行，所以请明确按小端编码，比如用 `BinaryPrimitives`：

```csharp
/// 用 6 字节存 Unix 毫秒时间戳，小端序（够用到 10889 年）。
public struct UnixMillis48Formatter : INinoFormatter<long>
{
    public void Serialize(long value, ref Writer writer)
    {
        if ((ulong)value >= 1UL << 48)
            throw new ArgumentOutOfRangeException(nameof(value));
        Span<byte> bytes = MemoryMarshal.CreateSpan(ref writer.Reserve(6), 6); // [!code highlight]
        BinaryPrimitives.WriteUInt32LittleEndian(bytes, (uint)value);
        BinaryPrimitives.WriteUInt16LittleEndian(bytes.Slice(4), (ushort)(value >> 32));
    }

    public void Deserialize(ref Reader reader, ref long value)
    {
        // 剩下不足 6 字节时抛 NinoDataException
        ReadOnlySpan<byte> bytes = MemoryMarshal.CreateReadOnlySpan(ref reader.ReadBlock(6), 6); // [!code highlight]
        value = BinaryPrimitives.ReadUInt32LittleEndian(bytes) | (long)BinaryPrimitives.ReadUInt16LittleEndian(bytes.Slice(4)) << 32;
    }
}

[NinoType]
public sealed class AuditEntry
{
    [NinoMemberFormatter(typeof(UnixMillis48Formatter))]
    public long AtUnixMs;
    public string Action;
}
```

`MemoryMarshal.CreateSpan` 属于 .NET Standard 2.1，Nino 能跑的运行时都有。也可以直接通过 `ref byte` 用 `Unsafe.ReadUnaligned` 和 `Unsafe.WriteUnaligned` 读写。它们按主机字节序读写，而 `Writer` 和 `Reader` 能运行的主机都是小端序。

| 方法 | 作用 | 大小不对时 |
| --- | --- | --- |
| `Writer.Reserve(int size)` | 在输出末尾加 `size` 个字节（必要时扩容），返回指向第一个字节的 `ref`。这些字节**不会清零**，里面是池化缓冲区原来的内容，所以每个字节都要写 | 负数抛 `OverflowException` |
| `Writer.ReserveInt32()` | 加 4 个字节并返回它们的位置，等知道值以后用 `PatchInt32(position, value)` 或 `PatchLength(position)` 回填 | |
| `Reader.ReadBlock(int size)` | 消耗 `size` 个字节，返回指向第一个字节的 `ref` | 负数，或超过 `Remaining`：抛 `NinoDataException`（"unexpected end of data"），什么都不消耗 |
| `Reader.ReadRaw(int length)` | 同上，返回 `ReadOnlySpan<byte>` | 同上 |
| `Reader.Advance(int count)` | 跳过 `count` 个字节（不返回 `ref` 的 `ReadBlock`） | 同上 |

<Callout type="warn" title="这些引用不做任何检查">

- `Reserve` 返回的 `ref` 只在下一次写入这个 writer 之前有效：任何一次写入都可能把输出挪到更大的缓冲区，并把旧缓冲区还给池；再通过旧的 `ref` 写，就会改坏别处正在用的内存。拿到之后立刻填满。
- `ReadBlock` 返回的 `ref` 指向你正在反序列化的数据。它不是只读的：千万别通过它写，也只读你要的那 `size` 个字节。`size` 为 `0` 时，它可能指向数据末尾之后。
- `PatchInt32` 不检查你传的位置，直接写：只传这个 writer 的 `ReserveInt32` 返回的位置。

</Callout>

### 切片里的位置 [#positions-in-a-slice]

`Reader.ReadSlice()` 读一个 `int32` 字节长度，返回只覆盖后面那个数据块的 reader（`ReserveInt32()` 加 `PatchLength(...)` 写出的就是这种数据块）。它的 `Position` **不会**从 `0` 重新算：和父 reader 一样，是相对整个输入开头的偏移。`Remaining` 和 `Eof` 则以切片末尾为界。要统计切片里读了多少字节，先记下起始位置，再相减：

```csharp
static void ReadBlock(ref Reader reader)
{
    Reader slice = reader.ReadSlice();     // 父 reader 跳过整个数据块
    int start = slice.Position;            // 整个输入中的偏移，不是 0
    slice.Read(out int kind);
    // ...
    int consumed = slice.Position - start; // 切片内读取的字节数
    bool complete = slice.Eof;             // Remaining == 0：切片已读完
    reader.EndSlice(in slice);             // 切片里读出的对象，之后的回引用仍然能找到
}
```

`Writer.Position` 同样是在 `NinoArrayBufferWriter` 里的绝对位置。

## 写得快 [#keep-it-fast]

格式化器和生成的格式化器一样，直接调用、可以内联，所以它有多快取决于你在里面写的代码。连续的非托管数据整块拷贝，读入当前的值并保留它的字符串，分配之前先检查长度：每一条对应的方法见[热路径上的自定义格式化器](/zh/docs/v4/advanced/type-design#custom-formatters)。成员上加了 `[NinoMemberFormatter]`，它所在的类型就不再按原始内存拷贝、也不再是固定大小，热点结构体最好只用内置的成员类型。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 由谁发现 |
| --- | --- | --- |
| 成员格式化器是类，或者格式化的类型和成员类型不一致 | 编译失败 | NINO008 |
| Nino 用不了的注册（推断不出某个类型参数、格式化器嵌套在泛型类型里、实现了两个 `INinoFormatter<P>`） | 编译失败，这条注册不生效 | NINO020 |
| `[NinoType]` 的成员类型没有格式化器（`T` 标了 `[NinoRaw]`，成员却是 `Grid<string>`） | 这个成员无法序列化 | NINO007 |
| 在成员上直接写 `Utf8StringFormatter` | 能用，但它是给生成代码用的 | NINO031：改成给成员加 `[NinoUtf8]` |
| 从数据里读出长度或容量，不检查就按它分配 | 几个恶意字节就能让格式化器分配好几 GB | 无：用 `ReadLength(minElementSize)`，或者自己设上限（见 [`RingFormatter`](#for-a-type-assembly-ninoformatter)） |
| 在 `Deserialize` 里直接覆盖 `value`，不用 `NinoRecycler.Discard` 或 `Replace` | 丢弃的实例到不了[回收器和对象池](/zh/docs/v4/pooling#where-dropped-instances-go) | 无 |
| 读的顺序或项数和写的不一样 | 值读错，或者在后面抛 `NinoDataException` | 无：字节里不带 schema |
| 又写了别的数据之后，还通过 `Reserve` 返回的 `ref` 写入 | 写坏对象池已经交给别人的内存 | 无：[拿到就立刻填](#raw-bytes) |
