Nino 为[内置类型](/zh/docs/v4/types)提供了格式化器，并为每个 `[NinoType]` 生成一个。想换一种方式编码某个成员（变长整数、定点数），或者要序列化 Nino 不认识的类型（第三方集合、其他库里的类型）时，就自己写一个格式化器。

格式化器是实现了 `INinoFormatter<T>` 的**结构体**：

```csharp
public interface INinoFormatter<T>
{
    void Serialize(T value, ref Writer writer);
    void Deserialize(ref T value, ref Reader reader);
}
```

`Deserialize` 通过 `ref` 接收当前值：`default` 表示要创建新值，已有实例则可以复用。格式化器以 `default(TFormatter)` 的形式调用，所以没有实例状态；需要保存的状态请放在静态字段里。

## 用于单个成员 [#for-one-member]

用 `[NinoCustomFormatter]` 让某个成员使用你自己的格式化器。格式化器实现的 `INinoFormatter<T>` 中，`T` 必须**正好**是成员类型（NINO008）。

典型的例子是账本或指标流：每条记录保存各个数值的变化量。变化量通常很小，而 `long` 总是占 8 字节。改用 zig-zag 变长整数后，-64 到 63 之间的值只占 1 字节，±8191 以内只占 2 字节：

```csharp
/// Writes a long as a zig-zag varint.
public struct ZigZagLongFormatter : INinoFormatter<long>
{
    public void Serialize(long value, ref Writer writer)
    {
        ulong v = (ulong)((value << 1) ^ (value >> 63));
        while (v >= 0x80)
        {
            writer.Write((byte)(v | 0x80));
            v >>= 7;
        }
        writer.Write((byte)v);
    }

    public void Deserialize(ref long value, ref Reader reader)
    {
        ulong v = 0;
        int shift = 0;
        byte b;
        do
        {
            reader.Read(out b);
            v |= (ulong)(b & 0x7F) << shift;
            shift += 7;
        } while ((b & 0x80) != 0);
        value = (long)(v >> 1) ^ -(long)(v & 1);
    }
}

[NinoType]
public sealed class BalanceChange
{
    public int AccountId;
    [NinoCustomFormatter(typeof(ZigZagLongFormatter))] // [!code highlight]
    public long DeltaCents;
}
```

这个特性作用于单个字段或属性，无论外层类型在哪里序列化都会生效。使用自定义格式化器的成员，不会作为[原始内存](/zh/docs/v4/defining-types#structs)的一部分被整块拷贝。格式化器不是结构体，或者针对的类型不对时，分析器会报告 NINO008。

## 用于整个类型：`[assembly: NinoFormatter]` [#for-a-type-assembly-ninoformatter]

要让 Nino 支持它不认识的类型（你自己的或第三方的），就在程序集上注册一个格式化器。类型参数和元素格式化器都会自动推断：约束为 `INinoFormatter<E>` 的类型参数会得到 Nino 为 `E` 解析出的格式化器，因此元素的序列化和反序列化都能内联。生成代码直接调用这个格式化器，运行时也使用同一份注册信息。

```csharp
[assembly: NinoFormatter(typeof(RingFormatter<,>))]

// a third-party fixed-capacity buffer: Ring(int capacity), Count, Capacity, Push, Clear,
// and a struct enumerator, so foreach does not allocate
public sealed class Ring<T> : IEnumerable<T> { /* ... */ }

public struct RingFormatter<T, TFormatter> : INinoFormatter<Ring<T>>
    where TFormatter : struct, INinoFormatter<T>
{
    public void Serialize(Ring<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.WriteNullLength();          // -1
            return;
        }

        writer.WriteLength(value.Count);
        writer.Write(value.Capacity);
        foreach (var item in value)            // Ring's struct enumerator: no allocation
            default(TFormatter).Serialize(item, ref writer); // inlined element formatter
    }

    public void Deserialize(ref Ring<T> value, ref Reader reader)
    {
        int count = reader.ReadLength();       // validated against the bytes left
        if (count < 0)
        {
            NinoRecycler.Discard(ref value);   // the data holds null: recycle the old ring
            return;
        }

        reader.Read(out int capacity);
        if (value != null && value.Capacity == capacity)
            value.Clear();                     // reuse the existing ring // [!code highlight]
        else
            NinoRecycler.Replace(ref value, new Ring<T>(capacity)); // recycles the old one, if any
        for (int i = 0; i < count; i++)
        {
            T item = default;
            default(TFormatter).Deserialize(ref item, ref reader);
            value.Push(item);
        }
    }
}

[NinoType]
public sealed class RingHolder
{
    public Ring<int> Ints;          // uses RingFormatter<int, ...>
    public List<Ring<string>> Nested;
}
```

- 格式化器必须是结构体，不能嵌套在泛型类型中，并且只实现一次 `INinoFormatter<P>`。泛型格式化器以开放定义注册（`typeof(F<,>)`），非泛型格式化器直接注册（`typeof(F)`）。每个类型参数都必须能推断出来：要么出现在 `P` 中，要么出现在类型约束中（`where TList : List<T>`），要么受 `INinoFormatter<E>` 约束。无法使用的注册会被忽略，并报告 NINO020。
- `Deserialize` 丢弃实例时（数据为 `null`，或旧实例无法复用），请交给 `NinoRecycler.Discard(ref value)` 或 `NinoRecycler.Replace(ref value, replacement)`，不要直接覆盖，这样[回收处理器和对象池](/zh/docs/v4/pooling)才能拿到它。
- 如果格式化的目标是一个裸类型参数（`INinoFormatter<TCollection>`），可以列出适用的类型定义：`[assembly: NinoFormatter(typeof(F<,,>), typeof(IList<>))]`。不列出时，它适用于约束允许的所有类型。
- 查找顺序：先找为该类型自身定义（以及数组）注册的格式化器，然后是原始非托管值，然后是 `[NinoType]`，最后是裸类型参数的格式化器。多个注册同时匹配时，`Priority` 高的优先（例如 `Priority = 10`）；优先级相同时，取完整名称按序数排序靠前的那个。

<Callout type="info" title="声明式注册，无需启动代码">

`[assembly: NinoFormatter]` 是一个特性，而不是一次调用：没有模块初始化器，启动时也不需要执行任何代码。运行时第一次遇到某个程序集里的类型时，会读取该程序集的注册信息（查找失败时则读取所有已加载的程序集）。因此，HybridCLR 热更新程序集里声明的格式化器，程序集一加载就能用。Nino 自带的 BCL 格式化器也是这样声明的。

没有在运行时注册或替换格式化器的 API：所有格式化器都用 `[assembly: NinoFormatter]` 声明，单个成员则用 `[NinoCustomFormatter]`。因此进程运行期间，一个类型的格式化器不会改变，生成代码和运行时用的始终是同一个。

</Callout>

### 示例：其他库中的泛型类型 [#example-grid]

下面的 `Grid<T>` 代表一个来自其他库、无法加上 `[NinoType]` 的类型。这个格式化器支持元素为任意原始类型的 `Grid<T>`：写入宽度，再把所有格子作为一整块写入；读取时如果大小不变，就直接读进现有的网格，所以[复用反序列化](/zh/docs/v4/pooling)不会分配内存：

```csharp title="GridFormatter.cs"
using System.Runtime.CompilerServices;

// From a library you cannot annotate:
//   public sealed class Grid<T> { public Grid(int width, int height); public int Width { get; } public T[] Cells { get; } }

[assembly: NinoFormatter(typeof(GridFormatter<>))]

/// Grid<T> of raw cells: the width (-1 for null), then the cells as a T[] (a length, then one block).
public struct GridFormatter<[NinoRaw] T> : INinoFormatter<Grid<T>>
    where T : unmanaged
{
    public void Serialize(Grid<T> value, ref Writer writer)
    {
        if (value == null)
        {
            writer.Write(-1);
            return;
        }

        writer.Write(value.Width);
        writer.Write<T>(value.Cells.AsSpan());                     // length, then one block copy
    }

    public void Deserialize(ref Grid<T> value, ref Reader reader)
    {
        int width = reader.Read<int>();
        if (width < 0)
        {
            value = null;
            return;
        }

        int length = reader.ReadLength(Unsafe.SizeOf<T>());     // checked against the bytes left
        if (width == 0 ? length != 0 : length % width != 0)
            throw new InvalidOperationException("Not a grid.");
        if (value == null || value.Cells.Length != length || value.Width != width)
            value = new Grid<T>(width, width == 0 ? 0 : length / width); // reuse the grid when its size matches
        reader.ReadUnmanagedRaw(value.Cells.AsSpan());          // one block copy // [!code highlight]
    }
}

[NinoType]
public sealed class Level
{
    public string Name;
    public Grid<byte> Tiles;        // uses GridFormatter<byte>
    public Grid<Vector2> Flow;      // uses GridFormatter<Vector2>
}
```

- `[NinoRaw]` 只把 `T` 绑定到 Nino 按原始字节拷贝的类型：`Grid<byte>`、`Grid<Vector2>` 会用这个格式化器，而 `Grid<string>` 成员没有格式化器（NINO007）。
- `Writer.Write<T>(ReadOnlySpan<T>)` 和 `Reader.ReadUnmanagedRaw<T>(Span<T>)` 把元素作为一整块拷贝；如果运行时的内存布局与规范布局不同，会逐字段转换。
- 剩余字节放不下这么多格子时，`ReadLength` 会抛出异常，所以损坏的数据不会让格式化器分配一个巨大的网格。

## Writer 与 Reader [#writer-and-reader]

格式化器用 `Writer` 写入、用 `Reader` 读取，两者都是 `ref struct`。最常用的方法：

| Writer | Reader | 数据 |
| --- | --- | --- |
| `Write<T>(in T value)` | `Read(out T value)`、`Read<T>()` | 非托管值（`int`、`float`、非托管结构体等），按原始字节 |
| `Write<T>(T? value)` | `Read(out T? value)` | 可空的非托管值 |
| `Write<T>(T[] values)`、`Write<T>(ReadOnlySpan<T>)` | `Read(out T[] values)` | 非托管数组：长度加一整块数据 |
| `WriteUnmanagedRaw<T>(ReadOnlySpan<T>)` | `ReadUnmanagedRaw<T>(Span<T>)` | 不带长度的一整块非托管值，可以读进你已有的内存 |
| `Write(string)`、`WriteUtf8(string)` | `Read(out string)`、`ReadUtf8(out string)` | 字符串：逐个选择每字符一个字节或 UTF-16，或者 UTF-8 |
| | `ReadString(string current)`、`ReadUtf8(string current)` | 字符串；数据中的文本与 `current` 相同时直接返回 `current`，生成代码读入已有实例时就是这样做的 |
| `WriteLength(int)`、`WriteNullLength()` | `ReadLength(minElementSize = 1)` | 集合长度，`-1` 表示 null；如果剩余字节装不下这么多个至少 `minElementSize` 字节的元素，`ReadLength` 会抛出异常 |
| `ReserveInt32()`、`PatchInt32(...)`、`PatchLength(...)` | | 预留 4 字节稍后回填，例如字节长度 |
| `WriteRaw(ReadOnlySpan<byte>)` | `ReadRaw(int)`、`Advance(int)` | 原始字节，或跳过若干字节 |
| `Position` | `Position`、`Remaining`、`Eof` | 当前位置：`Position` 是绝对偏移，`Remaining` 是剩余字节数 |

`Write(string)` 写入一个 `int32` 头和字符：`null` 为 `-1`，空串为 `0`，两者之后都不再有内容；所有字符都不超过 U+00FF 时为 `~长度`，然后每个字符一个字节；否则为长度，然后是 UTF-16 码元。`WriteUtf8` 先写字符数（`-1` 和 `0` 同上），再写 `int32` 字节数，然后正好是这么多个 UTF-8 字节：`"é😀"` 写成 `03 00 00 00` `06 00 00 00` `C3 A9 F0 9F 98 80`。不成对的代理项写成 U+FFFD。参见[二进制格式](/zh/docs/v4/platforms#binary-format)。

### 切片中的位置 [#positions-in-a-slice]

`Reader.ReadSlice()` 读取一个 `int32` 字节长度，并返回覆盖其后数据块的 reader（`ReserveInt32()` 加 `PatchLength(...)` 写出的就是这种数据块）。它的 `Position` **不会**从 `0` 重新开始：与父 reader 一样，它是相对整个输入起点的偏移。`Remaining` 和 `Eof` 则以切片末尾为界。要统计切片内读了多少字节，先记下起始位置，再相减：

```csharp
Reader slice = reader.ReadSlice();     // the parent skips the whole block
int start = slice.Position;            // an offset in the whole input, not 0
slice.Read(out int kind);
// ...
int consumed = slice.Position - start; // bytes read inside the slice
bool complete = slice.Eof;             // Remaining == 0: the slice is used up
reader.EndSlice(in slice);             // objects read in the slice stay visible to back references
```

`Writer.Position` 同样是在 `NinoArrayBufferWriter` 中的绝对位置。

如果要写入的值有自己的格式化器（`[NinoType]`、`List<T>` 等），就把 writer 或 reader 传给常规 API，这样引用和多态都能照常处理：

```csharp
NinoSerializer.Serialize(value.Owner, ref writer);
NinoDeserializer.Deserialize(ref owner, ref reader);
```

读取时必须按写入的顺序，读回完全相同的内容：字节里不带 schema。
