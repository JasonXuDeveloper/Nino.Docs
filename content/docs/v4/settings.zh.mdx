Nino 运行时的设置都是 `NinoSettings`（命名空间 `Nino.Core`）的静态成员，对整个进程生效。没有每次调用单独传入的选项对象；按类型设置的，只有对象池和回收器这几个成员。本页把它们列在一起，每行都链到对应的指南，那里讲什么时候需要它。

## 在启动时设置 [#startup]

```csharp title="Program.cs"
using Nino.Core;

// 在任何线程第一次序列化或反序列化之前。
NinoSettings.Untrusted = true;              // 数据来自客户端
NinoSettings.MaxCollectionLength = 100_000; // 我们的消息不会超过这个数
NinoSettings.PoolMaxRetained = 1024;        // 此后新建的每个池最多保留 1024 个
```

所有设置随时都能读取。每一项都可以不设：Nino 不需要初始化调用（见[启动时](/zh/docs/v4/start#at-startup)）。

## 读取数据的限制 [#limits]

| 设置 | 类型 | 默认值 | 取值 | 作用 |
| --- | --- | --- | --- | --- |
| `MaxDepth` | `int` | `512` | 不小于 128 | 读写时对象最多嵌套几层。超过时，读取抛 `NinoDataException`，写入抛 `InvalidOperationException`。默认值即常量 `NinoSettings.DefaultMaxDepth`。见[限制](/zh/docs/v4/security#limits)、[深层对象图](/zh/docs/v4/reference-tracking#deep-object-graphs) |
| `MaxCollectionLength` | `int` | `int.MaxValue` | 不小于 0 | 数据里一个集合或数组最多能声明多少个元素（或键值对），在分配内存之前就检查。见[限制](/zh/docs/v4/security#limits) |
| `MaxHashCollisions` | `int` | `100` | 不小于 1 | 读到的键在它的哈希桶里最多能遇到几个键。默认值即常量 `NinoSettings.DefaultMaxHashCollisions`。见[哈希洪泛](/zh/docs/v4/security#hash-flooding) |
| `Untrusted` | `bool` | `false` | | 打开每次读取都有开销的检查：带种子的哈希、校验按字节复制的值、拒绝值后面多余的字节。见[不可信模式](/zh/docs/v4/security#untrusted-mode) |

<Callout type="warn" title="必须在第一次使用前设置">

读写路径把这四项当常量用：Nino 第一次用到它们时，四项一起冻结。之后再赋值就抛 `InvalidOperationException`，哪怕赋的是原值。赋的值低于下限，抛 `ArgumentOutOfRangeException`。

</Callout>

## 对象池与回收器 [#pools]

| 成员 | 类型 | 默认值 | 取值 | 作用 |
| --- | --- | --- | --- | --- |
| `PoolMaxRetained` | `int` | `256` | 不小于 0 | 此后新建的 `[NinoPooled]` 池，共享栈最多保留几个实例（某个类型第一次反序列化或归还时，它的池才创建）。见[设置](/zh/docs/v4/pooling#settings) |
| `SetPoolMaxRetained<T>(int maxRetained)` | 方法 | | 不小于 0；`T` 是 `[NinoPooled]` 类 | 只设 `T` 的池，不管这个池是否已经创建。每个线程另外还各留最多 64 个。见[池容量](/zh/docs/v4/advanced/high-performance#pool-sizes) |
| `SetRecycler<T>(Action<T> handler)` | 方法 | 无 | 传 `null` 即移除 | 复用反序列化时，从声明为 `T` 的槽位上丢下的实例交给这个处理函数，不再还回池里。见[为什么要注册回收器](/zh/docs/v4/pooling#why-setrecycler) |

这几项不会冻结，但和限制一样都是普通字段，读的时候不加同步。其他线程正在序列化时修改，新值迟早生效，但正在进行的调用不一定立刻看到，所以也请在启动时设置。`PoolMaxRetained` 只在创建池时读取，已经存在的池不受影响。

## 常见陷阱 [#pitfalls]

| 错误做法 | 结果 | 正确做法 |
| --- | --- | --- |
| 第一次序列化之后才设置限制，比如放在稍后才运行的处理函数里 | 抛 `InvalidOperationException` | 放进启动代码，在任何 Nino 调用之前 |
| Unity 关闭域重载后，下一次进入运行模式又设置一遍限制 | 抛 `InvalidOperationException`：静态状态在多次运行之间保留（见[降低帧耗时的技巧](/zh/docs/v4/advanced/unity#frame-time-tips)），限制仍是冻结的 | 只在值不同时才设置：`if (!NinoSettings.Untrusted) NinoSettings.Untrusted = true;` |
| 想靠 `PoolMaxRetained` 调整已经在用的池 | 那个池不会变 | 用 `SetPoolMaxRetained<T>(...)` |
| 想让同一进程里的两类数据用不同的限制 | 所有调用共用同一组值 | 按进程里最严格的需要来设 |
