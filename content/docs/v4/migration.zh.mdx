Nino v4 是不向后兼容的大版本。本页列出所有变化的 API、特性和选项，附上修改前后的代码，并说明 v3 写出的数据该怎么处理。如果是从 v4 beta 或 preview 升级，请看[从 v4 beta 升级](#upgrading-from-a-v4-beta)。

<Callout type="warn">

v4 的二进制格式与 v3 以及更早的 v4 beta/preview 版本**不兼容**。v4 读不了 v3 写出的数据，v3 也读不了 v4 写出的数据。如果你保存了 v3 数据（文件、数据库、缓存），升级前请先阅读[转换 v3 数据](#converting-v3-data)。

</Callout>

## 检查清单 [#checklist]

<Steps>
<Step>

把 `Nino` NuGet 包（Unity 中是 OpenUPM 包）更新到 v4。

</Step>
<Step>

把 `Serializer`/`Deserializer` 调用换成 `NinoSerializer`/`NinoDeserializer`，并删掉 `using <YourAssembly>.NinoGen;`。

</Step>
<Step>

在需要的类型上用 `[NinoType(format: NinoFormat.VersionTolerant)]` 取代 `WEAK_VERSION_TOLERANCE`（可选，见下文）。

</Step>
<Step>

把 `[NinoFormerName]` 的参数改成运行时类型名的写法。

</Step>
<Step>

构建项目，修复分析器报告的问题（`NINO001`–`NINO025`），许多诊断都带代码修复。

</Step>
<Step>

转换或丢弃持久化的 v3 数据。

</Step>
</Steps>

## 序列化 API [#serialization-api]

v3 的生成器会在每个程序集的 `<AssemblyName>.NinoGen` 命名空间里生成静态的 `Serializer` 和 `Deserializer` 类（以及扩展方法）。v4 只有 `Nino.Core` 里的一套 API，所有程序集共用。

| v3 | v4 |
| --- | --- |
| `using MyApp.NinoGen;` | `using Nino.Core;` |
| `Serializer.Serialize(obj)` / `obj.Serialize()` | `NinoSerializer.Serialize(obj)` |
| `Serializer.Serialize(obj, bufferWriter)` / `obj.Serialize(bufferWriter)` | `NinoSerializer.Serialize(obj, bufferWriter)` |
| `obj.Serialize(ref writer)` | `NinoSerializer.Serialize(obj, ref writer)` |
| `Deserializer.Deserialize(data, out T value)` | `T value = NinoDeserializer.Deserialize<T>(data)` |
| `Deserializer.Deserialize(out T value, ref reader)` | `T value = NinoDeserializer.Deserialize<T>(ref reader)` |
| `Serializer.GetBufferWriter()` / `ReturnBufferWriter(...)` | 复用一个 `NinoArrayBufferWriter`（参见[序列化与反序列化](/zh/docs/v4/basic#reusing-a-buffer)） |
| （无） | `NinoDeserializer.Deserialize(data, ref value)`：反序列化到已有实例 |
| （无） | `NinoSerializer.SerializeBoxed(value, type)`、`NinoDeserializer.DeserializeBoxed(data, type)`：仅用于运行时才知道、并且与其他类型没有共同 `[NinoType]` 基类型的类型（参见[运行时类型](/zh/docs/v4/basic#runtime-types)） |

<Tabs groupId="nino-version" persist items={["v3", "v4"]}>

<Tab value="v3">

```csharp
using MyApp.NinoGen;

byte[] bytes = obj.Serialize();

Deserializer.Deserialize(bytes, out ObjClass result);
```

</Tab>
<Tab value="v4">

```csharp
using Nino.Core;

byte[] bytes = NinoSerializer.Serialize(obj);

ObjClass result = NinoDeserializer.Deserialize<ObjClass>(bytes);
```

</Tab>
</Tabs>

复用缓冲区：

<Tabs groupId="nino-version" persist items={["v3", "v4"]}>

<Tab value="v3">

```csharp
var bufferWriter = Serializer.GetBufferWriter();
obj.Serialize(bufferWriter);
Serializer.ReturnBufferWriter(bufferWriter);
```

</Tab>
<Tab value="v4">

```csharp
// create once and keep it (one per thread)
var buffer = new NinoArrayBufferWriter();

// for each message
buffer.ResetWrittenCount();
NinoSerializer.Serialize(obj, buffer); // [!code highlight]
ReadOnlySpan<byte> bytes = buffer.WrittenSpan; // valid until the next write
```

</Tab>
</Tabs>

<Callout type="info">

v3 生成的 `Serialize` 可以接收 `Span<T>`。v4 中 `T` 是泛型类型参数，不能是 `ref struct`，所以请改为序列化数组、`List<T>` 或 `ArraySegment<T>`。

</Callout>

## 特性与选项 [#attributes-and-options]

| v3 | v4 |
| --- | --- |
| `[NinoType]`、`[NinoType(autoCollect, containNonPublicMembers)]` | 不变；新增可选参数 `allowInheritance`、`format`（`NinoFormat.Positional`、`NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`）、`trackReferences` |
| 每个子类型都要单独标记 `[NinoType]` | 子类型从基类或接口**继承** `[NinoType]`（除非基类设置了 `allowInheritance: false`） |
| `WEAK_VERSION_TOLERANCE`（整个项目） | 按类型使用 `[NinoType(format: NinoFormat.VersionTolerant)]`；该符号仍然有效，会让项目中所有 `NinoFormat.Positional` 的类型改为版本容错 |
| `[NinoFormerName("global::Old.Namespace.Type")]`（名称从 `NinoTypeConst.g.cs` 复制） | `[NinoFormerName("Old.Namespace.Type")]`：运行时写法，不带 `global::`，嵌套类型用 `+` 分隔 |
| `[NinoMember(index)]`、`[NinoIgnore]`、`[NinoUtf8]`、`[NinoConstructor(...)]` | 不变；`[NinoConstructor]` 也可以标记静态工厂方法 |
| `[NinoExplicitOrder(...)]` | 已移除；改用 `[NinoType(false)]`，并按成员原来的写入顺序给每个成员编上 `[NinoMember(index)]`（参见[成员顺序](/zh/docs/v4/defining-types#member-order)） |
| `[NinoPrivateProxy]`（由生成器生成） | 已移除；私有成员通过 `[UnsafeAccessor]`（.NET 8+）或 `partial` 类型中生成的访问器访问 |
| （无） | `[NinoPooled]`、`[NinoFactory]`、`[NinoCustomFormatter]`、`[assembly: NinoFormatter]` |

### 版本容错 [#version-tolerance]

<Tabs groupId="nino-version" persist items={["v3", "v4"]}>

<Tab value="v3">

```csharp
// v3: #define WEAK_VERSION_TOLERANCE in the project settings
[NinoType]
public class Customer
{
    public int Id;
    public string Name;
    public bool Verified; // appended later
}
```

</Tab>
<Tab value="v4">

```csharp
[NinoType(format: NinoFormat.VersionTolerant)]
public class Customer
{
    public int Id;
    public string Name;
    public bool Verified; // appended later
}
```

</Tab>
</Tabs>

v4 的版本容错按类型设置。成员可以追加到**最末端的派生类型**（没有 `[NinoType]` 子类的类），嵌套多深都可以，旧代码会跳过它不认识的成员。追加到基类的成员会让子类的成员错位，所以不在容错范围内。要调整顺序、删除或插入成员，或者向基类添加成员，请使用 `[NinoType(format: NinoFormat.Keyed)]`。参见[版本容错](/zh/docs/v4/evolving-data#version-tolerance)和[键控成员](/zh/docs/v4/evolving-data#keyed-members)。

<Callout type="warn">

在 v3 中，`WEAK_VERSION_TOLERANCE` 还允许把成员改成大小相同的非托管类型（`int` → `float`）。v4 中不要依赖这一点：修改成员类型不在容错范围内。

</Callout>

### 旧名称 [#former-names]

<Tabs groupId="nino-version" persist items={["v3", "v4"]}>

<Tab value="v3">

```csharp
[NinoType]
[NinoFormerName("global::MyApp.Billing.Bill")]
public class Invoice { ... }
```

</Tab>
<Tab value="v4">

```csharp
[NinoType]
[NinoFormerName("MyApp.Billing.Bill")]
public class Invoice { ... }
```

</Tab>
</Tabs>

旧名称只对 v4 自己写出的数据有意义（v3 的数据本来就读不了），所以只有升级到 v4 之后才改名的类型需要它。

### 多态 [#polymorphism]

<Tabs groupId="nino-version" persist items={["v3", "v4"]}>

<Tab value="v3">

```csharp
[NinoType]
public abstract class Payment { public long Id; }

[NinoType] // no longer required: inherited from Payment
public sealed class CardPayment : Payment { public string Last4; }
```

</Tab>
<Tab value="v4">

```csharp
[NinoType]
public abstract class Payment { public long Id; }

public sealed class CardPayment : Payment { public string Last4; }
```

</Tab>
</Tabs>

在子类型上保留 `[NinoType]` 没有坏处，子类型还能借此设置自己的选项。但这些选项会取代继承来的选项，想保留的（例如 `format: NinoFormat.VersionTolerant`）要再写一遍。唯一的例外是 `trackReferences`：被追踪类型的所有子类型都会保持追踪。

## 生成的代码 [#generated-code]

- 生成的格式化器位于 `<AssemblyName>.NinoGen` 命名空间，但不应该直接调用。请删掉所有引用 v3 生成类（`Serializer`、`Deserializer`、`NinoTypeConst` 等）的代码。
- 每个 `[NinoType]` 对应一个生成文件，改一个类型只会重新生成这个类型。
- 在 v3 中表现为生成代码编译错误的问题，现在会以分析器诊断的形式标在你自己的代码上。成员类型无法序列化时，只报告警告（NINO007）并跳过该成员，不会再导致编译失败。参见[诊断列表](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/diagnostics.md)。

## Unity [#unity]

- 仍然要求 Unity 2022.3 及以上。
- OpenUPM 包已自带源生成器，不必再手动往 Unity 项目里装 `Microsoft.CodeAnalysis` NuGet 包；如果当初只是为 Nino 装的，可以删掉。
- Unity 中的调用不会被拦截：包里附带的是源生成器的 Roslyn 4.3 版本，而拦截器需要 Roslyn 4.8。调用走常规路径，写出的字节相同。
- 启用 `Override References` 时，`asmdef` 仍需手动引用 `Nino.Core.dll`。

## HybridCLR [#hybridclr]

- 热更新程序集**无需初始化调用**：程序集里的类型第一次用到时，Nino 就会找到该程序集生成的注册表，即使它是用 `Assembly.Load` 加载的也一样。
- v4 的文档和测试覆盖 HybridCLR；ILRuntime 不再列为支持的方案。

## 转换 v3 数据 [#converting-v3-data]

v4 读不了 v3 的数据，而且同一个项目不能同时引用两个版本（两者的程序集和命名空间都叫 `Nino.Core`）。要保留已保存的数据：

<Steps>
<Step>

写一个小的**转换程序**，它仍然引用 Nino v3 和你的 v3 类型。它用 v3 的 `Deserializer` 读出旧数据，再导出成中立的格式（例如 JSON），或者把对象交给另一个引用 v4 的程序集（例如在单独的 `AssemblyLoadContext` 中加载该程序集）。

</Step>
<Step>

在 v4 程序中导入这些中立格式的数据，再用 `NinoSerializer` 写出。

</Step>
<Step>

如果无法离线转换（例如数据保存在用户设备上，像本地文档或应用状态），就把转换逻辑随应用一起发布，并给新数据加上**文件头**（魔数或版本字节）。有文件头的数据用 v4 读取；没有的就转换一次，再用 v4 重新保存。

</Step>
</Steps>

另请参阅[版本迭代](/zh/docs/v4/versioning#reading-data-from-an-older-version)。

<Callout type="idea">

只存在于内存中、或者只在一起部署的进程之间传输的数据（网络消息、缓存）不需要转换，所有端同时升级到 v4 即可。

</Callout>

## 从 v4 beta 升级 [#upgrading-from-a-v4-beta]

从 v3 升级的话可以跳过这一节。针对 v4 beta 或 preview 编写的代码和写出的数据，需要做以下调整。

### v4 beta 中改过的名称 [#names-from-the-v4-betas]

针对早期 v4 beta 写的代码，会用到一些在正式发布前改了名的 API：

| v4 beta | v4 |
| --- | --- |
| `[NinoRefDeserialization]` | `[NinoFactory]` |
| `NinoFactory<T>` | `NinoActivator<T>` |
| `NinoDeserializer.DeserializeRef(ref value, data)` | `NinoDeserializer.Deserialize(data, ref value)` |
| `NinoDeserializer.DeserializeRef(ref value, ref reader)` | `NinoDeserializer.Deserialize(ref value, ref reader)` |
| `NinoSerializer.Serialize(object value)` | 借助共同的 `[NinoType]` 基类型调用 `Serialize<TBase>`；只有运行时才知道、且没有共同基类型的类型才用 `NinoSerializer.SerializeBoxed(value, type)`（见下文） |
| `NinoDeserializer.Deserialize(data, type)` | `NinoDeserializer.DeserializeBoxed(data, type)` |
| `NinoDeserializer.Deserialize(data, type, ref value)` | `NinoDeserializer.DeserializeBoxed(data, ref value, type)` |
| `[NinoExplicitOrder(...)]` | `[NinoType(false)]` 配合 `[NinoMember(index)]`（见上文） |
| “ref 反序列化” | 复用反序列化 |

### v4 beta 之后的行为变化 [#behavior-changes-since-the-v4-betas]

4.0.0-rc.1 还改变了以下行为，为 beta 写的代码和 beta 写出的数据可能依赖这些行为：

<Callout type="warn">

**任何 v4 beta 或 preview 写出的数据，4.0.0-rc.1 都无法读取**：数据格式在很多地方都变了（例如版本容错的类型，包括定义了 `WEAK_VERSION_TOLERANCE` 的项目中的所有类型，以及 `[NinoUtf8]` 字符串）。请用 beta 读出，再用 rc.1 重新写入（参见[读取旧版本的数据](/zh/docs/v4/versioning#reading-data-from-an-older-version)），或者丢弃这些数据。

</Callout>

- **`[NinoUtf8]` 字符串同时记录字符数和字节数。** 先写 UTF-16 字符数，和 UTF-16 字符串一样；字符串既不是 `null` 也不是空串时，再写字节数和 UTF-8 字节。beta 在字节之前只写一个长度。参见[二进制格式](/zh/docs/v4/platforms#binary-format)。
- **版本容错的对象整个继承体系只写一个长度**，不再每层继承各写一个。因此成员只能追加到最末端的派生类型：向有子类的基类追加成员，现在会让子类的成员错位。参见[向基类追加成员](/zh/docs/v4/evolving-data#appending-to-a-base-class)。
- **固定大小的类型直接序列化到大小正好的数组中。** 对所有成员都是固定大小的结构体或密封类调用 `NinoSerializer.Serialize(value)`，会直接按最终大小分配结果再写入，不经过暂存缓冲区，也没有拷贝；写出的字节不变。新增了 `NinoSerializer.GetFixedSize<T>()`。参见[固定大小的类型](/zh/docs/v4/performance#fixed-size-types)。
- **对声明为 `object` 的变量调用 `NinoSerializer.Serialize(obj)`，会写入类型 ID。** beta 有一个 `Serialize(object)` 重载，按值的运行时类型写入。这个重载已经移除，同样的调用现在会编译成 `Serialize<object>`：它只接受 `[NinoType]` 的值，并且先写 4 字节的类型 ID。写出的字节因此不同，也只有 `Deserialize<object>` 能读取。请给这些类型一个共同的 `[NinoType]` 基类型并调用 `Serialize<TBase>`；如果类型要到运行时才知道，就调用 `SerializeBoxed(obj, type)`；`SerializeBoxed(obj, obj.GetType())` 写出的内容与旧重载相同（采用 rc.1 的格式）。参见[运行时类型](/zh/docs/v4/basic#runtime-types)。
- **不能再在运行时注册格式化器。** `NinoFormatterCache<T>.Register<TFormatter>()` 已移除，请改用 `[assembly: NinoFormatter]` 或 `[NinoCustomFormatter]` 声明格式化器。参见[自定义格式化器](/zh/docs/v4/custom-formatters)。
- **`[NinoFactory]` 与 `[NinoConstructor]` 同时出现时会报告。** 这样的工厂方法本来就不会被调用，现在分析器会给出警告（NINO025）。参见[构造函数还是工厂方法？](/zh/docs/v4/constructors#constructor-or-factory)。
- **在 `ReadSlice()` 返回的 reader 上，`Reader.Position` 是相对整个输入的偏移**，而不是相对切片起点。如果自定义格式化器拿它和切片长度比较，应当在切片开始处记下位置，再把它减掉。参见[切片中的位置](/zh/docs/v4/custom-formatters#positions-in-a-slice)。
