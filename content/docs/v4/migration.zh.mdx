Nino v4 是不向后兼容的大版本。本页列出所有变化的 API、特性和选项，附上修改前后的代码，并说明 v3 写出的数据该怎么处理。

<Callout type="warn">

v4 的二进制格式与 v3 以及更早的 v4 beta/preview 版本**不兼容**。v4 读不了 v3 写出的数据，v3 也读不了 v4 写出的数据。如果你保存了 v3 数据（存档、缓存、配置文件），升级前请先阅读[转换 v3 数据](#converting-v3-data)。

</Callout>

## 检查清单 [#checklist]

<Steps>
<Step>

把 `Nino` NuGet 包（Unity 中是 OpenUPM 包）更新到 v4。

</Step>
<Step>

把 `Serializer`/`Deserializer` 调用换成 `NinoSerializer`/`NinoDeserializer`，并删掉 `using <YourAssembly>.NinoGen;`。

</Step>
<Step>

在需要的类型上用 `[NinoType(versionTolerant: true)]` 取代 `WEAK_VERSION_TOLERANCE`（可选，见下文）。

</Step>
<Step>

把 `[NinoFormerName]` 的参数改成运行时类型名的写法。

</Step>
<Step>

构建项目，修复分析器报告的问题（`NINO001`–`NINO023`），大多数诊断都附带代码修复。

</Step>
<Step>

转换或丢弃持久化的 v3 数据。

</Step>
</Steps>

## 序列化 API [#serialization-api]

v3 的生成器会在每个程序集的 `<AssemblyName>.NinoGen` 命名空间里生成静态的 `Serializer` 和 `Deserializer` 类（以及扩展方法）。v4 则只有 `Nino.Core` 中的一套 API，所有程序集共用。

| v3 | v4 |
| --- | --- |
| `using MyGame.NinoGen;` | `using Nino.Core;` |
| `Serializer.Serialize(obj)` / `obj.Serialize()` | `NinoSerializer.Serialize(obj)` |
| `Serializer.Serialize(obj, bufferWriter)` / `obj.Serialize(bufferWriter)` | `NinoSerializer.Serialize(obj, bufferWriter)` |
| `obj.Serialize(ref writer)` | `NinoSerializer.Serialize(obj, ref writer)` |
| `Deserializer.Deserialize(data, out T value)` | `T value = NinoDeserializer.Deserialize<T>(data)` |
| `Deserializer.Deserialize(out T value, ref reader)` | `T value = NinoDeserializer.Deserialize<T>(ref reader)` |
| `Serializer.GetBufferWriter()` / `ReturnBufferWriter(...)` | 复用一个 `NinoArrayBufferWriter`（参见[序列化与反序列化](/zh/docs/v4/basic#reusing-a-buffer)） |
| （无） | `NinoDeserializer.Deserialize(data, ref value)`：反序列化到已有实例 |
| （无） | `NinoSerializer.Serialize(object)`、`NinoDeserializer.Deserialize(data, Type)`：装箱 / 运行时类型 |

<Tabs items={["v3", "v4"]}>

<Tab value="v3">

```csharp
using MyGame.NinoGen;

byte[] bytes = obj.Serialize();

Deserializer.Deserialize(bytes, out ObjClass result);
```

</Tab>
<Tab value="v4">

```csharp
using Nino.Core;

byte[] bytes = NinoSerializer.Serialize(obj);

ObjClass result = NinoDeserializer.Deserialize<ObjClass>(bytes);
```

</Tab>
</Tabs>

复用缓冲区：

<Tabs items={["v3", "v4"]}>

<Tab value="v3">

```csharp
var bufferWriter = Serializer.GetBufferWriter();
obj.Serialize(bufferWriter);
Serializer.ReturnBufferWriter(bufferWriter);
```

</Tab>
<Tab value="v4">

```csharp
var buffer = new NinoArrayBufferWriter(); // keep and reuse it (one per thread)
buffer.ResetWrittenCount();
NinoSerializer.Serialize(obj, buffer);
```

</Tab>
</Tabs>

<Callout type="info">

v3 生成的 `Serialize` 可以接收 `Span<T>`。v4 中 `T` 是泛型类型参数，不能是 `ref struct`，请改为序列化数组、`List<T>` 或 `ArraySegment<T>`。

</Callout>

## 特性与选项 [#attributes-and-options]

| v3 | v4 |
| --- | --- |
| `[NinoType]`、`[NinoType(autoCollect, containNonPublicMembers)]` | 不变；新增可选参数 `allowInheritance`、`versionTolerant`、`keyed`、`trackReferences` |
| 每个子类型都要单独标记 `[NinoType]` | 子类型从基类或接口**继承** `[NinoType]`（除非基类设置了 `allowInheritance: false`） |
| `WEAK_VERSION_TOLERANCE`（整个项目） | 按类型使用 `[NinoType(versionTolerant: true)]`；该符号仍然有效，会为项目中的所有类型开启版本兼容 |
| `[NinoFormerName("global::Old.Namespace.Type")]`（名称从 `NinoTypeConst.g.cs` 复制） | `[NinoFormerName("Old.Namespace.Type")]`：运行时写法，不带 `global::`，嵌套类型用 `+` 分隔 |
| `[NinoMember(index)]`、`[NinoIgnore]`、`[NinoUtf8]`、`[NinoConstructor(...)]`、`[NinoExplicitOrder(...)]` | 不变；`[NinoConstructor]` 也可以标记静态工厂方法 |
| `[NinoPrivateProxy]`（由生成器生成） | 已移除；私有成员通过 `[UnsafeAccessor]`（.NET 8+）或 `partial` 类型中生成的访问器访问 |
| （无） | `[NinoPooled]`、`[NinoFactory]`、`[NinoCustomFormatter]`、`[assembly: NinoFormatter]` |

### v4 beta 中的旧名称 [#names-from-the-v4-betas]

基于早期 v4 beta 编写的代码会用到一些在正式版发布前改过名的 API：

| v4 beta | v4 |
| --- | --- |
| `[NinoRefDeserialization]` | `[NinoFactory]` |
| `NinoFactory<T>` | `NinoActivator<T>` |
| `NinoDeserializer.DeserializeRef(ref value, data)` | `NinoDeserializer.Deserialize(data, ref value)` |
| `NinoDeserializer.DeserializeRef(ref value, ref reader)` | `NinoDeserializer.Deserialize(ref value, ref reader)` |
| “ref 反序列化” | 复用反序列化 |

### 版本兼容 [#version-tolerance]

<Tabs items={["v3", "v4"]}>

<Tab value="v3">

```csharp
// v3: #define WEAK_VERSION_TOLERANCE in the project settings
[NinoType]
public class SaveData
{
    public int Id;
    public string Name;
    public bool Extra; // appended later
}
```

</Tab>
<Tab value="v4">

```csharp
[NinoType(versionTolerant: true)]
public class SaveData
{
    public int Id;
    public string Name;
    public bool Extra; // appended later
}
```

</Tab>
</Tabs>

v4 的版本兼容比 v3 更灵活：成员可以追加到该类型**或任意一层基类**的末尾。如果要调整顺序、删除或插入成员，请使用 `[NinoType(keyed: true)]`。参见[版本兼容](/zh/docs/v4/evolving-data#version-tolerance)和[键控成员](/zh/docs/v4/evolving-data#keyed-members)。

<Callout type="warn">

在 v3 中，`WEAK_VERSION_TOLERANCE` 还允许把成员改成大小相同的非托管类型（`int` → `float`）。v4 中不要依赖这一点：修改成员类型不是兼容的改动。

</Callout>

### 曾用名 [#former-names]

<Tabs items={["v3", "v4"]}>

<Tab value="v3">

```csharp
[NinoType]
[NinoFormerName("global::MyGame.Items.Sword")]
public class Weapon { ... }
```

</Tab>
<Tab value="v4">

```csharp
[NinoType]
[NinoFormerName("MyGame.Items.Sword")]
public class Weapon { ... }
```

</Tab>
</Tabs>

曾用名只对 v4 自己写出的数据有意义（v3 的数据本来就读不了），所以只有升级到 v4 之后才改名的类型需要它。

### 多态 [#polymorphism]

<Tabs items={["v3", "v4"]}>

<Tab value="v3">

```csharp
[NinoType]
public abstract class Shape { public int Id; }

[NinoType] // no longer required: inherited from Shape
public class Circle : Shape { public float Radius; }
```

</Tab>
<Tab value="v4">

```csharp
[NinoType]
public abstract class Shape { public int Id; }

public class Circle : Shape { public float Radius; }
```

</Tab>
</Tabs>

在子类型上保留 `[NinoType]` 没有坏处，子类型还能借此设置自己的选项。但这些选项会完全取代继承来的选项，想保留的（例如 `versionTolerant: true`）需要再写一遍。

## 生成的代码 [#generated-code]
- 生成的格式化器位于 `<AssemblyName>.NinoGen` 命名空间，但不应直接调用。请删掉所有引用 v3 生成类（`Serializer`、`Deserializer`、`NinoTypeConst` 等）的代码。
- 每个 `[NinoType]` 对应一个生成文件，修改一个类型只会重新生成该类型。
- v3 中表现为生成代码编译错误的问题，现在改为在你的代码上报告分析器诊断。成员类型无法序列化时，只报告警告（NINO007）并跳过该成员，不再导致编译错误。参见[诊断列表](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/diagnostics.md)。

## Unity [#unity]
- 仍然要求 Unity 2022.3 及以上。
- OpenUPM 包已自带源生成器，不必再手动往 Unity 项目里装 `Microsoft.CodeAnalysis` NuGet 包；如果当初只是为 Nino 装的，可以删掉。
- Unity 中的调用不会被拦截：包里附带的是源生成器的 Roslyn 4.3 版本，而拦截器需要 Roslyn 4.8。调用走常规路径，写出的字节相同。
- 启用 `Override References` 时，`asmdef` 仍需手动引用 `Nino.Core.dll`。

## HybridCLR [#hybridclr]
- 热更新程序集**无需初始化调用**：程序集中的类型第一次被用到时，Nino 就会找到它生成的注册表，即使程序集是通过 `Assembly.Load` 加载的。
- v4 的文档和测试覆盖 HybridCLR；ILRuntime 不再列为支持的方案。

## 转换 v3 数据 [#converting-v3-data]
v4 读不了 v3 的数据，而且同一个项目不能同时引用两个版本（两者的程序集和命名空间都叫 `Nino.Core`）。要保留已保存的数据：

<Steps>
<Step>

写一个小的**转换程序**，继续引用 Nino v3 和你的 v3 类型。它用 v3 的 `Deserializer` 读出旧数据，导出成通用格式（例如 JSON），或者把对象交给另一个引用 v4 的程序集（例如在单独的 `AssemblyLoadContext` 中加载）。

</Step>
<Step>

在 v4 程序中导入这些数据，再用 `NinoSerializer` 写出。

</Step>
<Step>

如果无法离线转换（例如存档在玩家设备上），就把转换逻辑随游戏一起发布，并给新数据加上**文件头**（魔数或版本字节）。有文件头的数据用 v4 读取；没有的就转换一次，再用 v4 重新保存。

</Step>
</Steps>

另请参阅[版本迭代](/zh/docs/v4/versioning#reading-data-from-an-older-version)。

<Callout type="idea">

只在内存中，或者只在一起部署的进程之间传输的数据（网络消息、缓存）不需要转换，各端同时升级到 v4 即可。

</Callout>
