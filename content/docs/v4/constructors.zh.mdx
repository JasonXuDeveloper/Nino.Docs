Nino 反序列化每个类型，都得知道怎么创建它的实例。生成器在编译期按下面的顺序选定：

1. 标了 `[NinoConstructor]` 的构造函数或静态工厂方法（如果有）。
2. 否则，如果所有序列化成员在构造之后都能赋值：用不传参数就能调用的构造函数（无参，或参数都有默认值），也可以用 [`[NinoFactory]`](#from-a-pool) 方法代替它。实例创建后逐个成员填充；[复用反序列化](/zh/docs/v4/pooling)时直接填充已有实例。结构体用 `new T()`。即使类型还有参数能对上成员的构造函数，也优先走这一步。
3. 否则（有成员只有 getter、只有 `init` 或是 `readonly`）：在可访问（`public` 或 `internal`）的构造函数里，挑参数都能按名称（不区分大小写）对上序列化成员、且参数最多的那个。位置记录挑中的就是主构造函数。不是参数的成员，调用后立即赋值。
4. 结构体最后退回 `new T()`；类如果以上都不满足，就报错（NINO004）。

所以大多数类什么都不用写：无参构造函数加可写成员就是最快的路径。类型需要**不可变**，或者要**校验**读到的数据时，再为 Nino 写构造函数。比如从商品目录文件加载商品：哪一行数据坏了，应该加载时就报错，而不是等用户结账到一半才出问题。

`[NinoConstructor]` 按顺序列出要传给构造函数的序列化成员名，所以参数名不必和成员同名。不写成员名时，按参数名匹配成员：

```csharp title="Product.cs" tab="构造函数"
using System;
using Nino.Core;

[NinoType]
public sealed class Product
{
    public int Id { get; }
    public string Name { get; }
    public decimal Price { get; }

    // 不需要特性：参数按名字对应 Id、Name 和 Price
    public Product(int id, string name, decimal price)
    {
        if (price < 0)
            throw new ArgumentOutOfRangeException(nameof(price)); // 有问题的商品目录行在加载时就失败
        Id = id;
        Name = name;
        Price = price;
    }
}

[NinoType]
public sealed class Customer
{
    public int Id { get; }
    public string Name { get; }
    public string Email;              // 不是参数：调用构造函数之后赋值

    [NinoConstructor(nameof(Id), nameof(Name))] // [!code highlight]
    public Customer(int customerId, string displayName) // 名字不同，所以要列出成员
    {
        Id = customerId;
        Name = displayName;
    }
}
```

```csharp title="Currency.cs" tab="工厂方法"
using System;
using System.Collections.Concurrent;
using Nino.Core;

[NinoType]
public sealed class Currency
{
    private static readonly ConcurrentDictionary<string, Currency> s_known = new();

    public string Code { get; }   // ISO 4217，大写
    public int Decimals { get; }  // 小数点后的位数

    private Currency(string code, int decimals)
    {
        Code = code;
        Decimals = decimals;
    }

    [NinoConstructor(nameof(Code), nameof(Decimals))] // [!code highlight]
    public static Currency Of(string code, int decimals)
    {
        if (code is not { Length: 3 })
            throw new FormatException($"Invalid currency code '{code}'.");
        if (decimals is < 0 or > 4)
            throw new ArgumentOutOfRangeException(nameof(decimals));

        // 规范化，并让每个代码共享一个实例：构造函数这两件事都做不到
        return s_known.GetOrAdd(code.ToUpperInvariant(), static (c, d) => new Currency(c, d), decimals);
    }
}
```

```csharp tab="主构造函数"
[NinoType]
public record PriceChanged(long ProductId, decimal OldPrice, decimal NewPrice); // [!code highlight]
```

```csharp tab="结构体"
[NinoType]
public struct Money
{
    public long MinorUnits; // USD 就是美分
    public string Currency;

    // 代替隐式的无参构造函数
    [NinoConstructor(nameof(MinorUnits), nameof(Currency))] // [!code highlight]
    public Money(long amount, string currencyCode)
    {
        MinorUnits = amount;
        Currency = currencyCode?.ToUpperInvariant(); // 读取时规范化
    }
}
```

## 规则 [#rules]
- 标了 `[NinoConstructor]` 的构造函数或工厂方法必须是 `public` 或 `internal`（NINO021）。
- `[NinoConstructor]` 中的每个名称（不写名称时则是每个参数）都必须对应一个序列化成员（NINO005）。
- 找不到可用的构造函数时，报告 NINO004。
- 通过构造函数重新创建的类型，如果某个只读成员不是构造函数参数，它的值读出来后直接丢掉（NINO006）。请把它加进构造函数、改成可写，或者用 `[NinoIgnore]` 忽略。
- C# 11 的 `required` 成员：有匹配的 `[SetsRequiredMembers]` 构造函数就用它；否则生成代码用对象初始化器设置 required 成员，所以每个 required 成员都必须参与序列化，且生成代码能给它赋值（`public` 或 `internal`）。

## 构造函数还是工厂方法？ [#constructor-or-factory]

Nino 有两种方式介入实例创建，用途不同：

| | `[NinoConstructor]` | [`[NinoFactory]`](/zh/docs/v4/pooling#creating-instances-with-ninofactory) |
| --- | --- | --- |
| 标在 | 构造函数或静态工厂方法上 | 不传参数就能调用的公共静态方法上 |
| 接收 | 所列成员反序列化后的值 | 无 |
| 适合 | 构造不可变类型、校验数据、计算派生状态 | 从你自己的对象池中取实例 |
| 调用之后 | 逐个给不是参数的成员赋值 | 所有成员原地填充 |
| 复用 | 每次读取都重新创建，所以不能池化（NINO018） | 复用实例，0 GC 反序列化就靠它 |

两者只能选一个。有 `[NinoConstructor]` 的类型总是通过它重新创建，同一类型上的 `[NinoFactory]` 永远不会调用，分析器会对此报警告（NINO025）：想保留构造函数，就删掉 `[NinoFactory]`；想用工厂创建实例再原地填充，就删掉 `[NinoConstructor]`。

## 从对象池取实例 [#from-a-pool]

只有 Nino 需要**新**实例时，才调用 `[NinoFactory]` 方法：槽位是 `null`、列表变长，或者多态槽位换了类型。然后 Nino 原地填充这个实例。再配合[复用反序列化](/zh/docs/v4/pooling#deserializing-into-existing-instances)，为丢弃的实例注册[回收器](/zh/docs/v4/pooling#why-setrecycler)，对象池预热之后，源源不断的消息也不再分配内存：

```csharp title="Order.cs"
using System.Collections.Generic;
using Nino.Core;

[NinoType]
public sealed class Order
{
    public long Id;
    public List<OrderLine> Lines = new(); // 跟着订单保留，原地复用

    [NinoFactory] // [!code highlight]
    public static Order Rent() => ObjectPool<Order>.Rent(); // ObjectPool<T>：见池化集合

    public void Return()
    {
        Lines.Clear();
        ObjectPool<Order>.Return(this);
    }
}

[NinoType]
public sealed class OrderBatch
{
    public List<Order> Orders;
}

[NinoType]
public struct OrderLine
{
    public int ProductId;
    public int Quantity;
}
```

```csharp
// 启动时：列表变短时丢弃的订单回到对象池
NinoSettings.SetRecycler<Order>(order => order.Return());

OrderBatch batch = null;
foreach (byte[] data in messages)
    NinoDeserializer.Deserialize(data, ref batch); // 订单变多：Order.Rent()；变少：Return()
```

- 这个方法必须是 `public`、`static`，不传参数就能调用（无参，或参数都有默认值），返回类型正好是声明它的类型；否则报 NINO017。它不能返回 `null`。
- 槽位里已经有实例时，直接原地填充，不调用工厂方法。
- [`ObjectPool<T>`](/zh/docs/v4/pooling#your-own-pooled-collections) 是对象池页面里那个简单的线程本地池，换成别的对象池也行。不需要自己的对象池时，[`[NinoPooled]`](/zh/docs/v4/pooling#ninopooled) 会生成一个，丢弃的实例自动还回池里，不用注册回收器。

## 重新创建的类型 [#re-created-types]

类型标了 `[NinoConstructor]`，或者成员在构造之后没法再赋值（构造函数参数、`init` 属性、只读属性或 `readonly` 字段），每次反序列化都会**重新创建**它，[复用反序列化](/zh/docs/v4/pooling)也不例外，旧实例交给[回收器](/zh/docs/v4/pooling#where-dropped-instances-go)。这类类型不能用 [`trackReferences`](/zh/docs/v4/reference-tracking)（NINO016）或 [`[NinoPooled]`](/zh/docs/v4/pooling#ninopooled)（NINO018）。这类类型上的 `[NinoFactory]` 方法也不会调用（和 `[NinoConstructor]` 同时出现时，分析器报 NINO025）。需要这些功能时（比如要做到 0 GC 反序列化），请把成员改成可写，改为[从对象池取实例](#from-a-pool)。
