## Nino 是什么 [#what-is-nino]

Nino 是一个 C# 二进制序列化库。给类型加上 `[NinoType]`，Roslyn 源生成器就会在编译期写好它的序列化代码；运行时只需调用 `NinoSerializer.Serialize` 和 `NinoDeserializer.Deserialize`。整个过程没有反射，没有运行时代码生成，不需要 schema 文件，也不需要注册。

<Stats lang="zh" />

```csharp
using Nino.Core;

[NinoType]
public class GameData
{
    public int Score;
    public string PlayerName;
    public List<Item> Items;
}

byte[] bytes = NinoSerializer.Serialize(data);
GameData copy = NinoDeserializer.Deserialize<GameData>(bytes);
```

## 为什么选 Nino [#why-nino]

- **快。** 与 MemoryPack 在同一轮测试中对比，Nino 序列化最高快 <BenchValue k="serialize.max" />，反序列化类和多态对象最高快 <BenchValue k="deserialize.max" />，非托管结构体数组与之接近；生成的代码编译也远快于 Nino v3。详见[基准测试](/zh/docs/v4/perf)。
- **热路径零 GC。** 序列化到复用的缓冲区不分配内存；[反序列化到已有对象或池化实例](/zh/docs/v4/pooling)同样零分配，速度最高比 MemoryPack 覆盖模式快 <BenchValue k="reuse.max" />。
- **一切在编译期完成。** 源生成器为每个类型生成一个格式化器，因此 IL2CPP、NativeAOT 和 HybridCLR 都能直接使用。使用 .NET 8 SDK 及以上版本编译时，调用会被[拦截器](/zh/docs/v4/performance#interceptors)直接导向对应的格式化器。生成器是增量的：修改一个类型只会重新生成这个类型；在 1,100 个类型的项目中，生成代码的编译速度是 v3 的 289 倍。
- **多态无需标签。** 声明为基类或接口的值，读回来仍是它的实际类型。类型 ID 由类型名哈希得到，不用维护标签表，其他程序集里的子类型也能自动找到。详见[多态](/zh/docs/v4/polymorphism)。
- **数据可以演进。** 每个类型可以单独选择[版本兼容](/zh/docs/v4/evolving-data#version-tolerance)（追加成员）、[键控成员](/zh/docs/v4/evolving-data#keyed-members)（增删、重排成员）或[引用追踪](/zh/docs/v4/reference-tracking)（共享引用和循环引用）。不启用的类型没有任何额外开销。
- **各平台字节一致。** `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0` 写出的字节完全相同，CoreCLR、Mono、IL2CPP 以及 32 位和 64 位平台之间都能互读。Unity 客户端和 .NET 服务端可以直接交换数据。详见[平台与二进制格式](/zh/docs/v4/platforms)。
- **线程安全。** `NinoSerializer` 和 `NinoDeserializer` 的所有方法都可以在任意多个线程上同时调用，热路径上没有锁。
- **写代码时就发现错误。** 共 23 条[分析器诊断](/zh/docs/v4/analyzers)（NINO001–NINO023），多数提供一键修复。

## 适用场景 [#where-it-fits]

| 场景 | Nino 提供什么 |
| --- | --- |
| **Unity**（Mono、IL2CPP、HybridCLR） | 支持 Unity 2022.3 及以上版本，从 OpenUPM 安装，自带源生成器。`Vector3`、`Quaternion`、`Color32` 等非托管结构体按原始内存拷贝。热更新程序集无需初始化调用。详见 [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity)。 |
| **Godot 4（.NET）** | 普通的 NuGet 包。Godot 的数学结构体都是非托管类型，按原始内存拷贝。详见 [Godot](/zh/docs/v4/platforms#godot)。 |
| **游戏服务器与网络** | 直接序列化到 `PipeWriter` 等 `IBufferWriter<byte>`，从 `ReadOnlySpan<byte>` 反序列化，消息对象可以池化复用。详见[网络层](/zh/docs/v4/advanced/networking)。 |
| **存档与持久化** | 键控和版本兼容类型能跨版本读取；引用追踪保留完整的对象图。详见[存档与持久化](/zh/docs/v4/advanced/persistence)。 |
| **服务、缓存与进程间通信** | 数据紧凑，每次调用不分配内存，可在 ASP.NET Core、后台任务和 Actor 中并发使用。详见[高性能序列化](/zh/docs/v4/advanced/high-performance)。 |

## 什么时候不适合 [#when-not-to-use-it]

- **需要人能读懂的格式。** Nino 输出的是二进制。需要人工查看或编辑的文件，请用 JSON、YAML 或 TOML。
- **数据要给其他语言读取。** 格式由你的 C# 类型决定，没有 schema 文件，也没有其他语言的代码生成器。与非 .NET 程序通信，请用 Protocol Buffers、FlatBuffers 或 MessagePack。
- **需要流、异步 API、回调或内置压缩。** Nino 只处理缓冲区和 span。参见[限制](/zh/docs/v4/limit)，以及 [MemoryPack 领先的地方](/zh/docs/v4/vs-memorypack#where-memorypack-is-ahead)。
- **必须直接读取 Nino v3 的数据。** v4 的二进制格式是全新的，旧数据需要先转换一次。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。

## Nino 能序列化什么 [#what-nino-serializes]

- **你自己的类型**：标记了 `[NinoType]` 的类、结构体、记录、接口和泛型类型，支持[私有成员](/zh/docs/v4/defining-types#private-members)、[自定义构造函数](/zh/docs/v4/constructors)和[类型改名](/zh/docs/v4/defining-types#former-name)。详见[定义类型](/zh/docs/v4/defining-types)。
- **内置类型**：基元类型、枚举、字符串、`Nullable<T>`、元组、数组、BCL 集合、你自己的集合类型；安装 `Nino.Immutable` 后还支持 `ImmutableArray<T>` 和 `ImmutableList<T>`。详见[支持的类型](/zh/docs/v4/types)。
- **其他类型**：通过[自定义格式化器](/zh/docs/v4/custom-formatters)支持，可以针对单个成员，也可以针对整个类型。
