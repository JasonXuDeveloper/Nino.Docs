## Nino 是什么 [#what-is-nino]

Nino 是一个通用的高性能 C# / .NET 二进制序列化库。凡是 .NET 代码需要在对象和字节之间来回转换的地方都能用上它：服务间消息与 RPC、消息队列、缓存、文件与本地存储、进程间通信、数据管道与遥测。它可以运行在 .NET 服务器和桌面应用、NativeAOT、Unity（包括 HybridCLR）以及 Godot 上。

给类型加上 `[NinoType]`，Roslyn 源生成器就会在编译期生成它的序列化代码；运行时只需调用 `NinoSerializer.Serialize` 和 `NinoDeserializer.Deserialize`。整个过程没有反射，没有运行时代码生成，不需要 schema 文件，也不需要注册。

```csharp
using Nino.Core;

[NinoType]
public class Order
{
    public long Id;
    public string Customer;
    public List<OrderLine> Lines;
}

byte[] bytes = NinoSerializer.Serialize(order);
Order copy = NinoDeserializer.Deserialize<Order>(bytes);
```

## 为什么选 Nino [#why-nino]

- **快。** 在同一轮测试中与 MemoryPack 相比，Nino 序列化最高快 <BenchValue k="serialize.max" />，反序列化类和多态对象图最高快 <BenchValue k="deserialize.max" />；非托管结构体数组两者都是整块拷贝，性能持平。详见[基准测试](/zh/docs/v4/perf)。
- **热路径零 GC。** [序列化到复用的缓冲区](/zh/docs/v4/basic#reusing-a-buffer)时不分配内存；[反序列化到已有对象或池化实例](/zh/docs/v4/pooling)时同样不分配：内容不变的字符串会直接保留，只有内容变化的文本才读成新字符串。
- **一切在编译期完成。** 源生成器为每个类型生成一个格式化器，所以 IL2CPP、NativeAOT 和 HybridCLR 都能直接使用。用 .NET 8 SDK 及以上版本编译时，[拦截器](/zh/docs/v4/performance#interceptors)会把每次调用直接转给对应的格式化器。生成器是增量的：改一个类型只重新生成这个类型，生成的代码编译起来也比 v3 快得多（参见[构建时间](/zh/docs/v4/v3-vs-v4#build-time-and-generated-code)）。
- **多态无需标签。** 声明为基类或接口的值，读回来仍是它的实际类型。类型 ID 是类型名的哈希，不用维护标签表；其他程序集里的子类型，Nino 也能自己找到。详见[多态](/zh/docs/v4/polymorphism)。
- **数据可以演进。** 每个类型可以单独选择[版本容错](/zh/docs/v4/evolving-data#version-tolerance)（追加成员）、[键控成员](/zh/docs/v4/evolving-data#keyed-members)（增删、重排成员）或[引用追踪](/zh/docs/v4/reference-tracking)（共享引用和循环引用）。不开启的类型没有任何额外开销。
- **各平台字节一致。** `netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0` 在 CoreCLR、Mono、IL2CPP 上，在 64 位和 32 位平台上，写出的字节完全相同。Unity 客户端和 .NET 服务端可以直接读取对方的数据。详见[平台与二进制格式](/zh/docs/v4/platforms)。
- **线程安全。** `NinoSerializer` 和 `NinoDeserializer` 的所有方法都可以在任意多个线程上同时调用，热路径上没有锁。
- **写代码时就发现错误。** 共 26 条[分析器诊断](/zh/docs/v4/analyzers)（NINO001–NINO026），许多都带一键代码修复。

## 适用场景 [#where-it-fits]

| 场景 | Nino 提供什么 |
| --- | --- |
| [网络与 RPC](/zh/docs/v4/advanced/networking) | 直接序列化到 `PipeWriter` 等 `IBufferWriter<byte>`，从 `ReadOnlySpan<byte>` 读取，消息对象池化复用；多态消息不需要操作码表。 |
| [消息队列与事件流](/zh/docs/v4/advanced/message-queues) | 负载紧凑，事件继承体系按真实类型读回，非托管记录的批次整块拷贝。 |
| [缓存](/zh/docs/v4/advanced/caching) | 写入 Redis 或 `IDistributedCache` 的值体积小，Nino 自身每次调用不分配内存，类型跨多次部署仍然可读。 |
| [持久化](/zh/docs/v4/advanced/persistence) | 文件、键值存储和日志：键控类型和版本容错类型经得起版本更新，引用追踪完整保留对象图。 |
| [进程间通信与热路径](/zh/docs/v4/advanced/zero-allocation) | 分帧的流和固定大小的记录，每次调用 0 B，任意线程均可使用。 |
| [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity) | Unity 2022.3+，从 OpenUPM 安装，自带源生成器；`Vector3` 等非托管结构体按原始内存拷贝；热更新程序集无需初始化调用。 |
| [Godot 4（.NET）](/zh/docs/v4/platforms#godot) | 普通的 NuGet 包；Godot 的数学结构体按原始内存拷贝。 |

## Nino 能序列化什么 [#what-nino-serializes]

- **你自己的类型**：标记了 `[NinoType]` 的类、结构体、记录、接口和泛型类型，支持[私有成员](/zh/docs/v4/defining-types#private-members)、[自定义构造函数](/zh/docs/v4/constructors)和[类型改名](/zh/docs/v4/defining-types#former-name)。详见[定义类型](/zh/docs/v4/defining-types)。
- **内置类型**：基元类型、枚举、字符串、`Nullable<T>`、元组、数组、BCL 集合、`BigInteger`、`Uri`、`Memory<T>` 等 BCL 类型、你自己的集合类型；安装 `Nino.Immutable` 后还支持所有不可变集合。详见[支持的类型](/zh/docs/v4/types)。
- **其他类型**：用[自定义格式化器](/zh/docs/v4/custom-formatters)支持，可以只用于某个成员，也可以用于整个类型。

## 什么时候不适合 [#when-not-to-use-it]

- **需要人类可读的格式。** Nino 输出的是二进制。需要人工查看或编辑的文件，请用 JSON、YAML 或 TOML。
- **数据要给其他语言读取。** 格式由你的 C# 类型决定，没有 schema 文件，也没有其他语言的代码生成器。要和非 .NET 程序通信，请用 Protocol Buffers、FlatBuffers 或 MessagePack。
- **需要自动生成 TypeScript 代码或 ASP.NET Core MVC 格式化器。** Nino 目前两者都不生成，都计划在 [4.0.0-rc.6](/zh/docs/v4/changelog#400-rc6) 提供。在此之前，浏览器客户端可以在 .NET WebAssembly 上运行你的 Nino 类型：参见[浏览器与 JavaScript 客户端](/zh/docs/v4/advanced/browser)以及 [MemoryPack 领先的地方](/zh/docs/v4/vs-memorypack#where-memorypack-is-ahead)。
- **必须直接读取 Nino v3 的数据。** v4 采用了全新的二进制格式，旧数据需要转换一次。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。
