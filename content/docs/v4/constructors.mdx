Nino needs a way to create each type it deserializes. The generator picks one at compile time, in this order:

1. A constructor or static factory method marked `[NinoConstructor]`, if there is one.
2. Otherwise, if every serialized member can be assigned after construction: a constructor callable without arguments (parameterless, or every parameter optional). The instance is then filled member by member, and [reuse deserialization](/en/docs/v4/pooling) fills an existing instance in place. Structs use `new T()`. A parameterless constructor wins here even when the type also has a constructor whose parameters match members.
3. Otherwise (some members are get-only, `init`-only or `readonly`): the accessible (`public` or `internal`) constructor with the most parameters that all match serialized members by name, ignoring case. For a positional record this is the primary constructor. Members that are not parameters are set right after the call.
4. Structs fall back to `new T()`; a class with none of the above is an error (NINO004).

So most classes need nothing: a parameterless constructor and settable members are the fastest path. Write a constructor for Nino when the type should be **immutable** or should **validate** what it reads, for example item definitions loaded from a config table, where a broken row should fail at load time instead of in the middle of a match.

`[NinoConstructor]` takes, in order, the names of the serialized members passed as arguments, so the parameter names do not have to match. Without names, parameters are matched to members by name:

<Tab value="Constructor">

```csharp title="ItemDef.cs"
[NinoType]
public sealed class ItemDef
{
    public int Id { get; }
    public string Name { get; }
    public int MaxStack { get; }

    // no attribute needed: the parameters match Id, Name and MaxStack by name
    public ItemDef(int id, string name, int maxStack)
    {
        if (maxStack <= 0)
            throw new ArgumentOutOfRangeException(nameof(maxStack)); // a bad config row fails at load time
        Id = id;
        Name = name;
        MaxStack = maxStack;
    }
}

[NinoType]
public sealed class Weapon
{
    public int Id { get; }
    public string Name { get; }
    public int Damage;                // not a parameter: assigned after the call

    [NinoConstructor(nameof(Id), nameof(Name))] // [!code highlight]
    public Weapon(int weaponId, string displayName) // names differ, so list the members
    {
        Id = weaponId;
        Name = displayName;
    }
}
```

[NinoType]
public struct SimpleStruct

    [NinoConstructor(nameof(Id), nameof(Name), nameof(CreateTime))] // [!code highlight]

        Id = a;
        Name = b;

## Rules
- The constructor or factory method marked `[NinoConstructor]` must be `public` or `internal` (NINO021).
- Every name in `[NinoConstructor]` (or every parameter, when no names are given) must match a serialized member (NINO005).
- If no constructor can be used, NINO004 is reported.
- When a type is re-created through a constructor, a read-only member that is not a constructor parameter is read and then dropped (NINO006): add it to the constructor, make it settable, or `[NinoIgnore]` it.
- C# 11 `required` members: a constructor marked `[SetsRequiredMembers]` is used when one matches; otherwise the generated code sets the required members with an object initializer, so every required member must be serialized and assignable by generated code (`public` or `internal`).

## Constructor or Factory?

Nino has two ways to hook into instance creation, each for a different job:

| | `[NinoConstructor]` | [`[NinoFactory]`](/en/docs/v4/pooling#creating-instances-with-ninofactory) |
| --- | --- | --- |
| On | a constructor or a static factory method | a public static method callable without arguments |
| Receives | the deserialized values of the listed members | nothing |
| Use it to | build immutable types, validate, compute derived state | take an instance from your own pool |
| After the call | members that are not parameters are assigned | every member is filled in place |

## Re-created Types

Types whose members cannot be assigned after construction (constructor parameters, `init`-only, get-only or `readonly` members) are always **re-created** when deserialized, even by [reuse deserialization](/en/docs/v4/pooling); the old instance is passed to the recycler. Such types cannot use [`trackReferences`](/en/docs/v4/reference-tracking) (NINO016) or [`[NinoPooled]`](/en/docs/v4/pooling#ninopooled) (NINO018). Give them settable members when you need either.
