---
title: 引用追踪
description: 保留共享引用和循环引用。
icon: Share2
---

默认情况下，被引用两次的对象会写入两次，读回后变成两个实例；带环的对象图则无法序列化。给类加上 `trackReferences: true`（子类型会继承）即可保留对象图：

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // may point back to an earlier node
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // a cycle
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

- 每个启用追踪的对象前面都有 4 字节的引用头：同一次调用中已经写过的对象，只写它的序号。
- 无论槽位的声明类型是什么（包括 `object` 和接口），共享引用都能保持同一个对象。
- 追踪只针对 `[NinoType]` 类，不包括集合：同一个 `List<T>` 出现在两个成员中，仍然会写两次。
- 开销：每次顶层调用有一小笔固定开销，每个被追踪的对象再多 4 字节和一次身份查找。不涉及追踪类型的调用没有任何开销。

<Callout type="warn">

必须通过构造函数参数或只读成员重新创建的类型（例如位置记录）不能启用追踪（NINO016）。在结构体上设置 `trackReferences` 会被忽略，并给出警告（NINO015）。

</Callout>

## 何时使用 [#when-to-use-it]

<Accordions type="single">
<Accordion title="用于对象图">

场景图、实体关系、编辑器的撤销栈、多个对象指向同一对象的存档、带父节点引用的树：凡是对象身份有意义或存在循环的地方都适用。一个列表把同一个追踪对象重复 100 次时，写出的字节数和耗时都只是不追踪时的一小部分。

</Accordion>
<Accordion title="消息和普通数据不需要">

网络消息、配置以及其他树状数据没有共享引用。这些地方不要开启追踪：不追踪的类型没有任何开销，连 4 字节的头部都没有。

</Accordion>
<Accordion title="自己连续写入、读取多个值时">

顶层的 `NinoSerializer`/`NinoDeserializer` 调用会把引用表限定在单次调用内。如果你自己创建 `Writer` 或 `Reader`，通过它写入的所有内容会共享引用，直到调用 `ReleaseReferences()` 为止；请在一条完整消息结束时调用它。

</Accordion>
</Accordions>

ref 反序列化对新对象照常工作；遇到回指引用时，会直接替换当前值，而不会回收旧值，因为旧值可能仍被对象图中的其他地方引用。
