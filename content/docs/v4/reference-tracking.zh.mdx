默认情况下，Nino 把对象图当成一棵树来写。同一个对象引用两次就写两次，读回来是两个实例。对象图里有环（`a.Next = b; b.Next = a;`）时，序列化会检测出来，抛出 `InvalidOperationException`，消息里指明类型、提示加上 `trackReferences`，不会无限循环。很深的树什么都不用加，见[深层对象图](#deep-object-graphs)。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合对象图">

有关联关系的领域模型（多个订单指向同一个客户）、撤销栈、多个对象指向同一个对象的文档、带父节点引用的树：凡是对象身份要紧或者有环的地方都用得上。一个列表把同一个追踪对象重复 100 次，字节数和耗时都只有不追踪时的零头。

</Callout>

<Callout type="warn" title="消息和普通数据别开">

网络消息、配置和其他树状数据没有共享引用，嵌套多深都一样。这些地方别开追踪：不追踪的类型没有任何开销，连 4 字节的头都没有。

</Callout>

## 怎么用 [#how-to-use-it]

给类加上 `trackReferences: true`，对象图就能原样保留。它的所有子类型也都会追踪，哪怕子类型自己声明的 `[NinoType]` 没写这个选项：

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // 可能指回更早的节点
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // 形成环
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

共享引用和环一样要紧。比如一张组织架构图里，两名员工属于同一个部门：

```csharp
[NinoType(trackReferences: true)]
public class Department { public string Name; }

[NinoType]
public class Employee { public string Name; public Department Department; }

var sales = new Department { Name = "Sales" };
var staff = new List<Employee>
{
    new() { Name = "Ana", Department = sales },
    new() { Name = "Ben", Department = sales },
};
byte[] bytes = NinoSerializer.Serialize(staff);
var loaded = NinoDeserializer.Deserialize<List<Employee>>(bytes);
// loaded[0].Department == loaded[1].Department：同一个对象，所以改名后两个员工都能看到 // [!code highlight]
```

不追踪的话，读出来是两个独立的 `Department` 对象，读完再给部门改名，只有一名员工看得到。只有被共享的类型需要这个选项，`Employee` 本身不用追踪。

- 每个追踪的对象前面有 4 字节的引用头；同一次调用里已经写过的对象，只写它的序号。
- 不管成员声明成什么类型（包括 `object` 和接口），共享引用都保持同一个对象。
- 只追踪 `[NinoType]` 类，不管集合：同一个 `List<T>` 出现在两个成员里，还是写两次。
- 开销：你每调用一次 `NinoSerializer`/`NinoDeserializer`（<Term id="top-level-call" lang="zh">顶层调用</Term>）有一笔很小的固定开销；每个追踪的对象再多 4 字节和一次身份查找。不涉及追踪对象的调用没有任何开销。
- 复用反序列化对新对象照常工作；遇到指回已读对象的回引用时，直接替换当前值，不回收旧值，因为对象图里别的地方可能还引用着它。

一个 `Node { V = 5 }` 被密封类 `Holder` 引用两次（先是 `object` 成员，再是 `Node` 成员），字节来自[规范](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/spec/wire-format.md#a5-reference-tracking)：

<Callout type="warn">

必须靠构造函数参数或只读成员重建的类型（例如位置记录）不能追踪（NINO016）。结构体上的 `trackReferences` 直接忽略，并报警告（NINO015）。

</Callout>

### 自己用 Writer 写多个值 [#own-writer]

传一个值进去、返回字节（或写进缓冲区写入器、流）的调用，以及读出一个值的调用，引用表只在这一次调用里有效。自己创建 `Writer` 或 `Reader` 时，经它写的所有内容共享引用，直到调用 `ReleaseReferences()` 为止：每条逻辑消息结束时调用一次；同一个 `Writer` 写的值要用同一个 `Reader` 读（见[连续写入多个值](/zh/docs/v4/advanced/high-performance#several-values-back-to-back)）。

## 深层对象图 [#deep-object-graphs]

递归类型（链表、树、节点里又包含节点）可以嵌套任意深，开不开 `trackReferences` 都一样。前 128 层嵌套的对象，Nino 在原处直接写入；更深的对象会成为<Term id="deferred-object" lang="zh">推迟的对象</Term>：之后从较浅的层级写入，读取时也一样。因此：

- 无论对象图有多深，写入和读取占用的栈都有上限：10 万个节点的链表在 512 KB 栈的线程上也能正常往返。
- 无法构造出让读取方栈溢出的数据，所以递归类型可以放心用在来自不可信来源的消息里。
- 嵌套不到 128 层的数据不受影响，写出的字节完全不变。

```csharp
[NinoType]
public class TreeNode
{
    public int Value;
    public List<TreeNode> Children;
}

// 多深都可以：两边都不会 StackOverflowException。
byte[] bytes = NinoSerializer.Serialize(deepTree);
var copy = NinoDeserializer.Deserialize<TreeNode>(bytes);
```

像 `TreeNode` 这样的递归类型，只要数据是一棵树（每个节点只引用一次），就不需要 `trackReferences`；某个节点出现两次，或者有环，才需要。

推迟的对象在 Nino 读到存放它的成员或集合元素时就立即创建并放进去，它的成员则在同一次调用中稍后读取，所以复用反序列化和 `[NinoPooled]` 仍然会复用每一个实例。有两种类不能这样推迟，总是在原处嵌套：

- 由**构造函数**创建的类（位置记录、init-only 或只读成员），因为成员读完之前还没有实例；
- **按值比较**的类（记录、重写了 `GetHashCode` 或实现了 `IComparable` 的类），因为 `HashSet<T>`、字典的键或有序集合可能在成员读完之前就已经持有它。

由这两种类组成的对象图，嵌套超过 [`NinoSettings.MaxDepth`](/zh/docs/v4/settings#limits)（默认 512 层）就会抛异常，外围包含自身的结构体里尚未结束的主体也计入层数，写和读都一样：序列化时抛 `InvalidOperationException`，读取这样的数据时抛 `NinoDataException`。需要深度递归的类型，请给它无参构造函数和可赋值的成员。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 由谁发现 |
| --- | --- | --- |
| 没开 `trackReferences` 的类型之间有环 | 序列化时抛 `InvalidOperationException`，消息里指明类型 | 序列化器 |
| 两个成员共用一个对象，它的类型却没开追踪 | 读回来是两个对象，改了一个，另一个看不到 | 无：给共享的那个类型加上 `trackReferences: true` |
| 给要靠构造函数重建的类型（位置记录、init-only 或只读成员）开 `trackReferences` | 编译失败 | NINO016 |
| 给结构体开 `trackReferences` | 直接忽略 | NINO015（警告） |
| 同一个集合放在两个成员里 | 写两次，读回来是两个集合 | 无：把它放进一个开了追踪的 `[NinoType]` 类 |
| 用同一个 `Writer` 写多条消息，中间没调 `ReleaseReferences()` | 后面的消息会回引用前面消息里的对象，单独读不出来 | 无：每条消息结束时调用（见[上文](#own-writer)） |
| 构造函数创建或按值比较的类嵌套超过 `MaxDepth` | 序列化时抛 `InvalidOperationException`，读取时抛 `NinoDataException` | 序列化器和读取方 |
