默认情况下，一个对象被引用两次就写两次，读回来成了两个实例；序列化带环的对象图会抛 `InvalidOperationException`（见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)）。给类加上 `trackReferences: true`，对象图就能原样保留。它的所有子类型也都会追踪，哪怕子类型自己声明的 `[NinoType]` 没写这个选项：

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // 可能指回更早的节点
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // 形成环
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

共享引用和环一样要紧。比如一张组织架构图里，两名员工属于同一个部门：

```csharp
[NinoType(trackReferences: true)]
public class Department { public string Name; }

[NinoType]
public class Employee { public string Name; public Department Department; }

var sales = new Department { Name = "Sales" };
var staff = new List<Employee>
{
    new() { Name = "Ana", Department = sales },
    new() { Name = "Ben", Department = sales },
};
byte[] bytes = NinoSerializer.Serialize(staff);
var loaded = NinoDeserializer.Deserialize<List<Employee>>(bytes);
// loaded[0].Department == loaded[1].Department：同一个对象，所以改名后两个员工都能看到 // [!code highlight]
```

不追踪的话，读出来是两个独立的 `Department` 对象，读完再给部门改名，只有一名员工看得到。只有被共享的类型需要这个选项，`Employee` 本身不用追踪。

- 每个追踪的对象前面有 4 字节的引用头；同一次调用里已经写过的对象，只写它的序号。
- 不管成员声明成什么类型（包括 `object` 和接口），共享引用都保持同一个对象。
- 只追踪 `[NinoType]` 类，不管集合：同一个 `List<T>` 出现在两个成员里，还是写两次。
- 开销：你每调用一次 `NinoSerializer`/`NinoDeserializer`（<Term id="top-level-call" lang="zh">顶层调用</Term>）有一笔很小的固定开销；每个追踪的对象再多 4 字节和一次身份查找。不涉及追踪对象的调用没有任何开销。

一个 `Node { V = 5 }` 被密封类 `Holder` 引用两次（先是 `object` 成员，再是 `Node` 成员），字节来自[规范](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/spec/wire-format.md#a5-reference-tracking)：

<Callout type="warn">

必须靠构造函数参数或只读成员重建的类型（例如位置记录）不能追踪（NINO016）。结构体上的 `trackReferences` 直接忽略，并报警告（NINO015）。

</Callout>

## 什么时候用 [#when-to-use-it]

<Accordions type="single">
<Accordion title="用于对象图">

有关联关系的领域模型（多个订单指向同一个客户）、撤销栈、多个对象指向同一个对象的文档、带父节点引用的树：凡是对象身份要紧或者有环的地方都用得上。一个列表把同一个追踪对象重复 100 次，字节数和耗时都只有不追踪时的零头。

</Accordion>
<Accordion title="消息和普通数据不需要">

网络消息、配置和其他树状数据没有共享引用。这些地方别开追踪：不追踪的类型没有任何开销，连 4 字节的头都没有。

</Accordion>
<Accordion title="自己连续写入、读取多个值时">

传一个值进去、返回字节（或写进缓冲区写入器）的调用，以及从 span 读出一个值的调用，引用表只在这一次调用里有效。自己创建 `Writer` 或 `Reader` 时，经它写的所有内容共享引用，直到调用 `ReleaseReferences()` 为止。每条逻辑消息结束时调用一次。

</Accordion>
</Accordions>

复用反序列化对新对象照常工作；遇到指回已读对象的回引用时，直接替换当前值，不回收旧值，因为对象图里别的地方可能还引用着它。
