---
title: 引用追踪
description: 保留共享引用与循环引用。
icon: Share2
---

默认情况下，被引用两次的对象会被写入两次，并被读回为两个实例，循环图也无法序列化。将类标记为 `trackReferences: true`（子类型会继承）即可保留对象图：

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // may point back to an earlier node
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // a cycle
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

- 每个被追踪的对象都会在一个 4 字节的引用头部之后写入：同一次调用中已经写入过的对象只写入它的索引。
- 共享引用在任意声明类型的成员之间都能保持同一性，包括 `object` 和接口。
- 追踪只覆盖 `[NinoType]` 类，不包括集合：同一个 `List<T>` 出现在两个成员中仍会被写入两次。
- 开销：每次顶层调用约 28 ns，外加每个对象 4 字节和一次身份查找。不含被追踪对象的调用没有任何开销。

<Callout type="warn">

必须通过构造函数参数或只读成员重新创建的类型（例如位置 record）无法被追踪（NINO016）。结构体上的 `trackReferences` 会被忽略并给出警告（NINO015）。

</Callout>

## 何时使用 [#when-to-use-it]

<Accordions type="single">
<Accordion title="用于对象图">

场景图、实体关系、编辑器的撤销栈、多个对象指向同一对象的存档、带父链接的树：凡是对象身份重要或存在循环的情况。把同一个被追踪对象重复 100 次的列表，其写入的字节数和耗时只有未追踪列表的一小部分。

</Accordion>
<Accordion title="消息和普通数据不要使用">

网络消息、配置以及其他树形数据没有共享引用。这些场景请关闭追踪：未追踪的类型没有任何开销，连 4 字节的头部都没有。

</Accordion>
<Accordion title="自己写入和读取多个值时">

顶层的 `NinoSerializer`/`NinoDeserializer` 调用会把引用表限定在一次调用内。当你自己创建 `Writer` 或 `Reader` 时，通过它写入的所有内容都会共享引用，直到你调用 `ReleaseReferences()`；逻辑上的一条消息结束时必须调用它。

</Accordion>
</Accordions>

引用反序列化对新对象照常工作；回引用会直接替换当前值而不回收它，因为旧值可能仍被对象图中的其他地方引用。
