Nino v4 重写了运行时和源生成器。运行速度超过 v3 和 MemoryPack，构建速度大幅提升，并新增了键控与版本容错类型、引用追踪、对象池、分析器以及大量内置类型。本页按领域介绍 v4 现在的全部内容；每个候选版本各自改了什么，见[更新日志](/zh/docs/v4/changelog)。

<Callout type="warn">

v4 的二进制格式与 v3 以及更早的 v4 beta/preview 版本**不兼容**，API 也有变化。参见[从 v3 迁移](/zh/docs/v4/migration)。

</Callout>

## 逐项对比 [#features]

v3（3.3.13）与 v4 的全部差异列在一张表里，下面各节再按领域展开。

| | v3 | v4 |
| --- | --- | --- |
| API | 每个程序集各自生成 `Serializer` / `Deserializer`，外加扩展方法 | `Nino.Core` 中的 `NinoSerializer` / `NinoDeserializer` |
| 二进制格式 | 按位置 | 默认按位置，可按类型改为 `VersionTolerant` 或 `Keyed`；所有目标框架写出的字节相同；填充字节清零 |
| 版本容错 | 用 `WEAK_VERSION_TOLERANCE` 对整个项目统一开启，只能在末尾追加 | 按类型设置 `NinoFormat.VersionTolerant`；可以向最末端的派生类型追加，嵌套多深都可以；旧代码会跳过新成员 |
| 键控成员（调整顺序 / 删除 / 插入） | 不支持 | `[NinoType(format: NinoFormat.Keyed)]` |
| 共享引用与循环引用 | 不支持 | `[NinoType(trackReferences: true)]` |
| 反序列化到已有实例 | 不支持 | `Deserialize(data, ref value)`，并回收丢弃的实例 |
| 流与管道 | 写入可用 `IBufferWriter<byte>`；读取只支持 span | `Serialize(value, stream)`、`Deserialize<T>(stream)` 及其异步版本；`Deserialize<T>(ReadOnlySequence<byte>)` 直接读 `PipeReader` 的数据 |
| 序列化回调 | 不支持 | `[NinoOnSerializing]`、`[NinoOnSerialized]`、`[NinoOnDeserializing]`、`[NinoOnDeserialized]` |
| 对象池 | 不支持 | `[NinoPooled]`、`[NinoFactory]` 工厂方法、`NinoSettings.SetRecycler<T>` |
| `[NinoType]` 的子类型 | 需要各自标记 `[NinoType]` | 自动继承 |
| 自定义集合（`List<T>`、`Dictionary<,>` 等的子类） | 字典子类需要公共索引器 | 直接支持，无需特性 |
| `PriorityQueue<,>`、不可变集合、`BigInteger`、`Uri`、`Memory<T>` 等 | 不支持 | .NET 8+ 支持 `PriorityQueue<,>`；安装 `Nino.Immutable` 后支持所有不可变集合；BCL 类型见[支持的类型](/zh/docs/v4/types) |
| 自定义格式化器 | 不支持 | 针对成员用 `[NinoMemberFormatter]`，针对类型用 `[assembly: NinoFormatter]` |
| 成员顺序 | 声明顺序、`[NinoMember(index)]` 或 `[NinoExplicitOrder]` | 声明顺序或 `[NinoMember(index)]`；`[NinoExplicitOrder]` 已移除 |
| 固定大小的类型 | 不支持 | `Serialize(value)` 直接写入大小正好的数组；`NinoSerializer.GetFixedSize<T>()` |
| 装箱 / 运行时类型 API | 不支持 | `SerializeBoxed(value, type)`、`DeserializeBoxed(data, type)`，用于运行时才知道、且没有共同 `[NinoType]` 基类型的类型 |
| 诊断 | 生成代码中的编译错误 | 44 条分析器诊断（NINO001–NINO044），许多带代码修复 |
| 检查类型改动会不会弄坏已存数据 | 不支持 | 布局基线：写代码时分析器就报出破坏性改动，CI 里用 `nino-gen layouts --check` |
| 逐字节查看一条消息 | 不支持 | `nino-gen inspect` 列出每个成员的偏移、长度和值 |
| 增量生成 | 否：每次都扫描整个 Compilation，任何修改都会重新生成全部类型 | 每个类型一个文件，只重新生成改动过的类型 |
| 拦截器 | 不支持 | Roslyn 4.8+（.NET 8 SDK 及以上）下始终开启 |
| 热更新（HybridCLR） | 支持 | 支持，无需初始化调用 |
| Unity | 2022.3+，需手动安装 `Microsoft.CodeAnalysis` | 2022.3+，生成器随包附带 |
| 线程安全 | 内联缓存在高并发下可能出现竞争 | 注册表无锁，采用写时复制 |
| `ValueTuple`、`KeyValuePair`、`Nullable<T>` | 在 .NET Core 与 Unity/Mono 上布局不同 | 所有运行时同一种格式 |
| 深层嵌套的数据 | 可能栈溢出 | 超过 128 层的对象推迟处理，栈深有上限 |
| 不可信输入 | 没有为此设计 | 任何无效输入都抛同一个 `NinoDataException`，分配和深度都有上限（[不可信数据](#untrusted-data)） |

## 性能 [#performance]

### 比 v3 更快 [#faster-than-v3]

对比基准是 v3 API 的最后一个版本 **3.3.13**（3.9.x 是测试 v4 功能的过渡版本），与 v4 在同一台机器上接连运行。

<BenchmarkChart chart={['v3-serialize', 'v3-deserialize']} lang="zh" />

- **类的序列化**明显更快。
- **类的反序列化**与 v3 一样快或略快。耗时主要花在分配结果对象上，而 v4 还要校验数据，并支持引用追踪和复用反序列化。
- **非托管结构体数组**两者持平：两个版本都整块拷贝。v4 还会把填充字节清零，保证输出是确定的（没有填充的结构体会跳过这一步，参见[结构体布局](/zh/docs/v4/performance#struct-layout)）。
- **复用反序列化**是 v3 没有的：填充已有实例或池化实例，每次调用分配 **0 B**。参见[内存分配与对象池](#allocation-and-pooling)。

### 比 MemoryPack 更快 [#faster-than-memorypack]

用 `ref` 反序列化进已有的对象、新实例从 [`[NinoPooled]`](/zh/docs/v4/pooling) 对象池取时，比 MemoryPack 的覆盖模式最高**快 <BenchValue k="reuse.max" />**，池化路径上每次调用分配 **0 B**（见[池化测试结果](/zh/docs/v4/benchmarks#pooling)）。两个库序列化时都不分配内存，数据大小也基本相同（`SimpleClass`：Nino <BenchValue k="payload.v4" /> 字节，MemoryPack <BenchValue k="payload.memorypack" /> 字节）。详见[完整对比](/zh/docs/v4/vs-memorypack)，包括 [MemoryPack 仍然领先的地方](/zh/docs/v4/vs-memorypack#where-memorypack-is-ahead)。

### 构建更快 [#faster-to-build]

v3 的生成器会把每个子类型的代码内联到它的每个多态基类中，而且每敲一次键都要重新生成全部类型。v4 每个类型只生成一个文件，只生成一次，之后只重新生成你改动的部分。

<BenchmarkChart chart="compile" lang="zh" />

项目越大，差距越明显：见[构建时间与生成代码](/zh/docs/v4/benchmarks#build-time-and-generated-code)。

### 速度从哪里来 [#where-the-speed-comes-from]

- **拦截器**：在 Roslyn 4.8+（.NET 8 SDK 及以上）下，类型已知的 `NinoSerializer`/`NinoDeserializer` 调用会在编译期直接改写为调用生成的格式化器。始终开启；Unity（使用生成器的 Roslyn 4.3 版本）和更旧的编译器走常规路径，写出的字节相同。参见[拦截器](/zh/docs/v4/performance#interceptors)。
- **JIT 和 AOT 编译器能内联的结构体格式化器**；小型类的主体也会内联到容纳它们的集合循环中。参见[可内联的结构体格式化器](/zh/docs/v4/performance#struct-formatters-inlined)。
- **整块拷贝，不逐个循环**：非托管 `[NinoType]` 结构体及其数组、列表都按原始内存拷贝。元素是这类结构体的 `Stack<T>`、`Queue<T>` 和声明为接口的集合也一样；`DateTimeOffset` 的数组和列表，以及元素为非托管值的值元组、`KeyValuePair` 的数组和列表也是，内存与字节不一致时用 SIMD 重排。参见[非托管数据按原始内存处理](/zh/docs/v4/performance#raw-memory-for-unmanaged-data)和[集合类型](/zh/docs/v4/types#collection-types)。
- **每种集合走它自己的内部结构**：`SortedSet<T>`、`SortedDictionary<TKey, TValue>`、`SortedList<TKey, TValue>`、`LinkedList<T>`、并发集合和不可变集合，都通过它们的字段、构造函数和批量方法读写，而不是逐个元素循环。这些字段在某些运行时（.NET Framework 和 Mono）上不一样，所以启动时会检查一次布局，对不上就改用公开 API。参见[可移植的设计](/zh/docs/v4/platforms#portable-by-design)。
- **CPU 有 SIMD 就用**：AVX-512 上用 64 字节向量和掩码拷贝，AVX2 上用 32 字节向量，Arm64 上用查表指令，.NET 10 的 WebAssembly SIMD 上用字节重排。参见[SIMD](/zh/docs/v4/simd#dotnet)。
- **固定大小的类型**直接写进大小正好的 `byte[]`；`NinoSerializer.GetFixedSize<T>()` 返回这个大小。参见[固定大小的类型](/zh/docs/v4/performance#fixed-size-types)。
- **在 x64 和 Arm64 上测量**：每个版本都会在 x64 和 GitHub 的 Arm64 runner 上跑基准测试；见[.NET 基准测试](/zh/docs/v4/benchmarks)。

这些优化都不改变字节：每条快速路径写出的内容都和普通路径一样。

## 不可信数据 [#untrusted-data]

Nino v4 本来就是为读取不可信来源的数据而设计的：网络对端的消息、用户交给你的文件、请求体。专门针对读取器构造的数据，不会让进程崩溃，不会越过输入末尾读取，不会分配与自身大小不成比例的内存，也不会让 Nino 创建你没声明的类型。读取路径每次改动，都会用模糊测试和手工构造的数据把每个内置类型测一遍（[Nino 如何测试](/zh/docs/v4/testing#fuzzing)）。

- **数据里没有类型名**：多态值写的是类型 ID，只能是声明类型已注册的子类型之一；回引用必须指向已经读过、且符合这个槽位类型的对象。`System.Type` 有意不支持。
- **分配有上限**：分配内存之前，每个长度都先和剩余字节数比对；集合在读到元素之前最多预先分配剩余字节数的 16 倍，数量更大时随元素实际读出再扩容。
- **栈用量有上限**：嵌套超过 128 层的对象会推迟到较浅的层级再读取；无法推迟的类型（包含自身的结构体、由构造函数创建的类型）最多 512 层（由 `NinoSettings.MaxDepth` 设置），途中还会检查栈空间。参见[深层对象图](/zh/docs/v4/reference-tracking#deep-object-graphs)。
- **只有一种异常**：任何无效输入都抛 `NinoDataException`（一种 `InvalidOperationException`），消息以 `Nino:` 开头；类型自己拒绝的值（格式错误的 `Uri`、未知的区域性、为 null 的字典键）也一样，原始异常放在 `InnerException` 里。在数据进入的地方一个 `catch` 就够了。
- **严格的字节与限制**：Nino 从不写出的字节一律拒绝（不是 0 或 1 的 `bool` 或存在字节、读完还剩字节的键控成员、格式错误的推迟主体段）；专门构造来在哈希表里冲突的键会抛异常（`NinoSettings.MaxHashCollisions`）；`NinoSettings.MaxDepth` 和 `MaxCollectionLength` 可以收紧限制，`NinoSettings.Untrusted` 则加上那些每次读取都要花时间的检查。参见[不可信数据](/zh/docs/v4/security)。
- **不留下未初始化内存**：读入已有值失败时，不会在里面留下装着未初始化内存的数组。

值本身不做校验（负数的血量会照原样读出），字节里也不带 schema，所以要自己检查逻辑依赖的值，并在缓冲之前限制消息大小。Nino 检查什么、哪些仍归你的代码负责，见[不可信数据](/zh/docs/v4/security)；与 MemoryPack（建议只用于可信数据）的对比，见[不可信输入](/zh/docs/v4/vs-memorypack#untrusted-input)。

## 数据演进与对象图 [#data-and-object-graphs]

- **用一个选项决定格式**：`[NinoType(format: ...)]` 接收一个 `NinoFormat`。`Positional`（默认值）最快；`VersionTolerant` 允许向最末端的派生类型追加成员，嵌套多深都可以，每个对象多 4 字节，旧代码跳过它不认识的成员；`Keyed` 按成员名的哈希写成员，所以继承层次里任何一个类都能重排、删除和插入成员。v3 针对整个项目的 `WEAK_VERSION_TOLERANCE` 已移除（错误 NINO032 及其代码修复帮你把项目迁走）。参见[数据演进](/zh/docs/v4/evolving-data)。
- **布局元数据**：生成器用 `[assembly: NinoTypeLayout]` 记下每个 `[NinoType]` 怎么写，包括每个按原始内存拷贝的值的大小和字段偏移。工具可以据此比较两次构建的布局，在发布前发现字节的变化。每个成员都按它写出的字节来描述（`seq(string)`、`map(K,V)`、`type(T)` 等），键控类型的成员还带有它的键。参见[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。
- **布局基线**：用 `NinoLayouts.cs` 记下要存储或传输的类型当前的布局。之后你一边写代码，分析器一边比对：改动会让旧数据或旧版本读不了时报 NINO034，会悄无声息丢数据时报 NINO035，需要留意时报 NINO036，并提供撤销或接受改动的代码修复；`nino-gen layouts --check` 在 CI 里跑同一套规则。参见[布局基线](/zh/docs/v4/evolving-data#layout-baseline)。
- **类型改名**后，用 [`[NinoFormerName]`](/zh/docs/v4/evolving-data#former-name) 仍能读取旧数据；键控成员改名也一样。
- **引用追踪**：`[NinoType(trackReferences: true)]` 保留共享引用和循环引用：同一个对象引用多次也只写一次，读回来仍是同一个实例；每个追踪的对象只多 4 字节。参见[引用追踪](/zh/docs/v4/reference-tracking)。
- **无需标签的多态**：类型 ID 是类型名的哈希，任何未密封的类或接口都能当基类型，其他程序集（插件、热更新）里的子类型会自动找到。参见[多态](/zh/docs/v4/polymorphism)。
- **深层对象图**：嵌套超过 128 层的对象推迟到较浅的层级再写入和读取，所以递归类型嵌套再深、数据再恶意，也不会栈溢出。参见[深层对象图](/zh/docs/v4/reference-tracking#deep-object-graphs)。

## 定义类型 [#defining-types]

- **私有成员**：使用 `includeNonPublicMembers`；在 .NET 8 及以上通过 `[UnsafeAccessor]` 访问，无需 `partial`（泛型类型需 .NET 9 及以上）。参见[私有成员](/zh/docs/v4/defining-types#private-members)。
- **构造函数、record 和 `required` 成员**：Nino 调用合适的构造函数，或标记了 `[NinoConstructor]` 的那个。参见[自定义构造函数](/zh/docs/v4/constructors)。
- **紧凑的字符串**：字符都不超过 U+00FF（ASCII、Latin-1）的文本每个字符占一个字节，其他文本按 UTF-16 写，63 个字符以内的字符串头只占 1 字节（[字符串](/zh/docs/v4/wire-format#strings)）。[`[NinoUtf8]`](/zh/docs/v4/defining-types#string-encoding) 可按成员写成 UTF-8。
- **回调**：标了 `[NinoOnSerializing]`、`[NinoOnSerialized]`、`[NinoOnDeserializing]` 或 `[NinoOnDeserialized]` 的方法，会在这个类型的每个值写入、读取前后执行，基类的先执行，由生成的代码直接调用。MemoryPack 的 `[MemoryPackOnSerializing]` 等四个特性换成它们即可（[从 MemoryPack 迁移](/zh/docs/v4/vs-memorypack#switching-from-memorypack)）。参见[回调](/zh/docs/v4/defining-types#callbacks)。
- **子类型继承 `[NinoType]`**：子类型自动从基类或接口继承这个特性；泛型类型可以用作成员、元素和顶层值。参见[定义类型](/zh/docs/v4/defining-types)。

## 支持的类型 [#supported-types]

- **日常代码中的 BCL 类型**：`BigInteger`、`Uri`、`Version`、`StringBuilder`、`BitArray`、`CultureInfo`、`TimeZoneInfo`、`Lazy<T>`、`Memory<T>`、`ReadOnlyMemory<T>` 和 `ReadOnlySequence<T>`，此外还有基元类型、枚举、字符串、`Nullable<T>`、元组、`KeyValuePair`、`DateTimeOffset` 和 `nint`。`System.Type` 有意不支持。参见[其他内置类型](/zh/docs/v4/types#other-built-in-types)。
- **所有 BCL 集合**：一到四维的数组、`List<T>`、`HashSet<T>`、`Queue<T>`、`Stack<T>`、`LinkedList<T>`、有序集合和并发集合、`BlockingCollection<T>`、`PriorityQueue<TElement, TPriority>`（.NET 8 及以上）、`ObservableCollection<T>`、只读包装（`ReadOnlyCollection<T>`、`ReadOnlyObservableCollection<T>`、`ReadOnlyDictionary<TKey, TValue>`）、`ILookup<TKey, TElement>`、`IGrouping<TKey, TElement>` 以及各集合接口。参见[集合类型](/zh/docs/v4/types#collection-types)。
- **所有不可变集合**：安装可选的 `Nino.Immutable` 包即可，从 `ImmutableArray<T>` 到 `ImmutableSortedDictionary<TKey, TValue>`，各自写出与对应可变集合相同的字节。参见[不可变集合](/zh/docs/v4/types#immutable-collections)。
- **你自己的集合**：派生自 `List<T>`、`Dictionary<TKey, TValue>` 等，或实现了 `ICollection<T>`、`IDictionary<TKey, TValue>`、`IProducerConsumerCollection<T>` 的类型，无需任何特性。参见[自定义集合](/zh/docs/v4/types#user-collections)。
- **Unity 的 `AnimationCurve`、`Gradient` 和 `RectOffset`**：Unity 包附带 `Nino.UnityTypes.dll`，其中包含它们的格式化器。Unity 和 Godot 的结构体（`Vector3`、`Quaternion` 等）按原始内存拷贝。参见 [Unity 的类](/zh/docs/v4/advanced/unity#unity-classes)。
- **可扩展的格式化器**：用 `[assembly: NinoFormatter(typeof(MyFormatter<,>))]` 让 Nino 学会处理一个新类型（你自己的或第三方的）。类型参数和元素格式化器会自动推断（`[NinoRaw]` 把类型参数限定为按原始字节处理的类型），生成的代码直接调用它，Nino 自带的 BCL 格式化器也是这样声明的。`[NinoMemberFormatter]` 只改一个成员的编码。参见[自定义格式化器](/zh/docs/v4/custom-formatters)。

## 内存分配与对象池 [#allocation-and-pooling]

- **复用反序列化**：`NinoDeserializer.Deserialize(data, ref value)` 原地填充已有的对象、列表、数组和字典，文本未变的字符串会保留原实例。
- **池化反序列化**：给类加上 `[NinoPooled]`，Nino 就把数据反序列化进你用 `ReturnToPool()` 归还的实例，并复用它们的列表、数组和字典。丢弃的实例（数据为 `null`、列表变短、类型改变）交给用 `NinoSettings.SetRecycler<T>` 注册的处理器；没注册就回到各自的池。
- **`[NinoFactory]` 工厂方法**让 Nino 从你自己的对象池中获取新实例。

参见[复用与对象池](/zh/docs/v4/pooling)。

## API [#api]

- **两个入口**：`NinoSerializer.Serialize` 写入 `byte[]`、`IBufferWriter<byte>`（例如 `PipeWriter`）或 `Writer`；`NinoDeserializer.Deserialize` 从 `ReadOnlySpan<byte>` 或 `Reader` 读取。每个 `Serialize` 重载都以 `in T` 接收值，所以写字段里的结构体时不会先复制一份。参见[序列化与反序列化](/zh/docs/v4/basic)。
- **流与管道**：`NinoSerializer.Serialize(value, stream)`、`SerializeAsync` 和 `NinoDeserializer.Deserialize<T>(stream)`、`DeserializeAsync<T>` 读写一条消息，字节和 span 版本相同，中间用池化缓冲区；`Deserialize<T>(in ReadOnlySequence<byte>)` 直接读 `PipeReader` 或 gRPC 交给你的数据，只有一段时不拷贝。一个流上传多条消息仍然要分帧。参见[流与压缩](/zh/docs/v4/advanced/streams)。
- **`NinoArrayBufferWriter`**：可复用的缓冲区，让序列化不分配内存；用 `new NinoArrayBufferWriter(initialCapacity, pool)` 还能从你自己的 `ArrayPool<byte>` 租用数组。参见[复用缓冲区](/zh/docs/v4/basic#reusing-a-buffer)。
- **`Writer` 与 `Reader`**：在一个缓冲区里写入多个值再依次读回，也是自定义格式化器使用的 API。参见 [Writer 与 Reader](/zh/docs/v4/custom-formatters#writer-and-reader)。
- **面向运行时类型的装箱 API**：`SerializeBoxed(value, type)` 和 `DeserializeBoxed(data, type)` 用于只拿得到 `Type` 的类型，写出的内容与 `Serialize<T>` 完全相同。有共同 `[NinoType]` 基类型的，用 `Serialize<TBase>` 更快。参见[运行时类型](/zh/docs/v4/basic#runtime-types)。
- **`NinoSerializer.IsSupported(Type)`** 判断 Nino 能否序列化和反序列化某个类型，供只拿到 `Type` 的代码使用，例如 ASP.NET Core 格式化器。参见[装箱 API](/zh/docs/v4/basic#the-boxed-api)。
- **无需初始化**：生成的注册表会自行注册并按需查找；`NinoSettings`、`NinoPolymorphic.TryRegister<T>()` 和 `NinoRegistry.EnsureInitialized` 都是可选的。参见[启动时](/zh/docs/v4/start#at-startup)。

## Web 与 ASP.NET Core [#web-and-aspnet-core]

- **ASP.NET Core**：`Nino.AspNetCore` 包提供用于 `application/x-nino` 的 MVC 输入输出格式化器（`AddNinoFormatters()`），以及 Minimal API 的请求体（`NinoBody<T>`）和结果（`NinoResults`），直接在请求和响应的管道上读写。参见 [ASP.NET Core](/zh/docs/v4/advanced/aspnetcore)。
- **TypeScript、Go 与 Rust**：Nino.Codegen（每次构建后）或 `nino-gen` 工具（Nino.Codegen.Tool，基于构建好的程序集）把你的 `[NinoType]` 生成 TypeScript 类、Go 结构体或 Rust 类型及其编解码代码；`nino.ts`、Go 和 Rust 运行时读写的字节与 .NET 完全一致，浏览器和 Node 里也一样。参见 [TypeScript、Go 与 Rust](/zh/docs/v4/advanced/codegen)、[Go](/zh/docs/v4/advanced/go) 和 [Rust](/zh/docs/v4/advanced/rust)。
- **浏览器中的 .NET**：你的类型本身也可以运行在 .NET WebAssembly 上。参见[浏览器客户端](/zh/docs/v4/advanced/browser)。

## 平台 [#platforms]

- **跨平台、跨运行时字节一致**：`netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0` 写出的字节完全相同，数据在 CoreCLR、Mono 和 IL2CPP，64 位和 32 位，x64 和 Arm64 之间通用。各运行时内存布局不一致的地方（`Nullable<T>`、元组、`decimal`、32 位对齐），Nino 自己定义字节，不拷贝内存，还会清零填充字节，所以相等的值总是序列化成相同的字节。参见[平台](/zh/docs/v4/platforms)。
- **裁剪与 Native AOT**：Nino.Core 带有这两方面的标注，用 `PublishTrimmed` 和 `PublishAot` 发布时，Nino 不产生警告。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。
- **Unity 2022.3+**：从 OpenUPM 安装，包内附带源生成器和 `Nino.UnityTypes.dll`。参见 [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity)。
- **Unity 中的代码修复**：Unity 包附带分析器的代码修复，Rider 和 Visual Studio 提供与 .NET 项目相同的快速修复。参见[分析器](/zh/docs/v4/analyzers)。
- **HybridCLR 热更新**无需初始化调用，**Godot 4** 以普通 NuGet 包安装。参见 [HybridCLR 与热更新](/zh/docs/v4/platforms#hybridclr-and-hot-update)和 [Godot](/zh/docs/v4/platforms#godot)。
- **程序集可卸载**：可回收 `AssemblyLoadContext` 里的程序集能随它一起卸载，Nino 会清掉为它缓存的内容（.NET 8 及以上自动完成；.NET Core 3.0 到 .NET 7 需调用 `NinoRegistry.Remove`）。参见[卸载程序集](/zh/docs/v4/platforms#unloading-assemblies)。

## 工具 [#tooling]

- **真正的增量源生成器**：每个 `[NinoType]` 一个文件，模型可判等（equatable），不再扫描整个 Compilation。改一个类型只重新生成这个类型；不改变模型的修改（例如注释、方法体）什么都不重新生成。
- **生成的代码大幅减少**：集合、字符串、可空类型、元组等内置类型，都在 `Nino.Core` 里以泛型格式化器的形式统一实现；生成器只为你的 `[NinoType]` 生成代码。
- **44 条分析器规则**（NINO001–NINO044）在写代码时就指出错误，例如不支持的成员类型、缺少 `partial`、一个类型上有两个 `[NinoFormerName]`，不少还带一键代码修复。参见[分析器](/zh/docs/v4/analyzers)。
- **`nino-gen inspect`**：按程序集的布局读一条消息，列出每个成员的偏移、长度、编码和值；数据有问题时，指出在哪里、因为什么读不下去。参见[查看一条消息](/zh/docs/v4/advanced/codegen#inspect)。

## 已移除 [#removed]

- `[NinoExplicitOrder]`：改用 `[NinoType(false)]` 配合 `[NinoMember(index)]`。
- beta 中的 `Serialize(object)`：现为 `SerializeBoxed`。
- 用 `NinoFormatterCache<T>.Register<TFormatter>()` 在运行时注册格式化器：请用 `[assembly: NinoFormatter]` 或 `[NinoMemberFormatter]` 声明。

参见[从 v3 迁移](/zh/docs/v4/migration)和[从 v4 beta 升级](/zh/docs/v4/migration#upgrading-from-a-v4-beta)。

## 快速示例 [#quick-example]

```csharp
[NinoType, NinoPooled]
public sealed partial class Packet
{
    public int Id;
    public List<int> Values;

    // 必须写（分析器提供一键添加两者的修复）。
    private static partial IEnumerable<Packet> OnNinoPoolWarmup() => Enumerable.Range(0, 16).Select(_ => new Packet());
    private partial void OnNinoPoolReturn() { /* 清除 Nino 不反序列化的状态 */ }
}

var buffer = new NinoArrayBufferWriter(); // 留着反复用：序列化进它不分配内存
NinoSerializer.Serialize(new Packet { Id = 1, Values = new List<int> { 1, 2, 3 } }, buffer);

var packet = NinoDeserializer.Deserialize<Packet>(buffer.WrittenSpan); // 池中有实例时复用它（连同它的列表）
// ……使用它……
packet.ReturnToPool();                                                 // 归还两次会抛异常
```
