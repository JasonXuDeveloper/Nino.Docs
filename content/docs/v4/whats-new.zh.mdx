Nino v4 重写了运行时与源生成器：运行速度超过 v3 **和** MemoryPack，构建速度大幅提升，并提供长期项目所需的功能。

<ShowcaseHero lang="zh" />

<Callout type="warn">

v4 的二进制格式与 v3 以及更早的 v4 beta/preview 版本**不兼容**，API 也有变化。请参阅[从 v3 迁移](/zh/docs/v4/migration)。

</Callout>

## 比 v3 更快 [#faster-than-v3]

与 v3 的最后一个版本 **3.3.13** 在同一台机器上对比。耗时以两次运行共同的基准 MemoryPack（1.0）归一化。

<BenchmarkChart chart={['v3-serialize', 'v3-deserialize']} lang="zh" />

结构体数组（`SimpleStruct[100]`、`Vector4[10000]`）在 v3 中就已经是一次内存拷贝，因此保持持平。

## 构建更快 [#faster-to-build]

v3 的生成器会把每个子类型的主体内联到每个多态基类中，并且每次按键都会重新生成所有类型。v4 为每个类型生成一个文件、只生成一次，并且只重新生成你修改的部分。

<BenchmarkChart chart="compile" lang="zh" />

{/* GEN_N100 */}

<Callout type="info" title="1,100 个类型（N = 100）">

v3 3.3.13 在 N = 100 时的数据正在测量，完成后会补充到这里。v4 随类型数量线性增长：每个类型约 3.5 KB 源码和 2 ms 编译时间。

</Callout>

## 比 MemoryPack 更快 [#faster-than-memorypack]

与 MemoryPack 1.21.4 在同一次运行中对比。Nino 在序列化上明显领先，在类和多态对象图的反序列化上领先，在原始数组上持平（两者都是一次 `memcpy`）。

<BenchmarkChart chart={['serialize', 'deserialize']} lang="zh" />

<Callout type="info" title="MemoryPack 唯一胜出的用例">

反序列化 `Vector4[10000]` 测得 0.85 倍。每次调用都会在大对象堆上分配一个 160 KB 的数组，因此主要测量的是第 2 代垃圾回收：两次运行分别为 0.96 倍和 0.85 倍，误差 ±15%。

</Callout>

### 反序列化到已有对象 [#deserialize-into-existing-objects]

v4 新增：通过 `ref` 反序列化到你已有的对象中，新实例取自 [`[NinoPooled]`](/zh/docs/v4/pooling) 对象池。与 MemoryPack 的覆盖模式相比，Nino 在池化节点上**快 2.6 倍**，在原地更新的池化叶子上**快 4.9 倍**，并且分配 **0 B**，而 MemoryPack 每次调用分配 1,024 B 和 12,800 B。

<BenchmarkChart chart={['reuse', 'allocation']} lang="zh" />

两个库在序列化时都不分配内存，载荷大小也相同（`SimpleClass`：Nino 为 1,146 字节，MemoryPack 为 1,148 字节）。请阅读[与 MemoryPack 的完整对比](/zh/docs/v4/vs-memorypack)（包括 MemoryPack 仍然领先的地方）以及[基准测试表格](/zh/docs/v4/perf)。

## 亮点

### 构建更快
- **真正增量的源生成器**：每个 `[NinoType]` 一个文件，模型可比较（equatable），不再扫描整个编译。修改一个类型只会重新生成该类型；不改变任何模型的修改（注释、方法体）不会重新生成任何内容。
- **生成的代码大幅减少**：集合、字符串、可空类型、元组等内置类型以泛型格式化器的形式在 `Nino.Core` 中实现一次；生成器只为你的 `[NinoType]` 生成代码。
- **分析器与代码修复**：在你输入时报告错误（NINO001–NINO022），其中许多提供一键修复。参见[诊断列表](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/diagnostics.md)。

### 运行更快
- **可被 JIT/AOT 编译器内联的结构体格式化器**，对 unmanaged 的 `[NinoType]` 结构体及其数组和列表直接拷贝原始内存，除结果对象外不产生任何分配。
- **新版编译器上的拦截器**：在 Roslyn 4.8+（.NET 8 SDK 及更高版本）上，类型已知的 `NinoSerializer`/`NinoDeserializer` 调用会在编译期被重定向到生成的格式化器（没有虚调用）。始终开启，无需配置；旧版编译器走常规路径，写出相同的字节。参见[拦截器](/zh/docs/v4/performance#interceptors)。
- **线程安全、缓存友好**：无锁、写时复制（copy-on-write）的注册表；热路径上没有共享的可变状态。

### 复用而非分配
- **Ref 反序列化**：`NinoDeserializer.Deserialize(data, ref value)` 原地填充已有的对象、列表、数组和字典。
- **对象池反序列化**：给类加上 `[NinoPooled]`，Nino 就会反序列化到你通过 `ReturnToPool()` 归还的实例中，并复用它们的列表、数组和字典。被丢弃的实例（数据为 `null`、列表变短、类型变化）会回到各自的对象池，或交给通过 `NinoSettings.SetRecycler<T>` 注册的处理器。
- **`[NinoRefDeserialization]` 工厂方法**让 Nino 从你自己的对象池中获取新实例。

参见 [Ref 反序列化与对象池](/zh/docs/v4/pooling)。

### 让数据演进
- **可选的版本兼容**：`[NinoType(versionTolerant: true)]` 允许在该类型或其任意基类中追加成员，适用于任意嵌套深度。
- **键控成员**：`[NinoType(keyed: true)]` 按成员名称的哈希写入成员，因此成员可以重新排序、删除和插入。
- **引用追踪**：`[NinoType(trackReferences: true)]` 保留共享引用与循环引用。

### 更多类型，随你定制
- **用户集合**：派生自 `List<T>`、`HashSet<T>`、`Dictionary<TKey, TValue>` 等的类型，无需任何特性。
- **更多内置类型**：.NET 6+ 上的 `PriorityQueue<TElement, TPriority>`，以及通过 `Nino.Immutable` 包支持的 `ImmutableArray<T>` / `ImmutableList<T>`。
- **可插拔的格式化器**：`[assembly: NinoFormatter(typeof(MyFormatter<,>))]` 让 Nino 认识一个新类型（你自己的或第三方的）。类型参数与元素格式化器会被自动推断，生成的代码直接调用它，运行时也使用同一份注册。Nino 自己的 BCL 格式化器也是这样声明的。参见[自定义格式化器](/zh/docs/v4/custom-formatters)。
- **子类型继承 `[NinoType]`**：从其基类或接口继承。

### 随处运行
- **处处同一种格式**：`netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0` 产出完全相同的字节，数据可在 CoreCLR、Mono 与 IL2CPP 之间、64 位与 32 位之间通用。
- **无需初始化调用**：生成的注册表会被延迟查找，因此热更新程序集（HybridCLR）开箱即用。
- **Unity**：生成器随包附带，无需额外安装。

## 快速示例

```csharp
[NinoType, NinoPooled]
public sealed partial class Packet
{
    public int Id;
    public List<int> Values;

    // Required (the analyzer offers a fix that adds both).
    private static partial IEnumerable<Packet> OnNinoPoolWarmup() => Enumerable.Range(0, 16).Select(_ => new Packet());
    private partial void OnNinoPoolReturn() { /* clear state Nino does not deserialize */ }
}

byte[] bytes = NinoSerializer.Serialize(new Packet { Id = 1, Values = new List<int> { 1, 2, 3 } });

var packet = NinoDeserializer.Deserialize<Packet>(bytes); // reuses a pooled instance (and its list) if there is one
// ... use it ...
packet.ReturnToPool();                                    // returning it twice throws
```
