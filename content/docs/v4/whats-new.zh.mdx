Nino v4 重写了运行时和源生成器。运行速度超过 v3 和 MemoryPack，构建速度大幅提升，并新增了键控与版本容错类型、引用追踪、对象池、分析器以及大量内置类型。本页按领域介绍截至 **4.0.0-rc.5** 已发布的全部 v4 内容，以及 **4.0.0-rc.6** 新增的内容（标为 *rc.6*）；每个版本各自改了什么，见[更新日志](/zh/docs/v4/changelog)。

<Callout type="warn">

v4 的二进制格式与 v3 以及更早的 v4 beta/preview 版本**不兼容**，API 也有变化。参见[从 v3 迁移](/zh/docs/v4/migration)。

</Callout>

## 性能 [#performance]

### 比 v3 更快 [#faster-than-v3]

对比基准是 v3 API 的最后一个版本 **3.3.13**（3.9.x 是测试 v4 功能的过渡版本），在同一台机器上与 v4 先后运行。

<BenchmarkChart chart={['v3-serialize', 'v3-deserialize']} lang="zh" />

类的序列化明显更快，反序列化与 v3 一样快或略快，非托管结构体数组两者持平。原因分析见 [v3 与 v4 对比](/zh/docs/v4/v3-vs-v4#runtime)。

### 比 MemoryPack 更快 [#faster-than-memorypack]

在同一轮测试中与 MemoryPack 对比。序列化时 Nino 明显领先（最高快 <BenchValue k="serialize.max" />）；反序列化类和多态对象图时也领先（最高快 <BenchValue k="deserialize.max" />）；非托管值的数组两者持平，都只做一次 `memcpy`。

<BenchSource lang="zh" />

<BenchmarkChart chart={['serialize', 'deserialize']} lang="zh" />

通过 `ref` 反序列化到你已有的对象中、新实例从 [`[NinoPooled]`](/zh/docs/v4/pooling) 对象池中取时，比 MemoryPack 的覆盖模式最高**快 <BenchValue k="reuse.max" />**，在池化路径上每次调用只分配 **0 B**（见[池化测试结果](/zh/docs/v4/perf#pooling)）。两个库序列化时都不分配内存，数据大小也基本相同（`SimpleClass`：Nino <BenchValue k="payload.v4" /> 字节，MemoryPack <BenchValue k="payload.memorypack" /> 字节）。另请阅读[完整对比](/zh/docs/v4/vs-memorypack)，包括 [MemoryPack 仍然领先的地方](/zh/docs/v4/vs-memorypack#where-memorypack-is-ahead)。

### 构建更快 [#faster-to-build]

v3 的生成器会把每个子类型的代码内联到它的每个多态基类中，而且每敲一次键都要重新生成全部类型。v4 每个类型只生成一个文件，只生成一次，之后只重新生成你改动的部分。

<BenchmarkChart chart="compile" lang="zh" />

项目越大，差距越明显：见[构建时间与生成代码](/zh/docs/v4/perf#build-time-and-generated-code)。

### 速度从哪里来 [#where-the-speed-comes-from]

- **拦截器**：在 Roslyn 4.8+（.NET 8 SDK 及以上）下，类型已知的 `NinoSerializer`/`NinoDeserializer` 调用会在编译期直接改写为调用生成的格式化器。始终开启；Unity（使用生成器的 Roslyn 4.3 版本）和更旧的编译器走常规路径，写出的字节相同。参见[拦截器](/zh/docs/v4/performance#interceptors)。
- **JIT 和 AOT 编译器能内联的结构体格式化器**；小型类的主体也会内联到容纳它们的集合循环中。参见[可内联的结构体格式化器](/zh/docs/v4/performance#struct-formatters-inlined)。
- **整块处理，而不是逐个循环**：非托管 `[NinoType]` 结构体及其数组和列表按原始内存拷贝。由这类元素组成的 `Stack<T>`、`Queue<T>` 和声明为接口的集合也一样；`DateTimeOffset` 的数组和列表，以及由非托管值组成的值元组和 `KeyValuePair` 的数组和列表也整块处理，内存与字节不一致时用 SIMD 重排。参见[非托管数据按原始内存处理](/zh/docs/v4/performance#raw-memory-for-unmanaged-data)和[集合类型](/zh/docs/v4/types#collection-types)。
- **每种集合走它自己的内部结构**：`SortedSet<T>`、`SortedDictionary<TKey, TValue>`、`SortedList<TKey, TValue>`、`LinkedList<T>`、并发集合和不可变集合，都通过它们的字段、构造函数和批量方法读写，而不是逐个元素循环。这些字段在不同运行时（.NET Framework 和 Mono）上不同，所以布局会在启动时检查一次，不匹配时改用公开 API。参见[可移植的设计](/zh/docs/v4/platforms#portable-by-design)。
- **CPU 有 SIMD 就用**：AVX-512 上用 64 字节向量和掩码拷贝，AVX2 上用 32 字节向量，Arm64 上用查表指令，.NET 10 的 WebAssembly SIMD 上用字节重排。参见[各平台的 SIMD](/zh/docs/v4/platforms#simd)。
- **固定大小的类型**直接写进大小正好的 `byte[]`；`NinoSerializer.GetFixedSize<T>()` 返回这个大小。参见[固定大小的类型](/zh/docs/v4/performance#fixed-size-types)。
- **在 x64 和 Arm64 上测量**：每个版本都会在 x64 和 GitHub 的 Arm64 运行器上跑基准测试；见[基准测试](/zh/docs/v4/perf)。

这些都不会改变字节：每条路径写出的内容都与普通路径相同。

## 数据演进与对象图 [#data-and-object-graphs]

- **用一个选项决定格式**：`[NinoType(format: ...)]` 接收一个 `NinoFormat`。`Positional`（默认值）最快；`VersionTolerant` 允许向最末端的派生类型追加成员，嵌套多深都可以，每个对象多 4 字节，旧代码会跳过它不认识的成员；`Keyed` 按成员名的哈希写入成员，因此层次结构中的任何类都可以重排、删除和插入成员。在项目中定义 `WEAK_VERSION_TOLERANCE`，会把该项目中 `Positional` 的类型变为 `VersionTolerant`。参见[数据演进](/zh/docs/v4/evolving-data)。
- **布局元数据**：生成器把每个 `[NinoType]` 的写入方式记录为 `[assembly: NinoTypeLayout]`，包括每个按原始内存拷贝的值的大小和字段偏移，工具可以借此比较两次构建的布局，在发布前发现字节的变化。自 *rc.6* 起，每个成员都按它写出的字节来描述（`seq(string)`、`map(K,V)`、`type(T)` 等），键控类型的成员还带有它的键。参见[布局元数据](/zh/docs/v4/evolving-data#layout-metadata)。
- **类型改名**后，用 [`[NinoFormerName]`](/zh/docs/v4/defining-types#former-name) 仍能读取旧数据；键控成员改名也一样。
- **引用追踪**：`[NinoType(trackReferences: true)]` 保留共享引用和循环引用：同一个对象被引用多次时只写一次，读回后仍是同一个实例，每个被追踪的对象只多 4 字节。参见[引用追踪](/zh/docs/v4/reference-tracking)。
- **无需标签的多态**：类型 ID 是类型名的哈希，任何非 sealed 的类或接口都可以作为基类型，其他程序集（插件、热更新）中的子类型会被自动找到。参见[多态](/zh/docs/v4/polymorphism)。
- **深层对象图**：嵌套超过 128 层的对象会推迟到较浅的层级再写入和读取，因此无论递归类型嵌套多深，还是遇到恶意数据，都不会栈溢出。参见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)。
- **恶意输入**：每个长度在分配内存之前都会与剩余字节数比对，截断的数据会抛出异常，而不会越界读取。参见[无效数据](/zh/docs/v4/basic#invalid-data)。

## 定义类型 [#defining-types]

- **私有成员**：使用 `containNonPublicMembers`；在 .NET 8 及以上通过 `[UnsafeAccessor]` 访问，无需 `partial`（泛型类型除外）。参见[私有成员](/zh/docs/v4/defining-types#private-members)。
- **构造函数、record 和 `required` 成员**：Nino 调用合适的构造函数，或标记了 `[NinoConstructor]` 的那个。参见[自定义构造函数](/zh/docs/v4/constructors)。
- **紧凑的字符串**（*rc.6*）：所有字符都不超过 U+00FF（ASCII、Latin-1）的文本每个字符写一个字节，其他文本按 UTF-16 写出。[`[NinoUtf8]`](/zh/docs/v4/defining-types#string-encoding) 可按成员写成 UTF-8。
- **子类型继承 `[NinoType]`**：子类型自动从基类或接口继承该特性；泛型类型可以用作成员、元素和顶层值。参见[定义类型](/zh/docs/v4/defining-types)。

## 支持的类型 [#supported-types]

- **日常代码中的 BCL 类型**：`BigInteger`、`Uri`、`Version`、`StringBuilder`、`BitArray`、`CultureInfo`、`TimeZoneInfo`、`Lazy<T>`、`Memory<T>`、`ReadOnlyMemory<T>` 和 `ReadOnlySequence<T>`，此外还有基元类型、枚举、字符串、`Nullable<T>`、元组、`KeyValuePair`、`DateTimeOffset` 和 `nint`。`System.Type` 有意不支持。参见[其他内置类型](/zh/docs/v4/types#other-built-in-types)。
- **所有 BCL 集合**：任意维数的数组、`List<T>`、`HashSet<T>`、`Queue<T>`、`Stack<T>`、`LinkedList<T>`、有序集合和并发集合、`BlockingCollection<T>`、`PriorityQueue<TElement, TPriority>`（.NET 8 及以上）、`ObservableCollection<T>`、只读包装（`ReadOnlyCollection<T>`、`ReadOnlyObservableCollection<T>`、`ReadOnlyDictionary<TKey, TValue>`）、`ILookup<TKey, TElement>`、`IGrouping<TKey, TElement>` 以及各集合接口。参见[集合类型](/zh/docs/v4/types#collection-types)。
- **所有不可变集合**：安装可选的 `Nino.Immutable` 包即可，从 `ImmutableArray<T>` 到 `ImmutableSortedDictionary<TKey, TValue>`，各自写出与对应可变集合相同的字节。参见[不可变集合](/zh/docs/v4/types#immutable-collections)。
- **你自己的集合**：派生自 `List<T>`、`Dictionary<TKey, TValue>` 等，或实现了 `ICollection<T>`、`IDictionary<TKey, TValue>`、`IProducerConsumerCollection<T>` 的类型，无需任何特性。参见[自定义集合](/zh/docs/v4/types#user-collections)。
- **Unity 的 `AnimationCurve`、`Gradient` 和 `RectOffset`**：Unity 包附带 `Nino.UnityTypes.dll`，其中包含它们的格式化器。Unity 和 Godot 的结构体（`Vector3`、`Quaternion` 等）按原始内存拷贝。参见 [Unity 的类](/zh/docs/v4/advanced/unity#unity-classes)。
- **可扩展的格式化器**：用 `[assembly: NinoFormatter(typeof(MyFormatter<,>))]` 教 Nino 处理一个新类型（你自己的或第三方的）。类型参数和元素格式化器会自动推断（`[NinoRaw]` 把类型参数限定为按原始字节处理的类型），生成的代码直接调用它，Nino 自带的 BCL 格式化器也是这样声明的。`[NinoCustomFormatter]` 改变单个成员的编码方式。参见[自定义格式化器](/zh/docs/v4/custom-formatters)。

## 内存分配与对象池 [#allocation-and-pooling]

- **复用反序列化**：`NinoDeserializer.Deserialize(data, ref value)` 原地填充已有的对象、列表、数组和字典，文本未变的字符串会保留原实例。
- **池化反序列化**：给类加上 `[NinoPooled]`，Nino 就会把数据反序列化到你用 `ReturnToPool()` 归还的实例中，并复用实例里的列表、数组和字典。被丢弃的实例（数据为 `null`、列表变短、类型改变）会交给用 `NinoSettings.SetRecycler<T>` 注册的处理器；没有注册时，回到各自的池。
- **`[NinoFactory]` 工厂方法**让 Nino 从你自己的对象池中获取新实例。

参见[复用反序列化与对象池](/zh/docs/v4/pooling)。

## API [#api]

- **两个入口**：`NinoSerializer.Serialize` 写入 `byte[]`、`IBufferWriter<byte>`（例如 `PipeWriter`）或 `Writer`；`NinoDeserializer.Deserialize` 从 `ReadOnlySpan<byte>` 或 `Reader` 读取。每个 `Serialize` 重载都以 `in T` 接收值，从字段读出的结构体写入时不会先复制一份。参见[序列化与反序列化](/zh/docs/v4/basic)。
- **`NinoArrayBufferWriter`**：可复用的缓冲区，让序列化不分配内存；用 `new NinoArrayBufferWriter(initialCapacity, pool)` 还能从你自己的 `ArrayPool<byte>` 租用数组。参见[复用缓冲区](/zh/docs/v4/basic#reusing-a-buffer)。
- **`Writer` 与 `Reader`**：在一个缓冲区里写入多个值再依次读回，也是自定义格式化器使用的 API。参见 [Writer 与 Reader](/zh/docs/v4/custom-formatters#writer-and-reader)。
- **用于运行时类型的装箱 API**：`SerializeBoxed(value, type)` 和 `DeserializeBoxed(data, type)` 用于只能以 `Type` 形式得知的类型，写出的内容与 `Serialize<T>` 完全相同。有共同 `[NinoType]` 基类型的类型，用 `Serialize<TBase>` 更快。参见[运行时类型](/zh/docs/v4/basic#runtime-types)。
- **`NinoSerializer.IsSupported(Type)`**（*rc.6*）判断 Nino 能否序列化和反序列化某个类型，供只拿到 `Type` 的代码使用，例如 ASP.NET Core 格式化器。参见[装箱 API](/zh/docs/v4/basic#the-boxed-api)。
- **无需初始化**：生成的注册表会自行注册并按需查找；`NinoSettings`、`NinoPolymorphic.Register<T>()` 和 `NinoRegistry.EnsureInitialized` 都是可选的。参见[启动时](/zh/docs/v4/start#at-startup)。

## Web 与 ASP.NET Core [#web-and-aspnet-core]

- **ASP.NET Core**（*rc.6*）：`Nino.AspNetCore` 包提供用于 `application/x-nino` 的 MVC 输入输出格式化器（`AddNinoFormatters()`），以及 Minimal API 的请求体（`NinoBody<T>`）和结果（`NinoResults`），直接基于请求和响应管道读写。参见 [ASP.NET Core](/zh/docs/v4/advanced/aspnetcore)。
- **TypeScript 客户端**（*rc.6*）：`Nino.TypeScript` 包在每次构建后为你的 `[NinoType]` 生成 TypeScript 类、枚举和编解码器，并附带 `nino.ts` 运行时，浏览器和 Node 读写的字节与 .NET 完全相同。参见 [TypeScript 客户端](/zh/docs/v4/advanced/typescript)。
- **浏览器中的 .NET**：你的类型本身也可以运行在 .NET WebAssembly 上。参见[浏览器与 JavaScript 客户端](/zh/docs/v4/advanced/browser)。

## 平台 [#platforms]

- **处处同一格式**：`netstandard2.0`、`netstandard2.1`、`net8.0` 和 `net10.0` 写出完全相同的字节，数据在 CoreCLR、Mono、IL2CPP 之间，64 位和 32 位之间，x64 和 Arm64 之间通用。在运行时内存布局不一致的地方（`Nullable<T>`、元组、`decimal`、32 位对齐），Nino 自己定义字节而不是拷贝内存，并清零填充字节，所以相等的值总是序列化为相同的字节。参见[平台与二进制格式](/zh/docs/v4/platforms)。
- **裁剪与 Native AOT**：Nino.Core 带有相应标注，用 `PublishTrimmed` 和 `PublishAot` 发布时 Nino 不会产生警告。参见[裁剪与 Native AOT](/zh/docs/v4/platforms#trimming-and-native-aot)。
- **Unity 2022.3+**：从 OpenUPM 安装，包内附带源生成器和 `Nino.UnityTypes.dll`。参见 [Unity 与 HybridCLR](/zh/docs/v4/advanced/unity)。
- **HybridCLR 热更新**无需初始化调用，**Godot 4** 以普通 NuGet 包安装。参见 [HybridCLR 与热更新](/zh/docs/v4/platforms#hybridclr-and-hot-update)和 [Godot](/zh/docs/v4/platforms#godot)。
- **程序集可卸载**：可回收 `AssemblyLoadContext` 中的程序集能随上下文一起卸载，Nino 会清除相关缓存（.NET 8 及以上自动完成；.NET Core 3.0 到 .NET 7 需调用 `NinoRegistry.Remove`）。参见[卸载程序集](/zh/docs/v4/platforms#unloading-assemblies)。

## 工具 [#tooling]

- **真正的增量源生成器**：每个 `[NinoType]` 一个文件，模型可判等（equatable），不再扫描整个 Compilation。改一个类型只重新生成这个类型；不改变模型的修改（例如注释、方法体）不会触发任何重新生成。
- **生成的代码大幅减少**：集合、字符串、可空类型、元组等内置类型，都在 `Nino.Core` 里以泛型格式化器的形式统一实现；生成器只为你的 `[NinoType]` 生成代码。
- **26 条分析器规则**（NINO001–NINO026）在写代码时就报告错误，例如不支持的成员类型、缺少 `partial`、一个类型上有两个 `[NinoFormerName]`，许多都带一键代码修复。参见[分析器诊断](/zh/docs/v4/analyzers)。

## 已移除 [#removed]

- `[NinoExplicitOrder]`：改用 `[NinoType(false)]` 配合 `[NinoMember(index)]`。
- beta 中的 `Serialize(object)`：现为 `SerializeBoxed`。
- 用 `NinoFormatterCache<T>.Register<TFormatter>()` 在运行时注册格式化器：请用 `[assembly: NinoFormatter]` 或 `[NinoCustomFormatter]` 声明。

参见[从 v3 迁移](/zh/docs/v4/migration)和[从 v4 beta 升级](/zh/docs/v4/migration#upgrading-from-a-v4-beta)。

## 快速示例 [#quick-example]

```csharp
[NinoType, NinoPooled]
public sealed partial class Packet
{
    public int Id;
    public List<int> Values;

    // Required (the analyzer offers a fix that adds both).
    private static partial IEnumerable<Packet> OnNinoPoolWarmup() => Enumerable.Range(0, 16).Select(_ => new Packet());
    private partial void OnNinoPoolReturn() { /* clear state Nino does not deserialize */ }
}

var buffer = new NinoArrayBufferWriter(); // keep it and reuse it: serializing into it allocates nothing
NinoSerializer.Serialize(new Packet { Id = 1, Values = new List<int> { 1, 2, 3 } }, buffer);

var packet = NinoDeserializer.Deserialize<Packet>(buffer.WrittenSpan); // reuses a pooled instance (and its list) if there is one
// ... use it ...
packet.ReturnToPool();                                                 // returning it twice throws
```
