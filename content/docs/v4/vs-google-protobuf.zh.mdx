[Google.Protobuf](https://github.com/protocolbuffers/protobuf/tree/main/csharp) 是 Google 官方的 [Protocol Buffers](https://protobuf.dev) C# 运行时，走 schema 优先的路子：消息先写在 `.proto` 文件里，`protoc` 为每条消息生成一个 C# 类，任何有 protobuf 实现的语言都能按同一份 schema 读出同样的字节。Nino 则从你的 C# 类型出发。本页对比 Nino v4 和 Google.Protobuf **3.36.2**，也就是 Nino 基准测试所用的版本：Google.Protobuf 的功能以 [protobuf.dev](https://protobuf.dev) 上的 Protocol Buffers 文档为准，Nino 的功能以 Nino 源码为准。无法核实的功能，一律不列出。protobuf-net 在 C# 类上加特性，写的是同一种格式，见 [Nino 与 protobuf-net 对比](/zh/docs/v4/vs-protobuf-net)。所有库放在一起比，见[序列化库选型](/zh/docs/v4/compare)。

## 两种格式 [#formats]

Protocol Buffers 给每个字段写上字段号和 wire type，读取方遇到不认识的字段可以跳过；schema 就是那份 `.proto` 文件。Nino 的字节不带字段号：怎么读由你的 C# 类型决定，在 .NET 里如此，在 [nino-gen](/zh/docs/v4/advanced/codegen) 从这些类型生成的 Go、Rust 和 TypeScript 代码里也一样。两个 protobuf 库共有的部分（对象、整数、null 与空）见 [protobuf-net 那张表](/zh/docs/v4/vs-protobuf-net#formats)；Google.Protobuf 自己的做法如下：

| | Nino v4 | Google.Protobuf |
| --- | --- | --- |
| schema | 你的 C# 类型 | `.proto` 文件，由 `protoc` 生成 C# 类 |
| 子类型 | 4 字节类型 ID（类型名的哈希），写在子类型的成员前面 | 没有继承：用一个 `oneof` 字段装几种消息之一 |
| 缺失的值 | 可空值或引用前面一个存在字节 | proto3 的标量没有 null：要么标成 `optional`，要么用包装消息（`Int32Value`，读出来是 `int?`） |
| 时间 | `DateTime`、`DateTimeOffset`、`TimeSpan` 原样写 | 知名类型 `Timestamp` 和 `Duration` |

## 性能 [#performance]

用 BenchmarkDotNet 测量，与 Nino 在同一轮测试中运行，数据相同。Google.Protobuf 用的是自己的消息类型，由 `protoc` 从基准测试的 [`workloads.proto`](https://github.com/JasonXuDeveloper/Nino/blob/main/benchmarks/Nino.Benchmark/Workloads/workloads.proto) 和 `cases.proto` 生成，写出的 protobuf 消息和 protobuf-net 相同。写入用 `WriteTo` 写进复用的 `ArrayBufferWriter<byte>`，读取用 `Parser.ParseFrom(ReadOnlySpan<byte>)`（[测试设置](/zh/docs/v4/benchmarks#workloads)）。<IfWorkloads>在 Nino 领先的[真实负载](/zh/docs/v4/benchmarks#workloads)上，序列化快 <BenchValue k="workloads.googleprotobuf.serialize" />，反序列化快 <BenchValue k="workloads.googleprotobuf.deserialize" />。</IfWorkloads>Google.Protobuf 跑了真实负载以及基础、多态、可空值三组用例。

## 不可信输入 [#untrusted-input]

Google.Protobuf 没有专门读不可信数据的模式。消息没法指定要创建的类型：没有继承，`Any` 也只能解包成调用方点名的类型（`Any.Unpack<T>`）。嵌套深度受 `CodedInputStream` 的递归上限约束；消息大小只有在你用 `CodedInputStream.CreateWithLimits` 创建流，或者在宿主上限制输入时才有上限。

Nino 的默认模式就能读不可信数据；[`NinoSettings.Untrusted`](/zh/docs/v4/security#untrusted-mode) 再加上那些每次读取都要多花时间的检查。

## Google.Protobuf 领先的地方 [#where-google-protobuf-is-ahead]

下面这些 Google.Protobuf 能做，Nino v4 不做：

- **一份 schema 通吃所有语言。** `.proto` 文件就是契约，Google 为 C++、Java、Python、Go 等语言提供的实现都从它生成代码。Nino 的数据要通过你的 C# 类型读，或者通过从这些类型生成的 Go、Rust 和 TypeScript 代码读。
- **gRPC。** gRPC for .NET（`Grpc.AspNetCore`、`Grpc.Net.Client`）建立在 Google.Protobuf 的消息之上，其他语言的 gRPC 对端也能与之通信。
- **每条消息都能承受修改**，靠的是字段号，Protocol Buffers 文档还写明了规则（编号永不复用，用 `reserved` 防止删掉的编号再被用上）。在 Nino 里这是按类型选的（[`NinoFormat.Keyed`](/zh/docs/v4/evolving-data#keyed-members)）；默认的按位置格式在成员改变后就读不了旧数据。
- **自带 JSON 形式。** `JsonFormatter` 和 `JsonParser` 按 Protocol Buffers 的 JSON 映射读写同样的消息。
- **描述符。** 每条消息运行时都带着自己的 schema（`Descriptor`），通用工具可以处理任意消息。
- **小整数更小。** varint 让小的数字只占 1 字节。

Nino 不做的事有什么替代做法，见[局限](/zh/docs/v4/compare#limitations)。什么场景选哪个：[怎么选](/zh/docs/v4/compare#which-to-choose)。

## 从 Google.Protobuf 迁移 [#switching-from-google-protobuf]

用 Nino 时，C# 类型就是 schema，所以每条消息都换成你自己的一个类型：

| Google.Protobuf | Nino |
| --- | --- |
| `.proto` 文件里的 `message Order { ... }`，由 `protoc` 编译 | 加了 `[NinoType]` 的 C# 类、结构体或记录（[定义类型](/zh/docs/v4/defining-types)） |
| 字段号（`int32 id = 1;`） | 声明顺序；或者用 `[NinoType(false)]`，在要写的成员上加 `[NinoMember(n)]`（[显式指定成员](/zh/docs/v4/defining-types#choosing-members-explicitly)） |
| 删除字段、`reserved` 编号 | `[NinoType(format: NinoFormat.Keyed)]`：按名字识别成员，可以随意删除，用 `[NinoFormerName]` 重命名（[数据演进](/zh/docs/v4/evolving-data)） |
| `oneof` | 加了 `[NinoType]` 的基类或接口，每个分支一个子类型（[多态](/zh/docs/v4/polymorphism)） |
| `repeated T`、`map<K, V>` | `List<T>` 或 `T[]`、`Dictionary<K, V>` |
| `optional` 标量、包装类型（`Int32Value`） | `int?` 等可空类型 |
| `google.protobuf.Timestamp`、`Duration` | `DateTime` 或 `DateTimeOffset`、`TimeSpan` |
| `bytes` | `byte[]` |
| `message.WriteTo(bufferWriter)`、`message.ToByteArray()` | `NinoSerializer.Serialize(value, bufferWriter)`、`NinoSerializer.Serialize(value)` |
| `Order.Parser.ParseFrom(span)` | `NinoDeserializer.Deserialize<Order>(span)` |
| `MergeFrom` | `NinoDeserializer.Deserialize(bytes, ref value)`，它替换内容而不是追加（[复用与对象池](/zh/docs/v4/pooling)） |
| `WriteDelimitedTo`、`ParseDelimitedFrom` | 在流上读写[帧](/zh/docs/v4/advanced/streams#frames) |

两者写出的字节不同，所以已经存下的数据要转换：用 Google.Protobuf 读出每个值，拷进对应的 Nino 类型，再用 Nino 写出（步骤见[换成 Nino](/zh/docs/v4/compare#switching)）。其他语言的程序依据 `.proto` 文件读的消息继续用 Protocol Buffers；如果那些程序是 TypeScript、Go 或 Rust，也可以改用 [nino-gen](/zh/docs/v4/advanced/codegen) 生成的代码。gRPC 本身并不绑定 protobuf：用 `Marshallers.Create` 把 `NinoSerializer.Serialize` 和 `NinoDeserializer.Deserialize` 包成一个 `Marshaller<T>`，就能传 Nino 类型，前提是两端都用 Nino。
