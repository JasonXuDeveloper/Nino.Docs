`NinoSerializer` 和 `NinoDeserializer`（命名空间 `Nino.Core`）就是全部的运行时 API。两者都是静态类，并且**线程安全**：可以在任意多个线程上同时调用，无需加锁。每次调用用到的临时状态（<Term id="scratch-buffer" lang="zh">暂存缓冲区</Term>、引用表）按线程保存，热路径上不会写共享内存。

这一页讲日常用到的调用。同样这些调用怎样做到完全不分配内存，见[高性能序列化](/zh/docs/v4/advanced/high-performance)。

本页的例子序列化下面这个 `Order`：

```csharp title="Order.cs"
using System.Collections.Generic;
using Nino.Core;

[NinoType]
public sealed class Order
{
    public long Id;
    public string Customer;
    public List<OrderLine> Lines;
}

[NinoType]
public struct OrderLine
{
    public int ProductId;
    public int Quantity;
}
```

## 序列化 [#serializing]

```csharp nocheck
// 写入新的字节数组
byte[] NinoSerializer.Serialize<T>(in T value);

// 写入任意 IBufferWriter<byte>
void NinoSerializer.Serialize<T>(in T value, IBufferWriter<byte> bufferWriter);

// 用已有的 Writer（一个缓冲区中的多个值、自定义格式化器）
void NinoSerializer.Serialize<T>(in T value, ref Writer writer);

// 装箱的值，仅用于运行时才以 Type 得知的类型（见运行时类型）
byte[] NinoSerializer.SerializeBoxed(object value, Type type);
void NinoSerializer.SerializeBoxed(object value, IBufferWriter<byte> bufferWriter, Type type);
void NinoSerializer.SerializeBoxed(object value, ref Writer writer, Type type);
```

`T` 可以是任何[受支持的类型](/zh/docs/v4/types)：`[NinoType]`、基元类型、字符串、集合等。

```csharp
byte[] bytes = NinoSerializer.Serialize(order);
```

### 复用缓冲区 [#reusing-a-buffer]

`Serialize<T>(value)` 每次都会为结果分配一个 `byte[]`。如果是<Term id="fixed-size" lang="zh">固定大小的类型</Term>，或者元素大小固定的数组和列表，这个数组按最终大小分配，数据直接写进去（原理见[固定大小的类型](/zh/docs/v4/performance#fixed-size-types)）；其他值先写入线程独享的暂存缓冲区，再拷贝出来。想做到零分配，就序列化到一个自己长期持有的缓冲区里。

`NinoArrayBufferWriter` 是 Nino 自带的 `IBufferWriter<byte>`，底层数组默认租自 `ArrayPool<byte>.Shared`（也可以传入你自己的池），Nino 会**直接写入**其中。换成其他 `IBufferWriter<byte>`（.NET 的 `ArrayBufferWriter<byte>`、`PipeWriter`、包装 `Stream` 的写入器），最后会多一次拷贝。

```csharp
var buffer = new NinoArrayBufferWriter();      // 或 new NinoArrayBufferWriter(initialCapacity)

NinoSerializer.Serialize(order, buffer);
ReadOnlySpan<byte> bytes = buffer.WrittenSpan; // 还有 WrittenMemory、WrittenCount、ToArray()
// ……发送或存储这些字节……

buffer.ResetWrittenCount();                    // 复用同一个数组 // [!code highlight]
NinoSerializer.Serialize(order, buffer);       // 这次不分配内存
```

缓冲区不够用时，会从池里租一个更大的数组。如果大致知道消息有多大，可以用 `new NinoArrayBufferWriter(initialCapacity)` 或 `EnsureCapacity(sizeHint)` 预先分配好；`Capacity` 和 `FreeCapacity` 分别是数组的大小和剩余空间。

<Callout type="warn">

`NinoArrayBufferWriter` **不是**线程安全的：每个线程、每个连接或每次操作各用一个。不再使用时调用 `Dispose()`，把数组还给池。

</Callout>

写进你自己管理的数组（传入自己的池）、精确大小的数组，以及其他所有手段，都在[高性能序列化](/zh/docs/v4/advanced/high-performance#levers)里。

### 一个缓冲区写多个值 [#several-values-in-one-buffer]

`Writer` 是一个写入 `NinoArrayBufferWriter` 的 `ref struct`。要连续写入多个值，或者在[自定义格式化器](/zh/docs/v4/custom-formatters)里写数据时，就用它：

```csharp
var buffer = new NinoArrayBufferWriter();
var writer = new Writer(buffer);
NinoSerializer.Serialize(header, ref writer);
NinoSerializer.Serialize(body, ref writer);
writer.Flush();             // 把字节提交到 buffer.WrittenCount（Dispose() 也会这样做）
writer.ReleaseReferences(); // 结束引用追踪，见下文
```

<Callout type="info">

直接传入值、拿回字节（或传入缓冲区写入器）的调用，[引用追踪](/zh/docs/v4/reference-tracking)只覆盖这一次调用。自己创建 `Writer`（或 `Reader`）时，通过它写入的所有内容共用一张引用表，直到调用 `ReleaseReferences()` 为止。请在每条逻辑消息结束时调用它；如果没有写入任何开启追踪的类型，这个调用没有开销。

</Callout>

## 反序列化 [#deserializing]

```csharp nocheck
// 新的值
T NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data);

// 读入已有的值，复用它的实例
void NinoDeserializer.Deserialize<T>(ReadOnlySpan<byte> data, ref T value);

// 用已有的 Reader
T NinoDeserializer.Deserialize<T>(ref Reader reader);
void NinoDeserializer.Deserialize<T>(ref Reader reader, ref T value);

// 装箱的值，仅用于运行时才以 Type 得知的类型（见运行时类型）
object NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, Type type);
void NinoDeserializer.DeserializeBoxed(ReadOnlySpan<byte> data, ref object value, Type type);
void NinoDeserializer.DeserializeBoxed(ref Reader reader, ref object value, Type type);
```

输入数据是 `ReadOnlySpan<byte>`：`byte[]`、`ArraySegment<byte>`、`Span<byte>`、`Memory<byte>.Span`，或者现有缓冲区的任意切片，都可以直接传入，不用拷贝。`ReadOnlySequence<byte>`（来自 `System.IO.Pipelines`）没有对应的重载，读法见[多段输入](/zh/docs/v4/advanced/streams#readonlysequence-input)，最多拷贝一次。

```csharp
Order order = NinoDeserializer.Deserialize<Order>(bytes);
Order fromSlice = NinoDeserializer.Deserialize<Order>(rented.AsSpan(0, received));
```

递归类型（树、链表）嵌套多深都可以，两边都不会栈溢出。同一个对象引用两次就写两次；对象图里有环，序列化时直接抛异常。想保留共享对象和环，见[引用追踪](/zh/docs/v4/reference-tracking)，深层对象图也在那一页讲。

### 反序列化到已有值 [#into-an-existing-value]

用 `ref` 传入已有的值，Nino 会原地填充它（<Term id="reuse-deserialization" lang="zh">复用反序列化</Term>），尽量复用这个实例以及其中的嵌套对象、列表、数组和字典。传入 `null`（或 `default`）则创建新值。字符串会和已有值里的字符串比较：内容相同就直接保留，只有内容变化（或原来为 `null`）的字符串才读成新实例。`[NinoUtf8]` 字符串在文本为 ASCII 时同样会保留；非 ASCII 的 UTF-8 文本总是解码成新字符串。

```csharp
Order order = null;
foreach (var message in messages)
{
    NinoDeserializer.Deserialize(message, ref order); // 第一次调用创建 order，之后的调用复用它
    Handle(order);
}
```

过程中丢弃的实例（数据中为 `null`、列表变短、字典少了某个键、多态类型变了）可以归还到对象池。Nino 没有 `out` 重载：要新实例就用返回值，要复用就用 `ref`。详见[复用与对象池](/zh/docs/v4/pooling)。

### 从一个缓冲区读多个值 [#several-values-from-one-buffer]

连续写入的多个值，用 `Reader` 按相同顺序读回：

```csharp
var reader = new Reader(buffer.WrittenSpan);
var header = NinoDeserializer.Deserialize<Header>(ref reader);
var body = NinoDeserializer.Deserialize<Body>(ref reader);
reader.ReleaseReferences();
```

## 运行时类型 [#runtime-types]

需要同时处理很多类型的代码（RPC 或消息分派、插件系统、编辑器工具），其实很少真的需要运行时类型。给这些类型一个共同的 `[NinoType]` 基类或接口，通过它来序列化即可：`Serialize<TBase>` 会写入类型 ID，`Deserialize<TBase>` 读出类型 ID 后，在生成代码里创建对应的类型。这是处理多种类型最快的方式，而且能配合[复用反序列化和对象池](/zh/docs/v4/pooling)使用，接收循环除了数据里的字符串之外不分配内存：

```csharp
[NinoType]
public abstract class Message { }

public sealed class Ping : Message { public long SentAt; } // 继承 [NinoType]
public sealed class Chat : Message { public string Text; }

var buffer = new NinoArrayBufferWriter();                  // 每个连接一个，反复复用
NinoSerializer.Serialize<Message>(new Ping { SentAt = 1 }, buffer); // 声明为基类：会写出类型 ID

Message message = null;
NinoDeserializer.Deserialize(buffer.WrittenSpan, ref message); // 一个 Ping，类型相同时之后的调用复用它
```

参见[多态](/zh/docs/v4/polymorphism#dispatching-through-a-common-base)。

### 装箱 API [#the-boxed-api]

装箱 API **只**用在一种情况：类型要到运行时才以 `Type` 的形式拿到，而且这些类型没有共同的 `[NinoType]` 基类型。比如基于反射、处理任意类型的工具，像指向哪个字段就保存哪个字段的检视器。序列化和反序列化必须用**同一个**类型：

```csharp
Type type = field.FieldType;                                   // 运行时才知道
byte[] bytes = NinoSerializer.SerializeBoxed(field.GetValue(target), type);
object copy = NinoDeserializer.DeserializeBoxed(bytes, type);

// 读入已有实例；它是 type 的实例时复用
object current = field.GetValue(target);
NinoDeserializer.DeserializeBoxed(bytes, ref current, type);
field.SetValue(target, current);
```

`SerializeBoxed(value, type)` 写出的字节与 `T` = `type` 时的 `Serialize<T>(value)` 完全相同（对可以为 null 的类型，`null` 也一样），所以泛型调用和装箱调用可以互相读取对方的数据。装箱 API 按 `Type` 查找格式化器（第一次用到时通过反射，之后查字典），值类型会装箱。`NinoSerializer.IsSupported(type)` 判断 Nino 能否序列化和反序列化某个类型（`[NinoType]`、内置类型或有已注册格式化器的类型），适合手里只有 `Type`、要决定处理不处理它的代码，比如 [ASP.NET Core 格式化器](/zh/docs/v4/advanced/aspnetcore#mvc)。

<Callout type="warn" title="不要把 object 当作 T">

变量声明为 `object` 时，`NinoSerializer.Serialize(value)` 调用的是 `Serialize<object>`，而不是装箱 API。它只接受 `[NinoType]` 的值，会写入<Term id="type-id" lang="zh">类型 ID</Term>，并通过包含所有 `[NinoType]` 的全局注册表分派，开销比共同基类型的生成分派更大。请把变量声明为共同的基类型，或者带上 `Type` 调用 `SerializeBoxed`。

</Callout>

## 无效数据 [#invalid-data]

Nino 本来就是为读取不可信的数据设计的，比如网络对端发来的消息、用户交给你的文件、请求体。不管字节是什么，读取都不会让进程崩溃，不会读到输入末尾之外，也不会分配与输入大小不成比例的内存。数据无效时（截断、长度不合理、类型 ID 未知、含有 Nino 从不写出的字节），只会抛一种异常：[`NinoDataException`](/zh/docs/v4/security#ninodataexception)（命名空间 `Nino.Core`），消息以 `Nino:` 开头。在数据进来的地方捕获它，丢掉这份输入即可。如果数据可能是别人刻意构造的，还要打开 `NinoSettings.Untrusted`，并自己限制消息大小：上线之前请读[不可信数据](/zh/docs/v4/security)。
