本页列出 Nino v4 不做的事情，以及早期版本中已被 v4 消除的局限。

## 当前的局限 [#current-limitations]
- **离不开源生成器。** Nino 依赖它的源生成器（Roslyn 4.3 及以上），声明 `[NinoType]` 的项目需要 C# 9 及以上。
- **不兼容 v3 数据。** v4 格式无法读取 v3 或 v4 beta/preview 版本写出的数据。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。
- **默认按位置写入。** 不启用 `versionTolerant` 或 `keyed` 时，插入、删除或调整成员顺序都会破坏已有数据。`versionTolerant` 只允许在末尾追加成员，其他改动请用 `keyed`。修改成员类型在任何模式下都不兼容。
- **原始结构体依赖布局。** 按原始内存写入的非托管 `[NinoType]` 结构体以规范的字段顺序写入：调整字段顺序或修改 `StructLayout` 都会破坏已有数据。标记 `versionTolerant`（或对某个字段使用 `[NinoIgnore]`）可以改为逐个成员写入。
- **只支持小端序主机。** 所有多字节值都按小端序写入。在大端序主机上，构造 `Writer` 或 `Reader` 时会抛出 `PlatformNotSupportedException`，不会写出不兼容的字节。目前 .NET 和 Unity 运行的所有平台都是小端序。
- **不支持的成员类型会被跳过。** 委托、`Task`、指针、`Memory<T>`、非泛型集合（`ArrayList`）、`ReadOnlyCollection<T>`、抽象集合、结构体集合，以及没有可用构造函数的集合都没有格式化器：这类成员会被跳过，并报告警告 NINO007。可以给它加上 `[NinoIgnore]`，或者编写[自定义格式化器](/zh/docs/v4/custom-formatters)。
- **集合按值处理。** 同一个集合实例出现在两个成员中，会写入两次，读回为两个实例；`trackReferences` 只追踪 `[NinoType]` 类。
- **部分类型不能追踪引用或池化。** 通过构造函数参数或只读成员重新创建的类型（例如位置记录）不能使用 `trackReferences`（NINO016）或 `[NinoPooled]`（NINO018）。`[NinoPooled]` 还要求类是 `sealed`。
- **结构体至少要有一个成员。** 不序列化任何成员的结构体会报错（NINO023），因为它会被写成零字节。请至少序列化一个成员，或者标记 `versionTolerant` 或 `keyed`。
- **接口不支持版本兼容。** 在 `[NinoType]` 接口上追加的成员不兼容旧数据，请把成员追加到类上。
- **只在运行时出现的泛型实例化。** 如果某个封闭泛型 `[NinoType]` 在进程中只会按类型 ID 读取，代码里从未写出它的名字，也从未写入过它，就必须在启动时用 `NinoPolymorphic.Register<T>()` 注册。
- **`PriorityQueue<TElement, TPriority>`** 只在 BCL 提供它的平台上可用：.NET 6 及以上，.NET Standard 和 Unity 中没有。
- **拦截器**需要 Roslyn 4.8 及以上（.NET 8 SDK 及以上）。Unity 使用 Roslyn 4.3 版本，它和更旧的编译器一样走常规调用，每次慢几纳秒，写出的字节相同。
- **没有按调用设置的选项。** 设置要么是进程级的（`NinoSettings`），要么按类型设置（特性），不能随某次调用传入。
- **内置的 BCL 类型比部分序列化库少。** `BigInteger`、`Uri`、`Version`、`StringBuilder`、`Type`、`Lazy<T>`，以及 `ImmutableArray<T>` 和 `ImmutableList<T>`（来自 `Nino.Immutable`）以外的不可变集合，都需要[自定义格式化器](/zh/docs/v4/custom-formatters)。参见[不支持的类型](/zh/docs/v4/types#not-supported)。
- **有时必须声明 `partial`。** `[NinoPooled]` 类，以及在 .NET 8 之前（包括 .NET Standard 和 Unity）或在泛型类型中序列化非公开成员的类型，都必须是 `partial`（NINO002）。这些情况下，被 `new` 隐藏的非公开基类成员无法访问（NINO022）。

## 平台说明 [#platform-notes]

Nino 自己定义字节格式，而不是直接拷贝内存，所以数据可以在 CoreCLR、Mono、IL2CPP 之间，以及 64 位和 32 位平台之间通用。`Nullable<T>`、`ValueTuple`、`decimal`、`DateTimeOffset`、32 位对齐和填充字节的处理方式，参见[平台与二进制格式](/zh/docs/v4/platforms#portable-by-design)。

## 已解决的局限 [#resolved-limitations]

<Accordions type="multiple">
<Accordion value="resolved-1" title={<><code>ValueTuple</code> 在 .NET Core 与 Unity/Mono 中表现不同</>}>

v4 已解决：`ValueTuple`、`KeyValuePair` 和 `Nullable<T>` 有明确定义、与运行时无关的格式，数据在 .NET Core 与 Unity/Mono/IL2CPP 之间通用。

</Accordion>
<Accordion value="resolved-2" title={<>启用 <code>WEAK_VERSION_TOLERANCE</code> 的项目无法读取未启用该符号的项目的数据，反之亦然</>}>

v4 已解决：版本兼容改为每个类型自己的选项（`[NinoType(versionTolerant: true)]`），属于类型自身的格式，不再依赖项目设置。`WEAK_VERSION_TOLERANCE` 仍为兼容而保留，只影响定义了该符号的项目中声明的类型。

</Accordion>
<Accordion value="resolved-3" title={<>成员只能追加在末尾，不能删除或调整顺序</>}>

v4 已解决：版本兼容的类型允许在继承层级中任意一个类的末尾追加成员；`[NinoType(keyed: true)]` 还允许调整顺序、删除和插入成员。

</Accordion>
<Accordion value="resolved-4" title={<>不支持的类型会导致编译错误</>}>

v4 已解决：分析器会在你的代码上报告警告 NINO007（附带代码修复），并跳过该成员。

</Accordion>
<Accordion value="resolved-5" title={<>共享引用和循环引用无法保留</>}>

v4 已通过 `[NinoType(trackReferences: true)]` 解决。

</Accordion>
<Accordion value="resolved-6" title={<>字典子类需要公共索引器</>}>

v4 已解决：派生自 `List<T>`、`Dictionary<TKey, TValue>` 等类型，或实现了集合接口的自定义集合，不需要任何额外代码即可使用。

</Accordion>
<Accordion value="resolved-7" title={<>序列化后无法修改类型名或命名空间</>}>

自 v3.2.2 起，可以用 `[NinoFormerName]` 解决。

</Accordion>
<Accordion value="resolved-8" title={<>无法序列化非公开的字段和属性</>}>

自 v3.0.6 起，可以用 `containNonPublicMembers` 解决。在 .NET 8 及以上，除泛型类型外不需要 `partial`；.NET 8 之前类型必须是 `partial`。

</Accordion>
<Accordion value="resolved-9" title={<>多态的非托管结构体转换为接口后，序列化结果与转换前不同</>}>

自 v3.0.3 起已解决。

</Accordion>
</Accordions>
