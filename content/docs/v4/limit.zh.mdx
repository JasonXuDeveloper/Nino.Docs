本页介绍 Nino v4 的局限性，以及 v4 已经解决的早期版本局限性。

## 当前的局限性
- **需要源生成器。** Nino 需要它的源生成器（Roslyn 4.3 或更高版本），声明 `[NinoType]` 的项目需要使用 C# 9 或更高版本。
- **与 v3 数据不兼容。** v4 格式无法读取 v3 或 v4 beta/preview 版本写入的数据。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。
- **默认按位置读写。** 不使用 `versionTolerant` 或 `keyed` 时，插入、删除或重新排序成员都会破坏已有数据。`versionTolerant` 只容忍追加的成员；其他修改请使用 `keyed`。修改成员的类型在任何情况下都不被容忍。
- **原始结构体对布局敏感。** 以原始内存写入的 unmanaged `[NinoType]` 结构体按其规范字段顺序写入：重新排序字段或修改其 `StructLayout` 会破坏已有数据。将其标记为 `versionTolerant`（或对某个字段使用 `[NinoIgnore]`），即可改为逐个成员写入。
- **仅支持小端序。** 所有多字节值都以小端序写入；不支持大端序的主机。（目前 .NET 和 Unity 运行的所有平台都是小端序。）
- **不支持的成员类型会被跳过。** 委托、`Task`、指针、非泛型集合（`ArrayList`）、`ReadOnlyCollection<T>`、抽象集合、结构体集合以及没有可用构造函数的集合都没有格式化器：该成员会被跳过并产生警告 NINO007。请将其标记为 `[NinoIgnore]`，或提供[自定义格式化器](/zh/docs/v4/custom-formatters)。
- **集合是值。** 同一个集合实例出现在两个成员中会被写入两次，读回时是两个实例；`trackReferences` 只追踪 `[NinoType]` 类。
- **部分类型无法追踪或池化。** 通过构造函数参数或只读成员重新创建的类型（例如位置记录）不能使用 `trackReferences`（NINO016）或 `[NinoPooled]`（NINO018）。`[NinoPooled]` 还要求类为 `sealed`。
- **版本兼容的接口。** 追加到 `[NinoType]` 接口上的成员不被容忍；请追加到类上。
- **仅在运行时出现的泛型实例化。** 如果某个封闭泛型 `[NinoType]` 在进程中只通过类型 id 被读取，从未在代码中出现或被写入，就必须在启动时用 `NinoPolymorphic.Register<T>()` 注册。
- **`PriorityQueue<TElement, TPriority>`** 仅在 .NET 6 及更高版本上可用（.NET Standard 和 Unity 上不可用）。
- **拦截器**需要 Roslyn 4.8 或更高版本（.NET 8 SDK 及更高版本）；Unity 和更旧的编译器使用常规（稍慢的）调用，写出相同的字节。
- **只支持缓冲区。** 没有 `Stream` 或异步 API，也没有 `ReadOnlySequence<byte>` 重载：请序列化到 `IBufferWriter<byte>`，并从 `ReadOnlySpan<byte>` 反序列化（多段序列需先拷贝）。
- **没有序列化回调**（序列化或反序列化前后的钩子）、没有内置压缩，也没有按调用的选项。变通方法参见 [Nino 与 MemoryPack 对比](/zh/docs/v4/vs-memorypack#where-memorypack-is-ahead)。
- **内置的 BCL 类型比部分序列化库少**：`BigInteger`、`Uri`、`Version`、`StringBuilder`、`Type`、`Memory<T>`、`Lazy<T>` 以及大多数不可变集合需要[自定义格式化器](/zh/docs/v4/custom-formatters)。
- **.NET 8 之前**（包括 .NET Standard 和 Unity），序列化非公开成员或使用 `[NinoPooled]` 的类型必须是 `partial`，并且泛型类型中用 `new` 隐藏的非公开基类成员无法访问（NINO022）。

## 平台说明 [#platform-notes]

Nino 自己定义字节格式而不是拷贝内存，因此数据可以在 CoreCLR、Mono 与 IL2CPP、64 位与 32 位之间移植。`Nullable<T>`、`ValueTuple`、`decimal`、`DateTimeOffset`、32 位对齐和填充的处理方式参见[平台与二进制格式](/zh/docs/v4/platforms#portable-by-design)。

## 已解决的局限性

<Accordions type="multiple">
<Accordion value="resolved-1" title={<><code>ValueTuple</code> 在 .NET Core 与 Unity/Mono 中表现不同</>}>

已在 v4 中解决：`ValueTuple`、`KeyValuePair` 和 `Nullable<T>` 有明确的、与运行时无关的格式，因此数据在 .NET Core 与 Unity/Mono/IL2CPP 之间兼容。

</Accordion>
<Accordion value="resolved-2" title={<>启用 <code>WEAK_VERSION_TOLERANCE</code> 的项目无法读取未启用该符号的项目的数据，反之亦然</>}>

已在 v4 中解决：版本兼容是每个类型的选项（`[NinoType(versionTolerant: true)]`），属于该类型自身的格式，因此不再依赖项目设置。`WEAK_VERSION_TOLERANCE` 为兼容而保留，只影响定义它的项目中声明的类型。

</Accordion>
<Accordion value="resolved-3" title={<>成员只能追加在末尾；不能删除或重新排序</>}>

已在 v4 中解决：版本兼容的类型接受追加到层级中任意类的成员，`[NinoType(keyed: true)]` 允许重新排序、删除和插入成员。

</Accordion>
<Accordion value="resolved-4" title={<>不支持的类型会导致编译错误</>}>

已在 v4 中解决：分析器在你的代码上将其报告为警告 NINO007（并提供代码修复），该成员会被跳过。

</Accordion>
<Accordion value="resolved-5" title={<>不保留共享引用与循环引用</>}>

已在 v4 中通过 `[NinoType(trackReferences: true)]` 解决。

</Accordion>
<Accordion value="resolved-6" title={<>字典子类需要公共索引器</>}>

已在 v4 中解决：派生自 `List<T>`、`Dictionary<TKey, TValue>` 等，或实现了集合接口的用户集合，无需任何额外代码即可使用。

</Accordion>
<Accordion value="resolved-7" title={<>序列化后无法重命名类型名/命名空间</>}>

自 v3.2.2 起通过 `[NinoFormerName]` 解决。

</Accordion>
<Accordion value="resolved-8" title={<>无法序列化/反序列化非公开字段/属性</>}>

自 v3.0.6 起通过 `containNonPublicMembers` 解决。在 .NET 8 及更高版本上没有限制；.NET 8 之前类型必须是 `partial`。

</Accordion>
<Accordion value="resolved-9" title={<>多态 unmanaged 结构体在转换为接口与不转换时序列化结果不同</>}>

自 v3.0.3 起解决。

</Accordion>
</Accordions>
