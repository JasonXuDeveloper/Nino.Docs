本页列出选择 Nino v4 之前需要了解的事项，以及早期版本中已被 v4 消除的局限。

## 当前的局限 [#current-limitations]
- **离不开源生成器。** Nino 依赖自己的源生成器（Roslyn 4.3 及以上），声明 `[NinoType]` 的项目需要 C# 9 及以上。
- **不兼容 v3 数据。** v4 无法读取 v3 以及 v4 测试版、预览版写出的数据。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。
- **默认按位置存储。** 不带参数的 `[NinoType]` 最快，但成员一改，旧数据就读不了。需要保存或跨版本交换的数据，请在写入之前选好 `versionTolerant` 或 `keyed`：参见[数据演进](/zh/docs/v4/evolving-data)。
- **部分类型没有内置格式化器。** 参见[支持的类型](/zh/docs/v4/types#not-supported)；用[自定义格式化器](/zh/docs/v4/custom-formatters)可以支持其中任何一种。

## 平台说明 [#platform-notes]

Nino 自己定义字节格式，而不是直接拷贝内存，所以数据可以在 CoreCLR、Mono、IL2CPP 之间，以及 64 位和 32 位平台之间通用。`Nullable<T>`、`ValueTuple`、`decimal`、`DateTimeOffset`、32 位对齐和填充字节的处理方式，参见[平台与二进制格式](/zh/docs/v4/platforms#portable-by-design)。字节序为小端；在大端主机上 Nino 会直接抛出异常，而不是写出字节（目前 .NET 和 Unity 支持的平台都是小端）。

## 已解决的局限 [#resolved-limitations]

<Accordions type="multiple">
<Accordion value="resolved-1" title={<><code>ValueTuple</code> 在 .NET Core 与 Unity/Mono 中表现不同</>}>

v4 已解决：`ValueTuple`、`KeyValuePair` 和 `Nullable<T>` 有明确定义、与运行时无关的格式，数据在 .NET Core 与 Unity/Mono/IL2CPP 之间通用。

</Accordion>
<Accordion value="resolved-2" title={<>启用 <code>WEAK_VERSION_TOLERANCE</code> 的项目无法读取未启用该符号的项目的数据，反之亦然</>}>

v4 已解决：版本容错改为每个类型自己的选项（`[NinoType(versionTolerant: true)]`），属于类型自身的格式，不再依赖项目设置。`WEAK_VERSION_TOLERANCE` 仍为兼容而保留，只影响定义了该符号的项目中声明的类型。

</Accordion>
<Accordion value="resolved-3" title={<>成员只能追加在末尾，不能删除或调整顺序</>}>

v4 已解决：`[NinoType(keyed: true)]` 允许在继承体系的任意一个类中调整顺序、删除和插入成员。版本容错的类型仍然只允许追加成员，并且只能追加到最末端的派生类型。

</Accordion>
<Accordion value="resolved-4" title={<>不支持的类型会导致编译错误</>}>

v4 已解决：分析器会在你的代码上报告警告 NINO007（提供代码修复），并跳过该成员。

</Accordion>
<Accordion value="resolved-5" title={<>共享引用和循环引用无法保留</>}>

v4 已通过 `[NinoType(trackReferences: true)]` 解决。

</Accordion>
<Accordion value="resolved-6" title={<>字典子类需要公共索引器</>}>

v4 已解决：派生自 `List<T>`、`Dictionary<TKey, TValue>` 等类型，或实现了集合接口的自定义集合，不需要任何额外代码即可使用。

</Accordion>
<Accordion value="resolved-7" title={<>序列化后无法修改类型名或命名空间</>}>

自 v3.2.2 起，可以用 `[NinoFormerName]` 解决。

</Accordion>
<Accordion value="resolved-8" title={<>无法序列化非公开的字段和属性</>}>

自 v3.0.6 起，可以用 `containNonPublicMembers` 解决。在 .NET 8 及以上，除泛型类型外不需要 `partial`；.NET 8 之前类型必须是 `partial`。

</Accordion>
<Accordion value="resolved-9" title={<>多态的非托管结构体转换为接口后，序列化结果与转换前不同</>}>

自 v3.0.3 起已解决。

</Accordion>
<Accordion value="resolved-10" title={<>嵌套很深的数据会导致栈溢出</>}>

v4 已解决：嵌套超过 128 层的对象会推迟到较浅的层级再写入和读取，所以无论递归类型嵌套多深（以及恶意数据），占用的栈都有上限；未追踪的环会抛出异常，而不是无限递归。参见[深层对象图](/zh/docs/v4/basic#deep-object-graphs)。

</Accordion>
</Accordions>
