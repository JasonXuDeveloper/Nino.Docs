选择 Nino v4 之前需要了解的事：它需要什么、不做什么，以及该改用什么。

## 当前的局限 [#current-limitations]
- **离不开源生成器。** Nino 依赖自己的源生成器（Roslyn 4.3 及以上），声明 `[NinoType]` 的项目需要 C# 9 及以上。
- **不兼容 v3 数据。** v4 无法读取 v3 以及 v4 测试版、预览版写出的数据。参见[从 v3 迁移](/zh/docs/v4/migration#converting-v3-data)。
- **默认按位置存储。** 不带参数的 `[NinoType]` 最快，但成员一改，旧数据就读不了。需要保存或跨版本交换的数据，请在写入之前选好 `NinoFormat.VersionTolerant` 或 `NinoFormat.Keyed`：参见[数据演进](/zh/docs/v4/evolving-data)。
- **只支持连续内存。** Nino 从 `ReadOnlySpan<byte>` 读取，写入 `IBufferWriter<byte>`；没有 `Stream` 或 `ReadOnlySequence<byte>` 重载。参见[多段数据](/zh/docs/v4/basic#multi-segment-data)。
- **部分类型没有内置格式化器。** `System.Type` 是有意不支持的（由数据指定要创建的类型是一种反序列化攻击手段），委托、非泛型集合，以及 Unity 的 `AnimationCurve`、`Gradient`、`RectOffset` 之外的引擎类也没有。参见[支持的类型](/zh/docs/v4/types#not-supported)；用[自定义格式化器](/zh/docs/v4/custom-formatters)可以支持其中任何一种。
- **生成的 TypeScript 覆盖大多数类型，但不是全部。** [Nino.Codegen](/zh/docs/v4/advanced/codegen#not-generated) 会跳过多维数组、`DateTimeOffset` 或自定义格式化器等成员以及包含它们的类型，并给出构建警告（[TypeScript 不支持的内容](/zh/docs/v4/advanced/codegen#not-supported)）。需要它们的浏览器客户端可以在 [.NET WebAssembly](/zh/docs/v4/advanced/browser) 上运行 C# 类型。

## 平台说明 [#platform-notes]

Nino 自己定义字节格式，而不是直接拷贝内存，所以数据可以在 CoreCLR、Mono、IL2CPP 之间，以及 64 位和 32 位平台之间通用。`Nullable<T>`、`ValueTuple`、`decimal`、`DateTimeOffset`、32 位对齐和填充字节的处理方式，参见[平台](/zh/docs/v4/platforms#portable-by-design)。字节序为小端；在大端主机上 Nino 会直接抛出异常，而不是写出字节（目前 .NET 和 Unity 支持的平台都是小端）。

## 已解决的局限 [#resolved-limitations]

v3 的局限中 v4 已经解决的（共享引用、键控成员、深层嵌套、元组布局随运行时不同等），都列在 [v4 新特性](/zh/docs/v4/whats-new#features)的 v3 与 v4 对比表里。
