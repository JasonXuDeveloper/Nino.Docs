Any `class`, `struct`, `record`, `record struct` or `interface` marked `[NinoType]` becomes serializable. The source generator writes its formatter at compile time; there is nothing to register. This page covers which members are written, in what order, and the options that change the format.

```csharp
using Nino.Core;

[NinoType]
public class Order
{
    public long Id;                              // public fields
    public string CustomerName { get; set; }     // public properties with a getter and a setter
    public List<OrderLine> Lines { get; init; }  // init setters work too
    public DateTime? ShippedAt;                  // Nullable<T> of any serializable T
}
```

## `[NinoType]` Options

```csharp
public NinoTypeAttribute(
    bool autoCollect = true,
    bool containNonPublicMembers = false,
    bool allowInheritance = true,
    NinoFormat format = NinoFormat.Positional,
    bool trackReferences = false)
```

`NinoFormat` is an enum in `Nino.Core` with three values: `Positional`, `VersionTolerant` and `Keyed`. Use named arguments for readability: `[NinoType(format: NinoFormat.VersionTolerant)]`. A bare `[NinoType]` gives the fastest and most compact format: [positional](/en/docs/v4/evolving-data#positional) (members in declaration order, with no names or lengths), no per-member overhead.

## Which Members Are Serialized

With the default `autoCollect: true`, Nino collects:

- every **public field**, and every **public property with a getter and a setter** (`set` or `init`);
- the members of `[NinoType]` base classes first (root first), then the type's own members in declaration order; the members of a `[NinoType]` interface come just before those of the first class in the hierarchy that implements it;
- for records, the primary constructor parameters (they are public properties).

And it skips:

- **get-only auto-properties** (`public int Id { get; }`), unless a constructor has a parameter with the same name (ignoring case), since nothing else can restore them. See [Constructors](/en/docs/v4/constructors);
- **explicit interface implementations** (`int IHasId.Id { get; set; }`), which generated code cannot name. A `[NinoType]` interface serializes its members through the implementing type's members of the same name;
- members whose type Nino cannot serialize (delegates, `Task`, pointers...), reported as warning NINO007.

An `override` counts as the member it overrides and is collected once. A member that hides a base member with `new` is a separate member: both are serialized, the base one first. When the hidden base member is not public, generated code can only reach it through `[UnsafeAccessor]` (.NET 8+, non-generic types); otherwise it is skipped with warning NINO022.

### Ignoring a Member

```csharp
[NinoType]
public class Session
{
    public int UserId;
    [NinoIgnore] public DateTime CachedAt; // [!code highlight]
}
```

### Choosing Members Explicitly

With `[NinoType(false)]` (`autoCollect: false`) only members marked `[NinoMember(index)]` are serialized, ordered by `index` ascending:

<Tabs items={["Class", "Record"]}>
<Tab value="Class">

```csharp
[NinoType(false)] // [!code highlight]
public class Invoice
{
    public decimal CachedTotal;                         // not serialized
    [NinoMember(1)] public string Number { get; set; } // [!code highlight]
    [NinoMember(0)] public long CustomerId;            // written first
}
```

</Tab>
<Tab value="Record">

```csharp
[NinoType(false)] // [!code highlight]
public record Shipment(
    [property: NinoMember(2)] string Carrier,         // [!code highlight]
    [property: NinoMember(1)] string TrackingNumber); // [!code highlight]
```

</Tab>
</Tabs>

<Callout type="info">

The analyzer keeps these consistent: `[NinoMember]` is redundant with `autoCollect: true` (NINO010) and `[NinoIgnore]` with `autoCollect: false` (NINO011), a member cannot have both (NINO012), and indices must be unique (NINO013). Each comes with a code fix.

</Callout>

### Private Members

Set `containNonPublicMembers` to serialize non-public members as well:

```csharp
[NinoType(containNonPublicMembers: true)] // [!code highlight]
public partial class Account
{
    private long _balance;
    protected string Owner;
    public int Id;
}
```

- On .NET 8 and later, generated code reaches private members through `[UnsafeAccessor]` (except in generic types).
- Before .NET 8 (including .NET Standard and Unity), and in generic types, it uses an accessor generated **inside** the type, so the type and every type containing it must be `partial` (NINO002, with a code fix).
- A non-public `[NinoMember]` without `containNonPublicMembers` is an error (NINO009).
- Private members of a base class are never part of a subtype.

Nino also suppresses the compiler's "field is never used / never assigned" warnings on the private members it serializes, since the compiler cannot see the generated accessors.

## Member Order

Without `format: NinoFormat.Keyed`, the order of members **is** the format. By default, base-class members come first, then the type's own members in declaration order. To choose another order, use `[NinoType(false)]` and give each member a `[NinoMember(index)]`: members are written by index, ascending, as shown in [Choosing Members Explicitly](#choosing-members-explicitly).

<Callout type="warn">

Reordering, inserting or removing members (or changing their indices) breaks previously written data. Plan for change with [version tolerance or keyed members](/en/docs/v4/evolving-data).

</Callout>

## String Encoding

By default Nino picks the form of each string: one byte a char when every char is at most U+00FF (ASCII and Latin-1: English, identifiers, keys, Western European text), and UTF-16 otherwise. Both are a single pass that narrows, widens or copies the chars, vectorized on .NET 8 and later. Mark a member with `[NinoUtf8]` to write UTF-8 instead. It pays off for text that is mostly ASCII but holds a few chars above U+00FF (curly quotes, emoji, a name in another script), which the default writes entirely as UTF-16, at the cost of transcoding and a 4-byte byte count: chat messages and user names sent to many clients, or large text tables on disk. Keep the default for text that is mostly CJK, which takes 3 bytes per character in UTF-8 instead of 2.

```csharp
[NinoType]
public class ChatMessage
{
    public int SenderId;
    [NinoUtf8] public string Text;                       // [!code highlight]
    [NinoUtf8] public Dictionary<string, string> Tags;   // keys and values are UTF-8 too
}
```

The attribute applies to every string the member's own formatter writes: the member itself, and the `string` elements, keys, values and tuple items of a collection or tuple member (`List<string>`, `string[]`, `Dictionary<string, int>`, `(string, int)`). Strings inside a nested `[NinoType]` keep that type's own encoding, and on a member that holds no strings the attribute does nothing.

Writer and reader must agree: data written as UTF-8 cannot be read by a type that declares the member without `[NinoUtf8]`. A UTF-8 string is written with its length in chars and its length in bytes, so the reader allocates the string at its final size and transcodes exactly its bytes into it in one pass (see [Binary Format](/en/docs/v4/platforms#binary-format)).

## Former Name

A value stored in a member, element or variable declared as a non-sealed class, an abstract class, an interface or `object` is written with the **type id** of its runtime type: a 32-bit hash of that type's full name, so it can be read back as the right type. Renaming the type or moving it to another namespace changes the id, for sealed subtypes too (such as the message classes sent through a `Message` base).

A typical case: you move your protocol classes from `MyApp.Net` to `MyApp.Protocol`, while stored files or clients from the previous release still use the old ids. Keep reading old data with `[NinoFormerName]`:

```csharp
namespace MyApp.Protocol
{
    [NinoType]
    [NinoFormerName("MyApp.Net.OrderPlaced")] // [!code highlight]
    public class OrderPlaced
    {
        public long OrderId;
    }
}
```

The former name is the **runtime form** of the full name: `Namespace.Type`, `+` between a nested type and its container (`Namespace.Outer+Inner`), no `global::`. The type id is computed from the former name, so the renamed type keeps writing and reading the id that existing data and older readers use. `NinoTypeId.Of(typeof(T))` returns the id a type writes. A type takes a single `[NinoFormerName]`, since its id comes from one name; a second one is error NINO026.

On a field or property of a `NinoFormat.Keyed` type, `[NinoFormerName("OldName")]` (repeatable) keeps reading data written under the member's old names; see [Renaming Keyed Members](/en/docs/v4/evolving-data#renaming-keyed-members). Positional and version-tolerant types write no member names, so renaming a member needs nothing there.

## Structs

A `[NinoType]` struct has no header at all. It is written as its **raw memory** (one copy per value, one block per array or list) when it:

- is unmanaged and has sequential layout (the default, with or without `Pack` and `Size`; `LayoutKind.Explicit` and `LayoutKind.Auto` structs are not raw);
- is neither `NinoFormat.VersionTolerant` nor `NinoFormat.Keyed`, and has no custom member formatters;
- serializes every instance field, and each field is itself written as raw bytes (not a `Nullable<T>`, tuple, `nint`, `DateTimeOffset` or non-raw `[NinoType]` struct).

Otherwise it is written member by member. Either way, a positional struct (neither version-tolerant nor keyed) whose members are all raw values or such structs is [fixed-size](/en/docs/v4/performance#fixed-size-types): `NinoSerializer.Serialize(value)` writes it straight into a `byte[]` of its size.

```csharp
[NinoType]
public struct SensorReading // raw: one 16-byte copy, no padding
{
    public int SensorId;
    public float Value;
    public long Timestamp;
}
```

A struct that ends up serializing no members at all (every field ignored) is an error (NINO023): it would be written as zero bytes, and a collection of it could not be read back. Serialize at least one member, or give the struct `format: NinoFormat.VersionTolerant` or `format: NinoFormat.Keyed`.

<Callout type="warn">

A raw struct is written in its canonical field order: reordering its fields or changing its `StructLayout` breaks existing data. Give it `format: NinoFormat.VersionTolerant` (or `[NinoIgnore]` a field) to opt out of raw copying. See [Platforms and Binary Format](/en/docs/v4/platforms).

</Callout>

## Records

Positional records are created through their primary constructor; their parameters are the serialized properties. Records with a body work like classes.

```csharp
[NinoType]
public record Price(decimal Amount, string Currency);

[NinoType]
public record struct DateRange(DateTime Start, DateTime End);
```

Because their properties are `init`-only, positional records are re-created on every deserialization, even into an existing instance, and cannot use [`trackReferences`](/en/docs/v4/reference-tracking) or [`[NinoPooled]`](/en/docs/v4/pooling). Use a record with settable properties when you need those. See [Constructors](/en/docs/v4/constructors) for how instances are created.

## Generic Types

```csharp
[NinoType]
public class Box<T>
{
    public T Value;
}

[NinoType]
public record struct Pair<TKey, TValue>(TKey Key, TValue Value);
```

A generic `[NinoType]` gets one formatter per definition, not one per closed type. Type arguments must be serializable (`Box<int>`, `Box<List<string>>`, `Box<Order>`). The generator registers every closed type the compilation names (member types, base types, type arguments of `NinoSerializer`/`NinoDeserializer` calls), so AOT platforms have the instantiations they need; the runtime closes the rest on first use.

<Callout type="warn">

A closed generic type that a process only **reads** polymorphically (by type id) and never names or writes must be registered at startup: `NinoPolymorphic.Register<Box<int>>()`. This only matters for instantiations created by reflection or in another assembly.

</Callout>

## Inheritance

Subtypes inherit `[NinoType]`, with its options, from their nearest `[NinoType]` base class or interface; put `[NinoType]` on a subtype to give it options of its own. A subtype's own `[NinoType]` replaces the inherited options, so repeat the ones you want to keep: `[NinoType(format: NinoFormat.VersionTolerant)]` on a subtype of a version-tolerant base. The one exception is `trackReferences`: a class is tracked when it or any `[NinoType]` base class or interface asks for it, whatever its own attribute says, so a tracked hierarchy stays tracked. See [Polymorphism](/en/docs/v4/polymorphism).
