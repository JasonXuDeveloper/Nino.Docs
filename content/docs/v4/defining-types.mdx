Any `class`, `struct`, `record`, `record struct` or `interface` marked `[NinoType]` becomes serializable. The source generator writes its formatter at compile time; there is nothing to register. This page covers which members are written, in what order, and the options that change the format.

```csharp
using Nino.Core;

[NinoType]
public class Player
{
    public int Id;                       // public fields
    public string Name { get; set; }     // public properties with a getter and a setter
    public List<Item> Inventory { get; init; } // init setters work too
    public Vector3? LastCheckpoint;      // Nullable<T> of any serializable T
}
```

A `[NinoType]` and every type containing it must be `public` or `internal` (`protected internal` also works), and it cannot be a `static` class or a `ref struct` (NINO001, with a code fix).

## `[NinoType]` Options

```csharp
public NinoTypeAttribute(
    bool autoCollect = true,
    bool containNonPublicMembers = false,
    bool allowInheritance = true,
    bool versionTolerant = false,
    bool keyed = false,
    bool trackReferences = false)
```

Use named arguments for readability: `[NinoType(versionTolerant: true)]`. A bare `[NinoType]` gives the fastest and most compact format: positional, no per-member overhead.

## Which Members Are Serialized

With the default `autoCollect: true`, Nino collects:

- every **public field**, and every **public property with a getter and a setter** (`set` or `init`);
- the members of `[NinoType]` base classes first, then the type's own members in declaration order;
- for records, the primary constructor parameters (they are public properties).

And it skips:

- **get-only auto-properties** (`public int Id { get; }`), unless a constructor takes them as a parameter of the same name (ignoring case), since nothing else could restore them. See [Constructors](/en/docs/v4/constructors);
- **explicit interface implementations** (`int IHasId.Id { get; set; }`), which generated code cannot name. A `[NinoType]` interface serializes its members through the implementing type's members of the same name;
- members whose type Nino cannot serialize (delegates, `Task`, pointers...), reported as warning NINO007.

An `override` is the member it overrides, collected once. A member that hides a base member with `new` is a separate member: both are serialized, the base one first. When the hidden base member is not public, generated code can only reach it through `[UnsafeAccessor]` (.NET 8+, non-generic types); otherwise it is skipped with warning NINO022.

### Ignoring a Member

```csharp
[NinoType]
public class Session
{
    public int UserId;
    [NinoIgnore] public DateTime CachedAt; // [!code highlight]
}
```

### Choosing Members Explicitly

With `[NinoType(false)]` (`autoCollect: false`) only members marked `[NinoMember(index)]` are serialized, ordered by `index` ascending:

<Tabs items={["Class", "Record"]}>
<Tab value="Class">

```csharp
[NinoType(false)] // [!code highlight]
public class SampleClass
{
    public int Id;                       // not serialized
    [NinoMember(1)] public string Name { get; set; } // [!code highlight]
    [NinoMember(0)] public int Level;    // written first
}
```

</Tab>
<Tab value="Record">

```csharp
[NinoType(false)] // [!code highlight]
public record SampleRecord(
    [property: NinoMember(2)] int Id, // [!code highlight]
    [property: NinoMember(1)] string Name); // [!code highlight]
```

</Tab>
</Tabs>

<Callout type="info">

The analyzer keeps these consistent: `[NinoMember]` is redundant with `autoCollect: true` (NINO010) and `[NinoIgnore]` with `autoCollect: false` (NINO011), a member cannot have both (NINO012), and indices must be unique (NINO013). Each comes with a code fix.

</Callout>

### Private Members

Set `containNonPublicMembers` to serialize non-public members as well:

```csharp
[NinoType(containNonPublicMembers: true)] // [!code highlight]
public partial class Account
{
    private long _balance;
    protected string Owner;
    public int Id;
}
```

- On .NET 8 and later, generated code reaches private members through `[UnsafeAccessor]` (except in generic types).
- Before .NET 8 (including .NET Standard and Unity), and in generic types, it uses an accessor generated **inside** the type, so the type and every type containing it must be `partial` (NINO002, with a code fix).
- A non-public `[NinoMember]` without `containNonPublicMembers` is an error (NINO009).
- Private members of a base class are never part of a subtype.

Nino also suppresses the compiler's "field is never used / never assigned" warnings for private members it serializes, since the compiler cannot see the generated accessors.

## Member Order

Without `keyed: true`, the order of members **is** the format. Members are written base-class members first, then in declaration order, unless you change it:

- `[NinoMember(index)]` with `[NinoType(false)]`: by index, ascending.
- `[NinoExplicitOrder(...)]` on a class, struct or interface: the listed members (by name) first, in the given order; the others follow in declaration order.

```csharp
[NinoType]
[NinoExplicitOrder(nameof(Name), nameof(Id))] // [!code highlight]
public class Ordered
{
    public int Id;
    public string Name;
    public bool Flag;   // written after Name and Id
}
```

<Callout type="warn">

Reordering, inserting or removing members (or changing their indices) breaks data written before. Plan for change with [version tolerance or keyed members](/en/docs/v4/evolving-data).

</Callout>

## String Encoding

Strings are written as UTF-16 by default: a length and one block copy, the fastest option. Mark a member with `[NinoUtf8]` to write UTF-8 instead, which halves the size of mostly-ASCII text at the cost of transcoding (vectorized by the runtime). Use it where bytes cost more than CPU: chat and player names sent to many clients, or large text tables on disk. Keep UTF-16 for text that is mostly CJK, which takes 3 bytes per character in UTF-8 instead of 2.

```csharp
[NinoType]
public class ChatMessage
{
    public int SenderId;
    [NinoUtf8] public string Text;                       // [!code highlight]
    [NinoUtf8] public Dictionary<string, string> Tags;   // keys and values are UTF-8 too
}
```

The attribute applies to every string the member's own formatter writes: the member itself, and the `string` elements, keys, values and tuple items of a collection or tuple member (`List<string>`, `string[]`, `Dictionary<string, int>`, `(string, int)`). Strings inside a nested `[NinoType]` keep that type's own encoding, and on a member that holds no strings the attribute does nothing. Writer and reader must agree: data written as UTF-8 cannot be read by a type that declares the member without `[NinoUtf8]`. Both encodings write the length in chars, not in bytes, so a UTF-8 string is decoded in one pass into a string allocated at its final size (see [Binary Format](/en/docs/v4/platforms#binary-format)).

## Former Name

A value stored in a slot declared as a non-sealed class, an abstract class, an interface or `object` is written with the **type id** of its runtime type, a 32-bit hash of that type's full name, so it can be read back as the right type. Renaming the type or moving it to another namespace changes the id, and that includes sealed subtypes such as the message classes sent through a `Message` base. A typical case: you move your protocol classes from `Game.Net` to `Game.Protocol`, while save files or clients from the previous release still use the old ids. Keep reading old data with `[NinoFormerName]`:

```csharp
[NinoType]
[NinoFormerName("Old.Namespace.Outer+Item")] // [!code highlight]
public class ItemRenamed
{
    public int Id;
}
```

The former name is the **runtime form** of the full name: `Namespace.Type`, `+` between a nested type and its container (`Namespace.Outer+Inner`), no `global::`. The type id is computed from the former name, so the renamed type keeps writing the id old readers expect, and readers find the type under both names. `NinoTypeId.Of(typeof(T))` returns the id a type writes.

On a field or property of a `keyed` type, `[NinoFormerName("OldName")]` (repeatable) keeps reading data written under the member's old names; see [Renaming Keyed Members](/en/docs/v4/evolving-data#renaming-keyed-members). Positional and version-tolerant types write no member names, so they need nothing to rename a member.

## Structs

A `[NinoType]` struct has no header at all. When it is unmanaged, not `versionTolerant` or `keyed`, uses the default sequential layout, has no custom member formatters and every instance field is serialized, it is written as its **raw memory**: one copy, and arrays and lists of it as one block. Otherwise it is written member by member.

```csharp
[NinoType]
public struct Hit          // raw: one 16-byte copy, no padding
{
    public int TargetId;
    public float Damage;
    public long Tick;
}
```

A struct that ends up serializing no member at all (every field ignored) is an error (NINO023): it would be written as zero bytes, and a collection of it could not be read back. Serialize a member, or mark it `versionTolerant` or `keyed`.

<Callout type="warn">

A raw struct is written in its canonical field order: reordering its fields or changing its `StructLayout` breaks existing data. Mark it `versionTolerant` (or `[NinoIgnore]` a field) to opt out of raw copying. See [Platforms and Binary Format](/en/docs/v4/platforms).

</Callout>

## Records

Positional records are created through their primary constructor; their parameters are the serialized properties. Records with a body work like classes.

```csharp
[NinoType]
public record Point(int X, int Y);

[NinoType]
public record struct Range(int Start, int Length);
```

Because their properties are `init`-only, positional records are re-created on every deserialization, even into an existing instance, and cannot use [`trackReferences`](/en/docs/v4/reference-tracking) or [`[NinoPooled]`](/en/docs/v4/pooling). Use a record with settable properties when you need those. See [Constructors](/en/docs/v4/constructors) for how instances are created.

## Generic Types

```csharp
[NinoType]
public class Box<T>
{
    public T Value;
}

[NinoType]
public record struct Pair<TKey, TValue>(TKey Key, TValue Value);
```

A generic `[NinoType]` gets one formatter per definition, not one per closed type. Type arguments must be serializable (`Box<int>`, `Box<List<string>>`, `Box<Player>`). The generator registers every closed type the compilation names (member types, base types, type arguments of `NinoSerializer`/`NinoDeserializer` calls), so AOT platforms have the instantiations they need; the runtime closes the rest on first use.

<Callout type="warn">

A closed generic type that a process only **reads** polymorphically (by type id) and never names or writes must be registered at startup: `NinoPolymorphic.Register<Box<int>>()`. This only matters for instantiations created by reflection or in another assembly.

</Callout>

## Inheritance

Subtypes inherit `[NinoType]`, with its options, from their nearest `[NinoType]` base class or interface; put `[NinoType]` on a subtype to give it options of its own. A subtype's own `[NinoType]` replaces the inherited options, so repeat the ones you want to keep: `[NinoType(versionTolerant: true)]` on a subtype of a version-tolerant base. The one exception is `trackReferences`: a class is tracked when it or any `[NinoType]` base class or interface asks for it, whatever its own attribute says, so a tracked hierarchy stays tracked. See [Polymorphism](/en/docs/v4/polymorphism).
