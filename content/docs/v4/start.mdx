Install Nino, mark a type with `[NinoType]` and serialize it. There is nothing to register and nothing to initialize.

## Installation

<AnchorRedirect map={{ 'installation-details': '/en/docs/v4/start#installation' }} />

<Tabs groupId="platform" persist items={['.NET', 'Unity', 'Godot']}>
<Tab value=".NET" id="net-project" forceMount>

Requirements:

- **Runtime**: any project that can use a .NET Standard 2.0 library. `Nino.Core` targets `netstandard2.0`, `netstandard2.1`, `net8.0` and `net10.0`, and all targets write identical bytes.
- **Compiler**: Roslyn 4.3 or later for the source generator (Visual Studio 2022 17.3+, Rider, or the .NET 6.0.400 SDK and later).
- **Language version**: C# 9 or later, which generated code uses. Older .NET Framework projects default to C# 7.3 and need `<LangVersion>9</LangVersion>` or later.

<Steps>
<Step>

**Add the package.** In Visual Studio or Rider, tick **Include prerelease** in the NuGet package manager, search for `Nino` and install it. Or:

```shell tab="dotnet CLI"
dotnet add package Nino --prerelease
```

```xml tab=".csproj"
<ItemGroup>
  <PackageReference Include="Nino" Version="%NINO_VERSION%" />
</ItemGroup>
```

<Callout type="info">

Nino v4 is still a prerelease, so `--prerelease` (or **Include prerelease**) is required: without it NuGet installs the latest stable 3.9.x, a test build of v4 features that cannot read or write v4 data.

</Callout>

</Step>
<Step>

**Build.** `Nino` brings in the runtime library (`Nino.Serialization`, which is `Nino.Core.dll`) and the source generator with its analyzers and code fixes (`Nino.Generator`); both are required. On the .NET 8 SDK and later, calls whose type is known at compile time go straight to the generated code ([interceptors](/en/docs/v4/performance#interceptors)), with the same bytes.

</Step>
<Step>

**Serialize a type**: [First Serialization](#first-serialization), below.

</Step>
</Steps>

<Tab value="Unity" id="unity-project" forceMount>

Requirements: Unity 2022.3 or later, on every player platform (Mono and IL2CPP).

<Steps>
<Step>

**Add the package from [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/#modal-manualinstallation)**, with the openupm CLI, or by merging its scoped registry and the package into `Packages/manifest.json`:

```shell tab="openupm CLI"
# in your Unity project's folder (openupm-cli: npm install -g openupm-cli)
openupm add com.jasonxudeveloper.nino
```

```json tab="Packages/manifest.json"
{
  "scopedRegistries": [
    {
      "name": "package.openupm.com",
      "url": "https://package.openupm.com",
      "scopes": ["com.jasonxudeveloper.nino"]
    }
  ],
  "dependencies": {
    "com.jasonxudeveloper.nino": "%NINO_OPENUPM_VERSION%"
  }
}
```

In Unity, %NINO_VERSION% is %NINO_OPENUPM_VERSION% ([OpenUPM versions](#openupm-versions), below).

</Step>
<Step>

**Let Unity import it.** The package ships `Nino.Core.dll` together with the source generator (`Nino.Generator.dll`, labelled as a `RoslynAnalyzer`) and `Nino.UnityTypes.dll`, the formatters for [Unity's `AnimationCurve`, `Gradient` and `RectOffset`](/en/docs/v4/advanced/unity#unity-classes), so nothing else has to be installed. This is the generator's Roslyn 4.3 build, which matches the oldest compiler Unity supports, so calls are not [intercepted](/en/docs/v4/performance#interceptors) in Unity. They take the regular path and write the same bytes.

</Step>
<Step>

**Serialize a type**: [First Serialization](#first-serialization), below. Unity compiles against .NET Standard, which has no `[UnsafeAccessor]`, so a type that serializes non-public members (or uses `[NinoPooled]`) must be declared `partial`, and so must every type that contains it. The analyzer reports this (NINO002), and its code fix adds `partial` in Rider or Visual Studio.

</Step>
</Steps>

<Accordion title="OpenUPM versions" id="openupm-versions" value="openupm-versions">

OpenUPM cannot order prerelease labels, so each release candidate is published to it as `4.0.0-preview.(200 + N)`: rc.N on NuGet and in these docs is preview.(200 + N) in the Unity Package Manager. rc.10, for example, is preview.210.

OpenUPM's alpha and beta previews below preview.200 are older v4 test builds; use an rc.

</Accordion>

If you use `asmdef` files, make sure `Auto Referenced` is enabled. If `Override References` is on, add a reference to `Nino.Core.dll` explicitly.

</Accordion>
<Accordion title="Hot-update code (HybridCLR)" id="hot-update-code" value="hot-update-code">

- Nino supports **HybridCLR**. Generated registries are found lazily the first time one of their types is used, so a hot-update assembly loaded with `Assembly.Load` needs **no initialization call**. See [Unity and HybridCLR](/en/docs/v4/advanced/unity#hybridclr-hot-update).
- Hot-update code can live in a Unity `asmdef`, or in an external C# project that installs Nino from NuGet ([.NET](#net-project)); use the compiled DLL in HybridCLR as usual.

</Accordion>

The `Nino.Unity` sample project on GitHub shows Nino in a Unity project, with unit tests you can run in the Test Runner. If something does not work, check that the sample project runs first; if the problem persists, open an issue on GitHub.

## First Serialization

At compile time, the source generator writes a **formatter** for every `[NinoType]`: the code that writes and reads that type. `NinoSerializer` and `NinoDeserializer` (namespace `Nino.Core`) are the only API you call:

<Steps>
<Step>

### Mark a type with `[NinoType]`

```csharp title="UserProfile.cs"
using System;
using Nino.Core;

[NinoType]
public class UserProfile
{
    public long Id;
    public string Name;
    public DateTime LastLogin;
}
```

Put the type in a file of its own. In a console app's `Program.cs`, it can also go after the top-level statements, never before them (CS8803).

</Step>
<Step>

### Serialize it

```csharp title="Program.cs"
using System;
using Nino.Core;

var data = new UserProfile { Id = 42, Name = "Ada", LastLogin = DateTime.UtcNow };
byte[] bytes = NinoSerializer.Serialize(data);
```

This allocates the returned array. On a hot path, serialize into a buffer you keep instead, and nothing is allocated: see [Reusing a Buffer](/en/docs/v4/basic#reusing-a-buffer).

</Step>
<Step>

### Deserialize it

```csharp
UserProfile restored = NinoDeserializer.Deserialize<UserProfile>(bytes);
Console.WriteLine($"{restored.Id} {restored.Name}"); // 42 Ada
```

The data is a `ReadOnlySpan<byte>`, so a slice of a pooled array or a network buffer works too, without copying.

</Step>
<Step>

### Or deserialize into an object you already have

Pass an existing instance by `ref` and Nino fills it in place, reusing its nested objects and collections. Pass `null` and a new one is created:

```csharp
byte[] newBytes = NinoSerializer.Serialize(new UserProfile { Id = 42, Name = "Ada Lovelace" });

UserProfile current = null;
NinoDeserializer.Deserialize(bytes, ref current);    // creates the instance
NinoDeserializer.Deserialize(newBytes, ref current); // fills the same instance
```

</Step>
</Steps>

<Callout type="info">

The examples on the following pages assume `using Nino.Core;` (or one `global using Nino.Core;` in your project) and leave out nullable annotations. New .NET projects enable nullable reference types, so copied code shows warnings such as CS8618 and CS8600: declare `string? Name` or `UserProfile? current = null` where you want them gone. Nino writes and reads the same bytes either way.

</Callout>

## At Startup

Nino needs no initialization call: generated code registers itself, and assemblies loaded later are found on first use. Three calls are optional:

- `NinoSettings` (pool sizes, recyclers, the [limits for untrusted data](/en/docs/v4/security#limits)), set before the first serialization call. [Settings](/en/docs/v4/settings) lists them all.
- `NinoPolymorphic.TryRegister<T>()`, for a closed generic `[NinoType]` that the process only reads through a base type and never names in code.
- `NinoRegistry.EnsureInitialized(assembly)`, to load a plugin's registry now instead of on first use.

Custom formatters need no call either: they are declared with attributes ([Custom Formatters](/en/docs/v4/custom-formatters)). For Unity and HybridCLR projects, see the [startup checklist](/en/docs/v4/advanced/unity#startup-checklist).
