---
title: Reference Tracking
description: Preserve shared references and cycles.
icon: Share2
---

By default, an object referenced twice is written twice and read back as two instances, and serializing a cycle throws an `InvalidOperationException` (see [Deep Object Graphs](/en/docs/v4/basic#deep-object-graphs)). Set `trackReferences: true` on a class to preserve the object graph. Every subtype is tracked too, even one that declares its own `[NinoType]` without the option:

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // may point back to an earlier node
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // a cycle
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

Shared references matter as much as cycles. In an RPG save, two party members belong to the same guild:

```csharp
[NinoType(trackReferences: true)]
public class Guild { public string Name; }

[NinoType]
public class Hero { public string Name; public Guild Guild; }

var guild = new Guild { Name = "Dawn" };
var party = new List<Hero> { new() { Name = "Ayla", Guild = guild }, new() { Name = "Bran", Guild = guild } };
var loaded = NinoDeserializer.Deserialize<List<Hero>>(NinoSerializer.Serialize(party));
// loaded[0].Guild == loaded[1].Guild: renaming the guild after loading changes it for both heroes
```

Without tracking, the save would load two separate `Guild` objects, and a rename after loading would show on one hero only. Only the shared type needs the option: `Hero` itself is not tracked.

- Each tracked object is written after a 4-byte reference header; an object already written in the same call is written as just its index.
- Shared references keep their identity across members of any declared type, including `object` and interfaces.
- Tracking covers `[NinoType]` classes, not collections: the same `List<T>` in two members is still written twice.
- Cost: a small fixed cost per top-level call, plus 4 bytes and one identity lookup per tracked object. Calls without tracked objects pay nothing.

<Callout type="warn">

Types that must be re-created from constructor arguments or read-only members (for example positional records) cannot be tracked (NINO016). `trackReferences` on a struct is ignored with a warning (NINO015).

</Callout>

## When to Use It

<Accordions type="single">
<Accordion title="Use it for object graphs">

Scene graphs, entity relationships, editors' undo stacks, save games where several objects point to the same one, trees with parent links: anything where identity matters or cycles exist. A list that repeats one tracked object 100 times takes a fraction of the bytes and time of the same list untracked.

</Accordion>
<Accordion title="Skip it for messages and plain data">

Network messages, configuration and other tree-shaped data have no shared references. Leave tracking off there: untracked types pay nothing, not even the 4-byte header.

</Accordion>
<Accordion title="Writing and reading several values yourself">

The top-level `NinoSerializer`/`NinoDeserializer` calls scope the reference table to one call. When you create a `Writer` or `Reader` yourself, references are shared across everything written through it until you call `ReleaseReferences()`. Call it at the end of each logical message.

</Accordion>
</Accordions>

Reuse deserialization works as usual for new objects; a back reference replaces the current value without recycling it, since the old value may still be referenced elsewhere in the graph.
