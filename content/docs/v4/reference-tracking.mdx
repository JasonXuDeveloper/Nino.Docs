title: Reference Tracking
description: "Serialize object graphs with shared references and cycles: opt in per type; types that don't opt in pay nothing. Graphs of any depth keep the stack bounded."
icon: Share2
---

By default, Nino writes an object graph as a tree. An object referenced twice is written twice and read back as two instances. A cycle (`a.Next = b; b.Next = a;`) is detected while serializing and throws an `InvalidOperationException` that names the type and points to `trackReferences`, so it never loops forever. Deep trees need nothing: see [Deep Object Graphs](#deep-object-graphs).

## When to Use It [#when-to-use-it]

<Callout type="idea" title="Use it for object graphs">

Domain models with relationships (orders pointing at a shared customer), undo stacks, documents where several objects point to the same one, trees with parent links: anything where identity matters or cycles exist. A list that repeats one tracked object 100 times takes a fraction of the bytes and time of the same list untracked.

</Callout>

<Callout type="warn" title="Skip it for messages and plain data">

Network messages, configuration and other tree-shaped data have no shared references, however deep they nest. Leave tracking off there: untracked types pay nothing, not even the 4-byte header.

</Callout>

## How to Use It [#how-to-use-it]

Set `trackReferences: true` on a class to preserve the object graph. Every subtype is tracked too, even one that declares its own `[NinoType]` without the option:

```csharp
[NinoType(trackReferences: true)] // [!code highlight]
public class Node
{
    public int Value;
    public Node Next;    // may point back to an earlier node
}

var a = new Node { Value = 1 };
var b = new Node { Value = 2, Next = a };
a.Next = b;                                   // a cycle
var bytes = NinoSerializer.Serialize(a);
var copy = NinoDeserializer.Deserialize<Node>(bytes);
// copy.Next.Next == copy
```

Shared references matter as much as cycles. In an organization chart, two employees belong to the same department:

```csharp
[NinoType(trackReferences: true)]
public class Department { public string Name; }

[NinoType]
public class Employee { public string Name; public Department Department; }

var sales = new Department { Name = "Sales" };
var staff = new List<Employee>
{
    new() { Name = "Ana", Department = sales },
    new() { Name = "Ben", Department = sales },
};
byte[] bytes = NinoSerializer.Serialize(staff);
var loaded = NinoDeserializer.Deserialize<List<Employee>>(bytes);
// loaded[0].Department == loaded[1].Department: one object, so a rename shows on both employees // [!code highlight]
```

Without tracking, the chart would load two separate `Department` objects, and a rename after loading would show on one employee only. Only the shared type needs the option: `Employee` itself is not tracked.

- Each tracked object is written after a 4-byte reference header; an object already written in the same call is written as just its index.
- Shared references keep their identity across members of any declared type, including `object` and interfaces.
- Tracking covers `[NinoType]` classes, not collections: the same `List<T>` in two members is still written twice.
- Cost: a small fixed cost per `NinoSerializer`/`NinoDeserializer` call you make (a <Term id="top-level-call">top-level call</Term>), plus 4 bytes and one identity lookup per tracked object. Calls without tracked objects pay nothing.
- Reuse deserialization works as usual for new objects; a back reference replaces the current value without recycling it, since the old value may still be referenced elsewhere in the graph.

One `Node { V = 5 }` held twice by a sealed `Holder` (an `object` member, then a `Node` member), bytes from the [specification](https://github.com/JasonXuDeveloper/Nino/blob/main/docs/spec/wire-format.md#a5-reference-tracking):

<Callout type="warn">

Types that must be re-created from constructor arguments or read-only members (for example positional records) cannot be tracked (NINO016). `trackReferences` on a struct is ignored with a warning (NINO015).

</Callout>

### Several Values with Your Own Writer [#own-writer]

A call that takes your value and returns bytes (or writes into a buffer writer or a stream), and a call that reads one value, keep the reference table to that one call. When you create a `Writer` or `Reader` yourself, references are shared across everything written through it until you call `ReleaseReferences()`: call it at the end of each logical message, and read values written through one writer with one reader ([Several Values Back to Back](/en/docs/v4/advanced/high-performance#several-values-back-to-back)).

## Deep Object Graphs [#deep-object-graphs]

Recursive types (a linked list, a tree, a node that holds another node) can nest to any depth, with or without `trackReferences`. Nino writes the first 128 levels of nested objects in place; an object nested deeper is a <Term id="deferred-object">deferred object</Term>: written later from a shallower level, and read back the same way. As a result:

- Writing and reading use a bounded amount of stack, however deep the graph is: a 100,000-node linked list round-trips on a 512 KB thread stack.
- Data cannot be crafted to overflow the reader's stack, so recursive types are safe in messages from untrusted sources.
- Data nested less than 128 levels deep is not affected: its bytes do not change.

```csharp
[NinoType]
public class TreeNode
{
    public int Value;
    public List<TreeNode> Children;
}

// As deep as you like: no StackOverflowException on either side.
byte[] bytes = NinoSerializer.Serialize(deepTree);
var copy = NinoDeserializer.Deserialize<TreeNode>(bytes);
```

A recursive type like `TreeNode` needs no `trackReferences` as long as the data is a tree, where each node is referenced once; a node that appears twice, or a cycle, needs it.

A deferred object is created and stored in its member or collection element as soon as Nino reaches that member, and its members are read later in the same call, so reuse deserialization and `[NinoPooled]` still reuse every instance. Two kinds of classes cannot be deferred like that and are always nested in place:

- classes created by their **constructor** (positional records, init-only or read-only members), since there is no instance until their members are read;
- classes **compared by value** (records, classes that override `GetHashCode` or implement `IComparable`), since a `HashSet<T>`, dictionary key or sorted collection could hold one before its members are read.

A graph of such classes nested deeper than [`NinoSettings.MaxDepth`](/en/docs/v4/settings#limits) (512 levels by default) throws, counting the open bodies of structs that hold themselves around them too, on both sides: an `InvalidOperationException` when it is serialized, a `NinoDataException` when such data is read. Give a deeply recursive type a parameterless constructor and settable members.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| A cycle among types without `trackReferences` | Serializing throws `InvalidOperationException`, naming the type | the serializer |
| An object shared by two members, its type not tracked | It is read back as two objects, and a change to one does not show on the other | nothing: set `trackReferences: true` on the shared type |
| `trackReferences` on a type re-created through its constructor (a positional record, init-only or read-only members) | The build fails | NINO016 |
| `trackReferences` on a struct | Ignored | NINO015 (warning) |
| The same collection in two members | Written twice and read back as two collections | nothing: hold it in a tracked `[NinoType]` class |
| Several messages through one `Writer` with no `ReleaseReferences()` between them | A later message refers back to objects of an earlier one, so it cannot be read on its own | nothing: call it at the end of each message ([above](#own-writer)) |
| Constructor-created or value-compared classes nested deeper than `MaxDepth` | `InvalidOperationException` when serializing, `NinoDataException` when reading | the serializer and the reader |
