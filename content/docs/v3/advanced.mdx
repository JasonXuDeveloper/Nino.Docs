This page covers renaming serialized types, string encoding, which changes keep old data readable, and custom constructors.

## Former Name [#former-name]

Since v3.2.2, a type can be renamed, or moved to another namespace, and still read data serialized under its old name. Before v3.2.2, renaming a type or its namespace made old data fail to deserialize.

Add `[NinoFormerName]` to the renamed type, with its old full name (namespace included).

<Callout type="info" title="Where to find the old name">

Copy the old name from the previous version of the generated `NinoTypeConst.g.cs`. For a generic type, give the old name and namespace only, without the type arguments.

```csharp title="NinoTypeConst.g.cs"
// <auto-generated/>

using System;

namespace Nino.UnitTests.NinoGen
{
    public static class NinoTypeConst
    {
        ...
        // global::Nino.UnitTests.Generic<int> // [!code highlight]
        public const int Nino_UnitTests_Generic_int_ = -388704858;
        // global::Nino.UnitTests.Generic<string> // [!code highlight]
        public const int Nino_UnitTests_Generic_string_ = -1996567692;
        // global::ListElementClass2Renamed // [!code highlight]
        public const int ListElementClass2Renamed = 329143115;
        ...
```

</Callout>

### Example [#former-name-example]

```csharp
[NinoType]
[NinoFormerName("global::Nino.UnitTests.Generic")] // [!code highlight]
public class Generic<T> // [!code --]
public class GenericRenamed<T> // [!code ++]
{
    ...
}

[NinoType]
[NinoFormerName("global::ListElementClass2")] // [!code highlight]
public class ListElementClass2 // [!code --]
public class ListElementClass2Renamed // [!code ++]
{
    ...
}
```

## String Encoding [#string-encoding]

By default, Nino writes the string members of a `[NinoType]` as UTF-16. Mark a member `[NinoUtf8]` to write it as UTF-8 instead, which halves the size of its serialized data.

<Callout type="warn">

UTF-8 makes serializing and deserializing those members about 5% to 10% slower.

</Callout>

<Callout type="info">

On a member that is not a string, `[NinoUtf8]` is ignored.

</Callout>

### Example [#string-encoding-example]

```csharp
[NinoType]
public class StringData
{
    [NinoUtf8] public string Str; // [!code highlight]
    [NinoUtf8] public bool ShouldHaveNoEffect;
}
```

## Version Compatibility [#version-compatibility]

Which changes to a serialized type keep existing data readable:

| Change | Allowed? |
| --- | --- |
| **Rename** a serialized field or property (keep the member order, or the `id` in `[NinoMember]`, the same) | Yes |
| **Change the type** of a member (an **unmanaged** struct) to an **unmanaged** struct of the same memory size (`int` → `uint`, `int` → `float`, `List<long>` → `List<double>`, `List<int[]>` → `List<float[]>`) | Yes |
| **Change the type** of a member to its **base or derived type** | Yes |
| **Add** members at the **end** of the type | Only with `WEAK_VERSION_TOLERANCE` defined |
| **Delete** a serialized field or property | No |

To add members at the end: with automatic collection (`[NinoType]`), declare the new members after the last existing member; with `[NinoType(false)]` and `[NinoMember(id)]`, give them an `id` that sorts after the existing members (Nino orders members by `id`, ascending). Define the symbol `WEAK_VERSION_TOLERANCE` in the project to enable this.

<Callout type="warn">

A project that defines `WEAK_VERSION_TOLERANCE` cannot deserialize data serialized by a project that does not define it, and vice versa.

</Callout>

### Examples [#version-compatibility-examples]

Valid changes:

<Tabs items={["Unmanaged, same size", "Derived → base", "Base → derived"]}>
<Tab value="Unmanaged, same size">

```csharp
[NinoType]
public class SampleClass
{
    // float and int have the same size, so List<float> can become List<int>
    public List<float> Data; // [!code --]
    public List<int> Data; // [!code ++]
}
```

</Tab>
<Tab value="Derived → base">

```csharp
[NinoType]
public interface IBase
{
}
[NinoType]
public class Derived : IBase;
[NinoType]
public class SampleClass2
{
    public Derived Data; // [!code --]
    public IBase Data; // [!code ++]
}
```

</Tab>
<Tab value="Base → derived">

```csharp
[NinoType]
public interface IBase
{
}
[NinoType]
public class Derived : IBase;
[NinoType]
public struct DerivedStruct : IBase;
[NinoType]
public class SampleClass2
{
    public IBase Data; // [!code --]
    // if Data holds a DerivedStruct
    public DerivedStruct Data; // [!code ++]
    // if Data holds a Derived
    public Derived Data; // [!code ++]
}
```

</Tab>
</Tabs>

Invalid changes:

<Tabs items={["Unrelated type", "Wrong derived type", "Unmanaged, different size"]}>
<Tab value="Unrelated type">

```csharp
[NinoType]
public class SampleClass2
{
    public SampleClass Data; // [!code --]
    // SampleClass2 is neither a base nor a derived type of SampleClass
    public SampleClass2 Data; // [!code highlight]
}
```

</Tab>
<Tab value="Wrong derived type">

```csharp
[NinoType]

{
}
[NinoType]
public class Derived : IBase;
[NinoType]
public struct DerivedStruct : IBase;
[NinoType]
public class SampleClass2
{
    public IBase Data; // [!code --]
    // if Data holds a DerivedStruct
    public Derived Data; // [!code highlight]
    // if Data holds a Derived
    public DerivedStruct Data; // [!code highlight]
}
```

</Tab>
<Tab value="Unmanaged, different size">

```csharp
[NinoType]
public class SampleClass2
{
    public int Data; // [!code --]
    public long Data; // [!code highlight]
}
```

</Tab>
</Tabs>

## Custom Constructors [#custom-constructors]

Nino can deserialize an object through a constructor of your choice. Use it to run extra code while an object is deserialized, for example to initialize fields or properties that are not serialized. For records, Nino can use either the primary constructor or a custom one.

### Usage [#usage]

The attribute below passes the members `Field1, Field2, ...` as the arguments of the constructor it marks:

```csharp
[NinoConstructor(nameof(Field1), nameof(Field2), ...)]
```

Without the attribute, Nino picks a constructor itself:

| Type | Constructor used by default |
| --- | --- |
| `record` | The primary constructor. |
| `class` | The **first public constructor** that is parameterless, or whose parameters all have the same names as the fields or properties to deserialize. |
| `struct` | The parameterless constructor (a struct always has one). |

When that constructor is not suitable, mark the one to use with `[NinoConstructor]`.

### Restrictions [#restrictions]
- The constructor must be `public`.
- It must have as many parameters as the names listed in `[NinoConstructor]`.
- Each name in `[NinoConstructor]` must match (ignoring case) a field or property of the class, struct or record that is deserialized, so that member must be serialized in the first place.
- The names in `[NinoConstructor]` are the members passed to the constructor, in order.

### Examples [#constructor-examples]

<Tabs items={["Several constructors", "Primary constructor", "Not the primary constructor"]}>
<Tab value="Several constructors">

```csharp
[NinoType]
public record SimpleRecord
{
    public int Id;
    public string Name;
    public DateTime CreateTime;

    public SimpleRecord()
    {
        Id = 0;
        Name = string.Empty;
        CreateTime = DateTime.MinValue;
    }

    [NinoConstructor(nameof(Id), nameof(Name))] // [!code highlight]
    public SimpleRecord(int id, string name)
    {
        Id = id;
        Name = name;
        CreateTime = DateTime.Now;
    }
}
```

</Tab>
<Tab value="Primary constructor">

```csharp
[NinoType]
public record SimpleRecord2(int Id, string Name, DateTime CreateTime); // [!code highlight]

[NinoType]
public record SimpleRecord4(int Id, string Name, DateTime CreateTime) // used // [!code highlight]
{
    [NinoIgnore] public bool Flag;

    public int ShouldNotIgnore;

    // Nino does not use this one // [!code highlight]
    public SimpleRecord4() : this(0, "", DateTime.MinValue)
    {
    }
}
```

</Tab>
<Tab value="Not the primary constructor">

```csharp
[NinoType]
public record SimpleRecord5(int Id, string Name, DateTime CreateTime) // not used // [!code highlight]
{
    [NinoIgnore] public bool Flag;

    public int ShouldNotIgnore;

    // Nino uses this one, which discards the primary constructor values when deserializing
    [NinoConstructor] // [!code highlight]
    public SimpleRecord5() : this(0, "", DateTime.MinValue)
    {
    }
}
```

</Tab>
</Tabs>

Custom constructors work for classes and structs too:

<Tabs items={["Struct with a parameterized constructor", "Class with a parameterized constructor"]}>
<Tab value="Struct with a parameterized constructor">

```csharp
[NinoType]
public struct SimpleStruct
{
    public int Id;
    public string Name;
    public DateTime CreateTime;

    // used to create the struct when deserializing
    [NinoConstructor(nameof(Id), nameof(Name), nameof(CreateTime))] // [!code highlight]
    public SimpleStruct(int a, string b, DateTime c)
    {
        Id = a;
        Name = b;
        CreateTime = c;
    }
}
```

</Tab>
<Tab value="Class with a parameterized constructor">

```csharp
[NinoType]
public class SimpleClassWithConstructor
{
    public int Id;
    public string Name;
    public DateTime CreateTime;

    // No [NinoConstructor] needed: this is the only public constructor,
    // and its parameters match the member names, so Nino uses it
    public SimpleClassWithConstructor(int id, string name, DateTime createTime) // [!code highlight]
    {
        Id = id;
        Name = name;
        CreateTime = createTime;
    }
}
```

</Tab>
</Tabs>
