Nino v3 is a NuGet package for .NET projects and a UPM package for Unity. Both bring the runtime library and the source generator.

<Callout type="warn" title="Do not use Nino v3.9.x">

`v3.9.*` releases were used to test features of Nino v4.0 and are not API-compatible with `3.*`. If you want those features, use Nino v4.0 directly.

</Callout>

## Installation [#installation]

<Tabs groupId="platform" persist items={['.NET', 'Unity']}>
<Tab value=".NET">

```shell
dotnet add package Nino
```

Details: [.NET Project](/en/docs/v3/start#net-project).

</Tab>
<Tab value="Unity">

Install `com.jasonxudeveloper.nino` from [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/#modal-manualinstallation).

Details: [Unity Project](/en/docs/v3/start#unity-project).

</Tab>
</Tabs>

### .NET Project [#net-project]

<Callout type="info">

Nino supports projects targeting .NET 5.0 or later, or .NET Standard 2.0 or later.

</Callout>

- Search for `Nino` in the NuGet package manager of Visual Studio or Rider and install it
- Or use the `dotnet` CLI:
    ```shell
    dotnet add package Nino
    ```

<Callout type="info">

Nino needs two NuGet packages, both required: `Nino.Generator` and `Nino.Serialization`. Installing `Nino` brings in both.

</Callout>

<Callout type="warn">

This does not work for .NET Framework projects, or in IDEs that cannot run source generators (such as Visual Studio Code).

</Callout>

### Unity Project [#unity-project]

<Callout type="info">

Nino supports Unity 2022.3 or later, on every player platform.

The `Nino.Unity` sample project on GitHub shows how to use Nino in Unity and includes a set of unit tests (via `TestRunner`). Run it first.

</Callout>

<Steps>
<Step>

### Install the package [#install-the-package]

Install Nino through the Unity Package Manager (UPM). See [OpenUPM](https://openupm.com/packages/com.jasonxudeveloper.nino/#modal-manualinstallation) for the steps.

</Step>
<Step>

### Check `Microsoft.CodeAnalysis` [#check-microsoftcodeanalysis]

Source generators in Unity need the `Microsoft.CodeAnalysis` NuGet package (any recent version). Unity 2022.3 and later should already have it; if not, install it yourself, for example from the Unity project folder (the one that contains `Assets`):

```shell
dotnet add package Microsoft.CodeAnalysis.CSharp --version 4.10.0
```

</Step>
<Step>

### Reference `Nino.Core.dll` from your `asmdef` [#reference-ninocoredll]

If you use `asmdef` files, make sure `Auto Referenced` is enabled. If `Override References` is on, add a reference to `Nino.Core.dll` explicitly.

</Step>
</Steps>

<Callout type="idea">

If you run into problems, check that you followed the steps above and that the `Nino.Unity` sample project runs. If the problem persists, please open an issue on GitHub.

</Callout>

#### Hot Update Code [#hot-update-code]
- Nino supports **HybridCLR** and **ILRuntime**.
- To write hot-update code in a separate C# project (not an `asmdef` inside Unity), create a .NET Core project, install Nino from NuGet ([see above](/en/docs/v3/start#net-project)), and use the compiled DLL in HybridCLR or ILRuntime.
